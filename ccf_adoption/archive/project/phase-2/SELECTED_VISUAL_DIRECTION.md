# Phase 2B — Selected Visual Direction

## Status

**APPROVED visual baseline for Phase 2C — dark enterprise direction.**

David explicitly approved this direction on 2026-09-13 as the version to keep. It supersedes the earlier light landing-page treatment as the prototype source truth while preserving the approved Phase 2A information architecture, learning-path separation, and evidence model.

## Overall direction

Use a **dark, modern enterprise technical-product hero and navigation system** paired with clean white documentation/content surfaces below it.

Primary characteristics:

- deep navy hero and global header;
- cobalt / electric-blue architecture visualization;
- restrained gold accent for the primary CTA and active state;
- L1–L6 CCF architecture as the dominant hero visual;
- crisp white documentation/content surfaces for scanning and long-form reading;
- technical and financial-services credibility rather than a generic marketing aesthetic;
- strong support for engineers, architects, financial-services SMEs, evaluators, and controls/governance readers.

## Hero and architecture

Hero message:

- `From data to better decisions`
- CCF assembles, contextualizes, and delivers trusted Context Products from real-world data with provenance, controls, and clarity.

The architecture visual must preserve the six layers:

1. **L1 — Signal Layer**
2. **L2 — Context Assembly**
3. **L3 — Context Graph**
4. **L4 — Context Operators**
5. **L5 — Context Projection**
6. **L6 — Context Products**

Supporting messaging includes:

- **Real-time assembly**
- **Data products to Context Products**

No scenic / mountain imagery.

## Landing-page structure

### Header

Keep the approved seven destination model, with compact labels allowed at desktop widths:

- Start Here / Home
- Learn CCF / Learn
- Build with CCF / Build
- Reference
- Financial Services
- Govern & Operate / Govern
- Adopt CCF / Adopt

Global search remains visible.

### Resource strip

Immediately below the hero provide direct access to:

- Watch Overview
- Read the Whitepaper
- View Architecture
- Try the SDK
- Explore Examples
- See Context Products

### Audience entry cards

Three prominent entry points:

- **For Developers** — quickstart, SDK reference, tutorials
- **For Financial Services** — example library, domain scenarios, control/evidence views
- **For Evaluators** — value, architecture, governance, FAQ

These are routing components, not generic promotional statements.

### Financial Services examples

Use a **horizontal scrollable carousel/catalog**. Cards are concise and click through to the full business-first use-case page.

### Lower utility row

Provide high-value operational entry points rather than decorative marketing:

- Latest Updates
- Popular Resources
- Get Started Today

## Inner-page visual system

Tutorial, Reference, Financial Services, Governance, and Adoption pages should inherit:

- the dark enterprise header;
- blue / navy / white token system;
- version/evidence metadata;
- compact side navigation for technical content;
- high-readability long-form body surfaces;
- distinct evidence components for Data Reality, Control Demonstrated, Boundary / Not Proven, Known Limitation, and Evidence Baseline.

## Product rules retained

- Consumer and Assembler journeys remain distinct.
- Financial Services pages begin with the business problem and decision.
- Controls/governance are a first-class audience.
- Reference pages stay version pinned.
- Demonstration-data limitations must not be mislabeled as SDK limitations.
- Security assurance remains separate from mechanism evidence.
- CP-04 remains canonical-only.
