## 1 · `D-IMPL-336` — composite Context Products

**The architecture, in Dave's words, which is what Amendment 5 simplified the
implementation back down to:**

> A complex context product can be made up of several other context products.
> It does not have to be responsible for assembling the atomic context
> products. They very well may be registered elsewhere servicing other use
> cases. The composite context product needs to be able to call the atomic
> context product whose definition exists either in-process, via an MCP, A2A or
> by calling another agent. The skill that the composite agent has knows how to
> acquire the atomic context product and roll it in.

So: a composite declares the child product **classes** it requires. A granted
skill acquires each child. The composite rolls them up under the four
**pre-ruled** laws — `D-IMPL-31` per-factor debt, lineage set-union, expiry
floor, mixing refusal — with aggregate debt as the per-factor maximum
(`D-IMPL-104`). **Zero new weights were invented; the socket `D-IMPL-104` left
is now filled.**

**The composite is a consumer, not a second Control Plane.** It assembles
nothing atomic and it re-governs nothing that is already governed.

**`MCP` is a Peering TRANSPORT, not the concept** (`D-IMPL-59` separates them
explicitly). Apply the controls for the *actual provider relationship*; do not
demand a new signed envelope merely because acquisition happened to use MCP. A
genuinely peered product still passes peering verification regardless of how
the skill retrieved it. `ChildAcquisition = Literal["local-dispatch", "mcp",
"peered"]`, read from the dispatch type, never from a caller's string.

**Where it lives:** `src/ccf/products/composite.py` and
`src/ccf/products/child_resolver.py` (`GrantBoundChildResolver`: effective
grant → dispatch → governed door → fit → compose).

**Two details that are load-bearing and will not survive a casual refactor:**

- **`compose_children`'s branch order** is provenance → refusal → `None` →
  `unsupported-outcome`. Reordering it changes which governed absence a caller
  observes.
- **`ChildRecordMismatch` derives from `ValueError` deliberately.** As a
  `RuntimeError` it escaped the MCP door's `(ValueError, TypeError,
  LookupError, OSError)` wrap and leaked across a boundary that is required to
  be opaque.

**Records:** `docs/D-IMPL-336-COMPLETION.md`,
`docs/D-IMPL-336-CLOSE-PANEL.md`, `docs/D-IMPL-336-PANEL-REVIEW.md`,
`docs/D-IMPL-336-REMEDIATION-DISPOSITION.md`.

## 2 · `D-IMPL-337` — guarded-path provenance

336 exposed a gap that was **not 336's**: token-guarded types were reaching
publicly reachable consumers that never verified them. Dave's ruling was to
**raise it separately and not widen 336 into four subsystems.**

**The governing rule, as ruled:**

> If a type derives authority or validity from a guarded construction path,
> every publicly reachable consumer that relies on that authority must
> **positively verify the guarded runtime type** before using it. Structural
> compatibility or duck typing is insufficient.

**The governed unit is `entry point × authority-bearing value × external
substitutability`** — not "every function that touches the type". That is what
keeps the rule finite and auditable.

### The registry is the source of truth

`src/ccf/contracts/guarded.py` declares **7 guarded types across 9 governed
boundaries**. `GuardedTypeDeclaration(type_path, authority, mint, verifier,
boundaries, propagation, residual, verifier_aliases, notes)` — **every field is
a string**, so the registry imports nothing and cannot cycle with the modules
it governs. The drift lint resolves the strings against the tree at check time.

`verifier_aliases` exists because **the lint caught a real mismatch on its
first run**: `compose_children` calls the `TypeGuard` *predicate* form, not the
raising form, so a naive name match reported a genuinely governed boundary as
unverified. The instrument found a defect in its own model.

- **Lint:** `tools/lints/guarded_provenance.py`, registered in `--all`. It keys
  on **none** of the forbidden signals (annotations, name visibility,
  `isinstance` syntax, `Protocol` presence, PEP 634 patterns) and does not scan
  `examples/` (frozen specimens are never edited to satisfy a lint —
  `D-IMPL-261`, CLAUDE.md §9).
- **Controls:** `tests/invariants/test_guarded_provenance.py`, 25 controls,
  four per type.
**One wiring detail measured at this save, because `--help` misreports it.**
`guarded-provenance` is in `--all` — `tools/lints/__main__.py` builds
`every = list(CHECKERS) + list(WHOLE_TREE_CHECKERS)` and the checker is in
`WHOLE_TREE_CHECKERS` — but it has **no individual `--guarded-provenance`
flag**, so `python -m tools.lints --help` does not list it and a reader
checking the help output would conclude it is unwired. **Proven by sabotage,
not by reading:** stripping the verifier from one governed boundary
(`ccf.replay.serve:serve`) turns `make lint` RED with the D-IMPL-337 message;
restoring it turns it green. Restored **by marker and md5**, never by a clean
`git status`.

- **Design record:** `docs/D-IMPL-337-DESIGN.md`. Census:
  `.planning/censuses/guarded_type_census_v3.py`.

### `isinstance` is insufficient — measured, not argued

A subclass that skips `__init__`, and `object.__new__(Cls)`, **both satisfy
`isinstance` and reach a real `ServedProduct` with the gates never run.**

The project had already settled this before 337 existed, at
`src/ccf/controlplane/state.py::_verify`, pinned by
`tests/invariants/test_state_seam_closure.py::test_a_token_subclass_skipping_init_cannot_succeed`:

> isinstance is not the gate — the mint is verified at the write.

The mechanism is the mint/sentinel, applied uniformly:

```python
self._gate_provenance = _GATE_TOKEN          # set ONLY on the guarded path

def verify_gate_provenance(product: object) -> "ServableProduct":
    if getattr(product, "_gate_provenance", None) is not _GATE_TOKEN:
        raise GateBypassError(...)
    return cast(ServableProduct, product)
```

Same shape at `src/ccf/peering/admission.py::verify_admission_provenance`
(`AdmissionBypassError`) and at
`src/ccf/products/composite.py::verify_resolved_producer_provenance`
(`ProvenanceForgeryError`).

### The threat model is unchanged and is stated in the modules

**This is the supported-interface threat model. It is NOT authorization to
defend against arbitrary Python reflection or module patching.** An attacker
who can call `object.__setattr__` was never in scope and still is not.

### Two residuals, ruled NOT to be fixed

1. **Third-party `ControlPlaneStateStore` Protocol enforcement limitation.** A
   third-party implementation cannot be held to the guarded path.
2. **`AmbiguousProducerError` escapes the MCP opaque-failure posture**
   (`D-IMPL-253` Q20: a runtime failure crosses a door as an opaque
   `ccf-runtime-failure` id — no message, no type name, no traceback). **If
   that door is ever repaired, this needs its own decision.**

## 5 · What this sitting taught — the transferable half

**1. A population census beats sampling, and costs less.** Three separately
reported "mechanism defects" turned out to be three samples from a population
of **15 consumer sites, of which exactly 1 verified**. **45 agents across two
cross-AI panels found two instances. A 40-line AST census found the whole
population in under a second.** When the same defect recurs, stop fixing
instances and enumerate the population.

**2. Sabotage the INVOCATION BOUNDARY, not just the verifier.** Sabotage S7
reverted the *call site* to `isinstance` and **all 24 controls stayed green**,
because every one of them exercised the verifier function directly. A control
that only tests the verifier cannot see a caller that stopped calling it.
Closed by `test_the_INVOCATION_BOUNDARY_refuses_a_nominal_forgery`.

**3. A test can be tautological by construction.** R2's first version asserted
`debt == context_debt(factors)` — true by construction under `_reassess`, so it
could never fail. Caught by an independent reviewer, not by the suite.

**4. `F15` (the one-`as_of` invariant) fires BEFORE dependency invalidation.**
INT-01b's first version pinned a cached leaf and measured `as-of-mismatch`
rather than invalidation, and **passed for the wrong reason**. It was exposed
only because **sabotage 2 stayed green**. Rewritten as a historical
reconstruction.

**5. "Pre-existing" is measured against the phase base, never against a
stash.** I called a red pre-existing on the evidence that it was red with work
stashed — wrong: stashing removes only *uncommitted* work, and the cause was in
my commits.

**6. `git checkout src/` destroyed my own uncommitted fix** while restoring a
sabotage, and `git status` went clean as if nothing had happened. Caught by
reading the diff stat. **Verify restoration BY MARKER, never by a clean
`git status`.**

**7. Running the generator is not running the gate.** `test_surface_drift` was
RED on the branch and GREEN on `main`, and the only unclaimed names were the
branch's headline deliverable. I had run `make surface-changes` and never run
the gate.

**8. An accounting error reached Dave.** I reported "all seven sites" — a
design-phase census figure — while the registry declared **nine** governed
boundaries. Census v2 over-credited, v1 under-counted, and v3 filed
`ProductSource.__init__` as module-private **because the function name begins
with an underscore**; a 7th governed site was found by review, not by the
instrument. **State the population in the same breath as the number, and name
the instrument that produced it.**
