## Lessons (transferable)

1. Every fix moves a committed derived artifact somewhere: before "done", ask which artifact reads
   what I changed (surface manifest, openapi, README fences, closed-set tables, sweeps) and run ITS
   check. Two of the 62 reds and two more mid-repair were mine that way.
2. A guarantee about a KIND of value (a literal default) is enforced by TYPE where the value is
   rendered, never by parsing rendered text — two scrub designs were refuted before that held.
3. `cite03` has NO historicity exemption: renaming a test breaks every dated record citing it by
   `path::symbol`; cite historical ids in split form. Never write `x.py:NN` in docs — the ratchet
   counts it. A long prose sentence in an assertion string trips `cinv01a`.
4. Committed evidence under `docs/`, or as loose text anywhere, gets swept as documentation — pack it
   as a tarball under `qualification/`.
5. A one-shot `make test` needs `setsid nohup` + a Monitor keyed on the pytest PID (a pgrep pattern
   matches the monitor's own shell); junit via `PYTEST_ADDOPTS`; ~27 min with estate + substrates.
6. The main working tree carries 25 git-ignored macOS `._*` sidecars that filesystem-globbing tests
   parametrize over (+96 nodes) — always qualify on a fresh checkout.
7. Parallel repairs: read-only root-cause agents first (one per independent group, with a required
   "problems this fix could create" section), then implement; large mechanical groups in isolated
   worktree agents, cherry-picked and reviewed. Three adversarial review rounds found 15 real holes
   in ~150 lines.
8. `git cherry-pick` has no `-q`; a shell `cd` in a chained command moves the tool's cwd.
