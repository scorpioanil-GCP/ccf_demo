## Instrument errors made while measuring, recorded rather than tidied

These are the value of the wave, not its embarrassment: **four instruments were
wrong before they were right, and each was caught by its own guard rather than
by luck.**

1. **The M-1 control's anchor drifted, and its assert fired.** The mutation was
   written against `| HARD-01 | Phase 11 |`; the row reads `| HARD-01 | Phase 9 |`.
   Without the assert the "control" would have re-measured an *unmodified*
   document and reported a refusal that never happened.
2. **The M-5 decision-id reader was BLIND to ids 2–29** — those entries ship as
   `- **D-IMPL-NN**` bullets, and the first regex matched only the line-initial
   form. It reported 28 ids as FREE. **This is the dangerous direction**: a
   blind reader makes the whole intersection vacuous while looking green.
3. **The M-6 deletion control matched a SUBSTRING, twice.** Anchoring on
   `"Phase 23.1" in line` found **3** lines; scoping to the `## Phases` block
   still found **2**, because **Phase 23's bullet contains the string "Phase
   23.1" in its prose**. Only anchoring on the *parsed* number found exactly one.
   *A substring is not a subject.*
4. **The M-4 grep returned a false clean at exit 0.** `git grep -E`-less
   `[0-9]+` under BASIC regex matches a literal `+`; the search found nothing and
   exited 0. Re-run with `-E` it finds 38 occurrences in one file.

And one guard that fired correctly and is worth recording as such: **the
retirement-report currency gate went RED the moment `23.1-GATE-MEASUREMENTS.md`
was written** (`test_the_committed_report_is_current` FAILED, 1 failed / 58
