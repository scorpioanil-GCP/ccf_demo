## The disposition vocabulary and how it is written into a row

Criterion 1 requires the disposition **written into the row itself**. It is
written as an explicit greppable bolded token — `**Discharged**`,
`**Deferred to v0.3**`, `**Dropped**` — placed **after** the row's existing
verdict token and evidence prose, never in front of it.

**Why it is not written in front.** `test_requirement_ledger.py::vocabulary_offenders`
refuses any status cell whose **leading** token is outside `D-09`'s six-word
vocabulary, and none of the three disposition words is in it. A disposition
written as the leading token would redden the shipped gate; a disposition
written after the verdict is invisible to `verdict_token` (which reads the
leading alphabetic run only) and to `cell_verdicts` (which collects bolded runs
**that are in the vocabulary** — the three disposition words are not). Measured
rather than assumed: see the gate legs in this plan's summary.

**Consequence, stated rather than left implicit (plan verification bullet 1).**
The nine rows keep their existing verdict tokens, so **I-1's open-row set stays
the same 13 ids with the same 13 verdicts**. The disposition SUPERSEDES the
verdict as the row's operative statement; the verdict stays as readable history.
Nothing about the tick or the token changes, so **no channel disagreement can be
introduced by the disposition itself** — which matters, because the shipped
comparator could not see one if it were.
