## Three stale ledger claims found and corrected in place

Each correction is written INTO the row beside its disposition; the superseded
prose stays readable, which is this repo's standing discipline.

1. **`DOCS-12` claimed no page under `public/` names `s1-00` or `s1-01`.**
   Measured, `public/concepts/answers-no-document-contains.md` names `s1-01` and
   carries **five snippet includes from it**. The clause was true when written
   and was falsified by Phase 22. The disposition does not change: the limb that
   matters — `assembly_mode` as a governance choice with its two siblings named —
   is still absent.
2. **`DOCS-11` names three trees that are no longer under `examples/`.**
   `examples/00-quickstart`, `examples/08-e2e-demo` and
   `examples/external/00-hello-context` were moved under `archive/examples/` by
   Phase 23. They are the **only three spans in all nine rows that fail a direct
   stat**, and they fail because the tree moved, not because the reference was
   ever wrong. The absence is re-stated against the post-move tree: **two of the
   four module-bearing example trees** open the ordered marker set.
3. **`DOCS-03` says six class ids are named nowhere; the residual is five.**
   `ccf.scope-mapping` now reaches the rendered tree in 19 units, through an
   include. The measurement that matters here is the CONTROL: a page-source grep
   returns 0 for all 27 class ids, so a 0 from that reader is a broken
   instrument rather than a finding.

## How the disposition is written, and why it is not written first

The disposition is appended **after** the row's existing verdict and evidence
prose, as its own bolded run — `**Discharged**` / `**Deferred to v0.3**` — so it
is literally greppable.

It is **not** written as the leading token, and that is a measured constraint
rather than a style choice. `test_requirement_ledger.py::vocabulary_offenders`
refuses any status cell whose LEADING token falls outside `D-09`'s six-word
vocabulary, and none of the three disposition words is in it. A disposition
written in front would have reddened a shipped gate. Written after, it is
invisible to `verdict_token` (leading alphabetic run only) and to
`cell_verdicts` (bolded runs **that are in the vocabulary** — these three are
not), so `doubled_verdicts` cannot read it as a second verdict either.

**The consequence, stated rather than left implicit.** The nine rows keep their
existing verdict tokens, so **I-1's open-row set is still the same 13 ids with
the same 13 verdicts** after the edit. The disposition SUPERSEDES the verdict as
the row's operative statement; the verdict stays as readable history. Because no
tick and no token moved, the edit could not introduce a channel disagreement —
which matters, since the shipped comparator could not have seen one.

raises `ModuleNotFoundError: No module named 'tools'`, because `tools/` sits at

`python -m tools.lints` forms were left exactly as the plan wrote them.

### [Rule 2 — Missing critical instrument] I-2 does not compare dispositions

The plan's Task 2 says to *"set one edited row's traceability **disposition** to a
different token in a scratch COPY and confirm the instrument names that id."*
**I-2 as specified by Wave 1 compares VERDICT tokens**, so a disposition-only
mutation passes it silently — measured, not assumed. A disposition-level
comparator (`I-2d`) was written and controlled, and **both** controls were run:
the disposition mutation (I-2d RED, I-2 silent) and the verdict mutation (I-2
RED, I-2d silent). Each instrument is now known to be blind where the other
looks. Neither is committed — this phase builds nothing.

### My own I-3 is wider than Wave 1's, and the difference is recorded rather than reconciled away

Wave 1's I-3 family B reported **30 paths / 1 MISSING** across all 13 rows. Mine,
rebuilt from the written spec, reported **93 / 19** on the first pass, because it
admitted bare filenames and directory spans. It was narrowed to three declared
families — anchored (A), slashed spans (B), bare-suffixed spans (S) — and each
result is reported as **FILE / DIR / ABSENT** rather than as a boolean, because
`refuse_unresolvable` treats a directory as *not evidence*. **The two waves'
family-B figures are therefore not comparable, and I do not claim they are.**
What is comparable and does agree: **family A, the repo's own extractor, is
ZERO MISSING in both waves.**

### One reader artifact of my own, named rather than tidied

My S-family reader matches a suffix of 1–8 characters, so **`D-GATE-21.1`**,
which I wrote into `DOCS-18`, is extracted as a path-shaped span and reported
ABSENT. It is a decision id, not a path, exactly like `15.6-05` and `15.6-06`
in `DCD-02`. Left as written, because the repo's convention backticks decision
ids and changing that to please my own instrument would be the wrong repair.
**A later wave running an I-3 of this shape will see four such false ABSENTs in
the S family; all four are named here.**
