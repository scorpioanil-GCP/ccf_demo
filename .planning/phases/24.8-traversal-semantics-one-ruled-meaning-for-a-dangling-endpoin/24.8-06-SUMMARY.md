## Deviations from Plan

### Rule 1 — instrument defects found and fixed in my own verification code

Four, all in verification machinery rather than in the subject, and all recorded in the artifacts
rather than quietly corrected. This is the project's `verification-code-is-where-my-defects-land`
pattern, and it fired four times in one plan.

**1. A fabricated control block (caught before it stood).** While drafting § Batches I wrote a
`git diff --name-only 8567d683 -- tests | wc -l` control *with its output*, reasoning rather than
running — and included a confident digression explaining why the count read 6 while the roster had
7 lines. Measured, the count is **7**. The digression was wrong and the number was invented. Both
were replaced with the measured roster-then-count, in that order. Had it stood it would have been a
false number in a close artifact.

**2. The AST sabotage control's first attempt did not fire.** It planted a trailing `# planted`
comment, and the comparison correctly reported no change — correct instrument, **broken control**,
because it never tested the claim. Re-planted a semantic one-token change
(`direction="undirected"` → `"forward"` inside `TraversalNeighborhood.read_intent`); the instrument
then named that definition and its enclosing class. Both attempts are in the artifact.

**3. The prose classifier's first version was too loose.** It called a line prose if any `STRING` or
`COMMENT` token covered it, and its control caught it calling `__all__ = ["answer"]` prose — because
that line *contains* a string literal. A classifier that loose would have called a hypothetical new
`dangling_count: int = 0` field "prose" the moment it sat near a docstring. Replaced with AST
docstring **nodes** plus comment tokens; the control now returns `CODE` for all four
known-executable lines including that one.

**4. A count written from arithmetic, not measurement.** A draft sentence said "18 definitions" for
the three non-traversal families; the enumerated roster is **17** (`SimilaritySelect` has four
members, not five). Corrected to the pasted roster, with the error stated in place.

### Rule 3 — a weak instrument the plan proposed, replaced and disclosed

The plan's acceptance wording suggested `grep -c "operator_tier" <leg>_after.xml > 0` as the
differential-presence check. Measured, that reads **1 on every leg** because the junit XML is a
**single line** — it would read 1 for seven testcases or for one, satisfying `> 0` vacuously. It is
used as evidence nowhere; the XML `<testcase>` parse is the instrument of record. The neighbouring
`grep -o | wc -l` reads 8, resolved rather than left dangling: 7 dotted `classname` attributes plus
one slashed path inside a `hypothesis-statistics` `<property>`, which is not a testcase.

### A measurement taken, failed, and DISCARDED rather than substituted

A whole-tree collection at the base in the scratch worktree **errored** —
