## Deviations from Plan

### 1. `_apply_callees` split into two helpers

The plan gave `_apply_callees(source: str) -> dict[str, set[str]]` and then asked it to "also
return the count of module-level `FunctionDef`s named `_bounded_walk`" — a return type that
cannot carry both. Shipped as `_apply_callees` (the dict, signature as written) plus
`_bounded_walk_definitions(source) -> int`. Both are asserted by `_assert_one_walk_pin`, so the
plan's two obligations are both proven; only the packaging differs.

### 2. `[Rule 2] The idempotence test is parametrized, and the count assertion moved inside it`

The plan's action text derived the traversal keys inside the test body; its acceptance criteria
name per-key node ids (`...[traversal.typed-neighborhood]`). Those ids only exist under a
parametrization, so `TRAVERSAL_KEYS` is derived at module level from the registry's own category
assignment and the `== 2` pin stays inside the test, as the plan required. The ids in the
acceptance criteria now resolve.

### 3. One extra byte assertion added to the shape test

`canonical_bytes(TWIN) != canonical_bytes(G1)`. Without it the provenance control in
`test_exclusion_is_silent` could be comparing an operator's answer on one state with itself.
Not in the plan; added because the control it protects is otherwise assertable on a relabeling.

### 4. Disclosure — criterion 15's bare-`_walk` grep roster in `test_traversal_direction.py`

```
$ grep -n '_walk(' tests/operators/test_traversal_direction.py | grep -v '_bounded_walk('
BASE (382b072b): 4 lines   NOW: 5 lines
```

Base 4: three real `fallback._walk` oracle calls (`:250`, `:308`, `:768` — plan 05 re-derives
these) **plus one pre-existing false positive**, the def name
`test_direction_and_admission_compose_on_the_descendant_walk()`. The added fifth is this plan's
control def name, `test_control_the_one_walk_pin_fails_on_a_copy_with_a_private_walk(`, which
the plan prescribes verbatim.

I removed every hit I could remove without renaming a plan-prescribed id: the pin helper is
`_assert_one_walk_pin` (not `_assert_one_walk`, which would have added three), and the
docstring's `self._walk(...)` illustration was reworded. The alias literal in the sabotage is
`_private_bounded_walk(`, which the `grep -v` already excludes — B-1 honored.

**Consequence for plans 06/07:** the bare pattern cannot read 0 on the merged tree even after
plan 05 re-derives the three oracles, because the pre-existing `descendant_walk()` def name
survives it. The instrument needs scoping to *calls* (e.g. `= _walk(` or the import) rather
than the bare substring. That was true at base; this plan adds one more member of the same
class rather than creating the problem.

I chose disclosure over renaming because renaming a node id the plan prescribes — and that the
criteria may cite — to make a grep read a rounder number is changing the instrument's subject,
which is the failure this project has recorded before.
