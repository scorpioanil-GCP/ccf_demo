<objective>
Prove criterion 6's default-path half for legs 1 and 3: they reach no model
because they reach **no network at all**.

Purpose: `H-06` rules the default path is "the harness invokes the registered
tool", with no model. The strongest available proof of that is not an assertion
that no model was called — it is a process-global socket refusal that the legs
run inside and do not trip. `stdio_client` spawns a child over pipes and
`FastMCP.run(transport="stdio")` serves over pipes, so a socket-refusal guard
around either leg proves no egress whatsoever, which is the same claim
`examples/03-harness-portability/legs/deterministic.py::install_no_model_guard`
already makes for example 03.

Output: one test module, one guard, one non-vacuity control, and a written
statement of what leg 2 is excluded from and why.

<mechanical_constraint>
**The guard cannot live in the runner, and this is the reason.** The guard is
process-global, and the three clients run as **child processes** of the runner. A
runner cannot install a socket guard inside a child's interpreter without the
client importing something — which would be exactly the non-teaching clutter the
clients must not carry, and would put a non-harness import into a program whose
whole claim is how little it imports.

So the guard lives in a **test** that drives legs 1 and 3 **in-process**, inside a
copied guard. That is also what example 03 already does; its own docstring notes
the drive *"now runs inside `pytest` as well as under `make example-03`"*.
</mechanical_constraint>

<interfaces>
From `examples/03-harness-portability/legs/deterministic.py::install_no_model_guard`
— the technique to copy (not import: that module is producer-side and its code
does not transfer):

    @contextmanager
    def install_no_model_guard() -> Iterator[None]:
        # patches socket.socket.connect and socket.create_connection to raise
        # AssertionError; restores BOTH in `finally`, including on failure
        # "the driver refuses to proceed unless it actually fires"

Two disciplines from its docstring are the ones worth inheriting: the guard is
process-global and installed before any leg runs, and it **carries its own
non-vacuity control**. An unscoped patch would survive the drive and refuse egress
for every later test in the same process — a failure reporting itself somewhere
unrelated to its cause, which is the defect class a guard exists to prevent rather
than cause.
</interfaces>
