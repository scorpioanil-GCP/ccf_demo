# Phase 15.1 Plan 19: Five Surviving False Claims — Summary

Closed the five claim defects phase verification found, plus **four more of the same
two classes** that measurement surfaced and neither the register nor the verification
report named — including a second false citation in shipped `src/`, and one this plan
created in the act of fixing another.

## What Changed

### 1. `binder.py` — W-1, the only present-tense false claim in shipped `src/`

The docstring said `load_and_boot`'s signature "spans lines 181-188 in the tree as it
now stands". Opened `manifest.py` and read it: the signature spans **248-255**; 181-188
is inside `_document_inside_the_deployment`'s `Raises:` block.

The other half of the sentence — that the D-IMPL-86 correction cites
`manifest.py:177` — I verified two ways rather than one: `docs/DECISIONS.md:278` does
carry that citation, and `git show f18289c:src/ccf/deployment/manifest.py` shows
`load_and_boot` at line 177 in the tree the correction was written against. So the
correction's citation was accurate when written and has since drifted. The docstring
now says exactly that, and drops the present-tense line claim entirely. **No behavior
change; the assertion the sentence supports was true throughout.**

### 2. `test_workflow_hitl_output.py` — W-2, docstring *and* failure message

Both said the four author-versioned classes stay out of the manifest because "the
manifest path registers through `register_typed`, which does not run the D-05 bump
check". Verified false against the tree: `load_and_boot` dispatches on
`entry.registration` (`manifest.py:436`) and `refuse_registration_the_sdk_fixes`
(`classes.py:243`, called at `manifest.py:407`) refuses `typed` for these classes in
preflight, before any document is read.

The true reason was already in the tree, in the example's own manifest: the four are
outside it **by this example's teaching choice**, so the four `register_versioned`
calls stay visible as the thing being taught. The docstring now says that, marks the
withdrawn claim, and — a third defect in the same docstring that no finding named —
corrects "a future edit that tidied them into the manifest would flip the action
recorded here", which is false: declared `versioned`, the audit action would be
unchanged and only the pin-set assertion would fire. Each of the three assertions now
states separately what it actually catches.

**Assertions unchanged.** Re-read against the standard: an author who trips the pin-set
assertion is now told it does *not* mean the bump check was dropped, what it does mean,
and which two files to correct together.

### 3. `test_schema_export.py` — W-3, and two more sites in the same file

W-3's docstring claimed a manifest entry naming an author-versioned class "would
silently drop the D-05 bump check". False: those six classes **are** manifest-
addressable via `SDK_VERSIONED_ARTIFACT_CLASSES`, which `resolve_artifact_class`
consults at `classes.py:327` before the envelope.

Reading the rest of the file for the same claim found **two further sites the
verification report did not name**:

- `test_every_author_versioned_class_has_a_committed_schema`'s docstring — "a manifest
  must not carry them, because `load_and_boot` registers through `register_typed`".
- the same docstring's "no member is manifest-addressable" — false as written. The
  assertion is `not in SDK_ARTIFACT_CLASSES`, which means *not typed-registerable*, a
  different and weaker statement.

All three corrected to the real reason: the two mappings are disjoint by construction
and `SDK_ARTIFACT_CLASSES` is the typed-only set. Assertions unchanged.

### 6. I-1 — the all-`typed` observation, ruled explicitly

**Re-measured rather than inherited.** A naive grep returns 174 `typed` / 15 `versioned`
and is wrong — the 15 are prose comments saying a manifest *may* declare `versioned`.
Counting real YAML keys (`^ *registration: (typed|versioned)`) returns **172 `typed`,
0 `versioned`**, confirming the verifier's figure.

**Ruling: examples are left exactly as they are.** No example behavior changed. Reasons,
recorded in the register in full: ROADMAP criterion 2 does not require an example to use
the declared path and is independently verified; changing example behavior after
re-approval is new scope; and example 05 — the one W-2's assertion "forbids" — has the
strongest reason *not* to adopt it, since keeping the four `register_versioned` calls
visible in `run.py` is what that example teaches.

What was wrong was not the assertion but its **rationale**, which claimed necessity and
so made a choice look like a constraint. That is corrected, so the residual is now
visible where a reader meets it. Recorded as an open demonstrability gap for Phase 16,
whose cheapest honest close is a new small example — not an edit to 05.
