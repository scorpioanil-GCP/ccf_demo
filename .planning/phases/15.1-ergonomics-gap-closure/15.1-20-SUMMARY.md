# Phase 15.1 Plan 20: A Citation Guard, and a Sweep Whose Scope Was Measured — Summary

Built the first mechanical check this repository has ever had for **cross-file
citation drift** — a defect class that recurred four times inside this phase,
twice inside the commit correcting it — and then closed the superseded-claim
sweep in `public/` and `tools/` by **measuring** its scope instead of inheriting
it for a sixth round.

---

## Task A — `tools/lints/citations.py`

Wired into `python -m tools.lints --all`, therefore into `make lint`,
`make ci-core`, `make ci` and the CI lint job. House style: stdlib only,
hand-rolled (D-06), blocking with no report-only mode (D-07), same
`path:line rule message` finding format as the other four checkers.

### Three rules

| Rule | What it checks |
| --- | --- |
| `cite01-resolves` | the cited file resolves and every cited line is inside it |
| `cite02-anchor` | an **anchored** citation must lie inside what the anchor names — a Python name resolving to exactly one `def`/`class`/module-level binding is checked against that symbol's own line span; a dot/kebab id (`ccf.debt-profile`) is checked as text in the cited lines |
| `cite03-node-id` | a `file.py::symbol` citation must resolve |

An **anchor** is a backticked span sitting immediately before the citation,
separated by nothing but whitespace, opening punctuation and at most a locator
word (`at`, `in`, `line`). That definition is the whole design: it is why the
lint finds real drift, and why it does not fire on correct prose.

### What it cannot see — stated in the module docstring, not just here

Semantics beyond the anchor; **unanchored citations** (the largest blind spot,
95 of them); ambiguous bare filenames; extensionless targets (`Makefile:NNN`);
bare `:NNN` continuations; citations inside Python *code* strings (deliberately —
`.py` files are scanned only in comments and docstrings, because a node id in a
test fixture is data, not a claim); and **a false claim carrying no citation at
all**, which is the other half of this phase's defect set and is out of a
pointer-checker's reach by construction.

### Historical citations pass

The convention already in the tree is prose — `ccf.deployment.binder`'s module
docstring cites `load_and_boot`'s old line and then says outright it "is where
it stood in the tree the correction was written against". `HISTORICITY_MARKERS`
mechanises that: a marker phrase or a git object id **in the citation's own
sentence** exempts it.

Sentence-scoped, not line-scoped, and that mattered: one `.planning/REQUIREMENTS.md`
line is a four-thousand-character paragraph that opens by saying an *earlier*
record's numbers "have since moved" and then makes six present-tense citations of
its own. Line-scoped, all six were exempted and the guard found nothing. That is
a regression test (`test_a_marker_in_a_neighbouring_sentence_does_not_exempt`).

### What it found before anything was fixed

Run over the tree at the phase base, **3 findings, 0 false positives** — each
opened and confirmed against the file:

| Finding | Verdict |
| --- | --- |
| `src/ccf/peering/admission.py` cites `artifacts.py:268,270` for the `ccf.half-life-table` / `ccf.debt-profile` ids | TRUE — they are at `:961` / `:963`. Verification **N-4** |
| `.planning/REQUIREMENTS.md` cites `binder.py:121-123` for `refuse_operator_set_divergence` | TRUE — the `def` is at `:123`. Verification **N-1** |
| `docs/surface-changes/15-06-class-lookup.md` cites `test_class_lookup.py::test_this_plans_fragment_claims_exactly_what_it_added` | TRUE — that name exists **nowhere in the tree**; a `grep -rn` over the whole repo returns only the citation itself. **Named by no prior round.** The real test is `::test_the_phases_fragments_claim_exactly_what_was_added` |

It also immediately caught a citation **I** staled while writing it: my own
docstring cited `citations.py::_symbol_spans` after I renamed the function to
`symbol_spans`. That is the fourth true positive and the cheapest possible
demonstration.

### What it could not reach, and why — precisely

- **`public/` and `tools/`.** Unreachable **by construction**. Those are false
  claims about mechanism carrying no citation. A pointer-checker checks pointers.
  Task B closes them by reading, not by tooling.
- **`docs/DECISIONS.md:282` and `:284`.** Reachable, and deliberately scoped out.
  Measured with the exemption bypassed: the file yields **11 findings across nine
  dated entries**, one of which is explicitly "preserved **unedited**". A file
  whose record discipline forbids correcting a citation cannot be gated on
  citation freshness, and correcting 2 of 11 would leave a reader to infer the
  other 9 are current. Resolution: a **reader note in the file's preamble** — not
  in any dated entry — recording the snapshot convention for all 63 of its
  citations, with the 11/63 measurement in it. Phase documents under
  `.planning/phases/` are exempt on the same test; `deferred-items.md` is
  explicitly pulled back **in**, because it is the live hand-off contract.
- **`deferred-items.md:572-573`.** Reachable only after the fix. Those two
  citations were **unanchored** ("The docstring at `…:823-824` says …"), so
  `cite02` had nothing to bind and reported them as unchecked. They are rewritten
  to `::_Binding` / `::_binding_before` — the form the entry itself prescribes —
  which `cite03` now holds. Both symbols were resolved and both quoted sentences
  confirmed to live inside them before the citations were written.

`python -m tools.lints --citations --report` on the final tree:

| unchecked — anchor not resolvable/ambiguous | **14** |
| unchecked — path ambiguous | **6** |
| unchecked — path unresolvable | **9** |

**False positives: 0 of 4 findings across development** — each was opened and
confirmed. Every intermediate false positive the design produced was removed by
tightening, and each is now a regression test:

- an anchor gap containing `:` bound `` `cinv01a-prompt-shape`: `file.py:38` `` —
  a *labelling* construction, not a locating one. `:` and `=` are excluded.
- a node id inside a Python code string (`{"suites/micro/test_gates.py::test_renamed": …}`)
  was flagged as a broken pointer. `.py` files are now scanned only in comments
  and docstrings.
- an unresolvable path in a `::` citation (`module.py::test_name`, a placeholder
  in prose) was flagged. It is now *unchecked* and counted, not red.

**A fourth rule was prototyped and rejected on measurement.** Checking a *quoted
claim* against the cited lines matched 7 sites tree-wide and failed 3 — and all
3 were **false positives**: two because the citer abridged an RST role
(`SDK_ARTIFACT_CLASSES` for `` :data:`~ccf.deployment.classes.SDK_ARTIFACT_CLASSES` ``)
and one because the cited region is a `#` comment block whose prefixes break the
quoted text. Not shipped, and recorded in the module docstring so the finding is
not lost.

### Tests — `tools/lints/tests/test_citations.py`, 22 cases

Every case builds a real two-file tree under `tmp_path`. The first two are the
**watched-to-fail pair**: the *same* citing file, against a cited module that
differs only by a two-line docstring insertion above the cited symbol — clean
before, caught after. That is the exact event that happened four times in this
phase.

Watched, not asserted: with `_anchor_verdict` stubbed to `None` (the tree's state
before this plan) `test_a_docstring_edit_above_the_cited_symbol_is_caught`
**fails**, and passes with the rule restored. The control case above it is what
makes it a discriminator rather than a tripwire that is always red.

Both directions on historicity (marked → admitted; git sha → admitted; marker in
a *neighbouring* sentence → still caught), both directions on `::` (resolves →
admitted across both trees; renamed → caught), and every measured false-positive
shape as a regression case.

`pytest tools/lints/tests -q` → **75 passed**.

## Task B — the sweep, with the scope measured

### How the scope was decided

Every top-level tracked directory was enumerated from `git ls-files` —
`.github`, `.planning`, `docs`, `examples`, `perf`, `public`, `references`,
`runtime`, `src`, `tests`, `tools`, plus the repo-root files — and **every one
was swept**. Nothing was assumed clean; nothing was inherited.

### The method mattered more than the phrase list

Every prior round grepped **lines**. `public/how-to/compose-a-workflow-with-hitl.md`
spells the claim across a line break — *"What the manifest deliberately does
**not**\nname is the four author-versioned definition classes"* — and **no
line-scoped grep of any of the seven documented phrasings finds it**. I
reproduced that: my own first-pass line-scoped sweep found 4 of the 4 `public/`
sites the verification named and missed exactly that one.

Re-run paragraph-scoped — join each file into one whitespace-normalized string,
match there, map the offset back to a line — it appears immediately. **The line
boundary, not the phrase list, was this sweep's binding constraint**, and no
round had identified that.

Hits per tree (paragraph-scoped, ten claim-specific phrasings), after this
plan's corrections:

`.planning` 142 · `examples` 51 · `docs` 48 · `tests` 16 · `tools` 11 ·
`src` 10 · `runtime` 1 · `public` **0** · `.github` 0 · `perf` 0 ·
`references` 0 · root 0.

A hit is a candidate, not a defect. `public/`, `tools/`, `src/`, `runtime/`,
`tests/` and `examples/` had **every** hit opened and read.

### `public/` — CLOSED, 4 sites on 3 navigated mkdocs pages

A tree named by no round of this sweep and appearing nowhere in the register.
`mkdocs.yml` sets `docs_dir: public`; all three pages are in the nav.

1. `public/tutorial/demo-walkthrough.md` — the canonical claim verbatim, in
   published documentation.
2. `public/tutorial/adopters-guide.md` (workflow section) — "one of the four
   author-versioned classes a deployment manifest deliberately cannot name". Also
   corrected **"four" → "six"**: `SDK_VERSIONED_ARTIFACT_CLASSES` has six members
   (read at `ccf.deployment.classes`), of which example 05 registers four.
3. `public/tutorial/adopters-guide.md` (agent-basics section) — *"That check is
   the reason those two registrations stay in adopter code."* The **I-1 rationale
   defect verbatim**, a choice stated as a necessity, in adopter-facing prose.
4. `public/how-to/compose-a-workflow-with-hitl.md` — the wrapped site.

Each replacement is grounded in the tree, not in prose judgment: a manifest may
name an author-versioned class as `registration: versioned`
(`SDK_VERSIONED_ARTIFACT_CLASSES`), `load_and_boot` dispatches that entry to
`register_versioned`, and `registration: typed` for such a class is refused at
preflight before any document is read (`refuse_registration_the_sdk_fixes`). All
four now say what `examples/05-workflow-hitl/artifacts/manifest.yaml` and
`examples/08-e2e-demo/artifacts/manifest.yaml` already said — the prose now
matches the snippet it wraps.

**Three true "deliberately not" statements in `public/` were read and left**
(`charter.md`'s non-blocking gate, `pillars/experience.md`'s signal ingestion,
`swap-the-artifact-store.md`'s manifest field).

## Deviations from Plan

**[Rule 2 — Missing critical functionality] The guard needed a scope policy, not
just rules.** Running it over everything would have produced 11 findings in a
dated append-only log whose own discipline forbids correcting them. Added
`HISTORICAL_RECORDS` / `MAINTAINED_RECORDS` as an explicit config surface with a
stated reason per entry — the same posture `RULE_TREE_SCOPE` already takes for
the other lints, where what a check does not cover is stated rather than left to
path accident.

**[Rule 3 — Blocking] The worktree had no `.venv`.** Symlinked the repo venv so
the `make` command surface runs command-for-command as documented (D-10).
`.venv` is gitignored; nothing was committed.

**Deferred, not fixed (scope boundary).** Three gate-checker tests fail —
`test_no_docstring_reproduces_whitepaper_body_text` (20 whitepaper shingle hits
in `ProductClassDeclaration`) and two `test_snippet_gate` cases whose fixture
expects an `[start:ontology]` marker `examples/00-quickstart/run.py` no longer
carries. **Verified not mine**: `git diff --name-only` against the phase base
shows this plan touches neither file. Logged in `deferred-items.md` with the more
interesting half — `make ci` cannot reach those suites at all, though CI runs
them, so `make ci`'s documented claim to be "the full local reproduction of the
always-on pipeline" does not hold for them. Same shape as every other finding in
this phase.

**Scope held.** No assertion weakened or deleted, no floor lowered, no allowlist
widened (`tools/lints/allowlist.yaml` is byte-identical), no behavior changed in
`src/`, `runtime/` or `examples/`. The single `src/` edit is a three-line `#:`
comment in `admission.py` at unchanged line count; `make schemas` produced no
drift and `dump_surface.py --check` exits 0.
