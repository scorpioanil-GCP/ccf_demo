## Critical Issues

### CR-01: `_bindings` reads three binding forms out of eight, so a plan local rebound by a tuple unpack, a `for` target or `with ... as` silently keeps its stale binding — WR-F2 back on both sides

**File:** `tests/products/test_gate_two_call_shape.py:492-500` (`_assignment`),
`:549-583` (`_bindings`, whose docstring states the opposite), `:586-602`
(`_binding_before`, whose stated cost lists only the semicolon case),
`:138-181` (the limits list, which does not name this), and the threat-table
rows in `15.1-14-SUMMARY.md:405-406`

**Issue.** `_assignment` recognises exactly `ast.Assign` with `ast.Name`
targets, `ast.AnnAssign` with a `Name` target, and `ast.NamedExpr` with a `Name`
target. Everything else binds nothing. Measured, over probe bodies:

```
  tuple unpack     bindings={}
  starred unpack   bindings={}
  for target       bindings={}
  with as          bindings={}
  except as        bindings={}
  aug assign       (records only the preceding `a = 1`, not the `a += x`)
```

`_bindings`'s docstring says: *"Every assignment to every local name in one body,
in source order."* It is every **simple** assignment. That is not a wording
quibble — a binding that is missed is worse than a binding that is unreadable,
because `_binding_before` then hands back the **previous** binding as if it were
still in force, and the checks act on it affirmatively.

**Consequence (a) — property (2) reports the opposite of the truth, silently.**
Concrete triggering input, driven through the shipped helpers:

```python
def serve(pid, r, declared, requirements):
    plan = QuickstartPlan(plan_id=pid, required=requirements.required_operator_keys)
    refuse_operator_set_divergence(declared=declared, plan=plan)
    first = ProjectionEngine(reader=r).execute(plan=plan)
    plan, spare = QuickstartPlan(plan_id=pid, required=declared.required_operator_keys), None
    second = ProjectionEngine(reader=r).execute(plan=plan)
    return (first, second)
```

```
bindings for plan  : (_Binding(lineno=2, path=None),)
plan sources       : {('plan@2',): ('requirements', 'required_operator_keys')}
binder calls       : [(3, ('declared',), ('plan@2',))]
executions         : [(6, ('plan@2',)), (4, ('plan@2',))]
problems           : []
names binder       : True
per-body readable  : True
```

The line-5 construction is built from `declared.required_operator_keys` — CR-03
variant 1 — and no binder was ever handed it — CR-03 variant 2. The line-6
execution resolves to `plan@2`, the object bound at line 2, because line 5 bound
nothing. `call.handed == execution.plan` therefore matches, property (2) says
*"the plan bound is the plan run"*, property (1) never sees the second
construction, property (3) is satisfied, coverage is green and the per-body
readable-source assertion is green. **Every assertion in the module passes.**
This is the module's own `caught` probe at
`:1669-1675` — which it rejects correctly — spelled with a tuple target.

The same holds with a single construction, so the mixed-body precondition is not
required:

```python
def serve(pid, r, declared, requirements, alts):
    plan = QuickstartPlan(plan_id=pid, required=requirements.required_operator_keys)
    refuse_operator_set_divergence(declared=declared, plan=plan)
    for plan in alts:
        out = ProjectionEngine(reader=r).execute(plan=plan)
    return out
```
```
projecting=True names_binder=True per_body_readable=True problems=0  -> SILENT
```
The engine runs every plan in `alts` and the binder saw none of them. The
`with cm as plan:` spelling measures identically. The plain `plan = ...`
rebinding — the one spelling `_assignment` reads — is caught (`problems=1`,
`"runs plan@6, which no refuse_operator_set_divergence call in this body was
handed beforehand"`), which is what makes the gap a spelling gap rather than a
design one.

**Consequence (b) — tripwire (1) is red on correct code, again.** WR-F2(a)'s
charter was exactly this:

```python
def serve(execution, candidate, declared, pair):
    ops = frozenset(declared.required_operator_keys)
    product = ProductLineage(operators_invoked=ops)
    ops, spare = pair
    return run_gates(candidate, engine_resolved=ops)
```
```
-> RED
```
`ops` at line 5 is a tuple element and has nothing to do with line 2, but line 4
bound nothing, so both sides resolve to `declared.required_operator_keys` and the
body is reported as the CR-2 collapse. Augmented assignment behaves the same way
(`ops |= execution.operators_invoked` after an opaque initial binding leaves the
opaque token in force).

**Why this is Critical.** It is the identical outcome CR-F1 carried one round
ago — a check written to close CR-03, routed around by one legal spelling of
ordinary Python, with every assertion in the module green — and it puts back
*both* halves of WR-F2, which `15.1-14-SUMMARY.md`'s threat table records as
`mitigated` without qualification for (a) and `mitigated` for (b). The module's
"What tripwire (2) still cannot see" list names five residuals and does not name
this one, and `_bindings`'s docstring affirmatively states the opposite, so a
reader auditing the module is told the gap is closed.

**Fix — measured before proposing, per the brief.** Extend `_assignment` to
record every binding form, with the unreadable ones recorded as `path=None`
(which `_opaque` already turns into a per-line source token):

```python
def _bound_names(target: ast.expr) -> list[str]:
    if isinstance(target, ast.Name):
        return [target.id]
    if isinstance(target, ast.Tuple | ast.List):
        return [n for e in target.elts for n in _bound_names(e)]
    if isinstance(target, ast.Starred):
        return _bound_names(target.value)
    return []
```

and dispatch `ast.Assign` non-`Name` targets, `ast.AugAssign`, `ast.For` /
`ast.AsyncFor`, `ast.withitem` and `ast.ExceptHandler` to it, binding an
unreadable value. **Measured against the tree with that patch applied:**

```
tripwire (1) problems tree-wide: 0
projecting bodies: 11 (floor 11)
tripwire (2) problems tree-wide: 0
bodies with no readable plan source: []
readable binder sites: 11 (floor 11)
```

and all seven of the module's own probe tests still pass, while the tuple-unpack
and `for`-target shapes above become loud (`problems=1`, naming the right line).
**One caveat I measured and did not solve:** `ast.withitem` carries no `lineno`,
so a naive `getattr(node, "lineno", 0)` records the `with ... as` binding at line
0, which sorts before every other binding and is therefore never "in force" —
the `with` spelling stayed admitted under my patch. The remedy must take the
line from the enclosing `ast.With`/`ast.AsyncWith` statement. Correct
`_bindings`'s docstring in the same change, and add the surviving forms (nested
subscript/attribute targets, comprehension targets) to the limits list.

### WR-02: `test_every_bound_body_has_a_readable_plan_source` asserts `any()`, so one readable binder site in a body licenses any number of unreadable ones

**File:** `tests/products/test_gate_two_call_shape.py:1520-1553`,
`:152-159` (the limits list, which says the property is asserted "per body" and
does not state what `any()` costs)

**Issue.** The five evasion shapes the brief asked about — a factory-built plan,
a plan class imported from outside the scanned trees with unconventional
keywords, a plan whose Protocol members come from a base class, the same from a
mixin, `**kwargs` forwarding — are all **loud** in isolation, and that is the
good news: measured, each gives `per_body_readable=False` and this assertion
fires. But the assertion is `any(...)`, so a body that *also* contains one
compliant readable site absorbs them:

```python

    refuse_operator_set_divergence(declared=declared, plan=good)
    first = ProjectionEngine(reader=r).execute(plan=good)
    bad = CreditProjection(identity=pid, operators=declared.required_operator_keys)
    refuse_operator_set_divergence(declared=declared, plan=bad)

```
```
projecting=True names_binder=True per_body_readable(any)=True
argument_problems=0 floor_contribution=1
```
`bad` is built from the binder's own `declared`, so its binder compares a value
against itself; property (1) is silent because `CreditProjection` (members from a
base class, no `plan_id=`) is not a recognised plan construction. The
factory-built spelling measures identically. The aggregate floor is unaffected —
the body contributes one readable site, so `>= 11` holds.

This is a residual, not a regression: the previous review's own WR-F3 fix snippet
proposed `assert any(...)`, and the implementation matches it. But the limits
list at `:152-159` says the per-body assertion is why the unreadable-`required=`
residual is *"from silent to loud for any body that acquires it"*, which is true
only for a body that acquires it **everywhere**.

**Fix — measured.** The per-call form is green on the tree today; I counted every
binder call in every projecting body:

```
11 projecting bodies, 11 binder calls, 0 unreadable
an all()/per-call assertion would be: GREEN
```

so `assert all(...)`, reported per call with the call's line number, costs
nothing now and closes the composition. If `all()` is judged too tight for a
future body that legitimately has two binder calls, the honest alternative is to
state the `any()` cost in the limits list rather than leave it implied closed.
