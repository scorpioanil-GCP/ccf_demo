## 2. CR-03 — the binder is now read, not spelled

`_names_the_binder` is unchanged and is now explicitly *labelled* as the coverage half. The new
`_binder_collapses` is the argument half, and the two are separate functions behind separate
assertions because collapsing them is the finding.

Three properties, each of which a body naming the binder can violate:

1. **Two arguments, two documents.** The plan handed to the binder must not read its `required=`
   from the same source as the binder's `declared=`. Resolved through the existing identifier-path
   machinery (`_path`, `_resolve`, `_shares_a_source`), so one alias hop and a transparent
   conversion do not evade it.
2. **The plan bound is the plan run.** Every `execute(plan=P)` with a readable `P` must have a
   binder call handed that same `P` at an earlier line.
3. **The binder precedes the engine.** If a body executes a projection at all, some binder call
   must sit before the first execution.

**A fourth shape the review did not name, found by probing and detected rather than exempted.**
The review's `_binder_collapses` sketch, and my first implementation of it, both admitted this:

```python
spare = FooPlan(plan_id='p', required=requirements.required_operator_keys)
refuse_operator_set_divergence(declared=declared, plan=spare)
return ProjectionEngine(reader=r).execute(plan=FooPlan(plan_id='q', required=...))
```

The executed plan is an inline construction, so `_path` yields `None` and property (2) skipped it.
But an inline construction is not an unreadable expression — it is a *certainly* unbindable one: the
plan comes into being inside the call expression that consumes it, so no binder can ever have been
handed that object. That is exactly why 15.1-04-SUMMARY recorded the hoist as **required, not
cosmetic** ("until the plan is a named local there is no statement the call can occupy"), and the
check now enforces the hoist the corrected ruling already demanded.

## 3. WR-01 — `_aliases` terminates by construction

The predecessor grew a shared binding map until nothing changed. On a three-name rotation the
substitution oscillates: `a` settles at `(c,)`, `c` at `(a,)`, and `b` alternates forever. The
`name not in resolved` guard blocks the two-cycle and not the three-cycle.

**Refusing was rejected as the fix.** The review proposes `raise AssertionError` after
`len(bindings) + 1` passes. But `def f(b, c): a = b; b = c; c = a` is legal, executable Python — a
rotation spread over three statements — so refusing it would be **red on correct code**, which is
the sin WR-02 is about, committed in the same commit that fixes it.

Each name is instead resolved independently by walking its own chain while carrying the set of
heads already substituted; a head that reappears ends that walk. Every iteration adds one element
to a set bounded by `bindings`, so termination is structural rather than convergent. On the
rotation each name resolves to itself — terminating, and still three *distinct* sources, so a
cycle cannot manufacture a shared one (asserted). Resolving from the raw first-assignment map
rather than mutating it in place also makes the result independent of dict iteration order.

**The bound is real and the bound itself is tested.** `_within` uses `signal.setitimer` —
a worker thread that never returns cannot be joined and would hang the suite somewhere else, which
is the failure mode under repair. `test_the_wall_clock_bound_is_itself_live` asserts `_within`
fires on a deliberate infinite loop, because a bound that never triggers proves nothing.

**Watched to fail (mutation 5):** the old loop restored →
`test_alias_resolution_terminates_on_a_cyclic_assignment_chain` **FAILED with `_TookTooLong` in
5.44s**, rather than hanging. That is the whole point of the bound.

## 4. WR-02 — a method's return value is out of reach

`_path` no longer collapses `obj.method()` to `("obj",)`. A method is a member of its receiver
exactly as an attribute is, and which member it returns is not something an AST walk knows — so it
returns `None`, joining the helper return value, the container and the dynamic attribute access
already named as limits. The docstring says why the shortcut is *wrong* rather than merely
unimplemented, and two new benign probes hold the line.

**This is not a loosening, and it was measurably a strengthening.** Mutation 6 restored the
collapse and **two** tests failed, the second unexpectedly:

- `test_the_tripwire_detects_the_shape_it_exists_to_refuse` — the false positives return.
- `test_the_binder_argument_scan_is_not_vacuous` — **`10 >= 11` fails**. The missing site is
  `examples/external/00-hello-context/run.py:183`, whose plan class is `fabric.CreditContextPlan`
  — an **attribute** callee. Under the old rule `_path` read that construction as `("fabric",)`,
  so `plan` aliased to `fabric` and the binder's plan source became unreadable. The collapse was
  blinding the new check at one of the two replay sites.

## 5. WR-05, WR-06, IN-05 — decided explicitly

### WR-05 — premise verified and found not to hold; widening NOT adopted

The review's evasion body is `ProjectionEngine(reader=r).execute(pi, perspective=q)`. Checked
against the engine rather than assumed:

```
ProjectionEngine.execute (self, *, plan, perspective, tenant_id, temporal_boundary, ...)
    self POSITIONAL_OR_KEYWORD
    plan KEYWORD_ONLY
```

`plan` is **keyword-only**. That body is a `TypeError` against the SDK's own engine, so the
positional half of the evasion is not reachable, and the proposed fix — widen the detector to
positional form, discriminating on a `perspective` keyword — closes nothing while trading one
naming convention for another and risking sweeping in unrelated `execute` calls.
`WorkflowEngine.execute(workflow, *, execution_id)` was checked in the same pass and passes no
`plan=`, confirming the existing discriminator is sound.

The genuinely surviving hole is narrower than stated: because any body running a projection through
the SDK's engine must pass `plan=`, a non-`Plan`-suffixed class is only invisible if it is also
never executed in its own body — the `resolve_plan` shape. That, and only that, is recorded as a
residual in the module docstring. **Not closed; the finding's stated reproduction is corrected.**

### WR-06 — closed, as part of CR-03

Ordering is not a separate concern from "the plan handed to the binder is the plan that gets
executed"; a binder that runs after the engine has not bound the execution. Enforced twice: by
property (3) generally, and by property (2)'s `call.lineno < execution.lineno` for readable plans.
The assertion docstring that claimed the placement is amended to say ordering **is** now checked
and that **reachability** is the residual — a never-taken branch remains out of AST reach and is
named rather than implied away.

### IN-05 — decided against headroom, with the reasoning recorded

Both floors stay **exactly at the observed count** (9 and 11), and a third is added at 11.

A floor equal to the current count is the **strongest** setting, not the most brittle: headroom is
not slack, it is a licence for that many call sites to disappear with nothing failing to say so —
the silent loss the floor exists to prevent. Lowering either constant would be loosening a check
to buy comfort. Deriving the floor from the example directory count was considered and rejected: a
new example that serves no product would raise the derived floor and make CI red on correct code.

The cost is real and is paid deliberately: a *legitimate* removal presents as red and is fixed by
the identical edit an accidental removal needs, and nothing at the failure site tells them apart.
So the failure message carries the one thing that does — `FLOOR_REMOVAL_INSTRUCTION`, which
requires the removed site to be named in the commit message, making `git log` the discriminator the
constant cannot be. All three floor messages now report found-vs-expected counts and the site list.
