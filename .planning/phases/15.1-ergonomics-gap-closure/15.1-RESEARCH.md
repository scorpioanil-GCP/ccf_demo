## Summary

This phase closes two HIGH defects a post-gate cross-AI review raised against **shipped Phase
15 code**. Both were re-verified here against source rather than accepted from the review
report, per the review's own discipline. The verification changed the shape of **CR-1
materially** and confirmed **CR-2 exactly**, and it produced one finding neither the reviewers
nor the orchestrator had: the currently-reachable bypass is *not* the one the review
described, and it is **worse in one dimension and narrower in another**.

**CR-2 is a clean mechanical rewrite with no new artifact work.** All nine files already read
an authored declaration — `ProductClassDeclaration.required_operator_keys`, parsed from a
`ccf.product-class` artifact — into a local named `declared`, in scope at the `run_gates` call
site. The SDK's own contract docstring
(`src/ccf/controlplane/artifacts.py:506-521`) states that this field exists *precisely* to be
Gate 2's authored side. The examples simply did not wire it that way. No new artifacts, no new
fields, no schema change. See §Per-File Authored-Source Ledger.

**CR-1's bypass is real but is not the one the reviewers described, and the naive form fails
loudly.** `ccf.workflow-definition`, `ccf.agent-definition`, `ccf.task-definition` and
`ccf.prompt-artifact` are **absent from `SDK_ARTIFACT_CLASSES`**
(`src/ccf/deployment/classes.py:79-95`), so `resolve_artifact_class` returns the *open
`DeclaredArtifact` envelope*, not the real contract
(`src/ccf/deployment/classes.py:173-176`). A manifest naming a real workflow-definition
document therefore **raises `ArtifactLoadError` at parse** — verified by execution. What *does*
get through is an **envelope-shaped document that squats the SDK class id**: it registers, it
pins, it enters replay dimension 2, and it binds the Control Plane key to `ccf.workflow-definition`
with no bump check and arbitrary content. Also verified by execution. The `ccf.*` namespace is
not reserved by `resolve_artifact_class`.

**Primary recommendation:** implement `registration: typed | versioned` as ruled, but plan it
as **three coupled changes, not one field** — (1) the manifest contract + committed schema, (2)
admitting the four author-versioned classes into a *separate* SDK-owned resolution set so
`versioned` can resolve the real contract, and (3) a refusal that closes the envelope-squat,
which is the actually-reachable hole. Treat item (3) as in scope: it is the only path by which
an author-versioned class currently enters the Control Plane through the manifest, so a
refusal that does not close it does not close CR-1.

### Does anything out-of-scope become unavoidable?

**No — with one qualification the planner must rule on, stated plainly rather than pulled in
quietly.**

Closing CR-1 as ruled (`registration: typed | versioned` dispatched by `load_and_boot`) requires
the manifest to be able to resolve `ccf.workflow-definition` to the **real** `WORKFLOW_DEFINITION`
contract — otherwise `register_versioned` receives a `DeclaredArtifact`, which carries no
`artifact_version` and raises `TypeError` at `registry.py:422-427`. That means admitting the four
author-versioned classes to *some* SDK-owned resolution set. That is **inside CR-1's scope** (it
is the mechanism the ruling names), but it has two adjacent consequences:

1. It touches `tests/deployment/test_class_lookup.py::test_every_exported_artifact_class_is_manifest_addressable`
   (`test_class_lookup.py:108-118`) — currently asserted only over `ccf.controlplane.artifacts`
   exports, so it does not fail today, but the invariant it encodes ("an SDK class a manifest
   cannot name is a class no adopter can register") now has a second answer.
2. It brushes the **deferred item** recorded at `15/deferred-items.md`: the HTTP `/schema` route
   and `ccf schema export` enumerate `SDK_ARTIFACT_CLASSES`, so six author-versioned classes 404.
   Widening the addressability set changes that route's answer.

**Recommendation:** keep `SDK_ARTIFACT_CLASSES` as-is (it means "typed-registerable") and add a
**second, separate** mapping for versioned-registerable classes, so the route's contract is
untouched and the deferred item stays deferred. This is stated as a recommendation, not a
decision — it is D-IMPL material (Q3 below).

### The consequence the planner must not miss

`build_operator_plan` **does not expand** the required set. `src/ccf/operators/planner.py:119-142`:
`resolved = {key: registry.resolve(key) for key in required_operators}`, then sort. And
`ProjectionEngine.execute` returns `operators_invoked=frozenset(outputs)` where `outputs` is
keyed by `operator.key` over exactly that plan (`src/ccf/projection/engine.py:263-316`).

Therefore, **structurally**: `execution.operators_invoked == frozenset(plan.required_operators())`,
always, in the current SDK. `[VERIFIED: read]`

What this means for the fix:

- Swapping the lineage's source to `frozenset(declared.required_operator_keys)` gives the two
  sides **distinct program provenance** (an artifact field read directly, vs the engine's
  observation of what it ran through registry resolution, dedup and ordering) but a **common
  root** (the same artifact field).
- Gate 2 then becomes falsifiable against **engine/planner/registry defects** — an unregistered
  key, a resolver returning a differently-keyed operator, a plan whose `required_operators()`
  stops echoing what it was constructed with. It does **not** become falsifiable against
  *producer misdeclaration*, because the producer's declaration and the plan's input are the
  same authored value.
- **A reviewer will raise this.** The honest framing, and the one the repo already uses, is the
  A-4 caution recorded at `docs/SURFACE-AUDIT.md` (§5.3, row A-4): "editing the artifact alone
  moves both ends and is **not** detected." Several `tests/examples/test_*_output.py` docstrings
  already say so in those words (e.g. `test_agent_basics_output.py:96-99`,
  `test_artifact_store_output.py:243-245`).
- **The mutation test is what supplies the missing proof.** Criterion 4 asks for exactly this:
  divergence ⇒ refusal. With the mutation test, the claim becomes "the two sides are separately
  computed and the comparison demonstrably bites," which is true and defensible. Without it,
  the rewrite is open to "you replaced a value with a provably equal one."

### Pattern: refusal beside the class registry, not in the contract

**What:** a class-property refusal lives in `ccf.deployment.classes`, is called from
`load_and_boot`'s preflight loop, and raises `ValueError` naming the decision id.
**When to use:** ERGO-18's "refuse an author-versioned class declared `typed`".
**Why here:** `ManifestEntry`'s own docstring states the reason
(`src/ccf/controlplane/artifacts.py:602-608`): "That check lives beside the class registry
rather than here because it is a property of the class, and because **this module cannot import
`ccf.deployment` without closing an import cycle**." A validator on `ManifestEntry` is therefore
**structurally unavailable**. `[CITED: src/ccf/controlplane/artifacts.py:606-608]`

**Example (the shipped shape to copy):**

```python
# Source: src/ccf/deployment/classes.py:123-149
def refuse_role_the_sdk_fixes(class_id: str, role: ArtifactRole) -> None:
    fixed = SDK_ARTIFACT_ROLES.get(class_id)
    if fixed is not None and role != fixed:
        raise ValueError(
            f"artifact class {class_id!r} is role {fixed!r} and the manifest"
            f" declares {role!r}; the SDK fixes this class's role because the"
            " other choice would put raw event data into Decision Replay"
            " dimension 2 (D-IMPL-80) — correct the manifest entry"
        )
```

Called from `src/ccf/deployment/manifest.py:275-276`, in a loop over every entry, **before**
`_preflight_backend` and before any document is read.

### Pattern: refusals are returned values, not exceptions

```python
# Source: src/ccf/controlplane/registry.py:365, 440-449
def register_versioned(...) -> str | RegistrationRefusal:
    ...
    def _refused(refusal: RegistrationRefusal) -> RegistrationRefusal:

                     resolved=False, actor=actor, artifact_class=artifact_class.class_id)
```

`load_and_boot` currently has no branch for this. A dispatcher that assigns the result to
`version` without checking would put a `RefuseUnbumpedChange` object into `ArtifactPin.version`
(a `str` field) — mypy `--strict` catches it, but the plan must specify the intended behavior.
**Recommendation:** raise loudly, in the two-phase spirit — but note the current design registers
sequentially and accepts partial state on failure (`manifest.py:216-221`), so a refusal at
entry seven leaves entries one through six registered. That is consistent with the shipped
posture and does not need re-deciding.

### Anti-patterns to avoid

- **A `ccf.deployment` helper that builds `ProductLineage` or calls `run_gates`.** Refused by

  `tests/products/test_gate_independence.py::test_no_deployment_module_names_the_gate`, which
  bans the identifiers `run_gates`, `ProductLineage`, `engine_resolved` from every file under
  `src/ccf/deployment/`.
- **A `ResolvedPins` accessor whose name implies selection.** `pins.py:9-29` states the
  constraint; `tests/deployment/test_manifest.py:314` pins the public method set exactly. Any
  bump-evidence surface must respect this — see Q2.
- **Authoring a literal operator tuple in an example driver or a test** to manufacture Gate 2
  independence. Violates the No-Hardcoding Rule (§6.4), CI-enforced over `examples/` and
  `tests/` (D-IMPL-78).
- **Silently rewriting a manifest entry to the correct registration mode.** The role refusal's

## Common Pitfalls

### Pitfall 1: Writing the CR-1 test against the reviewed description instead of the code
**What goes wrong:** a test asserts that a manifest naming a real `workflow-definition.yaml`
"silently registers via `register_typed`". It fails — the current code raises `ArtifactLoadError`.
**Why it happens:** the review and the ROADMAP both describe CR-1 that way; the orchestrator's
re-verification did not go as far as parsing a real document through the envelope.
**How to avoid:** the refusal test must exercise **both** shapes — the real document (already
refused, assert the *message* names the registration mode, not just the parse failure) and the
envelope squat (currently admitted, must become refused).
**Warning sign:** a test that passes before the fix is written.

### Pitfall 2: `register_versioned` receiving a `DeclaredArtifact`
**What goes wrong:** `TypeError: artifact for class 'ccf.workflow-definition' declares no string
artifact_version` (`registry.py:422-427`).
**Why it happens:** `registration: versioned` dispatched without first making the class resolve
to its real contract.
**How to avoid:** the versioned-registerable mapping and the dispatch land in the **same wave**,
or the dispatch is dead on arrival.

### Pitfall 3: `ControlPlaneProtocol` does not declare `register_versioned`
**What goes wrong:** mypy `--strict` fails on `registry.register_versioned(...)` where
`registry: ControlPlaneProtocol` (`manifest.py:180`).
**Why it happens:** the Protocol at `registry.py:154-187` lists five methods and this is not one.
**How to avoid:** this is **Q1**, a genuine SDK-contract decision, not an implementation detail.
Widening a Protocol changes what a remote Control Plane must implement — CLAUDE.md §11 says the
obligations are on the surface "precisely so a remote plane cannot conform while quietly
dropping them."

### Pitfall 4: The refusal object silently becoming a pin version
**What goes wrong:** `RefuseUnbumpedChange` assigned to `ArtifactPin.version`.
**Why it happens:** `register_versioned` returns `str | RegistrationRefusal`; `register_typed`
returns `str`. A copy-paste dispatch misses the union.
**How to avoid:** explicit `match`/`isinstance` in the dispatcher, and a test that authors a
changed-content-unbumped document and asserts a loud failure.

### Pitfall 5: 163 manifest entries and a required-no-default field
**What goes wrong:** a required field turns every example red at once, across eleven manifests
and eleven drivers, plus `tests/deployment/conftest.py`'s fixture tuples.
**Why it happens:** the `role` precedent (`artifacts.py:596-601`) argues for required-no-default,
and it is the better governance posture.
**How to avoid:** this is **Q4** — rule it before writing waves. If required, budget a wave for
the mechanical manifest edit and run `make schema-headers` and `make examples` after it. If
optional-defaulting-to-`typed`, the phase is smaller but the SDK is choosing a
replay-dimension-2-adjacent default on the adopter's behalf, which is the exact objection
D-IMPL-80 raised against defaulting `role`.

### Pitfall 6: Naming a surface-changes fragment `15.1-…`
**What goes wrong:** `docs/surface-changes/15-*.md` does not match it; the drift gate cannot be
satisfied by the fragment. See §Surface & Schema Regeneration.

### Pitfall 7: "Fixing" the two replay-leg sites that are already correct
**What goes wrong:** `06-decision-replay/run.py:361` and `external/00-hello-context/run.py:212`
already build lineage from the replay record. Rewriting them to read `declared` would *remove*
independence, because the record is a genuinely separate object.

### Pitfall 8: Assuming `execution.operators_invoked` can differ from the plan's declaration
**What goes wrong:** a test asserts the rewrite "makes the gate catch producer misdeclaration."
It cannot, in the current SDK — see §CR-2 "the consequence the planner must not miss".
**How to avoid:** claim exactly what the mutation test proves, and record the A-4-style caution.

### Pitfall 9: Touching `tests/examples/test_ext00_hardening.py`
**What goes wrong:** re-opens a module 15-20 was forbidden to modify, part of the D-GATE-15
ERGO-16 ruling. Read it, run it, do not edit it.

### Q1 — Does `ControlPlaneProtocol` gain `register_versioned`? *(gates the CR-1 fix)*

**RESOLVED: D-IMPL-82** — Dave widened `ControlPlaneProtocol`, as recommended; the narrow
second Protocol and the narrowing to the concrete `ControlPlaneRegistry` were both rejected on
the record, and the FABR-07 remote-plane obligation is the accepted consequence.

- **What we know:** `load_and_boot(registry: ControlPlaneProtocol)` (`manifest.py:180`). The
  Protocol declares `register`, `register_typed`, `resolve`, `resolve_latest`, `audit_events`
  (`registry.py:167-187`) — **not** `register_versioned`. Its docstring says the obligations are
  on the surface "precisely so a remote plane cannot conform while quietly dropping them."
- **What's unclear:** widening the Protocol makes `register_versioned` mandatory for every
  Control Plane implementation, including a remote one (FABR-07 extension point). Narrowing
  `load_and_boot` to accept `ControlPlaneRegistry` concretely would break the Protocol posture
  CLAUDE.md §11 mandates. A third option — a narrow `VersionedRegistrationProtocol` that
  `load_and_boot` requires only when a manifest declares `versioned` — preserves both but adds a
  type.
- **Recommendation:** widen `ControlPlaneProtocol`. The D-05 bump check is a governance
  obligation, and a remote Control Plane that cannot run it should not be able to conform — which
  is the docstring's own argument. But this is Dave's call: it is a public Protocol change.
- **Decision id:** propose `D-IMPL-82`.

### Q2 — Where does the bump evidence land?

**RESOLVED: D-IMPL-83** — a plain field on `ArtifactPin`, no accessor on `ResolvedPins`, and the
audit log stays the primary evidence; the "no-growth constraint forbids methods that select, not
fields that record" reading was adopted as recommended.

- **What we know:** codex asked for "the version/hash bump evidence in the returned
  `ResolvedPins` **or adjacent audit structure**". `ArtifactPin` carries `(key, version,
  class_id)`. `ResolvedPins` is under an explicit no-growth constraint (`pins.py:9-29`) and
  `tests/deployment/test_manifest.py:314` pins its public method set to exactly one.
  `register_versioned` already audits every outcome with `action="register_versioned"` and
  `resolved=True|False` (`registry.py:487-494`), so the evidence **already exists in the audit
  log** — which is how `test_the_author_versioned_definitions_kept_their_bump_check` reads it
  today (`test_workflow_hitl_output.py:761-772`).
- **What's unclear:** whether adding a field (e.g. `registration: str` or `bump_verified: bool`)
  to `ArtifactPin` counts as growth `pins.py` forbids. Reading it closely, the constraint is
  about **methods that select**, not about **fields that record** — `class_id` is already a
  recorded fact of the same kind.
- **Recommendation:** record the registration mode on `ArtifactPin` as a plain field; do **not**
  add a method to `ResolvedPins`; treat the audit log as the primary evidence and the pin field
  as the convenience. Note this is additive to a `CCFContract`, so it changes the pin set's
  content hash and therefore `test_two_loads_of_one_manifest_produce_an_identical_pin_set`
  (`test_manifest.py:86`) — which still passes (both loads change identically) but should be
  re-read.
- **Decision id:** propose `D-IMPL-83`.

### Q3 — How wide is the refusal? Four class ids, or the `ccf.` namespace?

**RESOLVED: D-IMPL-84** — the namespace-wide refusal, as recommended: `resolve_artifact_class`
refuses an envelope resolution for any `ccf.`-prefixed id the SDK does not own, and the entry
records explicitly that this reserves the `ccf.` prefix as a design statement rather than a bug
