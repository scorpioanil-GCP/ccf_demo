# Phase 15.1 Plan 02: Declared Registration Mode Summary

The registration path is now a declared property of each manifest entry rather than a
convention the examples happened to follow: `registration: typed | versioned` is required
with no default, `load_and_boot` dispatches on it, and the mode each entry travelled is
recorded on its pin.

## What Was Built

**`RegistrationMode` and two required fields (Task 1, `fb36286`).**
`RegistrationMode = Literal["typed", "versioned"]` sits beside `ArtifactRole` in
`src/ccf/controlplane/artifacts.py` with the same `#:` comment convention and is exported.
`ManifestEntry.registration` is required with no default; its attribute docstring carries
D-IMPL-85's own reasoning — either default would have the SDK deciding the *governance
path* by silence — rather than restating `role`'s replay-dimension-2 argument, and it names
`refuse_registration_the_sdk_fixes` (plan 15.1-03) as the class-property half, for the
import-cycle reason `role` already records. `ArtifactPin.registration` is a **recorded
fact** in the sense D-IMPL-83 ruled: the module's no-growth constraint forbids methods that
select, not fields that record, so `ResolvedPins` gained no accessor. The docstring states
plainly that the audit log remains primary evidence and that the pin-set content hash
changes as an accepted consequence.

**Dispatch, and the refusal that must not become a version (Task 2, `8ac0894`).**
`load_and_boot`'s phase two branches on `entry.registration`. The `versioned` branch
narrows `register_versioned`'s `str | RegistrationRefusal` return with an explicit
`isinstance` check **before** any assignment, and a returned refusal becomes a `ValueError`
naming the key, the class id and the refusal type. There is no fallback to `register_typed`
— the dispatcher's comment says so by name, because a fallback is the bypass returning in a
new costume. The `TypeError` a non-author-versioned class raises inside `register_versioned`
surfaces unhandled and is documented in the `Raises:` section as what an adopter sees. The
"What this call does **not** do" paragraph is untouched; this plan does not move the
abstraction line.

**163 entries, the schema, and the standing refusal (Task 3, `9a0fe6f`).**
Every deployment-manifest document in the tree was found by parsing, not by memory: 163
entries across 11 documents, matching the research counts file for file. `make schemas`
regenerated `docs/schemas/ccf.deployment-manifest.json` — `registration` in
`$defs.ManifestEntry.required`, the two-value enum in `properties` — and the JSON was not
hand-edited. `ARTIFACT_SET` in `tests/deployment/conftest.py` is now 6-tuples with every
unpacking site updated, and the module docstring says the fixture shows `registration` as
explicitly as it shows `role`. `test_a_manifest_entry_naming_no_registration_is_refused`
sits directly beside the `role` refusal it copies, under the renamed
`# --- (8) role and registration are required ---` block.
