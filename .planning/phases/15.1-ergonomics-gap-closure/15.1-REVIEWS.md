### F-1 — the package docstring still asserted the corrected-away claim

**Reviewer:** cursor (finding 3). **Disposition: `blocking` — CONFIRMED, CLOSED IN
PHASE.**

**Verified at source.** `src/ccf/deployment/__init__.py:71-73` read, verbatim:

> Lineage strict equality (whitepaper §7.6, INV-CH7-47) is a real check precisely
> because those two values arrive from two independent sources.

That is the exact claim ROADMAP Criterion 5 requires corrected — "every site
asserting that it compares two independently authored sets is corrected". It sits
in `/src`, in the package docstring of the very package this phase's binder lives
in, and it is rendered into the published API reference.

**Why it was missed, which matters more than the miss.** Plan 15.1-09 swept for
the phrase **"independent witness"** — the *engine-as-witness* spelling — and
corrected nine sites with it. This site uses a different spelling of the same
over-claim: **"two independent sources"**, the *two-inputs-to-the-gate* framing.
One over-claim, two vocabularies; a sweep keyed to one vocabulary found one of
them. This is the same class of defect as §6.3 item 2 in the audit: a token search
standing in for a claim search.

**Closed.** Rewritten to state assembly-path integrity, name the engine as a
faithful transcriber with the single-loop mechanism, cite D-IMPL-86 and the
D-IMPL-57 correction, and point authorable drift at the binder. The D-15A
abstraction line itself is **unchanged and now better argued**: a helper deriving
both arguments from one input would leave the gate nothing to compare *at all* —
not even a transcription.

### F-6 — preflight registration refusals emit no audit event

**Reviewer:** cursor (finding 7). Independently noticed by this executor while
verifying audit-by-construction; gemini also raised it, on a fabricated citation
(§1.1). **Disposition: `advisory` — CONFIRMED, carried.**

**Verified at source.** `ControlPlaneRegistry.register_versioned` audits **both**
outcomes — the `_refused()` helper records `action="register_versioned",
resolved=False` before returning every refusal, and success records `resolved=True`
(`src/ccf/controlplane/registry.py:471-479`, `:518-525`). `register_typed` audits
on success (`:379`). But `refuse_registration_the_sdk_fixes` and
`resolve_artifact_class`'s namespace reservation only **raise**
(`src/ccf/deployment/classes.py`), called at `manifest.py:312` with no `_record`.

**Why advisory rather than blocking.** These refusals fire in preflight, before any
document is parsed and before anything is registered — `15.1-03` asserts
`registry.audit_events() == ()` and `registry.versions(key) == ()` for the squat
case. No state changes, and boot aborts with a raised `ValueError`, so there is no
unrecorded *action* — only an unrecorded *rejection of an attempt*. Audit-by-
construction protects against unrecorded actions that changed state, and none did.

**But the asymmetry is worth Dave's word** and is carried: the SDK audits refusals
at the registry seam and not at the manifest seam. If "every refusal on the
registration path" is meant to include preflight, an audit event should be emitted
before the raise; if audit means registry mutations only, that should be stated.
Carried to Phase 16.
