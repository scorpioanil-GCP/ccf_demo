# Phase 15.1 Plan 05: Design E2 at Examples 00, 01 and 02 Summary

**Three of CR-2's nine sites are closed: the product's lineage claim now comes from the
product-class declaration, the plan's operator set from a separately authored
`ccf.projection-requirements` document, and the binder between them refuses — observed to
fire from a one-key edit at all three examples, from either document.**

## What changed, in one shape repeated three times

Each of the three drivers received the identical five-part rewrite, and each rewrite is
five things rather than one because the defect had five faces:

1. **A new artifact document.** `artifacts/projection-requirements.yaml`, `$schema`-headed at
   `ccf.projection-requirements`, with `plan_id` and `required_operator_keys` copied
   **verbatim** from where each value was already authored. Copying verbatim was the point:
   this plan changes where values are *read from*, not what they *are*, so no example output
   moved and no `expected.yaml` needed touching.
2. **A manifest entry**, `role: register` / `registration: typed`, with the reason stated at
   the entry: the document governs *what the projection does*, which is what the fabric is
   permitted to do, so it belongs in the pin set and in Decision Replay dimension 2 beside
   the product-class declaration it is bound to.
3. **The plan hoisted to a named local.** This is the load-bearing part 15.1-04 flagged and
   it was true at all three sites, not only the quickstart: every driver constructed its plan
   *inline as the `plan=` keyword argument* of the `.execute(...)` call, so the interval the
   corrected D-IMPL-86 placement names was empty — there was no statement for the binder to
   occupy because the plan did not exist as a value any statement could observe.
4. **The binder call**, `refuse_operator_set_divergence(declared=declared, plan=plan)`, on the
   line between the hoisted assignment and the engine construction.
5. **`lineage.operators_invoked=frozenset(declared.required_operator_keys)`** — the Control
   Plane claim, never `execution`.

## The comment corrections, which are as load-bearing as the code

The plan is explicit that the comments matter as much as the lines, and it is right: CR-2 was
a *claim* before it was a defect. Every driver said `engine_resolved` came from "a second,
independent source", which is false and is CR-2 stated as fact.

The replacement does not delete the claim and leave a hole. It states what Gate 2 **does**
verify — **assembly-path integrity**: the claim transcribed into the Contract equals the
engine's execution of the plan — and then says plainly why that is not independent witness:
the engine builds `operators_invoked` and `steps` in one loop over the same operator plan, so
no return path exists where invoked ≠ planned. Each comment then says where authorable drift
*does* fail: upstream, at the binder call. And each says, in so many words, that **Gate 2 does
not catch a producer misdeclaring** — the plan's explicit instruction not to oversell.

The plan-class docstrings were corrected on the same principle: `required` now comes from the
projection's own document, `required_operator_keys` is the product's claim, and the two are
held together by the binder.

Example 02's concrete detail was kept and re-pointed rather than dropped. Its module docstring
still says **three operators, not four**; what changed is that *two* documents now declare
those three keys and have to agree on which three, and `run` refuses before it projects if
they do not. The manifest's own top note carries the same correction.
