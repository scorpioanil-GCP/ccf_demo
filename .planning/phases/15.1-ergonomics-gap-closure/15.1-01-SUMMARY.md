## Decisions Made

- **`ControlPlaneProtocol` is recorded as `Change type: behavior`, not `reshaped`.** See Deviations, item 1.
- **Q1–Q5 map one-to-one onto D-IMPL-82…86.** The plan predicted "more than one question maps to the same entry in at least one case". Reading all five entries in full, that is not so: each of D-IMPL-82, -83, -84 and -85 opens by naming Q1, Q2, Q3 and Q4's question verbatim. Q5 — which research itself classed as "Not a `D-IMPL` — an editorial call" — is the one the ruling took out of editorial hands, and its marker names **D-IMPL-86 and its 2026-08-05 correction**, satisfying the plan's other hint that one question maps to the correction rather than the original ruling.
- **`tests/cli/test_schema_export.py` was not edited.** The plan's instruction was conditional ("If any of those tests pins a count or an exact set"). None does: `test_the_route_serves_a_schema_for_every_owned_class`, `test_the_list_verb_names_every_owned_class` and the committed-schema assertions all enumerate `SDK_ARTIFACT_CLASSES` at runtime, and the only length assertion is `len(committed) >= len(SDK_ARTIFACT_CLASSES)`. All 41 tests pass unchanged, which is the stronger evidence that a manifest-addressable class is served by construction.
- **The round-trip case landed in Task 2, not Task 3.** Task 3 lists it, but Task 2's own `<verify>` cannot pass without it — `test_every_sdk_artifact_class_has_a_round_trip_case` asserts `set(SDK_ARTIFACT_CLASSES) <= set(_IDS)`, and the new negative case calls `_document_for("ccf.projection-requirements")`. Task 3's acceptance criteria are unaffected.
- **The fixture operator key is deliberately not shared.** `ccf.projection-requirements`'s round-trip document declares `fixture-plan-operator` where `ccf.product-class`'s declares `fixture-operator`. A fixture that made the two agree by copy would teach exactly the authoring shape E2 exists to make visible.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 — Bug] `ControlPlaneProtocol`'s surface-log entry recorded as `behavior` rather than the plan's `reshaped`**

- **Found during:** Task 3 (writing the surface-change fragment)
- **Issue:** The plan specifies `ccf.controlplane.registry.ControlPlaneProtocol` as `reshaped`, `Public surface: true`. `docs/surface/v0.2-surface.json` records that name as `{"kind": "class", "shape": "(*args, **kwargs)"}` — a Protocol's shape is its `__init__`, so adding a member moves nothing the manifest can see. `tools/dump_surface.py --report` confirms `reshaped (0)`. A `Public surface: true` entry whose `Change type` is anything but `behavior` must have a matching diff line, per `tests/test_surface_completeness.py::test_every_public_log_entry_has_a_matching_diff_line` (assertion 3, `_DIFF_EXEMPT_CHANGE_TYPES = frozenset({"behavior"})`). As written, the fragment would have made that always-on test red, and the plan's own verification block requires it green.
- **Fix:** Classified the entry `Change type: behavior`, `Public surface: true`, and said why in the entry's `Why` field. This is precisely the case the `behavior` class exists for per `docs/surface-changes/README.md` — "an exported Python name whose observable behavior changed" that a signature diff is "structurally incapable of seeing". The `Migration` text the plan specified is unchanged: a non-reference Control Plane implementation must now provide `register_versioned` (D-IMPL-82, FABR-07 obligation). The alternative — `Public surface: false` — was rejected as dishonest: `ControlPlaneProtocol` *is* public Python API, and misclassifying it would have used the classification as the escape hatch the README forbids. `_REQUIRED_BEHAVIOR_SURFACES` is a required-members set, not an allowlist, so adding a behavior entry needs no change there.
- **Files modified:** `docs/surface-changes/15.1-01-projection-requirements-and-protocol.md`
- **Verification:** `tests/test_surface_completeness.py` and `tests/test_surface_drift.py` pass; `make ci-core` green.
- **Committed in:** `d3f4162` (Task 3 commit)
