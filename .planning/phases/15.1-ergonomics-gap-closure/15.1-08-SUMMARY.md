## Task 1 — the Gate 2 call-shape tripwire (D-IMPL-86 element 5)

`tests/products/test_gate_two_call_shape.py`, 702 lines, structured after
`tests/products/test_required_operators_guard.py`: module-level constants, a receiver helper with
alias tracking to a fixed point, runtime-assembled probe bodies, and asserted minimum-match floors.

**What it refuses.** Within one lexical body, a `run_gates` call whose `engine_resolved` keyword
resolves to some identifier path, paired with a `ProductLineage` construction whose
`operators_invoked` keyword resolves to the same path (or to a prefix of it).

**Three design choices worth naming, each of which prevents a red-on-correct-code check:**

1. **Identifier *paths*, not bare roots.** `_path()` returns
   `("execution", "operators_invoked")`, not `"execution"`. The G-B guard's `_receiver_name`
   returns the *attribute* (`node.attr`), which is the right answer for a `.keys()` receiver and
   the wrong one here. A leftmost-`ast.Name` root would have collapsed `self._declared` and
   `self._resolved` to `self` and flagged two genuinely different values as one source.
   `_shares_a_source` compares by prefix, so `resolved` and `resolved.keys` are one value while
   `self._declared` and `self._resolved` stay two.
2. **One body means one body.** `_scope_nodes` walks a scope without descending into nested
   `FunctionDef` / `AsyncFunctionDef` / `ClassDef` / `Lambda`. `ast.walk` from a class node would
   pair a `ProductLineage` built in one method with a `run_gates` call in another and report a
   collapse that is not there. `test_the_tripwire_does_not_pair_across_two_bodies` asserts this
   explicitly.
3. **Set conversions and `cast` are transparent; helper calls are not.** `frozenset`, `set`,
   `tuple`, `list`, `sorted` and `typing.cast` are unwrapped, so wrapping one side is not an
   evasion. Any *other* callee returns `None` — a helper's return value is out of reach, and the
   docstring says so rather than guessing.

**`SCANNED_TREES = ("src", "runtime", "examples")`**, with `tests` excluded and the G-B guard's
reason copied at `:110-118`: a test may legitimately build a deliberately-tautological
construction to prove a guard fires, and Task 3 of this plan is one of the places that happens.

**The docstring is written as a tripwire, not a wall**, in
`test_required_operators_guard.py:47-58`'s register. It contains `D-IMPL-86` (10 occurrences) and
the word `tripwire` (18), and it states what cannot be caught in four parts: a value arriving
through a helper's return value; through a container; through dynamic attribute access; and —
citing D-IMPL-86 — that **no AST gate can distinguish an authored literal from a transcribed
one**, which the D-GATE-15 second amendment *strengthened* from an advisory to a structural limit.
The claim supported is "the shape CR-2 found at nine sites, and the obvious evasions of it",
never "impossible to write".

## Task 2 — the binder-coverage check, and the forward reference

### The check

The second tripwire in the same module: **every lexical body under `examples/` that constructs a
projection plan, or runs one through `ProjectionEngine(...).execute(...)`, must name
`refuse_operator_set_divergence`.**

`BINDER_SCANNED_TREES = ("examples",)`. The docstring states the honest scope rather than implying
more: the binder returns `None` by contract, so **nothing observable at runtime proves the call
happened** — no product field, no pin, no audit event, and a deployment that omits it produces
byte-identical output. An AST check is the only mechanism available, and this one asserts the call
is *named*, not that it was reached. Nothing holds an adopter's deployment to calling it at all;
that is D-IMPL-86 (correction, 2026-08-05)'s residual, carried to Phase 16.

**Granularity is the lexical body, not the file** — `examples/06-decision-replay/run.py` and
`examples/external/00-hello-context/run.py` each carry two plan-construction sites, and a
file-level check would let one of the two go unbound while the file still passed.

**The trigger admits both projecting shapes, and this is the plan's most load-bearing correction.**
15.1-07-SUMMARY's forward note warned that an AST check requiring the binder call and the `execute`
call in one body would be **red on two correct sites**:
`examples/06-decision-replay/run.py:366` (`GridReplayEnvironment.resolve_plan`) and
`examples/external/00-hello-context/run.py:183` (`HelloReplayEnvironment.resolve_plan`) both
construct a plan and *return* it — the engine call happens inside `ccf.replay.engine.replay`. Both
were read in source and confirmed. The trigger is therefore

- `<Something>Plan(..., required=...)` — a plan construction, **or**
- `....execute(plan=..., ...)` — a projection execution.

The `plan` keyword is what separates a projection execution from a workflow one:
`engine.execute(workflow, execution_id=...)` in examples 05 and 06 passes none and is not swept in
(asserted by the last probe in `test_the_binder_tripwire_detects_a_projection_that_skips_it`).

## Decisions Made

### 1. The plan's `grep … == 0` framing is not used, and would have been wrong if it had been

The prior-wave briefing flagged that
`grep -c "operators_invoked=execution.operators_invoked" == 0` is not met across `examples/` and
**must not be**: in eight of the nine example files a second, non-lineage occurrence is the
demonstration dataclass's field carrying the *engine's* resolution to the test module, which is
exactly what turns
`assert result.product.lineage.operators_invoked == result.operators_invoked` from a tautology
into a two-source comparison.

**No check in this plan uses that grep, in either direction.** Tripwire (1) matches
`ProductLineage(...)` constructions on AST nodes, so those eight demonstration fields are
structurally invisible to it — a `ReplayDemonstration(operators_invoked=execution.operators_invoked, …)`
is not a `ProductLineage` and is never considered. Confirmed by running the tripwire over the tree
as-is: 9 gate call sites, zero violations. The substantive check the briefing names,
`grep -n "ProductLineage(" -A 2 examples/`, is the property tripwire (1) enforces structurally.

Recorded for plan 15.1-10, which runs the `== 0` grep at phase close: expect **8 lines**, none of
them a `ProductLineage` construction. This is 15.1-07-SUMMARY's Decision §1 restated with a second
independent confirmation.

### 2. Tripwire (2) triggers on plan construction, not on plan execution

15.1-07-SUMMARY's forward note is the whole reason. Requiring the binder and the `execute` call in
one body would have been red on `GridReplayEnvironment.resolve_plan` and
`HelloReplayEnvironment.resolve_plan`, which are correct. Excluding non-executing bodies would
have left both uncovered. Triggering on *either* signal covers all eleven and flags none, and
mutation 5 above proves the coverage is real rather than nominal.

### 3. Task 2's check shipped in Task 1's commit

The binder-coverage check lives in `tests/products/test_gate_two_call_shape.py` — Task 1's file —
and the module was written in one pass, so the check landed in `7195c5c` rather than in a commit of
its own. Task 2's commit `e397f42` therefore carries only the `test_gate_independence.py` docstring
amendment. Stated rather than smoothed over: the plan's task boundaries and this plan's commit
boundaries do not line up 1:1 for that file.

### 4. Both halves of Task 3 watched by mutating this module, not `gates.py`

The established practice (15.1-04) forces the *mechanism* in each direction. Here that would mean
editing `src/ccf/products/gates.py`, which the concurrently-running sibling plan 15.1-09 owns. The
equivalent observation was made from this module's own inputs instead — removing the perturbation
from the refusal test and adding it to the admission test — which demonstrates the same thing this
module is responsible for: that each assertion depends on the divergence rather than on the gate
being uniformly one thing. Mutations 6 and 7 above.

### 5. `sorted(claimed)[0] + suffix` rather than a literal key

The perturbing key had to be outside the deployment's declared set and derived from it.
`sorted(claimed)[0]` makes the derivation deterministic (so the test is not order-dependent on a
frozenset's iteration) and the suffix is test vocabulary that could not name a registered operator.
The result is asserted outside the set before use, so the derivation cannot silently stop
perturbing if the example's keys change.
