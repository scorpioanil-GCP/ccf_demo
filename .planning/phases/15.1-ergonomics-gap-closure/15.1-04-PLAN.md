It raises `ValueError` when
`frozenset(declared.required_operator_keys) != frozenset(plan.required_operators())`. The
message names the plan id, both sets, the symmetric difference, and D-IMPL-86, and it is
refuse-never-repair: the binder does not choose which document is right, because only the
deployment's author knows.

Return `None`. Do **not** return the frozenset, and do not offer a variant that does. A binder
that handed back the declared set would put the SDK in the position of supplying one of Gate 2's
arguments, which is the D-15A line `cinv02-deployment-gates` holds and the exact shape this
phase exists to close. Say that in the module docstring, in the negative, so the line is legible
from the surface rather than only from the guard — the pattern `src/ccf/deployment/manifest.py`
already uses.

The module docstring carries design E2's argument at the point of enforcement:

- What the binder is: element (3) of D-IMPL-86's design E2, SDK-defined mechanism (CLAUDE.md §11
  requires an SDK extension to cite this document, not the whitepaper).
- What it binds: the product-class artifact's `required_operator_keys` — the Control Plane
  **claim**, which fills `lineage.operators_invoked` — against the plan's own
  `required_operators()`, which under E2 comes from the separately authored
  `ccf.projection-requirements` artifact. Two documents, one comparison.
- Why the comparison is necessary: without it, the two documents are kept in sync by hand with
  no mechanism binding them, which was the standing objection to a second artifact.
- What it is **not**: it is not Gate 2. Gate 2 compares the claim transcribed into the Contract

- The residual, in D-IMPL-86's own words: a deployment that reads one artifact into the other
  still collapses this check, so dual authorship remains convention-assisted at the authoring
