## Summary

Phase 15.1 does the thing it set out to do: `ManifestEntry.registration` is required
with no default, `load_and_boot` dispatches on it, `refuse_registration_the_sdk_fixes`
and the `ccf.` reservation refuse the shapes CR-1 named, and
`refuse_operator_set_divergence` compares two genuinely separate authored documents
as sets and refuses without repairing. `tests/deployment/test_binder.py` is a good
piece of work — the admit/refuse pair, both subset directions, and the
`_DetachedPlan` case that justifies comparing against `plan.required_operators()`
rather than the second artifact all discriminate.

The defects are concentrated in three places, and two of them are the phase's own
signature failure mode recurring one seam further up.

1. **The binder tripwire admits the collapse it exists to prevent.**
   `tests/products/test_gate_two_call_shape.py` asserts only that
   `refuse_operator_set_divergence` is *named* in a projecting body. A body that
   builds its plan with `required=declared.required_operator_keys` and then hands
   that plan to the binder passes — and that binder call compares a value against
   itself, which is CR-2 exactly, at the seam this phase created to close CR-2.
   The check is AST-visible and the module already contains the machinery
   (`_path`, `_shares_a_source`) that would catch it. No live instance exists today;
   the defect is that nothing stops the next one. (CR-03)

2. **The `register_typed` walkaround is three sites, not one.** The known residual
   names `examples/05-workflow-hitl/run.py`. `examples/06-decision-replay/run.py:661`
   and `examples/08-e2e-demo/run.py:959` do the same thing to the same class, and
   example 05's own comment claims the opposite of what its code does. (CR-02)

3. **`load_and_boot` will read any file the manifest names**, including absolute
   paths and `../` escapes, contradicting its own documented contract; the content
   is handed back on `BootedFabric.artifacts` and, on a `register` entry,
   content-hashed into Control Plane state and replay dimension 2. Verified by
   execution. (CR-01)

Alongside those: a non-terminating loop in the tripwire's alias resolver that hangs
`pytest` on cyclic local assignments, a false positive in the same module that
contradicts its own stated design rule, and two example tests whose new docstrings
claim a discriminating power the assertion does not have.

Everything below was verified against source; where I could not construct the
failing case I say so and classify Info.

`make ci` being exit 0 does not contradict any of these. CR-01 and CR-02 are
behaviours the suite has no test for. CR-03, WR-05 and WR-06 are gaps *in* the
suite — a gap cannot fail itself. WR-01 needs source no file in the tree contains
yet. WR-02 needs a call shape no file in the tree uses yet. WR-03 is a docstring

## Critical Issues

### CR-01: `load_and_boot` reads arbitrary paths a manifest names — absolute and `../` escapes

**File:** `src/ccf/controlplane/artifacts.py:761-771` (the only `path` validator),
`src/ccf/deployment/manifest.py:319-324` (the read)

**Issue:** `ManifestEntry._path_is_a_name_not_a_pattern` rejects only the glob
characters `*`, `?`, `[`. It does not reject an absolute path and does not reject
`..`. `load_and_boot` then does:

```python
root = manifest_file.parent
document = (root / entry.path).read_text(encoding="utf-8")
```

`pathlib` discards `root` when `entry.path` is absolute, so `path: /etc/passwd`
reads `/etc/passwd`; `path: ../../elsewhere.yaml` escapes the manifest's directory.
This directly contradicts `load_and_boot`'s own `Args:` docstring at
`manifest.py:255-258`: *"Every entry's `path` resolves relative to **this file's
own directory**, never the process's working directory — a deployment's artifact
set must not depend on where a script was launched from."*

Verified by execution against a real fixture deployment: a manifest entry naming an
absolute path outside the deployment root parsed, booted, and returned the outside
file's contents to the caller:

```
READ SUCCEEDED, artifact returned to caller:
    semver='1.0.0' class_id='acme.leak' declaration={'aws_secret': 'AKIA-TOP-SECRET-9999'}
```

Any YAML-parseable file lands on `BootedFabric.artifacts`; on `role: register` it is
additionally content-hashed into the Control Plane and therefore into Decision Replay
dimension 2. On a non-parseable file the `ArtifactLoadError` carries the offending
input, which is a disclosure path of its own.

This hole predates Phase 15.1 — but it belongs in this review for two reasons. The
same preflight loop and the same contract class are what 15.1 edited, and D-IMPL-84
newly establishes that a manifest is *not* assumed benign: the whole `ccf.` namespace
reservation exists because a manifest can be authored to squat an SDK class id. A
document trusted that little should not also be trusted to name `/`-rooted paths.

**Fix:** refuse a path that is not a name relative to the manifest, at the contract
boundary where the glob refusal already sits:

```python
@field_validator("path")
@classmethod
def _path_is_a_name_not_a_pattern(cls, value: str) -> str:
    if any(character in value for character in _GLOB_CHARACTERS):
        raise ValueError(...)  # unchanged
    candidate = PurePosixPath(value)
    if candidate.is_absolute() or ".." in candidate.parts:
        raise ValueError(
            f"{value!r} leaves the manifest's own directory. A manifest names"
            " files beside itself; an absolute path or a `..` segment makes the"
            " artifact set depend on the filesystem outside the deployment, and"
            " a `role: register` entry would content-hash whatever it found into"
            " Decision Replay dimension 2. Name a path relative to the manifest."
        )
    return value
```

Belt-and-braces in `load_and_boot`, since the contract is not the only caller:

```python
resolved = (root / entry.path).resolve()
if not resolved.is_relative_to(root.resolve()):
    raise ValueError(f"manifest entry {entry.key!r} resolves outside {root}")
document = resolved.read_text(encoding="utf-8")
```

### CR-02: three examples register an author-versioned class through `register_typed`, and one of them documents the opposite

**File:** `examples/05-workflow-hitl/run.py:411`,
`examples/06-decision-replay/run.py:661`, `examples/08-e2e-demo/run.py:959`

**Issue:** `ccf.prompt-artifact` is author-versioned — its contract declares
`artifact_version: str`, and it is a member of `SDK_VERSIONED_ARTIFACT_CLASSES`
(confirmed at runtime). A manifest entry declaring `registration: typed` for it is
refused at preflight by `refuse_registration_the_sdk_fixes`
(`src/ccf/deployment/classes.py:281-286`). All three examples above reach the same
end state by calling `registry.register_typed(...)` directly, which runs no D-05
bump check — the exact governance loss D-IMPL-85 exists to prevent.

The known residual (R-2/R-3 family) names example 05 only. It is three sites, and
two of them (`06`, `08`) are in this phase's changed-file set.

Worse, the surrounding prose asserts the opposite of the code:

* `examples/05-workflow-hitl/run.py:402-404` — *"Four are AUTHOR-VERSIONED:
  `register_versioned` holds the author's `artifact_version` claim against content
  identity."* The very next statement (`:411`) registers the first of those four
  through `register_typed`. The other three (`agent-definition`, `task-definition`,
  `workflow-definition`) do go through `register_versioned`.
* `examples/08-e2e-demo/run.py:944-953` — the comment explains at length that
  `ccf.agent-definition`, `ccf.prompt-artifact` and `ccf.skill-catalog-entry` are
  kept out of the manifest *because* `register_typed` "does not run [the bump check]
  — so … a manifest entry naming one would parse fine while silently dropping the
  governance the class exists to carry". It then registers the prompt artifact with
  `register_typed` (`:959`) while its two siblings take the versioned path.
* `tests/examples/test_workflow_hitl_output.py:738-772`, the test the phase
  close-out cites as ERGO-18 evidence, says in its docstring *"deliberately not for
  the four author-versioned definition classes"* and then builds an
  `author_versioned` set of **three** keys (`:756-760`) — `prompt_artifact_key` is
  absent. The assertion is scoped to exactly the subset that passes.

**Concrete failure:** edit `examples/08-e2e-demo/artifacts/prompt-artifact.yaml`'s
`template` without touching its `artifact_version`, re-run. Under
`register_versioned` this returns `RefuseUnbumpedChange` and nothing is stored.
Under `register_typed` it registers as a new content version under the same
unbumped `artifact_version`, enters replay dimension 2, and nothing records that the
bump check was skipped. That is CR-1's harm, reproduced in the SDK's own teaching
material.

**Fix:** route all three through the versioned path and handle the returned refusal,
as the sibling call sites already do:

```python
prompt_version = registry.register_versioned(
    registration["prompt_artifact_key"], prompt, PROMPT_ARTIFACT
)
if not isinstance(prompt_version, str):
    raise RuntimeError(f"the prompt artifact was refused: {prompt_version!r}")
```

and widen `test_the_author_versioned_definitions_kept_their_bump_check`'s
`author_versioned` set to include `keys["prompt_artifact_key"]`, so the assertion
covers the four its docstring claims. Correct example 05's and example 08's comments
in the same change.

### CR-03: the binder tripwire admits the collapse it exists to prevent

**File:** `tests/products/test_gate_two_call_shape.py:582-586` (`_names_the_binder`),
`:621-641` (the assertion)

**Issue:** tripwire (2) requires that a projecting body *name*
`refuse_operator_set_divergence`. It checks nothing about the call's arguments. The
following body passes it, and the binder call inside it is a tautology:

```python
def serve(declared, r):
    plan = FooPlan(plan_id='p', required=declared.required_operator_keys)
    refuse_operator_set_divergence(declared=declared, plan=plan)
    return ProjectionEngine(reader=r).execute(plan=plan)
```

Verified by driving the module's own helpers:

```
PASSES tripwire  projecting=True  binder_named=True   plan built FROM the claim - binder compares a value against itself
PASSES tripwire  projecting=True  binder_named=True   binder on a DIFFERENT plan than the one executed
```

`plan.required_operators()` is now `declared.required_operator_keys`, so
`claimed == required` holds unconditionally at `binder.py:156-159`. The binder is
green, it cannot fail, and `ccf.projection-requirements` has been routed around
entirely. This is precisely the shape CR-2 found at `run_gates`, one seam upstream,
and it is the shape `test_required_operators_guard.py`'s *old* failure message used
to instruct (corrected in plan 15.1-10, Cursor finding 4).

This is **not** covered by residual R-3. R-3 is the *authoring*-boundary case —
an author copying one YAML document's keys into the other — which D-IMPL-86
correctly establishes as AST-undetectable because the compliant and violating states
are textually identical. This case is code, `required=declared.required_operator_keys`
is a readable identifier path, and this very module already resolves such paths.

Second variant, same class: the binder given a different plan object than the one
executed (row 2 above) also passes.

**Fix:** extend tripwire (2) from "the binder is named" to "the binder is handed the
executed plan, and that plan's `required=` does not root at the same path as the
binder's `declared=`". The module's existing helpers do all the work:

```python
def _binder_collapses(scope: ast.AST, path: pathlib.Path) -> list[str]:
    aliases = _aliases(scope)
    problems: list[str] = []
    plan_sources: dict[tuple[str, ...], tuple[str, ...] | None] = {}
    for node in _scope_nodes(scope):
        if _is_plan_construction(node):
            required = _keyword(node, PLAN_REQUIRED_KEYWORD)
            # bind the local the plan is assigned to -> the path `required` reads
            ...
    for node in _scope_nodes(scope):
        if not (isinstance(node, ast.Call) and _callee(node) == BINDER_CALL):
            continue
        declared = _resolve(_path(_keyword(node, "declared")), aliases)
        plan = _resolve(_path(_keyword(node, "plan")), aliases)
        if _shares_a_source(declared, plan_sources.get(plan)):
            problems.append(
                f"{path.relative_to(REPO_ROOT)}:{node.lineno}: the plan handed to"
                f" `{BINDER_CALL}` was built from the same source as `declared`."
                " The binder then compares a value against itself — CR-2's shape"
                " at the binder seam. Build `required=` from the"
                " `ccf.projection-requirements` artifact (design E2, D-IMPL-86)."
            )
    return problems
```

Add a probe pair to `test_the_binder_tripwire_detects_a_projection_that_skips_it`
covering both the caught shape above and the compliant
`required=requirements.required_operator_keys` shape, so the new check is watched to
fire *and* watched to stay quiet — the discipline the module already applies to
tripwire (1).

### WR-01: `_aliases` does not terminate on a cyclic assignment chain — `pytest` hangs

**File:** `tests/products/test_gate_two_call_shape.py:311-322`

**Issue:** the fixed-point loop grows bindings until nothing changes. On a cycle of
three or more local name assignments the substitution oscillates and `grew` is
`True` forever. Reproduced:

```python
def f():
    a = b
    b = c
    c = a
    return run_gates(x, engine_resolved=a)
```

```
$ timeout 15 python probe.py   # calls _aliases(f)
entering _aliases
exit=124
```

The `name not in resolved` guard (`:318`) blocks the two-cycle but not the
three-cycle: `a` stabilises at `(c,)`, `c` at `(a,)`, and `b` alternates between
`(a,)` and `(c,)` indefinitely. With an attribute in the chain (`a = b.k`) the path
also grows one element per pass, so memory grows without bound.

This helper runs over every `.py` file under `src/`, `runtime/` and `examples/`. A
contributor writing a rotation chain in any of those trees hangs the test suite with
no output and no timeout to break it.

**Fix:** bound the iteration and refuse rather than spin:

```python
for _ in range(len(bindings) + 1):
    grew = False
    ...
    if not grew:
        return bindings
raise AssertionError(
    "alias resolution did not converge; a cyclic assignment chain is present"
)
```

`len(bindings) + 1` passes is sufficient for any acyclic chain, so a non-terminating
input is by construction a cycle and the message says so.

### WR-02: `_gate_collapses` is red on correct code — a method call collapses to its receiver

**File:** `tests/products/test_gate_two_call_shape.py:265-268` (`_path` on
`ast.Call` with an `ast.Attribute` callee), `:339-351` (`_shares_a_source`)

**Issue:** `_path` maps `obj.method()` to `("obj",)`. `_shares_a_source` treats a
prefix as the same source. So *any* method call on an object paired with *any*
attribute read of the same object is reported as a collapse. Reproduced:

```python
def serve(self, candidate):
    product = ProductLineage(operators_invoked=self.declared_claim())
    return run_gates(candidate, engine_resolved=self._resolved)
```

```
FP method-call vs attribute: ["probe.py:3: `run_gates(..., engine_resolved=...)` and
the `ProductLineage(...)` at line 2 both read `self`. …"]
```

and equally for two different accessors on one artifact object
(`product_class.claim()` vs `product_class.resolved_ops`).

This contradicts the module's own stated design rule at `:44-46`: *"Paths, not bare
roots — `self._declared` and `self._resolved` share a root and are two different
values, and a check that collapsed them to `self` would be red on correct code."*
The method-call rule reintroduces exactly that collapse. No current call site trips
it, but the shape is ordinary — an accessor on a result object is a natural
refactor of the compliant pattern.

**Fix:** do not collapse a method call to its receiver; return `None` for a callee
the module cannot see through, exactly as it already does for helper functions and
subscripts:

```python
if isinstance(node, ast.Call):
    if isinstance(node.func, ast.Name) and node.args:
        if node.func.id in TRANSPARENT_CONVERSIONS:
            return _path(node.args[0])
        if node.func.id == TRANSPARENT_CAST and len(node.args) > 1:
            return _path(node.args[1])
    return None   # a method's return value is out of reach, like a helper's
```

Then amend the docstring paragraph at `:56-63` to add "a method's return value" to
the list of stated limits, which is where it belongs.

### WR-05: a projecting body can be made invisible to tripwire (2)

**File:** `tests/products/test_gate_two_call_shape.py:556-579`

**Issue:** a body counts as projecting only if it either constructs
`<Something>Plan(..., required=...)` or calls `.execute(plan=...)`. Both are naming
conventions, and dropping both at once removes the body from the scan entirely —
it is then never required to name the binder. Verified:

```
PASSES tripwire  projecting=False  binder_named=False  execute with a POSITIONAL plan and a non-Plan class name
```

for

```python
def serve(declared, r):
    pi = CreditProjection(plan_id='p', required=requirements.required_operator_keys)
    return ProjectionEngine(reader=r).execute(pi, perspective=q)
```

Neither convention is enforced anywhere: `ProjectionPlan` is a `Protocol`, so a
conforming plan class may be named anything, and `ProjectionEngine.execute`'s `plan`
parameter is positionally passable. The docstring at `:150-153` describes the class
suffix as "the two properties every implementation … *in the suite* shares", which
is accurate about today and silent about tomorrow.

**Fix:** widen the execution detector to positional form, which is the cheap half:

```python
def _is_plan_execution(node: ast.AST) -> bool:
    if not isinstance(node, ast.Call) or _callee(node) != ENGINE_EXECUTE_METHOD:
        return False
    if any(kw.arg == ENGINE_PLAN_KEYWORD for kw in node.keywords):
        return True
    # `engine.execute(plan, perspective=…)` — a projection execution passes its
    # plan first; `engine.execute(workflow, execution_id=…)` does not pass
    # `perspective`, which is what still separates the two.
    return bool(node.args) and any(
        kw.arg == "perspective" for kw in node.keywords
    )
```

and state the residual explicitly in the module docstring's limits section: a plan
class named without the `Plan` suffix, executed positionally, is outside the scan.

### WR-06: the binder tripwire checks neither ordering nor reachability

**File:** `tests/products/test_gate_two_call_shape.py:621-641`

**Issue:** the assertion's own docstring says the binder "must be called between
plan construction and `ProjectionEngine.execute`". The check enforces neither half.
Verified:

```
PASSES tripwire  binder AFTER execute
PASSES tripwire  binder in an unreachable branch
```

The unreachable-branch case is the material one — a binder call inside a never-taken
`if`, an `except` handler, or a `# pragma: no cover` branch satisfies the tripwire
while the comparison never runs, and (per the module's own reasoning) nothing at
runtime shows it. Ordering, unlike reachability, is trivially checkable from the
line numbers the scan already has.

**Fix:** require the binder call to precede every `execute` in the same body, at
statement level:

```python
binder_lines = [
    node.lineno for node in _scope_nodes(scope)
    if isinstance(node, ast.Call) and _callee(node) == BINDER_CALL
]
execute_lines = [
    node.lineno for node in _scope_nodes(scope) if _is_plan_execution(node)
]
if execute_lines and (not binder_lines or min(binder_lines) > min(execute_lines)):
    ...  # fail: the binder does not precede the engine
```

Reachability is genuinely out of AST reach; amend the docstring at `:627-628` from

### WR-07: the fragment glob is wider than the sort regex, and the mismatch mis-orders silently

**File:** `tools/assemble_surface_changes.py:122-163`, `tests/test_surface_drift.py:99-121`

**Issue:** `fragment_paths()` globs `15*-*.md` but sorts with
`_PLAN_NUMBER = re.compile(r"^15(?:\.(?P<minor>\d+))?-(?P<plan>\d+)-")`. A filename
the glob admits and the regex rejects — `152-03-slug.md`, `15a-01-slug.md`,
`15.1.2-04-slug.md` — falls to `return (0, 0, 0, path.name)` and sorts *ahead of
every Phase 15 fragment*. The function's own docstring names this outcome and calls
it "worse than not matching at all", then leaves it reachable: there is no
`FragmentError` on an unparsed name.

**Fix:** refuse rather than sort to zero, since the assembler already has a refusal
type and a regeneration command to point at:

```python
def key(path: pathlib.Path) -> tuple[int, int, int, str]:
    match = _PLAN_NUMBER.match(path.name)
    if match is None:
        raise FragmentError(
            f"{path.name} matches the fragment glob but not the plan-number"
            " pattern `15[.<minor>]-<NN>-<slug>.md`. It would sort ahead of"
            " every other fragment and silently mis-order"
            f" {OUTPUT.name}. Rename it."
        )
    minor = match.group("minor")
    return (15, int(minor) if minor else 0, int(match.group("plan")), path.name)
```
