## 2. CR-F1 — the recognition is now structural, and the alternative was measured before being rejected

### What was wrong

`_is_plan_construction` required `callee.endswith("Plan")`. It feeds `_plan_sources`, which feeds
property (1), which is the entire substance of the CR-03 fix. `ProjectionPlan` is a
`typing.Protocol` whose docstring commits to the opposite:

> *"**Structural, not nominal.** Any type exposing `required_operators()` and `invoke()` is a
> projection. There is no base class to inherit and no registry decorator to remember."*

So a rename made property (1) vacuous while coverage, properties (2) and (3), and all three floors
stayed green — the identical defect statement CR-03 carried, reachable by renaming one identifier,
inside the check written to close it.

### What it is now

Three branches, and the ordering is the finding. The first two are name-independent:

1. **The callee names a class that satisfies the Protocol structurally** — its body defines both
   `required_operators()` and `invoke()`, read off the class body across `src/`, `runtime/` and
   `examples/`. This is the SDK's own definition of "is a projection", applied to the class the
   call constructs. Renaming `QuickstartPlan` to `CreditProjection` renames its `class` statement
   too, so this branch follows the rename.
2. **The call passes both `plan_id=` and `required=`** — the constructor shape every plan in the
   suite has, and the two keywords the checks actually read. This reaches a plan class whose
   *definition* is out of reach: imported from a package, or from a tree this module does not scan.
3. **The `*Plan` suffix with `required=`** — the pre-CR-F1 rule, kept as a net, argued below.

**Why not the kwarg shape alone**, which is the direction Dave ruled: because it is *also* a
convention. A plan class taking `__init__(self, *, identifier, operators)` conforms to
`ProjectionPlan` perfectly and passes neither keyword. Keying on kwargs alone would have been CR-F1
one step sideways — rename the *keyword* and the check goes quiet again. Branch 1 is the one that
matches what the SDK is structural about; branch 2 is what covers the classes branch 1 cannot see.
`test_a_plan_class_is_recognised_by_the_protocol_and_not_by_its_name` isolates branch 1 by asserting
the same body **rejected with** the class index and **admitted without** it, so the branch is
demonstrably load-bearing rather than a spare wheel.

## 3. WR-F2 — the binding maps do what they say, and the code was fixed rather than the docstring

`_scope_nodes` pops from a stack and so yields a body's statements in **reverse** source order.
Combined with `setdefault`, `_aliases` and `_plan_sources` recorded the *last* textual assignment to
a name and applied it to every use of that name anywhere in the body — while `_aliases`'s docstring
called it "the raw first-assignment map". It described neither the traversal nor the result.

`_aliases` and `_resolve` are replaced by `_bindings` (every assignment to every name, sorted by
line, **including** bindings whose value has no identifier path), `_binding_before` (the last
assignment strictly above a line) and `_resolve_at` (resolve each hop as of the line that bound it).
Traversal order is no longer relied on anywhere: the result is sorted explicitly.

**An unreadable binding is a source, not a hole.** `plan = QuickstartPlan(...)` at line 231 becomes
the token `plan@231` (`_opaque`). Two reads of one construction share a source; two constructions do
not. That single move gives property (2) object identity without a second model, and it is why the
diff to `_handed_plan_source` is one line rather than a rewrite.

**Following an alias and reading an argument turned out to be two questions.** `_binding_path` treats
a call as opaque, because a call evaluates to a **new** value each time and following two
constructions of one class to the same path would make property (2) believe the binder bound the
plan the engine ran. `_path` treats a method call as a path, because two *reads* of
`execution.resolved()` are the same expression and Gate 2 comparing them is comparing a value
against itself. Collapsing the two questions into one function is what would have traded WR-F2
against WR-F4.

## 4. WR-F4 — the true positive restored, without WR-02's false one

WR-02 was right that reading `obj.method()` off its bare receiver as `("obj",)` was red on correct
code: it made *any* method call on an object share a source with *any* attribute read of it. Its
fix returned `None`, which also removed a **true** positive — `execution.resolved()` on both sides
of Gate 2, one expression whose value Gate 2 then compares against itself.

Both are avoidable, and the reviewer named the third option. `_path` now yields the receiver's path
extended by **the member name and a call marker**: `execution.resolved()` is
`("execution", "resolved", "()")`. `_shares_a_source`'s prefix rule then does the rest.

| Shape | Expected | Observed |
| --- | --- | --- |
| `execution.resolved()` on **both** sides | REJECT | **REJECTED** |
| `self.declared_claim()` vs `self._resolved` — WR-02's false positive | ADMIT | **ADMITTED** |
| `self._declared` vs `self._resolved` | ADMIT | **ADMITTED** |
| `product_class.claim()` vs `product_class.resolved_ops` | ADMIT | **ADMITTED** |
| two **different** methods on one receiver | ADMIT | **ADMITTED** |

`CALL_MARKER` is `"()"`, which contains characters no identifier can, so it cannot collide with a
real member name. What is still out of reach is what a method *returns*: `a.keys()` and
`a.key_set()` are two paths whatever they return, and the module docstring says so.

## 5. WR-F3 — closed, though it was outside the three assigned findings

`test_the_binder_argument_scan_is_not_vacuous` asserts `len(found) >= 11` over a flat list across
all bodies while its docstring claimed the property held "at each of those sites". A total is not a
per-site property, and the distinction is not academic here: **CR-F1's own escape analysis turns on
it.** A new body contributes zero readable sites while the existing eleven still contribute eleven,
so `11 >= 11` holds and the floor does not bite. Shipping the CR-F1 fix while leaving that arithmetic
intact would have left the fix one new body away from being routed around.

`test_every_bound_body_has_a_readable_plan_source` is added, parametrized per projecting body,
asserting what the docstring claimed. Both are kept and each docstring now says which statement it
carries. Measured: all eleven bodies pass, none `UNREADABLE`.

A body with no binder call at all returns early — that is
`test_every_projecting_example_body_names_the_binder`'s failure, and reporting it twice would tell
one story in two voices.

**Exactly one `assert` line was removed**, and it was replaced in the same test by a stronger one.
`assert resolved["a"] != resolved["b"] != resolved["c"]` claimed a three-name rotation resolves to
three *distinct* sources. That was a property of the predecessor's conservative fallback, not of the
code: at the bottom of `def f(b, c): a = b; b = c; c = a`, `a` and `c` both hold the parameter `b`
and `b` holds `c`. The line-aware model returns that, and the replacement pins it exactly —
`assert resolved == {"a": ("b",), "b": ("c",), "c": ("b",)}`. Pinning the semantics is stronger than
pinning the fallback, and the docstring records why the assertion changed so a later reader does not
read it as a relaxation. The wall-clock bound and
`test_the_wall_clock_bound_is_itself_live` are untouched.

defend against and a permanently-unreachable branch would be worse than no branch.
