# Phase 15.1 Plan 17: Positions, Not Lines Summary

**The binding model now orders bindings and reads by source position `(line, column)` and anchors
each binding where Python actually binds it — which closes the nine rebinding spellings that were
admitted whenever a compound statement's suite was written on its own header line or a rebinding was
separated by a semicolon, and which the previous round certified as closed after measuring only the
multi-line form; a comprehension target is scoped to its lexical span rather than to the lines it
spans, which removes the false positive the previous round introduced on correct code; a walrus is
read as the construction it evaluates to at both the execution and the binder seam; and the two
records that asserted more than the code did are corrected in place.**

## 1. R4-CR-01 — the certification defect

`_binding_records` recorded every binding form. `_binding_before` consumed them with
`binding.lineno < line`, and a compound statement's binding is recorded at the **statement's** line
— so a suite written on that same line read the name at a line its own binding was not yet "before",
and the **previous** binding answered. Affirmatively. That is CR-01's own inversion, one layer down.

Reproduced at the head of this plan against the unmodified `aedf81b` module, then re-measured after:

| spelling | one-line suite, before | one-line suite, after | multi-line (control), before → after |
| --- | --- | --- | --- |
| `for` | **ADMIT** | REJECT | REJECT → REJECT |
| `async for` | **ADMIT** | REJECT | REJECT → REJECT |
| `with … as` | **ADMIT** | REJECT | REJECT → REJECT |
| `async with … as` | **ADMIT** | REJECT | REJECT → REJECT |
| `except … as` | **ADMIT** | REJECT | REJECT → REJECT |
| `match` capture | **ADMIT** | REJECT | REJECT → REJECT |
| semicolon assign | **ADMIT** | REJECT | REJECT → REJECT |
| semicolon tuple | **ADMIT** | REJECT | REJECT → REJECT |
| semicolon import | **ADMIT** | REJECT | REJECT → REJECT |

All nine bodies satisfy the **coverage** half — each names the binder — which is the third time in
this phase that is the finding.

The other direction was red at the same time. `for ops in batches: out = run_gates(candidate,
engine_resolved=ops)`, where `ops` inside the loop is an element of `batches` and has nothing to do
with the lineage above it, was reported as the CR-2 collapse: **REJECT before, ADMIT after**. The
`with cm as ops:` one-liner measures identically.

### The remedy adopted is not the remedy proposed, and the difference was measured

The review proposed making a compound statement's binding inclusive from its own line. Measured:
that closes six spellings, and the review states two costs of it — it does **not** close the three
semicolon spellings, and it mis-resolves a read in a compound statement's own **header**
(`for plan in transform(plan):`, `with make(plan) as plan:`), which Python evaluates before it binds.

Ordering on `(line, column)` and anchoring each binding where it takes effect closes all nine and
pays neither cost:

| body | verdict | why |
| --- | --- | --- |
| `for plan in transform(plan):` — header read | **ADMIT** | resolves to the parameter `plan`, not the loop target: the binding is anchored past `node.iter` |
| `with make(plan) as plan:` — header read | **ADMIT** | anchored past the item's `context_expr` |
| a multi-line right-hand side reading the name it binds | **ADMIT** | anchored past `node.value`; a start-anchored model put the new binding in force on lines 2 and 3 of its own value |

Directly measured on the resolver rather than only through the checks:

```
for plan in transform(plan)      header read -> ('plan',)      suite read -> ('plan@2:31',)
with make(plan) as plan          header read -> ('plan',)      suite read -> ('plan@2:19',)
```

The header reads resolve to the **parameter**; the suite reads resolve to the **new** binding. That
is what Python does.

### One consequence outside the review's scope, taken deliberately

Properties (2) and (3) compared **line** numbers too, so `plan = P(); bind(plan=plan);
run(plan=plan)` on one physical line — correct code — was reported red at both properties at once
(`aedf81b`: 2 problems). They compare positions now: that body is **ADMIT**, and
`plan = P(); run(plan=plan); bind(plan=plan)` — the binder after the engine, on one line — is
**REJECT**. Fixing the binding order and leaving the call order would have left the same defect one
function away.

### The opaque token had to move with it

`_opaque` keyed on the line alone. Two constructions on one physical line then shared the token
`plan@4`, so property (2) would match a second execution against the first call's binder — CR-01's
inversion in the token space. The token is `name@line:column` now (`plan@231:84`), and
`_plan_sources` builds it from the **same `_Binding`** the resolver synthesises it from, so the two
cannot drift when a binding's effective position stops being its statement's start.

## 2. R4-WR-01 — the regression, closed structurally

`_Binding.until` was a pair of **line numbers**. Python scopes a comprehension target **lexically**.
Any other expression sharing the comprehension's first or last line had its reads attributed to the
comprehension's target — a false positive in one direction and a false negative in the other. Both
measured, both closed:

| body | before | after | which is right |
| --- | --- | --- | --- |
| `return ([str(plan) for plan in alts], engine.execute(plan=plan))` | **REJECT** | ADMIT | ADMIT — the target does not leak; the engine runs the outer plan |
| `return combine([x\n    for plan in alts], engine.execute(plan=plan))` | **REJECT** | ADMIT | ADMIT — same, multi-line |
| the generator-expression spelling | **REJECT** | ADMIT | ADMIT |
| the set-comprehension spelling | **REJECT** | ADMIT | ADMIT |
| the dict-comprehension spelling | **REJECT** | ADMIT | ADMIT |
| tripwire (1): a genuine collapse with a comprehension on the gate's own line | **ADMIT** | REJECT | REJECT — both sides read the same `ops` |
| the execute spelled **inside** the comprehension | REJECT | REJECT | REJECT — unchanged; the read really is the comprehension's target |
| an ordinary rebinding **after** the comprehension | REJECT | REJECT | REJECT — unchanged; the comprehension is not a licence for what follows it |

`until` is a `(line, column)` span now and containment is `position <= read < until`, which is the
scope Python gives it. The resolver-level property is asserted directly as well: on
`b = ([a for a in xs], a)` the read at `(3, 10)` resolves to the comprehension's own target and the
read at `(3, 25)` — same line, outside the span — resolves to the binding above it.

**This was a defect this phase introduced, not one it inherited**, and `15.1-16-SUMMARY.md`'s
"All ADMIT cases still admitted; no check loosened" row is corrected to say so.

## 3. R4-WR-02 — the walrus, closed at both seams

`execute(plan=(plan := FooPlan(...)))` made `plan_node` an `ast.NamedExpr`, so property (2)'s hoist
branch did not fire, `_binding_path` returned `None` for the same node, and the execution took the
`execution.plan is None` quiet exit — while `_plan_sources` had recorded the construction's source
and was holding it.

The review proposed unwrapping the walrus before `_is_plan_construction`. That is half of it. Doing
only that leaves the **binder** seam wrong in the other direction, which the probe found and the
review did not: `binder(declared=d, plan=(plan := P(...)))` followed by `execute(plan=plan)` is
correct code — the binder was handed the very object the engine runs — and it was reported unbound,
because `handed` resolved to `None` while the execution resolved to the walrus's own token.
`_bound_object` resolves a walrus argument to that binding's token, from the same `_Binding`.

| body | before | after | which is right |
| --- | --- | --- | --- |
| `execute(plan=(plan := built_from_declared))` | **ADMIT** | REJECT | REJECT — hoist; no binder can have been handed it |
| `binder(plan=(plan := built_from_declared))` then `execute(plan=plan)` | REJECT (property 2, wrong reason) [CORRECTED — was **ADMIT**] | REJECT | REJECT — property (1); the plan reads the binder's own `declared=` |
| `binder(plan=(plan := compliant))` then `execute(plan=plan)` | **REJECT** | ADMIT | ADMIT — correct code |

The last row was found by writing the probe, not by reading the review.

## 4. R4-WR-03 — loop-carried rebinding: decided, named, asserted, NOT closed

**This is the shape that remains undetected, and it is the one a reader auditing at the gate should
know about.** A plan rebuilt at the *bottom* of a loop body whose `execute` is at the top runs, from
the second iteration on, a plan built from the binder's own `declared=` that no binder was handed:

```python
plan = FixturePlan(plan_id=pid, required=requirements.required_operator_keys)
refuse_operator_set_divergence(declared=declared, plan=plan)
for item in alts:
    out = ProjectionEngine(reader=r).execute(plan=plan)
    plan = FixturePlan(plan_id=pid, required=declared.required_operator_keys)
```

Measured: **ADMIT**, before and after. The `while` spelling measures identically. The
straight-line spelling of the identical rebinding is **REJECT**, which is what makes the silence a
statement about control flow rather than about the check having gone quiet.

**Why not closed:** it needs control-flow ordering, not lexical ordering — a fixed point over a loop
body, a different analysis whose termination argument would have to be rebuilt from scratch. Two
predecessors of `_resolve_at` failed at exactly that, one of them by hanging `pytest` with no output.

**What was done instead**, three things, so it cannot quietly become false in either direction:

1. named in **both** limits lists in the module docstring, with the code shown;
2. registered in `deferred-items.md` as carried work for Phase 16, with the measurement;
3. **asserted as a limit** in `test_a_loop_carried_rebinding_is_out_of_reach_and_says_so`, whose
   failure message says that if it has closed, the limits lists and this SUMMARY must be corrected
   in the same commit.

## 5. R4-IN-01 — class bodies and lambdas, closed at zero measured cost

`_scope_nodes` deliberately refuses to descend into a `ClassDef` or a `Lambda`, and `_scopes` did
not list them — so a plan constructed there was scanned by **nothing**. Not "scanned and
unresolvable", which the limits list covers: invisible, and `MINIMUM_PROJECTING_BODIES` could not
see it either, because the body never entered the count.

Measured **before** widening, which is why widening rather than re-wording the docstring was
available: **0** class bodies and **0** lambda bodies under `examples/` construct or run a
projection, and **0** under `src/`/`runtime/`/`examples/` call `run_gates`. No floor moved and no
verdict moved. One imprecision is stated in `_scopes`: a lambda's *default* argument expressions are
evaluated in the enclosing body and are counted here as the lambda's, which misattributes which body
they belong to and cannot hide them.
