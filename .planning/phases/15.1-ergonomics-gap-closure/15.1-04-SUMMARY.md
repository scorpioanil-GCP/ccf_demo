# Phase 15.1 Plan 04: The Operator-Set Binder Summary

**`refuse_operator_set_divergence` ships — the refusal that turns two separately authored
operator-set documents into a bound pair, placed where the corrected ruling puts it, proven to
fire from a one-line artifact edit, and honest in its docstring about the two things it does

## 1. Placement — selected, cited at both bounds, and constraint-checked (Task 1)

**Ruling of record: `D-IMPL-86 (correction, 2026-08-05)`** — the last entry in
`docs/DECISIONS.md`, which withdraws element (3)'s "boot-time binder" wording and places the
binder *between plan construction and `ProjectionEngine.execute`*. The original D-IMPL-86
element (3) is superseded on this point and is **not** the citation this plan works from.
`.planning/ROADMAP.md:420` carries the amended Criterion-4 wording verbatim ("a check — placed

### (a) The ruling's own basis: `load_and_boot` takes no `plan`

Read at `src/ccf/deployment/manifest.py:181-188`, verbatim:

```python
def load_and_boot(
    manifest_path: str | Path,
    *,
    registry: ControlPlaneProtocol,
    database_path: str | None = None,
    postgres_dsn: str | None = None,
    tenant_id: str | None = None,
) -> BootedFabric:
```

**There is no `plan` parameter and no `ProjectionPlan` in scope at any preflight.** The three
preflights are `refuse_role_the_sdk_fixes` (`manifest.py:307`),
`refuse_registration_the_sdk_fixes` (`manifest.py:312`) and `_preflight_backend`
(`manifest.py:313`, defined at `:138`), and none of them sees a plan — the entire body operates
over `DeploymentManifest` entries and the artifacts they name. A comparison naming
`plan.required_operators()` therefore cannot run inside this function. The correction's basis
holds; nothing was surfaced.

**One precision note on the citation, recorded rather than smoothed over.** The correction cites
`src/ccf/deployment/manifest.py:177`. That was inside this signature block when the correction
was written — at the phase base commit `4877a01`, `def load_and_boot(` is line 175 and line 177
is the keyword-only marker `*,`. Waves 2 and 3 inserted six lines above it, so in the current
tree the signature spans **181-188** and line 177 falls inside `_preflight_backend`'s body. The
fact the correction established is unchanged; only its line number moved. Both spellings are
carried in `src/ccf/deployment/binder.py`'s docstring, so a reader who follows either lands
somewhere true.

### (b) The selected call site, witnessed at both bounds

Both bounds read in `examples/00-quickstart/run.py`:

| Bound | `file:line` | Text |
| --- | --- | --- |
| Engine construction | `examples/00-quickstart/run.py:206` | `execution = ProjectionEngine(` |
| **The `execute` call (forward bound)** | `examples/00-quickstart/run.py:208` | `).execute(` |
| **Plan construction (backward bound)** | `examples/00-quickstart/run.py:209-212` | `plan=QuickstartPlan(plan_id=…, required=declared.required_operator_keys,)` |

**The interval is presently empty, and that is the finding this task exists to surface.** The
plan is not bound to a name: `QuickstartPlan(...)` is constructed *inline as the `plan=` keyword
argument* of the `.execute(...)` call it is passed to. There is no statement between "the plan
exists" and "the engine runs it", because the plan does not exist as a value any statement could
observe — it comes into being inside the call expression that consumes it.

So the placement the corrected ruling names requires the plan to be **hoisted into a local
first**, and the selected call site is:

> the statement immediately after `plan = <PlanType>(...)` and immediately before the
> `ProjectionEngine(...).execute(plan=plan, ...)` statement — in the quickstart, the line that
> will sit between the hoisted assignment and today's line 206.

That hoist is plan **15.1-05**'s Task 1 (`15.1-05-PLAN.md:135-137`: "hoist the plan out of the
`execute(...)` call into a local … call `refuse_operator_set_divergence(declared=declared,
plan=plan)` on the line before"), and 15.1-05/06/07 apply the same shape to the other eight
sites. This plan does not edit any example.

**Why both bounds were read rather than one.** A placement cited only as "before `execute`" is
satisfied by a call placed before the plan exists — which, at this site as it stands today,
is *every* line in the function, since the plan exists for the duration of one call expression.
A placement cited only as "after the plan" is satisfied by a call placed after the product is
served. Only the pair fixes a line. The empty interval is precisely what a one-ended citation
would have hidden.

### (d) The residual this placement creates — four parts, unsoftened

1. **Where the call must sit:** between plan construction and `ProjectionEngine.execute`, in
   adopter code. `load_and_boot` cannot host it (see (a)), so the SDK never invokes it.
2. **The binder returns `None`.** There is no return value a caller must consume, so there is
   nothing observable at runtime — no product field, no pin, no audit event — that proves the
   call happened. A deployment that omits it produces output identical to one that made it.
3. **Nothing outside the SDK's own `examples/` tree holds a deployment to calling it at all.**
   An adopter who omits the call gets no error, no warning, and no degraded output.
4. **The AST coverage check that enforces the call —
   `tests/products/test_gate_two_call_shape.py`, added in plan 15.1-08 — is scoped to
   `examples/` only.** It is a check on the SDK's own teaching material, not on adopters, and is
   not claimed as more.

This is a second convention-not-enforcement residual of the same family as the *authorship*
residual D-IMPL-86 already names in its "Consequences accepted" paragraph (a deployment that
reads one artifact into the other collapses the binder). It is **carried to Phase 16**, recorded
in `src/ccf/deployment/binder.py`'s module docstring and in the surface fragment's `Migration`
field, and routed to `docs/SURFACE-AUDIT.md` §5.4 and the gate presentation in plan 15.1-10 —
**for Dave to rule on. It is not this plan's to accept.**

## 2. The binder (Task 2)

`src/ccf/deployment/binder.py`, tagged `__ccf_mode__ = "algorithmic"`, `__all__` exactly
`["refuse_operator_set_divergence"]`:

```python
def refuse_operator_set_divergence(
    *, declared: ProductClassDeclaration, plan: ProjectionPlan
) -> None:
```

Raises `ValueError` when `frozenset(declared.required_operator_keys) !=
frozenset(plan.required_operators())`. The message names the plan id, both sorted sets, the
symmetric difference and D-IMPL-86, and it is **refuse-never-repair**: the binder does not
choose which document is right, because only the deployment's author knows which of the two they
meant. The static prose of the message is 168 characters; only the interpolated sets vary with
the deployment.

**It returns `None`, and the docstring says in the negative that there is no variant that
returns the set.** A binder that handed the declared set back would put the SDK in the position
of supplying one of Gate 2's two arguments — the D-15A line `cinv02-deployment-gates` holds and
the exact shape this phase exists to close. Stating it on the surface rather than only in the
guard is the pattern `src/ccf/deployment/manifest.py` already uses.

The module docstring carries E2's argument at the point of enforcement: what the binder is
(element (3), SDK-defined, citing CLAUDE.md §11 rather than the whitepaper, which §7.5 leaves
under-determined); what it binds (the Control Plane **claim** against the plan's own
requirements, two documents, one comparison); why the comparison is necessary (without it the
two documents are kept in sync by hand — Cursor's standing objection to a second artifact);
and **what it is not** — it is not Gate 2. Gate 2 compares the claim after transcription into
the Contract against the engine's execution of the plan, which is **assembly-path integrity**;
this binder is upstream and is where **authorable drift** fails. The docstring says the two
descriptions must not blur, and names the blurring as what produced CR-2.

Both residuals are stated in the body, neither in a parenthetical: the authorship residual in
D-IMPL-86's own words, and the placement residual in all four parts, citing
`D-IMPL-86 (correction, 2026-08-05)` and never the withdrawn element (3). The docstring says the
placement residual is **carried** to Phase 16 and surfaced at the gate — open debt, not a closed
question.

Re-exported from `src/ccf/deployment/__init__.py` with the package `__all__`'s existing
isort-style grouping preserved (`load_and_boot` → `refuse_operator_set_divergence` →
`refuse_registration_the_sdk_fixes` → `refuse_role_the_sdk_fixes` → `resolve_artifact_class`),
and the package docstring's `Modules` list gained the module with a one-clause statement of what
it does not do.

## 3. The proof (Task 3)

`tests/deployment/test_binder.py`, five tests, **every case reaching the binder through authored
artifact documents parsed by `load_artifact`** — `grep -c "ProductClassDeclaration("` and
`grep -c "ProjectionRequirements("` are both **0**. Criterion 4 asks that the divergence be
reachable by editing an artifact; a test that constructed the models directly would prove the
comparison works on two objects and say nothing about whether an author could ever make them
disagree.

1. **`test_two_agreeing_documents_are_admitted`** — the same keys in **different orders** (so the
   test also pins that sets, not sequences, are compared — INV-CH7-28). Returns `None`.
2. **`test_one_edited_operator_key_in_one_document_is_refused`** — two product-class documents
   identical apart from one operator-key line, with the single-line property **asserted** by
   `difflib.ndiff` rather than eyeballed. The refusal message is asserted to carry the key the
   edit introduced, the key it displaced, the plan id and `D-IMPL-86`.
3. **`test_a_superset_and_a_subset_are_both_refused`** (parametrized ×2) — an extra key in the
   product class and an extra key in the requirements are different authoring mistakes; a binder
   that tested subset rather than equality would admit one of them.
4. **`test_a_plan_that_ignores_its_requirements_artifact_is_refused`** — the two *documents*
   agree perfectly and the plan returns something else. Its docstring states why the ruling names
   `plan.required_operators()`: this is the case comparing the two artifacts to each other could
   not catch, and it is what keeps this a binder rather than a document diff.
