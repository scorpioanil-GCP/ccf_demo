## WR-F5 — the guard existed at one of the three fixed sites

### What was wrong

CR-02's stated root cause is that *the site which had lost its bump check was the
site the check did not look at*. The remediation moved three registrations onto
`register_versioned` and widened the guard at **one** — example 05.
`tests/examples/test_decision_replay_output.py` and `test_e2e_demo_output.py` read
`result.audit` only for the tenant-authorization deny, `tools/lints/` has no rule
over `register_typed`, and `refuse_registration_the_sdk_fixes` guards the manifest
seam and never sees a direct `registry.register_typed(...)` call. So the finding's
own root cause survived for two-thirds of its own fix.

### The shape chosen, and why it is not the reviewer's

The review proposed a key-set assertion modelled on example 05's:

```python
author_versioned = {keys["prompt_artifact_key"], keys["agent_definition_key"], ...}
```

**That shape has CR-02's hole by construction.** A registration added tomorrow
under a key nobody remembered to add to the set is invisible to it — which is the
sentence CR-02 was written about. Every audit event carries the `artifact_class`
it registered, so the guarantee is expressible without a key list at all:

```python
author_versioned_typed = {
    (class_id, key)
    for class_id, key in typed
    if class_id in SDK_VERSIONED_ARTIFACT_CLASSES
}
assert not author_versioned_typed
```

Three assertions, each saying something the others do not:

| | Assertion | What it catches that the others do not |
| --- | --- | --- |
| 1 | no author-versioned class went through `register_typed` | a reversion — **including at a site this module has never heard of** |
| 2 | the class set that went `register_versioned` is exactly the six (06) / four (08) the docstring names | a registration **deleted or moved** rather than re-routed |
| 3 | the keys `agent-registration.yaml` files by name are among them | (2) satisfied by some *other* document of the same class |

The reviewer's key-set idea survives as (3), where it is the right tool: it anchors
the class-level statement to this deployment's own declaration.

## WR-F6 — the sweep that stopped mid-directory

### What was wrong

`15.1-12-SUMMARY.md` records: *"Corrected together — leaving a subset right would
be worse than either extreme."* A subset is what it left, and the boundary ran
through the middle of two of the three directories it edited:

* `06/artifacts/prompt-artifact.yaml` was edited to forward the reader to *"that
  file's header for the reasoning"* — and `06/artifacts/agent-definition.yaml` was
  not edited, so a corrected document pointed at the superseded claim. Same
  construction in example 08.
* `06/artifacts/manifest.yaml` said *"A manifest CAN name them"* while
  `06/artifacts/task-definition.yaml` and `workflow-definition.yaml` said
  *"deliberately not manifest-addressable"* — two documents in one directory in
  flat contradiction.

### The phrasings searched — and why the list is the deliverable

This phase has now been bitten twice by a single-phrase sweep. The claim exists in
this tree in **six distinct phrasings**, and the list below is what a follow-up
should start from rather than re-derive:

| # | Phrasing searched | Where it appears |
| --- | --- | --- |
| 1 | `manifest-addressable` / `not manifest-addressable` | 06 task/workflow/skill-catalog headers, 05 README, `src/`, `tools/`, `tests/` |
| 2 | `Not addressable by the manifest` / `addressable by the manifest` | 05 agent/task/workflow/hitl-policy/scope-mapping headers |
| 3 | `not in the deployment manifest` | 06 and 08 `agent-definition.yaml` — the two forwarded-to documents |
| 4 | `silently drop` / `silently drops` / `would silently drop` / `drop the governance` / `dropping the governance` | 05 agent+workflow headers, 05 `run.py`, 06 and 08 `agent-definition.yaml`, examples 01/04 |
| 5 | **`drop it silently` / `drop them silently` / `dropped silently`** — *the same sentence with the word order inverted* | `examples/01-agent-basics/README.md:128`, `examples/02-skilling/artifacts/manifest.yaml:24`. **A search for phrasing 4 does not find these.** |
| 6 | `resolve to the open` / `resolves to the open` / `open envelope` / `open \`DeclaredArtifact\` envelope` / `would resolve them to the open` | the SECOND claim — 05 and 06 `hitl-policy.yaml`, `scope-mapping.yaml`, `manifest.yaml`, `run.py`, 05 README, example 03 |

Four further searches were run to *separate the true from the false* rather than to
find sites: `absent from SDK_ARTIFACT_CLASSES`, `outside the manifest` /
`stay out of the manifest`, `Routing them through the manifest` / `routing them

/ `runs no bump check` (which is a TRUE statement about `register_typed` and must
not be edited to match the pattern).

A seventh search followed the **forwards** — `see .* header`, `see that file`,
`for the same reason`, `own headers` — and every destination was opened and read.
That search is what found the four documents WR-F6 names, and it is the reason the
fix is not another subset.

### The second superseded claim, which the first sweep never looked for

WR-F6 notes example 03 is *"additionally wrong on a second point"*. That second
point is not confined to example 03. Since **D-IMPL-84** the `ccf.` prefix is
reserved, so a manifest entry naming `ccf.hitl-policy` or `ccf.scope-mapping` is
**refused at load**, not resolved to the open `DeclaredArtifact` envelope. Verified
by executing `resolve_artifact_class` rather than by reading it:

```
ccf.agent-definition    typed_map=False versioned_map=True  resolves -> AgentDefinition
ccf.prompt-artifact     typed_map=False versioned_map=True  resolves -> PromptArtifact
ccf.hitl-policy         typed_map=False versioned_map=False REFUSED: claims the SDK's reserved 'ccf.' prefix...
ccf.scope-mapping       typed_map=False versioned_map=False REFUSED: claims the SDK's reserved 'ccf.' prefix...
meridian-bank.policy-bundle                                 resolves -> DeclaredArtifact

registration=typed     for ccf.prompt-artifact -> REFUSED (D-IMPL-85)
registration=versioned for ccf.prompt-artifact -> ADMITTED
```

Example 05's own `manifest.yaml` already recorded this correction — *"Naming
either here is now a refusal (D-IMPL-84), where it was previously an envelope
resolution"* — while five sibling documents in 05 and 06 still asserted the
superseded version. Corrected in all five.

### What was left alone because it is TRUE

The brief says a true statement must not be edited to match a pattern. Three
families were verified and left:

1. **`ccf.hitl-policy` / `ccf.scope-mapping` are genuinely not manifest-addressable.**
   They are in neither `SDK_ARTIFACT_CLASSES` nor `SDK_VERSIONED_ARTIFACT_CLASSES`.
   Every sentence saying so stands; only the *consequence* (envelope vs refusal)
   was wrong.
2. **Deployment-owned class ids do resolve to the open envelope.**
   `05/artifacts/policy-bundle.yaml`, `06/artifacts/policy-bundle.yaml`,
   `06/artifacts/task-skill.yaml`, `08/artifacts/ingest-spec.yaml` and
   `08/artifacts/policy-bundle.yaml` all say so correctly.
3. **`register_typed` really does run no bump check.** Every sentence about the
   *method* is true; only sentences about what a *manifest entry* would do were
   superseded. `08/artifacts/manifest.yaml`, `08/README.md:111`, `05/run.py:407-415`
   and `06/README.md`'s artifact table were already correct and were not touched.

### One contradiction fixed that is not the claim

`06/artifacts/agent-registration.yaml` said *"Six documents in this directory are
registered by the driver"* while `06/artifacts/manifest.yaml` and `06/README.md`
both say **seven** — and the file's own next sentence enumerates five plus two.
Corrected to seven, with the two kinds distinguished (five a manifest *could* name
as `registration: versioned`, two it cannot name at all). Found by following the
forward, which is the point of following forwards.
