## Critical Issues

### CR-F1: the CR-03 argument check is silently vacuous for any plan class not named `*Plan`

**File:** `tests/products/test_gate_two_call_shape.py:713-722` (`_is_plan_construction`),
`:763-784` (`_plan_sources`), `:842-855` (`_handed_plan_source`), `:895-912` (property 1),
and the false residual claim at `:138-146`

**Issue.** Property (1) — "the plan handed to the binder does not read its `required=`
from the same source as the binder's `declared=`" — is the entire content of the CR-03
fix. It gets its input from `_plan_sources`, which records only assignments whose value
satisfies `_is_plan_construction`:

```python
callee = _callee(node)
if callee is None or not callee.endswith(PLAN_CLASS_SUFFIX):   # :718
    return False
```

`ProjectionPlan` is a **Protocol** — `src/ccf/projection/plan.py:5-12`: *"Any type
exposing `required_operators()` and `invoke()` is a projection. There is no base class
to inherit and no registry decorator to remember."* The `Plan` suffix is a convention
the eight current example plan classes happen to share, nothing more.

For a plan class named anything else, `_plan_sources` is empty for that local,
`_handed_plan_source` returns `None`, `_shares_a_source(declared, None)` is `False`,
and property (1) reports nothing. Coverage still passes (the body executes a plan, so
`_is_plan_execution` matches on `plan=`), property (2) passes (the binder and the
engine both name the same local), property (3) passes (the binder is first).

**Concrete triggering input**, driven through the module's own helpers:

```python
def serve(pid, r, declared):
    projection = CreditProjection(plan_id=pid, required=declared.required_operator_keys)
    refuse_operator_set_divergence(declared=declared, plan=projection)
    return ProjectionEngine(reader=r).execute(plan=projection)
```

```
coverage: names the binder? True
argument check problems: []
projecting bodies with this new example: 12 >= floor 11 -> True
readable binder sites with this new example: 11 >= floor 11 -> True
```

Every assertion in the module passes. `plan.required_operators()` is
`declared.required_operator_keys`, so `claimed == required` holds unconditionally at
`src/ccf/deployment/binder.py:156-159`. The binder is green, it cannot fail, and
`ccf.projection-requirements` has been routed around. **That is CR-03's own sentence,
reproduced against the fixed module.**

Note the floor does not save this. `MINIMUM_RESOLVED_BINDER_SITES` is an aggregate over
the whole tree: renaming an *existing* example's plan class drops it 11→10 and the
floor bites, but a *new* body contributes 0 readable sites while the eleven existing
ones still contribute 11, so 11 ≥ 11 holds (shown above).

**Why this is Critical and not Warning.** It is the identical defect statement the
withdrawn gate's CR-03 carried — "No live instance exists today; the defect is that
nothing stops the next one" — reachable by renaming one identifier, in the check
written to close it. It is aggravated by the module affirmatively documenting the
opposite at `:138-146`:

> *"Plan **execution** is not [a convention]: `ProjectionEngine.execute` declares
> `plan` keyword-only, so any body that runs a projection through the SDK's engine
> passes `plan=` whatever its plan class is called and is detected regardless. The
> surviving hole is therefore narrow — a non-`Plan`-suffixed class constructed and
> *returned* rather than executed…"*

That reasoning is sound for **coverage** and false for the **argument** half, which is
the half this remediation exists to add. A module whose stated value is honest
limit-declaration should not understate the one limit it just introduced.

**Fix.** Stop keying the *source* map on the class name. A projection plan
construction is recognisable from the keyword the check already reads:

```python
def _plan_sources(
    scope: ast.AST, aliases: dict[str, tuple[str, ...]]
) -> dict[tuple[str, ...], tuple[str, ...] | None]:
    sources: dict[tuple[str, ...], tuple[str, ...] | None] = {}
    for node in _scope_nodes(scope):
        targets, value = _assignment(node)
        if value is None or not isinstance(value, ast.Call):
            continue
        required = _keyword(value, PLAN_REQUIRED_KEYWORD)
        if required is None:
            continue          # not a plan construction on any reading
        source = _resolve(_path(required), aliases)
        for target in targets:
            sources.setdefault((target,), source)
    return sources
```

`_is_plan_construction` can keep the suffix for the coverage predicate (where a false
positive would matter); property (1) needs only "a call that was handed `required=`",
which no naming convention gates. Then add the probe pair to
`test_the_binder_argument_checks_reject_a_binder_that_cannot_fail`:

```python
# the same collapse, spelled with a plan class the Protocol does not require
# to be named `*Plan` — the convention must not be load-bearing for the
# argument half the way it is for coverage
"def serve(pid, r, declared):\n"
f"    plan = CreditProjection(plan_id=pid, {PLAN_REQUIRED_KEYWORD}={inline_claim})\n"
f"    {bind}\n"
f"    return {execute}\n",
```

and correct `:138-146` to say the suffix convention is load-bearing for property (1)
until it is not.

### WR-F1: property (1) is also vacuous for any `required=` expression without an identifier path, and that limit is not stated

**File:** `tests/products/test_gate_two_call_shape.py:353-393` (`_path`), `:895-898`
(the `_shares_a_source` short-circuit), `:123-146` (the limits list that omits this)

**Issue.** `_handed_plan_source` returns `None` whenever `_path` cannot read the
`required=` expression, and `_shares_a_source(x, None)` is `False`, so property (1)
reports nothing. Four spellings of the same collapse, all driven through
`_binder_collapses` and all **ADMITTED**:

```
E1  required=[*declared.required_operator_keys]        named=True -> ADMIT
E2  required=declared.required_operator_keys[:]        named=True -> ADMIT
E3  required=_keys(declared)                           named=True -> ADMIT
E4  required=declared.keys_of()                        named=True -> ADMIT
```

(The natural spellings *are* caught: bare attribute, one alias hop,
`frozenset(...)`, `tuple(...)`, `sorted(...)`, `cast(...)`, the `self._declared`
attribute form, and the inline-in-`plan=` form. I verified all of those reject.)

The module is scrupulous about naming this class of limit for tripwire (1)
(`:54-83` — helper return, method return, container, dynamic attribute). The
"What tripwire (2) still cannot see" section (`:123-146`) names the *plan object*
being unreadable but never the `required=` source being unreadable, which is
property (1)'s only input. As with CR-F1, the aggregate floor does not catch a
newly-added unreadable site.

Related, same family: `engine.execute(**kwargs)` is invisible to
`_is_plan_execution` (`:736` requires a `keyword.arg == "plan"`, and `**` gives
`arg is None`), so a body that only executes — no plan construction — is not a
projecting body at all under that spelling.

**Fix.** Add the sentence to `:123-146`:

> * **A `required=` expression with no identifier path.** Property (1) compares two
>   resolved paths; `required=[*claim]`, `required=claim[:]`, `required=derive(claim)`
>   and `required=claim.as_keys()` all resolve to `None` and the property reports
>   nothing. `MINIMUM_RESOLVED_BINDER_SITES` holds the *existing* sites readable; it
>   does not stop a new one being added unreadable.

and consider making that floor per-body rather than aggregate (see WR-F3), which
converts the residual from silent to loud for any body that acquires it.

### WR-F2: the alias and plan-source maps are not line-aware — red on correct code in tripwire (1), and blind in tripwire (2)

**File:** `tests/products/test_gate_two_call_shape.py:311-328` (`_scope_nodes`),
`:439-448` (`bindings.setdefault`), `:783` (`sources.setdefault`)

**Issue.** `_scope_nodes` pops from a stack, so it yields a body's statements in
**reverse** source order; combined with `setdefault`, both maps record the *last*
textual assignment to a name and apply it to every use of that name in the body,
wherever it sits. `_aliases`'s docstring calls this "the raw first-assignment map"
(`:436-437`), which is not what it is.

Two demonstrated consequences.

**(a) Tripwire (1) is red on correct code.** This body fills the lineage from the
product-class declaration and `engine_resolved` from the engine — the compliant
design-E2 shape — and is flagged:

```python
def serve(execution, candidate, declared):
    ops = frozenset(declared.required_operator_keys)
    product = ProductLineage(operators_invoked=ops)
    ops = execution.operators_invoked
    return run_gates(candidate, engine_resolved=ops)
```
```
aliases: {'ops': ('execution', 'operators_invoked')}
FALSE POSITIVE on correct code? True
  p.py:6: `run_gates(..., engine_resolved=...)` and the `ProductLineage(...)` at line 4
  both read `execution.operators_invoked`. …
```

This is pre-existing (I confirmed the same result against `f8bdb8e`'s module), but
WR-02's charter was exactly "a check red on correct code", 15.1-13-SUMMARY's threat
table records that threat as **mitigated** without qualification, and this is a second
mechanism producing the identical defect in the same helper. Reusing a local name is
ordinary Python, not an exotic shape.

**(b) Tripwire (2) property (2) is blind to a rebound plan local.** Because
`sources` is keyed by name with no line, and property (2) matches
`call.handed == execution.plan` on names, rebinding the plan between the bind and the
execute satisfies both:

```python
def serve(pid, r, declared, requirements):
    plan = FixturePlan(plan_id=pid, required=requirements.required_operator_keys)
    refuse_operator_set_divergence(declared=declared, plan=plan)   # binds object A
    first = ProjectionEngine(reader=r).execute(plan=plan)
    plan = FixturePlan(plan_id=pid, required=whatever_i_like(declared))
    second = ProjectionEngine(reader=r).execute(plan=plan)         # runs object B, unbound
    return (first, second)
```
```
E12  named=True -> ADMIT
```

The line-3 binder call never saw the object the line-6 `execute` runs. Property (2)'s
own message ("the plan bound is the plan run") is exactly what is violated. The mirror
case is caught only by the accident of reverse traversal picking the second
construction, which is not a property anyone should rely on.

**Fix.** Make both maps line-aware and drop the reverse-order dependence. Iterate the
body in source order (`ast.walk`-free, e.g. sort `_scope_nodes` output by
`(lineno, col_offset)` before building the maps) and record a list of
`(lineno, path)` per name rather than one entry; resolve a use at line *L* against the
last binding with `lineno < L`. Property (2) then compares `(name, binding_lineno)`
rather than `name`. Correct the `_aliases` docstring's "first-assignment map" wording
either way — today it describes neither the traversal nor the result.

### WR-F3: `test_the_binder_argument_scan_is_not_vacuous` asserts an aggregate, its docstring claims a per-site property

**File:** `tests/products/test_gate_two_call_shape.py:1140-1154`, `:279`

**Issue.** The docstring says:

> *"This one says the checks that read the binder's arguments can actually see, **at
> each of those sites**, which document the handed plan was built from. A check that
> matched every body and could resolve none of their plans would report zero problems
> forever — CR-03's failure mode restated one layer in."*

The assertion is `len(found) >= MINIMUM_RESOLVED_BINDER_SITES`, where `found` is a flat
list over all bodies. That is a **total**, not a per-site property. It coincides today
only because the counts are equal (11 bodies, 11 readable sites). Any body that gains a
readable site while another loses one leaves the total unchanged. Demonstrated in CR-F1
and WR-F1: adding a body with an unreadable plan source keeps the total at 11 and the
assertion green.

The IN-05 no-headroom reasoning itself holds and I do not disagree with it — headroom
on a *count* floor is a licence to lose a site silently, as argued. The harm is on a
different axis: this floor is being asked to carry a per-site guarantee a count cannot
express.

**Fix.** Assert the property the docstring states, per body, alongside the count:

```python
@pytest.mark.parametrize(("path", "scope"), _projecting_scopes(), ids=…)
def test_every_bound_body_has_a_readable_plan_source(
    path: pathlib.Path, scope: ast.AST

    aliases = _aliases(scope)

    calls = _binder_calls(scope, aliases)
    if not calls:
        return  # coverage's problem, not this one
    assert any(
        _handed_plan_source(call, sources, aliases) is not None for call in calls
    ), (
        f"{path.relative_to(REPO_ROOT)}:{_scope_line(scope)}: every"
        f" `{BINDER_CALL}` call in this body was handed a plan whose"
        f" `{PLAN_REQUIRED_KEYWORD}=` this module cannot read, so the argument"
        " check ran and could say nothing. Hoist the plan into a local built"
        " from `requirements.required_operator_keys`."
    )
```

Keep the count as the second line of defence; it is not the same statement.

### WR-F4: the WR-02 fix removed a true positive from tripwire (1), and the record says it removed none

**File:** `tests/products/test_gate_two_call_shape.py:375-392` (`_path` on `ast.Call`);
claim in `15.1-13-SUMMARY.md` §4 — *"This is not a loosening, and it was measurably a
strengthening."*

**Issue.** Before the fix, `_path` read `obj.method()` as `("obj",)`. That was red on
correct code (`self.declared_claim()` vs `self._resolved`) — WR-02 was right. But it
also caught a genuine collapse that is now admitted. Measured, same body against both
revisions:

```python
def serve(execution, candidate):
    product = ProductLineage(operators_invoked=execution.resolved())
    return run_gates(candidate, engine_resolved=execution.resolved())
```
```
BEFORE fix - same method both sides caught? True
AFTER  fix - same method both sides caught? False
```

Both operands are the identical expression and Gate 2 compares a value against itself.
The docstring does disclose it as a limit (`:60-69`), so the module is honest; the
SUMMARY is not, and that sentence is what the gate presentation carries.

The trade was also avoidable. The false positive came from collapsing a call to its
*receiver*; keeping the method name in the path distinguishes them:

```python
if isinstance(node, ast.Call):
    if isinstance(node.func, ast.Name) and node.args:
        …  # transparent conversions and cast, unchanged
    if isinstance(node.func, ast.Attribute):
        base = _path(node.func.value)
        # `execution.resolved()` -> ("execution", "resolved", "()"): the SAME
        # call on both sides still shares a source, while
        # `self.declared_claim()` and `self._resolved` do not, because the
        # third element is the member and the members differ.
        return None if base is None else (*base, node.func.attr, "()")
    return None
```

`_shares_a_source`'s prefix rule keeps `self.declared_claim()` (`self`,
`declared_claim`, `()`) and `self._resolved` (`self`, `_resolved`) distinct — neither is
a prefix of the other — while making two identical calls identical. If that is judged
too clever, the honest alternative is to keep the current `None` and delete the
"not a loosening" claim from the record.

absolute, rooted, drive-qualified or `..`-bearing; `(anchor / "").resolve()` is
`anchor`, which `is_relative_to(anchor)`. Measured:

```
empty string    ADMITTED but read raised IsADirectoryError: Is a directory: '…/deployment'
dot             ADMITTED but read raised IsADirectoryError: Is a directory: '…/deployment'
```

`IsADirectoryError` is not among `load_and_boot`'s documented `Raises:`, and CLAUDE.md
§11 puts validation at the boundary. `path: Annotated[str, StringConstraints(min_length=1)]`
plus a `resolved.is_file()` check in `_document_inside_the_deployment` closes both for
two lines. Not a security issue — the read fails and nothing is registered.

### IN-F2: a hardlink inside the deployment to a file outside it is admitted

**File:** `src/ccf/deployment/manifest.py:189-190`

`Path.resolve()` follows symlinks and cannot see hardlinks. Measured against a real
deployment directory:

```
HARDLINK to outside file    ADMITTED -> …/deployment/hard.yaml  content='secret: AKIA-TOP-SECRET'
```

The precondition is write access inside the deployment tree, which is also enough to
copy the file, so the practical gain to an attacker is narrow (a party who can write to
the deployment but cannot read the target's directory could still exfiltrate it). I
classify Info for that reason. It is worth a clause in
`_document_inside_the_deployment`'s docstring, which currently says *"what is in force
is the deployment's own tree, not whatever that tree points at"* — a hardlink is
neither, and the sentence reads as if it were covered.

### IN-F3: TOCTOU between preflight resolution and the phase-one read — could not construct a practical case

**File:** `src/ccf/deployment/manifest.py:414` (resolve) vs `:425` (read)

The resolved path is stored at preflight and read in phase one, so re-pointing the
*named* symlink between the two is ineffective — the stored value is already the
realpath. Replacing the realpath's final component with a symlink to an outside file in
that window would be followed by `read_text`. **I could not construct a case that does
not already presuppose write access inside the deployment tree**, at which point the
attacker can write the content directly. Reported as Info per the discipline. If this
is ever judged in scope, the mitigation is `os.open(..., O_NOFOLLOW)` on the final
component rather than a wider check.

### IN-F4: the two-flavour rule refuses the legal POSIX filename `a:b.yaml`

**File:** `src/ccf/controlplane/artifacts.py:719-726`

`PureWindowsPath("a:b.yaml").drive` is `'a:'` (ntpath splits on a single character
followed by a colon), so a one-character stem plus a colon is refused as
drive-qualified on Linux:

```
'a:b.yaml'    leaves=True
'ab:c.yaml'   leaves=False
```

This is a direct and accepted consequence of the platform-invariance decision — I agree
with that decision — but the cost is not stated anywhere. One clause in
`_leaves_its_own_directory`'s docstring ("a single-character name followed by a colon
reads as a drive to the Windows flavour and is refused, which is the price of one
document being admissible on every platform or on none") makes it a recorded trade
rather than a surprise.

### IN-F5: WR-05's rejection is correct — verified independently

**File:** `src/ccf/projection/engine.py`, `ProjectionEngine.execute`

Confirmed by `inspect.signature`, not by reading the source:

```
execute (self, *, plan, perspective, tenant_id, temporal_boundary, recorded_acquisitions=None)

```

The review's evasion body `ProjectionEngine(reader=r).execute(pi, perspective=q)` is a
