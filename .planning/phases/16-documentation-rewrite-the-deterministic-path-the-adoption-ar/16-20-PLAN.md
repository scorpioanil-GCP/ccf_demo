Prove Section 2's claim rather than asserting it: upgrade the zero-CCF-import
guard from a line-anchored regex to an AST matcher with a widened negative
control, assert that exactly three named harnesses are present, and write the
example's README.

Purpose: this plan exists because plan 16-09 carried three tasks over thirteen
files in the wave `16-RESEARCH.md` names riskiest. The seam is where the
**example works** (plan 16-09: fabric, four legs, deterministic fixtures) ends
and where the **claim is proven and documented** begins. Splitting here rather
than at the fabric/legs boundary keeps plan 16-12's Makefile work at wave 5
instead of cascading every downstream wave by one.

`examples/external/00-hello-context/run.py:421-430`'s `_assert_zero_ccf_imports`
is a `^(import|from) (ccf|ccf_runtime)` regex under `re.MULTILINE` — line
anchored, so it misses `importlib.import_module("ccf")`, an indented import
inside a function, and `__import__`. Phase 15.4's CR-02 adds a fourth blind
spot: `from ccf.graph import _writer` binds `ccf.graph._writer` but
`imported_module_names` reports only `ccf.graph`. A widened matcher with an
unwidened control is a widening nobody proved, so both move together.

Output: an AST guard callable from the driver and the test alike, a
five-spelling parametrized negative control, the exactly-three-harnesses
assertion, the spike's retirement, and a seven-heading README.
</objective>
