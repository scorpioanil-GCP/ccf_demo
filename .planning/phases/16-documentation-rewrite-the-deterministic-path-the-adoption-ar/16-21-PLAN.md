<objective>
Measure, once and re-runnably, every live coupling in the repository to a path
this phase retires — and assign each to an owning plan before any wave deletes
anything.

Purpose: the retirement inventory in `16-RESEARCH.md` § A.1/§ A.2 swept
`examples/`, `tests/examples/` and `public/` **only**, and
`[tool.pytest] testpaths = ["tests"]` means `make ci` runs the whole of `tests/`.
So gates in `tests/cli/`, `tests/products/`, `tests/conformance/`,
`tests/lints/`, `tools/*_tests/` and `perf/` hard-couple to retiring paths, are
all in the always-on path, and surface as a red build at the wave that deletes
their subject. Two review rounds found five instances of this one defect class,
each in a different tree and each breaking a different wave. Fixing instances
one at a time is losing; the sweep is the class fix.

This plan is separated from `16-04` deliberately. Its task imports nothing
`16-04` produces, its three files are touched by no other plan in any wave, and
the artifact it ships is the single dependency of all three retirement waves
(`16-15` at wave 8, `16-17` at wave 10, `16-18` at wave 11). Round-2 review
demonstrated that the sweep's **specification** is itself a defect surface — a
coupling shape it did not enumerate went undetected through a full review round —
which is the argument for giving it its own plan, its own review and its own
SUMMARY rather than carrying it as a fourth task behind three unrelated ones.

Output: one re-runnable repo-wide sweep, one checked-in inventory with an owning
plan per row, and one standing gate over the sweep itself.
</objective>

**(a) `tools/retirement_sweep.py`.** One re-runnable pass over the **whole
repository** for live references to every path this phase retires. Its target
list is data, not code: the ten retiring example directories
(`examples/00-quickstart`, `01-agent-basics`, `02-skilling`,
`03-harness-portability`, `04-cross-process`, `05-workflow-hitl`,
`06-decision-replay`, `07-artifact-store-mcp`, `08-e2e-demo`,
`examples/external/00-hello-context`), the `tests/examples/test_*_output.py` and
`test_ext00_*.py` modules that retire with them, and the published pages
scheduled for deletion (`public/tutorial/adopters-guide.md`,
`public/tutorial/demo-walkthrough.md`). Read the list from a module-level
constant so a later plan can extend it without touching the walk.

**Live means live.** For `.py` files, parse with `ast` and classify a hit as
live only if it is **not** inside a module/class/function docstring and not on a
comment line — `tests/deployment/test_operator_builder.py:479` names
`examples/02-skilling` in a docstring and is not a coupling, while
`tests/cli/test_schema_export.py:60` builds a `pathlib.Path` from the same kind
of string and is. For non-Python files (`Makefile`, `*.yml`, `*.toml`,
`mkdocs.yml`, `*.md` outside `public/`) fall back to a token match with the
file's own comment syntax excluded, and say in the docstring that the
non-Python half is deliberately coarser.

Walk from `REPO_ROOT = pathlib.Path(__file__).resolve().parents[1]`, never
`Path.cwd()` — WR-04 is the recorded failure where a CWD-relative walk scanned
zero files and the gate passed over nothing.

**Report the `tmp_path` distinction rather than dropping it.** Some references
write a retiring path as a **synthetic token into a `tmp_path` tree** and never
resolve it on disk — `tests/lints/test_examples_scope.py` writes
`examples/00-quickstart/run.py` and `examples/03-harness-portability/run.py`
into a scratch tree, and
`tools/publish_scan_tests/test_publish_scan.py::test_include_of_example_source_is_clean`
does the same. These **survive** the deletion mechanically but still name a
directory that will not exist. Emit them with a `survives` marker and an owner,
not with no owner and not omitted: the owning plan repoints the token so the
fixture does not outlive its subject.

**(b) Count couplings — all three shapes, because two are not enough.** A count
coupling is a coupling with no path token in it: an assertion over *how many*
sites exist in a tree, which no grep finds and which no deletion breaks visibly
until `make ci` runs. This tree carries three shapes and the sweep must detect
each. Enumerating only the first two is precisely the specification defect
round-2 review found, and it is the reason this task is its own plan:

1. **Module-level `MINIMUM_*` constants** —
   `MINIMUM_GATE_CALL_SITES`, `MINIMUM_PROJECTING_BODIES`,
   `MINIMUM_RESOLVED_BINDER_SITES` in
   `tests/products/test_gate_two_call_shape.py`, and
   `MINIMUM_IMPLEMENTATIONS` in `tests/products/test_required_operators_guard.py`.
   Detect by AST: a module-level integer assignment whose name matches the
   floor convention. Owner: 16-18.

2. **Module-level scan functions** — `_gate_scopes`, `_projecting_scopes`,
   `_resolved_binder_sites`. Detect by calling each and reporting how many of
   the sites it finds lie under a retiring path. Owner: 16-18.

3. **Inline tree-witness assertions — the shape with neither a constant nor a
   named function.** An assertion whose evidence base is a scan written
   **inline in the test body**, keyed off a module-level scanned-tree tuple, and
   whose truth depends on at least one witness existing under a retiring path.
   The measured instance is
   `tests/products/test_gate_two_call_shape.py::
   test_the_plan_recognition_refuses_an_unrelated_required_keyword` (line 3139),
   which asserts `assert unrelated` over `BINDER_SCANNED_TREES = ("examples",)`
   (line 369). **Verified at HEAD: the scan returns exactly one witness —
   `examples/03-harness-portability/run.py:693`, an `argparse` flag carrying
   `required=True` — so `n = 1`, and plan 16-15 deletes it at wave 8.**
   Owner: **16-15**, three waves earlier than the `MINIMUM_*` owners.

   Detect this shape by walking each `tests/products/**` test function body for
   a scan rooted at a module-level scanned-tree constant (`SCANNED_TREES`,
   `BINDER_SCANNED_TREES`, or any tuple-of-tree-names bound at module level),
   evaluating how many witnesses the scan finds, and reporting a row whenever
   **any** witness lies under a retiring path. Report the witness count in the
   row — a coupling with `n = 1` is materially more urgent than one with
   headroom, and the report should say so rather than leaving it to be
   rediscovered.

   Two dead ends to avoid, both measured: the sweep must **not** rely on the
   witness path appearing as a string token in the module — the only occurrence
   of `examples/03-harness-portability/run.py:693` in that file is inside a
   **docstring**, which this sweep's own liveness filter correctly classifies as
   not-live. And it must **not** restrict itself to module-level scan
   functions — this scan is inline in the test body. A sweep that does either
   misses this row in both directions, which is exactly what happened.
