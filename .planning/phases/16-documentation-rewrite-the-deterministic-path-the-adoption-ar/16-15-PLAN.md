<objective>
Publish Section 2 and retire the first example, atomically with the one page that
sources from it.

Purpose: Section 2's constraint **is** the demonstration — the client has no CCF
dependency, and that must be visible in the client code's import list. This is
the primary adoption path, and `D-09` keeps all three harnesses because a
three-way assertion is materially stronger than a two-way one and because
`D-IMPL-24` ruled all three ship v0 reference adapters.

`16-RESEARCH.md` § A.2 measures its dependency row as exactly one page,
`how-to/bind-a-harness-adapter.md` (6 includes). It is the first example whose
deletion and whose page re-cut can land in one plan, which is criterion 5's
"no partial state" in its strictest reading.

Every other example's row includes `tutorial/adopters-guide.md`, which is
terminal-wave work (plan 16-18) — 447 lines, 35 includes, six of the ten
examples, and the phase's single hardest scheduling constraint.

Output: two new pages, one re-cut page, nav, one example retired with its test
module and Makefile target, and every gate green.
