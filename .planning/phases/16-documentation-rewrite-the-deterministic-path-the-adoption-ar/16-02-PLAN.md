<objective>
Extend the KYC/UBO enterprise source estate so that the question the whole
adoption argument is built on — *"Who ultimately owns Acme?"* — has a chain to
traverse, and ship it as an in-repo deterministic generator so always-on CI can
read it without a network.

Purpose: `16-RESEARCH.md` FINDING F-1 measured the shipped FIBO dataset and
found that `ownershipPercent` is an attribute of the **Party entity**, not of the
ownership relationship, and that every `hasOwnershipInterestIn` edge runs
Party → Corporation in exactly **one hop** — no corporation owns another. D-03's
stated teaching property (*"multi-hop ownership chains are what a graph does and
what chunk retrieval does badly"*) and D-10's worked demonstration
(*"traversing an ownership chain, aggregating percentages across hops"*) are
both unanswerable on that data. Dave's own instruction covers the remedy:
*"use the use case that the backend fibo based data stores can support today
**or be provided additional data to support**"*.

This is a **prerequisite of criterion 7**, not a nice-to-have. Every KYC/UBO
example and every page built on the UBO question is written against what this
plan produces.

Output: a definition artifact carrying the extended ownership vocabulary, a pure
interpreter that materialises it into a standalone source-system file, an
assertion suite proving the chain and the aggregation, and — behind a human
checkpoint — the same extension loaded into the four DGX FIBO stores.
</objective>
