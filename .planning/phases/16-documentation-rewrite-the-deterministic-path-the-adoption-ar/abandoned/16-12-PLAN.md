<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions secrets → job environment | Real DGX credentials cross into a runner; anything echoed there is public for the life of the log. |
| repository → DGX host | The opt-in job reaches a host outside GitHub's network; it must never run unattended. |
| workflow file → tree | A credential written into a workflow file is a credential in the tree. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-16-12-01 | Information disclosure | DGX credentials in logs or files | mitigate | Credentials arrive only as `${{ secrets.* }}`, are never echoed, and never enter the tree; `tests/examples/test_no_credential_in_tree.py` asserts absence with a control that fires, and `canonical_bytes` refuses `SecretStr` so a secret cannot be hashed into an artifact. |
| T-16-12-02 | Denial of service | a scheduled run against an unreachable host | mitigate | The DGX job is `workflow_dispatch` only, never on the weekly cron — the same reason recorded for `examples-live-anthropic`: a scheduled run would go red weekly for a reason unrelated to any change. |
| T-16-12-03 | Spoofing | a missing secret silently degrading to a skip | mitigate | The fail-fast precondition runs before any setup work and exits 1 with `::error::` guidance; `CCF_REQUIRE_*=1` plus `-rs` make a skip a failure in the leg itself. |
| T-16-12-04 | Tampering | the network-free claim for always-on CI | mitigate | The always-on legs run inside the non-loopback socket guard, which is proven to fire; the `examples` job gains no service container, and the `D-06` distinction is stated in a workflow comment rather than left to inference. |
| T-16-12-06 | Repudiation | misattributing a wave-5 `make examples` failure | mitigate | `make ci` here executes `examples/s2-01-external-consumers/run.py`, which plan 16-20 rewrites in the same wave. The dependency route was refused with a stated reason (it cascades every downstream wave by one, which is the cost 16-20's split exists to avoid); the hazard is bounded by 16-09's already-green wave-4 driver and by 16-20's own `run.py`-exits-0 verification, and an attribution rule plus a `git diff --stat -- examples/` criterion keep the repair in the plan that owns the file. |
| T-16-12-05 | Repudiation | `make ci` claiming to be the pipeline | mitigate | `ci` now composes the three gate-checker suites (`D-IMPL-94`, Q-8), so the description matches the mechanism instead of describing an aspiration. |
| T-16-12-SC | Tampering | npm/pip/cargo installs | accept | No install; the CI jobs use the existing `.[dev]` extras. |
</threat_model>
