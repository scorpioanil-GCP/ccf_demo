`_prose.PUBLIC_DIR` — `REPO_ROOT / "public"`, resolved from `__file__`, never the CWD.
`_prose.published_pages(root=None) -> list[pathlib.Path]` — `sorted(base.rglob("*.md"))`.
`_prose.iter_paragraphs(pages, *, prose_only=True)` — yields `(page, Paragraph)`; `prose_only=True` skips fenced blocks.
`_prose.page_paragraphs(path) -> list[Paragraph]`.
`_prose.Paragraph` — `NamedTuple(text, lineno, raw, fenced, info)`. `text` is markup-stripped with code spans removed and casing preserved; `raw` is untouched.

**`strip_markup` deletes backtick code spans, and this decides which field each
vocabulary matches.** `_prose.strip_markup` is documented as *"`text` with HTML
tags and backtick code spans removed"*; `Paragraph.text` is built from it and
`Paragraph.raw` is not. So an identifier written `` `D-IMPL-46` `` is INVISIBLE
in `.text` and present in `.raw`. This is not hypothetical on this tree:
measured, 4 of the 10 published paragraphs carrying a `D-IMPL-NN` id today
write it only inside a code span — `.text` sees 6, `.raw` sees 10. A
`CAVEAT_CONTRACT` matched against `.text` would therefore find nothing on a
CORRECT page, and the consequences would all read as green or as a
mysteriously-red floor: the positive caveat assertion RED, the
"had something to assert over" floor RED, control 3 RED, and control 7 passing
for entirely the wrong reason.
`_prose.sentence_at(text, offset) -> str` — the sentence containing `offset`. This IS the sentence scoping.
`_prose.relative(path) -> str` — repo-relative POSIX, absolute if off-root (which is what tmp-dir controls need).

Create `tools/docs_tests/test_adoption_wording.py`.

Open with a module docstring in the house voice that states, at minimum: which
requirement and which decisions it enforces (`DOCS-15`, `22-CONTEXT.md` D-02,
D-03, D-04, D-05); the two obligation ids `AW-1` and `AW-2` and what each means
in one sentence; why AW-2's non-vacuity is proven by an injected control rather
than by a corpus floor, in the A-3 manner and with the measurement behind it
(the published tree carried three `passage` occurrences at this plan's HEAD,
two of them the correct phrase `passage-level lineage`, so a corpus floor
asserting some paragraph triggers the extraction predicate would be RED on a
correct tree); and — stated plainly, because this repository's standing lesson
is that a check which does not say what it is blind to is how a defect class
survives — the module's own TWO blind spots:

1. it reads markdown SOURCE, so content arriving through a `--8<--` include is
   never scanned, and a naked claim inside an included artifact would be
   invisible to it;
2. `strip_markup` removes backtick code spans from `Paragraph.text`, so any
   vocabulary matched against `.text` is blind to a backticked spelling — which
   is why the identifier-shaped vocabulary below is matched against
   `Paragraph.raw` instead, and why one control exists solely to hold that.

Then the vocabulary, as `#:`-documented module-level compiled regexes. **Each
constant's `#:` comment must NAME the `Paragraph` field it is matched against
and give the one-line reason.** The split is not a preference; getting it wrong
turns a correct page red and an incorrect one green:

- Matched against **`Paragraph.text`** — the prose vocabularies. These describe
  how a sentence READS, and a claim hidden inside a code span is not a claim a
  reader takes away: `EXTERNAL_APPROACH`, `LIMIT_VERB`, `PASSAGE_ANCHOR`,
  `EXTRACTION_VERB`, `DOCUMENT_SOURCE`, `EXTRACTION_DENIAL`, `CAVEAT_ABSENCE`.
- Matched against **`Paragraph.raw`** — the identifier-shaped vocabulary.
  `CAVEAT_CONTRACT` matches `D-IMPL-46` together with a `passage_anchor` token,
  and this repository writes decision ids and identifiers inside backticks as
  house style. Measured: 4 of the 10 published paragraphs carrying a
  `D-IMPL-NN` id write it only in a code span; `.text` sees 6, `.raw` sees 10.
  Against `.text` this constant would find nothing on a correct page.

`paragraphs_carrying_the_caveat` therefore tests ONE `Paragraph` object against
TWO fields — `CAVEAT_CONTRACT` on `.raw`, `CAVEAT_ABSENCE` on `.text` — which
is still "both halves in one paragraph", and say so in its docstring so a later
reader does not "fix" it into one field.

The vocabularies themselves:

- `EXTERNAL_APPROACH` — the subjects: RAG, retrieval-augmented, vector store,
  vector database, embedding search, semantic layer, prompt template,
  hand-rolled or hand rolled, chunked documents. Word-bounded where a bare
  substring would over-match.
- `LIMIT_VERB` — the `X can't Y` shape: cannot, can't, can not, unable to,
  lacks, lacking, fails to, fail to, has no, have no, does not support,
  doesn't support, do not support, incapable of, no way to, falls short.
  Word-bounded on purpose; an unbounded `no` matches "note" and "nothing" and
  would make every paragraph an offender.
- `PASSAGE_ANCHOR` — `passage anchor`, `passage anchors`, `passage-level
  lineage`. **Never a bare `passage`** — `public/charter.md` uses it in an
  unrelated sense and a bare token would produce a false finding on correct
  prose.
- `EXTRACTION_VERB` — extract, extracts, extracted, extracting, derive,
  derives, pull, pulls, lift, lifts, produce, produces, generate, generates.
- `DOCUMENT_SOURCE` — document, documents, your documents, PDF, corpus,
  unstructured.
- `EXTRACTION_DENIAL` — the NARROW denial vocabulary that takes a production
  claim as its object and marks a sentence as denying extraction rather than
  asserting it: `no shipped pipeline`, `no pipeline`, `never built`,
  `was never built`, `does not produce`, `do not produce`, `does not extract`,
  `do not extract`, `nothing in the shipped`, `no such pipeline`. **Matched
  against `Paragraph.text`.** It is deliberately NOT a general negation
  vocabulary. A bare `not` or `no` would exempt any sentence carrying an
  unrelated negative clause anywhere in it, and an exemption limb that broad
  becomes the hole it was added to close — which is why controls 10 and 11 and
  sabotage 7 exist below.
- `CAVEAT_CONTRACT` — the half saying the contract ships: `D-IMPL-46` together
  with a `passage_anchor` token. **Matched against `Paragraph.raw`** — both
  tokens are identifiers and the page writes them backticked, which `.text`
  deletes. Note that a `passage_anchor` token with an underscore is also
  invisible to `PASSAGE_ANCHOR`, which is a `.text` vocabulary matching the
  prose forms `passage anchor` / `passage anchors` / `passage-level lineage`;
  the two constants are deliberately different and must not be merged.
- `CAVEAT_ABSENCE` — the half saying no shipped pipeline produces passage
  anchors from documents. **Matched against `Paragraph.text`** — it is ordinary
  prose and plan 02 is instructed not to backtick it.

**Why AW-2's negative predicate needs a denial limb — state this in the
predicate's docstring so a later reader does not delete the limb as clutter.**
The caveat ROADMAP criterion 6 requires, and which plan 02 ships in almost these
words, is *"Pattern 5, unstructured ingestion, was never built, so no shipped
pipeline produces passage anchors from documents."* That sentence matches
`PASSAGE_ANCHOR`, `EXTRACTION_VERB` (`produces`) and `DOCUMENT_SOURCE`
(`documents`) — all three. A predicate built from those three alone matches the
SHAPE of an extraction claim without reading whether the sentence asserts it or
denies it, so the most careful possible statement of the caveat is
indistinguishable from the overclaim the obligation exists to prevent. On a
CORRECT tree that predicate would turn AW-2's negative assertion RED, control 3
RED, and plan 02 task 3's own page audit RED. The limb below is the fix; the
wording stays, because criterion 6 quotes it almost verbatim.

Then the predicates, each a module-level function returning a list of
`page:line — sentence` strings so a red run is openable:

- `sentences_asserting_a_capability_limit(pages)` — for each paragraph matching
  `EXTERNAL_APPROACH`, for each such match, take `_prose.sentence_at` and
  report it if that SENTENCE also matches `LIMIT_VERB`. Paragraph is
  candidacy; sentence is judgement.
- `sentences_claiming_passage_extraction(pages)` — for each paragraph matching
  `PASSAGE_ANCHOR`, for each such match, take the sentence; it is a CANDIDATE if
  that sentence also matches `EXTRACTION_VERB` and `DOCUMENT_SOURCE`. Before
  reporting a candidate, apply the denial limb as a `continue` carrying an
  inline comment in the analog's *"this is a legitimate way to be right"* idiom
  (`tools/docs_tests/test_gate_two_wording.py` is the shape): skip the candidate
  if `EXTRACTION_DENIAL` matches the sentence **at an offset LOWER than the
  earliest `EXTRACTION_VERB` match in that same sentence**. Two conditions, both
  required, and the reason for each goes in the comment — the restricted
  vocabulary stops an unrelated negative clause from exonerating a claim, and
  the ordering requirement stops a denial appended AFTER the claim from doing
  the same. Everything not exempted is reported.
- `paragraphs_carrying_the_caveat(pages)` — the positive side: every paragraph
  whose `.raw` matches `CAVEAT_CONTRACT` AND whose `.text` matches
  `CAVEAT_ABSENCE`, reported as `page:line`. Two fields, one `Paragraph`.

Then the non-vacuity floors, under a banner comment in the analog's style
saying that a vacuous pass is the failure this module exists to prevent:

- **Three separate floors, not one test with three clauses.** A single
  `test_the_published_tree_is_populated` bundling "the directory exists", "the
  page list is non-empty" and "some paragraph matches `EXTERNAL_APPROACH`"
  fails ambiguously: a red from the first clause satisfies any control that
  only asks for "a red naming the external-approach vocabulary", which is a
  control that proves nothing. Write them as three, each with its OWN assertion
  and its OWN message naming what specifically was missing:
  - `test_the_published_directory_exists` — `_prose.PUBLIC_DIR.is_dir()`.
    Message names `PUBLIC_DIR` and its resolved path.
  - `test_the_published_tree_has_pages` — `published_pages()` is non-empty.
    Message names the page count and `PUBLIC_DIR`.
  - `test_some_published_paragraph_names_an_external_approach` — at least one
    published paragraph matches `EXTERNAL_APPROACH`. Message names
    `EXTERNAL_APPROACH` and states that this is AW-1's corpus floor. This one
    became satisfiable only when this phase's page shipped; say so in the
    docstring.
- `test_the_passage_vocabulary_is_present_in_the_published_tree` — at least one
  published paragraph matches `PASSAGE_ANCHOR`, so AW-2's walk is reading
  something. Name the pages that satisfy it today in the docstring.
- `test_the_positive_caveat_assertion_has_something_to_assert_over` — at least
  one published paragraph matches `CAVEAT_CONTRACT`, so the positive assertion
  below is not filtering an empty set.
- `test_the_denial_limb_is_load_bearing_on_the_shipped_page` — the limb's own
  non-vacuity floor. Locate the shipped caveat sentence in the published tree
  and assert TWO things about it: that it matches `PASSAGE_ANCHOR`,
  `EXTRACTION_VERB` and `DOCUMENT_SOURCE` — so it genuinely IS a candidate the

  dead code against the real tree and nobody would find out until someone
  deleted it and the build stayed green. The message names `EXTRACTION_DENIAL`
  and quotes the sentence.
- `test_the_walk_does_not_depend_on_the_process_cwd` — `monkeypatch.chdir(tmp_path)`

Then the three shipped assertions, each with a three-part failure message
