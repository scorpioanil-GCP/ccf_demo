### Control 7 — a defect I shipped and then caught

The plan asked for pairwise distinctness in `len(set(x)) == len(x)` form. I
wrote it that way, then sabotaged it by giving the two-token branch the generic
branch's message **verbatim** at the source level.

**It passed.** Every refusal interpolates the offending address, so two branches
carrying byte-identical template text still *render* differently:
`` `a b c` states 3 tokens… `` and
`` `examples/…/serve.py examples/…/deployment` states 2 tokens… ``. Whole-message
distinctness in this module is nearly free and therefore nearly worthless — the
exact "verification code is where the defects land" pattern, with the shipped
mechanism correct and the proof machinery wrong.

**Fix:** a `SIGNATURES` register mapping each refusal to the clause it owns, and
an assertion that each clause appears in **exactly one** of the five messages.
That catches both collapses — a clause in two messages (control 8) and a clause
in none (control 7b) — and the individual controls now assert against the same
register, so the phrase is decided in one place. Whole-message comparison is
kept beside it. `SIGNATURES`' docstring records the measurement so the next
reader does not weaken it back.

### Control 10, read honestly

`declare_server` as a no-op broke the **three stub-program legs** and not the
healthy one. That is correct and worth recording rather than glossing: `_root`
