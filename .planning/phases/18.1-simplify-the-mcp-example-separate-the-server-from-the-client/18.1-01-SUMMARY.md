## Task 2 — `server:` in the loader

### The parameterization choice, and why

**Chosen: a sibling parameterized test** (`test_binding_document_refuses_a_server_leaving_the_holding_directory`),
not a third limb of the existing two-key `test_binding_document_refuses_a_path_leaving_the_deployment`.

Reason: the existing test asserts the literal `"outside the deployment root"`, and a
`server:` limb **must not** assert that string — asserting it and passing would prove
the base description was never threaded through, which is exactly the `B0b`
report-quality defect wearing a green tick. Adding a per-key expectation map would have
meant editing the shipped assertions of the `config` and `artifact_store` limbs to carry
a parameter only one key uses. The sibling shares `_document`/`_rewrite` and adds a
shared helper, `assert_the_refusal_named_the_parent_as_the_base`, which asserts **both**
halves: the correct base is named *and* `the deployment root` is not.

The pre-existing test's docstring now says there are three paths and where the third's
limbs live. Its assertion strings are untouched — `grep -n "outside the deployment root"
tests/client/test_binding_document.py` returns exactly 3 hits, all pre-existing, none
inside a `server` limb.

### D-18's refusal message, as shipped

```
`server: {declared}` in {document} resolves to {resolved}, which is inside the
deployment root {root} — `D-IMPL-141` Amendment A.3 grants that directory **one**
Python module, its projection, and a server program is not deployment content. Name
```

test, not by eye.

## Task 3 — the two committed deployments and the provisioning sites

### `declare_server`'s final signature

```python
def declare_server(root: Path, program: Path) -> None
```

`program` is an **absolute path to the file as it now sits on disk**; the value written
is `program.resolve().relative_to(root.parent.resolve())`. One signature, used
identically at both call sites. It **raises `ValueError`** when `program` is not under
`root.parent`, rather than writing a value the loader would refuse for containment — a
fixture failing for a reason no test is about is `T-18.1-05` arriving by the back door.

The module docstring's *"an `mcp+stdio` binding names the two separately"* is gone
(`grep -c "names the two separately"` → 0), replaced by the reason the layout is right:
the program sits one level up, which is where `server:`'s parent-relative base looks.

## Deviations from Plan

### 1. [Rule 2 — missing critical verification] The conformance provisioning site had no check that could fail

**Found during:** Task 3, sabotage control 7.

**Issue:** The plan wires `declare_server` into `tests/client/conformance/conftest.py`
and correctly notes the site is *inert today* — the conformance factories still build
two-token addresses, so nothing reads the declaration. That also means **no test in the
suite could observe the wiring being wrong.** Sabotage 7 removed both provisioning lines
and the entire conformance package stayed green (`69 passed`); the defect was only
visible by measuring the fixture directly, by hand. That is a check wired to nothing —
the failure mode `T-18.1-13` describes, in the site the plan added it to.

**Fix:** Added `tests/client/conformance/test_the_provisioning_declares_a_server.py` —
two tests over the `provision` fixture asserting a handed-out root's `server:` is not
`None`, `is_file()`, and sits in the copied root's parent; the second asserts it for
**every** root a single test is handed, not only the first. Re-run as control 7b: both
go red under the same sabotage.

**Files:** `tests/client/conformance/test_the_provisioning_declares_a_server.py` (new)
**Commit:** `482ffca`

### 2. [Rule 1 — bug in the plan] The plan's spelling of an inward `server:` value does not reach inward

**Found during:** Task 2, writing D-18's test.

**Issue:** The plan writes the inward value as `server: projection.py` (Task 2
`<behavior>`, and Task 3 `<action>`: *"set `server` to a value inside the root
(`projection.py`)"*). With the base at `root.parent`, `projection.py` resolves to
`<parent>/projection.py` — **outside** the deployment root. D-18 would never fire and
the test would have proved nothing. `18.1-CONTEXT.md` D-18 has it right
(`server: deployment/anything.py`); the plan's restatement dropped the leading segment.

**Fix:** Both tests compute it — `f"{deployment_root.name}/projection.py"` and
`f"{seeded_root.name}/projection.py"` — which is robust to the root's directory name
rather than hard-coding `deployment/`.

**Files:** `tests/client/test_binding_document.py`, `tests/client/test_data_only_deployment.py`
**Commit:** `ffe6826`, `482ffca`

### 3. [Rule 1 — false green caught in RED] The reference-shape test passed for the wrong reason

**Found during:** Task 2's RED gate — 9 of 10 tests failed and one passed.

**Issue:** `test_a_reference_shaped_server_is_refused_as_a_reference` asserted only
`` "`server`" in message ``. Before `server` joined `OPTIONAL_KEYS`, the **unknown-key**
refusal produced that substring, so the test passed against a loader that had never seen
the key. Per the TDD fail-fast rule, this was investigated rather than accepted.

**Fix:** Strengthened to assert `` "`server: serve.py:main`" `` and
`"reference in a **data** position"` — strings only `_refuse_references_in_data` emits.
The test then went red and came green for the right reason.

**Commit:** `10cb22c`

### 4. [Rule 3 — scope] Two committed-deployment assertions live in `test_binding_document.py`

The plan's Task 3 `<files>` names no test module for the *hw1* claim. Both
committed-deployment assertions were put in `tests/client/test_binding_document.py`,
which is already in the plan's file list and is where loader claims about committed
documents belong. The alternative — `tests/examples/test_hw1_two_transports.py` — runs
the example end to end and would have paid ~5 s for a loader assertion.
