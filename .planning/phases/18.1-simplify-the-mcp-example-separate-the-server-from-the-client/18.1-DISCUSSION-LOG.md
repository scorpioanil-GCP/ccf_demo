## How simple is simple enough for `serve.py`

**This area opened with Dave reopening the morning's residence ruling.** Asked
where the cut should fall between the two modules, he replied instead:

> *"Where do you believe the server should reside? In practice the server will be
> on a different machine more than likely. It could be placed in its own directory."*

Claude's answer, given as a recommendation rather than a survey: the server should
stay **outside** the deployment root. Filing it inside to satisfy a path check
makes the example teach that a server is deployment *content*, which is false —
the normal case is a remote server reached by an endpoint, with `server:` absent
entirely, and a design that reads correctly when the key is missing is the right
design. Keeping it a sibling is also strictly less mechanism (no A.3 amendment, no
gate rewrite) and costs nothing on the portability demo, since both addresses
still name the identical token.

### Q1 — Where does the server reside? *(reopened)*

| Option | Description | Selected |
|--------|-------------|----------|
| Sibling; resolve `server:` against the parent | Containment enforced against a declared base; A.3 and the gate untouched | ✓ (see Q2) |
| Sibling; `server:` exempt from containment | The path says what it is, at the cost of the first hole in the rule | |
| Keep the morning's decision — move it inside | Containment untouched, at the cost of teaching that servers are deployment content | |

**User's choice (free text):**

> *"Server is temporary in this specific example because it is not the focus. Make
> sure not to generalize the documentation that servers will always be in
> deployment — they will not. When we get into Context Product development we will
> put the server at the top level. My vote is to have two directories at the top:
> client and server. This way there is no confusion. This is what I want going
> forward but am ok leaving it where it is as a temporary measure."*

**Resolved as:** `server/` stays where it is — a sibling of `deployment/` at the
example's top level. The `client/` + `server/` restructure is **deferred** to the
assembly examples. A documentation constraint was created from the middle sentence.
