## Rulings settled at planning

1. **Module name: `compose.py`.** Collision-free (0 existing basenames, re-measured), and it
   is what D-11 named the cut. Three alternatives were rejected and the rejections are
   recorded here so they are not re-litigated at review:
   - **`run.py` — forbidden.** It is `EXAMPLE_ROOT_MARKER` (`tests/examples/test_artifact_schema_headers.py:159`),
     matched by an **rglob** at `:206`. A `server/run.py` would register `server/` as an
     example root and fail the artifacts bijection, which owns no `artifacts/`.
   - **`boot.py` — rejected.** `src/ccf/boot.py` exists; a second makes the basename
     ambiguous to `tools/lints/citations.py`'s `repo_index`, which **drops** ambiguous-basename
     citations from the sweep rather than checking them. A silently unchecked citation is
     worse than a refused one.
   - **`deployment.py` — rejected by position**, despite being the strongest idiom match in
     `examples/`. A `server/deployment.py` sitting beside `deployment/` would read as a second
     deployment root.
   - **`resolver.py` — rejected by name**, per CONTEXT: `binding.yaml` refuses a `resolver:`
     key **by name**, and a module of that name beside the deployment would read as the thing
     that was ruled out.
2. **The export is one function returning a frozen dataclass, not a 3-tuple.** Modelled on
   `src/ccf/client/adapters/inprocess.py:125-143` (`_BootedDeployment`), which carries
   `fabric`, `control_plane`, `resolver` — literally D-11's three values. A bare 3-tuple in
   example code that is meant to be **read** is the wrong teaching for an adoption-contract
   example. The bundle carries exactly the three; it does **not** carry `document` or
   `schema_version`, because after Ruling 3 the door half needs neither.
3. **Entitlement-policy registration MOVES into `compose.py`.** D-11 enumerates what
   `serve.py` keeps — *"read the door's four governance values, `build_egress_server`, set the
   stdio identity, run on stdio"* — and registration is not in that list; the ROADMAP scope
   bullet independently calls it composition. Both agree. Its two inputs (`fabric.artifacts`
   and `control_plane`) are composition products and it produces neither, so leaving it
   door-side would make the door reach into the bundle for a value it does not otherwise use.
   **The tension worth recording:** the shipped analog `tests/client/fixtures/stdio_server.py:126-141`
   keeps registration door-side. That file is a **test fixture**, written before D-11 and not
   bound by it, and it reaches a private seam this example may not. Follow D-11; note the
   divergence in the SUMMARY.
4. **Per-boot token minting STAYS in `serve.py`.** The ROADMAP scope bullet lists it among
   the composition; D-11 — later, and specific about what the door keeps — lists *"set the
   stdio identity"* as door-side. `server/egress-door.yaml:28-30` states in writing that
   *"`serve.py` mints a throwaway credential per boot into a temporary directory that is
   deleted on exit"*, and the credential is consumed twice on the door side and nowhere else.
   Moving it would make the composition module return a credential it has no business holding
   and falsify a document this phase does not open. **D-11 is the later, more specific ruling
   and wins over the earlier ROADMAP bullet. The tension is recorded, not resolved silently.**
5. **`compose.py` composes through public seams only.** `serve.py`'s own docstring commits to
   this in writing (`:32-38`) and `tests/client/fixtures/stdio_server.py:29-40` names
   `serve.py` as the file that must not reach `_boot`. All three bundle types are public and
   importable: `BootedFabric` from `ccf.deployment` (`__init__.py:145`), `ControlPlaneProtocol`
   from `ccf.controlplane.registry` (`:64`), `ServedProductResolverProtocol` from
   `ccf.products.resolver` (`:177`). **Do not import anything private.**
6. **No line budget, anywhere.** D-12. Do not add a `declared budget:` line to any README —
   `check_example_budget` parses exactly one per README and returns `None` on two, which makes
   `check_example_budget` report *"declares no line budget"*, a red gate reading as the
   opposite of what happened. Do not add a server README. Do not add a second checker.
7. **`_artifact`'s narrowing refusal is NOT copied.** `inprocess.py:201-222` has a better
   refusal than `serve.py:191-196`'s bare `fabric.artifacts[key]` + `isinstance` raise — it
   enumerates the keys the deployment does hold. Adopting it would be **new prose in an
   example** in a phase scoped to simplify one, so the move is a **move**: carry
   `serve.py:191-196` across verbatim. Recorded as a deliberate non-adoption.
