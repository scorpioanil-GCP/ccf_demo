<objective>
Run the out-of-tree adapter through the same conformance suites the six built-in
adapters run through, and take the measurement the phase's headline claim rests
on.

The claim is that per-adapter substrate cost is zero. The measurement is
`git diff --stat src/ccf` over the commits that added the adapter, and it has to
be empty. That is an assertion about repository history rather than about a
running program, which is why it is taken deliberately and recorded verbatim
rather than inferred — and why its range is a SHA plan 15.4-10 wrote down
(`ADAPTER_BASE`) rather than something re-derived here from a commit message.

One failure mode is specifically guarded here. The conformance parameter lists
are hand-written in two files. An adapter that is installed but named by no
param produces a proof that proves nothing, and it looks green. So a third test
asserts the param lists and the registry agree — a mismatch fails loudly instead
of passing quietly.

The unchanged bar also applies: four database legs green, and
`tests/conformance/query_corpus.py` byte-untouched for the whole phase. Under
D-IMPL-93's own standard, "the corpus grew" is recordable and "the SDK bent"
fails.

Purpose: turn the proof into evidence.
Output: two params, one parity test, one published how-to page, and the V8
measurement.
</objective>

    - What a graph backend adapter owes: the `BackendStore` Protocol, a
      `GraphReader`, a transaction implementing the nine typed operations, a
      `BaseGraphWriter` subclass, a config model deriving from `CCFContract`,
      and a `BackendRegistration`.
    - Where each piece goes: a read module and a `<name>_write` module, with the
      registration in the write module, and why — the read module is imported by
      many callers, so putting the write factory there would put write code on
      an unguarded import path.
    - How the adapter is found: the `ccf.graph_backends` entry-point group, and
      the fact that entry points live in build-time metadata, so a change to
      `pyproject.toml` requires a reinstall before it is visible. Say this
      plainly; it is the single most likely first failure.
    - Naming rules: lowercase, matching `^[a-z][a-z0-9_]*$`, and the six
      built-in names are reserved. Two installed distributions declaring one
      name is refused, naming both.
    - Credentials: the config model holds references, never values; secrets
      arrive at `open_store` as a separate mapping; a named reference that is
      unset or empty is refused rather than treated as no credential.
    - Declining pushdown is a first-class outcome, so an adapter can ship
      without a query translator and let the fallback answer.
    - How to prove it works: run the two conformance suites with the adapter as
      a param, and point at `tests/fixtures/ccf-demo-adapter/` as the smallest
      complete worked example.
    - What the SDK's lints do and do not cover for a third-party adapter, and
      why single-writer still holds — because `mint_boot_token` refuses a second
      live writer for one graph identity, which is the mechanism, while the lint
      is what stops a *core* module reaching for the writer.
