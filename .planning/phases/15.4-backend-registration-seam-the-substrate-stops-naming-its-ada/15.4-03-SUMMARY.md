# Phase 15.4 Plan 03: The Writer Split Summary

Moved 2,230 lines of per-backend write code out of `ccf.graph._writer` and into
six modules beside their readers, leaving a 935-line neutral base that imports
no backend — the change that turns the D-IMPL-93 dependency arrow around.

## What Was Built

### Task 1 — six write modules, and WR-01 fixed on the way past (`e1f1f1f`)

Each backend's writer class and transaction implementation now lives at
`src/ccf/graph/backends/<name>_write.py`:

| Module | Lines | Holds |
| --- | --- | --- |
| `sqlite_write.py` | 140 | `_SqliteTxn`, `SqliteGraphWriter` |
| `postgres_write.py` | 150 | `_PostgresTxn`, `PostgresGraphWriter` |
| `memory_write.py` | 312 | `_MemoryTxn`, `MemoryGraphWriter` |
| `neo4j_write.py` | 469 | ten Cypher constants, `_neo4j_claim_projection`, `_Neo4jTxn`, `Neo4jGraphWriter` |
| `mongo_write.py` | 572 | `_mongo_claim_projection`, `_MongoTxn`, `MongoGraphWriter` |
| `fluree_write.py` | 953 | statement and predicate constants, `_fluree_claim_projection`, `_FlureeTxn`, `FlureeGraphWriter` |

**The relocation is verbatim, and that was mechanical rather than careful.** A
script sliced the spans out of the source by line range and wrote them
unchanged; only the module headers — docstring, imports, `__ccf_mode__`,
`__all__` — were authored. Nothing was retyped, so nothing could be
mistyped.

Each module docstring states the three things the plan asked for: which backend
it serves, that it is one of the modules the CINV-02 `cinv02-graph-writer` rule
guards (`ccf.assembly` and `ccf.boot` only), and that it may import its own
reader while the reverse is forbidden — with the reason, which is that a reader
importing its writer would drag write code into every importer of the reader
and get the *reader* flagged.

**WR-01, fixed rather than relocated (D-14).** `_POLICY_KEY_SEPARATOR` was a
duplicate of `backends.fluree.POLICY_KEY_SEPARATOR`, justified on the ground
that importing the reader from the writer would break the CINV-02 confinement
and cycle. The justification was false when written — the write path already
imported the reader — and after the split it is not even arguable. The
duplicate constant and its hand-rolled `.join()` are gone;
`_fluree_claim_projection` calls `policy_key`, so the injectivity guard that
lived on the read copy alone now covers both sides.

What that changes, stated precisely: a `(class, attribute, value)` triple whose
own components carry the separator no longer materializes a stored key. The
observable answer does not move — such a key was already unreachable from the
read side, and a query naming such a triple declines the pushdown so the
fallback answers the whole thing (D-04) — but the over-disclosure surface CR-01
exploited is now closed at both ends instead of one.

**No `REGISTRATION` record.** The six modules are discoverable the moment they
exist and unresolvable until 15.4-04. That window is deliberate, is refused by
name in 15.4-02's `resolve()`, and no test here asserts `resolve()` succeeds on
a built-in name.

**The surface fragment landed in this commit**, not the next one. Six writer
classes enter the generated manifest here — `tools/dump_surface.py` skips a
module only for a leading-underscore segment, so `ccf.graph._writer` is
invisible to it and `ccf.graph.backends.<name>_write` is not — and
`tests/test_surface_drift.py` runs in the always-on `test` job. Claiming them a
commit later would leave `make ci-core` red in between (T-15.4-42).

### Task 2 — the neutral base, trimmed and re-argued (`748ec03`)

`_writer.py`: **3,215 -> 935 lines.** Every relocated span deleted, all six
`from ccf.graph.backends...` import blocks gone, and every stdlib or
third-party import those spans were the only user of (`copy`, `sqlite3`,
`psycopg`, `contextmanager`, `Iterator`, `Any`, `parse_timestamp`). `__all__`
reduced from eight names to four: `BaseGraphWriter`, `BootToken`,
`SingleWriterViolation`, `mint_boot_token`.

The module docstring's argument was rewritten because D-01 superseded it. It
used to say every backend's writer belonged *here* so the lint could guard one
file. The premise was right and the conclusion too narrow: the answer is to
guard a *class* of modules. The new text says so, states that
`_LIVE_WRITERS` and `_MINT_KEY` must live in exactly one module or the
invariant breaks (two live-writer tables means "a writer already exists for
this graph" stops being answerable), and keeps the honest-residual paragraph on
determined-insider evasion intact.

`_SqlGraphTxn` stayed and now argues its own position: shared but not
universal, and a home inside one SQL adapter would make one backend's module a
dependency of another's.

`backends/__init__.py`'s docstring said backends expose readers only and the
write handle lives in `ccf.graph._writer`. Both halves were wrong after the
split. It now says an adapter is two modules, that the write module carries the
same CINV-02 guard, and that the import runs one way only — without
enumerating the adapters.

`boot.py` imports the six writer classes from their write modules. The Neo4j
and MongoDB branches keep their lazy in-function imports and now name the write
modules there too, so a SQLite boot loads neither optional driver's adapter —
verified: after `import ccf.boot`, `neo4j`, `pymongo`,
`ccf.graph.backends.neo4j_write` and `ccf.graph.backends.mongo_write` are all
absent from `sys.modules`. The branch cascade itself is untouched; deleting it
is 15.4-05's work and this plan did not start it.

### Task 3 — the four legs (no commit; nothing was caught)

The container legs are this migration's regression net: built in 15.2 and 15.3
to prove six adapters agree, run here to prove they still agree after 2,230
lines moved. All four green at exactly their D-GATE-15.3 counts, no skips, no
code changes required. A relocation that had changed the write semantic would
have moved a differential count; none moved.

## Deviations from Plan

### Six test files changed beyond `files_modified` — Rule 3, blocking

The plan's `files_modified` lists source and docs only. Six test modules
encoded the pre-split world and would have been red without amendment. None of
these is a weakening; three are strictly stronger than what they replaced.

**1. `tests/graph/test_writer_seam.py` — the confinement test asserted a path.**
`test_write_code_has_no_second_home_outside_the_writer_module` skipped exactly
`src/ccf/graph/_writer.py` and flagged every other `*GraphWriter` / `*GraphTxn`
class in `src/`. After the split that is six offenders. Rewritten as
`test_write_code_has_no_second_home_outside_a_guarded_write_module`, which
imports `is_write_module` from the checker rather than restating it — so
whatever the lint guards is what the test permits, and a seventh adapter is
admitted on arrival for the same reason it joins the guarded set on arrival.
Added `test_the_guarded_set_is_not_vacuous`, because a predicate that matched
nothing would make the scan pass by finding no writer at all.

**2. `tests/invariants/test_single_writer_boot.py` — the importer test asserted
a literal list.** `offenders == ["ccf/boot.py"]` is false the moment a write
module imports the neutral base. Split into
`test_only_permitted_modules_name_the_neutral_write_base`, which derives the
permitted set from `NEUTRAL_WRITER_OK_MODULES` and `is_write_module`, and
`test_the_composition_root_is_still_among_the_importers`, the non-vacuity leg.
Deriving rather than re-listing also means 15.4-02's `ccf.graph.registry` — a
member of `NEUTRAL_WRITER_OK_MODULES` that does not exist in this worktree —
lands without a second edit to this file. The module's `SqliteGraphWriter`
import was repointed to `backends.sqlite_write`.

**3. `tests/graph/test_fluree_backend.py` — five relocated-symbol imports.**
`_FlureeTxn` (x2), `_fluree_claim_projection` (x2) and the two `_FLUREE_*_COUNT`
statement constants now come from `backends.fluree_write`. Three docstrings
that argued "the write half lives in `ccf.graph._writer`" were corrected.

**4. `tests/graph/test_fluree_backend.py::test_no_pushed_policy_key_can_collide_with_a_stored_one`
— the CR-01 regression test, amended for D-14.** As shipped it asserted the
write path was *deliberately ungated* and the forgeable key was still
materialized, then argued it was unreachable by a separator count. D-14 makes
the key not stored at all. The test now asserts the absence, keeps both halves
of the divergence claim unchanged (the query still declines; the fallback still
excludes the claim), and gains a non-vacuity leg asserting a well-formed triple
still projects its key — so the absence is the guard firing rather than the
projection having died.

**5. `tests/graph/test_mongo_backend.py::test_module_imports_without_the_driver`
— the no-extra import assertion.** It imported `ccf.graph._writer` as the proof
that the extras-free tree stays importable. The neutral base no longer touches
the driver's adapter at all, so that assertion had become vacuous; it now
imports `ccf.graph.backends.mongo_write`, which is where the claim actually
bites.

**6. `docs/SURFACE-CHANGES.md` regenerated.** `make surface-changes` is a
standing staleness gate (`test_the_curated_log_is_assembled_from_the_current_fragments`),
so a fragment added without reassembly is a red build. Note for the merge: this
file is regenerated by every plan that writes a fragment, and 15.4-02 writes one
too — a textual conflict here is expected and is resolved by re-running
`python tools/assemble_surface_changes.py` after the merge, never by hand.

### D-14 read as "call the function", not "import the constant"

Both readings clear the plan's `grep -c "_POLICY_KEY_SEPARATOR" ... is 0`
criterion. Only calling `policy_key` puts the guard on the write side, and a
guard on one copy only is what the Phase 15.3 review named as the enabling
condition for CR-01. Recorded because the narrower reading would have looked
compliant while leaving the defect class alive.

No Rule 1 bugs found. No Rule 4 architectural question arose.
