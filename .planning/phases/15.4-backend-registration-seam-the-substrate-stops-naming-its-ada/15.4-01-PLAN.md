<objective>
Build the two structural lint rules D-IMPL-93 asks for, and widen the existing
single-writer import rule so it will still hold after the writer file splits.

Nothing in `src/` moves in this plan. The checkers are written and unit-tested
here, but they are **not** registered in `tools/lints/__main__.py` yet, because
the properties they check are not true of the tree until plan 15.4-06 lands.
Registering them now would make `make lint` red for the rest of the phase.

The window this opens is stated rather than hidden: between this plan and plan
15.4-07 the two new rules exist and are proven to *fire* by their negative
controls, but they do not run over the tree. What guards the properties during
that window is the plan sequence itself — 15.4-03 through 15.4-06 are the plans
that make the properties true, and 15.4-07 turns the rules on in the first
commit where they can be green. A rule proven to fire before it is proven to
pass is worth more than a rule that has only ever been green.

The window has one real hole and it is closed cheaply. Plans 15.4-02 through
15.4-06 call these checkers directly, but only on the files each of them
touches, so a substrate name reintroduced in a core module nobody edited — a
`binder.py` docstring enumeration, a new helper — would survive until 15.4-07.
Plan 15.4-06's last task therefore runs one dry run of `substrate_names.check`
over all of `src/ccf` except `backends/`, and one of `backend_imports.check`
over `src/` and `runtime/`, before the rules are registered. That converts the
window's guard from plan-sequence discipline into a check, without moving the
registration commit or changing anything here.

Purpose: the enforcement half of the phase, built first so that everything
after it has something to fail against.
Output: one widened rule, two new checkers, three test modules.
</objective>

    **Vocabulary, derived and never typed.** Implement
    `substrate_vocabulary(base: pathlib.Path) -> frozenset[str]` returning the
    stems of `*.py` files under `src/ccf/graph/backends/`, dropping `__init__`
    and stripping a trailing `_write`. On today's tree that is six names; a
    seventh adapter file extends the ban with no lint edit. This is CLAUDE.md
    §11 applied to the checker itself — it holds an interpreter, not a list.
    Cache the result per `base` so the walk does not re-stat the directory per
    file.

    **Sub-rule 2a — code positions.** Match a vocabulary word with the
    word-boundary pattern `(?i)(?<![a-z0-9])<name>(?![a-z0-9])` inside any of:
    a string literal that is not a docstring, an `ast.Name.id`, an
    `ast.Attribute.attr`, an `ast.arg.arg`, a `FunctionDef`/`AsyncFunctionDef`/
    `ClassDef` name, or an import alias (`ast.alias.name` or `ast.alias.asname`).
    The loose boundary is deliberate: tightening it to exclude `_` on both sides
    clears the one residual on today's tree but also stops the rule catching a
    reintroduced `postgres_dsn` parameter, which is the exact thing it exists to
    catch.

    **Sub-rule 2b — docstring enumeration.** A finding when one docstring
    contains three or more *distinct* vocabulary words. Measured margin: every
    legitimate comparative docstring in core today names at most two, and every
    file at three or more is a file this phase reshapes. Identify docstrings
    structurally (the first statement of a Module/ClassDef/FunctionDef/
    AsyncFunctionDef when it is a string constant), not by position in the text.

    **Scope, in named constants.** `SUBSTRATE_NAME_EXEMPT_PACKAGES` =
    `frozenset({"ccf.graph.backends", "ccf.similarity"})`. The first is the
    adapters' own home. The second is a different pluggable axis with its own

    accident is the discipline `tools/lints/__main__.py` lines 50-77 already
    documents. `ccf.graph.registry` is deliberately **not** exempt: the registry
    derives its adapter set and names none, so it needs no allowance, and
    proving that is stronger evidence for property (2) than an exemption would
    be.

    No allowlist (D-13), stated in the docstring in the same words as the other
    import rules.

    **False negatives, listed in the docstring** rather than discovered later: a

    behaviour without naming it; `#` comments, which are not AST nodes and are

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repository source → CI gate | The lint reads source it does not trust to be correct; its job is to fail on the source, never to be persuaded by it |
| checker rule surface → reviewer | A carve-out constant is the checker's own attack surface — a widened constant is a silently weakened invariant |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15.4-09 | Elevation of privilege | `cinv02-graph-writer` guarded set | mitigate | The guarded set is a predicate over module names (`is_write_module`), so a new write module is covered on arrival rather than when someone remembers to add it. Two separate permitted-importer constants keep the registry carve-out from silently covering per-backend write modules; a test pins that asymmetry. |
| T-15.4-12 | Tampering | new rules' exception surface | mitigate | No allowlist (D-13). Carve-outs are named constants reviewed with the code. `SUBSTRATE_NAME_EXEMPT_PACKAGES` has exactly two entries, each with a stated reason. |
| T-15.4-13 | Repudiation | a rule that scans nothing | mitigate | Every rule ships with a negative control asserting it fires. A rule with only green tests cannot be distinguished from a rule with a broken matcher. |
| T-15.4-03 | Tampering | dynamic import evading the import lint | accept (stated) | An AST import lint cannot see `importlib.import_module`. Recorded in `backend_imports.py`'s docstring; the compensating control is plan 15.4-02's single-call-site confinement plus a test that scans `src/` and `runtime/` — the same trees this rule covers. A scan narrowed to the graph package would leave a dynamic backend import in `src/ccf/deployment/manifest.py` invisible to both. |
| T-15.4-SC | Tampering | package installs | mitigate | This plan adds no package. Every import is stdlib (`ast`, `pathlib`, `re`) or `tools.lints`. |
</threat_model>
