## What Was Built

### Task 1 — the two params and the parity test (`c4b3647`)

`pytest.param("demo")` in the `graph_backend` fixture and in `BACKEND_PARAMS`,
neither carrying a mark: the store is an in-process dict, so it belongs on the
always-on leg beside `sqlite` and `memory`.

**The param alone was not enough,** exactly as plan 15.4-10 warned and this
plan's own text did not mention. `test_graphstore.py`'s fixture *body* carries
an explicit name set and raises `NotImplementedError` on anything outside it;
`demo` had to be added there too. `test_substrate_differential.py` needed the
param only.

Both files' comment blocks gained a sentence saying what is different about this
one: every previous param named an adapter living in `src/ccf`, and this one
does not, so the suites now demonstrate the **contract** rather than the
**implementation** — the six D-IMPL-34 semantics are shown reachable by a third
party through the published seam, not merely upheld by code the seam's authors
also wrote.

`tests/conformance/test_param_registry_parity.py`, six assertions:

| Assertion | What it closes |
| --- | --- |
| registry ⊆ GraphStore params | An installed adapter no param names — the silent pass |
| registry ⊆ differential params | The same hole, for byte-identity |
| GraphStore params ⊆ registry | A param naming nothing installed; turns nine boot errors into one message naming the cause |
| differential params ⊆ registry | The same, for the other list |
| the two lists agree | Names the invariant the four above jointly imply, so relaxing one does not quietly relax this |
| `demo` is registered | **Non-vacuity.** Without it, all five would pass against six built-ins while the phase's central claim went untested |

**The lists are read, never re-typed** — off the fixture's own params marker and
off the imported `BACKEND_PARAMS` tuple. A re-typed list would be a third
enumeration of one category, free to drift from the other two: the parity test
would then assert that two hand-written lists agree with a third while the
registry went unconsulted, which is the defect it exists to catch, rebuilt
inside it. The extractor **raises** rather than returning an empty set when it
cannot read what it was given, for the same reason.

The module docstring names the failure mode and ties it to the defect class
`D-GATE-15.3` records three times — a rule stated as a category, enforced by a
hand-written enumeration born incomplete.

## Findings

### 1. This plan's own automated verify for Task 2 extracts no SHA and fails closed

The plan's verify begins:

```sh
ADAPTER_BASE="$(grep ADAPTER_BASE "$SUMMARY" | grep -oE '[0-9a-f]{40}' | head -1)" && test -n "$ADAPTER_BASE"
```

Measured: it yields the **empty string**. In the 15.4-10 summary no single line
contains both the token `ADAPTER_BASE` and a forty-character SHA — the heading
`## ADAPTER_BASE` is on line 84 and the SHA sits on line 87 inside a fenced
block. So `test -n` fails and the chain stops.

**This is the plan's own instruction working as designed** — "If no
forty-character SHA is found on such a line, the verify fails rather than
diffing an empty range" — and it is the right failure. But the command as
written cannot pass, so it is recorded rather than quietly replaced. The
measurement above was taken with the SHA read from the summary's `## ADAPTER_BASE`
block and written out in full, which measures exactly the range the plan
intended.

For plan 15.4-12: a form that works against the summary as it actually is —

```sh
ADAPTER_BASE="$(grep -A3 '^## ADAPTER_BASE' "$SUMMARY" | grep -oE '[0-9a-f]{40}' | head -1)"
```

### 2. The commit-message cross-check disagrees with the summary; the summary is authoritative

The plan asks that `ADAPTER_BASE` be cross-checked against
`git rev-list --reverse HEAD --grep="15.4-10" | head -1` followed by `^`.
Measured:

| Source | Value |

The grep does not find plan 15.4-10's first *implementation* commit. It finds a
**planning-era** commit that merely mentions 15.4-10 in passing — planning
commits touch the plan documents, so they carry the string too, and `--reverse`

Per the plan's instruction the disagreement is recorded, not resolved by picking
the convenient one. The summary's value is independently corroborated by its own

### Recorded, not fixed

**2. The parity test reads a pytest-internal attribute**

`pytest.fixture(params=…)` stores the params on `_fixture_function_marker`
(pytest 9.1.1); there is no public accessor. The helper tries that name, falls
back to the older `_pytestfixturefunction`, and **asserts with a message telling
the reader to update the helper rather than re-type the param list** if pytest
moves it again. Re-typing the list was the alternative and is precisely what the
module exists to prevent, so the fragility was accepted deliberately and made
loud rather than silent.

**3. The `demo` param sits with the always-on group, not appended last**

Placed after `memory` so the differential suite's existing comment — naming
which params are always-on and which carry marks — stays true as written.
