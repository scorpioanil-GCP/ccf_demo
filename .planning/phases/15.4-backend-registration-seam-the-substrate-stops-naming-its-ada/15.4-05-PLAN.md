<objective>
Replace the composition root's branch cascade with a registry lookup, and break
the public boot signature.

`_open_backend` takes eleven keyword arguments — two to three per substrate —
and decides by asking which one is not `None`. It goes away. `boot()` takes an
adapter name and one connection mapping, hands both to the registry, and gets
back a store and a writer factory.

The signature break is pre-authorized. D-15B grants free rein on the public API
before 1.0 on one explicit condition: adopters get a migration. This plan writes
that migration fragment. Note what is *not* being done, because it was raised in
discussion and rejected: keeping the per-database keyword arguments as
deprecated pass-throughs alongside the new mapping. That would leave adapter
names in the public surface, which is the thing property (2) forbids.

Thirty-one of the forty-three call sites in the repository pass only
`database_path`, so most of the migration is one line each. `tests/conftest.py`
already splats a dictionary and needs almost nothing.

Purpose: the core stops naming adapters.
Output: a boot function with no substrate in it, twenty-three migrated call
sites, one surface-change fragment, and the tests that prove the seam.
</objective>

<interfaces>
Target signature:

    def boot(*, backend: str,
             connection: Mapping[str, object] | None = None,
             secrets: Mapping[str, ResolvedSecret] | None = None,
             registry: ControlPlaneProtocol,
             resolution_spec_key: str, resolution_spec_version: str,
             policy_bundle_key: str, policy_bundle_version: str) -> FabricHandle

`backend` is required and has no default. SQLite is no longer reachable by
omission; a fabric that could infer its substrate could boot against a
development file in production and still pass every test, which is the refusal
`_open_backend`'s docstring states today and this signature inherits.

`secrets` is keyed by config field and carries `ResolvedSecret`, not a bare
`SecretStr`. That is not decoration: `AdapterPin.secret_refs` records the
*names of the references in force*, and a mapping of field name to value can
only tell `boot()` that a `bearer_token` was supplied — never that it came from
`CCF_FLUREE_TOKEN`. Without the reference name the pin is weaker than D-08,
D-09 and V15 require. `boot()` unwraps to `Mapping[str, SecretStr]` keyed by
field before calling `open_store`, so `BackendRegistration` and every adapter's
`_open_store` are unaffected.

From `ccf.graph.registry` (plan 15.4-02):

    resolve(name) -> ResolvedBackend(registration, version, distribution)
    validate_connection(registration, connection) -> CCFContract
        raises InvalidBackendConfig(ValueError) naming adapter and field
    ResolvedSecret(field: str, ref_name: str, value: SecretStr)
    AdapterPin(name: str, version: str, secret_refs: tuple[str, ...])

**The connection-key mapping, in one table.** This is the vocabulary every
migrated call site and every adopter has to learn, and it is the part most
easily buried in a paragraph. A key that changed name and was not migrated does
not read as a rename — it reads as `extra_forbidden` on a key that "obviously"
exists.

    Delete `_open_backend` entirely and delete the `_Backend` Protocol, which now
    lives in the registry as `BackendStore`. Delete the six module-top backend
    imports and the two lazy in-function backend imports.

    `boot()` takes the target signature above. Its body, in order:
    `resolve(backend)` from the registry; `validate_connection(record.registration,
    connection or {})` — **that function, by name, never a `model_validate` call
    written here**, because it is the one place a connection refusal is built
    and the reason it is one place is that a hand-rolled version formats
    `str(exc)` and puts the supplied value in the message; refuse a key in
    `secrets` that is not in `record.registration.secret_fields`, naming the
    adapter and the offending key and never the value, in the same shape
    `validate_connection` uses; unwrap the secrets to
    `{field: rs.value for field, rs in secrets.items()}` and call
    `record.registration.open_store(config, unwrapped)`;
    `mint_boot_token(graph_identity=store.graph_identity)` inside the existing
    try/close guard; `record.registration.make_writer(store, token)`. Everything
    after that — the shutdown closure, the Control Plane resolution, the
    `AssemblyWorker` construction, the half-booted-fabric cleanup — stays exactly
    as it is.

    The unwrap happens at the call site and nowhere earlier. A `SecretStr` that
    is bound to a local before it is needed is a value with a longer life than
    the call that wanted it.

    Four refusals `_open_backend` performs today, and where each goes. "Not
    exactly one backend selected" becomes structurally impossible: one name
    selects one adapter. "A credential supplied for a backend that was not
    selected" is now the `secret_fields` membership check above. The two
    connection refusals moved into the adapter's config model in plan 15.4-04.
    Say this in the new docstring, so a reader can see that nothing was dropped.

    **`FabricHandle` gains one attribute: `adapter: AdapterPin`.** Name and
    version come from the `ResolvedBackend`; `secret_refs` is
    `tuple(sorted(rs.ref_name for rs in secrets.values()))` — the names of the
    references, never the fields they filled and never a resolved value. Reading
    the field names instead would pin `bearer_token`, which says a credential
    was used and not which one, and "which reference was in force" is the fact
    D-08 exists to make auditable. A caller that supplies a `secrets` mapping
    with no reference names has nothing to pin, which is why `ResolvedSecret`
    carries the name rather than leaving it to a parallel argument that can
    drift. This is a departure worth naming in the class docstring:
    `FabricHandle` has until now carried capabilities and no state you could
    misuse, and this makes it carry a fact. The fact is one an adopter needs,
    because from Phase 15.4 onward the adapter can be third-party code, so which
    adapter and which version answered is something that affects the answer.
    Plan 15.4-08 threads it into Decision Replay dimension 2. Do not add a writer
    attribute, private or otherwise; the argument in the existing docstring
    stands unchanged.
