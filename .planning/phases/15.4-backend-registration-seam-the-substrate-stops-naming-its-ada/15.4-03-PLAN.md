<objective>
Move each backend's writer class out of the 3,215-line `_writer.py` and into a
module beside that backend's reader. `_writer.py` survives as the neutral base
and imports no backend.

This is the change that makes property (1) reachable. `_writer.py` imports all
six adapters today, so nothing can import the write module without importing
every substrate, which is the dependency arrow D-IMPL-93 exists to reverse.

The split is mechanical rather than a disentangling job, and that was measured
rather than hoped: an AST scan of the file found that lines 176-973 — the whole
neutral base including the shared SQL transaction — reference no
backend-derived name at all. The six per-backend sections below line 973 are
what move.

Two shapes were considered and rejected during discussion; neither should
reappear here as a de-risking measure. Reads and writes in one file per backend
(D-02) would force the single-writer lint to guard a *class* instead of a
module, which is weaker and harder to check statically. Exempting `_writer.py`
from the no-backend-import rule would leave per-adapter churn exactly where
D-IMPL-93's recurrence test forbids it.

Purpose: relocate the write code so the import arrow can turn around.
Output: six write modules with their surface claim, a trimmed `_writer.py`, and
one recorded defect fixed on the way past (D-14, WR-01).
</objective>
