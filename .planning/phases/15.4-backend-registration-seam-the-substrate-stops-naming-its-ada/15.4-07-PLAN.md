<objective>
Turn the two structural rules on, and retire the line-budget gate they replace.

This is the first commit where both properties D-IMPL-93 names can be green, so
it is the commit where they start being enforced. Until now the rules have
existed and been proven to fire against fixtures; from here they run in
`make lint` and in the always-on CI lint job, over every file in `src/` and
`runtime/`, with no new CI wiring — the workflow already runs
`python -m tools.lints --all` and `pytest tools/lints/tests -q`.

`src/ccf/graph/_writer.py`, so it went red the moment that file split; its own
docstring says it expects to be superseded rather than extended; and D-IMPL-93
says the structural lints replace the line budgets. Leaving a red target in the
tree is worse than either outcome.

Purpose: the properties stop being a plan and start being a gate.
Output: two registered rules, one retired gate, and a green `make lint`.
</objective>

<interfaces>
The runner's three registration surfaces (`tools/lints/__main__.py`):

    CHECKERS: dict[str, Checker]              rule id -> per-file check function
    RULE_TREE_SCOPE: dict[str, tuple[str,...]]  rule id -> trees it runs over
    build_parser()                            one --flag per rule

Existing scopes, for reference: `no-hardcoding` runs over
`("src", "runtime", "examples", "tests")`; `harness-imports`, `algorithmic` and
`orchestration-imports` run over `("src", "runtime")`. A rule absent from
`RULE_TREE_SCOPE` runs over every linted tree, which is why both new rules need
an explicit entry.

Target scopes:
- `backend-imports` -> `("src", "runtime")`, matching CINV-02. `runtime/` has
  zero violations today and `tests/` is deliberately out of scope: the 45
  backend imports there are per-backend unit suites, which is what a unit suite
  for an adapter is supposed to look like.
- `substrate-names` -> `("src",)`. The rule is about the *core* not naming its
  adapters; `runtime/`, `examples/` and `tests/` all legitimately name one.
</interfaces>
