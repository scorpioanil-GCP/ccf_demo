<objective>
Build the proof: an adapter that lives entirely outside `src/ccf`, ships as its
own installable distribution, and reaches the fabric through the entry-point
group.

D-11 chose this over an in-tree seventh backend deliberately. An in-tree backend
would prove the in-repo path works, which is the weaker claim. What needs
proving is the path an actual third party takes: install a package, name it in a
manifest, and have it answer — with no line changing in this repository.

Its backing store is a plain in-process dictionary, not SQLite and not a copy of
the in-tree memory backend. Copying an in-tree adapter would prove the copy
works, not that the seam works. A dict store also needs no container, so this
adapter joins the always-on test leg rather than a container-gated one.

Purpose: exercise the third-party path end to end.
Output: a second distribution, its install wiring, a `demo` branch in the test
fabric factory, a test that boots it, and the recorded commit the measurement
runs from. Plan 15.4-11 runs it through the conformance suites and takes that
measurement.
</objective>

| Contract | Where | What it requires |
|---|---|---|
| `BackendStore` | `ccf.graph.registry` | `graph_identity` property, `reader` property, `close()` |
| `GraphReader` | `ccf.graph.protocols` | the read seam; declining pushdown is a first-class outcome (`GQ-29`), so this adapter may decline every query and let the fallback answer |
| `_GraphTxn` | `ccf.graph._writer` | the nine typed operations (D-IMPL-88) |
| `BaseGraphWriter` | `ccf.graph._writer` | the write semantic every adapter subclasses |
| `BackendRegistration` | `ccf.graph.registry` | name, config model, secret fields, `open_store`, `make_writer` |

`(tenant_id, entity_uri)`; idempotent upsert with set-union lineage
