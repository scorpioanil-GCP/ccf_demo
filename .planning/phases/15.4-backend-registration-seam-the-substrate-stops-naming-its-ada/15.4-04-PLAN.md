<objective>
Each adapter declares what it needs. Six typed config models, six registration
records, one per write module.

Today the knowledge of "which connection argument does this backend require"
lives as a hand-maintained dictionary in `src/ccf/deployment/manifest.py` lines
253-266. That dictionary is already declarative — the migration is largely
relocating knowledge that was always data, from a core file that has to be
edited per adapter into the adapter that owns it.

Two refusals live in that dictionary today and both must survive the move. A
declared backend whose connection argument is missing is refused. An argument
the declared backend does not take is refused rather than ignored. The first
becomes a required field. The second comes entirely from `extra="forbid"`, and
it is the one a migration loses silently — a config model written as a plain
`BaseModel` gets Pydantic's `extra="ignore"` default and the protection
disappears with no test failing and every valid manifest still working. So the
models derive from `CCFContract`, and a test sweeps every registered adapter
asserting it.

Purpose: move each substrate's requirements into the substrate's own module, so
the core stops holding them.
Output: six config models, six registration records, their surface claim, one
recorded defect closed (D-14, WR-05), and the test module that proves both
refusals per adapter.
</objective>

  <action>
    In each `backends/<name>_write.py`, add three things: a config model, an
    `_open_store` function, and a module-level `REGISTRATION`.

    **Config models**, each deriving from `CCFContract` so it inherits
    `extra="forbid"` and `frozen=True`. Field names and defaults exactly as the
    interfaces table above states: `SqliteConnection(database_path: Path)`;
    `PostgresConnection(dsn: str, schema_name: str = DEFAULT_SCHEMA)`;
    `MemoryConnection()` with no fields at all; `Neo4jConnection(uri: str,
    partition: str | None = None)`; `MongoConnection(uri: str, partition: str |
    None = None)`; `FlureeConnection(url: str, partition: str | None = None)`.

    Two field-name choices that are not free. `database_path` is annotated
    `Path`, not `str`, because Pydantic coerces a string to `Path` but not the
    reverse, and every existing caller passes one or the other. The Postgres
    schema field is `schema_name`, not `schema`, because a field named `schema`
    shadows an attribute on Pydantic's own `BaseModel` and emits a warning on
    every class construction.
    The optional-partition default stays `None` and resolves to the adapter's
    `DEFAULT_PARTITION` inside `_open_store`, exactly as `_open_backend` does
    today — that is the behaviour to preserve, not the argument shape.

    Note what the empty `MemoryConnection` buys: a manifest declaring `memory`
    with any connection key is refused by `extra_forbidden` automatically, so
    the `"memory": None` special case in the old dictionary disappears without a
    special case replacing it.

    **No credential is a config-model field.** The Fluree config model carries
    `url` and `partition` only. The bearer token arrives through the `secrets`
    mapping at construction time, never through the model, because Pydantic
    reports `input_value=` verbatim in a `ValidationError` — a misspelled
    connection key would otherwise put a live credential into an error message.
    Write that reason into `FlureeConnection`'s docstring so nobody adds the
    field later for convenience.

    **`_open_store(config: CCFContract, secrets: Mapping[str, SecretStr]) ->
    BackendStore`** in each module. Type the parameter as `CCFContract` so the
    function is assignable to the record's field under `mypy --strict`, then
    narrow with an explicit `isinstance` check that raises `TypeError` naming
    both the expected model and what arrived. Construct the reader module's
    store with the same arguments `_open_backend` passes today. For Fluree, read
    `secrets.get("bearer_token")` and pass `.get_secret_value()` to the store
    constructor at the call site — the resolved value is unwrapped once, at the
    last moment, and never assigned to anything that outlives the call.

    **`REGISTRATION`** — a module-level `BackendRegistration` with `name` set to
    the module's own stem minus `_write`, `config_model` the model above,
    `secret_fields` `frozenset()` for five adapters and
    `frozenset({"bearer_token"})` for Fluree, `open_store=_open_store`, and
    `make_writer` a small function taking `(store, token)` and returning this
    module's writer class — the same construction `_open_backend`'s lambdas do
    today.

    **Preserve the deliberate import-shape difference.** The `neo4j` and
    `pymongo` drivers are optional extras and their imports must stay inside the
    store constructors, so resolving the sqlite adapter loads neither. Fluree is
    different on purpose: `httpx` is a core pin, so Fluree imports at module top
    with no lazy deferral, and that difference is recorded SUBQ-14 evidence. The
    registry must not flatten it into "all adapters load the same way". State
    the distinction in each of the three module docstrings.

    **The `__all__` ruling, made here rather than left to whoever types the
    module.** Each write module's `__all__` gains its config model name and
    `REGISTRATION`, and does **not** gain `_open_store`, which is private by
    name. Both exported names are part of the contract a third-party adapter
    author reproduces — the config model is what an adopter authors a manifest
    against, and `REGISTRATION` is the object an entry point points at — and a
    public contract the surface manifest cannot see is a contract nothing holds
    anyone to. Leaving them out would also be a decision, so it is made
    explicitly either way.

    **Twelve names therefore enter the live surface on this commit, and they
    are claimed in the same commit.** Extend
    `docs/surface-changes/15.4-03-write-modules.md` — the fragment plan 15.4-03
    wrote for these same six modules — with one section per added name, all
    seven fields, `Public surface: true`, `Change type: added`, and a `Surface`
    field carrying the fully dotted name
    (`ccf.graph.backends.sqlite_write.SqliteConnection`,
    `ccf.graph.backends.sqlite_write.REGISTRATION`, and their ten siblings).
    It extends that fragment rather than opening a `15.4-04-` one because the
    fragment is keyed to the module set it describes, and splitting one module's
    surface across two files makes the phase-close cross-check harder to read
    for no gain. `Migration: none` throughout — nobody could have been using
    these names yet.

    Without this, `tests/test_surface_completeness.py` at wave 9 would demand
    twelve entries that do not exist, and nothing would go red until then.
