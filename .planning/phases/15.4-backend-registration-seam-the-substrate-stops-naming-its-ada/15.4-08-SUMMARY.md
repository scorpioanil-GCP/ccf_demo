`PolicyBindingsSnapshot` gains three sentinel-defaulted fields:

```
graph_adapter: str = NO_ADAPTER
graph_adapter_version: str = NO_ADAPTER
graph_secret_refs: tuple[str, ...] = ()
```

`NO_ADAPTER = "no-adapter"` sits beside the other sentinels in the same
one-comment style, and enters `__all__` in sorted position (between
`MODE_1_MODEL_VERSION` and `NO_AGENT_DEFINITION`) **on the commit that adds
it** — the fragment claims the name `added`, and a sentinel left out of
`__all__` produces a claim with no diff line behind it.

fields are, why they are dimension-2 facts (the bindings in force now include
which adapter was bound and under which references, because from D-IMPL-93 the
adapter can be third-party code), and the one thing they may never hold.

**The premise correction the plan carried is real and is recorded in the
fragment.** This is the *first* adapter pin in any replay dimension, not a
widening of an existing one — the 15.2-08 extension to this same dimension was
`survivor_cap`. Anyone looking for a backend pin to extend will not find one.

`build_replay_record` gained `adapter: AdapterPin | None = None`, and the
docstring says why it is a parameter rather than an execution fact — the
asymmetry with the two extensions documented immediately below it in the same
docstring, which both arrive on `ExecutionResult`.

### Auto-fixed Issues

**1. [Rule 3 — Blocking] The byte-fidelity test had to gain a `.replace()`, against an explicit acceptance criterion**

- **Found during:** Task 1, by `pytest tests/replay`
- **Issue:** `tests/replay/test_harness_trace.py::test_every_pre_change_field_is_byte_for_byte_unchanged`
  strips each extension's sentinel keys from the produced bytes and compares
  the remainder to `PRE_CHANGE_CANONICAL`. Three new dimension-2 keys break it.
  The plan's task-2 acceptance criterion says the opposite: "the fixture file is
  unmodified", gated on `git diff --quiet -- tests/replay/test_harness_trace.py`.
  The criterion is **unsatisfiable** — any field added to any of the five
  dimensions changes the produced bytes, and the file is where the comparison
  lives.
- **Why this is mechanical rather than a judgement call:** `git log` on that
  file returns exactly four commits, and three of them are the three prior
  dimension extensions — `07-05` (hitl_actions, workflow_step_sequence),
  `15.2-08` (survivor_cap, graph_query_sequence) and `15.2-11`
  (source_attestation). Each added one `.replace()`. The test's own comment
  enumerates them. This is the documented path, not an improvisation.
- **Fix:** one `.replace()` for the three new keys, plus the comment extended to
  name this extension. **The `PRE_CHANGE_CANONICAL` literal is untouched**, and
  that is proven at a finer granularity than the plan's file-level gate could
  reach: the literal is AST-extracted from the phase base and from HEAD and
  compared byte-for-byte (1044 bytes, identical). A comment was added at the
  literal saying why it is never edited, so the fifth extension does not have to
  rediscover this.
- **Why the intent is met and not merely worked around:** the criterion exists so
  that a fixture is not doctored to make a new test pass. Editing the *literal*
  would do that; editing the *comparison* is what every extension must do. The
  finer claim is also the stronger one — a file-level `git diff --quiet` would
  pass on a file whose literal had been rewritten and whose replace-chain had
  been rewritten to match.
- **Files:** `tests/replay/test_harness_trace.py`
