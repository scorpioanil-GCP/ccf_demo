<objective>
Take the last two substrate enumerations out of the core: the six-name `Literal`
on `DeploymentManifest.backend`, and the hand-maintained backend-to-required-
argument dictionary in `_preflight_backend`.

The `Literal` becomes a plain string checked against the registry at load. A
*generated* list was considered and rejected — generated or not, six database
names in a core file is the thing property (2) forbids. The cost is
one-directional: a typo is caught at load rather than at parse, and it is paid
back by an error message that can name what *is* registered, which the `Literal`
never could.

One premise recorded as settled turned out to be wrong, and the correction
lands here. `docs/schemas/ccf.deployment-manifest.json` **does** exist, is
committed, carries the six-name enum, and its freshness is asserted by
`tests/cli/test_schema_export.py` in the always-on test job. So dropping the
`Literal` changes a committed file, and `make schemas` runs in this same change
or CI goes red (C-01). The autocompletion an adopter loses is accepted rather
than worked around, and plan 15.4-09 adds the `ccf backends` command that
answers the better question — not "what names did someone hard-code" but "what
is installed here" (D-15).

This plan is also where credentials change shape. A manifest names an
environment variable; boot resolves it. That is a net improvement rather than a
lateral move: today the Fluree token and the database passwords travel as
separate boot arguments precisely so they are never persisted — safe, but
invisible, because nothing in the versioned record says which credential a
deployment used. A named reference is auditable, and replay can pin which
reference was in force without ever recording what it resolved to.

Purpose: the manifest stops enumerating substrates and starts naming
credentials by reference.
Output: a reshaped contract, a registry-driven preflight, the one environment
read in `src/`, a regenerated schema, twenty migrated call sites, and the test
module that proves nothing leaks.
</objective>

<interfaces>
Target manifest shape:

    backend: fluree                       # plain string, matched ^[a-z][a-z0-9_]*$
    backend_secrets:                      # optional; names, never values
      - field: bearer_token
        env_var: CCF_FLUREE_TOKEN

`backend_secrets` is a tuple of a small `CCFContract` (`field`, `env_var`), not
a mapping, matching the `artifacts: tuple[ManifestEntry, ...]` shape the model
already uses and giving the uniqueness validator somewhere to live.

Target `load_and_boot` signature:

    def load_and_boot(manifest_path: str | Path, *,
                      registry: ControlPlaneProtocol,
                      connection: Mapping[str, object] | None = None,
                      tenant_id: str | None = None) -> BootedFabric

Connection values stay caller-supplied — a DSN or a Bolt URI is environment
material that the current docstrings say repeatedly is never persisted, and a
content-hashed manifest is exactly a place it would be persisted. What the
manifest gains is the *reference* to a credential, which is auditable and holds
nothing secret.

The twenty `load_and_boot()` call sites: twelve example `run.py`/`serve.py`
files (all `database_path`), `tests/deployment/test_manifest.py` lines
84, 392, 422, 435, 446, 470, 488 (one of them the deliberate contradiction
test), and `tests/deployment/test_operator_builder.py` line 82.

Measured leak surfaces for a resolved credential, and what each requires:

| Surface | Behaviour | Requirement |
|---|---|---|
| Pydantic `repr`/`str` | a plain `str` field prints the value | keep secrets out of models |
| `model_dump()` | returns the `SecretStr` object, not the value | use `SecretStr` |
| `model_dump_json()` | emits `"**********"` for `SecretStr` | use `SecretStr` |
| `canonical_bytes()` | **raises** on `SecretStr` | the strongest guarantee available |
| Pydantic `ValidationError` | embeds `input_value=` **verbatim** | never build a message from `str(exc)` |
| store constructors | already credential-free | preserve, do not regress |
</interfaces>

    Replace `_preflight_backend` with a preflight that asks the registry instead
    of a dictionary. Keep its position in `load_and_boot`'s ordering — before any
    document is read and before anything is registered — because that ordering
    is the whole point of the function: a manifest declaring an adapter the
    deployment cannot satisfy parses perfectly well, so a check placed beside the
    `boot` call would register every artifact first and fail afterwards, leaving
    Control Plane state from a fabric that never booted.

    The new preflight, in order: refuse `manifest.backend` if it is not in
    `declared_names()`, with the registry's message that lists what is
    registered; `resolve()` it; validate the caller's `connection` mapping
    against the adapter's config model, so both of the old refusals — a missing
    required setting, and a setting the adapter does not take — fire here with a
    message naming the adapter and the field; refuse any `backend_secrets` entry
    whose `field` is not in the adapter's `secret_fields`, naming the adapter and
    the field.

    **Message hygiene is a requirement, not a style note.** Pydantic embeds
    `input_value=` verbatim in a `ValidationError`, so a misspelled connection
    key produces a message containing whatever was supplied under it. Build every
    refusal from `exc.errors()` using `error["loc"]` and `error["msg"]` only.
    Never interpolate `str(exc)`, and never read `error["input"]`. Say so in a
    comment at the construction site so the next person does not simplify it.

    **Secret resolution.** Add `_resolve_secret_references(...)` reading
    `os.environ` — the first and only production environment read in `src/ccf`.
    It belongs in this wiring layer, not in `ccf.boot`: `boot()` takes values and
    reads no environment, which keeps the composition root deterministic and
    testable, and the manifest already lives here. For each `SecretReference`,
    read the named variable; if it is unset **or empty**, raise, with a message
    naming the adapter, the field and the variable name — and never the value.
    The message must state why silence is not consent: a manifest that names a
    reference has asserted a credential is required, and the fabric does not fall
    back to an anonymous connection. That refusal is the direct lesson of
    WR-02/WR-03, where a credentialed Fluree URL connected anonymously because
    `httpx` derives no header from `base_url` userinfo. Wrap each resolved value
    in `pydantic.SecretStr` before it goes anywhere, and pass the mapping to
    `boot(secrets=...)`.

    Reshape `load_and_boot`'s signature to the target above and update the
    internal `boot()` call. Do not keep the retired keyword arguments as
    deprecated pass-throughs — that shape was raised in discussion and rejected,
    because it would leave adapter names in the public surface.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| manifest document → Control Plane | Adopter-authored, content-hashed, versioned; anything it holds is persisted |
| process environment → fabric | The first production environment read in `src/`; the value it returns is a live credential |
| refusal message → logs and tracebacks | Anything a refusal interpolates leaves the process |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15.4-04 | Information disclosure | credential in a content-hashed manifest | mitigate | `backend_secrets` carries `field` and `env_var` only, both names. `canonical_bytes` refuses `SecretStr`, so a value could not be hashed into an artifact even by accident. Stated in the field docstring. |
| T-15.4-05 | Information disclosure | Pydantic `ValidationError` echoing `input_value` | mitigate | Every refusal is built from `error["loc"]` and `error["msg"]`; `str(exc)` and `error["input"]` are never read. Asserted by a test that supplies a recognisable token under a misspelled key and requires it to be absent from the refusal (V13b). |
| T-15.4-07 | Spoofing | a mis-set variable producing an anonymous connection | mitigate | A named reference that resolves to unset or empty is refused, with the variable name and not its value in the message. Two tests, one per case; the empty-string case carries a docstring saying why it must not be "fixed" to fall back. This is WR-02 arriving through a new door (V14). |
| T-15.4-22 | Elevation of privilege | a credential supplied for an adapter that did not declare it | mitigate | A `backend_secrets` entry whose `field` is outside the resolved adapter's `secret_fields` is refused, naming the adapter and the field. |
| T-15.4-10 | Information disclosure | credential in a graph identity | mitigate | Store constructors and their identity derivations are untouched by this plan; a test asserts `graph_identity` carries no credential (V13c). |
| T-15.4-23 | Tampering | an unknown adapter name reaching registration | mitigate | The membership check runs in preflight, before any document is read and before anything is registered, preserving the ordering guarantee `_preflight_backend`'s docstring makes today. |
| T-15.4-SC | Tampering | package installs | mitigate | No package added. `os`, `pathlib` are stdlib; `pydantic.SecretStr` is an existing exact pin. |
</threat_model>
