<objective>
Build the registry: the one place that knows which graph adapters a deployment
has, and the only place that imports one.

Two discovery sources, one record type, one resolution path. Built-in adapters
are found by reading module names out of `ccf.graph.backends` — no packaging
metadata involved, so a stale editable install cannot make the SDK unbootable.
Third-party adapters are found through the `ccf.graph_backends` entry-point
group, which is what lets someone ship an adapter as a separate installable
package with no line changing in this repository. That is D-04's "both, not
either", and the reason built-ins do not travel the entry-point path is
measured: entry-point names are not deduplicated across distributions and the
stdlib returns the first match silently, so a built-in that travelled that path
could be shadowed by an installed package.

Neither discovery source imports anything (D-05). Only `resolve(name)` imports,
and it imports exactly one adapter.

Purpose: the seam the whole phase inverts around.
Output: `src/ccf/graph/registry.py` and its test module. No adapter is
registered yet — that is plan 15.4-04 — so this plan proves the mechanism
against fixtures.
</objective>

  <action>
    Create `src/ccf/graph/registry.py`, an algorithmic module
    (`__ccf_mode__ = "algorithmic"`). Public names, all in `__all__`:
    `BackendStore`, `BackendRegistration`, `ResolvedBackend`, `AdapterPin`,
    `UnknownBackend`, `DuplicateBackendName`, `ReservedBackendName`,
    `declared_names`, `resolve`.

    **Constants.** `BACKEND_ENTRY_POINT_GROUP = "ccf.graph_backends"` (the PyPA
    convention is a group name starting with the consuming distribution's own
    name; note in the docstring that `ccf` is unpublished so the namespace is
    conventional rather than owned). `WRITE_MODULE_SUFFIX = "_write"`.
    `ADAPTER_NAME_PATTERN` — a compiled `^[a-z][a-z0-9_]*$` (D-16: exact match,
    lowercase; a versioned document should not need a convention to say which
    case won).

    **`BackendStore`** — a `Protocol` with the three members above, relocated
    from `boot._Backend` and made public because a third-party adapter has to
    implement it. Cite CLAUDE.md §11 (Protocols over inheritance) and mark it an
    SDK extension.

    **`BackendRegistration`** — a frozen dataclass, what one adapter declares:
    `name: str`; `config_model: type[CCFContract]`; `secret_fields:
    frozenset[str]` (config keys whose value is a credential, supplied at boot
    rather than declared in the config document — empty for an adapter with no
    credential); `open_store: Callable[[CCFContract, Mapping[str, SecretStr]],
    BackendStore]`; `make_writer: Callable[[BackendStore, BootToken],
    BaseGraphWriter]`. A record the registry *interprets*, not a base class an
    adapter subclasses (CLAUDE.md §6.4, §11).

    **`ResolvedBackend`** — a frozen dataclass the registry returns:
    `registration: BackendRegistration`, `version: str`, `distribution: str`.
    Version and distribution are derived by the registry, never declared by the
    adapter, so a third-party adapter gets its pin for free: for an
    entry-point-discovered adapter they come from `ep.dist.version` and
    `ep.dist.name`; for a built-in they come from
    `importlib.metadata.version("ccf")` and the string `"ccf"`, with a
    documented fallback when the distribution metadata is absent (a source
    checkout that was never installed).

    **`AdapterPin`** — a `CCFContract` with `name: str`, `version: str`,
    `secret_refs: tuple[str, ...]`. This is what a booted fabric can hand to
    Decision Replay: adapter name, adapter version, and the *names* of the
    secret references in force. It has no field that can hold a resolved
    credential, and plan 15.4-08 threads it into dimension 2.

    **Discovery — `_builtin_names()`.** `pkgutil.iter_modules(<the backends
    package>.__path__)`, keeping module names that end with
    `WRITE_MODULE_SUFFIX`, stripping the suffix. Importing the `backends`
    package itself is importing an `__init__.py` that imports nothing; no
    adapter module is imported. Returns a mapping of adapter name to the dotted
    write-module path.

    **Discovery — `_declared_entry_points()`.**
    `importlib.metadata.entry_points(group=BACKEND_ENTRY_POINT_GROUP)`, reading
    `.name`, `.value`, `.dist.name`, `.dist.version` only. Never `.load()`.

    **`declared_names() -> frozenset[str]`** — the union, with two refusals
    computed here so that no caller can reach a name the fabric would not
    honour. Refuse with `ReservedBackendName` when an entry point declares a
    name that `_builtin_names()` already holds, naming the declaring
    distribution and stating that the six SDK adapter names are reserved (D-16,
    on the D-IMPL-84 precedent that reserves the `ccf.` artifact-class prefix
    against manifest squatting). Refuse with `DuplicateBackendName` when two
    entry points from *different* distributions declare one name, listing both
    distributions and their versions and stating that the fabric does not choose
    between them. Refuse with `ValueError` naming the offending value when a
    declared name does not match `ADAPTER_NAME_PATTERN`.

    **`resolve(name: str) -> ResolvedBackend`** — the only function in this
    module that imports anything. Call `declared_names()` first so the two
    refusals above fire before any third-party code runs. Refuse an unregistered
    name with `UnknownBackend`, and put the registered names in the message,
    sorted, plus one sentence saying an adapter becomes available by installing
    a distribution that declares it under `ccf.graph_backends`. For a built-in,
    `importlib.import_module(<dotted write module>)` and read its module-level
    `REGISTRATION`; for a third party, `entry_points(...).select(name=name)`
    and `.load()` on the single match — `.select`, never `eps[name]`, because
    the mapping form returns the first match silently and that is exactly the
    shadowing hazard. Validate that the loaded object is a
    `BackendRegistration` whose `name` equals the requested name, and refuse
    with a message naming both if it does not.

    **The confinement that makes the import lint's blind spot survivable.**
    `importlib.import_module` appears exactly once in this module, inside one
    private function, and nowhere else under `src/` or `runtime/`. Those two
    trees, not `src/ccf/graph`, because that is the scope
    `cinv02-backend-import` covers when plan 15.4-07 registers it: a dynamic
    `import_module("ccf.graph.backends.<name>")` in `src/ccf/deployment/manifest.py`
    — the obvious candidate, since it holds the adapter name — would be
    invisible to the lint and outside a scan narrowed to the graph package.
    A compensating control narrower than the threat is not a control.

    Say so in the module docstring, in the voice `src/ccf/boot.py` lines 22-26
    use for the determined-insider claim: an AST import lint cannot see a
    dynamic import, so the compensating control is that there is one call site
    across both trees and a test asserts it is the only one. Do not claim the
    limit away.

    **Two things this module must not do**, both stated in the docstring so a
    later reader does not reach for them. It does not import every declared
    adapter at start-up (D-06, rejected: that runs arbitrary installed packages'
    module-level code at every boot, and would undo the optional-extra
    deferral that keeps the `neo4j` and `pymongo` drivers unloaded when booting
    SQLite). It does not infer an adapter from the shape of a connection value;
    selection is a name in a manifest, the rule `_open_backend`'s docstring
    states today and this module inherits rather than re-decides.

    **No substrate name appears in this file**, including in prose. The vocabulary
    comes off disk; the refusal messages are built from `declared_names()`.

    **Write `docs/surface-changes/15.4-02-registry.md` in this same change.**
    `tests/test_surface_drift.py` is a standing gate in the always-on test job:
    the committed manifest must equal what the tree emits, *or* every module
    whose entry moved must be claimed by a `docs/surface-changes/15*-*.md`

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| installed distribution → fabric | A third-party package's entry-point metadata is untrusted input; its *code* is untrusted until a manifest names it |
| adapter name in a manifest → registry lookup | Adopter-authored input selecting which code the process will import |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15.4-01 | Spoofing | `declared_names()` across distributions | mitigate | Built-in adapters never travel the entry-point path, so they cannot be shadowed. An entry point declaring a built-in name raises `ReservedBackendName`; two distributions declaring one name raise `DuplicateBackendName` naming both. `.select(name=...)` is used, never `eps[name]`, which returns the first match silently. Measured behaviour, not assumed. |
| T-15.4-02 | Tampering / Elevation of privilege | adapter module-level code at discovery | mitigate | `declared_names()` reads `.name`, `.value`, `.dist.name`, `.dist.version` and calls `.load()` never. `resolve()` imports exactly the adapter the manifest names, at boot. Asserted by V6 against a module with an import side effect. D-06 (import everything at start-up) is rejected in the module docstring so it is not reintroduced as a de-risking step. |
| T-15.4-03 | Tampering | dynamic import invisible to the import lint | mitigate + accept (stated) | Exactly one `importlib.import_module` call site across `src/` and `runtime/` — the same trees `cinv02-backend-import` covers — asserted by a test that parses both. The scan matches the rule's scope deliberately: narrowed to `src/ccf/graph` it would miss a dynamic backend import in `src/ccf/deployment/manifest.py`, which holds the adapter name. The residual — a dynamic import is not statically visible — is written into the module docstring rather than claimed away. |
| T-15.4-43 | Elevation of privilege | writer factory reachable from any core module | mitigate | `BackendRegistration.make_writer` is a public field on a record the public `resolve()` returns, so `cinv02-graph-writer`'s statement — only `ccf.assembly` and `ccf.boot` may import a write module — no longer bounds who can reach a writer constructor. | T-15.4-14 | Spoofing | a loaded object that is not the adapter it claims to be | mitigate | `resolve()` verifies the loaded object is a `BackendRegistration` and that its `name` equals the requested name, refusing with both names in the message. |
| T-15.4-15 | Denial of service | stale or absent packaging metadata | mitigate | Built-in discovery reads the package directory, not packaging metadata, so a stale `egg-info` or an uninstalled checkout cannot make the SDK unbootable. Version derivation falls back documented-ly when distribution metadata is absent. |
| T-15.4-SC | Tampering | package installs | mitigate | This plan adds no package. `importlib.metadata`, `pkgutil` and `ast` are stdlib; `pydantic` is an existing exact pin. |
