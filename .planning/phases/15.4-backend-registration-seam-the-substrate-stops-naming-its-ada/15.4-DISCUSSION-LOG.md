## Where per-backend write code lives

Framing: all six backends' writer classes live in one 3,200-line file,
`src/ccf/graph/_writer.py`, and `tools/lints/harness_imports.py:92` enforces
single-writer by permitting exactly one module to be imported only from L2.
That module imports all six backends, which is what D-IMPL-93 forbids. The code
must move; the question was what happens to the lint when it does.

| Option | Description | Selected |
|--------|-------------|----------|
| Two modules per backend | `backends/<name>.py` reads, `backends/<name>_write.py` writes. Lint rule keeps its exact current shape — guards write modules, only L2 imports them. One rule, six files. | ✓ |
| One file per backend | Reads and writes together. Fewer files, but readers import the file too, so the rule must shift from guarding a module to guarding a class — weaker and harder to check. | |
| Move only the subclasses | Shared machinery stays central, per-backend subclasses move out. Core stops importing backends but the large file stays large and the split point needs care. | |

**User's choice:** Two modules per backend.
**Notes:** Recorded as D-01/D-02/D-03. The deciding factor was that single-writer
is architectural (CLAUDE.md §10), so trading a statically checkable rule for an
approximately checkable one is not worth fewer files. The substrate-neutral base
stays in `_writer.py`.

## How a backend announces itself

| Option | Description | Selected |
|--------|-------------|----------|
| Manifest names it, entry points find it | Manifest declares the adapter in force (explicit, auditable, replay-pinnable); entry points let a third party ship an adapter as a separate package with no change to this repo. | ✓ |
| Manifest names the module only | Fully auditable, nothing to make deterministic, but every deployment must point at a third-party adapter by hand. | |
| Entry points only | Least ceremony, but what's in force becomes implicit in the installed environment rather than declared in a versioned document. | |
| Import-time self-registration | Simplest to build, but `backends/__init__.py` still lists all six, and optional drivers load even when unused. | |

**User's choice:** Manifest names it, entry points find it.
**Notes:** Recorded as D-04. Discovered during discussion: `pyproject.toml`
declares no entry points today, so this is CCF's first plugin surface — group
name, documentation, and versioning are new ground.

## When third-party code is imported

Follow-on question created by the entry-point choice: any installed package can
declare an adapter, so when does CCF run that package's code?

| Option | Description | Selected |
|--------|-------------|----------|
| Only when the manifest names it | Discovery reads names without executing. The named adapter imports at boot. Nothing runs unless asked for by name; optional drivers stay unloaded. | ✓ |
| At startup, all of them | Registry complete and broken adapters fail early — at the cost of running any installed package's module-level code at every boot. | |
| At startup, from an allowlist | Early failure for trusted packages only, but adds a second list to maintain alongside the manifest. | |

**User's choice:** Only when the manifest names it.
**Notes:** Recorded as D-05/D-06. Preserves today's lazy-import behavior for the
`neo4j` and `pymongo` extras (`boot.py:191,211`) by construction rather than by
special case.

## Connection settings validation

| Option | Description | Selected |
|--------|-------------|----------|
| Typed config model per adapter | Adapter ships a Pydantic model naming what it needs; registry validates before boot. Failure names the adapter and the field. | ✓ |
| Plain string mapping, adapter checks | Less machinery, but error quality varies per adapter and requirements can't be inspected without running the adapter. | |
| Plain mapping plus required-key list | Uniform "you forgot X" errors without per-adapter models, but catches only a missing value, never a malformed one. | |

**User's choice:** Typed config model per adapter.
**Notes:** Recorded as D-07. Follows CLAUDE.md §11. `_preflight_backend`'s
existing dictionary (`manifest.py:261-266`) already holds this knowledge in
declarative form, so the migration largely relocates it. The current refusal
behavior — a declared backend missing its connection argument, or a credential
supplied for an unselected backend — must survive.

## Secrets

| Option | Description | Selected |
|--------|-------------|----------|
| Manifest holds references, boot resolves | Manifest names an environment variable, not a value. Uniform shape, no secret in the manifest, and replay can pin which reference was used without recording what it resolved to. | ✓ |
| Secrets stay a separate argument | Smallest change, provably no secret reaches a manifest — but the boot signature keeps a per-database shape, which is what the phase set out to remove. | |
| One mapping, secrets refused by validation | Uniform and simple, but relies on detection that can be fooled. | |

**User's choice:** Manifest holds references, boot resolves them.
**Notes:** Recorded as D-08. Judged a net improvement over today rather than a
lateral move: current side-channel arguments are safe but invisible, so nothing
versioned records which credential a deployment used. Flagged for planning —
Phase 15.3 review found a real credential defect in this area (WR-02/WR-03), so
the no-persistence guarantee at `backends/fluree.py:678-679` is the regression
reference.

## Decided without asking (stated, open to objection)

- **Replay pins the adapter** (D-09) — name, version, and secret-reference
  names, never a resolved value. Follows from CCF pinning everything that
  affects an answer.
- **Public API break is pre-authorized** (D-10) — D-15B grants free rein
  pre-1.0 (`pyproject.toml` version `0.1.0`) conditioned on a migration note in
  `docs/SURFACE-CHANGES.md`. Verified during discussion rather than asked.
- **The six-name `Literal` becomes a plain string** (D-12) — a generated list
  would still be six database names in a core file. Verified that no exported
  JSON Schema exists and that `DeploymentManifest` is content-addressed by file
  bytes, so existing manifests and replay pins are unaffected.
- **Proof is an out-of-tree adapter** (D-11) — exercises the path a real third
  party would take, which an in-tree seventh backend would not.

## Rejected as half-measures

Ruled out on Dave's explicit "complete seam, not partial" instruction, and
recorded so they don't reappear during planning as de-risking:

- Exempting `_writer.py` from the no-backend-import rule.
- Keeping per-database keyword arguments as deprecated pass-throughs alongside
  the new mapping.
