<objective>
Record which adapter answered.

Once an adapter can be a third-party package, which adapter and which version
produced a Context Product is something that affects the answer, and CCF pins
everything that affects an answer. So dimension 2 gains three fields: adapter
name, adapter version, and the *names* of the credential references in force.
Never a resolved value.

One premise in the phase context was wrong and the correction shapes this plan.
There is no existing backend pin to extend — no replay dimension records a
substrate today. The 15.2-08 extension to dimension 2 was `survivor_cap`, not a
backend pin. Dimension 2 is still the right home, but this creates the **first**
adapter pin rather than extending one, so it is correspondingly larger and needs
its own plumbing decision. That decision was made in plan 15.4-05: the fact
travels on `FabricHandle.adapter` as an `AdapterPin`, which is the smallest
route and the one an adopter can reach.

Purpose: replay can answer "which adapter, which version, which references"
from the record alone.
Output: three dimension-2 fields, one optional builder parameter, the one
in-repo caller that uses it, and the tests that prove old records still resolve
and new ones carry no secret.
</objective>

Dimension 2 today (`src/ccf/replay/record.py`, `PolicyBindingsSnapshot`):

    bindings: tuple[PolicyBinding, ...]
    hitl_actions: str = NO_HITL_ACTIONS
    survivor_cap: int | None = None

Target additions, following the same positive-sentinel discipline the class
docstring already describes for `hitl_actions` and `survivor_cap` (and the
`workflow_step_sequence` precedent):

    graph_adapter: str = NO_ADAPTER
    graph_adapter_version: str = NO_ADAPTER
    graph_secret_refs: tuple[str, ...] = ()

Sentinel constants in this module follow one style — `NO_GRANTS_SET_HASH =
"no-grants"`, `NO_HARNESS = "no-harness"`, `NO_HITL_ACTIONS =
"no-hitl-actions"`, `NO_WORKFLOW_TRACE = "no-workflow-trace"`. Add
`NO_ADAPTER = "no-adapter"`.

From `ccf.graph.registry` (plan 15.4-02) and `ccf.boot` (plan 15.4-05):

    AdapterPin(name: str, version: str, secret_refs: tuple[str, ...])
    FabricHandle.adapter -> AdapterPin

Why old records still resolve: D-IMPL-89 makes `resolve_artifact` verify
`sha256(raw fetched bytes) == content_address` **before** model validation, so a
record written before the fields existed still resolves. That ruling was made in
plan 15.2-08 to unblock exactly this kind of extension.
</interfaces>
