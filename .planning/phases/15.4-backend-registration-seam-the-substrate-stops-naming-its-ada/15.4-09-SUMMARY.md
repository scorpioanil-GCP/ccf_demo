# Phase 15.4 Plan 09: `ccf backends` Summary

**The manifest schema's lost `backend` enum is replaced by a read-only route
and a CLI noun that answer a better question — not what someone hard-coded,
but what is installed here — and that refuse with the offending distribution
named rather than with an opaque 500.**

## What Was Built

### Task 1 — `GET /backends` over the registry (`024a8be`)

`runtime/ccf_runtime/http_api/routes/backends.py`, 129 lines, one public name.

One read-only endpoint returning `{"backends": [...]}` — the sorted result of
`ccf.graph.registry.declared_names()` — mounted in `app.py` beside the other
nine under the same `guarded` dependency list every other read route carries.
No new posture was invented, and a test proves it by holding the route's
unauthenticated status *equal to* `GET /schema`'s rather than to a literal
401.

**The route enumerates no vocabulary.** The names come from the registry,
which derives them from the adapter package on disk and from installed entry
points. `substrate_names.check` on the real derived vocabulary — six words,
`memory` included, which is the one a hand-typed alternation omits — returns
zero findings, so the module passes the stricter bar deliberately even though
plan 15.4-07 scopes that rule to `("src",)`.

**The success path discloses names and nothing else** (T-15.4-11). The
registry knows each adapter's distribution and version; the route returns
neither, and the reason is in the docstring: a caller who learned those would
have learned the deployment's dependency inventory. The test asserts
`set(body) == {"backends"}` rather than listing fields that must be absent —
a blocklist only ever catches the leaks somebody thought of, while an exact
key set fails on any widening.

**The refusal path is the one stated narrowing.** `declared_names()` is
fail-closed on any installed distribution's bad entry-point metadata, so the
one command an operator reaches for to answer "which adapters does this
deployment have" raises in exactly the case they need it. Uncaught, that
arrives as an opaque 500 and throws away the one thing the refusal carries:
the name of the offending distribution, which is what tells a packaging
conflict apart from a missing adapter. It is caught and returned as `503` in
the API's existing typed-refusal shape. Not `200` with an empty list, because
an empty list is a different fact — asserted directly, by requiring
`"backends"` absent from the refusal body.

**The committed OpenAPI document was regenerated and the diff read.** It is
exactly one new path and nothing else: **25 insertions, 0 deletions**.
`public/reference/http-api.md` needed no edit — it includes `openapi.json`
whole rather than enumerating endpoints, so the new endpoint is published by
construction. The plan's instruction was conditional ("if it enumerates
endpoints"); it does not.

### Task 2 — the `backends` noun and its migration note (`23c0dbd`)

`runtime/ccf_runtime/cli/commands/backends.py`, 66 lines, one public name.

`register(subparsers)` adds the noun and one verb, `list`, whose `build`
returns a single `RequestSpec(method="GET", path="/backends")`. Registered in
`main.build_parser` beside the other nine. The noun-verb shape D-IMPL-22 ruled
is kept — there is deliberately no bare `ccf backends`, and a test asserts the
usage error names the available verb.

**The command re-derives nothing.** `grep -c "declared_names"` on the module
is **0**, and that is a standing test rather than a one-time check, because
the failure it guards — someone "simplifying" the HTTP hop away — would pass
every behavioural test in the file while costing the zero-privileged-path
invariant.

**The `503` reaches the operator with something usable.** Under `--local` the
CLI runs the app in-process rather than around it, so the typed refusal
travels the same path a remote client sees. The test makes `declared_names`
raise and requires both distribution names in stderr and no traceback
anywhere.

**2. [Rule 2 — Missing critical] The CLI discarded 5xx response bodies, so the 503's whole point never reached the operator**

- **Found during:** Task 2
- **Issue:** `_execute` wrote `wiring error: GET /backends -> 503` to stderr
  and returned `EXIT_WIRING`, **discarding the body**. The plan's own
  acceptance criterion — "`ccf --local backends list` exits nonzero and prints
  the offending distribution name, not a traceback" — was unsatisfiable
  against that code path. Task 1 built a refusal specifically to carry the
  distribution name, and the CLI threw it away one layer later.
- **Fix:** `_execute` now appends the response body to the stderr message when
  the body is non-empty. Exit code and stream are unchanged — still
  `EXIT_WIRING`, still stderr — so the documented contract ("2 — a wiring
  error (transport failure or 5xx), reported on stderr") holds exactly as
  written; only the message got the information it was missing.
- **Why the opaque-5xx posture is not weakened:** T-07-26's rule is that
  *wiring errors* surface as opaque 5xx, and it is right for an unhandled
  exception. A deployment that answered with a **typed** refusal has said
  something the operator must act on. The comment at the change site makes
  that distinction rather than leaving the next reader to assume the posture
  was relaxed.
- **Files:** `runtime/ccf_runtime/cli/main.py`
- **Verification:** `test_wiring_error_exits_2_on_stderr` (the transport-failure
  case, which never reaches this branch) still passes; the new refusal test
  asserts both distribution names in stderr; `pytest tests/cli -q` → 89 passed.
- **Committed in:** `23c0dbd`

### Recorded design notes (not fixes)

**5. The error-code value keeps the plan's underscores against house style**

The plan names the stable code `backend_registry_conflict`. Every existing
value in `ccf_runtime.http_api.errors` is hyphenated (`subject-conflict`,
`tenant-unauthorized`). Plan fidelity won — the plan names the literal and
calls it stable — but the inconsistency is real and is recorded here rather
than silently resolved, because that module's docstring says renaming a value
is a breaking change to every consumer. If it is to be hyphenated, now is the
only cheap moment.

**6. `public/reference/http-api.md` was deliberately not modified**

It is in the plan's `files_modified`, but the plan's action text is
conditional — "update it *if* it enumerates endpoints". It does not: it is 15
lines that include `openapi.json` whole via a snippet directive, precisely so
that "the published contract is the committed contract by construction. There
is no transcription step in which the two could diverge." The new endpoint is
published by regenerating `openapi.json`, which task 1 did.
