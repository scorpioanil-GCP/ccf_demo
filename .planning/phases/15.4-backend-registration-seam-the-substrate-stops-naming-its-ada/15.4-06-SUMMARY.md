# Phase 15.4 Plan 06: The Manifest Stops Enumerating Substrates Summary

**The last two substrate enumerations left core — a six-name `Literal` in a
Control Plane contract and a substrate-to-required-argument table in the wiring
layer — and in the same change a credential stopped travelling as an anonymous
boot argument and started travelling as a named, auditable reference that
refuses to resolve to nothing.**

## What Was Built

### Task 1 — a plain adapter name and a named credential (`4826b9d`)

`DeploymentManifest.backend` is now `str = Field(pattern=r"^[a-z][a-z0-9_]*$")`.
The pattern is a **shape** rule that fixes D-16's naming convention without
naming a single adapter; membership is task 2's, checked at load against the
registry. The docstring records the rejected alternative in the field itself: a
*generated* six-name list would still have been six database names in a core
file, which is what CLAUDE.md §11 forbids, and the accepted cost is stated
rather than worked around — a typo is caught at load instead of at parse, and an
adopter's editor no longer completes the name from the exported schema.

`SecretReference(field, env_var)` and `backend_secrets: tuple[SecretReference,
...] = ()` arrived with a validator refusing a repeated `field`, on
`_keys_are_unique`'s argument: a repeated field makes "which reference was in
force" ambiguous and that answer feeds Decision Replay dimension 2. A repeated
`env_var` under *different* fields is permitted, deliberately — one variable
legitimately satisfying two fields is ambiguous about nothing, and the asymmetry
is the same one the artifact-key validator already draws.

The dangling `_open_backend` citation at the class docstring is repointed at
`boot()`'s required `backend` argument, where the refuse-to-infer posture now
lives. `grep -c "_open_backend"` on the file is `0`.

**The prose rule fired where the plan said it would.** The class docstring
enumerated five substrates across the two paragraphs the field's `Literal` sat
between, and `cinv04-substrate-prose` trips at three. The file had to be read
for enumerations rather than edited only at the field: the "kind only" paragraph,
the `backend` attribute paragraph and the Q3 paragraph were all rewritten.
`substrate_names.check` on the real derived vocabulary — six words, `memory`
included, which is the one a hand-typed alternation omits — returns zero
findings for both sub-rules.

**The committed schema, regenerated and read before committing.** The diff is
exactly what the plan predicted and nothing else: `backend` loses its six-value
`enum` and gains `"pattern": "^[a-z][a-z0-9_]*$"`, `backend_secrets` appears with
its `$defs` entry, and the two class descriptions change. One file moved;
`docs/schemas/` is otherwise byte-identical.

**All eleven example manifests were parsed through `load_artifact` rather than
eyeballed.** Every one declares a name a plain string accepts, every one parses
byte-unchanged, and every one reports `backend_secrets=()`. None needed an edit,
so there is no finding to record.

**The name was claimed in the commit that added it.** `SecretReference` enters
`__all__` (in the module's existing sorted position — SCREAMING_CASE first, then
CamelCase) and `docs/surface-changes/15.4-06-manifest.md` was created in the same
commit with its section. This is why task 1 stands alone as a commit:
`tests/test_surface_completeness.py` is in `testpaths` and would have failed this
commit with `added: ccf.controlplane.artifacts.SecretReference — NO ENTRY`. The
drift gate would not have caught it — module-granular, and this module is already
named in six fragments — which is exactly the analysis the plan's T-15.4-42 makes.

### Tasks 2 + 3 — the preflight asks the registry, and twenty call sites move (`1c89942`)

**`_preflight_backend` is gone, and so is its table.** `_preflight_adapter` does
four things in order: refuses `manifest.backend` if it is not in
`declared_names()`; `resolve()`s it; calls
`ccf.graph.registry.validate_connection`; and refuses any `backend_secrets` entry
outside the adapter's `secret_fields`. Its position in `load_and_boot` is
unchanged — before any document is read and before anything is registered —
because that ordering is the entire reason the function exists, and the docstring
now says so about the adapter rather than about a substrate.

Both of the deleted table's refusals survive, by the adapter's own contract
rather than by a branch: a required setting missing is a required field (D-07), a
setting the adapter does not take is the inherited `extra="forbid"`.
`grep -c "model_validate\|ValidationError"` on the file is `0` — the connection
refusal is not rebuilt here, and a comment at the call site says why in the
registry's own terms.

**The one environment read in `src/`.** `_resolve_secret_references` reads
`os.environ` and nothing else under `src/` does:
`grep -rn "os.environ" src/ | wc -l` is **1**, and the match is the call itself.
It belongs in the wiring layer rather than in `ccf.boot` because `boot()` takes
values and reads no environment, which is what keeps the composition root
deterministic. Each entry becomes a `ResolvedSecret(field, ref_name, value)`, so
the variable name travels with the value all the way to `AdapterPin.secret_refs`
— a plain `Mapping[str, SecretStr]` could only ever have said that some
credential was supplied.

**Unset and empty are the same refusal.** `if not value` covers both, and the
message names the adapter, the field and the variable **name** and no value. The
docstring states why silence is not consent, in WR-02's own terms: a manifest
that names a reference has asserted a credential is required, and a fabric that
fell back would reproduce the defect where a credentialed URL connected
anonymously because the wire client derives no header from `base_url` userinfo.

**`load_and_boot`'s signature is now four parameters**, verified against the
D-10 target exactly: `['connection', 'manifest_path', 'registry', 'tenant_id']`.
The six per-database keywords are gone, and so are 15.4-05's three transitional
pieces — `DIRECT_ARGUMENT_REFERENCE`, `_connection_mapping` and
`_supplied_secrets` — which existed to keep the old signature working across one
wave and were deleted on schedule. Deprecated pass-throughs were not kept: the
plan rejected that shape, and the reason is in the fragment.

**`tests/deployment/test_secret_references.py`, 9 tests.** Each of the four
measured leak surfaces gets one, plus the positive half of the asymmetry, plus
both V14 cases, plus the undeclared-field refusal:

| Test | Claim |
| --- | --- |
| canonicalizing a `ResolvedSecret` raises | V13a — the no-persistence guarantee is a mechanism |
| a manifest's `SecretReference` **is** content-hashable | the positive half: the reference name is present in the canonical bytes, the value is not |
| a misspelled connection key does not echo its value | V13b — asserted on `str`, `repr`, `__cause__` **and** `__context__` |
| nothing is registered when the connection is refused | the preflight ordering, for the connection refusal too |
| a booted store's identity carries no credential | V13c — end to end from the manifest reference, with the value asserted to have *arrived* |

| a reference the adapter does not declare is refused | naming the adapter and the field, with the variable set and its value absent |

**Twenty call sites migrated.** Twelve examples, seven in
`tests/deployment/test_manifest.py`, one in
`tests/deployment/test_operator_builder.py`. An AST scan for any `boot(...)` or
`load_and_boot(...)` call carrying one of the eleven retired keywords, over `src

The contradiction test kept its name and its point in the shape the mapping gives
it — one connection mapping carrying a key the declared adapter does not take —
and **gained** an assertion the plan did not ask for: the supplied value must be
absent from the refusal. That is the assertion that makes it a test about the
