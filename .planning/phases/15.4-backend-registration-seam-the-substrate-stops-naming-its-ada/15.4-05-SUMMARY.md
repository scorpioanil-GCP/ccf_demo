# Phase 15.4 Plan 05: The Composition Root Stops Naming Substrates Summary

**`boot()` went from sixteen keyword arguments — eleven of them per-database,
with the substrate chosen by asking which was not `None` — to eight, none of
which names a database; the handle now says which adapter answered, at which
version, and under which credential reference names; and all twenty-three call
sites moved with it, including the two test callers of the deleted
`_open_backend`, neither of which lost its guarantee.**

## What Was Built

### Task 1 + 2 — the registry lookup and every call site, one commit (`f542b65`)

Tasks 1 and 2 are a single commit by the plan's own instruction: the moment the
signature changes, every unmigrated call site is a `mypy --strict` error, so
committing the reshape alone would have left `make typecheck` red.

**`_open_backend` and the `_Backend` Protocol are gone.** So are the six
module-top backend imports and the two lazy in-function ones. `src/ccf/boot.py`
is 315 lines against 403, and the AST scan for `ImportFrom` nodes under
`ccf.graph.backends` returns `[]`.

`boot()`'s body is now five steps: `resolve(backend)`; `validate_connection`
**by name**, never a `model_validate` written here; the `secret_fields`
membership refusal; `open_store` with the secrets unwrapped in the argument
expression; then `mint_boot_token` inside the existing try/close guard and
`make_writer`. Everything after — the shutdown closure, the Control Plane
resolution, the `AssemblyWorker` construction, the half-booted-fabric
cleanup — is byte-identical to what it was.

**All four of the cascade's refusals are accounted for, in the docstring, so a
reader can see nothing was dropped:**

| Refusal | Where it went |
| --- | --- |
| not exactly one backend selected | structurally impossible — one name selects one adapter |
| a credential for a backend not selected | `_refuse_undeclared_secrets`, against the resolved adapter's own `secret_fields` |
| a required connection setting missing | the adapter's config model, where the field is required (D-07) |
| a connection setting the adapter does not take | the same model, by inherited `extra="forbid"` |

The last two are built by `ccf.graph.registry.validate_connection` and nowhere
else: `grep -c "model_validate\|ValidationError" src/ccf/boot.py` is `0`. The
secrets refusal reads in the same shape — adapter, then field — and is built
from key names only, so it needs no sanitizing.

**`FabricHandle` gains one attribute and it is a pin.** `adapter: AdapterPin`,
with `secret_refs` built from `ResolvedSecret.ref_name` and sorted. The class
docstring names the departure rather than slipping it in: this class has until
now carried capabilities and no state a caller could misuse, and now it carries
a fact — one an adopter needs, because from D-IMPL-93 onward the adapter can be
third-party code. `vars(handle)` is `['_shutdown', 'adapter', 'reader',
'registry', 'worker']`; no attribute anywhere on the class contains `writer`.

**Every docstring naming a substrate was rewritten.** The cinv04 checker, run
with its real derived vocabulary (six words, including the `memory` a
hand-typed alternation omits), returns zero findings for both sub-rules.

**Twenty-three call sites migrated.** Nineteen were one-line mechanical edits.
`tests/conftest.py` changed least and matters most: its per-backend `location`
dict became the `connection` mapping with keys renamed to the config models'
field names, and the `**location` splat became `backend=backend,
connection=location`. An AST scan for `boot(...)` calls carrying any of the
eleven retired keywords, over `src runtime tests perf examples tools`, reports
**0**.

**The four `exactly one backend` tests were migrated rather than deleted** —
see the decision list above. The `no backend selected` one became a signature
assertion plus a `TypeError`, which is the stronger form of "there is no
default substrate".
