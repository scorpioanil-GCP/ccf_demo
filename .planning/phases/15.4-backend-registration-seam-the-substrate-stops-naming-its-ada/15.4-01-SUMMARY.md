# Phase 15.4 Plan 01: Structural Lint Rules Summary

Built the enforcement half of the phase first, so everything after it has
something to fail against: one widened rule that survives the writer split, and
two new rules that are proven to fire before anything has proven them able to
pass.

## What Was Built

### Task 1 — `cinv02-graph-writer` guards a class of modules (`ee2bddd`)

D-01 moves every backend's writer class out of `ccf.graph._writer` into
`ccf.graph.backends.<name>_write`. The rule as written guarded one path, so it
would have kept running, kept passing, and guarded nothing the moment plan
15.4-03 landed.

`WRITER_MODULE` membership became `is_write_module(name)`: true for the neutral
base, or for a dot-bounded member of `ccf.graph.backends` whose final segment
ends with `WRITE_MODULE_SUFFIX`. No substrate name appears, so a seventh
adapter's write module joins the guarded set on arrival.

The permitted importers split in two, because the neutral base has one more
legitimate consumer than a per-backend write module does:

| Guarded module | Permitted importers |
| --- | --- |
| `ccf.graph.backends.<name>_write` | `ccf.assembly`, `ccf.boot` — unchanged |
| `ccf.graph._writer` | those two, plus `ccf.graph.registry`, plus any guarded write module (by predicate) |

The registry entry is a reviewed named constant, not an allowlist line (D-13).
It exists because the registry *types* the write seam — naming `BaseGraphWriter`
and `BootToken` so `BackendRegistration.make_writer` can be typed under
`mypy --strict` — and it stops there. Two tests pin the asymmetry: the registry
may import the neutral base, and the registry may **not** import a per-backend
write module.

Rule id unchanged. This is the same rule with a wider guarded set, not a new
rule, and the module docstring says why naming the class rather than the
instance is the lesson D-GATE-15.3 records.

### Task 2 — `cinv02-backend-import` (`40bdfc7`)

`tools/lints/backend_imports.py`. A module may import `ccf.graph.backends` or
anything under it only if it is itself under `ccf.graph.backends`. Eleven tests,
six of them negative controls covering every import spelling — `from ... import`,
plain `import`, the package-level `from ccf.graph.backends import <name>_write`,
a function-scope import reported at the import's own line, and the message
naming `ccf.graph.registry` as the way out. Dot-boundedness is tested in both
directions: a lookalike sibling package is neither matched nor exempt.

### Task 3 — `cinv04-substrate-name` and `cinv04-substrate-prose` (`b7d6d40`)

`tools/lints/substrate_names.py`, two rule ids under one AST walk.

`substrate_vocabulary(base)` reads the stems of `*.py` under
`src/ccf/graph/backends/`, drops `__init__`, strips a trailing `_write`, and
caches per base. That is CLAUDE.md §11 turned on the checker itself: the module
holds an interpreter, not a list. The proof is a test that builds a temporary
adapter package containing `zzquux.py`, `zzquux_write.py` and `__init__.py`,
asserts the vocabulary is exactly `{"zzquux"}`, asserts `zzquux` appears nowhere
in the real repo, and then drives the full matcher off that temporary
vocabulary — so the derivation is proven end to end, not just at the reading
step.

Sub-rule 2a fires on non-docstring string literals, `Name.id`, `Attribute.attr`,
`arg.arg`, `def`/`class` names, and import aliases. Sub-rule 2b fires when one
docstring names three or more *distinct* vocabulary words, with docstrings
identified structurally (first statement of a Module/Class/Function body when it
is a string constant) rather than by position in the text.

Findings are collected as `(lineno, rule, message)` and sorted before formatting,
so output order does not depend on `ast.walk`'s BFS traversal.

## Deviations from Plan

None that changed behaviour. Three places where the implementation is stricter
or more explicit than the plan required, each recorded rather than assumed:

**1. Zero substrate names, not zero literals.** The acceptance criteria for
tasks 2 and 3 permit substrate names inside docstring prose (`grep -vn '^\s*#'`
does not strip docstrings, and the criteria say "outside the docstring" and
match only quoted forms). Both checkers contain none at all —
`grep -rln "sqlite\|postgres\|neo4j\|mongo\|fluree" tools/lints/*.py` returns
nothing across every checker in the tree. The plan's action text for task 3
suggested naming the similarity-axis token when arguing its exemption; that
argument is made without the name instead, because the phase's own success
criterion is "no substrate name appears as a literal in any checker module" and
a docstring is a string literal.

**2. `substrate_names.check`/`check_source` take an optional `base`.** The
shared per-file checker contract is `(path, module_name)` with no base, but the
vocabulary has to be read from somewhere. `repo_base_for(path)` walks the path's
ancestors for the one holding `src/ccf/graph/backends/` and falls back to the
working directory, and an explicit `base=` keyword is added for tests. The
positional signature the runner calls is unchanged, so registration in
`CHECKERS` at 15.4-07 needs no adaptation.

**3. Three extra tests beyond the acceptance criteria.**
`test_the_exempt_set_has_exactly_two_reviewed_entries` (T-15.4-12 — makes a
third exemption a deliberate decision), `test_the_adapter_package_is_actually_populated`
(an empty vocabulary makes the rules silent rather than wrong, which would be a
silent vacuum), and `test_relative_imports_are_reported_as_nothing` in the
backend-import suite (pins a documented blind spot as a *known* one).

No Rule 1/2/3 auto-fixes were needed. No architectural question arose.

## The Stated Window

Between this plan and 15.4-07 the two new rules exist and are proven to fire,
but do not run over the tree. This is deliberate and is stated in the plan
objective rather than hidden: registering them now would make `make lint` red
for five plans, which is how a team learns to read a red gate as normal.

What guards the properties during the window is the plan sequence (15.4-03
through 15.4-06 make them true), plus one closure that converts sequence
discipline into a check: 15.4-06's last task runs `substrate_names.check` over
all of `src/ccf` except `backends/`, and `backend_imports.check` over `src/` and
`runtime/`, before registration. That closes the hole where a substrate name
reintroduced in a core module nobody edited would survive to 15.4-07.
