## What Was Built

### Task 1 — six config models, six registration records, and their surface claim (`d5c7282`)

Each `backends/<name>_write.py` gained three things: a config model, a private
`_open_store`, a private `_make_writer`, and the module-level `REGISTRATION`
that names them.

| Adapter | Config model | Required | Optional | `secret_fields` |
| --- | --- | --- | --- | --- |
| sqlite | `SqliteConnection` | `database_path: Path` | — | `frozenset()` |
| postgres | `PostgresConnection` | `dsn` | `schema_name = DEFAULT_SCHEMA` | `frozenset()` |
| memory | `MemoryConnection` | — | — | `frozenset()` |
| neo4j | `Neo4jConnection` | `uri` | `partition = None` | `frozenset()` |
| mongo | `MongoConnection` | `uri` | `partition = None` | `frozenset()` |
| fluree | `FlureeConnection` | `url` | `partition = None` | `frozenset({"bearer_token"})` |

**Where the knowledge came from.** The `required` dict at
`ccf/deployment/manifest.py:260-267` was already declarative, so this is mostly
a relocation of data that was always data — out of a core file that had to be
edited for every substrate, into the adapter that owns it.

**Both refusals survive, by different mechanisms, and only one of them is
code.** A missing connection argument is refused because the field is required.
An argument the adapter does not take is refused because every model derives
from `CCFContract` and inherits `extra="forbid"` — there is no statement to
read, which is precisely why a sweep asserts it per adapter. The empty
`MemoryConnection` is the clearest case: the `"memory": None` special case in
the old mapping disappears with no special case replacing it, because a model
with no fields requires nothing and forbids everything.

**No credential is a field on any model.** `FlureeConnection` carries `url` and
`partition` only, and its docstring states the reason so nobody adds
`bearer_token` later for convenience: Pydantic reports `input_value=` verbatim
in a `ValidationError`, and a misspelled connection key is exactly the case
where a live token sits under a name nobody declared. The token is named in
`secret_fields` and its value arrives in the separate `secrets` mapping, which
is never validated. `_open_store` unwraps the `SecretStr` in the call-site
argument expression, so the plain value is never bound to a name that outlives
the call.

**The import-shape difference is preserved and now argued in three
docstrings.** `neo4j_write` and `mongo_write` keep their driver imports inside
their store constructors; `fluree_write` imports `httpx` at module top because
it is a core pin. Each of the three docstrings now says that the registry must
not flatten the two shapes into one, and names the other as the deliberate
contrast. The property this buys — resolving one adapter loads no other
adapter's driver — used to be two hand-written lazy branches in `boot.py` and
now holds by construction, because `resolve` imports exactly the write module a
deployment named.

**`__all__` ruled explicitly.** Each module's `__all__` gains its config model
and `REGISTRATION` and nothing else; `_open_store`, `_make_writer` and
`ADAPTER_NAME` stay off the surface. Twelve names therefore entered the live
surface on this commit and were claimed in the same commit, in
`docs/surface-changes/15.4-03-write-modules.md` — the fragment 15.4-03 wrote
for these same six modules — with all seven fields, `Public surface: true`,
`Change type: added`, fully dotted `Surface` values and `Migration: none`.

### Task 2 — WR-05 closed (`13d00f0`)

`FlureeGraphStore.__init__` built an `httpx.Client` and then issued three
bootstrap requests. Any failure among them propagated with the client — and its
pool — still open, and a constructor that raises returns no object the caller
could have closed.

Everything after the client is assigned is now wrapped in
`try: … except BaseException: self._client.close(); raise` — the shape
`ccf.boot.boot` already uses around `mint_boot_token`. `BaseException` rather
than `Exception` because a `KeyboardInterrupt` between two bootstrap requests
leaks a pool exactly as an HTTP error does.

D-14 put this in *this* phase for a specific reason, and the class docstring now
records it: D-08 adds a secret-resolution step in front of store construction,
so a mis-set environment variable produces construction failures routinely
rather than exceptionally.

Two tests, not one:

- `test_a_failed_construction_closes_its_client` — `/health` answers 503 over a
  `MockTransport`; `httpx.Client.close` is counted and must be called **exactly
  once**, and the original `httpx.HTTPStatusError` must reach the caller.
- `test_a_refusal_before_the_client_exists_closes_nothing` — the two credential
  and origin refusals are raised before any client exists, so the counter must
  stay at zero. Without this leg, a guard placed one line too early would pass
  the first test and turn both refusals into `AttributeError`s.

**The credential behaviour is byte-untouched.** The diff to
`tests/graph/test_fluree_backend.py` is `+90/-0` — no existing assertion about
the userinfo/bearer refusals was edited — and the deletions in `fluree.py` are
the re-indented bootstrap block and its reflowed comments only.

### Task 3 — both refusals, per adapter, from a derived list (`8e51fa2`)

`tests/deployment/test_adapter_config.py`, 382 lines, **38 tests**. Every
parameter list is built from `declared_names()`; the module contains **zero**
substrate-name literals, verified against the lint's own derived vocabulary
rather than by eye.

| Claim | What is asserted |
| --- | --- |
| V12, sweep | every registered adapter's `config_model.model_config["extra"] == "forbid"` and `["frozen"] is True` |
| V12, per adapter | a fixed nonsense key raises `ValidationError` with an `extra_forbidden` error whose `loc` names the key |
| V11, per adapter | the required field omitted raises `missing` with the field in `loc`; then `ccf.graph.registry.validate_connection` — **by name** — raises `InvalidBackendConfig` naming both the adapter and the field |
| V11, empty-model adapter | an adapter with no required settings validates an empty mapping (asserted, not skipped) |
| V13b, per adapter | a recognisable value under an undeclared key appears in neither `str(exc)`, `repr(exc)`, `__cause__` nor `__context__` |
| V7, general | in a fresh interpreter, resolving one adapter loads that adapter's write module and **no other adapter's** |
| V7, drivers | in a fresh interpreter, resolving **any** adapter loads no optional-extra driver package |
| non-vacuity | the derived adapter list is non-empty and every entry resolves; the derived driver set is non-empty |

Two design points worth naming.

**The refusal message is asserted, never rebuilt.** `validate_connection` is
the single owner of connection-refusal text because a refusal formatted from a
`ValidationError`'s own rendering embeds the supplied value. A second formatter
written in the test that exists to assert that property would be the first
crack in it, so the module defines no helper that builds one — verified by the
plan's own grep.

**The V7 driver claim is derived, and stated wider than the plan asked.** The
plan named `neo4j` and `pymongo` as literals and checked two adapters. Instead,
the optional extras whose name is also a declared adapter name are read from
`pyproject.toml`, mapped to the packages they install, and asserted absent after
resolving **every** adapter — including the extras-gated ones, whose drivers
must not load either, because their imports live inside their store
constructors. The derived set is `{bson, gridfs, neo4j, pymongo}`, a strict
superset of the plan's pair, and the module gains no vendor literal and no
substrate literal.
