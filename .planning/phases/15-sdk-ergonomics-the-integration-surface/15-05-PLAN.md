<objective>
Make timestamp handling in the artifact load path correct once, in `/src`, instead of
eleven times in `/examples`.

Purpose: D-02. `2026-08-03T12:00:00Z` is not an implicit timezone — `Z` is the ISO-8601 UTC
designator and the author stated UTC explicitly. PyYAML's timestamp resolver drops it and
hands back a naive `datetime`, which `ControlPlaneRegistry.register` then refuses as
non-canonicalizable. That naive datetime is a *parser* defect, not an authoring defect, so
refusing the author's document would punish them for a rule they did not break. The
timezone-attaching helper this forces has already drifted into six distinct implementations
across eleven sites.

Output: a resolver-stripped loader in the artifact path, a naive-timestamp refusal modeled
on `_reject_floats`, tests, and a `behavior`-class surface-change entry.
</objective>

  <action>
Define a private `_ArtifactLoader(yaml.SafeLoader)` in `artifacts.py` with its own copy of
`yaml_implicit_resolvers` and the `tag:yaml.org,2002:timestamp` entries removed, so a
timestamp-shaped scalar resolves as `str`. Build the copy explicitly rather than mutating
`yaml.SafeLoader`'s class attribute in place — mutating the shared class would change YAML
parsing for every other caller in the process, which is a much larger blast radius than
this decision authorizes.

Change `load_artifact`'s body at the single intervention point: `yaml.safe_load(text)`
becomes `yaml.load(text, Loader=_ArtifactLoader)`. No other line in `load_artifact` changes;
the `yaml.YAMLError` handler and the `parse_artifact` delegation stay as they are.

Add a `_reject_naive_timestamps(value, path)` sibling to `_reject_floats`, called from
`parse_artifact` immediately after `_reject_floats`. Copy three things from `_reject_floats`
exactly: the dotted path accumulator (`f"{path}.{key}"` / `f"{path}[{index}]"` with a
`'<root>'` fallback), the recursion over `Mapping` and `list`/`tuple`, and the
`ArtifactLoadError` type. It refuses a `datetime` instance whose `tzinfo` is `None` — such a
value can only arrive from a caller that pre-parsed the document with a stock loader — and
it refuses a string that matches an ISO-8601 date-time shape with no `Z` and no `±HH:MM`
offset. The message names D-IMPL-38 and stays under 200 characters and under three
sentences, so CINV-01a does not flag it (`_reject_floats`'s own three-line message is the
calibration point).

The `_ArtifactLoader` docstring carries the D-02 reframing verbatim, because without it a
future contributor reading "we refuse naive timestamps but accept `Z`" will read it as an
inconsistency and try to fix it: `Z` is the ISO-8601 UTC designator, the author stated UTC
explicitly, and PyYAML's resolver is what drops it — so the SDK reads timestamps as text and
lets the contract parse them, exactly as it already refuses floats rather than repairing
them.

Do not add a public timestamp-parsing helper. Contract fields annotated `datetime` are
parsed by Pydantic from the string, which is the whole point; a public helper would invite
adopters to keep hand-normalizing.

   `ArtifactClass` over a contract with a `str`-annotated field.
2. **`...Z` yields an aware UTC datetime** once a contract annotates the field `datetime` —
   `result.tzinfo is not None` and `result.utcoffset() == timedelta(0)`.

   already mixes converge.
