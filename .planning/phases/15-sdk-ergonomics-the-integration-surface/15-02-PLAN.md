<objective>
Create the `ccf.deployment` package as an empty, documented, algorithmic-tagged shell, and
land the D-15A standing guard around it **before any helper exists**.

Purpose: this phase's defining risk is that an ergonomic helper silently deletes a
whitepaper invariant — specifically, that a helper computes both `ProductLineage.operators_invoked`
and `run_gates`'s `engine_resolved` from one input, making lineage strict equality
tautological. The guard is written first so it is a standing constraint rather than a
retrofit. The package shell exists in this plan only so the guard has a real, non-vacuous
target from the moment it is written.

Output: the package root, the two-assertion gate-independence test module, and a
lint-level import ban with no allowlist.
</objective>

  <action>
Create `tests/products/test_gate_independence.py` with four tests.

**Test 1 — the perturbation regression.** Build a minimal valid `ContextProductContract`
with a `ProductLineage` whose `operators_invoked` is a known frozenset, then call
`run_gates(candidate, engine_resolved=<the declared set minus one element>, ...)` and assert
the result is a `LineageMismatchRefusal`. Add the mirror case: passing the declared set
unchanged yields a `ServableProduct`. Together these prove the two inputs are still
independently sourced and that the gate has something real to check.

**Test 2 — the AST identifier guard over `src/ccf/deployment/`.** Copy `_identifiers` from
`test_adapter_single_writer.py:128-150` verbatim, including its docstring reasoning.
**The guard MUST walk `ast.Name`, `ast.Attribute`, and `ast.alias` — never source text.**
The `ccf.deployment` package docstring names `run_gates` and `engine_resolved` as its worked
example, so a text or grep based guard would fail on the very documentation that records
compliance. Parametrize per file with `ids=lambda p: p.name` so a failure names the offending
module. Assert that no module's identifier set contains `run_gates`, `ProductLineage`, or
`engine_resolved`.

**Test 3 — signature inspection.** For every public callable exported from any
`src/ccf/deployment/` module, assert no single function's annotations mention both a
lineage-shaped name (`ProductLineage`) and an execution-shaped name (`ProjectionExecution`).
Use the whole-token `_annotation_names` regex helper from
`test_adapter_single_writer.py:231-250`, not substring matching.

**Test 4 — vacuity.** Assert the discovery glob found at least one module under
`src/ccf/deployment/` and that `ccf.deployment` is importable. A discovery helper that
silently returned nothing is the quietest way an invariant test stops being one — every
parametrized assertion above would go vacuously green.

The module docstring carries the two-section discipline: **"What these tests enforce,
exactly"** (D-15A: the two inputs to `run_gates` come from two sources; nothing in
`ccf.deployment` can collapse them) followed by **"What they do not enforce"** (they do not
prove the projection engine computed `operators_invoked` correctly, they do not cover
adopter code outside `ccf.deployment`, and they cannot catch a collapse expressed entirely
through dynamic attribute access). Scoping honestly is mandatory here; the I.2 retrospective
flagged overclaiming in exactly this test class.
