<objective>
Capture the phase-start public-surface baseline and stand up its drift gate, plus the
home for the curated surface-change log.

Purpose: ROADMAP Success Criterion 6 ("every removed or reshaped public surface is
recorded") cannot be satisfied honestly if the baseline is taken after the first surface
change. This plan is the **sole wave-1 plan**; nothing that touches a public surface — and
nothing that adds a module with an `__all__`, which includes `ccf.deployment` in 15-02 — may
start until it lands. Every other plan in the phase depends on it directly or transitively.

This plan also establishes the **single-owner regeneration rule**: `docs/surface/v0.2-surface.json`
is written by exactly two plans, this one (phase start) and 15-21 (phase close). No plan in
between lists it in `files_modified` or runs `make surface`. Eleven plans each regenerating the
whole-tree manifest in its own worktree would pass `--check` pre-merge and leave the tree stale
after the second merge, on a file no plan then owns.

Output: `tools/dump_surface.py` (with `--check` and `--report`), the committed
`docs/surface/v0.2-surface.json` baseline, `tests/test_surface_drift.py`, a `make surface` target, and the
`docs/surface-changes/` fragment directory with its stated entry shape.
</objective>

Discovery: import every module under `src/ccf/` and `runtime/ccf_runtime/` that defines

`model_fields`), and `type(obj).__name__` for everything else. Do not record docstrings —
the manifest tracks signatures, not prose.

Export `serialize(document: dict[str, Any]) -> str` returning
`json.dumps(document, indent=2, sort_keys=True) + "\n"`, with the docstring stating that
`tests/test_surface_drift.py` imports this function rather than restating the recipe so the
committed file and the drift assertion can never disagree about what "the surface" means.

`main(argv)` takes two mutually exclusive flags:

- `--check`: write nothing, compare on-disk bytes to `serialize(build_surface())`, print a
  stderr message naming `make surface` and exit 1 on difference.
- `--report`: write nothing, print to stdout the three lists — module-qualified names
  **added**, **removed**, and **shape-changed** relative to the committed manifest — and
  **always exit 0**. This is the read-only early signal the in-flight plans use. It exists
  because those plans deliberately do not regenerate the manifest (see the single-owner rule
  in the objective), so a bare `--check` would fail on every one of them for a legitimate,
  documented reason. `--report` lets a plan positively assert that the names it claims to add
  actually appear, which is a stronger check than `--check` ever was.

With neither flag, write the file and print the path. Document in the module docstring that
`--report` is the mode for a plan mid-phase and `--check` is the mode for the phase gate.

Module docstring carries an explicit "Determinism recipe" section stating why the bytes are
stable (sorted keys, sorted `__all__`, two-space indent, trailing newline) and the corollary
that a Pydantic or Python bump will move the manifest — that diff is desirable and
reviewable, and the correct response is to run `make surface` and read the diff, never to
relax the check.

Add a `surface:` target to the Makefile beside the existing `openapi:` target, with the
`## `-style help comment ("Regenerate the committed public-surface manifest — the D-15
baseline") and an entry in the `.PHONY` list.

`v0.2-surface.json`, and `docs/surface-changes/`.

**The gate is documented-drift, not bare bytes-equality.** The assertion is:

1. Compute the difference between the committed manifest and `serialize(build_surface())`.
2. If there is none, pass — this is the bytes-equality case, and it is the state the tree is
   in at phase start and again after 15-21 regenerates.
3. If there is a difference, collect the set of **dotted module names** whose entry differs.
   Read every `docs/surface-changes/15-*.md` fragment as text. The test passes only if every
   drifting module name appears literally in at least one fragment; it fails, naming the
   unclaimed modules, otherwise.

Record the reasoning in the module docstring: Phase 15 runs eleven waves of plans that each
change the public surface, and the manifest is regenerated by exactly one plan at each end of
the phase (the single-owner rule — a whole-tree file cannot be concurrently regenerated
without going stale after the second merge). A gate that demanded bytes-equality throughout
would be red for the whole phase and would therefore be switched off, which is how gates die.
This formulation keeps the gate live and enforces the thing D-15 actually asks for: **drift is
permitted exactly when it is documented.** Undocumented drift — someone widening the public
surface without a fragment — is precisely the failure Success Criterion 6 exists to catch, and
it stays red. After 15-21 regenerates, nothing is unclaimed and the assertion degenerates back
to bytes-equality with no code change.

Match on literal substring of the dotted module name (e.g. `ccf.deployment.operators`) rather
than parsing the fragment. The fragment's `Surface` field is required to carry the dotted name
(Task 3), so a literal match is sufficient and cannot rot against a Markdown reformat.

Add a third test asserting the manifest is non-vacuous: it records at least 50 modules and
includes `ccf.controlplane.artifacts`, `ccf.boot`, and `ccf.products.gates` — a discovery
helper that silently found nothing is the quietest way this gate stops being one.

Record in the module docstring that the test lives in `tests/` rather than a bespoke CI job
so a surface change fails CI on the same commit that causes it, with no new CI wiring
(the reasoning transferred verbatim from `test_openapi.py:9-14`).
