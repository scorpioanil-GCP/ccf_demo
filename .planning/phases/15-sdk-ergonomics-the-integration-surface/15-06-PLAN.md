<objective>
Build the class-id → `ArtifactClass` lookup the D-05 manifest needs, as genuinely new
structure rather than a reach through an existing seam.

Purpose: the manifest declares each artifact by `path, key, class`, where `class` is a
string. `src/ccf/controlplane/artifacts.py` has **no registry of artifact classes** —
`ArtifactClass` instances are module-level constants that callers import by name
(verified negative, 15-RESEARCH.md §2.1 and re-confirmed in 15-PATTERNS.md §4). Resolving a
string to a class object is new work, and this plan does not treat it as free.

Output: `ccf.deployment.classes` with SDK coverage plus `declared_artifact_class`
fallthrough, and a sync test so a future SDK class cannot be added without becoming
manifest-addressable.
</objective>

Structure, following the `tools/lints/__main__.py::CHECKERS` shape — a hand-maintained
`dict[str, ArtifactClass]` module constant, reviewed with the code:

```
SDK_ARTIFACT_CLASSES: dict[str, ArtifactClass]
```

keyed by `class_id`, populated from the `ArtifactClass` constants exported by
`ccf.controlplane.artifacts.__all__`. Today that is `HALF_LIFE_TABLE` and `DEBT_PROFILE`;
plans 15-07 through 15-09 add seven more, and each of those plans adds its constant here.
Build the mapping by iterating the constants explicitly by name — not by scanning
`globals()` — so the mapping is a reviewed list and a new SDK class becomes a deliberate
two-line addition rather than something that appears by import accident.

Public function:

```
def resolve_artifact_class(class_id: str) -> ArtifactClass
```

Behavior: return the SDK constant when `class_id` is in `SDK_ARTIFACT_CLASSES`; otherwise
return `declared_artifact_class(class_id)`, the open-envelope path that binds the id to
`DeclaredArtifact`. The docstring states the D-01 line this encodes: the SDK owns the schema
of what it ships and never invents one for what it does not, so an unrecognized class-id is
a deployment-authored schema and gets the declared envelope — it is not an error.

Refuse an empty or whitespace-only `class_id` with a `ValueError` whose message follows the
house refuse-never-repair phrasing (statement of refusal, the property that would be lost,
who owns the fix), under 200 characters.

Export `resolve_artifact_class` and `SDK_ARTIFACT_CLASSES` from
`src/ccf/deployment/__init__.py`'s `__all__`, and extend the package docstring's `:mod:`
cross-reference list with `ccf.deployment.classes`.

The module holds no key name, no path, and no domain value — it maps SDK-owned identifiers
to SDK-owned contracts. Confirm that reading before committing; CINV-01 binds this module.

Create `tests/deployment/test_class_lookup.py` with four tests:

1. **SDK resolution by identity.** Every entry in `SDK_ARTIFACT_CLASSES` resolves to the
   same object the `artifacts` module exports — object identity, not equality, so a copy
   cannot pass.
2. **Sync with `artifacts.__all__`.** Every `ArtifactClass` instance exported from
   `ccf.controlplane.artifacts.__all__` appears in `SDK_ARTIFACT_CLASSES`. This is the test
   that makes the hand-maintained mapping safe: a future SDK artifact class cannot be added
   without becoming manifest-addressable. The failure message names `ccf/deployment/classes.py`
   as the file to edit.
3. **Declared fallthrough.** An unrecognized class-id returns an `ArtifactClass` bound to
   `DeclaredArtifact`, and parsing a document through it yields a `DeclaredArtifact` whose
   `class_id` matches.
4. **Refusal.** Empty and whitespace-only class-ids raise `ValueError`.

Module docstring carries the enforces / does-not-enforce discipline: it enforces that the
lookup covers the SDK's shipped classes and falls through cleanly; it does not enforce that
any particular class-id is *correct* for a given artifact, which is the manifest author's
decision and the closed-world contract's job to reject.
