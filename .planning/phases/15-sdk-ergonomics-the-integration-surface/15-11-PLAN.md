<objective>
Replace the 579 lines of operator-registry construction spread across nine sites with one
two-phase, view-aware call.

Purpose: D-07. This cannot be a pure artifact read — `SimilaritySelect`'s `TokenOverlapIndex`
is built from a corpus read out of the live graph at a named temporal boundary, after boot
and after ingest (`00-quickstart/run.py:249-256`). Lazy binding at first invocation was
rejected because it would build the index during projection execution, inside the algorithmic
path, over a corpus determined by when the engine happened to invoke it rather than by a
boundary the deployment named. Putting the `GraphView` in the signature makes the ordering
constraint structural rather than documented.

Per D-IMPL-76, `permitted_policy_bundle_versions` is supplied by the adopter from the pin
set — the conservative side of a permitted choice, keeping the admitted-bundle decision
visible in adopter code exactly where D-06 already puts every other pin.

Output: the builder, tests that the ordering constraint and the corpus boundary are real,
and surface-change entries.
</objective>

Create `src/ccf/deployment/operators.py`, algorithmic-tagged per module, with the
SDK-extension docstring citation.

```
def build_operator_registry(
    *,
    parameters: Mapping[str, OperatorParameters],
    view: GraphView,
    pins: ResolvedPins,
    policy_bundle_key: str,
) -> OperatorRegistry
```

`view` is a required keyword argument with no default. The ordering constraint lives in the
signature: the registry cannot be built before there is a view, and a view exists only after
boot and after ingest at a boundary the deployment named. Say that in the docstring, and say
why lazy binding was rejected — it would build the index inside the algorithmic path over a
corpus determined by invocation timing.

Two phases, in one call:

- **Phase 1, parameter-only operators.** Construct traversal, temporal, and policy operators
  directly from their parsed parameters artifacts. For the policy operator, supply
  `permitted_policy_bundle_versions` as `frozenset({pins.version_for(policy_bundle_key)})`
  — from the adopter-passed pin set, per D-IMPL-76. Do **not** resolve the version from the
  registry inside the builder; that would move the builder one step toward the fabric
  deciding what it admits. There is no `resolve_latest` call in this module.
- **Phase 2, index-backed operators.** Read the corpus out of `view` using the
  per-entity-class attribute map declared on the similarity parameters artifact (which D-03
  moved there from the ontology document), build the `TokenOverlapIndex`, and construct
  `SimilaritySelect` with the index injected. The operator never constructs its own index —
  which index a deployment ranks against is deployment configuration.

Register each operator through `OperatorRegistry.register(operator)`. **Do not pass a
category.** `register` reads category and parameter schema off the operator, and a builder
that re-introduced a caller-declared category would reopen the ordering failure INV-CH7-26
forbids. `DuplicateOperatorKey` stays fatal; do not catch it.

Which operators exist is per-deployment policy, expressed by which parameters artifacts the
`parameters` mapping contains — `examples/02-skilling` registers three, not four, and the
builder must handle that without a hardcoded set of four keys. The builder holds no operator
key name and no category name as a literal; CINV-01 binds this module.

This module must not import `ccf.products.gates`; the lint from plan 15-02 enforces it.

Export `build_operator_registry` from `ccf.deployment.__all__` and extend the package
docstring's `:mod:` list.

Create `tests/deployment/test_operator_builder.py` with six tests.

1. **Ordering constraint is structural.** `inspect.signature(build_operator_registry)`
   contains a required keyword-only `view` parameter with `Parameter.empty` as its default,
   and calling without it raises `TypeError`. This is the guard against the builder drifting
   toward lazy binding because the two-phase signature is awkward.
2. **Corpus is read at the caller's boundary.** Boot the fixture fabric, ingest, build a
   registry from a view at boundary T1, then ingest a second batch and build again from a
   view at boundary T2. Assert the two similarity indices differ, proving the corpus tracks
   the named boundary rather than invocation time.
3. **Policy pin comes from the pin set.** Build with a `ResolvedPins` whose policy version is
   a known value; assert the constructed policy operator's
   `permitted_policy_bundle_versions` is exactly that frozenset. Then build with a different
   pin value and assert it changes — proving the value is not read from the registry.
4. **Category is not caller-declared.** Assert each registered operator's category equals the
   category the operator itself reports, and that the module's source contains no `category=`
   keyword in any `register` call (AST check).
5. **Partial operator sets.** A `parameters` mapping omitting similarity builds a registry
   with no similarity operator and does not raise.
6. **Duplicate key is fatal.** Two parameters entries producing the same operator key raise
   `DuplicateOperatorKey`, uncaught.

Module docstring carries the enforces / does-not-enforce discipline: it enforces that the
builder cannot run before a view exists, that the corpus honors the caller's boundary, and
that the policy pin arrives from the adopter; it does not enforce that the deployment chose
the right boundary, nor that the corpus attribute map is semantically correct.
