Give adopters schema-assisted authoring: committed JSON Schema per artifact class, `$schema`
headers on example artifacts, an HTTP route and CLI noun to export them, and a CI freshness
gate.

Purpose: D-04. Marshalling errors are cheapest to fix while authoring, and Phase 16 gets a
shipped instance to literal-include. Per **D-IMPL-79** the CLI noun stays a `RequestSpec`
like the other eight — `main()` gets no non-`RequestSpec` branch, because the first exception
to "every command travels the same routes any client uses" is the one that makes the second
easy. The committed-schemas + regenerator + freshness-gate triad follows Phase 14's OpenAPI
pattern unchanged.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP client → schema route | A new public read-only surface over SDK model shapes |
| committed schema → adopter editor | The schema an adopter authors against |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15-12-01 | Information Disclosure | `GET /schemas` exposing model internals | accept | Schemas describe SDK-owned artifact shapes that ship in the published reference already; no tenant data, no values, no deployment configuration is reachable |
| T-15-12-02 | Tampering | a stale committed schema misleading authors | mitigate | Bytes-equality freshness gate in the always-on test job, with orphan detection |
| T-15-12-03 | Elevation of Privilege | the CLI acquiring a privileged non-route path | mitigate | D-IMPL-79: the noun returns `RequestSpec`s; a test asserts `main()` has no alternate dispatch branch |
| T-15-12-04 | Denial of Service | schema generation cost per request | accept | Read-only generation from in-process models, comparable to the existing OpenAPI endpoint |
| T-15-12-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs in this plan |
</threat_model>
