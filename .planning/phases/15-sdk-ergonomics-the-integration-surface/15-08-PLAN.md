<objective>
Give each SDK-shipped operator category a typed artifact class, so the 579 lines of
operator-registry construction repeated across nine files become artifact reads.

Purpose: D-01. `PolicyFilterParameters` and its three siblings are already `/src` code whose
own module docstring calls them "Control Plane *values* that a deployment declares, versions,
and replays against" — refusing to parse them declaratively was inconsistent rather than
principled. The docstring argument that swept them in beside policy bundles was sound for
policy bundles and over-generalized here, and it must be corrected in **both** places it
appears or the module contradicts itself.

Note the ruled constraint this plan does NOT resolve: `PolicyFilterParameters.permitted_policy_bundle_versions`
is in no artifact anywhere — it is a content hash minted at registration. Per D-IMPL-76 the
adopter passes the pin set to the D-07 builder (plan 15-11); this plan's policy artifact
class simply does not declare that field's values.

Output: four artifact classes, the two docstring amendments, round-trip coverage, and
surface-change entries.
</objective>

Define four artifact contracts in `artifacts.py`, each subclassing **both** `_VersionedArtifact`
and the existing parameters model, so the fields are inherited verbatim and the SDK never owns
a second field vocabulary for the same concept:

- `TraversalNeighborhoodParametersArtifact(_VersionedArtifact, TraversalNeighborhoodParameters)`
- `TemporalAsOfParametersArtifact(_VersionedArtifact, TemporalAsOfParameters)`
- `PolicyFilterParametersArtifact(_VersionedArtifact, PolicyFilterParameters)`
- `SimilaritySelectParametersArtifact(_VersionedArtifact, SimilaritySelectParameters)`

Define them here rather than adding `semver` to `params.py` for two reasons, both of which
belong in the docstrings: `ccf.operators` (L4) importing the Control Plane's private
`_VersionedArtifact` would invert a layer, and a subclass leaves every existing direct
construction site — tests, perf fixtures, adopter code — untouched, which D-14's additive
posture requires. Each parsed artifact **is** an instance of its parameters model, so it
passes straight to the operator constructor with no unwrapping.

Handle `PolicyFilterParametersArtifact` deliberately: `permitted_policy_bundle_versions` is
minted at registration and is in no artifact. Give the artifact contract that field a default
of `frozenset()` **only if** the model permits it without violating CINV-01b; otherwise
declare the field `frozenset[str]` and let the D-07 builder (plan 15-11) supply it via
`model_copy(update=...)` from the adopter-passed pin set. Choose one, state the choice in the
class docstring citing D-IMPL-76, and note that the deployment still names which bundles it
admits — the SDK only resolves the pin, and the adopter passes it.

Per D-03, `classification_attribute_by_class` and `similarity_corpus_attribute_by_class` are
already fields of `PolicyFilterParameters` and `SimilaritySelectParameters` respectively, so
the split lands here for free: those maps move out of the ontology document and into the
operator-parameters artifacts that actually consume them.

Add the four module-level constants with `#:` attribute comments, class ids
`ccf.operator-parameters.traversal`, `.temporal`, `.policy`, `.similarity`; add all eight new
names to `__all__` in sorted position; and register the four constants in
`SDK_ARTIFACT_CLASSES` in `src/ccf/deployment/classes.py`.

Each contract docstring cites the whitepaper section for its operator category and carries
the "no default is a value nobody chose" argument in the `params.py:14-22` voice.
