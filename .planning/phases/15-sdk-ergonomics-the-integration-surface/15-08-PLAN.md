<objective>
Give each SDK-shipped operator category a typed artifact class, so the 579 lines of
operator-registry construction repeated across nine files become artifact reads.

Purpose: D-01. `PolicyFilterParameters` and its three siblings are already `/src` code whose
own module docstring calls them "Control Plane *values* that a deployment declares, versions,
and replays against" — refusing to parse them declaratively was inconsistent rather than
principled. The docstring argument that swept them in beside policy bundles was sound for
policy bundles and over-generalized here, and it must be corrected in **both** places it
appears or the module contradicts itself.

Note the ruled constraint that shapes the policy class: `PolicyFilterParameters.permitted_policy_bundle_versions`
is in no artifact anywhere — it is a content hash minted at registration. Per D-IMPL-76 the
adopter passes the pin set to the D-07 builder (plan 15-11). `src/ccf/operators/params.py:59`
declares that field **required, with no default**, so the policy artifact cannot be a subclass
of `PolicyFilterParameters` and still parse: a subclass would either fail at parse before the
builder could inject the pin, or, if given a `frozenset()` default, would become a directly
usable parameter set that admits nothing while looking complete. Task 1 pins the third option
and this plan does not leave the choice open.

Output: four artifact classes, the two docstring amendments, round-trip coverage, and
surface-change entries.
</objective>

First define the marker base, then the four contracts.

**`OperatorParametersArtifact(VersionedArtifact)`** — an empty base carrying no fields. It
exists so the D-07 builder (plan 15-11) can type its `parameters` mapping as
`Mapping[str, OperatorParametersArtifact]` and accept all four categories by type. Without it
the builder would have to `isinstance`-filter four unrelated classes, and that idiom, copied
into adopter code to assemble the mapping, is precisely the new duplication class this phase
exists to prevent. State that reason in the base's docstring.

Then the four contracts. **Three of them subclass their existing parameters model; the policy
one deliberately does not:**

- `TraversalNeighborhoodParametersArtifact(OperatorParametersArtifact, TraversalNeighborhoodParameters)`
- `TemporalAsOfParametersArtifact(OperatorParametersArtifact, TemporalAsOfParameters)`
- `SimilaritySelectParametersArtifact(OperatorParametersArtifact, SimilaritySelectParameters)`
- `PolicyFilterParametersArtifact(OperatorParametersArtifact)` — **not** a
  `PolicyFilterParameters`

Define them here rather than adding `semver` to `params.py` for two reasons, both of which
belong in the docstrings: `ccf.operators` (L4) importing the Control Plane's versioned base
would invert a layer, and a subclass leaves every existing direct construction site — tests,
perf fixtures, adopter code — untouched, which D-14's additive posture requires. For the three
subclassing contracts, a parsed artifact **is** an instance of its parameters model and passes
straight to the operator constructor with no unwrapping.

**`PolicyFilterParametersArtifact` — the pinned shape, not a choice left open.** Declare
exactly two fields, `classification_attribute_by_class: Mapping[str, str]` and
`permitted_classifications: frozenset[str]`, copied field-for-field from
`PolicyFilterParameters` including their docstring text. Do **not** declare
`permitted_policy_bundle_versions`, do **not** give it a default, and do **not** subclass
`PolicyFilterParameters`.

The class docstring must carry the reasoning, because both rejected alternatives look
reasonable until written down. `params.py:59` declares `permitted_policy_bundle_versions`
required with no default. Subclassing and leaving it required means the artifact cannot parse
at all — the adopter has no value to author, since the value is a content hash minted at
registration (D-IMPL-76). Subclassing and defaulting it to `frozenset()` means a parsed
artifact satisfies `isinstance(x, PolicyFilterParameters)` and can be handed straight to
`PolicyFilter` by anyone who bypasses the builder — producing an operator that admits nothing
while looking fully configured, which is a silent fail-open in the other direction and exactly
the kind of value-nobody-chose `params.py:14-22` refuses. A separate, deliberately incomplete
contract makes the incompleteness *structural*: the type system says this is not an operator
parameter set, and plan 15-11's builder is the only thing that turns it into one, by
constructing a real `PolicyFilterParameters` with the version set taken from the
adopter-passed pins. Say so, cite D-IMPL-76, and note that the deployment still names which
bundles it admits — the SDK only resolves the pin, and the adopter passes it.

**D-03's two attribute maps, stated correctly.** `classification_attribute_by_class` is
already a field of `PolicyFilterParameters` (`params.py:60`), so the policy artifact simply
carries it. `similarity_corpus_attribute_by_class` is **not** a field of
`SimilaritySelectParameters` — that contract has exactly three fields, `query`,
`minimum_score_percent`, and `ranked_entity_classes` (`params.py:64-80`) — and it must not
become one: the corpus map governs `TokenOverlapIndex` *construction*, not operator
invocation, and adding it to the L4 invoke contract would put a construction-time value on the
per-invocation parameter set. Declare
`similarity_corpus_attribute_by_class: Mapping[str, str]` as an **artifact-only extra field**
on `SimilaritySelectParametersArtifact`, with a docstring stating that it exists for index
construction, is read by `build_operator_registry` before the operator is constructed, and is
deliberately absent from `SimilaritySelectParameters`. `params.py` is not edited by this plan
and `git diff` on it stays empty — an acceptance criterion below.

Add the four module-level constants with `#:` attribute comments, class ids
`ccf.operator-parameters.traversal`, `.temporal`, `.policy`, `.similarity`; add all nine new
names (the marker base, four contracts, four constants) to `__all__` in sorted position; and
register the four constants in `SDK_ARTIFACT_CLASSES` in `src/ccf/deployment/classes.py`.

Each contract docstring cites the whitepaper section for its operator category and carries
the "no default is a value nobody chose" argument in the `params.py:14-22` voice.
