# Phase 24.10 Plan 04: `R-03` — the canonical author path, measured — Summary

**`s1-01` could not adopt `GovernedResolver`.** Four seams are missing, all
four measured against a live substrate rather than inferred from signatures,
and the SDK's own canonical worked example stops at step 4 of the composition's

## The outcome, stated first, and which one it is

This was a **dual-outcome plan** and it ended in **state B — THE DIFFERENCE IS
UNBRIDGED**. `D-IMPL-283` (4), Dave, verbatim:

> *"'cannot adopt without an unruled SDK change' is an admissible **successful**
> phase outcome. The plans must not structurally force a workaround just to get
> a green completion check. That is exactly the `D-IMPL-261` lesson."*

**A verifier reading this scores it COMPLETE, not partial.** The two acts state
A would have required — weakening
`tests/examples/test_s1_01_output.py`, or adding the missing behavior to
`GovernedResolver` — are both forbidden by this plan's own action text, so a
gate admitting only state A would be a gate passable only by a violation.

The sentence of Dave's this answers, verbatim:

> *"If that works with only `R-11` plus ordinary extension points such as
> `plan_factory` and the debt scorer, then the SDK architecture is
> substantially right and `R-03` may indeed be mostly discoverability. If
> substantial parallel governance code still survives, then we have earned an
> API redesign with real evidence."*

and `debt_scorer` were both supplied and both behaved; `R-11`'s product gate
was not even reached, because `s1-01` declares no product gate and the
composition failed two steps earlier. What blocks adoption is not parallel
governance code surviving — it is that four things `s1-01` legitimately does
have **nowhere to be said** on the canonical path.

`R-03` is therefore **not mostly discoverability**. Wave 3's `24.10-F-04`
handed this row a dated data point about a Protocol nobody could find; this row
found the opposite kind of defect. The four seams below are not hard to
discover. They do not exist.

**No redesign was started.** `D-IMPL-282`: *"No broader API redesign is
authorized up front."* What these four earn is Dave's ruling.

### `24.10-F-06` — a class using one of whitepaper §7.4's four operator categories cannot be served at all

`GovernedResolver.__call__` calls `build_operator_registry` with no
`similarity_index_version`. That builder **requires** it exactly when a
similarity artifact is present, and refuses (`D-IMPL-38`: *"an unversioned
index is one that cannot be replayed against"* — the refusal is right). There
is no field on `GovernedResolver`, no argument on `build_governed_resolver`,
and the registry is built inside `__call__`, so a deployment has **nowhere** to
supply it.

Measured unbridged, against a real fabric:

```
ValueError: `parameters` carries a similarity artifact but no
similarity_index_version was supplied … (D-IMPL-38)
    raised by src/ccf/deployment/operators.py::build_operator_registry
```

**This stops adoption at step 4 of the composition's own nine**, before Π runs
and before `R-11`'s gate seam or the tolerance comparison is reached. Not an
exotic wiring: Similarity is one of the four canonical categories.

### `24.10-F-07` — the request does not seed the traversal, and `DI-15.5-07` is reproduced on the canonical path

`GovernedResolver.__call__` executes Π with no `seeds`;
`ccf.replay.engine` replays with `seeds=request_seeds(path.request)`. Two
consequences, the second worse:

1. **Two companies, one pin.** Q1 (`AcmeCorp`) and Q2 (`BetaHoldings`) pin
   identically — `dbfe8864…` for both — so an auditor asking *"which question
   did this decision answer?"* cannot tell them apart from the record. That is
   `DI-15.5-07` exactly, which `D-IMPL-111` limb (a) closed on the hand-built
   path and which `test_a_later_instant_pins_a_different_question_to_the_graph`
   was inverted to guard against.
2. **Replay divergence by construction.** Serve-time and replay-time seed by
   different rules, which `request_seeds`' own docstring names as the failure
   it exists to prevent.

**This one is an SDK correctness defect independent of `s1-01`.**
