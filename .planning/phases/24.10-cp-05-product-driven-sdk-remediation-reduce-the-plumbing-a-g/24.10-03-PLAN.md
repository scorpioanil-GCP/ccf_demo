<objective>
`R-09` — give the SDK an explicit acquisition boundary: how external source records enter CCF.

Purpose: `src/ccf/graph/backends/` ships six adapters and every one of them assumes a CCF-owned
store. There is no seam for reading somebody else's system and normalizing toward L2, so cp-04
hand-rolled SPARQL in sixteen places and cp-05 hand-rolled it again. cp-05's own words, at
`assembler.py::acquire_edges`: *"Hand-rolled because the SDK has no acquisition boundary for an
external graph store — every adapter in `ccf.graph.backends` is an L3 substrate the fabric OWNS.
Recorded as `D-IMPL-277`, open."* This row resolves `D-IMPL-277`.

Output: one Protocol, one file/fixture-backed reference implementation, and the 77/100 evidence
driven through it from a test harness that leaves cp-05 untouched.
</objective>

<the_seam_that_already_exists — read this before writing a line>
**`src/ccf/signal/source.py` already declares `SignalSourceProtocol`**, and it already emits
envelopes, tenant-scoped, with a graph handle deliberately absent. The `CP-05-SDK-CHANGE-PROPOSALS`
row for `R-09` says the current surface is *"Nothing"*; that row was written about **graph
backends** and is imprecise about L1. Do not discover this at implementation time and do not build
a duplicate.

The measured difference, and the executor must **verify it before relying on it**:
`SignalSourceProtocol.envelopes(*, tenant_id) -> AsyncIterator[SignalEnvelope]` is a **stream**
shape — asynchronous, tenant-scoped, and parameterized by nothing else. cp-05's acquisition is
synchronous and **parameterized by the question**: `walk(source, anchor_node, depth,
follow_guarantees, follow_cross_default)`. A seam that cannot be told *which anchor, to what
depth* cannot express acquisition at decision time, which is the case both cp-04 and cp-05 hit.

So the executor's **first act** is a measurement with two possible outcomes, and both are
acceptable:

- **The existing Protocol cannot express it** (expected, from the signature above). Declare the
  new seam, and make its module docstring state — in one paragraph, naming `SignalSourceProtocol`
  by module path — what that Protocol answers, what it does not, and why this is a second seam
  rather than a duplicate. Two seams with no stated difference is how a surface accumulates
  synonyms.
- **The existing Protocol does express it.** Then the smallest change is a conforming reference
  implementation plus documentation, not a new Protocol. Build that instead, and record the fact
  that the seam already existed as finding `24.10-F-NN` — *"a Protocol nobody could find is a
  different defect from a Protocol that does not exist, and `R-03` is the row that measures
  discoverability."*

Either way the deliverable set is the same: one acquisition seam, one shipped reference
implementation beside it (`CLAUDE.md` §11), and the 77/100 evidence.
</the_seam_that_already_exists>
