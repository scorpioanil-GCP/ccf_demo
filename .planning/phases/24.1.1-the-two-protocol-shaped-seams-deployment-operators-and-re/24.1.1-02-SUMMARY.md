# Phase 24.1.1 Plan 02: The Deployment-Operator Seam (`D-59`)

## What shipped

`build_operator_registry` gains **one defaulted, keyword-only parameter** —
`deployment_operators: Sequence[Operator] = ()` — whose members register FIRST, sorted by
`operator.key`, through `register(operator)` with **no category argument**.

Registering first is a decision the research left open and the docstring now records: it makes
a collision **symmetric**, so a manifest operator colliding with a deployment operator and a
deployment operator colliding with a manifest operator both raise from the manifest loop —
one failure site rather than two.

The docstring also carries two things a signature cannot: the **`D-IMPL-38` weakness** — a
deployment operator's parameters do NOT travel as a Control Plane artifact through this
channel, the instance carries them, so the replay-determinism argument rests on the caller's
artifact discipline rather than the builder's — and the **`GovernedResolver` limit**, with
`resolver.py` named as outside the `D-IMPL-214` roster and deliberately untouched.

## The sabotage that found a defect in this wave's own test

**Five sabotages were run. Four went RED as designed. The fifth went GREEN, and it was right
to.**

| # | Sabotage | Result |
| --- | --- | --- |
| 1 | delete the registration loop | **RED** — lineage and collision tests both fail |
| 2 | swallow `DuplicateOperatorKey` inside the seam's loop | **GREEN — the defect** |
| 3 | give the miscategorised test a canonical operator | **RED** — it fails to refuse |
| 4 | route the operator through a private registry instead of the seam | **RED** — `UnregisteredOperator`, the pre-`D-59` world exactly |
| 5 | sabotage 2, replayed against the owed gate | **RED** |

**Why 2 went green, and why that is a finding rather than a nuisance.** Deployment operators
register FIRST, so a deployment-vs-manifest key collision raises from the **manifest** loop —
which the sabotage did not touch. The collision test therefore asserted *"a collision is fatal
somewhere"*, not *"the seam's own registration is fatal"*. **A deployment-vs-deployment
collision would have been swallowed and nothing would have noticed.**

The plan anticipated exactly this branch — *"if it does NOT go red, a new gate is owed — say
so and write one"* — so `test_two_deployment_operators_sharing_one_key_are_fatal_in_the_seam`
was written, and sabotage 2 replayed against it goes **RED**. Two operators sharing one key is
the case only the seam can refuse.

## The AST gate was proven, not assumed

The research claimed
`tests/deployment/test_operator_builder.py::test_the_builder_passes_no_category_to_register`
— an AST walk over the whole module — covers the new `register` call for free. **Measured:**
adding `category=operator.category` to the new call turned it RED; reverting turned it GREEN.
The claim was about the tree; this is the measurement of it.

## Two plan claims that were wrong, both measured

**1 — "the drift gate goes RED without a fragment" is FALSE here.** The reshape is real and
the count is right: exactly **2** entries reshaped,
`ccf.deployment.operators.build_operator_registry` and the package re-export
`ccf.deployment.build_operator_registry`. But `tests/test_surface_drift.py` was **GREEN before
any fragment existed**, because `unclaimed_drift` treats a drifting name as claimed when *"the
name itself **or its dotted module**"* appears in any fragment — and
`docs/surface-changes/15-11-operator-builder.md`, a **Phase 15** fragment, names
`ccf.deployment.operators`.

Measured both ways: with empty claims text both entries are unclaimed; with the real fragment
text, none is. **So a phase can reshape any symbol in a module some earlier phase documented,
and the gate stays green.** That is the module-granular fallback the gate's own docstring calls
deliberate — but it means the fragment here is owed by **practice, not by the gate**. It was
written anyway. **Adjacent to the blind spot the research already named for
`ContextAssemblerProtocol`'s `(*args, **kwargs)` shape: same gate, different hole. TOOLING, and
outside the `D-IMPL-213` fence — RECORDED, not closed.**

*A first draft of the fragment was refused by `make surface-changes` for carrying `Surface:`
without the other six required fields. The assembler failed closed and named all seven.*

**2 — "twelve call sites in that module" is wrong.** Re-enumerated by AST rather than quoted:
**eleven** actual calls; `git grep` reports 13 hits because one is the import and one the
`from` line. Three different numbers for one question, which is why the plan said re-enumerate.
