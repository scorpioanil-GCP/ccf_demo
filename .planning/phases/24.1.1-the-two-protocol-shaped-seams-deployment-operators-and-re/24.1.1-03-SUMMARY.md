# Phase 24.1.1 Plan 03: A Governed Refusal Returns as Data (`D-60`)

## What shipped

`ContextAssemblerProtocol.assemble` now returns `AssemblyOutcome | ProductRequestViolation`.
`DeterministicAssembler` gains **one** optional construction field, `request_contract`, and
**one** call into `refuse_request` whose non-`None` result is RETURNED — ordered **after** the
two identity checks, because a question asked of the wrong agent is not a question about a
contract's conformity.

The boundary between the channels is now written into the code rather than left to inference:
a **governed** refusal is data and returns; an **identity** disagreement stays
`AssemblyRefused`, because it says the caller reached the wrong agent rather than that the
answer is a refusal.

## The import was measured, not inherited

The module's own `TYPE_CHECKING` comment warned that a module-level import from
`ccf.products.request` risks a cycle *"real rather than hypothetical"*. **Measured on the line
that actually shipped**, not the one the research probed:

| Subject | Modules swept | Failures |
| --- | --- | --- |
| unmodified tree (baseline) | 141 | **0** |
| the shipped `from ccf.products.request import (...)` | 141 | **0** |
| control — `from ccf.products.refusal import RefusalEnvelope` | 141 | **15** |

The control is what makes the zero a measurement rather than a sweep that was not running.
`ccf.products.request` defers its own cycle-closing import to the bottom of its module
(`D-IMPL-56`); `ccf.products.refusal` does not.

**The research's module total was wrong** — it measured 115, the tree has **141**. Its
control figure of 13 is 15 here for the same reason. Re-enumerated rather than quoted.

**The comment now describes what shipped**, with those numbers in it. A comment that survives
a change it describes is a defect, and docstring drift away from a changed line is this
project's least-reviewed surface.

## The blind spot this wave could not avoid noticing

**The single most consequential change in this phase moves ZERO manifest entries.**
`ContextAssemblerProtocol`'s recorded shape is `"(*args, **kwargs)"` — its *constructor* — so
widening a Protocol **method**'s return type is invisible to the surface gate. Measured: the
reshape list contains only the two `DeterministicAssembler` entries and the two
`build_operator_registry` entries from Wave 2.

A fix is the dumper capturing Protocol member signatures. **This phase does not do it** — it
is tooling, outside the `D-IMPL-213` fence, and `D-IMPL-214` admits no fourth file. **RECORDED
in the fragment and carried to `24.1.1-06`**, so it survives between a fragment and a SUMMARY.

Together with Wave 2's finding — `unclaimed_drift` treating a name as claimed when its *module*
appears in any fragment, so a Phase 15 fragment claimed this phase's reshape — that is **two
holes in one gate, found in one phase, both recorded and neither closed.**
