**PROVE THE SEEDER SEEDED.** A fixture that silently applied nothing would make every
assertion below run against an empty table and several of them would pass. Assert the
seeded row count is the fixture's own row count, and record the control beside it: the
same `select count(*)` with an impossible `lei` returns **0**, while the real predicate
returns N. Both numbers in the assertion message. This project has shipped four false
zeros from paths that did not exist; a count without its control is not a measurement.

**The oracle is the SELECT this example argues against**, never a number this module
authors: issue `select ... from ccf_v2.institutional_holder where lei = %s and
report_period = %s and issuer_match_band = %s and value_usd > %s order by ...` over the
same seeded rows and require the served payload to match it exactly. A count this module
wrote down would be the test agreeing with itself.

Tests to write, each named for what it proves:

1. `test_the_threshold_selects` — the payload equals the SELECT oracle, row for row.
2. `test_two_thresholds_are_two_products` — two thresholds produce two different content
   addresses. **This is what refutes the reading of a Context Product as a precalculated
   static object:** the caller's number is part of the question, so it is part of the
   product's content address.
3. `test_the_same_question_is_stable` — the same question twice is byte-identical.
4. `test_a_missing_threshold_is_refused_not_defaulted` — a request with no threshold comes
   back as a `ProductRequestViolation` with `missing-required-parameter`, as DATA, before
   anything is assembled. Not raised.
5. `test_the_assembler_seam_is_the_path` — the deployment's assembler satisfies
   `isinstance(x, ccf.agents.assembler::ContextAssemblerProtocol)`; the returned
   `AssemblyOutcome` carries the deployment's `assembler_id`/`assembler_version`, the
   `NO_CONSULTATIONS` sentinel, empty `acquisitions` and empty `skill_set_in_force`; and
   `assemble` refuses a positional call (TypeError).
6. `test_the_gate_result_is_recorded_not_assumed` — **criterion 6.** The run holds a
   `ccf.products.gates::ServableProduct`, and the refusal branch is REACHABLE: construct a
   candidate whose declared lineage differs from the engine's resolved set and assert
   `run_gates` returns a `LineageMismatchRefusal` rather than a `ServableProduct`. A
   `ServableProduct` is only evidence if the alternative can happen.
7. `test_the_payload_validates_against_the_declared_contract` — **criterion 5's second
   half.** The served product is a `ccf.products.contract::ContextProductContract`
   (`extra=forbid`), and the payload's key set matches
   `examples/cp-00-institutional-holders/artifacts/expected.yaml`'s declaration, which
   derives nothing from the run.
8. `test_the_specification_and_the_json_are_both_printed_and_both_non_empty` —
   **criterion 5's first half.** Run `consume.py` as a subprocess (or call its `main`
   with captured stdout), and assert: the specification section is non-empty and contains
   the Standard's §A–§G headings; the JSON section parses with `json.loads`; and the
   parsed JSON is non-empty. Control: assert that a run whose spec path is repointed at an
   empty file FAILS this assertion, so the non-emptiness check is not vacuous.
9. `test_debt_is_driven_by_the_declared_freshness_anchor` — D_c moves when the seeded
   `report_period` moves, proving the half-life reads the source instant rather than the
   run's.
10. `test_the_record_is_written_before_delivery` — the replay record resolves from the
    ArtifactStore at its content address and re-asks the same question.

**Note the `Decimal` round-trip trap** `s1-00` recorded and reported as an SDK finding: a

This module is criterion 2's discharge: *"every named step is proven to correspond to code
that actually runs; a step nothing executes is RED."*

`pytestmark = pytest.mark.postgres` — resolving a witness requires a completed run.

**Half one — the two declarations cannot drift.** Parse
`examples/cp-00-institutional-holders/artifacts/assembly-recipe.yaml` for its step list,
and parse the spec's §D operator step table out of
`examples/cp-00-institutional-holders/spec/CP-SPEC-000-institutional-holders.md`. Assert
the two step sets are **set-equal**, keyed on `(step, operator)`. Report both directions by
name: a step in the table with no recipe row, and a recipe row with no table entry.
**Non-vacuity precondition:** assert both parses returned a non-empty list first, with the
counts in the message — a parser that silently matched nothing would make set-equality
trivially true. Control: feed the table parser a copy of the document with §D's table
removed and assert it returns zero and the assertion FAILS.

**Half two — every witness resolves against a completed run.** Perform ONE assembly, then
for each declared step resolve its witness:

| witness | how it resolves |
|---|---|
| `operator_in_lineage: <key>` | `<key> in product.lineage.operators_invoked` |
| `entities_assembled` | the graph view the projection ran over is non-empty |
| `plan_id_matches: <id>` | `execution.plan_id == <id>` |
| `servable_product_held` | the run's gated result is a `ccf.products.gates::ServableProduct` |
| `payload_key_present: <key>` | `<key> in product.payload` |

Report an unresolved witness by STEP NUMBER and OPERATOR NAME, so a failure says which
row of §D nothing executes.

**Half three — SABOTAGE EVERY WITNESS KIND.** This is the part that makes the module
evidence rather than decoration, and it is the defect class this project has hit in eight
consecutive waves: a check that has never refused anything is a check nobody has tested.
For each of the five witness kinds, write a control that feeds the resolver a deliberately
unsatisfiable witness of that kind against the SAME completed run and asserts it goes RED
with a message naming the step. Five controls, five kinds, no exceptions. If a witness kind
is not used by this recipe, its control still runs against a synthetic step — a kind that
cannot fail is a kind that must not be in the vocabulary.

**Half four — the resolver refuses an unknown witness kind.** A step declaring a witness
outside the closed vocabulary must RAISE, not be skipped. A silently-skipped step is
criterion 2's exact failure mode wearing a green tick.

Every predicate takes its subject as an ARGUMENT — the recipe path, the spec path, the run
— so the controls exercise the real predicate against a modified copy rather than a second
description of the same intent. That is the shape
`tests/examples/test_spine_separation.py` already ships and the reason it ships it.
