## THE FINDING THAT IS DAVE'S: the SDK has no slot for `MAX_TTL`'s value

`D-43` (Dave, 2026-08-26): *"Document the Control Plane `MAX_TTL` >=
31,536,000s requirement so a default that is too short doesn't look like an
example bug."* The plan adds: *"the artifacts must be consistent with it."*

**Measured.** `ccf.controlplane.artifacts::ProductClassDeclaration` carries
`max_ttl_key` — the key the ceiling registers UNDER — and has no field for the
ceiling's seconds.

| Reading | Result |
| --- | --- |
| **FIGURE** construct it with an extra `max_ttl_seconds` | **REFUSED**, `extra_forbidden` (`model_config` is `extra='forbid', frozen=True`) |
| **CONTROL** the same construction without the extra key | **constructs cleanly** |
| Fields it does have | 15, and none of them is a TTL duration |

The reason is sound and is not a defect: **registering the value is what MINTS
its pin**, so the value cannot be a field of the document whose pin it becomes.
`ccf.deployment.config::DeploymentConfig` is `additionalProperties: false` at
the top level too, so there is no escape hatch section either.

**Consequence.** The value has to live in a deployment-owned artifact or in
code. `examples/s1-00-companies-over-revenue/deployment.py` puts its 600
seconds in code as a module constant — and **that module carries 9 numeric
literals against `produce.py`'s 0**, which is the shape criterion 7 is about.
This product's number is domain-specific in a way `s1-00`'s is not: 365 days is
the 13F amendment window, not a demo convenience.

**So a SIXTH artifact was written**, beyond the plan's five:
`examples/cp-00-institutional-holders/artifacts/ttl.yaml`, carrying
`declared_ttl_seconds` and `max_ttl_seconds`, both 31,536,000, with `D-43`'s
two-refusal distinction written into it. **Recorded as an SDK finding, NOT
closed** (`D-04`). Classified per `D-08`: **use-case agnostic** — every product
class with a declared TTL has this value, so a `max_ttl_seconds` field beside
`max_ttl_key` would be **additive** and would open no new category (`D-10`).
**It is not proposed as SDK work here.**
