threshold, LEI or numeric band as a module-level dict/list/tuple/set constant

and the lint passed it. Had I reported "the lint reaches `tests/`" on that
control, I would have reported a pass from an instrument that never fired.

**Measured, rather than concluded.** `RULE_TREE_SCOPE["no-hardcoding"]` does
include `tests`, so the scope claim is right. What is narrower than the plan's
sentence is the RULE: `tools/lints/no_hardcoding.py::_is_numeric_table` requires
**at least two values with a strict numeric majority**. A two-entry dict pairing
a threshold with a string identifier is 1 of 2 — not a majority — and never
trips. A three-numeric table does:

| Reading | rc |
| --- | --- |
| **FIGURE** the file as shipped | **0** |
| **CONTROL 1** a 2-entry dict, one int and one string | **0** — the control that did not fire |
| **CONTROL 2** a 3-entry numeric table | **1**, naming `tests/examples/test_cp_00_output.py:973` `cinv01b-numeric-table` |

**Recorded under `D-04`, classified and NOT closed.** It is a narrow blind spot,
not a hole: the rule's own docstring is about numeric *tables*, and a two-key
