## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | pytest (project pins) + hypothesis + jsonschema, Python 3.12, via `.venv/bin/python -m pytest` |
| **Config file** | `pyproject.toml` `[tool.pytest]` (`testpaths = ["tests"]`; markers `fluree`, `postgres`, … as declared there) |
| **Quick run command** | `PYTHONPATH=.:src:runtime .venv/bin/python -m pytest <file>::<test> -q -p no:cacheprovider` |
| **Full suite command** | `make ci` in chunked FOREGROUND (three chunks proven a partition of `pytest --collect-only -q \| tail -1`), plus `make leg-postgres` and `make leg-fluree` with `CCF_REQUIRE_*=1` |
| **Estimated runtime** | single test: seconds; a store leg: minutes; `make ci`: exceeds one tool call — never run it in one background job (a killed run looks exactly like a pass) |

**Both env prefixes are required.** System `python3` cannot import `ccf_runtime`.

---

## Sampling Rate

- **After every task commit:** the task's own new/affected test file(s) with the quick command; `make lint typecheck` when `src/` or `runtime/` moved.
- **After every plan wave:** `make ci-quick-suite`, `make gate-tools`, plus the store leg the wave touched (`leg-fluree` for clusters A/B; `leg-postgres` for criterion 13).
- **Before the return trip (criterion 24):** both store legs RUN on the UNCHANGED examples, before any assertion edit, with every RED recorded BY ID — the flips-in-waiting (tier-verdict reds `CPR-G05`/`FTS-G05`/`OFS-G06` once plan 07 lands; `IH-G07` under `L-24`) are expected reds that plan 16 rewrites, not regressions; `CFT-G15`, `CFT-G16` and the three must-not-flip cp-04 modules must be GREEN by name.
- **Before `/gsd:verify-work`:** `make ci` chunked with the partition proof; both legs with `CCF_REQUIRE_*=1`.
- **Max feedback latency:** 30 s for a task's own tests; a store leg per wave.
- **Accepted latency above 30 s (recorded at revision 1, 2026-09-02):** store-leg commands (`CCF_REQUIRE_*=1` legs in plans 03, 04, 09, 16, 18) and multi-directory commands (`tests/products tests/replay …`) exceed 30 s by design — the project's sampling rate accepts a store leg per wave, and the 30 s bound applies to a task's own new/affected test file(s), which every task also runs.
