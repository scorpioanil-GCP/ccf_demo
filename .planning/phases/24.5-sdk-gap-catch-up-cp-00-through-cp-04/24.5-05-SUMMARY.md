# Phase 24.5 Plan 05: The directed descendant walk — a sibling shape under `traversal`, its artifact class, every backend declining it to the oracle Summary

A DIRECTED walk is now expressible under the `traversal` category as a sibling operator key —
`traversal.typed-descendants` (`TraversalDescendants`) — whose `read_intent` sets the new
`TraversalSpec.direction = "forward"`; `"undirected"` is the default and the 1.0.x walk byte-for-byte.
Both operators run one private `_bounded_walk` and differ in exactly the line that adds the reverse
adjacency, `fallback._walk` builds that adjacency only under `"undirected"`, and all five backends
decline a directed walk to the oracle before any statement, session, pipeline or request is built —
in the same commit the field landed, so no commit on this branch can answer a directed walk
undirected. The sibling has its own parameter class, artifact class (`ccf.operator-parameters.
traversal-descendants`), dispatch arm, committed schema and inline round-trip case, landed in one
commit so the vacuity guard never went red. `OperatorCategory` is four before and after.
