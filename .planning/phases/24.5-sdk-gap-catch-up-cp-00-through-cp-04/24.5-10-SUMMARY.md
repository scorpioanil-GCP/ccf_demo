# Phase 24.5 Plan 10: L2 mints only what the envelope selects; no self-loop under any rule Summary

`AssemblyWorker.ingest` now mints a relationship claim only when the envelope selects it: a
`RelationshipResolutionRule` carrying `predicate_key` fires only when `raw_payload[predicate_key]`
equals the rule's own `relationship_type`; one carrying `subject_rule`/`object_rule` picks each
endpoint by the entity rule that resolved it (so a member-to-member edge is one edge from one
envelope); and a rule with none of the selectors keeps co-occurrence semantics but never mints a
pair whose subject and object are the same URI. Measured on the base tree with cp-04's twelve
rules: 12 relationships, 6 self-loops from one envelope; after: 6 and 0 under the same rules, 0
and 0 once the rules select their predicate. Every mint still goes through
`admit_relationship_claim`; CINV-02 lint green; `examples/` untouched.

## Deviations from Plan

**1. The plan's first test expected `len(result.relationships) == 0` under twelve *co-occurrence*
rules; the plan's own mechanism gives 6.** The plan defines the self-loop skip as
`subject.entity_uri == obj.entity_uri` and keeps co-occurrence for selector-less rules (D-10, and
this brief's rule: "a resolution rule with none of the new selector fields behaves exactly as
before"). On the cp-04 shape the node's two class projections are two URIs, so the six
anchor→member rules legitimately fire under co-occurrence — they are not self-loops by URI. Making
them vanish would need either an identity-aware skip (parsing the INV-CH7-18 URI form, and
silencing a same-identity cross-class edge for every deployment) or a wider behavior change to
selector-less rules than the ledger ruled. Neither was made. Instead: the first test asserts zero
self-loops and pins the six as the D-10 control; a second test gives criterion 16's literal
zero/zero — the twelve rules *selecting* their predicate, on the node envelope that selects none,
which is what "mints a relationship claim only when the envelope SELECTS the predicate" means for
cp-04's actual envelopes. Recorded here rather than resolved silently; if the intended reading is
that the six cross-class edges must also vanish under unchanged co-occurrence rules, that is a
ruling on selector-less semantics, not a bug fix, and it is not made in this plan.

**2. [Rule 3 — blocking] `docs/SURFACE-CHANGES.md` regenerated.** Not in the plan's `files_modified`.
`tests/test_surface_drift.py::test_the_curated_log_is_assembled_from_the_current_fragments` requires
the curated log to equal what the fragments assemble to, so the new fragment made it red;
`tools/assemble_surface_changes.py` (what `make surface-changes` runs) regenerated it. Generated,
never hand-edited.

**3. `make` not used.** The worktree has no `.venv`; every `make` target the plan names was run as
the command the Makefile runs (`tools/dump_schemas.py`, `tools.lints --all`, `mypy`, the
`ci-quick-suite` pytest line) with the brief's interpreter and PYTHONPATH.

No edit serves any id other than `24.5-L-21`. No `examples/` file was touched (measured:
`git diff --name-only 55c2fe6..HEAD -- examples .planning/STATE.md .planning/ROADMAP.md` is empty).
