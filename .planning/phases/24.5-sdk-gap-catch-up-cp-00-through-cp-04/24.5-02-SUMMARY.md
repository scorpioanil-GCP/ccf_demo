# Phase 24.5 Plan 02: The Fluree pin distinct from its floor, and the three temporal axes named — Summary

A Fluree read can now be PINNED to a transaction `t` as an upper bound — JSON-LD `from: <ledger>@t:N`
handed to the byte-identical fallback (`D-IMPL-240` (2)) — distinct from the `Fluree-Min-T` FLOOR the
Cypher route threads; proven live on `fluree/server:4.1.4` by advancing a fresh ledger between two
reads (pin at 1 → ONE entity, floor → TWO, and a raw Cypher read floored at 1 → also TWO). The pin is
typed `StoreSnapshotPin` so `GraphQuery.as_of` refuses it, `query_pinned` refuses a `datetime`/`int`
naming `D-IMPL-88`, and the three temporal axes are named as `TEMPORAL_AXES` vocabulary and in the
adapter's docstring with a test whose in-test control fails on each phrase removed.

## The captured JSON-LD envelope (the "No Analog Found" row, closed)

Measured 2026-09-02 on the local `fluree/server:4.1.4` (`/health` → `4.1.4`, `api_base_url` → `/v1/fluree`),
throwaway ledger `ccf:probe-exec-e2f406162fa9`, two commits. A pinned select

```json
{"from": "<ledger>@t:2", "@context": {},
 "select": {"?node": ["ccf_claim_id","ccf_claim_json","ccf_entity_uri","ccf_policy_bundle_version","ccf_superseded_at","ccf_superseded_by"]},
 "where": {"@id": "?node", "@type": "CcfEntityClaim", "ccf_partition": "p", "ccf_tenant_id": "t"}}
```

answers `200 application/json` with a **bare array of node objects keyed by predicate name**, an absent
predicate **absent** (not `null`):

```json
[{"ccf_claim_id":"c1","ccf_claim_json":"{\"a\":1}","ccf_entity_uri":"e://1","ccf_policy_bundle_version":"v1"},
 {"ccf_claim_id":"c2","ccf_claim_json":"{\"a\":2}","ccf_entity_uri":"e://2","ccf_policy_bundle_version":"v1","ccf_superseded_at":"2026-02-01T00:00:00Z","ccf_superseded_by":"c9"}]
```

`@t:1` → the first node only; no `from` selector → both; a tenant with nothing → `[]`; `@t:3` →
`408 {"error":"Ledger has not reached t=3, current t=2","status":408,"@type":"err:db/ReadAfterWriteTimeout"}`;
with and without `"@context": {}` the bytes are identical. `GET /ledgers` is a list of
`{"name","branch","type","t"}`.

## A measured hazard, closed on the new route (Rule 2, T-24.5-03)

On the JSON-LD route a `where` **value** beginning with `?` is read as a query **variable**: with four
claims under tenants `"?t"`, `"a:b"`, `"plain"`, `"http://x/y"`, the query `{"ccf_tenant_id": "?zzz"}`
answered all four; `{"@value": "?zzz"}` behaved the same. `"a:b"` and `"http://x/y"` bound as literals
correctly. The Cypher route binds the same value as a `$param` and is immune. `_pinned_select` refuses a
partition or tenant beginning with `?` with a `ValueError` naming the threat — fail closed, never widen. Not
in the plan; recorded in the fragment and here.
