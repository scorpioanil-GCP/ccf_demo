# 24.5-FIX-02 — WR-02: a tolerance that is not a proportion is refused by name at the boundary

## The ruling and what it excluded

Dave, 2026-09-02: *"Refuse a negative `debt_tolerance` by name at the request/class boundary. It must not
coerce every serve to 409. No new gate type (224 still one mechanism)."* Three things the ruling excludes,
each honored: the review's own sketched fix (ignore the value at the gate — silent, and the class's ceiling
then stands for a caller who said something meaningless); any change to the gate family (`run_gates`,
`effective_debt_ceiling`, `DeclaredObligationRefusal`, `REFUSAL_KINDS` — all unchanged in behavior); a
`409` reached by any path from a non-proportion.

## One judgment call, stated

The ruling says *negative*; the finding's title says *outside `[0, 1]`*. The step refuses the whole
complement of the closed unit interval — `-1`, `1.5`, `Infinity`, `NaN` — because that is the interval
`ServeObligations._ceiling_is_a_proportion` already holds the CLASS's ceiling to (`24.5-L-14`), and the
request boundary and the class boundary should read one interval, not two. A value above one was harmless
under `min` (the class stood) but it is still not a ceiling, and a boundary that refuses `-1` and honors
`1.5` would be encoding a second, unstated rule. If Dave wants *negative only*, the change is one
comparison and one parametrize row.

## Where the residual is

A direct caller of `run_gates` / `effective_debt_ceiling` that bypasses `refuse_request` can still pass
`-1` and get `min(0.5, -1) == -1`. That is the deployment's own composition (the governed resolver always
runs the boundary first — `tests/products/test_resolver_seam.py::test_the_request_refusal_leg_never_reads_the_graph`
and the AST test in `test_structural_gates.py` pin the order); the ruling put the enforcement at the
boundary, and the gate function's docstring now says so rather than re-judging the interval in a second
place. Recorded here for the D-GATE, not absorbed.
