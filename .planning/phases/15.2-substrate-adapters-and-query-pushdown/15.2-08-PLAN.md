<objective>
Land the D-IMPL-87 replay story (D-11) and the Control Plane home for the D-10
cap value: the ordered per-round-trip hash tuple in the record (dimension 5,
sentinel precedent), the full canonical query bytes in the ArtifactStore keyed
by those hashes, the cap value as deployment-manifest configuration threaded to
the engine and pinned into dimension 2, and replay verification that recomputes
the query sequence and compares hashes.

Placement decisions (recorded for the gate register):
- The query-bytes artifact class is named `ccf.graph-query` (Claude's-discretion
  item from CONTEXT). Persistence follows the ReplayWriter precedent in
  src/ccf/replay/serve.py — the store is reached at the serve seam, never from
  inside the engine, so the engine stays free of persistence collaborators.
- The cap value lives deployment-wide on the deployment manifest (the
  Claude's-discretion resolution: the manifest is versioned Control Plane
  configuration with existing schema/regeneration machinery; a
  per-product-class override can arrive later without a contract break).
  Direct boot() callers pass survivor_cap to the engine themselves — the
  manifest path is the governed route.

Output: record fields for dims 2 and 5, query-bytes persistence, manifest cap
wiring with schema regen, replay verification, and the record-compatibility
matrix covering both new fields.
</objective>
