<objective>
Enforce D-09: product classes declare which attestation modes they accept per
dimension, the engine compares the source's attestation against those minima
before the first read, and refusal is a returned value naming the failing
dimension. The attestation in force pins into replay.

Design choice made here (record in SUMMARY for the gate package): minima are
per-dimension SETS of accepted modes, not an ordered "minimum" — no strength
ordering between assembly-stamped and admission-verified is invented. The
default for classes that declare nothing is the tier-1 set
({"assembly-stamped"} / {"graph-supplied"}) — the posture every pre-attestation
class already lived under, so nothing existing changes behavior and tier-2
consumption is deny-by-default until a class opts in. Peer is a reference, not
a mode; it is pinned, not ranked.

Output: minima on ProductClassDeclaration (+ schema regen), engine refusal,
replay pin, tests.
</objective>
