    1. A module-level mount function (e.g. mount_product_source(*, admitted:
       AdmittedProduct) -> ProductSource | ProductMountRefusal) that
       validates the payload against the prose convention: a top-level
       graph_state key whose entities/relationships items model_validate
       against the existing EntityRecord/RelationshipRecord contracts. A
       payload without that shape returns ProductMountRefusal — a typed value
       deriving from GateRefusal (the AdmissionRefusal derivation style),
       carrying the product's class/tenant identifiers and a reason field
       naming what was missing or invalid. Refusal is a value; a malformed
       AdmittedProduct wrapper itself (impossible by construction) is not
       handled — the token guard already raises AdmissionBypassError.
    2. class ProductSource: constructor keyword-only, accepts ONLY the
       validated records + the admitted wrapper (constructed via the mount
       function; make the direct constructor private-by-convention with a
       docstring stating mount_product_source is the door). Implements the
       GraphReader Protocol:
       - query(q): scope-check q.tenant_id against the product's tenant
         (out-of-scope tenant returns an empty view or refuses — follow the
         prose; the SnapshotReader precedent raises on scope violation, but
         this is a source, not a replay pin: answer with the empty view for
         a non-matching tenant, and document the choice citing the
         empty-answer clause), then fallback.answer over the mounted records,
         then order/freeze via the shared interface helpers.
       - as_of(*, tenant_id, at): the degenerate-query derivation, same as
         every reader (D-07).
       - attestation property: the tier-2 well-known value —
         policy_binding="admission-verified", lineage="product-carried",
         peer=self._admitted.peer.
    3. Module docstring: SDK-defined label (CLAUDE.md §11), cites D-08 and
       whitepaper §6.6; states the ephemerality commitment — the views this
       source answers terminate in the projection, nothing enters L3, no
       write handle exists in this module; states that tier 3 arrives as
       another gate producing the same AdmittedProduct wrapper.
