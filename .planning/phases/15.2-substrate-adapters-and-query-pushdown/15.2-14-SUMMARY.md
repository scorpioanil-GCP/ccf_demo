## 3. The D-IMPL-87 RE-RATIFICATION register

*First in the register, as the resolution entry's own closing commitment
requires: "the 15.2-12 gate package re-ratifies this entry with full evidence."*
(The resolution says 15.2-12; the phase was redrawn to 14 plans after that
sentence was written, and the phase-close plan is 15.2-14. Flagged in §6.)

Each of Dave's five rulings, mapped to shipped, tested artifacts.

### (1) Mechanism — the in-query frozen field: **SHIPPED AS RULED**

`GraphQuery.allowed_entities: frozenset[str] | None`, sentinel-defaulted `None`,
on the frozen/`extra=forbid` contract (plan 15.2-04). The query stayed a pure
value: `content_hash(q)` is the per-round-trip pin, unchanged. **Hash
distinctness is proven, not assumed** — three queries identical except
`allowed_entities` = `None` / `frozenset()` / a two-element set produce three
distinct content hashes, so a capped (in-process) execution and a pushed one can
never share a pin. Determinism proven against frozenset construction order.
Adapters translate the set natively and the wire realization stayed
adapter-internal: SQL `IN` over generated placeholders, Cypher `IN $allowed` as
a driver list parameter, Mongo `$in`, fallback set-intersection.

**The rejected alternatives stayed rejected:** no substrate session state, no
per-adapter side channel — canonical ordering and serialization are still the
interface's, in exactly one place (`_ordered_view`).

### (2) Semantics — the uniform rule: **NORMATIVE, AND ENFORCED EVERYWHERE**

The uniform rule and the induced-subgraph rule are normative GQ clauses, not
implementation conventions: `GQ-15` (every family computes within the set;
seeds keep one meaning) and `GQ-16` (a relationship needs **both** endpoints
in-set). §4 of the prose cites the D-IMPL-87 resolution entry by name and says
it transcribes rather than re-decides it.

Enforced by the fallback (15.2-05, one set-intersection before any family
evaluates) and by **every** adapter, with the differential corpus deliberately
generating the resurrection shapes so the enforcement is exercised rather than
assumed: sqlite/postgres state membership three times over — entity selection,
both edge endpoints, and *inside the recursive term* (15.2-09); Cypher states it
in four predicate positions including the walk's `all(n IN nodes(p) …)` path
predicate (15.2-12); Mongo carries `to ∈ survivors` inside
`restrictSearchWithMatch`, i.e. **during** the walk (15.2-13).

**The engine authors it and no operator can:** `QueryFragment.model_fields`
contains neither `allowed_entities` nor `seeds` — structurally, an operator's
declared intent cannot widen or replace the survivor set (T-15.2-26, closed by
construction and pinned by test).

**One correction the audit had to make here.** The SUBQ-06 requirement row still
said survivors ride "as seeds + `allowed_entities`" — the reading this
resolution *rejected*. The engine does the right thing (`seeds=None,
allowed_entities=survivors`); the row did not. Fixed (§3.1 triage B1).

### (3) Soundness — `apply(full_view) == pushed(intent)`: **PROVEN PER-PLAN ON SIMILARITY-BEARING PLANS**

Plan 15.2-07's end-to-end regression proves equivalence for **both** plan shapes
— the no-Similarity one-segment plan and the Similarity-bearing multi-segment
plan — at four levels: product bytes, `operators_invoked`, provenance hashes,
and `run_gates → ServableProduct`. **Gate 2 is pinned, not presumed**, which is
the direct consequence of the re-application design choice (§4.1).

The entity-resurrection defect is closed **with evidence, not by argument**: the
corpus generates the resurrection chain (in-set seed and target, out-of-set
intermediate) and the property suite asserts the out-of-set intermediate
provably does *not* reach the target, with an admissible control leg so the test
cannot pass by the graph being empty. sqlite/postgres carry a named pushed
resurrection test; Mongo asserts the reached set is exactly `{seed}` on that
shape; Neo4j now does too (§3.3).

### (4) Scaling — the cap mechanism, Control-Plane value: **SHIPPED, DEFAULT `None`**

The mechanism ships; the value does not. `ProjectionEngine(survivor_cap=...)` is
keyword-only, defaulting `None`. Above cap the segment runs in-process — always
sound and free, because the surviving view is already in memory. **No threshold
constant exists in `/src`** (No-Hardcoding; verified by a tree-wide sweep for
numeric module-level constants — see §3.1 triage G2).

**Control-Plane home:** `DeploymentManifest.survivor_cap: int | None = None` —
the versioned, content-hashed, schema-gated document, so a cap change is a
config change with an audit trail (T-15.2-27). `load_and_boot` threads it onto
`BootedFabric.survivor_cap` — **value-threading only**, constructing no engine,
which is the D-IMPL-86 correction's boundary held exactly.

**Dimension-2 pin:** `PolicyBindingsSnapshot.survivor_cap`, sentinel-defaulted.
And `replay()` re-executes under the **recorded** cap, never the deployment's
current one — a capped decision replays the way it ran, pinned by
`test_a_capped_decision_replays_under_the_recorded_cap`.

**Set-size telemetry** (D-10's locked sub-clause) is per-execution
`last_survivor_set_sizes` on the engine — it must live there, because the
survivor set exists only at the engine and a capped segment issues no query at
all, so a reader-level report could never observe it. Report-only, outside the
replay record.

### (5) Replay pin — hash tuple in the record, bytes in the ArtifactStore: **SHIPPED, ON A FOUNDATION THAT HAD TO BE FIXED FIRST**

`ContentGenerationPath.graph_query_sequence` carries the ordered per-round-trip
`content_hash` tuple, sentinel-defaulted with `NO_GRAPH_QUERIES` as the
positive "recorded before the query seam existed" claim. Hashes are appended at
each `reader.query()` **call site**, in execution order — recorded from
execution, never minted from plan-side prediction.

Full canonical query bytes land in the ArtifactStore *before* the record append
(`QueryPinWriter`, bytes-before-append, with `QueryPinMismatch` refusing
inconsistency before any write), so a published pin always resolves. The
auditor path is tested end to end: every pin resolves to the literal query
bytes, including through `resolve_artifact` itself. Replay recomputes the
sequence and compares.

**The A5 finding this required.** Plan 15.2-08's mandatory pre-work found
`resolve_artifact` re-derived the content address from a *re-validated model*,
so any honest pre-extension record re-hashed differently and tripped the tamper
check — latent since the I.2 extension. Empirically reproduced
(`26cdaded…` put-time vs `ad21e6ab…` re-derived), ruled by Dave as **D-IMPL-89**,
and fixed to byte-fidelity verification before validation. The combined
three-extension compatibility matrix (all five historical shapes over
`graph_query_sequence` + `survivor_cap` + `source_attestation`) now holds, and
the genuinely pre-phase fixture still verifies byte-for-byte. **The sentinel
extension strategy this resolution depends on only actually delivers its
compatibility promise because of that fix.**

### (6) Versioning — prose lane only: **SHIPPED, AND EXERCISED**

`docs/GRAPH_QUERY_SEMANTICS.md` carries the semver lane in its first seven
lines; `GraphQuery` has **no version field** and evolves by additive
sentinel-defaulted fields under frozen/`extra=forbid`, with the differential
suite as the compatibility check.

The lane is no longer hypothetical: this plan shipped **1.0.1**, the first
amendment, through `GQ-35` — with an amendment history recording what changed,
why, and that it is clarifying rather than behavioral. The lane was designed at
15.2-01 and has now been used once, correctly, which is better evidence that it
works than a version number nobody has moved.

## 4. The in-phase design-choice register

One entry per mechanism choice made inside the phase, per the Phase 05
precedent. Each is Dave's to ratify or reopen.

**4.1 — Segment-answer fixed-point re-application (plan 15.2-07).** Pushed
segments' operators are **re-applied** through `cache.run` over the segment's
answer, entitled by the `GQ-19` fixed-point clause. *Rejected alternative:*
record provenance without re-applying, minting it from plan-side prediction.
That would make the provenance chain a declaration rather than a record,
violating "the engine records what ran". *Price paid, deliberately:* Gate 2
becomes PINNED rather than presumed — the regression asserts lineage strict
equality for both plan shapes. *Price paid, discovered:* this is a material part
of the read-path perf shift in §5.

**4.2 — Deployment-wide cap placement and `ccf.graph-query` naming (15.2-08).**
The cap value lives on `DeploymentManifest` (deployment-wide) rather than
per-product-class: the manifest is the versioned Control Plane document with
existing schema machinery, and a per-class override can arrive later without a
contract break. The query-bytes artifact class is `ccf.graph-query` — a
**deployment vocabulary value used in tests, never assumed by the SDK**:
`QueryPinWriter` takes `artifact_class` at construction exactly as
`ReplayWriter` does.

**4.3 — The extras-gated property-transitivity reading (15.2-06).** Always-on
params (sqlite, memory, the tier-2 mounted product) get the property subset
**directly**, against their own `reader.query()`; extras-gated adapters inherit
the properties **transitively** through differential byte-identity. Recorded for
ratification because it is a real epistemic choice. *In practice the phase
overshot it:* neo4j and mongo params also run the direct subset via
`substrate_fabric`, so coverage is stronger than the recorded reading.

**4.4 — Writer-seam entailment (15.2-02).** Generalizing `BaseGraphWriter` onto
nine typed `_GraphTxn` operations was **entailed by D-05/D-06, not discretionary**:
all five adapters run under conformance suites whose writes go through booted
L2, and a dict store, Neo4j and Mongo cannot execute SQL text. *Rejected:* five
ad-hoc per-backend SQL interpreters, each privately re-implementing the write
semantics the shared base exists to keep singular — the conformance suite could
only ever report *that* they disagreed, never which was right.

**4.5 — Materialization-core extraction (15.2-03).** `materialize_view` is
graph-tier internal API — deliberately not in `__all__`, absent from the surface
manifest — so lineage-at-boundary and supersession-as-of exist exactly once and
no adapter can fork them. `grep -rn "_supersession_as_of" src/ccf` returns
`reader.py` only. Byte-identity to the pre-refactor sqlite path was verified
against actual pre-refactor bytes, not inferred from green tests.

**4.6 — Accepted-mode-set attestation defaults and refusal placement (15.2-11).**
Acceptance is per-dimension **unordered sets**, not an ordered minimum: D-09's
word "minima" realized as accepted-mode sets, because no strength ordering
exists between `assembly-stamped` and `admission-verified` — they attest
different things, not more/less of one thing. `peer` is a reference, pinned not
ranked. Defaults are the tier-1 posture every pre-attestation class already
lived under, so **tier-2 consumption is deny-by-default** until a class opts in.
*Placement:* two layers over one comparison — a pre-execute check (earliness:
refusal before a byte moves, proven zero-query) and the `run_gates` chokepoint
(structure: `ServableProduct` is unconstructible outside it). *Rejected:*
widening `execute()` to `ExecutionResult | AttestationRefusal`, which would have
forced a match arm onto every call site for a refusal the gate path already
makes structural, breaking the phase's byte-identical-signature promise for no
added enforcement.

**4.7 — A1/A2 outcomes and `MAX_DEPTH_CEILING = 100` (15.2-12).**
**A1 VERIFIED:** `neo4j==6.2.0` speaks Bolt to server 5.26.29, confirmed by live
round trip before any code was committed to the pairing — no 5.28.x downgrade
needed. **A2 VERIFIED, and it forces an exception:** Cypher quantifier bounds
cannot be parameters — both `-[*0..$depth]-` ("Parameter maps cannot be used in
MATCH patterns") and the quantified form were probed against the live server and
both raise `CypherSyntaxError`, while the literal control parses. So exactly one
depth literal must be inlined into query text, and `MAX_DEPTH_CEILING = 100`
is the named module-level constant bounding it.

**Presented explicitly for ratification, because two of three §3.1 reviewers
called it a ground-rule violation.** The distinction the register puts to Dave:
a domain value changes *what the fabric decides*; this changes only *which code
path produces the identical answer* — an over-ceiling `depth_limit` is still
answered, by the D-04 fallback, so no query is refused and no answer moves, and
the only observable difference is telemetry, which is deliberately outside the
replay record. It is an injection-safety bound on generated query **text**, and
it is deliberately *not* Control Plane configuration for that reason — a
deployment-tunable injection surface is a stranger idea than a fixed one. The
contrast is documented on the constant itself. Dave's call.

**4.8 — A3 and the Mongo stage outcome (15.2-13): PROMOTED, WITH PROOF.**
**A3 VERIFIED before any promotion code ran:** every predicate shape the hop
filter needs is accepted inside `restrictSearchWithMatch` on live MongoDB 7.0.39
— scope equality, `$in` on relationship type, `$lte` on canonical text, the
`$or` supersession pair, entity membership, all five combined, and the shipped
shape. **No `$expr` required anywhere.** The same probe *measured* the three
documented `$graphLookup` mismatches rather than trusting the manual: the
depth off-by-one (`depth_limit=N` → `maxDepth: N-1`), the excluded starting
document (explicit seed re-inclusion required), and that an out-then-in path is
reachable only over the doubled-edge layout.

The plan budgeted stage 1 (`$match` + fallback traversal) as a legitimate
shipped posture under D-04/`GQ-34`, and **either outcome satisfies SUBQ-08**.
It was not needed: stage 2 shipped. Nothing sits behind a default-off flag and
there is no degraded tail. *Staged delivery as a risk instrument* — land the
conformant floor, commit it, then attempt the promotion against the same corpus
— is the reusable pattern here: the phase's named risk was spent as a bounded
task instead of a tail.

**4.9 — The `GQ-16` amendment and its line-neutrality discipline (this plan).**
See §3.2. The amendment itself is a design choice: closure scoped to constrained
answers, degenerate exempt, stated in the prose rather than a docstring. *The
discipline is the transferable part:* the amendment is written to leave every
clause heading where it was, because the anchored cite02 citations across `/src`
and `/tests` carry line numbers into the document — a first, naive draft that
inserted the history near the top produced **124 citation-guard findings in one

### Attribution — the shape of the data is the argument

**Every regression is the read path. The write path did not move.** Assembly
passes at both rungs (+3%, +4%) — the typed `_GraphTxn` write-seam refactor cost
essentially nothing. The transports are flat or faster. What moved is
projection, and it moved *with graph size*: 1.49× at rung 500, 3.24× at rung
1000.

Two independent numbers confirm it is one effect, not several:
`test_composed_chain` (1.21715) and `test_projection_scale[1000]` (1.22044) are
the same work through the same path and land within 0.3% of each other. And
`test_composed_ab` — a **two**-operator Similarity-bearing plan — moved only
+0.8% and passed, while the **four**-operator plan tripled: the cost is in the
segment that carries a large survivor set into a pushed traversal, not in
segmentation as such.

Replay is the cleanest evidence of all: 2.52×–2.55× **flat across three rungs
spanning 100×**. The replay ladder exists to check curve *shape*, and the shape
is preserved exactly — replay re-executes the projection, so it inherited the
projection's constant and nothing else. No new scaling term was introduced.

**Why the read path got slower at these sizes, stated plainly.** At perf-fixture
scale the whole graph fits comfortably in memory. The old path was one
everything-read plus four in-process operator applications. The new path issues
a query per pushable segment, and a Similarity-bearing plan pays an extra round
trip whose second segment carries the survivor set into a SQL recursive CTE with
a large `IN` list — then re-applies the segment's operators over the answer
(§4.1's `GQ-19` re-application, which buys execution-derived provenance and
pinned Gate 2). At **this** scale that is strictly more work than the read it
replaced. The phase's thesis is that it inverts at financial-services graph
scale, where the everything-read is the thing that does not fit; these
benchmarks do not reach that scale and were never designed to.

**The mechanism that addresses it already shipped, and its default is why the
number looks like this.** D-10's survivor cap runs an above-cap segment
in-process, which the resolution notes is "always sound and free (the surviving
view is already in memory after the in-process segment)" — precisely the case
these benchmarks are in. Its default is `None` (no cap), because an SDK-default
numeric threshold in `/src` is a domain value the No-Hardcoding rule forbids.
**So the measured regression is what an *unconfigured* deployment sees**, and a
deployment that configures a cap gets the in-process path back for exactly the
segments where pushing does not pay.
