## Pattern Assignments

### `src/ccf/graph/protocols.py` — new contracts `GraphQuery`, `TraversalSpec`, `QueryFragment`, `SourceAttestation`; `query()` + `attestation` on `GraphReader`

**Analog:** the module's own existing contracts and Protocols.

**Frozen-view contract pattern** — `GraphView` (`src/ccf/graph/protocols.py:104–123`). `GraphQuery` copies this shape: a `CCFContract` whose docstring states the invariant it serves and why it is frozen, with set-valued fields as `frozenset` (they canonicalize for free — `canonical.py:102–111` normalizes field-by-field):

```python
class GraphView(CCFContract):
    """An immutable as-of view of one tenant's graph state.
    ...
    The view is a frozen contract rather than a live cursor: an operator
    (whitepaper §7.4) is a pure function over graph state, and a state that can
    change under it is not a value it can be pure over. Records are ordered
    deterministically (entities by ``entity_uri``, relationships by
    ``relationship_key``) so canonical serialization of a view is stable.
    """

    tenant_id: str
    as_of: datetime
    entities: tuple[EntityRecord, ...] = ()
    relationships: tuple[RelationshipRecord, ...] = ()
```

**Parameter-field vocabulary** — `TraversalSpec` fields should mirror
`TraversalNeighborhoodParameters` (`src/ccf/operators/params.py:98–113`):
`seed_entity_classes: frozenset[str]`, `relationship_types: frozenset[str]`,
`depth_limit: int` — required, no defaults (D-IMPL-38 discipline stated in
that module's docstring: "A default is a value nobody chose"). D-02's field
list (tenant_id, as_of, policy_bundle_versions, entity_classes, seeds,
traverse, require_valid_at_boundary) maps 1:1 onto fields already declared in
`params.py` — `PolicyFilterParameters.permitted_policy_bundle_versions` (:59),
`TemporalAsOfParameters.require_valid_at_boundary` (:95).

**Protocol method pattern** — `GraphReader.as_of` (`protocols.py:154–170`).
`query()` copies the keyword-only discipline and the empty-answer sentence:

```python
@runtime_checkable
class GraphReader(Protocol):
    """Read-only access to graph state — the only graph handle L4+ receives.

    DESIGN.md §2A.5.2/§2A.5.3. ``tenant_id`` is keyword-only and required on
    every method (D-IMPL-05): ...
    """

    def as_of(self, *, tenant_id: str, at: datetime) -> GraphView:
        """Return the state ``tenant_id``'s graph held at observed-time ``at``.

        An empty graph yields an empty view, never an error: "nothing is known"
        is a legitimate answer that operators compose over.
        """
        ...
```

Note: `GraphQuery` carries `tenant_id` as a field (it is a value), so the
D-IMPL-05 keyword-only rule applies to `query(self, q: GraphQuery)`'s
*contract*, not its arg list — the planner should state in the docstring that
tenant scope arrives inside the frozen query value.

**Closed-Literal modes for `SourceAttestation`** — copy `OperatorCategory`
(`src/ccf/operators/base.py:58`):

```python
OperatorCategory = Literal["policy", "similarity", "temporal", "traversal"]
```

i.e. `policy_binding: Literal["assembly-stamped", "admission-verified", "none"]`
etc., on a frozen `CCFContract` so `content_hash(attestation)` pins into
replay with zero new mechanism. `PeerRef` exists at
`src/ccf/peering/protocol.py:99`.

**Module header pattern** (every touched/new graph module):
```python
__ccf_mode__ = "algorithmic"
```
(`protocols.py:43`, `reader.py:34`, `sqlite.py:58` — CINV-03 lint keys on it.)

### `src/ccf/graph/reader.py` — `query()` template method; `as_of()` derived (D-07)

**Analog:** the module itself — this is the load-bearing pattern of the phase.

**Template-method split** (`reader.py:69–95`): backend supplies dialect +
`_query()`; base owns everything above the rows.

```python
class BaseGraphReader:
    """The shared ``GraphReader`` implementation over any SQL backend.
    ...
    A concrete backend supplies the five statements below in its own dialect
    and implements :meth:`_query`. Everything else — lineage set-union
    rendering, the supersession-as-of rule, record construction, view ordering
    — is inherited, so the semantics cannot drift between substrates.
    """

    SELECT_ENTITIES_AS_OF: ClassVar[str]
    ...
    def _query(self, sql: str, params: tuple[object, ...]) -> Sequence[Row]:
        """Run one parameterized read and return its rows."""
        raise NotImplementedError
```

**The shared materialization that must stay shared** — `_lineage(boundary=...)`
(`reader.py:97–123`), `_supersession_as_of` (:125–150), `_entity_records` /
`_relationship_records` (:152–219). The module docstring (:7–15) is the
argument the planner should quote in the plan: the bitemporal read has three
places "as of" must hold and only the row filter is substrate-expressible.
Adapters answer rows; the base materializes, orders, freezes.

**`as_of()` derivation target** — current body (`reader.py:221–239`) becomes
the D-07 degenerate query. Today's shape, which `query()` generalizes:

```python
def as_of(self, *, tenant_id: str, at: datetime) -> GraphView:
    boundary = canonical_timestamp(at)
    entity_rows = self._query(
        self.SELECT_ENTITIES_AS_OF, (tenant_id, boundary, boundary)
    )
    relationship_rows = self._query(
        self.SELECT_RELATIONSHIPS_AS_OF, (tenant_id, boundary, boundary)
    )
    return GraphView(
        tenant_id=tenant_id,
        as_of=at,
        entities=self._entity_records(entity_rows, tenant_id=tenant_id, boundary=at),
        relationships=self._relationship_records(
            relationship_rows, tenant_id=tenant_id, boundary=at
        ),
    )
```

The `Row` Protocol (`reader.py:43–50`) is just `__getitem__(str)` — a dict
satisfies it, which is what lets Neo4j/Mongo/memory adapters feed the same
shared materialization without SQL.

### `src/ccf/graph/fallback.py` (NEW) — reference implementation of the semantics prose

**Analog:** `src/ccf/operators/categories.py` — the in-memory operator bodies
are the exact behaviors the fallback must reproduce over a `GraphQuery`
instead of an `Operator`.

**Undirected bounded BFS with seed inclusion** (`categories.py:326–356`):

```python
adjacency: dict[str, set[str]] = {}
for edge in traversable:
    adjacency.setdefault(edge.claim.subject_uri, set()).add(edge.claim.object_uri)
    adjacency.setdefault(edge.claim.object_uri, set()).add(edge.claim.subject_uri)

frontier = {
    record.claim.entity_uri
    for record in view.entities
    if record.claim.entity_class in params.seed_entity_classes
}
reached = set(frontier)
for _hop in range(params.depth_limit):
    frontier = {
        neighbour
        for node in frontier
        for neighbour in adjacency.get(node, ())
        if neighbour not in reached
    }
    if not frontier:
        break
    reached |= frontier
```

Note the edge semantics this encodes (the prose must state them, the fallback
must cite them): seeds are included (`reached = set(frontier)` before any
hop); `depth_limit=0` yields seeds only (the loop body never runs);
undirected (both endpoints in adjacency).

**Temporal survival predicate** (`categories.py:241–258`,
`TemporalAsOf._survives`):

```python
if observed_at > boundary:
    return False
if superseded_at is not None and superseded_at <= boundary:
    return False
if not self._parameters.require_valid_at_boundary:
    return True
if valid_from > boundary:
    return False
return valid_to is None or valid_to > boundary
```

**Policy admissibility** (`categories.py:109–118`, `PolicyFilter._admits`):

```python
if record.policy_bundle_version not in params.permitted_policy_bundle_versions:
    return False
attribute = params.classification_attribute_by_class.get(record.claim.entity_class)
if attribute is None:
    return False
return record.claim.attributes.get(attribute) in params.permitted_classifications
```

**No-leak-by-absence substitution** (`categories.py:65–87`, `_substitute`) —
the INV-CH7-40 guarantee the fallback must preserve (Pitfall 1: hop
admissibility means pruning *before* walking, as `TraversalNeighborhood`'s
docstring at :298–305 states — "an edge to a node excluded upstream is not a
hop this walk can take"):

```python
surviving = {record.claim.entity_uri for record in entities}
kept = tuple(
    edge
    for edge in relationships
    if edge.claim.subject_uri in surviving and edge.claim.object_uri in surviving
)
```

**Docstring-citation form** — cite02 anchored citations
(`tools/lints/citations.py:21–29`): a backticked anchor immediately before
`file:line`, e.g. `` `GQ-07` at docs/GRAPH_QUERY_SEMANTICS.md:41 ``. The lint

### `src/ccf/graph/backends/memory.py` (NEW) — zero-dep KV floor

**Analog:** `src/ccf/graph/backends/sqlite.py` for the store envelope;
`ccf.graph.fallback` for answering.

**Store envelope** (`sqlite.py:133–194`, `SqliteGraphStore`) — the four
members boot and the single-writer check require:

```python
class SqliteGraphStore:
    def __init__(self, *, database_path: Path | str) -> None: ...

    @property
    def graph_identity(self) -> str:
        """Stable identity of the persisted graph this store is attached to.

        The single-writer boot check keys on this: two writers over two
        different databases are two fabrics, while two writers over the same
        database are the violation.
        """
        return self._database_path

    @property
    def reader(self) -> SqliteGraphReader: ...

    def close(self) -> None: ...
    def __enter__(self) -> SqliteGraphStore: ...
    def __exit__(self, exc_type, exc, tb) -> None: ...
```

The memory store needs a synthetic but stable `graph_identity` (e.g. a
per-instance UUID minted at construction) so the boot check stays meaningful.

**Write path** — a `_Txn`-satisfying class in `ccf.graph._writer` (Pitfall 6:
conformance writes go through booted L2, so the memory backend needs writer
wiring *before* its conformance leg runs). The Protocol
(`_writer.py:205–216`):

```python
class _Txn(Protocol):
    """One open write transaction, in whichever dialect.

    ``execute`` returns the number of rows the statement actually changed —
    zero for an ignored duplicate. That number is the whole of how the writer
    distinguishes a new claim from a re-arrival ...
    """

    def execute(self, sql: str, params: tuple[object, ...]) -> int: ...
    def query(self, sql: str, params: tuple[object, ...]) -> Sequence[Row]: ...
```

and the reference implementation shape (`_writer.py:503–514`, `_SqliteTxn`):

```python
class _SqliteTxn:
    def __init__(self, connection: sqlite3.Connection) -> None:
        self._connection = connection

    def execute(self, sql: str, params: tuple[object, ...]) -> int:
        cursor = self._connection.execute(sql, params)
        return max(cursor.rowcount, 0)
```

Caveat the planner must resolve: `_Txn.execute` takes SQL text and
`BaseGraphWriter` drives nine `ClassVar` SQL statements (`_writer.py:236–249`).
A dict-backed memory backend either (a) interprets those statement constants
against dicts (ugly), or (b) the writer seam generalizes the same way the
reader seam does this phase. This is a real design point, not a copy-paste —
flag it in the plan rather than absorbing it silently.

  before Π — segmentation is internal to the operator stage and must not
  reorder around it.
- `IntermediateCache` keying survives unchanged because it keys on values

### `src/ccf/graph/backends/sqlite.py` / `postgres.py` — migration

**Analog:** their own as-of statements — extension, not rewrite. The predicate
every pushed query reuses (`sqlite.py:229–237`; `postgres.py:269` identical in
`%s` style):

```sql
SELECT entity_uri, claim_id, claim_json, policy_bundle_version,
       superseded_by, superseded_at
FROM entity_claims
WHERE tenant_id = ?
  AND observed_at <= ?
  AND (superseded_at IS NULL OR superseded_at > ?)
ORDER BY entity_uri
```

The comment style above the statements (`sqlite.py:207–210`) — a prose
justification of the bitemporal predicate citing INV-CH7-14 — is the house
style for the new recursive-CTE statements. The traversal CTE sketch is in
RESEARCH.md ("Bounded undirected traversal via recursive CTE") with hop
admissibility in the recursive term (Pitfall 1); depth is a bound parameter in
SQL — no literal inlining needed (that exception is Cypher-only).

`relationships(subject_uri, object_uri, relationship_type)` are real columns
(`sqlite.py:87–96`) — the recursive term joins on columns, no JSON parsing.
JSON-borne predicates (`valid_from`/`valid_to`, classification attributes) use
`json_extract(claim_json, '$....')` in SQLite / `claim_json::jsonb ->> ...` in
Postgres.
