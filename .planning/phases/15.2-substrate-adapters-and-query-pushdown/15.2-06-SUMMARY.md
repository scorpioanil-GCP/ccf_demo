## Accomplishments

- **The seam needs no query engine — proven, not asserted.** `MemoryGraphStore` is five per-tenant dicts mirroring the relational shape (canonical-text timestamps typed `str` in TypedDict rows); `MemoryGraphReader.query()` is the whole read path in four steps: Python row filter over canonical text (lexicographic is chronological), `materialize_view`, `fallback.answer`, `_ordered_view`. Zero third-party imports; no adjacency, no record construction, no ordering of its own (grep-verified per the acceptance criteria).
- **The typed write seam's first non-SQL implementation.** `_MemoryTxn` implements the nine `_GraphTxn` operations natively over dicts — rowcount 0 for a re-arrived claim id, chain reads sorted `(observed_at, arrival)` exactly as `ORDER BY observed_at, rowid` — and `MemoryGraphWriter` inherits the entire `BaseGraphWriter` algorithm with no SQL ClassVars. All-or-nothing comes from lazy per-tenant deepcopy snapshots restored in place on exception. Everything write-shaped is in `_writer.py` (CINV-02).

- **The differential bar exists, with the amendment's teeth in it.** The corpus generates named strategies for mixed-admissibility multi-hop paths (Pitfall 1), depth-0/1/N + absent seeds + empty answers + single families, orphans + the DI-15.2-01 dangling first-class edge, self-loops, and the `allowed_entities` shapes: the resurrection chain (in-set seed/target, out-of-set intermediate), the empty frozenset, the full universe, and allowed × each family. Every registered param is held to `canonical_bytes(reader.query(q)) == canonical_bytes(fallback-derived expected)` plus the determinism twin, per drawn case, on a fresh fabric booted per example with all writes through L2.

## Decisions Made

- **Standalone reader, not a BaseGraphReader subclass.** `BaseGraphReader` is SQL-ClassVar-shaped; the pattern map's "interprets statement constants against dicts" option was rejected as the drift-shaped ugliness the typed write seam was built to avoid. The memory reader is the third client of the reader module's shared machinery (`materialize_view`, `_ordered_view`, `_entity_records`/`_relationship_records`), so the must-have "views ONLY through the core" holds by import structure. It has no `_translate_query` hook at all — the docstring states no native translation exists or is wanted, which is the D-06 teaching point rather than a stub.
- **Rollback lives in `_writer.py`, not in the store.** A `restore` method on `MemoryGraphStore` would be a mutation entry point in a read-tier module; instead `_MemoryTxn` snapshots each tenant's state on first touch and restores in place, so every mutating line sits behind the CINV-02 lint.
- **The full-universe/None equivalence is held differentially, not asserted pairwise.** Both specs are generated in the same corpus case; each is independently held byte-identical to the fallback, which pins the equivalence transitively without a second assertion form.
- **SUBQ-08 honesty.** The plan frontmatter lists SUBQ-04 and SUBQ-08; only SUBQ-04 is marked complete. SUBQ-08 requires all five adapters — the memory leg and the suites land here, neo4j/mongo land in plans 15.2-12/-13.
