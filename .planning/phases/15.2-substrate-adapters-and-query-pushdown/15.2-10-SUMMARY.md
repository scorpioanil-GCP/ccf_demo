- **Admission is a type-system property.** `ProductSource.__init__` accepts only `AdmittedProduct` — the type `PeeringAdmissionGate.admit()` alone can produce — so an unadmitted product cannot exist at this seam; the bypass test re-pins `AdmissionBypassError` from the consumer's side (T-15.2-04). - **Mount refuses as a value, exactly where the prose says.** `mount_product_source` validates the `GQ-25` payload convention — top-level `graph_state`, `entities`/`relationships` items `model_validate`d against the existing `EntityRecord`/`RelationshipRecord` contracts — and returns a `ProductMountRefusal` (GateRefusal-derived, carrying tenant/schema identifiers and a `reason` naming the failing index/contract) for a missing key, a non-list member, an invalid item, or a foreign-tenant record. No second payload ceiling: the admission gate's Control Plane ceiling runs before an `AdmittedProduct` can exist, and the module docstring says why.
- **No query engine, provably.** `query()` is the fallback over the mounted records — its re-applied as-of predicate is the records' only temporal enforcement (`GQ-12`) and its set-intersection the only `allowed_entities` enforcement (`GQ-15`; grep-verified: the module mentions `allowed_entities` in docstrings only) — then ordering/lineage-at-boundary/supersession-as-of through `materialize_view` with a records-backed supplier, never a local re-implementation. `as_of()` is the D-07 degenerate-query derivation; a tenant-mismatched query answers the empty view with the SnapshotReader contrast cited in the docstring (`GQ-27`).

No container, no extra, no mark.

## Decisions Made

- **Fallback-then-materialize, stated and argued.** The payload's records arrive verbatim, so the as-of survival predicate must see raw `superseded_at`/`observed_at` (GQ-12) — the fallback runs first; the materialization core then renders lineage-at-boundary and supersession-as-of and owns ordering/freezing. Family predicates read only fields the rendering never touches, so evaluation order commutes and byte-identity with the live substrate holds — which the differential leg asserts directly by computing its expected view from the *source fabric*, not from the mounted records.
- **History capture is the transport shape for test payloads.** `graph_state_of` carries `entity_history`/`relationship_history` records (full lineage, intact supersession edges) rather than an as-of view — an as-of capture would drop superseded claims and blank future edges, and the mounted source could never answer an earlier boundary; the supersession-bearing as-of direct test passes on the product param precisely because of this.
- **The mounted leg reuses the identical test bodies.** `MountedProductHandle` mimics the `FabricHandle` surface (recording `.worker`, mount-at-first-`.reader`), so the direct property subset runs on the tier-2 source as one more fixture param instead of duplicated test code.
- **No runtime isinstance on `admitted`.** The plan rules the forged-wrapper case impossible by construction (the token guard raises), and `warn_unreachable = true` would flag the dead branch; conformance is witnessed statically instead.
