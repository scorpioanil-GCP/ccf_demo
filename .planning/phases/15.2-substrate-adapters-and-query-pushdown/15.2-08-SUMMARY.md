## Findings for the 15.2-14 Gate Register (per the plan's output spec)

### The A5 finding (mandatory, verified first)

**A5 was FALSE, exactly as the prior executor found and D-IMPL-89 ruled.** Before this plan, `src/ccf/replay/engine.py::resolve_artifact` re-derived the content address from a **re-validated model**: it parsed the fetched payload with the current record class and re-hashed the rebuilt model (`content_hash(artifact)`, formerly at src/ccf/replay/engine.py:235-236), raising `ReplayDivergence` on mismatch (formerly :237-242). Because canonicalization serializes sentinel-defaulted fields added by later contract versions, an honest pre-extension record re-hashed to a different address. Empirical repro, re-confirmed in this worktree before any edit: `PRE_CHANGE_CANONICAL` (tests/replay/test_harness_trace.py:52) — sha256 of the raw literal = `26cdaded112c219b…` (the put-time address), re-derived through the current model = `ad21e6abc5633f99…`. The fix landed in Task 1 per the ruling: byte-fidelity verification before validation (now src/ccf/replay/engine.py:242-256), regression-pinned by `test_the_pre_phase_fixture_record_verifies_byte_for_byte` (tests/replay/test_query_sequence_pin.py), which resolves the genuinely pre-extension literal and asserts the re-derived hash still differs — so the re-hash can never quietly return.

### The store-address-vs-content_hash finding

**The store's derived address for a stored `GraphQuery` EQUALS `content_hash(q)`.** `FileArtifactStore.put` derives the address as `content_hash(artifact)` = `sha256(canonical_bytes(artifact))` (src/ccf/artifacts/file_store.py:164-165) and stores exactly `canonical_bytes(artifact)`, so the address lane and the `name=content_hash(q)` lane coincide — either resolves a pin to its bytes. Verified empirically and pinned in `test_the_auditor_resolves_every_pin_to_the_literal_query_bytes`. No divergence case exists for conforming stores; the `name` field is redundant-but-harmless annotation that keeps the URI lane resolvable.

### The `ccf.graph-query` artifact-class naming choice

The query-bytes artifact class is **`ccf.graph-query`** — a vocabulary value used in tests (and available to examples), never assumed by the SDK: `QueryPinWriter` takes `artifact_class` at construction exactly as `ReplayWriter` does ("deployment vocabulary, supplied rather than assumed"). Persistence follows the ReplayWriter precedent at the serve seam — the engine has no persistence collaborators.

### The deployment-wide cap placement choice

The D-10 cap value lives **deployment-wide on `DeploymentManifest.survivor_cap`** (default absent = `None` = no cap): the manifest is the versioned Control Plane document with existing schema/regeneration machinery, so a cap change is a schema-gated, versioned config change with an audit trail (T-15.2-27); a per-product-class override can arrive later without a contract break. `load_and_boot` threads the value onto `BootedFabric.survivor_cap` — **value-threading only**: `load_and_boot` constructs no `ProjectionEngine` (the D-IMPL-86 correction's boundary), so the governed route ends at the boot result exactly as `tenant_id` does, and the adopter passes it to `ProjectionEngine(survivor_cap=...)`. Direct `boot()` callers pass the value to the engine themselves.

### Residual, named for the gate register

The serve seam's pin persistence is **opt-in by construction**: `serve()`'s two new parameters default to the pre-15.2-08 posture so every existing call site is byte-identical. When engaged, consistency is refused-not-repaired (`QueryPinMismatch` before any store write) and bytes land before the append. A deployment that builds records from real executions but never wires a `QueryPinWriter` produces records whose pins have no stored bytes — the same class of convention-at-the-boundary residual as the D-IMPL-86 binder placement, surfaced here rather than papered over. In-repo, the governed path is exercised by the new suite; example/adopter-guidance wiring is Phase 16 documentation scope.

## Decisions Made

- **serve-seam enforcement is opt-in-strict, not repo-wide-strict.** A hard refusal of any pinned record served without a `QueryPinWriter` would have broken every existing serve() call site (examples, crossproc servers, integration tests — none in this plan's scope) the moment `build_replay_record` started deriving pins from real executions. The additive shape keeps legacy call sites byte-identical, makes the governed path strictly checked (order + element-for-element consistency, refusal before any write), and names the residual for the gate register (above) rather than silently widening scope.
- **The replay pin comparison exempts the pre-seam sentinel.** A record carrying `NO_GRAPH_QUERIES` asserts it predates the query seam; comparing its (empty) pins against a re-execution that issues real queries would fail every pre-phase record — the exact compatibility break this plan's must-have forbids. The snapshot and product checks still bind such records to the same answer.
- **replay() threads the recorded cap, not the current one.** Without it, a capped decision (one pin) replayed under a deployment's changed cap would issue a different query count and diverge for a configuration reason — `test_a_capped_decision_replays_under_the_recorded_cap` pins the correct behavior.
