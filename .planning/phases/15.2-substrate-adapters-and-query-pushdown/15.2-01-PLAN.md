    D-01 (15.2-CONTEXT.md) locks segmented pushdown with one query per pushable
    segment and data-dependent later-segment seeds. RESEARCH Pitfall 2 shows
    that pushing a second segment after an in-process operator has materialized
    (and removed) entities is unsound under the locked D-02 vocabulary: seeds
    alone under-specify the segment-2 constraint set, so a second pushed query
    can resurrect entities an in-process operator excluded — an
    information-disclosure defect. Sound multi-segment push requires an
    allowed-node-set in the query vocabulary, which is a permanent D-02
    vocabulary commitment. The plans as written therefore implement the
    simplest sound rule: push exactly the FIRST maximal pushable prefix of the
    plan; everything after the first non-pushable operator runs in-process; the
    replay pin structure stays a sequence, so survivors-as-seeds can arrive
    later as a versioned prose amendment without a contract break. Under the
    current shipped operator set (CATEGORY_ORDER puts the three pushable
    categories ahead of Similarity), the prefix rule loses no pushdown any
    shipped plan could legally have. Per CLAUDE.md §15, an amended reading of a
    locked decision is surfaced to Dave, never silently picked — this gate is
    that surfacing, before any prose or code exists.
