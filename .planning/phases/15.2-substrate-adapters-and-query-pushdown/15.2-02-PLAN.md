<objective>
Generalize the write seam the way this phase generalizes the read seam: replace
BaseGraphWriter's direct dependence on SQL-text transactions (`_Txn.execute(sql,
params)` driving nine SQL ClassVar statements) with a typed graph-write operation
Protocol that SQL, dict, Cypher, and aggregation backends can each satisfy
natively.

This is the design point the pattern map flags for explicit decision rather than
silent absorption. The resolution is entailed, not discretionary: D-05/D-06 lock
that all five adapters run under conformance suites whose writes go through
booted L2 (RESEARCH Pitfall 6 — "nothing constructs a writer"), and neither a
dict store nor Neo4j nor Mongo can execute SQL text. Interpreting the SQL
constants per backend was considered and rejected (five ad-hoc SQL interpreters).
Record this reasoning in the module docstring and SUMMARY; per the Phase 05
precedent, in-phase discretionary mechanism choices are recorded in the phase
gate package, not as D-IMPL entries.

Purpose: unblock the memory (plan 15.2-06), Neo4j (plan 15.2-12), and Mongo
(plan 15.2-13) write paths while keeping single-writer confinement
(INV-CH7-10 / CINV-02) structurally unchanged.
Output: `_GraphTxn` typed-operation Protocol; refactored BaseGraphWriter; shared
SQL adapter; all existing tests green.
</objective>
