<domain>
## Phase Boundary

The fabric asks a substrate a *question* instead of loading its graph. Today
`GraphReader.as_of()` returns a fully materialized `GraphView` — every entity
and relationship for a tenant, per read (`src/ccf/projection/engine.py:262` is
the single call site in the execution path). This phase introduces the read
seam operators express intent against (`GraphQuery` → `GraphView`), the
adapters that answer it (SQL, Cypher, aggregation pipeline, client-side scan),
and the tier-2 path that lets an admitted Context Product serve as a queryable
source at read time.

**Tiers (Dave, 2026-08-07, at insertion):** tier 1 (storage adapters) and
tier 2 (Context Product as a source) in scope; tier 3 (raw external sources)
out of scope but must not require a refactor to add.

**Invariants preserved unchanged:** operator purity (whitepaper §7.4), as-of
correctness (INV-CH7-14), single-writer (INV-CH7-10), policy binding at
assembly time (INV-CH7-03), replay portability. This phase must not disturb
the Phase 15.1 binder and registration seams.

**Blocks Phase 16** — do not document a read surface this phase reshapes.

</domain>

<decisions>
## Implementation Decisions

### The seam: what it carries and how many times it speaks

- **D-01 (amended 2026-08-07, D-IMPL-87 resolution) — Segmented pushdown; the
  engine owns the split; post-in-process segments carry the survivor set.**
  The engine splits the operator plan at non-pushable boundaries and issues
  one substrate query per pushable segment. Round-trip count is
  plan-dependent; a later segment's seeds are data-dependent (survivors of an
  in-process segment). **The amendment closing RESEARCH Pitfall 2:** seeds
  say where walks start, not which nodes they may cross, so every pushed
  segment *after* an in-process segment additionally carries the surviving
  entity set as `allowed_entities` (see D-02), under a **uniform rule**:
  every operator family in that segment computes within the set — traversal
  may not cross outside it, filters select within it. Seeds keep exactly one
  meaning (walk starting points). This is what makes
  `apply(full_view) == pushed(intent)` provable per-plan on Similarity-bearing
  plans and closes the entity-resurrection disclosure defect. Replay pins
  **every** round trip's query (shape per D-11), not one. The conformance
  suite must pin the split itself, not only the results — and the
  differential corpus MUST include multi-segment plans (Similarity mid-plan).
- **D-02 (extended 2026-08-07) — The segment request is a frozen, typed
  `GraphQuery` contract** (tenant_id, as_of, policy_bundle_versions,
  entity_classes, seeds, traverse: `TraversalSpec`,
  require_valid_at_boundary, **allowed_entities: frozenset | None** — exact
  fields finalize against the semantics prose; `allowed_entities` is `None`
  on first segments and on every segment of a fully-pushable plan, so the
  common no-Similarity case is untouched). `GraphReader.query(q) →
  GraphView`. The question is a *value*: `content_hash(q)` is replay's
  per-round-trip pin, and canonical ordering/serialization live in the
  interface, never in adapters (locked roadmap constraint 3). Adapters
  translate `allowed_entities` natively (SQL `IN`/temp table, Cypher
  `UNWIND`, Mongo `$in`, fallback set-intersection) — the *contract* carries
  the set; the wire realization is adapter-internal. Adapters never see an
  `Operator`. Accepted cost: the query vocabulary is a fixed commitment —
  what it cannot express cannot be pushed, by anyone. The vocabulary is
  versioned through the semantics prose lane only (D-12).

### Operator shape (roadmap open question #3 — resolved)

- **D-03 — Operators declare their own pushability.** The `Operator` Protocol
  gains one optional method: `read_intent() → QueryFragment | None`, computed
  from `self.parameters` alone — no view, no data, no clock, so purity is
  untouched. `None` means not pushable; the engine materializes for that
  segment instead. `apply()` keeps its exact current signature
  (`src/ccf/operators/base.py:142`); existing operators change only by
  *gaining* `read_intent()`. `SimilaritySelect.read_intent()` returns `None`
  (it consults an injected `SimilarityIndexProtocol` the substrate does not
  hold). A user-registered custom operator becomes pushable without an SDK
  change. **Named hazard the planner must design against:** `read_intent()`
  and `apply()` diverging returns silently different rows — conformance must
  prove `apply(full_view) == apply(pushed(intent))` per shipped operator.

### Pushdown fallback

- **D-04 — Adapters always answer; there is no "I can't" in the Protocol.**
  A conformant adapter answers any well-formed `GraphQuery`, degrading
  internally to scan-and-filter. The SDK ships one reusable fallback helper
  (`ccf.graph.fallback`) so no adapter reimplements BFS. Consequence: the
  engine's split depends **only on the plan, never the substrate**, so
  round-trip count and provenance chain are identical everywhere — replay
  portability is total (rows *and* trace). What was actually pushed vs.
  scanned is telemetry, deliberately outside the replay record: performance
  is never a replay input. No capability negotiation, no typed
  pushdown-refusal path.

### Conformance (roadmap open question #2 — resolved: yes, a deliverable)

- **D-05 — Prose decides, fallback executes, adapters agree, properties audit
  the fallback.** Three artifacts:
  1. **Normative semantics prose** defining what a `GraphQuery` means —
     including deliberately-decided edge semantics (`depth_limit=0`, traversal
     through policy-excluded state, seed inclusion, empty answers). Written
     **first**, before the fallback, before any adapter. It is the court of
     appeal for disputes and the versioned surface for semantic changes.
  2. **`ccf.graph.fallback` is the reference implementation of that prose**,
     docstrings citing clauses (enforceable via the existing
     `tools/lints/citations.py` citation-guard pattern).
  3. **Two conformance suites:** differential (every adapter byte-identical to
     the fallback over a generated query corpus) *plus* property assertions
     pinning named invariants (INV-CH7-14/-23/-24/-26) — with the property
     suite running **on the fallback itself**, so the oracle is audited by
     something it does not define.
  Rationale on record: prose-as-truth keeps the fallback optimizable (it is a
  production degrade path under D-04); fallback-as-truth would freeze it.
  Client-facing: failure messages cite clauses; disputes quote sentences;
  semantic changes ship as versioned amendments, not silent oracle drift.

### Substrates (roadmap open question #1 — resolved)

- **D-06 — All five adapters ship this phase** and run under both suites:
  - `postgres.py`, `sqlite.py` — existing backends migrated to answer
    `GraphQuery` (both already hold as-of SQL; traversal via recursive CTE).
  - `memory.py` — **new** in-memory KV floor: zero dependencies, a thin shell
    over `ccf.graph.fallback`, always-on in `make ci`, and the teaching
    example of "adapter with no query engine."
  - `neo4j.py` — **new**, Cypher with variable-length MATCH, behind a
    `neo4j` extra (chromadb/`chroma`-extra precedent), container-gated CI leg.
  - `mongo.py` — **new**, `$match` + `$graphLookup`, behind an extra,
    container-gated CI leg; the Homecams triangulation point (CLAUDE.md §2.1).
  - **Named risk for the planner:** `$graphLookup` depth semantics do not
    match BFS exactly — Mongo is the hardest differential target; budget for
    it deliberately, do not let it be the phase's silent tail.

### as_of() migration (roadmap open question #3b — resolved)

- **D-07 — `as_of()` is reframed, not deprecated: it is the
  everything-question.** The semantics prose defines
  `as_of(tenant, at) ≡ query(GraphQuery(tenant_id, as_of=at))` — the
  degenerate query with no predicates. `BaseGraphReader` derives `as_of()`
  from `query()`, so adapter authors implement **one** method. The engine
  needs this case anyway: a plan whose operators all return
  `read_intent() = None` compiles to precisely this query. Zero churn across
  all 15 call sites; `src/ccf/replay/snapshots.py:108` keeps its legitimate
  everything-read; the 13 example call sites stay valid for Phase 16.

### Tier-2 read path

- **D-08 — Same seam, admitted at mount.** A `ProductSource` implements the
  same `GraphReader.query()` Protocol. Its constructor accepts **only** an
  `AdmittedProduct` — the type `PeeringAdmissionGate.admit()` alone can
  produce (`AdmissionBypassError` already enforces unconstructability) — so
  the locked constraint "admission is a seam every non-graph source passes
  through" becomes a **type-system property**, and tier 3 later means another
  gate producing the same admitted wrapper, zero refactor. `ProductSource`
  needs no query engine: the shared fallback answers over the product's
  records (tier 2 is the KV-floor pattern with governed records). The view is
  ephemeral, owned by the execution; nothing enters L3 — single-writer is not
  implicated. Products whose payload carries no graph-shaped state refuse at
  **mount** with a typed refusal. The same differential suite runs on
  `ProductSource`.

### Attestation vocabulary

- **D-09 — A typed `SourceAttestation` contract with per-dimension modes**,
  one closed Literal per provenance dimension:
  `policy_binding: assembly-stamped | admission-verified | none`;
  `lineage: graph-supplied | product-carried | none`;
  `peer: PeerRef | None`. The three tiers are three well-known **values** of
  one schema — tier 3 (`none`/`none`/`None`) is expressible today, meeting
  the no-refactor commitment by construction. `GraphReader` gains an
  `attestation` property; product classes declare per-dimension minima; the
  engine refuses a source below minimum with a typed refusal **naming the
  failing dimension**. Canonically serializable, so the attestation in force
  pins into replay. **Scoping note:** temporal correctness is *not* an
  attestation dimension — D-04 made as-of a conformance obligation every
  source owes.

### Multi-segment design (D-IMPL-87 mini-cycle, Dave, 2026-08-07)

- **D-10 — Size-cap mechanism ships; the value is Control Plane config.**
  The engine ships a survivor-set size-cap mechanism now; the threshold
  *value* lives in Control Plane configuration (mechanism-not-values,
  CLAUDE.md §11), **default `None` = no cap**. Above cap, the engine runs
  that segment in-process instead of pushing — always sound and requires no
  extra substrate read (the surviving view is already in memory
  post-in-process-segment). The split therefore depends on plan + data +
  Control Plane config, never on the substrate — cross-substrate replay
  portability holds, and the config pins into replay dimension 2. Where the
  value lives (deployment-wide config vs per-product-class profile) is
  planner discretion. Cap firings are visible in the pinned query sequence
  itself (the record shows what ran); pushed-vs-scanned telemetry (D-04)
  additionally reports set sizes.
- **D-11 — Replay pin: hash tuple in the record, query bytes in the
  ArtifactStore.** The Decision Replay record carries an ordered tuple of
  per-round-trip `content_hash` values (sentinel-defaulted field per the
  RESEARCH Pitfall 4 / workflow-trace precedent); the full canonical query
  bytes land in the ArtifactStore keyed by that hash (§7.4 — immutable,
  content-addressed, replay resolves exact versions). Replay recomputes each
  query from the pinned snapshot + plan and compares hashes — a mismatch is
  caught non-determinism; an auditor resolves the literal question from the
  store without re-running anything.
- **D-12 — Vocabulary versioning through the prose lane only.**
  `docs/GRAPH_QUERY_SEMANTICS.md` carries a semver lane from day one (v1
  includes `allowed_entities`); the `GraphQuery` contract itself carries **no
  version field** — it evolves by additive sentinel-defaulted fields under
  the existing frozen/`extra=forbid` discipline, and the differential suite
  is the compatibility check.

### Claude's Discretion

- Exact `GraphQuery` / `QueryFragment` field set and union rules across
  fragments in a segment (D-02 fixes the shape-class; fields finalize against
  the semantics prose).
- Segment-boundary mechanics: how survivors of an in-process segment become
  the next segment's `seeds` + `allowed_entities`; induced-subgraph detail
  (relationships require both endpoints in the set) — entailed by the D-01
  equivalence property, stated in the prose.
- Where the D-10 cap value lives in Control Plane (deployment-wide vs
  per-product-class), and the ArtifactStore artifact class name for D-11
  query-bytes artifacts.
- Where `neo4j.py` / `mongo.py` live (`src/ccf/graph/backends/` vs a
  runtime-side location) given the extras pattern.
- Telemetry surface shape for pushed-vs-scanned reporting (D-04), so long as
  it stays out of the replay record.
- Conformance corpus generation strategy (field-combination coverage, empty
  results, depth 0/1/N, absent seeds).

## Existing Code Insights

### Reusable Assets
- `ccf.contracts.canonical.content_hash` — already the provenance/identity
  hasher; `content_hash(GraphQuery)` gives the per-round-trip replay pin with
  zero new mechanism (D-02).
- `PeeringAdmissionGate` + `AdmittedProduct` (`src/ccf/peering/admission.py`,
  1150 LOC) — complete tier-2 governance; `ProductSource` composes it (D-08).
- Backend as-of SQL (`SELECT_ENTITIES_AS_OF` in both backends) — pushdown
  partially exists, unexposed; migration is extension, not rewrite.
- The extras pattern (`chromadb` confined to the `chroma` extra) — precedent
  for `neo4j` / `mongo` extras (D-06).
- Container-gated CI legs (D-11 Postgres-wave pattern; `live-legs.yml`
  precedent) — for the postgres/neo4j/mongo conformance legs.

### Established Patterns
- **Refusals are returned values; exceptions mean broken deployments**
  (Phase 04 decision) — attestation refusals (D-09) and mount refusals (D-08)
  follow the refusal-value convention.
- **The engine records what ran, never what was declared** (operators_invoked
  from execution) — the recorded query sequence must likewise come from
  execution, not from plan-side prediction.
- **Frozen contracts with deterministic ordering** (`GraphView` orders by
  `entity_uri`/`relationship_key`) — every adapter inherits ordering from the
  interface (locked constraint 3).
- **No clock reads below the caller** — `GraphQuery.as_of` arrives as data,
  exactly as `temporal_boundary` does today.
- **`@algorithmic` modules** (`__ccf_mode__ = "algorithmic"`) — every new
  graph/operator module carries the marker; no LLM client imports.

### Integration Points
- `src/ccf/projection/engine.py:262` — where the single materialized read
  becomes the segmented query loop; everything downstream (`IntermediateCache`
  keying, `ExecutionStep`, lineage strict-equality gate) consumes values and
  should not care.
- `tests/conformance/` — new `test_substrate_properties.py` /
  `test_substrate_differential.py` beside the existing suite.
- Replay record — gains the pinned query sequence (bytes per round trip);
  planner must place it in the existing five-dimension record without a
  contract break.

## Specific Ideas

- The client-perspective framing that settled D-05: an adapter author's
  failure message cites a numbered semantics clause, disputes are resolved by
  quoting the sentence violated, and semantic changes arrive as versioned
  amendments — "adapters : semantics-doc :: SDK : whitepaper."
- The KV floor (`memory.py`) doubles as the tier-1 teaching example: an
  adapter with no query engine is a thin shell over `ccf.graph.fallback`,
  which is also exactly what `ProductSource` is over governed records.
- Pushed-vs-scanned is telemetry so "a slow adapter is visible without making
  performance a replay input" (Dave accepted this framing under D-04).

<deferred>
## Deferred Ideas

- **Tier-3 raw external sources** (REST, lake, vector store) — explicitly out
  of scope (Dave, 2026-08-07); designed-for via D-08 (another gate, same
  admitted wrapper) and D-09 (tier 3 is a value of the existing schema).
- **Neptune/Gremlin adapter** — the roadmap narrates Gremlin as a translation
  style; not in the D-06 ship set. A future adapter proves itself against the
  D-05 suites without SDK change.
- **Similarity pushdown** — substrates with native vector search could someday
  answer similarity segments; deliberately excluded (Similarity returns
  `read_intent() = None`) because it consults an injected index (D-IMPL-03
  seam). Revisiting is its own design conversation.
- **Longer-lived intermediate caching across executions** — still deferred
  under D-IMPL-36; the segmented path keeps the per-execution cache posture.
