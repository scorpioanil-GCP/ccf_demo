<objective>
Enforce D-09: product classes declare which attestation modes they accept per
dimension, the fabric compares the source's attestation against those accepted
modes, and refusal is a returned value naming the failing dimension. The
attestation in force pins into replay dimension 1.

Placement decision (cross-AI review consensus concern 5 — decided in planning):
ProjectionEngine.execute()'s return type is NOT widened. Enforcement is
two-layer:

1. Pre-execute check (early, zero data movement): a caller-visible
   ProjectionEngine.check_source_attestation(*, product_class) ->
   AttestationRefusal | None that serving code calls before execute(), in the
   same match-composition pattern the examples already use for run_gates. It
   consults only reader.attestation (a property — no query) and the class
   declaration.
2. Gate-path enforcement (structural): the engine threads the reader's
   attestation into the replay record unconditionally; run_gates additionally
   refuses a candidate whose pinned attestation is below the class's accepted
   modes. AttestationRefusal derives from GateRefusal, so run_gates' existing
   ServableProduct | GateRefusal return union is UNCHANGED — and because
   ServableProduct is constructible only through run_gates, a
   below-accepted-modes source structurally cannot yield a servable product
   even if a caller skipped the pre-check.

Named residual (record in SUMMARY): a caller that bypasses both the pre-check
and run_gates has left the governed path entirely — the same trust model as
any user-implemented Protocol (T-15.2-11); the unconditional replay pin makes
even that path repudiation-proof.

Design choice (record in SUMMARY for the gate package): acceptance is
per-dimension SETS of accepted modes, not an ordered "minimum" — no strength
ordering between assembly-stamped and admission-verified is invented. Use the
term "accepted modes" throughout (D-09's word "minima" realized as unordered
accepted-mode sets). The default for classes that declare nothing is the
tier-1 set ({"assembly-stamped"} / {"graph-supplied"}) — the posture every
pre-attestation class already lived under, so nothing existing changes
behavior and tier-2 consumption is deny-by-default until a class opts in.
Peer is a reference, not a mode; it is pinned, not ranked.

Output: accepted modes on ProductClassDeclaration (+ schema regen), the
pre-execute check, the gate-path refusal, the dim-1 replay pin, and the
combined compatibility matrix over all three 15.2 record extensions.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| source attestation → engine admission-to-read | The gate deciding whether a source's provenance posture is acceptable for a product class |
| candidate product → ServableProduct | The structural chokepoint: run_gates is the only constructor of servability |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15.2-11 | Spoofing | A reader claiming modes it does not hold | mitigate (partial) + accept (residual) | Tier-1 value is fixed in BaseGraphReader; ProductSource's value is constructible only around an AdmittedProduct (plan 10); a bespoke user reader can still claim falsely — that residual is the same trust model as any user-implemented Protocol and is named in the SUMMARY |
| T-15.2-17 | Elevation of privilege | Tier-2 data reaching classes that never opted in | mitigate | Deny-by-default accepted modes (tier-1 defaults) at the pre-check AND the gate path — a skipped pre-check still cannot produce a ServableProduct from a below-accepted-modes pinned source |
| T-15.2-16 | Tampering | Canonical-hash break via the record extension | mitigate | Sentinel-defaulted field per the established precedent; the combined three-field matrix pins compatibility with the plan-08 fields; historical fixtures asserted unmodified |
| T-15.2-25 | Repudiation | An ungoverned caller consuming a below-accepted-modes source with no trace | mitigate | Attestation threaded into the replay record unconditionally — the read path that skipped every check still leaves its provenance posture in dimension 1 |
</threat_model>
