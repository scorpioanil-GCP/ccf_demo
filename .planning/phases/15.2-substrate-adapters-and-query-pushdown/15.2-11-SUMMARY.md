## Decisions Made

*(Recorded for the gate package per the plan's output instruction.)*

- **The placement decision.** `ProjectionEngine.execute()`'s return type is not widened. Enforcement is two-layer: the caller-visible pre-execute check (earliness — refusal before any data moves, zero queries) and the gate-path refusal at the existing `run_gates` chokepoint (structure — `ServableProduct` is constructible only through `run_gates`, so a below-accepted-modes pinned source cannot become servable regardless of caller discipline). **The rejected alternative** — widening `execute()` to `ExecutionResult | AttestationRefusal` — would have forced a match arm onto every existing call site for a refusal the gate path already makes structural, breaking the phase's byte-identical-signature promise for no additional enforcement. `AttestationRefusal` deriving from `GateRefusal` is what keeps the `run_gates` union unchanged.
- **The accepted-mode-set design choice.** Acceptance is per-dimension unordered SETS of accepted modes, not an ordered "minimum" — D-09's word "minima" realized as accepted-mode sets. No strength ordering between `assembly-stamped` and `admission-verified` is invented (they attest different things, not more/less of one thing). The default for classes that declare nothing is the tier-1 set — the posture every pre-attestation class already lived under — so nothing existing changes behavior and tier-2 is deny-by-default until a class opts in. Peer is a reference, not a mode; it is pinned, not ranked.
- **The comparison sides.** The class side rides `RegisteredProductClass` (which `run_gates` already receives); the source side arrives as the plan-anticipated keyword-only `source_attestation=None` parameter, documented in the surface fragment, because a candidate product cannot carry its source's attestation — a product does not attest its own source; the engine's execution record does.
- **The None posture.** A `None` pin passes both layers: it is a record produced before attestation existed, or an execution against a pre-phase reader. Refusing it would retroactively reclassify every pre-phase decision; admitting it leaves the unconditional dimension-1 pin to say exactly what was and was not attested.

## Named Residual (for the gate package)

**T-15.2-11 bypass residual, named per the plan:** a caller that bypasses both the pre-check and `run_gates` has left the governed path entirely — the same trust model as any user-implemented Protocol. Two facts bound it: `ServableProduct` is unconstructible outside `run_gates` (the `_GATE_TOKEN` guard), so the bypass cannot produce anything the delivery layer serves; and the unconditional replay pin means even that path leaves its provenance posture in dimension 1 — repudiation-proof (T-15.2-25 `mitigate`). The spoofing half of T-15.2-11 (a bespoke reader claiming modes it does not hold) is partially mitigated — the tier-1 value is fixed in `BaseGraphReader` and `ProductSource`'s value is constructible only around an `AdmittedProduct` (plan 15.2-10) — with the user-Protocol residual accepted as planned.
