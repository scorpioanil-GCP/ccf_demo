# Phase 15.2 Plan 02: Generalize the Write Seam to Typed Graph Operations Summary

**_GraphTxn nine-operation typed write seam replacing SQL-text transactions in BaseGraphWriter, with one shared _SqlGraphTxn adapter keeping both SQL dialects byte-identical and behavior pinned by unmodified suites**

## Accomplishments

- `_GraphTxn` Protocol added to `ccf.graph._writer`: nine keyword-only typed operations mirroring the nine dialect ClassVar statements one-for-one (four per axis — node upsert, claim append, chain select, supersession update — plus the shared lineage append). Mutating operations return rows actually changed (zero = ignored re-arrival, the writer's whole idempotency signal); the two chain selects return `Sequence[Row]` ordered by observed-time with ties by arrival order.
- `BaseGraphWriter` now drives typed operations only — zero `txn.execute(self.CLASSVAR)` calls remain. The chain restitch is parameterized over a `_SetSupersession` callable Protocol, so the one subtle late-arrival algorithm serves both axes and every backend.
- One shared `_SqlGraphTxn` adapter implements the nine operations by executing the concrete writer's dialect ClassVars through the existing `_SqliteTxn`/`_PostgresTxn`; both SQL backends' statement strings are byte-identical to before (diff shows no changes inside any SQL literal).
- D-IMPL-88 remote-substrate constraint recorded in the module docstring and per-operation contracts: the seam MUST remain implementable by a remote substrate whose commit is a single batched transaction (no held session) — no operation observes intra-transaction committed state, every rowcount is resolvable before commit, and INV-CH7-10 single-writer makes read-before-buffer sound.
- `tests/graph/test_writer_seam.py` pins the seam three ways: exact nine-member Protocol shape (guards silent widening via `__protocol_attrs__`, which collects across the MRO), rowcount-zero re-arrival regression through booted L2 (never a directly constructed writer), and an ast-walk confinement test proving no `*GraphWriter`/`*GraphTxn` class exists outside `ccf.graph._writer`.

## Entailment reasoning (for the phase gate package)

**Why the seam generalized.** D-05/D-06 lock that all five substrate adapters run under conformance suites whose writes go through booted L2 (RESEARCH Pitfall 6 — "nothing constructs a writer"). A dict store, Neo4j, and Mongo cannot execute SQL text, so the write path had to be expressible in operations those backends can satisfy natively. The resolution is entailed by decisions already ratified, not a discretionary mechanism choice.

**Why SQL-interpretation was rejected.** The considered alternative — each non-SQL backend interpreting the nine SQL statement constants — would mean five ad-hoc SQL interpreters, each a private re-implementation of the module's write semantics (content identity, lineage set-union, chain restitch). That is precisely the drift the one-algorithm/two-dialects design exists to prevent: the conformance suite could only report *that* interpreters disagreed, never which was right. Recorded per the Phase 05 precedent: in-phase entailed/discretionary mechanism reasoning goes in the gate package, not a D-IMPL entry.

## Decisions Made

- Kept the nine SQL ClassVar *declarations* on `BaseGraphWriter` (annotated as the SQL dialect surface consumed only by `_SqlGraphTxn`; non-SQL backends leave them unset) rather than introducing an intermediate SQL-writer class — minimal hierarchy churn, and nothing in the base reads them.
- `upsert_*_node` takes a single `observed_at` (the typed value the call site passes); the SQL adapter expands it to the statement's two window placeholders. Typed operations carry values, not placeholder arity.
- Confinement test allows exactly one write-shaped name outside `_writer`: the `GraphWriter` Protocol in `ccf.graph.protocols` — the D-IMPL-41 layer-1 interface split, a declaration the CINV-02 restriction protects rather than confines.
