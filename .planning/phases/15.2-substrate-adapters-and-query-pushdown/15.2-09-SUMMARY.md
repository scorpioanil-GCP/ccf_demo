## Accomplishments

- **SQLite answers questions natively.** `SqliteGraphReader._translate_query` renders one `GraphQuery` as two statements over one WITH chain (`survivors` / `edges` / `walk`) with one shared parameter tuple: the INV-CH7-14 as-of cut on the canonical-text columns (`GQ-07`), validity windows over width-normalized claim-JSON renderings (`GQ-09`), all three policy cuts with the class-admissibility OR over the declared mapping (`GQ-08`), `allowed_entities` membership on entity selection (`GQ-15`), both edge endpoints (`GQ-16`), and the reached node inside the recursive term (the resurrection defect closed in SQL), walk-start selection within survivors (`GQ-11`), depth carried as a column and bounded by a parameter, and `depth_limit=0` as the base case alone (`GQ-10`). The empty survivor set answers the empty view from the hook without a substrate round trip (`GQ-04`/`GQ-23`).
- **Postgres mirrors it in the %s dialect.** Same chain, same predicate structure, jsonb extraction (`->> 'entity_class'`, `-> 'attributes' ->> %s` with the artifact-authored key bound as data — no charset site needed, so no decline path), same GQ-anchored statement comments. Proven against a real postgres:16 container locally: pushdown twins 6/6, differential corpus leg 6/6.
- **Parameterization is total.** No value ever enters statement text: IN lists are generated `?`/`%s` repetition over sorted members; the sqlite JSON path is assembled in Python and bound whole, guarded by the ONE named charset-validation site (`_json_attribute_path`) that declines to the byte-identical fallback on any name the path cannot carry literally; depth is a bound parameter (the literal-inlining exception stays Cypher-only).
- **The differential bar holds where the defects would hide.** The 15.2-06 suite — including the resurrection chain, empty/universe allowed sets, mixed-admissibility multi-hop paths, dangling edges, self-loops — is green with the translation answering (sqlite/memory local, postgres against the container), and the new pushdown module proves the push happened: `translated_answers` incremented and `fallback_answers` unchanged on every named shape, including the pushed resurrection shape where a silently-conformant fallback would have masked an unexercised defect.

## Decisions Made

- **Translate everything, decline once.** The plan's minimum was four shapes; the compositional builder covers every well-formed query with less code than shape special-casing, and the differential corpus is the acceptance bar for all of it. The one decline (sqlite unsafe attribute name) is itself tested to land on the fallback byte-identically.
- **`GQ-09` needed a width rule to be pushable.** Claim JSON (pydantic `mode="json"`) renders `2026-03-01T08:00:00Z` while the bound canonical boundary is `...T10:00:00.000000Z` — `Z` sorts after `.`, so naive text comparison excludes every whole-second claim. `_utc_fixed_width` widens the no-fraction Z-form to `.000000Z`; non-Z renderings (offset-authored claims, legal at the contract tier) become NULL and fail every comparison — fail-closed, recorded as DI-15.2-03 for 15.2-14 to route.
- **The walk expands over the materialized crossable set.** Hop admissibility lives in the `edges` CTE (relationship_claims joined with the as-of predicate, segment validity/policy predicates, permitted types, both endpoints surviving via EXISTS against `survivors`); the recursive term joins only that set, so a path through an excluded or out-of-set node structurally does not exist AND the walk is bounded work — exactly the fallback's prune-before-walk shape rendered in SQL.
- **`AS MATERIALIZED` on both CTEs, both dialects.** Removes planner discretion (SQLite 3.35+/PG 12+, both far below the Python 3.12 floor's era): each CTE computes once per statement instead of being re-evaluated per candidate row.
