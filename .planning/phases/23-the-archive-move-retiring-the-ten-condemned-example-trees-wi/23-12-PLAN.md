  <action>
**Prove coverage BEFORE running anything.** Criterion 15 names three properties
and all three are checkable mechanically:

    .venv/bin/python -m pytest --collect-only -q > full.txt
    # per chunk:
    .venv/bin/python -m pytest <chunk-paths> --collect-only -q > chunk-N.txt

1. **Sum:** the chunks' collected counts sum to the full total. Record all four
   numbers.
2. **Set-equality:** the union of the chunk node-id sets equals the full
   collection's node-id set. Compare with `sort` + `comm` (or a small script)
   and print BOTH difference directions — a one-way subset check passes when a
   chunk collects something the full run does not, which is a different bug and
   still a bug.
3. **Pairwise disjointness:** every pair of chunk node-id sets has empty
   intersection. Print each intersection's size.

**A chunk plan whose proof is not printed did not happen.** Put the actual
command output in the summary, not a claim that it matched.

**Then run each chunk in the FOREGROUND**, with the same environment `make test`
uses (`CCF_REQUIRE_HARNESSES=1`), one at a time:

- never with `&`, never with `run_in_background`, never piped into `tail` in a
  way that hides the exit code — read exit codes with `${PIPESTATUS[0]}` or with
  no pipe
- record each chunk's full summary line: `passed`, `failed`, `errors`,
  `skipped`, `xfailed`
- sum them and compare against **4105 passed / 118 skipped**

**If the totals do not match, do not adjust anything to make them match.**
Report the difference with the offending node ids. Criterion 7 pins the number
because a moved baseline is the signal that something other than paths changed.
In particular:

- a `skipped` count above 118 means a test started skipping — plan 23-07's S-9
  finding says the pass total cannot see that, and this is the run where it
  becomes visible
- a `passed` count below 4105 with no failures means a walk narrowed and
  collection dropped; hunt the walk, never lower a floor

**SABOTAGE the chunk plan itself, watched RED before GREEN:**

| # | Mutation | Prediction | Which check should catch it |
|---|---|---|---|
| S-K1 | Drop one directory from a chunk | the sum falls short of the full total AND set-equality reports missing node ids | properties 1 and 2 |
| S-K2 | Put one directory in TWO chunks | the sum EXCEEDS the full total and pairwise disjointness reports a non-empty intersection — **the sum alone would also catch this one, but only because it over-counts; if the same directory replaced a different one the sum could still match.** Run the variant where it does | property 3 |
| S-K3 | Run a chunk in the background and let it be killed at ~10 minutes | the summary line is absent or truncated. **PREDICT: a killed run is indistinguishable from a pass if only the exit code is read.** Record the observation; it is the reason criterion 15 says FOREGROUND | recorded as a finding — do not rely on the exit code |

S-K2's second variant is the one that matters: build a chunk set that
double-counts one directory and omits another of the same size, so the SUM
still matches and only disjointness catches it. Run it and record.
