Run the single-agent code review over the shipped diff, and give it the two
things a diff-scoped review structurally cannot see:

  that became false three hundred lines from any edit. This phase moved 265

  that describe those paths are exactly the population at risk. Direct the pass
  at them explicitly.
- **the last commit is the least-reviewed one.** Include plans 23-11's and
  23-12's own writes in the subject.

**VERIFY EVERY FINDING AGAINST THE TREE BEFORE RECORDING OR ACTING ON IT, AND
RECORD THE ONES YOU REJECT AS REJECTED.** Reviewers in this project have
produced confident, well-formatted, FALSE findings — one was rejected outright
in Phase 15.1 for fabricated citations, and Phase 15.4 received a finding
asserting two lint checkers had no tests when 41 test functions existed. **An
unverified finding acted on is worse than no review.**

For each finding, record: the claim, the verification command, the observed
result, and the verdict — **confirmed**, **rejected** (with why), or
**unverifiable** (with what could not be checked). A rejected finding stays in
the record as rejected; deleting it loses the evidence that the panel produces
false positives.

**Triage every confirmed finding** as `CLAUDE.md` §3.1 requires:

- **blocking** — a violated invariant, a whitepaper-fidelity defect, a missing
  deliverable element, an unsurfaced decision, a criterion not actually
  discharged, a control that cannot fail, or a scope breach
- **advisory** — style, sequencing, deferred-scope observation

**Every blocking finding is fixed INSIDE this phase**, before Dave sees
anything. Each fix is independently re-sabotaged — a fix whose control was not
watched RED is a fix nobody has tested. Advisory findings go into the review
appendix and are carried.
