# Phase 13.2 Plan 02: serve.py Composition Shrink Summary

The hello-context example's serve.py drops all deployment-side `@server.tool` registrations and instead composes the D-IMPL-74-promoted builder: provider closures, artifact-carried descriptions, and the experience.yaml `tool_allowlist` advertising exactly the three external-consumption tools.

## What Was Built

- **`artifacts/experience.yaml`**: new `tool_allowlist` key (`[MECHANISM]`) with three `[ADAPT]` values — `get_context`, `get_lineage`, `get_replay_record` — matching the `tools` block names exactly. `agent_exposure` block retained; the allowlist (not the empty directory) is what suppresses agent-tool advertisement.
- **`serve.py`**: the three former `@server.tool` blocks are gone. `main()` now passes into `build_experience_server`: a `context_provider` closure (tenant/entity guard against `assembled.address.tenant` and `focus["entity_ref"]`, raising `ExperienceProductNotServable` on mismatch, serving via `_serve_recorded`), a `lineage_provider` (canonical lineage bytes), a `replay_record_reader` (`latest["replay_ref"]` → `store.get`, not-servable when nothing served yet), the three artifact description strings, and `tool_allowlist=frozenset(experience["tool_allowlist"])`. Concrete resource registration, auth wiring, and READY/port-0 hosting are unchanged.
