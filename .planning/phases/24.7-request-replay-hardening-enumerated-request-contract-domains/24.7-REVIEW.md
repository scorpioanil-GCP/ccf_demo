## Blocking findings

### CR-01 (BLOCKER) — Criterion 2: the default-respects-domain refusal names the parameter but not the offending default

**Criterion violated:** 2 — *"A declared default outside its parameter's enumerated domain is refused at contract construction by the existing default-respects-domain validator (`src/ccf/products/request.py::ProductRequestContract`), naming the parameter and the offending default (D-03)."*
**Where:** `src/ccf/products/request.py::ProductRequestContract._every_domain_bounds_a_declared_number_the_default_respects` — the `contradicted` comprehension at lines 723–730 collects **names only** (`sorted(name for name, domain in ... if ... domain.refuses(self.defaults[name]) is not None)`), and the message at line 741 renders `f"... {contradicted} carry a declared default outside their own domain ..."`. The default's value is never interpolated.
**Failing scenario:** an enumerated contract with `defaults={"required_leaf": "gamma"}` against members `("alpha", "beta")`.
**Evidence (probe over the test module's own fixtures, `PYTHONPATH=.:src:runtime`):**

```
validator msg names parameter: True
validator msg names default 'gamma': False
full str names 'gamma' (pydantic input echo): True
from_declared raises: ValidationError | names gamma: False
  msg names gamma: False
```

The only place `gamma` appears is pydantic's `input_value=` echo of the entire declaration dict in `str(ValidationError)`, which is not the validator naming it and is not present on `e.errors()[0]["msg"]`. The same is true through the real path `ProductRequestContract.from_declared`.
**Control that passes vacuously:** `tests/products/test_request_contract.py::test_a_default_outside_an_enumerated_domain_is_refused_at_declaration` (line 1909) asserts only the fragment `['required_leaf'] carry a declared default outside their own domain` — it never asserts the offending value, so the clause of criterion 2 it cites in its docstring ("naming the parameter") is the only clause it measures.
**Fix (message + assertion, no behavior change):**

```python
# src/ccf/products/request.py, the `contradicted` comprehension (~line 723)
contradicted = sorted(
    f"{name}={self.defaults[name]!r}"
    for name, domain in self.argument_domains.items()
    if name in self.defaults
    and name not in undeclared
    and name not in unmeasurable
    and domain.refuses(self.defaults[name]) is not None
)
```

and in the criterion-2 test add `assert "'gamma'" in str(raised.value.errors()[0]["msg"])` beside the existing fragment assertion (assert on `errors()[0]["msg"]`, not `str(raised.value)`, so pydantic's input echo cannot satisfy it). The numeric-default case (`defaults={"optional_leaf": 0}` against `minimum=1`) has the same shape and the same fix.

- **Claim-check vacuity.** Rejected by probe 10 above: refuses on both trigger classes, passes on the others.

- **`NOT_DISCOVERABLE` by equality (K2.2 adjacent).** A declaration dumped and reloaded (YAML → model → YAML) turns an absent `discovery` into a same-content one; equality keeps it unjudged, identity would have flipped it to "serves none". Equality is the round-trip-safe choice.
