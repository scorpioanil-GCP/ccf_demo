<objective>
D-11's second half: construction (plan 04) prevents new incomplete records; replay verification protects against
a FALSE not-applicable claim, and *"must use the pinned historical contract/constraint state, not today's
configuration"*. The algorithm, as Dave narrowed it (`D-IMPL-264` am.3 B-3 a): a record whose dimension-2 value is a
`ResolutionNotApplicable` marker is refused iff any of its `policy_bindings.bindings`, resolved at its EXACT pinned
version through the Control Plane, is a `ProductRequestContract` or a `PolicyConstraint` — *"request-contract pin +
applicable constraint pins are the evidence that effective-request resolution ran"* — because in `src/`+`runtime/`
those two classes reach a record's bindings only through `GovernedResolver._applied_bindings(effective)`
(RESEARCH § Measurement 7). A `ProductClassDeclaration` pin is NOT a trigger: *"Do not use 'any class declaration pin
exists' as the proxy, because the intent check can legitimately pin the class declaration before parameter
resolution occurs"* — plan 07's intent refusal pins exactly that declaration beside a `refused-before-resolution`
marker, and the boundary denials pin only the entitlement policy. A record with the marker and no contract/constraint
pin is legitimate non-applicability and replays. The legacy sentinel is exempt (F-4).

Purpose: `CP04-G-33`'s replay-time protection.
Output: `ReplayResolutionClaimMismatch`, the verification step, its tests and executed controls, the fragment.
</objective>
