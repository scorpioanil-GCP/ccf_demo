## Deviations from Plan

### Instrument corrections (recorded; no change in substance)

**1. [Plan count] "184 + 1" was the red roster, not the module roster.** Measured before marking: the twelve
modules collect 224, not 184. Module-level marking (the `D-IMPL-265` mechanism) deselects 225; the set relation
to the roster is superset-by-40, reported as such at the top of this record. No test-level scheme was invented.

**2. [Guard classifier] a third evidence kind beyond the plan's "references AND loads/spawns".** The plan's own
context required `test_demo_generator.py` and `test_ext00_fixture_schemas.py` to classify as non-runners, but
both `spec_from_file_location` a file under the archive (`generator.py`, `replay_server.py`). The classifier
therefore also requires a program entry-point target (`run.py`/`serve.py`/`producer_child.py`); the twelve all
carry one, the two helper-loaders do not.

**3. [Guard self-reference, fixed before commit] the guard classified itself as a runner** on the first run:
its `_PROSE_ONLY` control fixture spelled the joined `archive/examples/…` prefix in a non-docstring literal, and
the guard also spawns `subprocess` (for the hook test) and names the program files. Fixed by building the
fixture's prefix from `ARCHIVE_PREFIX` components (documented in the module docstring); the same control's
premise was also wrong (its only `run.py` was in a docstring, which the classifier excludes by design) — it now
carries the literal in a `git log -- run.py` argument, so it also proves the docstring exclusion.

**4. [test_smoke.py diff shape] `+10/-1` rather than `+1/-0`.** `SUITES` was one line; the `pytest.param`
form with its carry-row comment re-lays the tuple one element per line. The other three parameters are the same
bare strings; the guard's test (2) reads them as unmarked.
