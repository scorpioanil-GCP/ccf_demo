<objective>
Define the one canonical refusal envelope, in `src/`, before anything emits it.

Purpose: **D-28 (Amendment 1 §A).** Research measured that **no product door emits
a fabric refusal in any body at all** — the resolver seam is typed
`-> ServableProduct` with no refusal in the union, `refusal_response` is never
called by `routes/product.py`, and every fabric refusal type reaches no wire
(`17-RESEARCH.md` §2.3 DIV-4, §9). So spec §12.4's "freeze the shape the doors
already emit" is satisfiable for the *served* half and is **new design surface**
for the refusal half. There is nothing for a door to emit until this shape exists,
which is why it comes first and alone.

Output: `src/ccf/products/refusal.py` — one envelope type, one request-identity
type, one total translation function, and an exhaustiveness gate that fails the
day a new refusal type ships untranslated.
</objective>

  <action>
Create `src/ccf/products/refusal.py`. It defines three things and nothing else.

**`RequestIdentity(CCFContract)`** — the pre-assembly identity D-28(b) requires,
because DIV-3 measured that no door echoes it and the vessel carries no
`parameters` field at all:
  - `product_id: str` — the `schema_name` the question addressed.
  - `product_version: str | None` — the semver lane, `None` when the question named none.
  - `parameters: Mapping[str, Any]` — what the caller supplied. Empty mapping is a
    question with no parameters; it is not the same as "unknown".
  - `temporal_boundary: datetime | None` — the instant the question was asked
    against. `None` means the caller deferred to the server's decision instant, the
    `as_of=None` rule spec §2 documents on `ask()`.

**`RefusalEnvelope(CCFContract)`** — one type carrying every kind without
flattening:
  - `kind: str` — **which refusal type this was.** This member is the whole
    substance of D-28(a): if the envelope loses the kind, `Result.refusal.reason`
    becomes mush and D-09's auditable refusal dies at the seam. Values come from
    the module-level `REFUSAL_KINDS` mapping below, never from a literal at a call
    site.
  - `reason: str` — the refusal's own reason token where its type has one (the
    request/payload `Literal`s), otherwise the gate id from `GateRefusal.gate`.
  - `key: str | None` — the parameter, field or gate the refusal names, when the
    refusal names one.
  - `detail: str` — the prose the refusal already carries, unchanged.
  - `fields: Mapping[str, str]` — the refusal type's **own typed fields**,
    preserved, canonically stringified. This is what makes "without flattening"
    true rather than claimed: `LineageMismatchRefusal.declared`/`.resolved` and
    `TTLRefusal.expires_at`/`.now`/`.max_ttl_seconds` survive the crossing.
  - `request: RequestIdentity`.
  - `pre_assembly_lineage: ProductLineage | None` — `None` for a refusal that
    preceded assembly (a `ProductRequestViolation`), populated for one that
    followed it. The distinction is D-09's *"any pre-assembly lineage/context that
    existed at the point of refusal"* and it is carried, not flattened.

**`REFUSAL_KINDS: Mapping[type, str]`** — the closed translation table from refusal
type to kind token. Mechanism, not values: it maps SDK types to SDK tokens and
contains no domain vocabulary.
