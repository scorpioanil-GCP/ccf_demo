<objective>
Define the one canonical refusal envelope, in `src/`, before anything emits it.

Purpose: **D-28 (Amendment 1 §A).** Research measured that **no product door emits
a fabric refusal in any body at all** — the resolver seam is typed
`-> ServableProduct` with no refusal in the union, `refusal_response` is never
called by `routes/product.py`, and every fabric refusal type reaches no wire
(`17-RESEARCH.md` §2.3 DIV-4, §9). So spec §12.4's "freeze the shape the doors
already emit" is satisfiable for the *served* half and is **new design surface**
for the refusal half. There is nothing for a door to emit until this shape exists,
which is why it comes first and alone.

Output: `src/ccf/products/refusal.py` — one envelope type, one request-identity
type, one total translation function, and an exhaustiveness gate that fails the
day a new refusal type ships untranslated.
</objective>

**Why the peering and mount families are IN, ruled explicitly rather than
inherited.** Both derive from `GateRefusal` deliberately and both say why in their
own docstrings. `AdmissionRefusal`'s (`admission.py:267-275`): *"an inbound product
meets the fabric's gate discipline, not a second one that happens to look similar
... a caller inspecting `gate` and `detail` reads a Peering refusal exactly as it
reads a TTL refusal."* `ProductMountRefusal`'s makes the same argument citing the
same precedent. An envelope that carried the TTL refusal and dropped the admission
refusal would break precisely the property those two modules were written to
preserve, and D-28(a) forbids exactly that flattening. They are in scope and
`envelope_for` is total over them. Neither is on the client seam's own serve path
today — that is a fact about *reachability*, not about the vocabulary, and D-28(a)
is worded over the vocabulary.

Add the anti-flattening gate. **It must be import-order independent, and that is
the whole design constraint on it.**

**Why `__subclasses__()` is forbidden here.** `type.__subclasses__` reports only
classes Python has already *executed*, so its answer depends on which modules the
importer happened to touch. Measured: with only `ccf.products.gates` imported it
reports **5** `GateRefusal` subclasses; under a full-package import it reports
**12**. A gate built on it therefore yields a different verdict under
`pytest tests/products/test_refusal_envelope.py -q` than under `make ci-core` —
green in the narrow run, red (or worse, green-and-wrong) in the wide one. That is a
flaky gate, and a flaky gate is the defect class this project keeps shipping.

**Build the enumeration as an AST walk over a source root, taking the root as a
parameter.** A helper in the test module:

`discover_refusal_types(root: Path) -> dict[str, str]` — walk `root.rglob("*.py")`,
`ast.parse` each file, collect every `ast.ClassDef`, and resolve the base-name graph
*within the walk* so a class reaches `GateRefusal` transitively (this is what finds
`PayloadTooLargeRefusal`, whose immediate base is `AdmissionRefusal`). Return a
mapping of class name to `path:lineno`. Reads no imports, executes no module,
answers the same thing every time. Also collect the three `CCFContract`-based
product refusals by name — `ProductRequestViolation`, `PayloadSchemaViolation`,
`MixingRefusal` — since they are in the vocabulary but not in the `GateRefusal`
subtree, and collect every remaining `*Refusal`-named `ast.ClassDef` as the
*excluded* set.

Then three assertions, all equalities:

1. `set(discover_refusal_types(SRC_ROOT)) == {t.__name__ for t in REFUSAL_KINDS}` —
   the vocabulary is exactly what the tree declares. Equality, not containment: a
   kind declared but no longer shipped is as much a defect as a type shipped but
   untranslated.
2. `excluded == NON_PRODUCT_REFUSALS` — the allowlist is exact. A fourth
   `*Refusal` class outside the vocabulary fails here and demands a ruling.
3. A **cross-check** that the AST answer and the runtime answer agree: import every
   module `discover_refusal_types` found a refusal in, explicitly and by name, then
   walk `GateRefusal.__subclasses__()` **transitively** and assert the resulting set
   equals the AST set. This is the leg that catches a class the AST walk mis-parsed,
   and it is deterministic because the module list came from the walk rather than
   from whatever pytest happened to import.

**`GateRefusal` is itself a row, and `__subclasses__()` excludes self.** Add the
base explicitly in leg 3 and say so in a comment — this is a one-line asymmetry
that silently costs one kind if it is not handled, and W2's reconciliation is
exactly it.

4. Remove a kind from a copy of `REFUSAL_KINDS` and assert assertion 1 fails in the
