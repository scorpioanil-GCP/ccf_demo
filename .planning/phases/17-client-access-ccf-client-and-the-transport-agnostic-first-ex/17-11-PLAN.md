<objective>
Ship the SDK's reference `AssemblyDebtScorerProtocol` implementation: the thin
`GraphView` → `DebtFactors` adapter over machinery the SDK already ships.

This closes half of the CLAUDE.md §11 violation recorded in
`docs/superpowers/specs/2026-08-16-reference-plan-factory-and-debt-scorer.md`.
The other half — `ProjectionPlanFactory` — was measured impossible and ruled a
narrow exception in that spec's **Amendment A**; do not attempt it here.
</objective>

<context>
**Read the spec first**, including Amendment A. It carries the ruling, the
measurement behind it, and the boundary you must not cross.

**What already ships, measured 2026-08-16** — you are adapting, not inventing:

- `~ccf.halflife.debt.FreshnessScorer` — a reference `DebtFactorScorer` under
  `D-IMPL-47`, taking a `HalfLifeTable` and a `risk_sensitivity`
- `~ccf.halflife.debt.assess_debt` — `(factors, *, profile, scorers) -> DebtAssessment`
- `~ccf.halflife.debt.basic_debt`, `~ccf.halflife.debt.context_debt`

**What is missing** is only the adapter that turns the `GraphView` a question
assembled into the `DebtFactors` that machinery consumes.

**The Protocol's docstring argues the SDK should not do this.** It says the
choice *"is bigger than a threshold: measuring freshness over the rows a
question **read** rather than over the rows that **survived** being read gives
a different number,"* and that a resolver scoring debt itself *"would be
choosing for every deployment, which is CLAUDE.md §6.4 firing."*

**Dave ruled that this overstates the objection** (Amendment A.1): a
documented, overridable default is not a choice imposed on every deployment —
it is the definition of a reference implementation, and §11 contemplates
exactly that. **You must still honour the docstring's real point:** the choice
is genuine, so it must be *made explicitly, documented at the seam, and
overridable* — never made silently.

**The docstring is now wrong** and you own correcting it. Rewrite the
"ships no implementation" claim to name this one and state what it chooses.
</context>

<action>
Create `src/ccf/products/debt_scorer.py` with a reference implementation
conforming to `~ccf.products.resolver.AssemblyDebtScorerProtocol` — callable as
`(*, view: GraphView) -> DebtAssessment`.

It must be constructed from Control Plane material only: the half-life table
and debt profile the deployment already registered, resolved by key, plus the
scorer pins `assess_debt` records. **No threshold, no risk-sensitivity value,
no half-life figure may appear as a literal in this module** — every number
comes from an artifact. `D-IMPL-47` already rules the scorer surface (versioned
scorers, Control-Plane-updatable class bindings, replay pinning the scorer
version in force); you implement that, you do not re-decide it.

**State its row-selection choice in the class docstring, in one sentence, with
the reason** — this is the choice the Protocol docstring names. Whichever you
choose (rows the question read, or rows that survived being read), say which,
say why, and say that a deployment needing the other supplies its own scorer.
Name the observable consequence of the choice so a reader can tell whether it
matters to them.
</action>
