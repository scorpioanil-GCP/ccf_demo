<objective>
Reshape `binding.yaml` into a **data-only** document carrying exactly one
permitted `module:attribute` reference — the projection — and make the loader
refuse any second one **by name**.

This discharges Amendment A.3 and A.4 of
`docs/superpowers/specs/2026-08-16-reference-plan-factory-and-debt-scorer.md`,
and rewrites the rejected `D-IMPL-141` entry to record what was actually ruled.
</objective>

<context>
**Read the spec, including Amendment A.** `D-IMPL-141` as originally proposed —
`resolver:` and `question:` as `module:attribute` factories — was **rejected by
Dave** because it reintroduces producer Python into `deployment/`, the shape
declined at the 2026-08-15 brainstorm.

**Measurement dissolved most of the argument for it** (spec §3): `Perspective`
is two plain strings; `subject`, `intent` and `freshness` are plain `str`;
`asked_at` the SDK already owns through `as_of`. So the request vocabulary and
the perspective are **data**, not factories.

**One exception survives, and only one** (Amendment A.2): `ProjectionPlan` is
itself a Protocol — code, not data — and no declarative plan artifact exists.
Mapping a `GraphView` of entities onto declared payload fields is *invention*,
not mapping. So the deployment supplies the projection, and nothing else.

**The load-bearing sentence in the amendment, and the reason this plan exists
rather than just editing a fixture:**

> *An exception with no mechanism holding it narrow is not an exception; it is
> a precedent.*

Your loader is that mechanism.

**What survives from the original proposal, and should be kept:** `binding.yaml`
is **deployment-environment material, never a Control Plane artifact** — not
registered, not content-hashed, carrying no `semver`, never reaching Decision
Replay dimension 2. The strict loader refuses an unknown top-level key **by
name**. Path containment refuses an absolute path, a `..` segment, and a plain
name resolving outside the root — the two-check rule
`~ccf.controlplane.artifacts.ManifestEntry` already holds a manifest to.
</context>

<task id="1">
<action>
Reshape the document schema in
`src/ccf/client/adapters/binding_document.py`.

**Permitted keys — data:**
`config` (path to `ccf_config.yaml`, relative to root); `question` (a mapping
carrying `subject`, `intent`, `freshness` — all plain strings); `perspective`
(a mapping carrying `principal_id`, `role`); and the eight resolver data keys
(`product_class_key`, `request_contract_key`, `operator_parameter_keys`,
`policy_bundle_key`, `replay_record_class`, `query_pin_class`,
`max_ttl_seconds`, `product_ttl_seconds`).

**Permitted key — the single exception:** `plan` — one `module:attribute`
reference to the deployment's projection or its factory.

**Removed:** `resolver` and `question`-as-factory. `connection` is removed as a
`module:attribute` reference; if connection material is needed it is data or it
is absent. Refuse either by name with a message that says the key was ruled out
and points at the spec.

The loader must **refuse any `module:attribute`-shaped value under any key
except `plan`** — not merely refuse unknown keys, but refuse a reference in a
data position. That is what keeps the exception from widening.
</action>
