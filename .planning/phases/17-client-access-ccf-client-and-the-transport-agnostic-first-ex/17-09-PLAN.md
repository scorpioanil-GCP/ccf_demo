`consume.py`, exactly as spec §7 names them, and the product id stays
`hw1.companies-over-revenue` (it is already that in the config the phase inherits).

(`:159`) means it does not see this example as an example root — Task 3 handles it.

**(2) The budget's counting rule, decided and testable.** `consume.py` is held to
**80 physical lines, total, with no exclusions** — blank lines and comments count.
That is the strictest and simplest reading of *"the ENTIRE example a reader studies.
Budget: ≤ 80 lines"*, and it is the only rule a 300-line file of one-statement-per-
comment cannot game. Research's sabotage row demands the rule be decided **and
tested**: both padding forms get a control.

**(3) Which pipeline proves it (D-32).** The deployment points at stores already
populated with FIBO data, living **outside the repository**. That example
**cannot run in always-on CI**, which is network-free and holds no credentials. The
project's established shape applies: `.github/workflows/live-legs.yml` runs the
opt-in job while `sqlite`/`memory` stay always-on (Phase 16 `D-06`, Phase 8 `D-11`).
So: **the example runs in `live-legs.yml`; the conformance suite that proves the
client contract runs always-on** against plan `17-06`'s fixture deployment. The
README states this plainly rather than leaving a reader to discover that the one
command needs a backend.

**(4) Nothing is committed as data.** No store file, no seed artifact, no fixture
data, no `scenario/` directory, no `provision.py`. D-16's prohibition on
provisioning inside a client call is satisfied **by construction** rather than by
discipline, because there is no ingest anywhere near the client. If you find
yourself writing a seeding step, stop — that is producer-side work belonging to the
later producer-examples effort.

## What `consume.py` looks like — Dave's strawman, adapted to D-07

From `17-CONTEXT.md` `<specifics>`:

```
from ccf.client import ProductClient
client = ProductClient.for_product("hw1.companies-over-revenue")
result = client.ask(parameters={"revenue_threshold": args.min_revenue},
                    as_of=datetime.fromisoformat(args.as_of) if args.as_of else None)
if result.refused:
    print(f"refused: {result.refusal.reason} — {result.refusal.key}")
    return 1
print(f"\nQ: which companies have revenue over {result.payload['threshold']}?")
...
print(f"   context debt D_c   {result.debt.debt:.4f}  →  {result.debt.signal.value}")
print(f"   content address    {result.content_address}")
print(f"   replay record      {result.replay_ref}")
```

It knows the product identity and the question parameters. It prints the answer and
then **what a `SELECT` would not have told you** — debt, content address, replay
record — with governance detail behind `--explain`. Nothing else.
