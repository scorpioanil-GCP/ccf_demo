<objective>
Ship the client surface: four exported names, a `Result` that carries either the
answer or the refusal, a guard that raises when a caller ignores the fabric saying
no, and a binding resolution with exactly three steps.

Purpose: **this is the product** (17-CONTEXT `<domain>`, deliverable 1). A Context
Product is valuable because of the contract it returns; if every transport
re-implements that contract differently, the value evaporates. So `Result` is
constructed in exactly one decoder inside `ProductClient` (D-12), and shape
identity across transports becomes a code path adapters cannot avoid rather than a
convention they follow.

Output: `from ccf.client import ProductClient` works, `ask()` returns a `Result`,
and every ruled property of that `Result` is asserted per field with a control
proving the assertion fires.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller → client API | untrusted `parameters` cross here and travel to a request contract that validates them server-side |
| environment → binding resolution | `CCF_BINDING` is process environment; it names *where*, never *how*, and the client holds an opaque address string |
| refused `Result` → caller | the point at which a governed "no" can silently become an empty answer |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-17-15 | Information disclosure | a refusal silently returning `None` and being consumed as an empty answer downstream | mitigate | The fail-closed guard raises on all six post-assembly fields, asserted once per field against a tuple both the guard and the test read |
| T-17-16 | Spoofing | `CCF_BINDING` pointing at an attacker-chosen address | accept | The binding is process environment, in the deployment's own trust boundary; auth/credential machinery is transport-level and on the v0 not-list. Recorded rather than omitted |
| T-17-17 | Elevation of privilege | the client seam serving a product with no principal entitlement check | accept | Deliberate: contract-level principal/entitlement at the client seam is on the v0 not-list, deferred to the MCP adapter work (`D-IMPL-129` neighborhood).
