<objective>
Make `17-11`'s reference debt scorer the **default**, so a deployment that
supplies only data plus its projection never has to know the Protocol exists —
then prove end-to-end that such a deployment produces a gated,
content-addressed product.

This closes the 2026-08-16 spec. Waves 6 and 7 resume when this is green.
</objective>

<context>
**Read the spec, including Amendment A.** Success criteria 1, 2, 4 and 5 stand;
criterion 3 was replaced by 3′ — the deployment holds `ccf_config.yaml`, a
data-only `binding.yaml`, and **exactly one Python module, the projection**.

**The defaulting decision, from §6:** `GovernedResolver` — or a thin
`build_governed_resolver(...)` helper — supplies the reference implementation
automatically when the caller does not pass one. Choose whichever fits the
tree, and say why in the SUMMARY.

**One constraint on that choice, from `17-03`'s own design:** `GovernedResolver`
today has **thirteen arguments and not one default**, deliberately — its
docstring says *"Every value this composition needs that the SDK cannot know
arrives from outside it, and nothing has a default."* A `debt_scorer` default
does not violate that sentence (the SDK *can* now know it), but it does weaken
the property that made the class auditable. **If you default on the class, say
plainly what that costs; if you default in a helper and leave the class
defaultless, say why that is better.** Do not make this choice silently.

**Risk 3 from the spec, which is this plan's sharpest exposure:**

> *Defaulting must be explicit and testable, so a future override path does not
> silently break. A default that nothing exercises is a check that stops
> checking without going red.*

This phase has hit that class **five times**. Your tests must prove the default
is **selected and used**, not merely that it exists.
</context>

<task id="3">
<action>
Write `tests/client/test_data_only_deployment.py` — the end-to-end proof of
success criteria 2 and 3′.

Build a deployment directory containing `ccf_config.yaml`, a data-only
`binding.yaml`, and exactly one Python module (the projection). Point a
`ProductClient` at it through `CCF_BINDING` and assert it produces a **gated,
content-addressed** product: a `Result` carrying a payload, a measured debt, a
content address and a replay reference.

Then assert the shape of the deployment itself: exactly one `.py` file, and
`binding.yaml` carrying no `module:attribute` value outside `plan:`. **This
assertion takes the deployment root as a parameter**, so its control can pass a
divergent root — a second module, or a reference in a data key — into the
shipped function.

**Include the negative:** a deployment whose `binding.yaml` names a `resolver:`
must be refused, proving `17-12`'s narrowing holds at the end of the chain and
not only at the loader's unit boundary.
</action>
