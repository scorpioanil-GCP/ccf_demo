<objective>
Open `VAC-06` — the GENERATOR of the check-vacuity class. Research found it by mutation: neuter each
refusal branch one at a time and **eight of the module's refusals can be deleted with all 51 tests
still green**. Nothing in the module proves that a CONTROL's mutation reaches the assertion it
vouches for, which is why `CONTROL A`, `CONTROL 5` and `CONTROL 13` all shipped mis-aimed.

This plan builds the machinery the rest of `VAC-06` stands on — a single refusal dispatcher, one
UNIQUE id per limb, a frozen roster of those ids, and a way to neuter exactly one limb under test —
and then rules on the two limbs that no control can reach.

Purpose: a limb with no identity cannot be quantified over. Criterion 12 asks that EVERY refusal
branch be either reachable and watched or identified and removed, and criterion 13 asks that every
control be proven to reach the limb it vouches for. Neither is expressible until each limb has a name
the module can hold.

off-switch guard, `refuse_unresolvable`'s dead zero-row limb removed, `base_ledger_text`
parameterised, and `CONTROL 5` re-aimed at the limb it has been observing all along.

<criterion_12_has_only_two_dispositions_and_needs_three>
**A defect in criterion 12 as written, and the reading this plan takes.** Criterion 12 offers exactly
two dispositions for a refusal branch: *reachable and watched RED under a named CONTROL*, or
*unreachable and REMOVED*. Two of the module's branches fit neither, and applying the literal binary
would delete a guard this project has actually needed:

- **`refuse_unresolvable`'s zero-row limb (`:1202`)** is genuinely dead. `traceability_rows` raises
  first on the same input, so NO argument to `refuse_unresolvable` can reach it. Disposition: REMOVE.
- **`uncited_verdicts`' empty-roster limb (`:1754`)** has no production caller — both call sites pass
  a 64-id roster — but a CONTROL can call the function with an empty roster directly, and that is the
  module's own idiom: every checker takes its subject as an argument *"so it can be pointed at
  something other than the tree it is about"*. It is reachable AT THE FUNCTION'S OWN BOUNDARY.
  Disposition: KEEP, and give it a control in plan `21.1-06`. **Research classified this limb
  alongside the zero-row limb as unreachable; that classification is corrected here, and the
  correction is recorded.**
- **`base_ledger_text`'s non-zero-exit limb (`:1611`)** is unreachable only because the function takes
  NO ARGUMENT. It guards a shallow CI clone — a failure this project hit for real in Phase 20. The
  literal criterion would delete it. Disposition: **repair to reachable** — give the function its base
  as a parameter defaulting to `phase_base_commit()`, exactly as `derived_uat_records` and
  `derived_working_set` already take theirs, and give it a control in plan `21.1-06`.

**Repair-to-reachable may be a third disposition, or it may just be the first one reached honestly —
and the smaller reading is probably the right one.** Once `base_ledger_text` takes its base as an
argument, its limb IS reachable and IS watched by a named control, which is criterion 12's FIRST
disposition satisfied on the nose. The repair is how you get there, not a new category. Put it to
Dave that way — the ask is then only *may a limb be made reachable rather than deleted*, which is a
much smaller question than *does criterion 12 need a third disposition*, and he should hear the
smaller one. What must NOT happen either way is deleting a guard against a failure this project
has actually hit, to satisfy the literal binary.

The genuinely dead limb — `refuse_unresolvable`'s zero-row branch — takes the second disposition and
is removed. No reading is needed for that one.
</criterion_12_has_only_two_dispositions_and_needs_three>

  <name>Task 1: The refusal dispatcher, the LIMBS roster, and the neutering switch</name>
  <files>tools/docs_tests/test_requirement_ledger.py</files>
  <action>
Add `_refuse(limb: str, message: str)`, which every refusal in the module raises through. It:

- refuses an unregistered limb id — if `limb` is not in `LIMBS`, that is itself an `AssertionError`
  naming the unregistered id. This is the mechanism that stops a refusal shipping without an
  identity, and it is the forward half of criterion 12;
- raises `AssertionError(f"{message} [limb:{limb}]")`, appending the id so the message stays a
  superset of what it is today. Every existing control asserts a SUBSTRING of its refusal message —
  "matches no file tracked", "exited", "no diff base was given", "no paths were given", "no rows",
  "not one citation-shaped token", "AMBIGUOUS", "BARE BASENAME", "DIRECTORY" — and appending must
  leave all of them passing, unamended. Verify that by running the suite, not by reading;
- raises `from None` so `traceability_rows`' header-absent branch keeps its current suppression of
  the `ValueError` chain;
- returns instead of raising when `limb` is in the module-level `_NEUTERED` set, so that a single
  named limb can be turned off under test. Returning rather than raising means control flow continues
  past the branch, which is exactly the mutation research used to find the eight unfalsified refusals.

Add `LIMBS` — a frozen roster of every limb id, one per refusal branch, NAMED, in the form
`<function>.<branch>`. Twenty branches exist today (research table A, `R1`..`R20`) plus the ones
plans `21.1-01` and `21.1-03` added — the per-member pathspec refusal, the two duplicate-id refusals
and the `_index` non-vacuity refusal. Enumerate them by reading the module, not by copying a list.
Never assert the roster's LENGTH; it is a set of names.

Add `neutered(limb)` — a context manager that adds one id to `_NEUTERED` and removes it in a
`finally`. It exists for the meta-controls in plans `21.1-07` and `21.1-08`.

**Then guard the switch itself, because a switch that turns off refusals is a hazard the moment it
ships.** Add a standing test asserting `_NEUTERED` is empty, and an autouse fixture that asserts it
is empty after EVERY test in the module — so a context manager that failed to restore reddens the
run rather than silently disarming every later assertion. Sabotage that guard once: leak a limb id
into `_NEUTERED` deliberately, watch the fixture go red, and record it.

Route every refusal site through the dispatcher. Do not change any refusal's CONDITION and do not
change any message's existing text. This task is identity only.
