## The `CHANGED_TREE` arity correction

The `D-GATE-21` re-run record's `RR-1` exposure paragraph lists `CHANGED_TREE` among the multi-member constants. **It is wrong.** `CHANGED_TREE` is `(".planning/",)` — a single member, and therefore genuinely protected by the tuple-level truthiness test `B-1` installed. The exposed set is exactly three: `FABRIC` (2 members), `FENCE` (5), `UAT_RECORDS` (11).

The correction is recorded in the tree, at `MULTI_MEMBER_PATHSPECS`'s own comment, so a later reader holding the re-run record does not conclude that a constant went missing from the roster. It is also why the roster is asserted by set equality against `asserted_pathspecs()`'s arity rather than transcribed: a transcribed roster is exactly what a stale review record produces.

## The mechanism choice, and why the cheaper one was refused

`git ls-files --error-unmatch -- <spec>` gives per-member semantics in a **single** subprocess call and names the offending member in stderr. It is cheaper and it was **not** chosen.

Placing it inside `tracked_under` changes the refusal message from `matches no file tracked` to `exited 1`, and `CONTROL 16` asserts that literal substring on four shipped subjects. The cheaper mechanism therefore costs an amendment to a shipped control's assertion — which is a weakening of the exact thing this phase exists to strengthen, and the move a later reader would be right to be suspicious of.

The N-call loop was taken instead. `UAT_RECORDS` is the worst case at eleven `git ls-files` calls, the standing per-member check adds twenty-one more, and the whole module still runs in **2.13 s** (baseline 1.95 s).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 — Missing critical] `CONTROL 18` mutates the FIRST and the LAST member, not one member per constant**

- **Found during:** Task 2 (writing `CONTROL 18`)
- **Issue:** The plan specifies one parametrization per multi-member constant, mutating one member. A single position cannot distinguish the per-member loop the fix installs from a degenerate implementation that inspects only `paths[0]` — which would satisfy a first-member mutation while leaving fifteen of the sixteen members unguarded. That is failure mode 1 from the phase's own control discipline: *the subject never reached the branch under test*, which is how two Phase 21 wave-1 controls failed.
- **Fix:** Parametrized over `MULTI_MEMBER_PATHSPECS × {first, last}` — six cases. **Each case still mutates EXACTLY ONE member**, which is what criterion 2 asks for; what changed is which one.
- **Files modified:** `tools/docs_tests/test_requirement_ledger.py`
- **Verification:** Sabotaged the shipped loop to `paths[:1]` — the three `-last` cases go red, the three `-first` cases stay green. Sabotaged it to `paths[-1:]` — the exact mirror. Both restored. Recorded above as sabotages 2 and 3.
- **Committed in:** `58465f7` (Task 2 commit)

**2. [Rule 2 — Missing critical] `CONTROL 18` runs the predicate on its own sabotage target and requires `False`, and requires the surviving members to be live**

- **Found during:** Task 2
- **Issue:** The plan says "replace exactly ONE member with a near-miss misspelling." A misspelling is only a near miss if it actually matches nothing, and the control is only about `RR-1` if the *other* members actually match something. Assuming either is failure mode 4 — *a neighbour satisfied the predicate* — and the phase's own instruction is to pick the sabotage target by running the predicate and requiring `False`.
- **Fix:** Two preconditions per case, before the refusal is asserted: `not tracked_under((broken,))` and `tracked_under(survivors)`. Each carries a message saying what a violation would mean about the control.
- **Files modified:** `tools/docs_tests/test_requirement_ledger.py`
- **Verification:** Both preconditions passed for all six cases at `58465f7`, which is why the recorded failure is the refusal that did not fire rather than a broken subject.
- **Committed in:** `58465f7` (Task 2 commit)

**3. [Rule 2 — Missing critical] The near miss is DERIVED from the member, not tabulated beside it**

- **Found during:** Task 2
- **Issue:** The plan names literal misspellings (`src/` → `scr/`, `examples/` → `example/`). A literal table is one edit away from naming a member that no longer exists — a control whose subject has drifted out of its own constant, which is the failure this phase is closing, arriving by a third route.
- **Fix:** `near_miss(member)` transposes the member's last two characters, preserving a trailing `/`. It reproduces the plan's own first example exactly (`src/` → `scr/`), and yields `runtime/` → `runtiem/`, `pyproject.toml` → `pyproject.tolm`, `…-VERIFICATION.md` → `…-VERIFICATION.dm`. Its output is then handed to `tracked_under` and required empty, so a transposition that happened to name a real file is caught rather than silently making the control vacuous.
- **Files modified:** `tools/docs_tests/test_requirement_ledger.py`
- **Verification:** All six derived near misses measured to match zero tracked files.
- **Committed in:** `58465f7` (Task 2 commit)
