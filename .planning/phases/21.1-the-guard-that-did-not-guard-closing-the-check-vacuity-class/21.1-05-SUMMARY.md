The widened match starts one character **earlier** and covers the lint's span entirely. **Nothing was corrected away**; the comparison was simply the wrong one. Wave 3's branch was green only because no dotted citation existed anywhere in the tree — failure mode 1, *the subject never reached the branch under test*, and it took a whole wave to produce a subject.

### The repair

`uncovered_lint_citations(document_text, lint_pattern, widened, name)` returns one message per lint match no widened match's span covers, **taking its subject as an argument** so a control can point it somewhere other than the real ledger. Two deliberate properties:

- **The anti-vacuity clause is kept and moved INTO the predicate.** In the test body it was reachable only by the real ledger. Inside the predicate, `CONTROL 23b`'s third limb watches it refuse. *A clause no control can reach is the shape this phase is about.*
- **Coverage is scoped to one cell**, because the extraction it stands in for is.

`D-07` is intact: `tools/lints/citations.py` is byte-identical and **both lint patterns stay imported** as the reference the check measures against.

## Task 1 — limb identity

### The mechanism

| Piece | What it is |
|---|---|
| `_refuse(limb, message)` | the one dispatcher every refusal raises through; appends `[limb:<id>]`; `from None`; **returns** instead of raising when the limb is neutered |
| `_require_registered(limb)` | refuses an unregistered id — **deliberately not a limb, deliberately not routed through `_refuse`** |
| `LIMBS` | a frozen roster of NAMED `<function>.<branch>` ids, asserted by MEMBERSHIP only |
| `_NEUTERED` | the switch — the most dangerous object in the module |
| `neutered(limb)` | one named limb off for a block, restored in a `finally`, id required registered first |
| `neutering_switch_offenders()` | the fixture's predicate, as a NAMED function a control can call |

**Why `_require_registered` is not a limb.** Were it one, neutering it would let an unregistered refusal ship **and** let `neutered()` silently turn off a typo — failure mode 3, *the mutation was invisible to the whole module*. A guard on the switch that can disarm every other guard must not itself be disarmable.

**Why appending rather than replacing.** Every existing control asserts a SUBSTRING of its refusal message — "matches no file tracked", "exited", "no diff base was given", "no paths were given", "not one citation-shaped token", "AMBIGUOUS", "BARE BASENAME", "DIRECTORY". Appending leaves all of them passing **unamended**, which was verified by running the suite, not by reading it.

**No refusal CONDITION and no message text changed.** This task is identity only.

### Every neutered branch degrades to SILENCE, never to a crash

A branch that raised `IndexError` or `KeyError` under neuter would be *falsified for the wrong reason* — the suite reddens on a crash, not on detection, and the meta-controls in `21.1-07`/`-08` would read that as coverage. Six branches needed shaping so that neutering them produces the silent failure they prevent:

|---|---|
| `traceability_rows.header_absent` | `return []` — the clean-looking empty parse the guard's own docstring names |
| `traceability_rows.cell_count` | `continue` — the malformed row silently dropped |
| `_table_line.not_unique`, `_checkbox_line.not_unique` | `""` — an anchor that doctors nothing |
| `roster_verdicts.absent_id` | the absent id silently skipped (`if req_id in table`; always true on the shipped path, so that path is byte-for-byte the comparison it always was) |
| `near_miss.too_short_to_transpose` | `return member` — a mutation that is not one |
| both `*.cell_count` control helpers | `return document_text` — a mutation that lands nowhere |
