## Criterion 8 is unsatisfiable here, the reading taken, and the conflict for Dave

**Criterion 8** asks that every control this phase adds be *watched failing against the pre-fix module and passing against the post-fix module*. **Criterion 12** asks for a named control over every refusal branch. For the refusals in this plan there **is no fix** — they already ship and work. Run against the pre-fix module, all fourteen controls **PASS**. Taken literally the two criteria cannot both be satisfied.

**The reading taken.** For a control over a refusal that already ships, the RED is produced by **neutering the aimed limb** — the same mutation-testing method that found the class in the first place — and that neutered run is what is recorded below.

It is **stronger** evidence than a pre-fix run, not weaker:

| Reading | What the red actually shows |
|---|---|
| Criterion 8, literal | the control fails against a module that **lacks the guard entirely** |
| The reading taken | the control fails against the **shipped** module with **exactly one NAMED branch** disarmed |

The second is what *"proven to reach that branch"* means. The first cannot be produced at all when the branch predates the phase.

**For Dave at the gate:** criteria 8 and 12 are in literal conflict for pre-existing refusals. The reading above is what waves 6, 7 and 8 depend on, and it is offered for ratification rather than assumed.

|---|---|

| `_duplicated_checkbox_bullet.twin_not_read` | `twin` differs from `line` only in the tick, replaced by `" "` or `"x"` — both admitted, and `group(2)` is untouched — so `CHECKBOX_LINE` matches with the same id in **all three** cases |
