<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| built `site/` → uploaded Actions artifact | The upload is the distribution channel; whatever survives the gate ships |
| CI job configuration → the gate's enforcement strength | A `continue-on-error` or a missing step silently disarms the whole phase |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-49 | Repudiation | The docs job is made `continue-on-error` or the scan step is dropped, and the never-publish guarantee quietly stops being enforced | mitigate | No softening construct in the target or the job, asserted by grep in both; the preceding comment block records the deliberate absence, per the three existing statements of this posture in the repo |
| T-14-50 | Information Disclosure | The build succeeds but the scan never runs, so a leak uploads | mitigate | `docs-strict` runs pre-build scan, build, post-build scan as one target with no independent invocation path; the CI job runs that one target |
| T-14-51 | Information Disclosure | The artifact uploads before the scan has passed | mitigate | The upload step follows `make docs-strict`; a nonzero exit fails the job and the upload does not run |
| T-14-52 | Information Disclosure | The docs job is granted a secret it does not need | mitigate | No `secrets:` key on the job, asserted by grep; the docs build consumes no credential |
| T-14-53 | Tampering | An opt-in workflow is accidentally made always-on, or vice versa, while editing ci.yml | mitigate | `perf.yml` and `live-legs.yml` diffs asserted empty; the docs job is asserted to carry no `if:` guard and no dispatch-only trigger |
| T-14-54 | Repudiation | The gate's own tests never run, so a broken checker passes everything | mitigate | The docs-gate unit tests run as their own CI step, before the gate they implement, following the existing lint-checker precedent |
</threat_model>
