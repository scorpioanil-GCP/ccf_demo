<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `examples/` sources → published guide | Example code and artifacts become published content verbatim through includes |
| snippet include path → filesystem | An include path is a read primitive against the repo tree |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-33 | Information Disclosure | A guide include reaches into `docs/` or `.planning/` instead of `examples/` | mitigate | The pre-build include-escape guard bans both prefixes; every include here is asserted to target `examples/` |
| T-14-34 | Spoofing | A silently-empty code block ships, showing the reader nothing while the build stays green | mitigate | `check_paths: true` plus this plan's two-case negative control, which proves both guard sites are live |
| T-14-35 | Spoofing | A pasted snippet drifts from the code CI runs, teaching a signature that no longer exists | mitigate | Zero pasted code asserted by grep for `def` and `class` in the guide; every block is an include |
| T-14-36 | Tampering | The marker pass changes example behaviour and a CI-run example silently stops proving what it claimed | mitigate | Diff asserted to contain only marker comment lines; `make examples` and `make test` re-run after the pass |
| T-14-37 | Information Disclosure | An example artifact included whole contains a credential or an internal path | mitigate | The examples suite is domain-neutral by charter and already public-facing; the post-build scan covers the rendered result |
</threat_model>
