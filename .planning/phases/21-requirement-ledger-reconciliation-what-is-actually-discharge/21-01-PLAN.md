`citations_in_status_cells(document_text)` extracts every citation-shaped token found inside a
traceability-table status cell. Mirror the two regexes from `tools/lints/citations.py` rather
than hand-rolling: `NODE_ID` for `path.py::symbol`, `CITATION` for `path.ext:NN` and
`path.ext:NN-MM`. Also capture `::symbol` tokens whose path does NOT end in `.py`, so that
companion assertion 1 can refuse them by name — `NODE_ID` cannot match them and the lint would
never see them.

`refuse_unresolvable(document_text)` returns a list of messages, one per refusal, each naming the
requirement id AND the offending token. It refuses four things:
  1. a cited path that does not exist as written at `REPO_ROOT` — the predicate is
     `(REPO_ROOT / cited).is_file()`, NOT `.exists()`, so a citation naming a directory is
     refused rather than resolving;
  2. a bare basename with no `/` in it — D-06 requires full repo-relative paths, and a
     basename that is unique today becomes ambiguous the day someone adds a second file;
  3. a `::symbol` citation whose path does not end in `.py`;
  4. a path that exists but whose basename is ambiguous in the repo index — reuse
     `tools.lints.citations.repo_index` rather than a bare `rglob`, because `repo_index` prunes
     `SKIP_DIRS` and a bare walk over a live agent worktree makes every basename ambiguous
     (`DEF-17-04`, RESEARCH §10 Pitfall 10). For an existing full path this branch is
     unreachable, which is the point; the message must still name the ambiguity when it fires.

Vacuity guard: `refuse_unresolvable` RAISES when the parse yields zero rows or zero citations. An
"every citation is a full path" assertion over an empty set passes trivially.

Write into the function docstring the two reasons this refusal exists, both measured in RESEARCH
