<decisions>
## Implementation Decisions

### Temporal posture — RULED, do not reopen
- **D-01: `as_of` is REFUSED**, exactly as cp-01/02/03 refuse it (`400 not_supported_at_tier`). Temporal remains Tier 3's subject, whose flagship is `covenant-in-force-as-of`.
- **D-02: The reproducibility claim is "byte-identical against a QUIESCENT LEDGER FOR THAT RUN", in those words.** No stronger claim is permitted anywhere — README, spec §G, docs page or test name. **The qualifier "for that run" is load-bearing:** `ledger_t` moved 4,560 → 5,112 between two sittings six days apart, which is the proof that quiet is a property of a RUN and never of the database forever.
- **D-03: NO "replay-pinned to `t=4560`" claim.** The estate survey overclaimed. `graph_snapshot_at` is a `datetime` (`src/ccf/products/contract.py:617`); `ledger_t` is an `int`. Measured this sitting: `ledger_t = 5112`, against the survey's 4,560 of 2026-08-28 — **the ledger moved 552 transactions between sittings**, which is itself evidence that quiescence is a property of a run, never of the store.
- **D-04: `D-IMPL-88` STANDS — `t` must not back `as_of`.** Snapshot pinning is a **different axis** and is simply not implemented. Do not collapse the two.
- **D-05: Spec §G STATES these claims; authors copy them.** Spec authoring does not invent a fourth option here.

### Traversal depth — RULED
- **D-06: Caller-supplied `max_depth`, spec-declared ceiling of 6, spec-declared default of 3.** Both numbers are MEASURED (see `<specifics>`), not picked: the SMCI cycle is fully visible at depth 3, and 6 is the deepest tree anywhere in the estate, so no tree is silently truncated at the cap.
- **D-07: `max_depth` above the ceiling is REFUSED BY NAME, never clamped.** A silent clamp is the fourteen-idle-gates class — the request says 8, the walk does 3, and the address still greens. **Sabotage: replace the refusal with a clamp and the gate must go RED.**
- **D-08: A missing `max_depth` takes the DECLARED default**, never a value invented at serve time.
- **D-09: Depth is part of product identity — two depths are two content addresses.**

### Cycles — RULED, and the claim is MEASURED SAFE
- **D-10: Cycle detection executes in the L2 assembler and the recipe declares `operator: null`.** `ccf_dataprep` already ruled detection application-side; `D-IMPL-223` forbids registering it under Traversal to make a category fit.
- **D-11: A cycle reaches the consumer as a `findings[]` entry carrying type, ORDERED MEMBERS and the CLOSING EDGE.** A cycle is a set plus the edge that closes it, never a bit on a node. Shape:
  ```yaml
  findings:
    - type: ownership_cycle
      predicate: owns
      members: [CycCalderIndustrialNv, CycThornburyCapitalLtd, CycMeridianHoldingsSa]
      closing_edge: [CycMeridianHoldingsSa, CycCalderIndustrialNv]
  ```
- **D-12: The tree stays the tree; findings are ORTHOGONAL to it** — the same separation cp-03 holds between entitlement and figures.
- **D-13: The gate asserts the ROSTER, not `len(findings) > 0`.** A detector reporting "some cycle" stays RED.
- **D-14: Headline gate — SMCI at the declared `max_depth` returns cycle 1 with an EXACT roster. Negative — the same anchor over an acyclic predicate (e.g. `isDirectlyConsolidatedBy`) yields NO `ownership_cycle` finding.** The negative control is production data, not a synthetic DAG.
- **D-15: Cycle 2 is NOT the headline** unless the README needs a second command.
- **D-16: Nodes carrying no LEI stay in the tree AND in the roster.** A failed Postgres join is a finding or a null resolution — **never a dropped member**.

### Store split — NOT a gray area
- **D-17: The split is the vault catalog's: Fluree 7 rows, Postgres 4, both 1 (12 §C rows).** Do not re-derive it.

### The MCP door — RULED
- **D-18: TOOL-ONLY egress. No resource is exposed.** cp-04's request needs an anchor LEI plus `max_depth`; the resource URI is only `tenant/class/version` and has nowhere to put them. A resource would help only if a standing, parameter-free answer existed — there is none.
- **D-19: The client supplies the parameters** (anchor/LEI, `max_depth`, plus whatever the request contract already names).
- **D-20: The consume path is `ProductClient` / an MCP tool ask — NEVER `GET /tenant/class/version`.**
- **D-21: The assembler is standalone with two thin callers** — `assembler.py` knows nothing about MCP; `run.py` calls it in-process; `server/serve.py` wraps it with `build_egress_server`. The standalone property is DEMONSTRATED by two callers sharing one module, not asserted.

### Gates — RULED
- **D-22: cp-04 ships `artifacts/gates.yaml` with a CLOSED schema. Every new gate id is DATA.** No new gate id may appear only as a YAML comment. **`expected.yaml` STAYS about expected VALUES** — it is not widened to carry gate rosters. **The spec's §G table is NOT the machine source** either: CI must not depend on parsing prose out of Markdown, which is the fragility the recipe artifact was created to escape (*"a prose table cannot be held against a run"*). Measured this sitting: across the whole ladder, gate ids appear in spec prose, artifact COMMENTS and test docstrings — never as machine-readable data, which is exactly why the declaration↔test link has never been checkable.
- **D-23: cp-02 / cp-03 MAY move existing ids from comments into a file if cheap.** That is transcription, not new tests.
- **D-24: The checker and the backfill are PHASE 24.5, not this phase.** Wiring seven idle cp-00 gates alongside first-multi-store + MCP tool + cycle findings would be a second phase wearing 24.4's name, and a checker designed against FOUR rosters (00–04) is a better instrument than one trained on a single new file. **24.5 is NAMED here in one line and its criteria are NOT locked** — they lock at its own discuss sitting per `D-GATE-19`.
- **D-25: 24.5's shape, recorded so it is not re-litigated:** schema + checker resolving an EXECUTING `test:` node (never `id in file`); scope is `cp-*` products that SHIP a `gates.yaml`; backfill covers cp-00's seven missing tests, `CPR-G08`, and files for any ladder product still comment-only; non-vacuity is zero ids RED and undeclared test id RED. **NO EXEMPTION ALLOWLIST** — a product without a file is simply not yet in the enforcement set; do not write `EXEMPT = [cp-00, ...]`, which is the ledger-exemption shape that drifted for months.

### SDK gaps to RECORD, not close (`D-04` of `24-CONTEXT.md`)
- **D-26:** Fluree adapter **floors but cannot pin** — `Fluree-Min-T` sets a lower bound ("don't answer older than this `t`") and leaves the upper bound open. No `@t:` or `from: ledger@t:N` construction exists in `src/ccf/graph/backends/fluree.py`. On a quiet ledger floor and pin are indistinguishable; **that is a vacant guarantee, not EXAM-06**.
- **D-27:** `graph_snapshot_at: datetime` versus store `t` (int) — a type mismatch for transaction-snapshot pinning.
- **D-28:** Fluree `@iso:` searches **event time** (`db:time`), nearest-at-or-before and backdatable. Legitimate for a CLOCK pin, wrong for a TRANSACTION pin; neither is CCF `as_of`.
- **D-29:** The adapter docstring collapses **three time axes into two**. Record it; do not edit `src/` in this phase.
- **D-30:** The MCP **resource URI cannot address a parameterized product** — every Tier 2+ product will hit this.

<specifics>
## Specific Ideas

**Everything below was MEASURED during this sitting against `fibo-v2` at `ledger_t = 5112`, with a cycle detector proven to discriminate (fires on a planted control cycle, silent on a control DAG).**

### The family graph
- **Six family predicates**, two of which the estate survey never mentioned: `owns` 636, `isDirectlyConsolidatedBy` 140, `isUltimatelyConsolidatedBy` 140, `hasGlobalUltimateParent` 103, **`hasDomesticUltimateParent` 36**, **`controls` 3**.
- Normalized parent→child: **1,058 edges, 748 nodes, 83 roots**.

### The cycles — the claim is safe to make
- **Exactly TWO distinct 3-node cycles, both entirely within `owns`.** The other five predicates are acyclic.
  1. `CycCalderIndustrialNv → CycThornburyCapitalLtd → CycMeridianHoldingsSa → ↺`
  2. `CycHarborstoneKy → CycLindenfeldGmbh → CycPahangPteLtd → ↺`
- Every member carries a `Cyc` name prefix — these are the planted conditions `ccf_dataprep` documents.
- **No cycle member carries an LEI.** They are Fluree-only nodes that cannot resolve to Postgres — the material for "ontology validates the assembly" (`D-16`).
- **The two cycles have DIFFERENT type-chain depths** — cycle 1's members carry 7 classes (`Corporation, FormalOrganization, LegalEntity, LegalPerson, Organization, Agent, Party`), cycle 2's carry 5. A type-constrained walk behaves differently on each.

### The anchor
- **`SuperMicroComputerInc`** — LEI `54930022CZO1N2UGVW07`, label `SUPER MICRO COMPUTER, INC.`, 7-class type chain. A real public company.
- It **owns 19 entities: 18 genuine `Sub*` subsidiaries plus `CycMeridianHoldingsSa`** — the single external edge into cycle 1. Exactly one such edge exists in the whole graph.
- From SMCI: **22 reachable nodes, max depth 3**. Depth to Meridian **1**, Calder **2**, Thornbury **3** — so the full cycle is visible at depth 3.
- **Deepest tree anywhere: 6** (`PSC-*`, UK Persons of Significant Control). This is why the ceiling is 6 (`D-06`).
- Depth is cheap from SMCI (22 nodes); **fan-out, not depth, is what would drag in the 748-node graph**.
