## The three things this plan was told not to get wrong

### Criterion 13's root is not unique, and the module says so

The criterion's ROADMAP text reads *"depth 6 rooted at `PSC-0124`"*. The estate
does not carry that uniqueness: seven roots attain the maximum, and the named one
is not even the largest of them — one of the seven spans eleven nodes where the
named root spans seven. `artifacts/expected.yaml` already records this at
`psc_0124_is_unique: false`.

So the test asserts the maximum depth, the exact roster of every root attaining
it, that the named root is A MEMBER of that roster, and that the artifact still
declares the root non-unique — with a message saying the criterion must never be
phrased as *the deepest root IS* that root. An assertion of uniqueness would be
RED against the estate, which is the point.

**Which root is named is read out of the artifact's own key.** `<root>_attains_it`
is matched back to the roster case-insensitively, so no root name is authored in
the module and the criterion's subject cannot be wrong in two places.

### Both cycles is a census claim, never a payload claim

The cycle work in this module runs the detector over the whole normalized edge
set, which is the only population in which *the only such path* is a statement
that can be made. One circuit has no external in-edge at all and is unreachable
from any LEI-bearing anchor. Nothing here asserts that circuit inside the
anchor's subtree, and its absence there is stated in the docstring as the
measured shape of this estate rather than as a defect.

### Rosters, not cardinalities

Every criterion with a declared roster asserts the roster: the anchor's nineteen
children, the stub/non-stub partition, the LEI-carrying subtree members with
their LEIs, the seven attaining roots, the external cycle edge, and the six cycle
members. Where a cardinality is also declared it is asserted BESIDE the roster,
never instead of it.

## Every check was sabotaged and observed RED

Fifty-seven controls over the nineteen checks, plus two more on the instruments
that report on them. Not one came back green.

**Family 1 — artifact perturbation (task 1), 14 of 14 RED.** One declared value
changed at a time; each isolated exactly the test that reads it. Covers criteria
3 (both halves), 4 (all three figures), 5 (both), 6 (the reading and the flip
table) and 7 (four figures plus the correct-table name).

**Family 2 — artifact perturbation (task 2), 31 of 31 RED** (29 in the first
pass, plus two re-runs after one pattern was found to be matching the wrong block. That miss is worth
recording: the pattern `- uri: SuperMicroComputerBV` matched inside the
duplicate-pair block before reaching criterion 12's `the_two_resolving`, so the
first result attributed a RED to the wrong test and criterion 12's roster
assertion was momentarily unproven. Re-run line-anchored against the right block,
both members went RED). **A control that fires on the wrong subject reports green
for the subject it was meant to test.**

**Family 3 — source- and configuration-side sabotage, 11 of 11 RED.** These prove the figures are
DERIVED from the store rather than echoed from the artifact, which no amount of
artifact perturbation can establish:

| Sabotage | Went RED |
| --- | --- |
| one extra `owns` edge in the committed fixture | predicate counts, collapse, reversal figures |
| an extra edge to an existing root plus a brand-new typed node | the above, plus node/root counts and LEI coverage |
| one predicate dropped from `ccf_config.yaml`'s declared roster | eight tests including the precondition |
| one predicate's `direction:` flipped in `source-vocabulary.yaml` | direction, root count, collapse, reversals |
| the attribute `table:` pointed at the declared decoy | LEI coverage and the decoy control |
| `schema_for` made constant | the per-module isolation check |
| the anchor's only edge into a cycle severed | nine tests, including the external-cycle-edge count |
| a cycle member given an LEI; a stub renamed; the duplicate pair's label replaced; the anchor's class chain shortened | criterion 18, criterion 9's roster, criterion 10, criterion 8 |

**A control on the reversal loop itself.** The reversal map was replaced with an
identity — flipping nothing — and the test went RED. Without that, six reversals
that silently stopped reversing would have kept reporting six clean passes.

**A control on the No-Hardcoding lint.** `make lint` is silent on this file. A
prompt-shaped literal appended to the module made it fire with the file and line,
so the silence is a real pass and not an untraversed tree. (Memory: wave 4's
first control on this same lint returned rc 0 and looked like an uncovered tree.)

**A control on the criterion 45 grep.** The gate returns nothing over the module;
the same expression over a one-line decoy file containing a bare `748` returns a
match. A grep that cannot fire proves nothing about the file it is silent on.

## Criterion 45

```
$ grep -nE '\b(636|140|103|36|1058|722|336|748|83|181|142)\b' tests/examples/test_cp_04_census.py
$ echo $?
1
```

Nothing, anywhere in the module — not in code, not in comments, not in
docstrings. The plan's acceptance criterion allows figures in comments and
docstrings; this module carries none in any position, so the gate holds under
the stricter reading too. Every figure of criteria 3 through 18, including the
ones outside that grep's roster (the child totals, the subtree size, the depths,
the attaining-root count), is read from `artifacts/expected.yaml`.

## Nothing disagreed

Every figure re-derived against the seeded fixture agreed with
`24.4-MEASUREMENT.md` and `artifacts/expected.yaml` on the first reading. There
was no case where a re-derivation disagreed with an artifact, so nothing was
adjusted and there is nothing to report under that heading.

The measured shape confirmed the two things the plan warned about, rather than
contradicting them: seven roots attain the maximum depth (the named one spanning
seven nodes against another's eleven), and the second circuit carries zero
external in-edges.
