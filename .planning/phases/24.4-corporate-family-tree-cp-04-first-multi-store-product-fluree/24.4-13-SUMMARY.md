## The page, and the guards that make its snapshot checkable

`D-IMPL-218` requires the page to name its snapshot in one sentence. Naming it is
cheap; **being unable to name the wrong one** is the part worth building, because
every value in that sentence is a long opaque string that looks right whatever it
says. So the sentence is assembled from `build_page.py::SNAPSHOT` and each value
is checked against a source that is not this module:

| Value | Checked against | Sabotage applied | Observed |
| --- | --- | --- | --- |
| `asked_at` `2026-08-31T12:00:00+00:00` | the committed transcript | — | (covered by the address check below, same predicate) |
| `content_address` `205ae065…` | the committed transcript | last hex digit `8` → `9` | **REFUSED**, naming the transcript path and telling the author to re-capture or correct in the same commit |
| `ledger_t` `5112` | `artifacts/expected.yaml::census.ledger_t_read_at` | `5112` → `5113` | **REFUSED**, naming both numbers and saying why the transcript cannot check this one |
| every placeholder | the template, before substitution | added `{{no_such_key}}` | **REFUSED**: *placeholders with no value: `['no_such_key']`* |
| every generator key | the template, before substitution | deleted `{{transport}}` | **REFUSED**: *values with no placeholder: `['transport']`* |

`ledger_t` is checked against the artifact rather than the transcript for a
measured reason: **the program does not print the transaction counter.** It was
read separately (`deployment.ledger_t()` → `5112`) and it agrees with the census
figure locked at measurement time.

**Byte-for-byte reproduction, and the blindness test.** `make -s example-cp-04`
reproduces `run-transcript.txt` exactly (`cmp` clean, 38,545 bytes / 850 lines).
The diff was proven non-blind **twice**: a one-character plant (`nodes returned
22` → `23`) failed at *byte 36363, line 808*, and a trailing-space plant also
failed — the second because a normalizing comparison is exactly the kind that
quietly stops discriminating.

**The render is not committed**, proven rather than asserted:
`git check-ignore -v` reports `.gitignore:40:examples/*/page/*.html`, and
`template.html` is confirmed **not** ignored by the same command.

## Deviations from Plan

### 1. [Rule 2 — the plan names a flag that does not exist] `--principal` is not documented

**Found during:** Task 1, reading `run.py` before writing the Run-it section.

**Issue:** The plan's task 1 says to run and document *"`--principal`, which
changes which nodes exist rather than how they are shaped."* **There is no
`--principal` in `run.py`, none in the Makefile target, and `run.py`'s own
docstring says so**: *"`--principal` is still NOT shipped, on exactly the same
rule and for want of exactly the same measurement."* `D-IMPL-231` part 3 kept
`--role` because two settings were measured to seal differently and dropped
`--principal` for want of that measurement.

**Fix:** Not documented. The plan text predates the strike.

### 2. [Rule 2] THREE ontology roles, not four

**Found during:** Task 2.

**Issue:** The plan's task 2 says to state that this rung puts *"ontology in four
load-bearing places."* The plan's **own task 1** says THREE, and the tree agrees:
`CP-SPEC-004` §D.2.1 is headed *"The three ontology roles — and the fourth, which
is STRUCK"*, `CFT-G17` is withdrawn, and the numbering 2/3/4 is kept only so a
reader holding the ROADMAP does not have to reconcile two schemes.

**Fix:** All three documents say **three**, and each states the strike with both
measured grounds. No document claims a type-constrained walk; the three places
the phrase appears are all negations.

### 3. [Rule 1 — the documented behavior was not the behavior] `--lei` against a second anchor is refused, in both directions

**Found during:** Task 1, running the variation rather than describing it.

**Issue:** The plan asks for *"`--lei` against a second anchor."* Measured, **no
second anchor serves**, and it fails two different ways:

- Extreme Networks and Celanese are refused because their families serve
  jurisdictions `artifacts/source-vocabulary.yaml` does not declare.
- `SuperMicroComputerBV` — inside the *same* family — is refused the other way:
  the document declares `US-DE`, which that sub-family does not serve.

This is the declared design and not a defect: the served jurisdiction set is
**closed in both directions** so that both declared rows fire and neither is
idle, which is what makes each of them sabotageable at all. The artifact says so
in its own comments.

**Fix:** Documented as it behaves, in all three documents, with both refusal
texts verbatim and the reason stated — swapping the anchor is an **artifact edit
as well as a parameter** at this rung. Nothing was smoothed and no anchor was
presented as working.

### 4. [Rule 3 — a required step measured impossible] the page carries no `mkdocs.yml` nav entry

**Found during:** Task 3.

**Issue:** The plan requires an explicit nav entry, reasoning that *"the nav is
enumerated and `--strict` fails an omitted file."* That reasoning is
`example_delivery.md` §10's, and **§10's rule is conditioned on a page under
`public/`**. This page is not: `docs_dir: public`, and the render is git-ignored.
cp-00 through cp-03 carry no nav entry either — three rungs of precedent.

**Measured rather than reasoned about.** Adding
`- Corporate Family Tree (cp-04): ../examples/…/page/cp-04.html` to the nav and
running `make docs-strict`:

```
WARNING -  A reference to '../examples/cp-04-corporate-family-tree/page/cp-04.html' is included in the 'nav' configuration, which is not found in the documentation files.
Aborted with 1 warnings in strict mode!
```

**Fix:** No nav entry. The measurement, the warning text, and the instruction not
to "fix" it are recorded as a comment in `mkdocs.yml` beside the block that
already explains `public/`'s default-deny posture — real information for the next
reader, and the reason the file mentions `cp-04` at all.

**Stated plainly so nobody is misled by a green check:** the plan's verify line
`grep -q 'cp-04' mkdocs.yml` now passes **on a comment, not on a nav entry.** The
nav entry was measured to be impossible; I did not satisfy the check by any other
route, and I am not claiming the requirement was met.

### 5. [Rule 3] the snapshot is not a header inside the transcript

**Found during:** Task 3.

**Issue:** The plan says to record the `ledger_t` and the commit *"in the
transcript's header."* A header makes `run-transcript.txt` stop being the
program's exact stdout, so `make -s example-cp-04` no longer reproduces it byte
for byte and the diff needs a normalization step — an approximate diff being the
check that quietly stops discriminating. The plan's **own acceptance criterion**
requires byte-for-byte reproduction. `example_delivery.md` §5 puts the snapshot
sentence **on the page**, not in the transcript.

**Fix:** The transcript is stdout and nothing else. The snapshot lives in
`build_page.py::SNAPSHOT`, travels into the page's one-sentence claim, and is
**verified against the transcript and against `expected.yaml` at build time**
(table above). That is strictly more than a header would have given: a header
nobody checks can be wrong forever.

### 6. [Rule 1] the placeholder guard moved from the render to the template

**Found during:** Task 3, first build.

**Issue:** cp-03's generator ends with `if "{{" in page: raise`. Carried over, it
fired immediately — because the page **embeds `deployment.py`**, whose SPARQL
builders legitimately write `f"... WHERE {{ ?s <{p}> ?o }}"`. The guard was
reading a token present in both the compliant and the violating case.

**Fix:** `_assert_placeholders_agree` checks the **template**, before
substitution, that its placeholder set and the generator's key set are equal.
Strictly stronger than the original: it names an unfilled placeholder **and** an
unused generator key, in both directions and by name. Both directions sabotaged
and observed refusing.
