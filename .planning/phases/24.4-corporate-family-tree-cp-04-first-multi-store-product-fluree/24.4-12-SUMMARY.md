## The finding this plan carries out: `CFT-G10` written the obvious way passes its own sabotage

**Measured before the gate was finished, and then again under the real file
edit.** `examples/cp-04-corporate-family-tree/deployment.py::source_read` records
`stores_opened` as a **literal pair** at the point the two connections are made.
So when the attribute leg is made to read Fluree, the opened-store set does not
move. Probed directly against the shipped adapter with the sabotage live:

```
STORES_OPENED: ('corporate_family_graph', 'corporate_family_attributes')
STATEMENTS: 0
REQUESTED: ('54930022CZO1N2UGVW07', '549300F16C4PEFXU0S92')
```

**A gate asserting only *"both stores were opened"* — which is criterion 34's own
wording — is green on a run whose attributes came out of the wrong store.** That
is wave 8's `CFT-G05` finding and wave 9's `CFT-G16` finding recurring a third
time, on a third gate, from a third cause. The role limb and the provenance limb
were written from that reasoning **before** the sabotage was run, and the
docstring names the set limb as non-discriminating rather than leaving a later
reader to find out.

**And the roster discipline was vindicated by measurement, not by argument.**
Variant C — the PostgreSQL leg left running, one column served from the graph —
made **only one** of the two declared resolving members disagree:
`SuperMicroComputerBV`'s PostgreSQL `legal_name` is byte-identical to its
`rdfs:label`, while `SuperMicroComputerInc`'s differs only in letter case
(`Super Micro Computer, Inc.` against `SUPER MICRO COMPUTER, INC.`). A gate that
had sampled one member instead of asserting the declared roster would have had a
coin-toss chance of reporting clean. `D-13`, demonstrated rather than quoted.

### `CFT-G10` — serve attributes from Fluree. **Three variants.**

the graph store. **It never reaches this gate**, and that is recorded rather than
glossed. The graph leg carries no jurisdiction at all, so
`deployment.py::refuse_open_jurisdiction_world` refuses the assembly upstream:

> `SystemExit: 22 member(s) were served and NONE carries a jurisdiction, so the declared set ['NL', 'US-DE'] is held against an empty observation.`

That is evidence the two stores hold different things. It is **not this gate
speaking**, so a second variant was run — the same split wave 9 recorded for
`CFT-G08`, arrived at from the opposite direction: there the declared sabotage
short-circuited the gate's own positive limb, here it trips the product's own
guard before the gate is reached at all.

**Variant B** — the whole leg reading the graph store, with a jurisdiction
assigned from the declared observed set so the assembly completes. RED on **two**
limbs:

> `CFT-G10: the relational leg 'corporate_family_attributes' issued NO statement, so the attributes on the served payload came from somewhere other than the store declared to hold them`
> `CFT-G10: member '…/SuperMicroComputerInc' was served [… ('legal_jurisdiction', 'NL'), ('legal_name', 'SUPER MICRO COMPUTER, INC.') …] where a DIRECT read of 'legal_entity' holds [… ('legal_jurisdiction', 'US-DE'), ('legal_name', 'Super Micro Computer, Inc.') …]`

**The opened-store limb reported nothing.**

**Variant C** — the PostgreSQL leg left running and ONE column served from the

### `CFT-G11` — fire one query per node

Mutation: the batched `WHERE lei = ANY(%s)` replaced by one `WHERE lei = %s` per
key, on the same connection, against the same table, returning the same rows.

> `CFT-G11: the demonstration subtree (22 members) resolved 2 key(s) in 2 statement(s), not 1.`
> `CFT-G11: the whole LEI-bearing population resolved 181 key(s) in 181 statement(s), not 1.`

**The second limb is why this gate is worth anything, and the reason is a
measured property of the estate.** Only two of the subtree's twenty-two members
carry an LEI, so the declared fan-out over the subtree is a difference of **one
statement** — a number a reader could dismiss. The gate therefore also drives the
shipped resolver over every LEI the graph leg carries, **181**, which
`expected.yaml::census.lei_coverage` declares and the precondition test asserts
the seed reproduces. `1` against `181` is what *"works at depth 2 and collapses at
depth 4"* actually looks like.

**`CFT-G10` stayed GREEN under this sabotage** — the leg still ran against the
declared table and served the right values — so the two gates are measurably
disjoint rather than two names for one check.
