**User's choice:** Option 1.
**Notes:** Two of my framings were corrected before the ruling. First I wrote that `ledger_t = 4,560` made `as_of` reachable; `D-IMPL-88` and the adapter docstring forbid it — `t` orders writes, not observations. Dave then supplied Fluree documentation separating THREE axes (`t` transaction time, v4 `db:time` event time, domain `validFrom`), where the adapter's docstring carries two. Rulings, verbatim: *"Single-writer is not a pin. Quiescence makes floor and pin look the same; it does not express `as of t=4560`."* And on a live demo: *"Don't wait on a live write-during-read. The adapter has no `@t:` … A demo on a quiet ledger would only show the vacant case."* Four follow-up guesses of mine were refused as reopening a closed ruling.

## Traversal shape & cycles

| Option | Description | Selected |
|--------|-------------|----------|
| Caller `max_depth`, spec ceiling, over-cap REFUSED | Depth in the request; ceiling declared; over-cap refused by name, never clamped | ✓ |
| Fixed depth declared in the spec | One depth for every request | |
| Fixed tree depth, cycle pass runs to closure | Two extents, tree and findings | |

**User's choice:** Option 1, ceiling **6** / default **3**.
**Notes:** *"A silent clamp is the same class as fourteen idle gates: the request says 8, the walk does 3, the address still greens."* Dave required the ceiling be measured before locking: the SMCI cycle is fully visible at depth 3 and the deepest tree in the estate is 6, so 6 truncates nothing. Options 2 and 3 refused — *"(2) hides the cycle behind a constant. (3) splits tree vs findings extents; consumers will treat them as one graph."*

**Precondition Dave imposed before any cycle claim could be written:** *"'cycles returned as findings' is RED if the estate has no cycle."* Measured this sitting — two distinct 3-node cycles exist, both in `owns`, reachable from a real LEI-bearing anchor, with five acyclic predicates available as a production-data negative control. No fixture injection needed and the claim was not dropped.

| Cycle payload option | Description | Selected |
|--------|-------------|----------|
| `findings[]` with type, ordered members, closing edge | A cycle is a set plus the edge that closes it | ✓ |
| `findings[]`, members by reference only | Smaller payload; consumer joins back to the tree | |
| Flag on each participating node | `in_cycle: true` plus a cycle id | |

**User's choice:** Option 1.
**Notes:** *"The gate asserts that roster, not `len(findings) > 0`. A detector that only reports 'some cycle' stays RED."* And: *"(3) cannot name the closing edge. Credit use is 'A owns B owns C owns A', not `in_cycle: true`."* Nodes without an LEI stay in the tree and the roster — a Postgres join failure is a finding or a null resolution, never a dropped member. Detection layer (L2 assembler, `operator: null`) accepted without objection. Store split was ruled not a gray area: the vault catalog already says Fluree 7 / Postgres 4 / both 1.
