# Phase 24.4 Plan 08: The First Caller, and How `D_c` Is Gated — Summary

**One-liner.** cp-04 answers from a cold shell with no arguments through
`ProductClient` over an in-process adapter that reaches the standalone assembler
and nothing else — with the declared depth default and ceiling read from
`ccf_config.yaml` rather than typed anywhere — and `D-IMPL-230`'s two riders
land: §E.2 carries the measured factor table with no invented weight, and `D_c`
is gated by **movement over a perturbed estate**, never by equality with
`0.090909…`.

## `D-IMPL-230` rider 1 — §E.2's factor table

§E.2.1 now carries `F=1`, `C=1`, `S=20/22`, `D_c=0.090909…`, signal `ok`, plus
the declared `risk_sensitivity 1.0`, `forced_llm_threshold 0.60` and
`fail_closed_threshold 0.77`, and `debt_tolerance: "0.25"`.

**NO WEIGHT WAS INVENTED, and §F.2 row 15 is answered by there being none.** The
declared model is `D_c = 1 − (F · C · S)` — multiplicative, with no weight term —
and `ccf.halflife.debt::assess_debt` takes `(factors, profile)` and applies none.
The marker had no referent; that is the answer, not a value withheld. Each row of
the table names where its value comes from: `F` from the measured absence of any
assertion date on any family node or edge, `C` from §E.2's own fail-closed
elements, `S` from the duplicate-identity finding.

**`debt_tolerance` did not move.** `0.090909…` against `0.25` serves.

**The `Gate 1 status` row records this as a SUBSTANCE amendment under
`D-IMPL-230`, separately from the citation-form amendment already there**, and
says what did not move with it: the sixteen gates, the MCP refusal, the consume
path, the census, the 22-node subtree, the ceiling and the default.

**One §E.2 cell was corrected rather than left false.** The attribute-resolution
row read *"Contributes to: `S`"* and the prose below it read *"returns a served
tree with an elevated `S`"*. The build does not do that and, under this ruling,
must not: the row now reads *"`S` in principle; NOT folded into `S` in this
build"* and points at §E.2.1 and the roster finding.

## `D-IMPL-230` rider 2 — how `D_c` is gated

**`tests/examples/test_cp_04_debt.py` asserts MOVEMENT and nothing asserts
`D_c == 0.0909`.** Four estates are seeded — the committed fixture, a ledger
whose duplicate pair no longer folds, a ledger with a third label collision, and
a ledger-plus-schema in which one row-less member acquires an LEI and a matching
attribute row — and every perturbation is an **estate** perturbation run through
the shipped assembler. Nothing patches a factor to make a number move.

| Boundary moved | roster | `D_c` |
| --- | --- | --- |
| one **fewer** disputed identity | unchanged | **falls** |
| one **more** disputed identity | unchanged | **rises** |
| one **more** member resolves in Postgres | **loses that member by name** | **does not move** |

The third row is the ruling itself, pinned: `D-IMPL-230` ruled SERVE, so the
attribute shortfall reaches the consumer as the roster and as `attributes: null`
and is deliberately not folded into `S`. A build that folded it in moves `D_c`
there — and serves `0.909`, which `409`s against `0.25`.

**NO NEW GATE ID WAS MINTED.** The roster's home is `CFT-G09`; the movement
assertion is a test. `artifacts/gates.yaml` still declares exactly sixteen ids,
`CFT-G01`…`CFT-G16`, verified by reading them out of the artifact.

## Deviations from Plan

### 1. [Rule 1 — the plan's own check cannot distinguish the compliant case] Two grep gates read the claim as the violation

**Found during:** Tasks 1 and 2.

**Issue:** `! grep -n 'transport' assembler.py` fails against the *conforming*
file, because the standalone claim is stated in that file's docstring. The same
shape as plan `24.4-07`'s recorded finding, one file over. And
`! grep -rnE 'GET /|requests\.get|httpx\.get' examples/cp-04-…/` matches (a) the
prose in `run.py` and the spec that **denies** the path, and (b)
`deployment.py::ledger_t`, a legitimate `client.get` against the **Fluree
source store** — a source read, not a consume path.

**Fix:** both replaced with AST, code-scoped checks. The standalone check reads
`assembler.py`'s **imports** and finds `transport` in none of them. The consume
check looks for a product-**address** shape (`GET /`, `/tenant/`,
`/context-products/`) in string constants that are not docstrings, plus any HTTP
client import in `run.py` or `transport.py`. **Sabotaged twice** — an `httpx`
import in `run.py`, and a `"GET /tenant/reference.corporate-family/1.0.0"`
constant in `deployment.py` — and RED on both, GREEN on the compliant tree.

**Note for `24.4-14`:** this sweep ran before `server/` and `page/` exist. One
clean run is not final; the standing check is that plan's.

### 2. [Rule 1 — bug] Omitting `--max-depth` did not walk the DECLARED default

**Found during:** Task 2's scratch-config proof, which is what caught it.

**Issue:** `demonstration_request` copies `question.yaml::parameters`, which
names `max_depth: 3`, so the wire always carried an explicit depth and
`resolve_max_depth`'s declared-default branch was unreachable from this caller.
Measured against a scratch config with the default moved to 2: **the help text
followed and the walk did not.** Two documents named one fact and the artifact's
copy silently won.

**Fix:** with no `--max-depth`, `run.py` asks **without naming a depth**, so the
contract's `argument_defaults` is the path the demonstration exercises — which is
`CFT-G04`'s own subject. The artifact's value is not dropped silently: it is read
on the way past and a **disagreement is refused by name**, naming both documents.
Re-measured with the default moved to 1 and the ceiling to 4: help text, walked
depth, node count and content address **all** follow, and the shipped output is
unchanged.

### 3. [Rule 2 — a flag that would assert an unmeasured discrimination] `--role`, not `--principal`

**Found during:** Task 2.

**Issue:** the plan lists `--principal`. `deployment.perspective` takes a role
and reads `principal_id` from the config, and `deployment.read` says in as many
words that **no equivalent of rung 03's measured 49/47/0/0 discrimination has
been taken over the family population** (§B.2, `[TBC — identity and access]`).
A `--principal` flag would change nothing while looking as though it did — the
nine-row-coverage shape `D-IMPL-228` refused.

**Fix:** `--role`, over the two declared roles, which is the axis this rung
actually has and the one §D.2.1 role 3 is about. `ROLE` is the Makefile
variable.

### 4. [Rule 2 — the CLI could drift from the contract] The inert flags are generated

**Found during:** Task 2. There is no `PARAM_AS_OF` constant, and spelling
`"as_of"` in `run.py` would have been a second copy of a Control Plane fact.

**Fix:** the parser adds one flag per entry in
`ccf_config.yaml::unsupported_arguments`, with the DECLARED refusal reason as its
help text. A parameter this tier starts or stops refusing moves the CLI with it.

### 5. [Rule 1 — the citation form the plan asked for is the one a later ruling forbids]

Task 1's acceptance criterion asks the adapter's docstring to cite
`inprocess.py` **by line**. `D-IMPL-114` rules `path.py::Symbol`, and the
unanchored-citation ratchet has a ceiling of **0**. The docstring cites
`src/ccf/client/adapters/inprocess.py::_boot` and
`src/ccf/client/adapters/binding_document.py::RULED_OUT_KEYS`, both of which
resolve. The ratchet stays at 0 — measured by count, and sabotaged: one planted
line-anchored citation of the `ProductClient` constructor, in the forbidden
`path.py` + line-number form, took it to 1 and RED; removing it returned it to 0.

### 6. [Rule 1 — a stale answer served with a fresh echo] The observer index

`transport.py` records the observer-log length **before** the assembly and reads
only what that call appended. A bare `seen[-1]` would hand the door the
**previous** question's vessel whenever the current one produced none — a stale
answer whose content address would be correct about the wrong product.
