# Phase 24.4 Plan FIX-01: The Served Roster Is the Denominator — Summary

`S` — and therefore `D_c` — are taken over the roster the payload SERVED rather
than over the deployment's source read, so context debt can finally fail through
the door; the depth pair `(3 → 0.0909…, 1 → 0.1)` is pinned as data and held by a
third limb of `CFT-G05`, watched red twice.

## What the finding was

`examples/cp-04-corporate-family-tree/produce.py::_agreement` opened with the
docstring *"S — the fraction of SERVED members whose identity no finding
disputes"* and then computed `members = tuple(sorted(scenario.facts))`. The
docstring said *served*; the code said *read*. The two are the same set at the
declared default depth and differ at every other one, which is exactly why it
survived a phase.

Mechanically: `scenario.facts` is the SOURCE READ, bounded by the declared
**ceiling** of 6. The caller's `max_depth` is applied downstream of it by the L4
traversal operator — `deployment.py`'s own docstring says so in as many words
(*"The ceiling bounds the INGEST; the caller's `max_depth` is applied"* by the
operator). So the denominator never saw the question.

Dave's ruling, verbatim: *"`S` / `D_c` are taken over the **served roster**, not
`scenario.facts`. The docstring already claims that. Computing over the
source-read 22 is why `MAX_DEPTH=1` still prints `20/22` and why `D_c` is the
same at every depth — a scalar that cannot fail **through the door**. That is not
the §E.2 weight TBC. It is a **wrong denominator**."*

## Task 1 — the denominator

**The served roster comes from the projection, which is the only thing that
knows it.** `FamilyTreeProjection.invoke` already computed `served`; it now
publishes it as `served_members`, `_project` returns it beside the execution, and
`measure_debt(scenario, *, served)` hands it to `_agreement`. Nothing recomputes
it: two places computing *the served members* would rebuild the same defect one
level up.

**Read back off `payload["nodes"]`, not off the pre-payload local.** The two are
the same set today and the distinction is what makes the reading
defect-resistant: the `CFT-G09` sabotage — filtering members out of the emitted
node blocks because their PostgreSQL join failed — moves this roster, and
therefore moves `S`. A roster recorded before the payload was shaped would not
notice.

`served_members` raises rather than returning an empty tuple before `invoke` has
run. An empty roster is `S = 0` by `_agreement`'s own vacuity rule, so a silent
empty would present *never projected* as *total disagreement*.

## Task 2 — the movement gate

**No gate id was minted. The roster is sixteen, `CFT-G01`…`CFT-G16`.** The pair
lands as a **third limb of `CFT-G05`**, whose declared statement is *"Depth is
part of product identity. Two depths are two content addresses."* Its two
existing limbs read the seal and the served roster; this one reads the measured
debt; all three fail under the same id. `gates.yaml` names one test per gate and
that test is `tests/examples/test_cp_04_traversal.py::test_cft_g05_depth_is_part_of_product_identity`,
which is where the limb went.

**Pinned as DATA in `artifacts/expected.yaml::debt_by_depth`, not in the test.**
A pin inside the test is not a pin, because the same edit that breaks the code can
fix the literal — and the sabotage this limb catches is an edit to `produce.py`,
which is a file the same author has open. Two files, and the pin's file is not the
mutated one.

Compared as `Decimal` over the declared **string**: the fabric computes a 28-digit
`Decimal` and a YAML float would make the comparison either false or
true-by-rounding.

**Five limbs, not one equality**, because equality alone is satisfiable by a
frozen scalar if the document happens to carry one value twice:

1. the pinned depths and the asks must correspond as **rosters** (`D-13`);
2. the ask's `max_depth_applied` must match the pin it is held against;
3. `D_c` equals its pin;
4. `S` equals its pin — pinned separately so a weights change is not read as a
   denominator change, or the reverse;
5. the declared pair must **differ in the document** and the observed pair must
   **differ in the run**.

Five positive controls hand the shipped check a subject it must refuse. The first
mirrors the shipped defect exactly — one `D_c` at two depths.

source read coincide on all 22. So `D_c` still moved with every perturbation, in
the right direction, by the right amount, and nothing there could see it.

**A movement gate over one boundary says nothing about a second.** That is now
written into the module's own docstring table beside the row it does not own.

### Sabotage B — the inverse control

The five controls stayed green under B, correctly: they assert what the check
REFUSES, and a moved pin does not change that.
