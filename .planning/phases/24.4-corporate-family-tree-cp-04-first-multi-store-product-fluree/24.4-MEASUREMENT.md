## Query surface, stated once

All Fluree figures are read through `/home/parkave/ccf_dataprep/ccf/fluree.py::query`,
which requires an explicit `FROM <fibo-v2>` (the server returns an unhelpful HTTP 500
without one). All Postgres figures are read through `ccf.config.PG` with `psycopg`,
read-only.

**Every predicate figure is ENUMERATED, never aggregated.** Over this ledger the
aggregate forms invent phantoms: `COUNT(DISTINCT ?p)` returns 178 and `GROUP BY ?p`
returns 198 where `SELECT DISTINCT ?p` returns **171**, which is the correct answer.
So the shape used throughout is:

```sparql
SELECT ?s ?o FROM <fibo-v2> WHERE { ?s <PREDICATE-IRI> ?o }
```

and the counting happens in Python over the enumerated rows.

- **Method:** elementary-circuit enumeration by depth-first search over an explicit

**THE ROTATION IS THE ROSTER ORDER, and that is load-bearing.** Criteria 15 and 16
assert EXACT ordered rosters. The same cycle entered from a different node is the same

assertion is unstable across runs. Rotating to the lexicographically smallest member
reproduces the locked rosters exactly. The shipped detector plan `24.4-06` builds must
carry this convention, or criterion 15 will fail against a correct detector.

**Verdict: PASS.**
