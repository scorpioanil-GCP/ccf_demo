# Phase 24.4 Plan FIX-02: Four Checks That Could Not Fail — Summary

The close panel's findings 2 through 5, all four in
`tests/examples/test_cp_04_seams.py`: a limb unreachable by construction, a
door gate reading a label instead of a walk, a batching gate that printed the
roster it never asserted, and two cardinalities standing in the precondition
that says what the five headline gates are allowed to mean. Each fixed, each
watched RED under the defect it now catches, each restored with a clean
`git diff` as the witness.

## What was found, and what it had in common

All four are the same shape the phase already met three times: **a check reading
a record of the intent rather than the effect**, or a cardinality standing where
a roster is required (`D-13`). Two of them were worse than that — they could not
fail at all.

| Finding | The defect | What it now reads |
|---|---|---|
| 2 | `observed` was FILTERED out of `declared`, so `observed - declared` was empty by construction and the limb beneath it was unreachable | the observations, read from the whole document |
| 3 | limb (c) read `max_depth_applied`, which is written from the REQUEST, and compared the anchor URI — never the walk | the served ROSTERS at two depths, against each other and against `depth_to` |
| 4 | two cardinalities, with the resolved roster PRINTED in the failure message and never asserted | what the one statement BOUND, and what it returned rows for |
| 5 | `len(served) == reachable_nodes` and `len(roster) == nodes_carrying_lei` | the rosters, by name, from `expected.yaml` and the committed fixture |

## Task 0 — the ratchet that was already red

`tests/invariants/test_citation_coverage.py::test_the_unanchored_python_citation_population_cannot_regrow`
was **RED on `main` at 5ac3190**, ceiling 0, population 1. The citation came in
at `7c2d6dd` — deferred item 12 quotes
`tests/products/test_gate_two_call_shape.py`'s own message, and that message
prints `produce.py:410`.

`D-IMPL-114` prefers converting a citation to `path.py::Symbol`; here it is a
**verbatim reproduction of program output** and converting it would make the
quote disagree with the tool. So the second sanctioned form was used —
`tools/lints/citations.py::HISTORICITY_MARKERS` — and the symbol the anchor
locates is named beside it, so a reader needs no line number.

**The first attempt did not work and the failing run is the record.** The marker
was placed four lines above the citation and the gate stayed red;
`tools/lints/citations.py::MARKER_WINDOW` is **two**. Measured rather than
reasoned.

This was fixed rather than reported because the plan's own verification list
requires that module to pass. Deviation rule 3.

## Task 1 — finding 2, the limb that could not fire

`roster_violations` built its observed set by filtering the declared one:

```python
declared = {str(gate["id"]) for gate in gates}
observed = {str(gate["id"]) for gate in gates if gate.get("observed_red")}
unowned  = sorted(observed - declared)          # ALWAYS EMPTY
```

while the function's own docstring promised that *"recorded but not declared,
and declared but not recorded, are two different defects."* One of the two could
not arise. Dave: *"assert set difference both ways; print is not an assertion."*

**The observations now come from a separate input**, read from the whole
document by `tests/examples/test_cp_04_seams.py::observations_in` — every mapping
anywhere in `artifacts/gates.yaml` carrying a truthy `observed_red` contributes
its id, member of `declaration.gates` or not. `observed` is a **required**
keyword and not a defaulted one, because a default derived from the roster would
rebuild the dead limb one level up.

Three things follow, and the second is a hole this closed rather than a
restatement:

- the withdrawal limb reads the DECLARED and the RECORDED ids alike, so an
  observation for `CFT-G17` recorded **beside** the roster is the same
  rejoining — previously invisible to both limbs;
- an observation carrying no id at all is named rather than dropped;
- the shipped test asserts both differences separately, so a failure names its
  own direction.

**The control had been passing for the wrong reason**, which the panel also
found: it appended `CFT-G99` carrying `observed_red: None` and read its
violation off the `never_red` limb — *declared but never red*, the other defect
entirely. It now feeds a document carrying an observation for an undeclared id
and requires the `unowned` limb by its own words.

### Sabotage 1

A side block carrying an observation for `CFT-G99` was appended to the shipped
`artifacts/gates.yaml`. **RED** —

```
these ids carry an observation and are not declared: ['CFT-G99']. An observation
nothing declares is a gate nobody owes, recorded as evidence for an obligation
the roster does not carry
```

The independent second defense fired too:
`tests/examples/test_cp_04_gates_declaration.py::test_the_roster_validates_against_the_closed_schema`
went red on `additionalProperties`. **That is not a reason for this limb to
stand down** — a reader running the roster check alone is entitled to an answer,
and the closed schema says nothing about *which ids were observed*.

Restored by copy; `git diff --quiet` reported the artifact identical to HEAD;
72 passed across both modules after.

## Task 2 — finding 3, the door gate the headline rests on

`examples/cp-04-corporate-family-tree/projection.py::FamilyTreeProjection.invoke`
writes `max_depth_applied` from `scenario.max_depth` — the **request** — while
the walk takes its bound from the operator parameter set
`examples/cp-04-corporate-family-tree/deployment.py::traversal_parameters`
binds. The two can disagree, and limb (c) read the first one. A door echoing the
caller's depth while walking the declared default passed the gate whole.

Dave: *"the door must compare **rosters across depths**, not echo
`max_depth_applied` — that is `CFT-G13`."*

`DoorReading` now carries **both** tool asks the one lifespan already drove —
the planted depth and the declared default — and
`tests/examples/test_cp_04_seams.py::_depth_roster_violations` adds four limbs,
all over rosters:

1. the shallower ask's roster is a **subset** of the deeper one's;
2. the deeper ask reached members the shallower did not, so two depths are two
   answers rather than one answer served twice;
3. every member `expected.yaml::census.anchor_subtree.depth_to` declares
   **beyond** the ask is absent, by name;
4. every member it declares **within** the ask is present, by name.

(3) and (4) hold the door against a DECLARATION rather than only against a
second run of the same product, and `depth_to` lives in a file no sabotage of
the door touches.

### Sabotage 2, and the comparison that is the whole finding

`traversal_parameters` was made to return the declared parameters unchanged, so
the caller's depth reached the label and not the walk. **RED under its own id,
on two roster limbs at once:**

```
CFT-G13 (c): max_depth=1 and the declared default 3 served the IDENTICAL roster
  ['CycCalderIndustrialNv', 'CycMeridianHoldingsSa', … 22 members …]
CFT-G13 (c): max_depth=1 served ['CycCalderIndustrialNv', 'CycThornburyCapitalLtd'],
  which expected.yaml::census.anchor_subtree.depth_to declares at [2, 3] — deeper
  than the caller asked for
```

**AND THE ECHO LIMB SAID NOTHING.** Neither *"did not reach the walk"* nor
*"substituted the declared default"* appeared. The gate as it shipped would have
been GREEN here. That comparison is asserted in the tree rather than only
recorded, by
`test_the_door_check_refuses_a_walk_at_the_default_while_the_echo_says_the_ask`,
which requires the roster limbs to fire **and** both echo limbs to stay silent.

**Reach measured, not assumed.** 4 of 225 cp-04 tests went red: this gate,
`CFT-G04`, `CFT-G05` and the traversal precondition. `CFT-G14` stayed green —
correctly, because both callers are equally sabotaged and their rosters still
agree. That is `CFT-G05`'s third-limb lesson met from the other side: a movement
gate over one boundary says nothing about a second.

Restored by exact string; `git diff --quiet` clean; 75 passed after.

## Task 3 — finding 4, two cardinalities and a printed roster

`CFT-G11` had exactly two limbs — `len(requested) < 2` and
`len(statements) != 1` — and **printed** the roster it resolved in the failure
message without ever asserting it. One unparameterized `SELECT` over the whole
attribute table satisfied it: one statement, every row, nothing addressed.

**What the statement ADDRESSED is a different fact from how many statements
there were**, and nothing in the tree carried it, so the channel is new.
`examples/cp-04-corporate-family-tree/deployment.py::_counting_cursor` now
records the values every `execute` BINDS beside the statement text — the same
seam, the same connection, the same reason it was put there in the first place:
a statement fired anywhere on that connection is seen.
`AttributeResolution` publishes them as `addressed`;
`examples/cp-04-corporate-family-tree/deployment.py::_bound_values` walks one
nesting level, because `= ANY(%s)` binds a list inside a one-element tuple.

Three limbs, by name: nothing requested went unaddressed; nothing was addressed
that was not requested; and no **row** came back for a key never requested. The
third reads the effect rather than the binding, and is what catches a whole-table
read that binds nothing at all.

**A resolved roster smaller than the requested one is deliberately NOT a
violation** — 181 LEIs resolve 142 rows on this estate, and a member with no row
is a null resolution rather than a dropped member (`D-16`, `CFT-G09`). That case
is pinned as compliant by `test_the_batching_check_accepts_the_compliant_shape`,
so a later limb cannot quietly forbid the population `CFT-G09` protects.

### Sabotage 3

The batched `WHERE lei = ANY(%s)` was replaced by an unparameterized read of the
whole table — one statement, same connection, same declared table. **RED under
its own id at both scales:**

```
CFT-G11: the demonstration subtree (22 members) asked for 2 key(s) and the
  statement(s) BOUND none of ['54930022CZO1N2UGVW07', '549300F16C4PEFXU0S92']
CFT-G11: … was RETURNED rows for [… 5 named …] … — 140 key(s) it never requested
CFT-G11: the whole LEI-bearing population … — 181 requested key(s) went unaddressed
```

**And the count limb said nothing** — no *"not 1"* appears, because
`len(statements)` was still exactly 1. That silence is the finding, and
`test_the_batching_check_refuses_one_statement_addressing_nothing` asserts it.

**Reach:** 2 of 229 cp-04 tests red — this gate and
`tests/examples/test_cp_04_census.py::test_the_anchor_subtree_store_split`, which
reads the same resolver. `CFT-G10` stayed green, correctly: the leg still ran
against the declared table and served the right values.

## Task 4 — finding 5, and the load-bearing sabotage

The precondition guarding the five headline gates read two counts. A member of
the subtree swapped for another valid node of this estate satisfies both lines
exactly.

**The subtree roster** is assembled by name from the two rosters
`artifacts/expected.yaml` already carries — `unresolved_subtree_members` (the
twenty with no attribute row) and
`census.anchor_subtree_store_split.the_two_resolving` — and compared with the
served roster in both directions, in the local-name space the census convention
uses. Their union is held against `census.anchor_subtree.reachable_nodes`, so a
half-edited document is **reported** rather than absorbed. The subtree's LEI
roster is declared whole, so it is compared whole.

**The LEI roster** is read from the committed fixture
`tests/examples/fixtures/cp_04_family_fluree.json` under the declared predicate
`artifacts/source-vocabulary.yaml::graph.node_predicates.lei`. See the judgment
call below. The chain is asserted at both edges — the declaration against the
fixture, the fixture against what the graph leg serves — so the figure
`expected.yaml` declares still governs and no member can be substituted
underneath it. The LEIs `expected.yaml` names **by value** must be in the served
roster besides.

### Sabotage 4 — the count-preserving member swap

`projection.py::FamilyTreeProjection.invoke` was made to serve one member under
another valid estate node's URI. **RED:**

```
the seed did not serve ['SuperMicroComputerInc'], which expected.yaml declares in
the anchor subtree. NOTE THE SIZES BESIDE THE ROSTERS — served 22, declared 22:
a count-based precondition is satisfied whenever these agree, however the members
differ
```

The count agreement sits **in the failure message on purpose**: it is the proof
that the line this replaces would have stayed green.

### Two inverse controls

A limb that read no file would be green under the sabotage as well. So:
`SubSupermicroKk` → `SubSupermicroKkTYPO` in `expected.yaml`, and the roster
limb named it; the declared LEI figure `181 → 180`, and the
declaration-versus-fixture limb named that. Both restored by copy,
`git diff --quiet` clean after each.

### The finding worth carrying out of this plan

**`CFT-G09` stayed green under the swap, and for a structural reason.** 2 of 229
cp-04 tests went red — this precondition and `CFT-G16` through its pinned seal.
`CFT-G09` passes `subtree_size` as an **integer** and names only the twenty
unresolved members by roster; the member swapped was one of the **two** that
resolve, so all twenty declared names were still in the tree and the size was
still twenty-two. It is the same defect class one gate over. **Logged as
deferred item 13, not fixed** — the panel's four findings are all in the seams
module, and widening what a gate claims is a decision rather than a repair.
