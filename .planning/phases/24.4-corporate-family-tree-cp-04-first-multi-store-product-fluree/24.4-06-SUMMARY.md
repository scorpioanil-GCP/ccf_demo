## The ruling, and why the shape it produces is determined rather than chosen

`D-IMPL-228` fixes three things: the declared set is `{NL, US-DE}`, closed, with
an unknown key refused; the walk is family-scoped to one root and 22 nodes; and
`CFT-G10` stays a claim about the assembly.

It does not, in terms, say what the 20 members carrying no PostgreSQL row are
classified as — and that is the one place the ruling could have been read more
than one way. It was not treated as a choice, because the ruling's own required
controls close it:

| Constraint | Source | Rules out |
|---|---|---|
| 22 members survive, 2 resolving and 20 not | criterion 12, criterion 33, `CFT-G09` | any rule that leaves the 20 with no permitted classification |
| dropping `NL` must go RED | `D-IMPL-228` | classifying every member on the ANCHOR's value — `NL` would then fire on nothing and dropping it would be invisible |
| declared set is exactly two, closed | `D-IMPL-228` | widening the list to cover the absent members |

Only one rule satisfies all three: **a member carries its own
`legal_jurisdiction` where PostgreSQL holds a row, and the family's — the
anchor's — where it does not.** Both declared rows then fire, which is what
makes each independently sabotageable. A third route was checked before it was
excluded: deriving the missing value from the graph leg's own
`jurisdictionCode`. Measured against the committed fixture, **0 of the 22
subtree nodes carry one**, so a mapping table nobody measured would have been
mapping an empty set.

The stricken shape from `D-IMPL-226` is not reinstated under another name. That
shape classified every member on the anchor's value over nine declared
jurisdictions; this one classifies each member on its own where one exists, over
two, and refuses a declared row that fires on nothing.

## Deviations from Plan

### Auto-fixed and auto-added

**1. [Rule 2 — missing critical functionality] The `entitlement:` block still said `status: open`**

- **Found during:** implementing `D-IMPL-228`
- **Issue:** `artifacts/source-vocabulary.yaml` declared the classification
  question open and named spec §B.2's `[TBC]` as its home. Leaving that after
  the ruling is the same defect the ruling was filed beside: a reader stops
  looking.
- **Fix:** the block moves to `status: ruled`, carries `classification_sources`
  in declared order, and the observed set. The deployment READS that order —
  a declared source it cannot honor raises rather than being skipped, so a
  document cannot declare a provenance nobody implements.
- **Commit:** `0876d8b`

**2. [Rule 2] The spec's §B.2 residency row contradicted the ruling**

- **Issue:** `D-IMPL-228` says in terms that *"Spec, config and the policy
  envelope list `{NL, US-DE}`"*. The spec still read `[TBC — identity and
  access]`.
- **Fix:** the row now carries the two-value list, the measured 33-versus-2
  contrast, and the inheritance rule. **§F.4 row 5 was deliberately left
  `[TBC]`** — `D-IMPL-228` does not close the identity-and-access certification
  question, and clearing it would be deciding something Dave did not.
- **Commit:** `0876d8b`

**3. [Rule 3] `read()` takes `max_depth` rather than resolving it**

- **Issue:** an over-ceiling depth is a 400 and an unresolvable anchor is a 404.
  A single return type cannot carry both without the caller discriminating by
  inspection.
- **Fix:** `resolve_max_depth` runs before `read()` and returns
  `DepthOutOfBounds` as data; `read()` returns `None` only for the 404. Both
  refusals stay distinguishable and neither clamps.

## Findings recorded, not fixed

**1. The TTL anchor degenerates at this rung.** `ttl.yaml` declares
`ttl_anchor_basis: latest_family_edge_assertion_time_in_payload` and the product
class declares `ttl_anchor: from_entity_freshness`. Measured over the committed
fixture, **no family node and no family edge carries an assertion date of any
kind** — the ledger holds the six predicates, `ex:lei`, `rdfs:label` and
`rdf:type`, and no timestamp. So every envelope carries `observed_time=None`
(the contract's "unknown"), and `expires_at` is the request instant plus the
declared window. This is **not** equivalent to rung 03's anchor, which moved
with a filing date. Recorded in `FamilyScenario.expires_at`'s docstring rather
than fixed by picking a date: Fluree's `t` is transaction time and `D-IMPL-88`
forbids it backing an observation axis, so there is no second candidate in the
store either. This belongs to the TTL artifact and to plan `24.4-07`.

**2. `source-vocabulary.yaml` cites 356 of 748 nodes carrying a
`jurisdictionCode`; the CI fixture carries zero.** That figure is about the live
estate and appears in no measurement-doc row, so it is not a disagreement with
`24.4-MEASUREMENT.md`. It is recorded because the `entitlement:` block's
original question rested on it, and over the population that actually matters —
the 22-node subtree — the count is 0 either way.

**3. `D_c` is not computed.** `ccf_config.yaml` declares a `debt_profile` and
`question.yaml` a `debt_tolerance`; `FamilyScenario` carries both as data. What
`F`, `C` and `S` are measured over for a graph payload is spec §E.2's question
and belongs with the spine that refuses on it. Named in the module docstring
rather than left to a stack trace.
