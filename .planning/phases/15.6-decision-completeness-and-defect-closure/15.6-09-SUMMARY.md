## Findings

**1. The gate caught one of my own citations, which is the best evidence it
works.** The first draft cited
`examples/04-cross-process/producer_child.py::producer_child` — a symbol that
does not exist. `cite03-node-id` failed the build in all three files at once.
Re-resolved to `::resolve`, the enclosing nested def at line 639, which is
also the more apt citation: the call site is literally inside the deployment's
*resolver*, which is the ruling's whole point.

**2. The first draft of the new test module was defeated by line wrapping, and
that is `_prose.py`'s documented finding arriving on a docstring.** Four cases
failed because `**serves an unvalidated\n      payload**` does not match a
regex written with a single space — the module reported a docstring that says
exactly the right thing as one that says nothing. Fixed with a `normalized()`
helper that collapses whitespace but deliberately does **not** strip markup,
unlike `_prose.strip_markup`, because the `path::Symbol` citations live inside
code spans. Both reasons are recorded in the helper's docstring. Worth keeping:
this is Phase 15.1's six-sweep under-count reproducing itself on a new corpus
within one plan of the module that documents it.

**3. Three `tools/docs_tests` gates are red and were red before this plan.**
Established by **running the same command in a detached worktree at `4b407e0`**
— identical three failures, `3 failed, 83 passed` there against `3 failed, 98
passed` at HEAD, the difference being this plan's 15 new cases. Logged as
`DI-15.6-01`, not fixed: `example-s1-01` runs in CI with no published page
naming it, and `docs/surface/examples/RETIREMENT-COUPLINGS.md` is stale by 18
rows across 5 files. Both are outside this plan's file scope and neither is
caused by its changes. **`testpaths = ["tests"]` is why nobody noticed** — the
package does not run under `make ci-core`, which is one of the two process
findings carried from the 15.1 close.

**4. The correction added zero citation-coverage debt, and the reason is worth
stating.** Quoting a stale anchor as evidence *is* a new citation. Anchoring
those two would make `cite02-anchor` correctly report a finding — they point at
the wrong lines, which is the entire claim. So they carry historicity markers
instead. Net: unanchored **434**, one *below* the base commit's 435, with the
gate still at **0 findings**.

**5. `docs/DECISIONS.md` needed no correction.** `D-IMPL-113`, `D-IMPL-110`,
`D-IMPL-114`, `D-IMPL-105`, `D-IMPL-118` and `D-IMPL-119` were all read in full
before the package was assembled. None was found wrong against the tree — the
six wrong figures live in `deferred-items.md`, the plan text and
