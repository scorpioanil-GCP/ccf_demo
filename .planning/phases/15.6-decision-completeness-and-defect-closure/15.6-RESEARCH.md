### B2. The central design question — fixed field or declared content

This is the phase's primary research output and the spike's charter.

#### Where `D-IMPL-97` draws the line, in my own words

`D-IMPL-97` ruling 1 says a Context Product is **one standardised vessel, not a
class hierarchy**. It then splits the vessel's contents in two:

- **Fixed structure on the base vessel** carries the things that are true of
  *every* product regardless of domain, and whose absence is a governance
  failure: policy versions in force, lineage that must strictly equal what ran,
  the freshness SLA, debt, and the replay record that must exist before
  delivery. The ruling's own decisive argument for putting debt here is **"debt
  by construction"** — *"debt on the base vessel means every product carries it
  while every subclass is a place to forget, and debt computed and discarded is
  exactly the defect this review found."*
- **Declared schema** carries the **domain payload** — validated against a
  schema the class registers, *"in the shape MCP tools declare `inputSchema`"*.
  The three arguments for this half are **language neutrality** (a Python
  subclass cannot cross A2A to a Java consumer), the **No-Hardcoding Rule** (a
  product taxonomy in code is code; `schema_name` + a declared schema is
  configuration), and **the code already works this way**.

**The line, stated as a test:** *does the fabric's own governance machinery have
to reason over this value?* If replay, the gates, the doors, or the Control
Plane must interpret it, it is fixed structure. If only the consuming agent
interprets it, it is declared content. `D-IMPL-97` is explicit that MCP is the
analogy **for the typing discipline only** — *"MCP-shaped in its typing
discipline, with a governance envelope MCP has no equivalent for."*

#### `D-IMPL-100`'s reconstructibility constraint, and the raise path read

**The constraint, precisely:** every field added to `ContextProductContract`
must be **reconstructible by `ReplayEnvironment.rehydrate_product` from (a) the
record, (b) the deployment's product class, or (c) the projection output** — or
replay diverges.

**The raise path, read rather than assumed:**

- `src/ccf/replay/engine.py::replay` (the module's only public replay entry;
  spans lines 356–485 at `29e1568`) calls
  `environment.rehydrate_product(record=…, projection=execution.projection)`,
  then computes `reproduced_address = content_hash(product)` and raises:

  ```python
  if reproduced_address != path.product_content_address:
      raise ReplayDivergence(
          f"the rehydrated product hashes to {reproduced_address!r}; the "
          f"record names {path.product_content_address!r}"
      )
  ```

#### Gap-by-gap analysis: fixed vs declared

**Gap 1 — observation-contribution evidence.**

| | Fixed field on the vessel | Declared content in the payload schema |
|---|---|---|
| Passes `D-IMPL-97`'s test? | **Yes for the pointer mechanism.** Replay must reason over it (reconstructibility), the address covers it, and an examiner asking "which observations decayed" is asking a governance question, not a domain question. | **Yes for the pointer contents.** *Which* observations matter is creator judgement, which `D-IMPL-117` assigns away from the SDK. |
| `D-IMPL-100` reconstructible? | **Free if nested inside `DebtAssessment`** (rides `ContentGenerationPath.debt`). **Costly if a sibling of `debt`** (needs a new dim-5 member + 7 implementations updated). | Payload is already `ProjectionOutput.payload` and is already reconstructible — but it is **not validated by replay**, so a divergence in evidence content is invisible. |
| Failure if wrong | Every deployment carries a shape someone else chose (`D-IMPL-117`) | Debt evidence is unvalidated free-form; replay cannot reason over it (`D-IMPL-117`) |

**RECOMMENDATION (MEDIUM-HIGH confidence, spike to confirm): a hybrid, with the
seam at `DebtAssessment`.** Add an **optional, typed, opaque** evidence member
*inside* `DebtAssessment` — a tuple of a small `CCFContract` carrying opaque
identifier strings the SDK never enumerates. This is the shape `D-IMPL-29`
already shipped for `src/ccf/skills/catalog.py::SkillRequirements`
(*"structurally, as subset/equality over opaque identifiers… Opaque to the SDK;
declared by the deployment"*) and the shape `D-IMPL-101` explicitly named as
salience option (a). It gets three things at once: the **pointer mechanism** is
fixed structure (governance, replay-reasonable, validated); the **pointer
contents** are opaque and creator-chosen (no shape imposed); and
reconstructibility is **free** because the whole assessment already rides dim 5.

Consequence of getting it wrong in each direction, grounded:
- **Too fixed** (e.g. `evidence: tuple[EntityURI, ...]` naming the CCF entity
  model): every deployment whose evidence is a document passage, a filing ID or
  an upstream row key is forced to encode it as a fake entity URI. `D-IMPL-117`
  names this outcome.
- **Too declared** (evidence as a free-form key in `payload`): replay validates
  `payload` only through the content address, so a rehydrator that reconstructs
  a *differently-shaped* evidence blob and happens to hash the same is
  undetectable, and — decisively — **`refuse_bound_payload` is not called by any
  shipped door** (`D-IMPL-113`, and see § A3), so a declared payload schema
  today constrains nothing on the serve path. Putting evidence there would put
  it behind the one gate the SDK has ruled it will not enforce.

is a narrowing of the guarantee's witness, not of the guarantee.

`content_hash(view)`. **Do not remove the hash — remove the *unconditional*
part** by computing the key only when `self._entries` is non-empty (a first
insertion still needs a key; every subsequent probe on a chain that provably
cannot hit does not). That preserves the key's composition verbatim and is a
strictly smaller change than lazy-per-component hashing.

  fail-closed posture for free. **This is a real Makefile/CI surface change and

## Common Pitfalls

### Pitfall 1: Planning `DI-15.5-06` against `D-IMPL-110`'s recorded numbers
**What goes wrong:** the plan asserts 56/30/54; the tree says 60/34/56; the
verification step fails or, worse, an executor "corrects" the tree-derived count
to match the plan.
**Why it happens:** `D-IMPL-110` is an append-only ruling and reads as current.
**Avoid:** the plan re-measures at its own base commit and records the drift as
a finding. `15.5-01`'s standing lesson applies verbatim — *"a module that
asserted those counts would go red as this phase's own work landed, and the
repair would be to edit the evidence, which is the opposite of evidence."*
**Warning sign:** any task whose acceptance criterion is a literal `56`.

### Pitfall 2: Track A's citation sweep landing before Track B's `src/` edits
**What goes wrong:** Track B adds lines to `src/ccf/products/contract.py`,
`halflife/*.py`, `replay/record.py` — all of which hold line-anchored citations
below the edit point. Every one shifts. The sweep is redone or, worse, silently
rots.
**Why it happens:** Track A reads as "mechanical, do it first."
**Avoid:** sweep in the **last** wave, after the final Track B commit that
touches `src/`.
**Warning sign:** a citation-sweep plan with a wave number lower than the last
Track B plan.

### Pitfall 3: Treating the citation gate as red
**What goes wrong:** the plan is scoped as "fix 449 findings." There are **0**
findings. The 449 are *unchecked*, which is a coverage statement.
**Avoid:** scope by the **125 `.py`-target** subset and state the gate is green.
**Warning sign:** the word "failing" near a citation count.

### Pitfall 4: Putting the obligation vocabulary in `src/`
**What goes wrong:** a `StrEnum` of `"re-pull" | "escalate" |
"accept-supervised-synthesis"` lands in `src/ccf/halflife/`. **Every lint in the
tree passes.** It is still the defect CLAUDE.md §11 forbids and the thing
`D-IMPL-117` explicitly said the SDK owes nothing of.
**Why it happens:** `D-IMPL-112` *quotes* those three words as what an analyst
asked for, so they read like a spec.
**Avoid:** an explicit AST structural test (§ B4). The obligation type must be
`str`-opaque or a contract of opaque strings; the SDK validates key type and
uniqueness only.
**Warning sign:** any `Literal[...]` or `StrEnum` in a Track B diff that is not
`DebtSignal` itself.

### Pitfall 5: Adding a **required** field to `Observation`
**What goes wrong:** 3 example YAML artifacts break, because `CCFContract` is
`extra=forbid` and `model_validate` on a required-field-missing dict raises. The
roadmap's "10 files" becomes 13.
**Avoid:** optional with a positive sentinel (`D-IMPL-38`), or budget the three
artifacts explicitly:
`examples/{00-quickstart,08-e2e-demo}/artifacts/decision.yaml` and
`examples/01-agent-basics/artifacts/debt-evaluation.yaml`.

### Pitfall 6: Editing `src/ccf/contracts/claims.py`
**What goes wrong:**
`tests/peering/test_admission_record.py::test_claims_py_is_unchanged_so_reading_a_cannot_creep_back_in`
fails on a `sha256` of the whole file. The tempting repair is to update the
constant.
**Why it happens:** `LineageEntry` looks like the natural home for source
recency.
**Avoid:** § B3. The test's own docstring says the correct response is a **new
`D-IMPL` entry**, not a constant edit.

### Pitfall 7: Re-running the D-20 sweep as the only gate
**What goes wrong:** `docs/schemas/` is swept clean by hand, exactly as
`D-GATE-15.5` recorded, and nothing prevents the next docstring edit from
republishing whitepaper prose. `D-GATE-15.5` already says this in terms:
*"which is clean but is not a gate."*
**Avoid:** the sweep task's acceptance is a **wired scan root in
`docs-strict`**, not a clean report.

### Pitfall 8: Running `make perf-micro` once to close `DI-15.5-01`
**What goes wrong:** the defect *is* variance. One green run is consistent with
the defect persisting.
**Avoid:** three consecutive runs, plus
`git diff --exit-code perf/baselines/local.json`.
