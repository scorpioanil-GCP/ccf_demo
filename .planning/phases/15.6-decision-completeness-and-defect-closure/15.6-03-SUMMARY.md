## Decisions Made

1. **The guard reads `Literal[...]` in field annotations, not only in alias
   values.** The plan's shape said *"an `ast.AnnAssign`/`ast.Assign` whose value
   is a `Literal[...]` subscript"*. That wording catches the type-alias form and
   misses the form gap 3 is most likely to write:
   `obligations: dict[DebtSignal, Literal["re-pull", "escalate"]]` on
   `DebtProfile`, where the strings live in the **annotation** and never in a
   value. A pydantic field is an `AnnAssign` whose value is `Field(...)` or
   nothing at all. Narrowing to values would have shipped a guard that passes
   the exact defect it was built for. Recorded as a Rule-2 addition below, with
   its own parametrized negative-control case so that re-narrowing the walk
   turns that case red rather than turning the guard quietly permissive.
2. **Four exemptions rather than one.** The plan named `DebtSignal` as *"the one
   exemption"*, which is true of `StrEnum` and not of `Literal`: the two scan
   roots already declare three `Literal` string aliases —
   `DebtFactorName` (whitepaper §7.7 F/C/S), `ArtifactRole` (D-IMPL-80) and
   `RegistrationMode` (D-IMPL-85). All three name SDK structure or SDK code
   paths, none is deployment vocabulary, and the plan's own acceptance criterion
   requires the module to pass on the tree as it stands. Each is exempted **by
   name with its reason**, in the analog's `DENIED_PACKAGES` reason-column shape.
   The exemption list is documented as the review seam: a new closed set of
   strings fails until someone adds it here with a justification, which is a
   reviewable event rather than a silent one.
3. **`docs/schemas` is scanned second, not fourth.** It is committed source
   rather than build output, so it does not depend on the build, and the
   recipe's own stated ordering principle — the structural scan runs first *"so
   a symlink or an escaping include is reported before the build has a chance to
   copy it"* — applies to it identically. The armed-gate demonstration confirmed
   the consequence: the refusal fired before mkdocs ran.
4. **No `D-IMPL` raised on the exit-code question**, because reading
   `self_test_fires` answered it. See the measured-results section above.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 — Missing critical functionality] The guard's `Literal` predicate
covered only alias values, not the annotation form**

- **Found during:** Task 2
- **Issue:** The plan specified the `Literal` shape as an `Assign`/`AnnAssign`
  *value*. Gap 3 (plan `15.6-08`) adds a field to `DebtProfile` in
  `src/ccf/controlplane/artifacts.py`; the natural spelling of the defect puts
  the strings in the field's **annotation**, where a value-only predicate never
  looks. The guard would have passed the exact defect it was built to catch.
- **Fix:** The walk reports any `Literal[...]` over string constants anywhere
  under a statement, attributed to its enclosing binding and qualified by the
  enclosing class (`DebtProfile.obligations`, not bare `obligations`). A third
  parametrized negative control —
  `id="literal-in-a-field-annotation (the DebtProfile spelling)"` — pins it.
