# Phase 15.6 Plan 05: Observation Subject Identity Summary

**`Observation` can now name what it is an observation *of* — an opaque string
behind a named positive sentinel — and the one real assembler in the tree stops
discarding the entity URI it was already holding, which is the whole of gap 1's
first limb.**

## Accomplishments

### Task 1 — the identity, in the shape Dave ruled (`b38f93a` RED, `d46bc8e` GREEN)

`D-IMPL-120` was read before a line was written. The clause implemented, quoted
by entry number:

> **D-IMPL-120** — RESOLVED — `qc-optional`. *"the absent value is **a named
> positive assertion, not `None`-as-unknown**, so an omitted identity and a
> dropped one are not the same artifact. An implementation that expresses the
> absence as `None` has not implemented this ruling."*

So:

- `src/ccf/halflife/decay.py::Observation` gains `subject: str`, defaulted to
  `NO_SUBJECT_IDENTITY = "no-subject-identity"` — a module-level `Final[str]`
  whose `#:` docstring states the positive claim, in the `NO_SCORER_PINS` voice.
  `grep -n "= None" src/ccf/halflife/decay.py` returns nothing.
- The type is a bare opaque `str`: no `Literal`, no `StrEnum`, no identifier
  scheme. `tests/invariants/test_no_obligation_vocabulary.py` is green (it scans
  `src/ccf/halflife/` for exactly this failure mode).
- The `Attributes:` entry cites whitepaper §7.7 for the type's grounding and
  labels the identity an SDK extension per CLAUDE.md §11, because §7.7 binds λ_c
  to the observation *type* and says nothing about subject identity. No
  whitepaper prose in the docstring — `Observation` is not schema-reachable, and
  `make ci`'s `docs/schemas/` publish scan is green either way.
- The class docstring's "decay needs exactly two things" claim was reworded to
  "decay **reads** exactly two things" and the third field explicitly marked
  *carried, never consumed* — the old wording would have become false.

Nine test-owned construction sites across the two `tests/halflife/` modules now
populate the identity, each from a module-level constant carrying a `#:` comment
saying the value is deployment-side and the SDK enumerates none of it (CINV-01's
scope reaches `tests/`).

Seven behaviour tests were written **first and observed failing** before the
field existed (`ImportError` on `NO_SUBJECT_IDENTITY`, then three
`ValidationError`s in `test_debt.py`):

| Test | Property |
| --- | --- |
| `test_a_subject_identity_round_trips_unchanged` | verbatim through `model_validate` / `model_dump` |
| `test_an_observation_without_a_subject_carries_the_positive_sentinel` | sentinel, not `None`; field not required |
| `test_a_two_key_observation_mapping_still_validates` | the three artifacts' shape keeps validating |
| `test_two_observations_differing_only_in_subject_are_distinct` | unequal **and** different `content_hash` |
| `test_an_unpopulated_subject_hashes_differently_from_a_populated_one` | absence is a distinguishable state |
| `test_a_naive_timestamp_is_still_refused_on_a_subject_bearing_observation` | D-IMPL-38's discipline unchanged |
| `test_freshness_ignores_the_subject_entirely` + `test_the_freshness_figure_is_unmoved_by_the_subject_identity` | carried, not consumed |

**The naming choice, stated because it departs from a quoted string.** The Q-C
measurement's stand-in field was spelled `subject_uri`, and `D-IMPL-120` quotes
that `loc` when reporting what the required variant raised. The field ships as
`subject`. `D-IMPL-120`'s own scope paragraph says it decides *"required-versus-
optional only"*, and the plan's action text forbids naming the field for any
particular identifier scheme — a `_uri` suffix would require an entity URI, which
`D-IMPL-117` says the SDK owes nothing of. Recorded here and in the fragment so
the departure is visible rather than inferred.

### Task 2 — the assembler stops discarding the key (`2fdda6a`)

`examples/s1-01-hello-context-product/deployment.py::KycScenario.debt` now passes
`subject=record.claim.entity_uri`. One line. The value was already in the loop
variable; `docs/DEBT_COMPLETENESS_RULING_EVIDENCE.md` § Q-D measured seven fields
in hand and thrown away.

An `[ADAPT]`-marked comment at the call site names **which** of the two available
values was carried and **why**, and says plainly that the SDK chose neither —
`lineage`'s `LineageEntry.envelope_id` would identify the source envelope
instead, and which you want depends on whether you attribute decay to entities or
to feeds. No identifier format is invented; the carried value is a field that
already exists on `EntityClaim`.

**Zero artifact edits, and that is the ruling's consequence rather than an
oversight.** `git diff --name-only examples/00-quickstart examples/01-agent-basics
examples/08-e2e-demo` is empty. Under `qc-optional` all three YAML artifacts
validate unchanged and carry the sentinel — the measured 0-artifact cost the
ruling was made against. Had `D-IMPL-120` gone the other way, all three would
raise `ValidationError` with `type: missing`. `make example-00`, `make
example-01` and `make example-08` each exit 0 anyway, run to confirm rather than
to assume.

**The s1-01 byte output did not move.** `make example-s1-01` exits 0 and
`tests/examples/test_s1_01_output.py` passes with **no regeneration** — 28 tests,
zero expectation edits. `Observation.subject` is an input to `FreshnessScorer`,
