# Phase 15.6 Plan 10: Protocol `__call__` Capture and the Phase's Single Manifest Regeneration Summary

The surface manifest can now see what a `Protocol`'s `__call__` takes and what a
type alias is, so the three-to-five-argument resolver break plan `15.5-15`
shipped is finally a `reshaped` diff line instead of a silence — and the phase's
one manifest regeneration carries that together with every Track B contract move
from plans `15.6-05` through `15.6-13`.

## What Was Built

**`tools/dump_surface.py` — two narrow branches added to `_shape_of`.**

1. `_protocol_call` resolves a Protocol's own `__call__` by walking `__mro__`
   `__dict__`s. `getattr(cls, "__call__")` was not usable: it finds
   `type.__call__` on the metaclass for *every* class and would have reported a
   signature for Protocols defining none. `_call_shape` elides the leading
   `self`, which is not part of the contract an adopter implements against.
   Detection is the runtime `_is_protocol` marker, never the class name — two of
   the twelve capture targets (`PeerCardResolver`, `PeerEndpointResolver`) carry
   no `Protocol` suffix, and a plain class can be named `...Protocol` without
   being one. Both directions are asserted.
2. `_render_alias` records a type alias's rendered type. `typing.get_origin` is
   the structural test: non-`None` for every subscripted typing form, `None` for
   a plain function, a class or a `functools.partial`, so the branch cannot
   reach anything whose signature is meaningful.

**`tests/test_surface_shape_capture.py`** — 17 assertions covering the capture,
the structural detection, the alias rendering, manifest determinism, the
narrowness of the change, the `None`-sentinel fix, and **the descope**.

**`docs/surface/v0.2-surface.json`** — regenerated once, as the plan's sequencing
required. `git log --oneline -- docs/surface/v0.2-surface.json` shows exactly one
15.6 commit touching it (`78bffc5`); the one before it is `15.5-14`'s.

**`docs/surface-changes/15.6-10-protocol-call-capture.md`** — the audit framing,
the re-measured inventory, the descope, the determinism trap, twenty entries for
the twenty new mechanical `reshaped` lines, and two `Public surface: false`
entries for the tooling itself.

## Rulings Implemented, Limb by Limb

**`D-IMPL-122` limb 1 — `q2a-reconcile`.** `docs/surface/v0.2-surface-baseline.json`
is byte-identical (`git diff --exit-code` exits 0) and `_BASELINE_DIGEST` in
`tests/test_surface_completeness.py` is unedited — that file is untouched by
this plan entirely. Both pinning assertions are green. The diff was reconciled
instead: every one of the 22 new lines carries a public-log entry.

**`D-IMPL-122` limb 2 — `__call__`-only.** Full method-set capture was **not**
implemented. The 39 multi-method Protocols are left information-free, and the
descope is recorded in three places rather than one: the tool's module
docstring (with the measured 11-against-65 cost and all seven `D-IMPL-110`
names), the fragment's *"What this fix deliberately leaves open"* section, and
`tests/test_surface_shape_capture.py::test_a_protocol_with_no_call_keeps_the_information_free_shape`,
which pins the behaviour against `ArtifactStoreProtocol`, `ControlPlaneProtocol`
and `HarnessAdapterProtocol` by name. **The phase does not close claiming the
blind spot is fixed. `DI-15.5-06` is narrowed, not closed** — after this fix the
manifest is still not evidence of surface stability for a multi-method Protocol.

**`D-IMPL-122` limb 3 — `q2b-in`.** All 20 distinct information-free aliases now
record their type. The plan text's "five `Literal` type aliases" was superseded
before execution began.

**The no-`__call__` Protocol behaviour is decided, not incidental.** It keeps
`(*args, **kwargs)` unchanged — because rendering anything else for those 39
would have produced the 65-line diff Dave declined. Making the shape *more*
informative and making the diff *smaller* were the same choice, and the ruling
picked the smaller diff.

## The Reclassification `D-IMPL-110` Authorized

**`15.5-15` — done, both entries.** `ccf_runtime.mcp.egress.ProductResolverProtocol`
and `ccf_runtime.mcp.experience.ExperienceProductResolverProtocol` moved from
`behavior` to `reshaped`. Each carries an inline note citing the ruling that
authorized the edit and stating that **the original classification was correct
when made** — `reshaped` fails `test_surface_completeness` when the manifest can
show no diff line, and at the time it could show none. The notes are indented
continuations of the `Why` field rather than free-standing bullets, so they
survive `make surface-changes` into `docs/SURFACE-CHANGES.md`; an unindented
non-field bullet is silently dropped by the assembler.

**`15.5-11` — NOT reclassified, and this is a correction to the plan.** The plan
directed reclassifying "the `15.5-11` and `15.5-15` fragment entries". Measured:
`ccf.replay.engine.ReplayEnvironment` defines **no `__call__`** — its whole
contract is a method set — and `D-IMPL-122` descoped method-set capture. The
manifest still shows nothing for that name, so `reshaped` would fail assertion 3
and `behavior` remains the only honest classification available. Its entry keeps
`behavior` and gains an inline note recording precisely that, so a later reader
does not mistake the omission for an oversight. `D-IMPL-122` lists
`ReplayEnvironment` among the descoped 39 by name, which is what makes this the
ruling's outcome rather than an executor's judgement call.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 — Bug] An export whose value is `None` was indistinguishable from one that resolves to nothing**

- **Found during:** Task 2, on the first `make surface` + test run.
- **Issue:** `_resolve_export` returned `None` both for a name it could not
  resolve and for a name whose value *is* `None`. Both recorded the shape
  `"NoneType"`, which is the exact fingerprint
  `tests/test_surface_drift.py::test_no_export_resolves_to_nothing` reads. Plan
  `15.6-07`'s `NO_SOURCE_REFRESH_RECENCY` — a legitimate
  `Final[SourceRefreshWindow | None] = None` sentinel, exported from two modules
  — therefore tripped a gate whose whole purpose is catching import-order
  sensitivity. It had been latent since `15.6-07` landed: the committed manifest
  was stale and predated the sentinel, so this plan's regeneration is what
  exposed it.
- **Fix:** `_resolve_export` now returns a module-level `UNRESOLVED` marker,
  which `None` can never be mistaken for, recorded as `kind`/`shape`
  `"unresolved"`. The drift gate's fingerprint became that positive marker
  instead of an inferred type name. **This strengthens the gate rather than
  relaxing it** — the old check was exact only for as long as no export's value
  was `None`, and it had already stopped being exact.
- **Files modified:** `tools/dump_surface.py`, `tests/test_surface_drift.py`,
  `tests/test_surface_shape_capture.py` (two new assertions covering both
  directions).
- **Commit:** `1612721`

**2. [Rule 2 — Missing critical functionality] Manifest determinism guard against embedded memory addresses**

- **Found during:** Task 1, while measuring what the alias branch would render.
- **Issue:** `str()` of an `Annotated` alias carrying a Pydantic validator
  renders as `<function name at 0x...>`. Two such aliases are exported four
  times between them (`DebtEvidence`, `SignalObligations`). A naive `str()`
  rendering would have committed a process-local address into
  `docs/surface/v0.2-surface.json`, making two runs on an unchanged tree emit
  different manifests — a worse defect than the blind spot being fixed, and one
  that would have surfaced as an unreproducible `make surface` diff rather than
  as a clean failure.
- **Fix:** `_render_alias` scrubs the address and keeps the validator's name.
  Two assertions guard it: one over the whole serialized manifest
  (`test_the_serialized_manifest_carries_no_memory_addresses`) so a future alias
  form that leaks one fails loudly, and one asserting two consecutive builds are
  byte-identical.
- **Commit:** `32a2977`
