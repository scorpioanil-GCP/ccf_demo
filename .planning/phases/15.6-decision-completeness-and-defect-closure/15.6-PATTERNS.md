## Pattern Assignments

### 1. `tests/invariants/test_no_obligation_vocabulary.py`

**Closest analog:** `tests/examples/test_section_one_is_agent_free.py`

**Why this analog:** it is the tree's only shipped example of an **AST walk over
a source tree asserting that something is absent**, written as a pytest module
rather than as a lint checker — which is exactly the shape `15.6-RESEARCH.md`
§ B4 asks for (*"an AST assertion that `src/ccf/halflife/` and
`src/ccf/controlplane/artifacts.py` declare no `StrEnum`/`Literal` of obligation
names"*). It carries the four things a gate of this class needs: a documented
deny list, a populated-scan precondition, a per-item parametrization, and a
negative control.

#### Which home the tree's conventions favour, and why

**`tests/invariants/`, not `tools/lints/`.** The tree draws the line
consistently and it is a *scope* line, not a taste line:

- `tools/lints/__main__.py::RULE_TREE_SCOPE` (lines 123-130) is a per-rule
  **whole-tree** scope map. Every checker registered there runs over `("src",
  "runtime")` or wider, on every file, on every `make lint`. A checker is the
  right home when the rule is *general over a tree*:

  ```python
  # tools/lints/__main__.py:123-130
  RULE_TREE_SCOPE: dict[str, tuple[str, ...]] = {
      "no-hardcoding": ("src", "runtime", "examples", "tests"),
      "harness-imports": ("src", "runtime"),
      "algorithmic": ("src", "runtime"),
      "orchestration-imports": ("src", "runtime"),
      "backend-imports": ("src", "runtime"),
      "substrate-names": ("src",),
  }
  ```

- The obligation-vocabulary rule is **not** general over a tree. It names two
  specific paths (`src/ccf/halflife/`, `src/ccf/controlplane/artifacts.py`) and
  one specific exemption (`DebtSignal`). Registering it in `RULE_TREE_SCOPE`
  would either over-apply it (every `StrEnum` in `src/` becomes suspect) or
  require a path allowlist inside a checker — and `tools/lints/__init__.py`'s own
  header states the allowlist posture: only `no_hardcoding` findings are ever
  offered to the allowlist (D-13).
- The precedent for a *targeted* structural claim is `tests/`. Compare
  `tests/lints/test_deployment_gates_ban.py` (a targeted one-importer ban whose
  checker half lives in `tools/lints/harness_imports.py` because it *is* an
  import rule) with `tests/examples/test_section_one_is_agent_free.py` (a
  targeted directory-scoped claim with no checker half at all).
- `tests/invariants/` is where this project puts named structural invariants
  that are neither lints nor unit tests — six modules today, all asserting a
  *named* architectural property (single-writer, MCP role separation,
  replay-by-construction, state-seam closure).

**Cost check:** adding a `tools/lints/` checker costs a `RULE_TREE_SCOPE` entry,
a `CHECKERS` registration, a `tools/lints/tests/test_*.py`, and a place in the
`make lint` exit-code contract. Adding a `tests/invariants/` module costs a
file. The rule here is targeted, so the cheap home is the correct one.

def require_populated(root: pathlib.Path, mode: str) -> list[pathlib.Path]:
    """Files under `root`, or a hard exit if there are none (CR-03).

    Fail-closed is the whole point. Before this, `publish_scan.py /tmp/typo`
    exited 0, and so did a run against a `site/` that a partially-failed build
    never wrote — the gate reported clean over a tree it had not read, ...

    if not root.is_dir():
        raise SystemExit(
            f"{mode}: {root} is not a directory — the gate cannot certify a"
            " tree it did not read (fail closed)"
        )
    files = iter_files(root)
    if not files:
        raise SystemExit(
            f"{mode}: {root} contains no files — refusing to report clean over"
            " an empty tree"
        )
    return files

```python
NO_SCORER_PINS: Final[tuple[ScorerPin, ...]] = ()

    @field_validator("scorers")
    @classmethod
    def _pins_are_one_per_factor_in_canonical_order(
        cls, value: tuple[ScorerPin, ...]
    ) -> tuple[ScorerPin, ...]:
        """Refuse a second pin for a factor; store the rest in one order.

        Two pins for one factor describe two computations claiming to have
        produced one value, which is not a stricter record but an incoherent
        one. The ordering follows ``graph_secret_refs``' reasoning exactly:
        declaration order is not a fact about the decision, and this value is
        inside the delivered product's content address, so an order-sensitive
        field would make two identical assessments hash differently.
        """
        factors = [pin.factor for pin in value]
        if len(set(factors)) != len(factors):
            raise ValueError(
                "a factor may carry at most one scorer pin; two pins for one "
                "factor describe two computations claiming to have produced "
                "the same value (D-IMPL-47)"
            )
        return tuple(sorted(value, key=lambda pin: pin.factor))
```
