## Blocker

### BL-01: the anti-vocabulary guard still cannot see the one shape gap 3 is actually about — a **dict**

**Files:** `tests/invariants/test_no_obligation_vocabulary.py::_string_table_members` (line 300),
`::COLLECTION_BUILDERS` (line 184), `::_declarations` (line 385)
**Introduced by:** `ad2bd57` (the close-panel B4 fix)

The B4 fix widened the guard from `Enum`/`Literal` to *"a closed table of string
constants in tuple/list/set/`frozenset` form"*. `COLLECTION_BUILDERS` is
`{"frozenset", "set", "tuple", "list"}` and `_string_table_members` accepts only
`ast.Tuple | ast.List | ast.Set` or a `Call` to one of those four builders.
**`ast.Dict` is in neither branch.**

D-IMPL-117 gap 3 is a *mapping* from routing state to obligation. A dict is the
most natural spelling of a mapping, and it is the one spelling the widened guard
does not read.

Verified by injecting the vocabulary into a full copy of the tree (never into the
working tree), appended to `src/ccf/halflife/debt.py` — inside the guard's own scan
root, beside `DebtSignal`:

```python
_SIGNAL_OBLIGATIONS: dict[str, str] = {
    "forced_llm": "re-pull-and-resynthesize",
    "fail_closed": "escalate-to-credit-officer",
}

def obligation_for_signal(signal: str) -> str:
    return _SIGNAL_OBLIGATIONS.get(signal, "ccf.no-obligation-in-force")
```

```
$ pytest -q tests/invariants/test_no_obligation_vocabulary.py tests/halflife/test_debt_delivery.py
47 passed in 0.40s

$ python -m tools.lints --all; echo "EXIT=$?"
EXIT=0
```

This is stronger than B4 was, and in two ways. B4's evidence had to be corrected
because the sibling `tests/halflife/test_debt_delivery.py::test_no_module_level_collection_of_string_literals_exists`
caught the tuple. **It does not catch the dict** — its predicate is
`isinstance(node.value, (ast.Tuple, ast.List, ast.Set))` at line 487 of that file,
the same three node types. So the dict shape passes the guard, passes the sibling,
and passes every registered CINV checker: `make ci` would be green with a
three-member obligation vocabulary shipped in `src/`.

Secondary hole in the same predicate, verified by the same method: a tuple table at
module scope inside any compound statement is invisible, because `_declarations`
only tests `_string_table_members` when `_bound_name(child, …)` is non-`None`
(line 432), and an `ast.If`/`ast.Try` node binds no name:

```
PASSES GUARD (hole): dict-mapping (signal -> obligation)
PASSES GUARD (hole): dict values only
PASSES GUARD (hole): tuple inside an if-block at module scope
refused          : tuple-table (known-refused control)
```

That the shape is natural rather than contrived is already evidenced inside `src/`:
`src/ccf/products/request.py::_REASONS` (line 163) is a module-level
`dict[str, ProductRequestViolationReason]` of three string constants. It is
legitimate SDK structure and is **not** a finding — but it is proof that a plan
reaching for a mapping in `src/` writes exactly this shape, and that the guard would
say nothing.

**Why blocker and not warning, stated rather than assumed.** On its own a lint gap
is not incorrect behaviour. But the phase itself ruled the *identical defect class*
blocking — the panel's B4 was raised from LOW to blocking on the argument that
"a tuple is the most natural alternative spelling of the exact thing it exists to
refuse" — and fixed it in-phase. A dict is a strictly more natural spelling of a
signal→obligation mapping than a tuple is. Shipping the tuple fix while leaving the
dict open means the fix closed an instance, not the class, and the guard's own
"What this check does NOT claim" contract (lines 62-83) does not declare the dict
omission the way it declares the `MINIMUM_TABLE_MEMBERS`, function-body and
`runtime/`/`examples/` omissions.

**Fix:** add `ast.Dict` to `_string_table_members` — reading `node.values` (and,
separately, `node.keys`) under the same all-strings + `MINIMUM_TABLE_MEMBERS` rule —
and either recurse `_declarations` into compound statements or record the compound-
statement omission in the "does NOT claim" list. Add both as parametrized refusal
controls beside the six that exist, and add `_REASONS`-shaped SDK structure to
`EXEMPT_DECLARATIONS` if the widening reaches `src/ccf/products/request.py` when a
later plan widens `SCAN_ROOTS`.

## Critical

### CR-01: `SourceRefreshWindow` accepts a bare number as an instant and supplies the zone itself

**File:** `src/ccf/halflife/assessment.py::SourceRefreshWindow._the_instant_names_its_zone` (lines 499-516)
**Introduced by:** `61d25b4` / `58d8d82` (15.6-07, reshaped by 15.6-13)

The validator's contract is stated in its own name and message: *"a source refresh
instant must name its zone; a naive datetime carries an implicit timezone, which is
a silent default (D-IMPL-38), and this value is inside the delivered product's
content address."* It runs **after** Pydantic coercion, so it only ever sees a
`datetime` — and Pydantic's lax mode converts an `int`, a `float` or a numeric
string into a tz-aware UTC `datetime` before the validator is reached. The check
therefore passes on inputs that named no zone at all:

```
refused   window from naive datetime      (ValidationError)
refused   window from naive ISO string    (ValidationError)
ACCEPTED  window from int epoch      -> 2026-01-01 00:00:00+00:00
ACCEPTED  window from float epoch    -> 2026-01-01 00:00:00.500000+00:00
ACCEPTED  window from numeric string -> 2026-01-01 00:00:00+00:00
```

Two consequences, both replay-stable because the value is inside the product's
content address (D-IMPL-118):

1. **The zone is the SDK's, not the deployment's.** `"2026-01-01T00:00:00"` is
   refused for carrying an implicit timezone; `1767225600` carries no timezone at
   all and is accepted with UTC supplied by the framework. The class enforces its
   invariant against one spelling of the defect and not the other, and the deployment
   never wrote the zone down in either case.
2. **A `float` reaches a hashed field in a module whose headline discipline is
   float-refusal.** `assessment.py:88-93` — *"Decimal, never float. These values
   reach the replay record and are inside the product's content address under
   D-IMPL-100; floats are not bit-stable, so a float is refused at construction
   rather than coerced."* `_refuse_float` (line 141) is wired onto `DebtFactors`
   (216), `DebtEvidencePointer.handle` (335), `SignalObligation.obligation_ref` (711)
   and `DebtAssessment.debt` (829). It is wired onto **neither** field of
   `SourceRefreshWindow`, and `1767225600.5` becomes a hashed instant.

**Fix:** add a `mode="before"` validator on both fields refusing anything that is not
already a `datetime` (or a string Pydantic parses as one carrying an explicit
offset) — the shape `_refuse_float` already has, generalised to the numeric family —
so that "the instant names its zone" is a property of the *input*, not of what the
framework made of it.

## Warnings

### WR-01: the `ccf.` namespace reservation (`3f410af`, panel B1) is bypassable by whitespace or case, and can false-positive

**File:** `src/ccf/halflife/decay.py::Observation._the_subject_is_declared_and_stays_out_of_the_sdk_namespace` (lines 184-238; blank check at 224, namespace check at 231)

The B1 fix's stated property is that *"no deployment-declared value can impersonate a
marker the fabric wrote."* The blank check strips (`if not value.strip()`); the
namespace check does not (`value.startswith(_SUBJECT_NAMESPACE)` on the raw value).
So a value that is the sentinel with a leading space, a non-breaking space, or a
different case walks past a reservation whose entire purpose is that a reader cannot
tell it from the sentinel:

```
ACCEPTED  subject='ccf.no-subject-identity'   (sentinel, correct)
refused   subject='ccf.something'             (correct)
ACCEPTED  subject=' ccf.no-subject-identity'  (leading space)
ACCEPTED  subject='\xa0ccf.no-subject-identity' (nbsp)
ACCEPTED  subject='CCF.no-subject-identity'   (case)
```

A leading space renders invisibly in most consumers of a JSON product, which is
precisely the "indistinguishable, to a reader" state the validator's own error
message names.

The same fix also introduced a **false-positive** surface that is not recorded
anywhere: the reservation is a bare `"ccf."` prefix with no delimiter discipline, so
a deployment whose opaque subject identifiers are domain-shaped —
`ccf.example.com/entity/42`, or any URI under a `ccf.*` host — is refused outright.
The SDK's own §11 posture is that a subject "is an opaque string… the SDK never
enumerates it, never parses it"; this refuses a whole family of legitimate opaque
values.

**Fix:** compare the stripped, case-folded value against the namespace, and narrow
the reservation to a form a deployment identifier cannot collide with by accident
(e.g. the exact set of `ccf.`-prefixed markers the SDK ships, or a `ccf:` scheme).

### WR-02: the B1 rationale was applied to one of four opaque-string fields the phase shipped

**Files:** `src/ccf/halflife/assessment.py::DebtEvidencePointer.handle` (331),
`::SignalObligation.obligation_ref` (682),
`src/ccf/products/contract.py::ContextProductContract.obligation_in_force` (676),
`src/ccf/replay/record.py::ContentGenerationPath.obligation_in_force` (590)

`3f410af` reserved the `ccf.` namespace on `Observation.subject` on the argument
that a deployment must not be able to write a value that impersonates a fabric
marker. Three sibling opaque-string fields shipped in the same phase, all inside the
product's content address, all without that reservation:

```
ACCEPTED  DebtEvidencePointer(handle='ccf.fabricated-marker')
ACCEPTED  SignalObligation(obligation_ref='ccf.anything-at-all')
ACCEPTED  ContextProductContract(obligation_in_force='ccf.fabricated')
```

`SignalObligation` refuses only the *exact* sentinel string
(`value == NO_OBLIGATION_IN_FORCE`, line 736), so
`" ccf.no-obligation-in-force"` is also accepted and reaches
`ContextProductContract.obligation_in_force` through
`DebtProfile.obligation_for` unchanged.

This is not a re-derivation of B1 — B1 was about one field's sentinel spelling, and
its fix shipped. This is the asymmetry the fix left behind: a marker-impersonation
property the phase decided was worth enforcing, enforced in one place out of four.
**Fix:** either extend the reservation to all four (one shared `AfterValidator`
alias, the shape `ObligationInForce` and `DebtEvidence` already use), or record in
`DECISIONS.md` why `Observation.subject` is the only field that needs it.

### WR-03: `dump_surface`'s alias branch is unreachable for PEP-604 unions — including the alias this phase shipped

**Files:** `tools/dump_surface.py::_kind_of` (172, `if callable(obj)` at 185),
`::_shape_of` (255, alias branch guarded by `if kind in ("class", "function")` at 274),
`::_is_type_alias` (227)
**Introduced by:** `32a2977` (15.6-10, D-IMPL-122)

`_is_type_alias` is correct — `typing.get_origin(SourceRefreshWindow | None)` is
`types.UnionType`, non-`None`. But it is only consulted when `_kind_of` returned
`"class"` or `"function"`, and `_kind_of` classifies by `callable(obj)`. A
`types.UnionType` is not callable, so it falls through to `"constant"` and
`_shape_of` returns `type(obj).__name__` at line 286 without ever reaching the alias
branch.

The alias this phase shipped is in that blind spot. Committed manifest,
`docs/surface/v0.2-surface.json`:

```json
"SourceRefreshRecency": {"kind": "constant", "shape": "UnionType"}
```

Verified that widening it produces no diff line:

```
SourceRefreshRecency: type=UnionType callable=False kind=constant shape='UnionType'
MUTATED alias (SourceRefreshWindow|str|None): kind=constant shape='UnionType'
```

`typing.Literal[...]` and `typing.Annotated[...]` *are* callable, which is why
`DebtFactorName` and `DebtEvidence` render correctly and the fix looked complete.

The tests cannot catch this because **every alias assertion hardcodes the kind**:
`tests/test_surface_shape_capture.py:208-224` calls `_shape_of(alias, "function")`
directly, so `_kind_of` — the function that actually decides whether the alias branch
runs — is never exercised on an alias. `test_every_moved_name_is_a_call_protocol_or_a_type_alias`
(line 300) ranges only over names that *did* move.

**Fix:** route the alias test through `_kind_of` in `_shape_of` (or classify
`_is_type_alias(obj)` objects as `"alias"` in `_kind_of`), and add
`SourceRefreshRecency` — a shipped `X | None` export — to the alias assertions
without the hardcoded kind.

### WR-04: `Observation.observed_at` documents a construction-time refusal it does not have

**File:** `src/ccf/halflife/decay.py`, `Observation` attribute docstring at lines 157-160,
field at line 179

The docstring reads *"Timezone-aware; a naive instant is rejected, because an
implicit timezone is a silent default (D-IMPL-38)."* There is no validator on the
field. Verified:

```
ACCEPTED  Observation(observation_type='t', observed_at=datetime(2026,1,1))
          -> observed_at=datetime.datetime(2026, 1, 1, 0, 0)   # naive, no tzinfo
```

The refusal is deferred to computation time:

```
freshness(naive observation) RAISED: ValueError:
  decay requires timezone-aware instants; a naive datetime carries an implicit
  timezone, which is a silent default (D-IMPL-38)
```

A naive `Observation` is therefore constructible, serialisable and storable, and the
failure arrives at whatever call site first computes decay. That is the deferral
CLAUDE.md §11 refuses (*"Validation is at the boundary, never deferred"*).

The docstring text is **pre-existing**, so this is not a defect the phase introduced.
It is in scope because the phase edited this exact class — `15.6-05` added `subject`
with a construction-time validator immediately below the field whose documented
validator does not exist — and because `SourceRefreshWindow._the_instant_names_its_zone`
(`assessment.py:502`) cites this field by name as the precedent it is *"restat[ing]
at construction"*. A reader following that citation to `Observation.observed_at` finds
nothing there.

**Fix:** add the field validator `SourceRefreshWindow` already carries (with CR-01's
correction), or correct the docstring to say where the refusal actually lives.

## Negative results — probed, could not break

Recorded because a review that only lists what it found says nothing about what it
looked at. Each of these was executed, not reasoned.

**1. `IntermediateCache._Deferred` is value- and hit-identical to the eager scheme.**
The review brief asked whether any input makes the deferred path return a different
value than the eager path would have. I reconstructed the pre-`f6ac822` cache from
its git history and diffed the two across five invocation sequences, comparing the
`content_hash` of every returned `OperatorOutput`, the `hits` counter, and the number
of `Operator.apply` calls:

```
PARITY   same key three times               deferred(hits=2,applies=1) eager(hits=2,applies=1)
PARITY   distinct views, then repeat 1st    deferred(hits=1,applies=2) eager(hits=1,applies=2)
PARITY   distinct upstream chains           deferred(hits=2,applies=2) eager(hits=2,applies=2)
PARITY   alternating 4x                     deferred(hits=2,applies=2) eager(hits=2,applies=2)
PARITY   single invocation                  deferred(hits=0,applies=1) eager(hits=0,applies=1)
```

The one theoretical divergence — the deferred key is built at a *later* moment than
the eager one, so a view mutated between the two would key differently — is closed by
construction: `GraphView` is a frozen `CCFContract`
(`src/ccf/graph/protocols.py:154`, *"a frozen contract rather than a live cursor"*).
Composition-preservation is not at risk from `15.6-02`.

**2. Every shipped `rehydrate_product` carries all three Track B fields verbatim.**
Enumerated exhaustively (`grep -rn rehydrate_product`), five implementations, all
reading `record.content_generation_path.*` and none re-resolving:
`examples/06-decision-replay/run.py:387`, `examples/external/00-hello-context/run.py:207`,
`perf/suites/replay/conftest.py:131`, `tests/replay/test_query_sequence_pin.py:258`,
`tests/replay/test_engine_rehydration.py:362`. No path drops, defaults, re-resolves
or coerces a value. In particular no implementation reaches
`DebtProfile.obligation_for` at replay, which is the substitution
`engine.py:218-234` exists to forbid.

**3. Could not construct a product that round-trips to a different content address.**
`canonical_bytes` normalises datetimes to UTC before hashing, so the one lever the
new fields offer — a `SourceRefreshWindow` naming the same instant in two different
offsets — produces identical bytes:

```
same instant?  True True
bytes a  {"newest_source_refresh_at":"2026-01-02T00:00:00.000000Z","oldest_source_refresh_at":"2026-01-01T00:00:00.000000Z"}
bytes b  {"newest_source_refresh_at":"2026-01-02T00:00:00.000000Z","oldest_source_refresh_at":"2026-01-01T00:00:00.000000Z"}
hash a == hash b == a7f848f80ebea3ab789b75bc30299b41e2a7630698ad88ba1c7eff3d11b9a5f7
```

`debt_evidence`'s canonical ordering and `signal_obligations`' canonical ordering are
both enforced at construction *and* re-applied on `model_validate`, so a re-validated
record sorts to the same sequence. The record→product→address chain is bound at both
ends: a tampered dimension-5 value produces a product whose hash does not match
`product_content_address`, and tampering with that too changes the record's own
address, which `resolve_artifact` re-hashes from raw bytes before validation
(`engine.py:322-333`).

**4. No domain value found in `src/` beyond the mechanism gap in BL-01.** An AST scan
of every module-level `dict` of ≥2 string constants across `src/` returns exactly one
hit, `src/ccf/products/request.py::_REASONS`, which is a translation table between two
SDK-owned `Literal` vocabularies and is not a domain value. The obligation refs are
opaque throughout; the KYC strings live in
`examples/s1-01-hello-context-product/artifacts/debt-profile.yaml`, and
`_declared_refresh_window` (`examples/.../deployment.py`) keeps the D-IMPL-124
source-identity boundary on the deployment side.

**5. All three delivery doors carry the new fields with no code change.** Verified
structurally rather than by claim: `egress.py:370`, `experience.py:701` and the HTTP
product route all serialise `canonical_bytes(servable.product)`, which walks
`model_fields`, so the three fields are on the wire at every door.
