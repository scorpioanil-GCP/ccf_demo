### 2.1 `src/ccf/graph/backends/fluree.py` (store + reader, request-response)

#### (a) Module header — copy the shape from `backends/mongo.py:1-88`

The docstring is not decoration here: it is where D-IMPL-34 (physical model is
adapter-internal), the byte-drift refusal, the credential rule, and the CINV-02
"no way to write" statement live. The Fluree module needs all four, plus two of
its own (the zero-coercion `@context`; the no-artifact-string-in-IRI-position
rule). Structure to reproduce, section for section:

`backends/mongo.py:1-10` — whitepaper §7.3 + DESIGN.md §2A.5.2 + the phase
ruling that commissioned it.
`backends/mongo.py:23-43` — **Physical model (adapter-owned, D-IMPL-34)**, with
the traversal-layout decision argued *in the docstring* because the write path
in `_writer.py` depends on it and the two must not drift. Fluree's equivalent
paragraph is the edge-as-node interposition.
`backends/mongo.py:57-63` — the timestamps-are-text refusal, verbatim in
argument:

```python
"""**Timestamps are stored as canonical RFC3339 UTC text, never BSON dates.**
Comparison in the conformance suite happens on ``canonical_bytes`` of
contracts, and a native ``Date`` would round-trip at the substrate's own
precision — the cross-backend byte-drift trap (04-RESEARCH.md Pitfall 3).
Canonical text sorts lexicographically as chronologically, which is what keeps
the as-of cut pushable as plain text comparison (`GQ-24` at
docs/GRAPH_QUERY_SEMANTICS.md:482)."""
```

`backends/mongo.py:65-70` — the credentials paragraph (T-15.2-05 / T-04-24).
`backends/mongo.py:72-79` — **the artifact-data-becomes-structure paragraph.**
This is the slot Fluree's strict-compact-IRI rule occupies. Mongo names
`attribute_field_path` as "the one place"; Fluree names "no artifact-authored
string ever occupies an IRI position."
`backends/mongo.py:81-87` — the "what this module deliberately does not
contain: any way to write" paragraph. **Mandatory** — CINV-02.
`backends/mongo.py:102` — `__ccf_mode__ = "algorithmic"` (CINV-03).
`backends/mongo.py:104-116` — the `__all__` discipline: the public surface is
deliberately small; collection/property constants are module-level and

#### (b) `_graph_identity` — copy from `backends/mongo.py:195-208` / `backends/neo4j.py:168-181`

Identical function in both analogs, differing only in scheme and default port.
Copy the **shape and the docstring argument**, not the string:

```python
def _graph_identity(uri: str, *, database: str, partition: str) -> str:
    """Name the graph a URI points at, without carrying its credentials.

    The single-writer boot check keys on this string, so it has to be stable
    and it has to distinguish two graphs — but it is also the string that ends
    up in exception messages, which is why the userinfo is dropped rather than
    merely "not usually shown" (threat T-15.2-05; the T-04-24 postgres
    precedent). Two partitions in one database are two graphs, exactly as two
    Postgres schemas are.
    """
    parts = urlsplit(uri)
    host = parts.hostname or "localhost"
    port = parts.port or 27017
    return f"mongodb://{host}:{port}/{database}#{partition}"
```

Fluree per D-03: `host/port/ledger#partition`, default port 8090.
**Note the Neo4j variant additionally has `_split_credentials`
(`backends/neo4j.py:151-165`)** because the Bolt driver takes an `auth=` pair.
Fluree's bearer token is a *header*, not userinfo — so the closer analog for
credential handling is Mongo (URI handed whole to the client, identity derived
credential-free), plus a header the store holds privately. Either way,
`graph_identity` never sees it.

#### (e) `_query` — copy from `backends/neo4j.py:570-583`

```python
    def _query(self, sql: str, params: tuple[object, ...]) -> Sequence[Row]:
        """Run one parameterized Cypher read and return its rows as dicts.

        Positional values bind as ``$p0…$pN``; ``$partition`` is supplied
        from the store on every statement. Every value is a driver
        parameter — nothing is rendered into statement text.
        """
        bound: dict[str, object] = {
            f"p{index}": value for index, value in enumerate(params)
        }
        bound["partition"] = self._store.partition
        with self._store.session() as session:
            result = session.run(sql, bound)
            return [dict(record) for record in result]
```

Fluree replaces the last three lines with one `POST {base}/query/{ledger}`
carrying `{"cypher": sql, "params": bound}`, `Content-Type: application/cypher`,
`Fluree-Min-T: {store._min_t}` — and an envelope→`dict` extraction written
**against bytes observed in probe F-A1**, not against a guess. Everything
above that line, including the `f"p{index}"` parameter-*name* rendering,
transfers verbatim. `dict(record)` is what makes rows satisfy
`ccf.graph.reader.Row` (`reader.py:61-68`) for `materialize_view`
(`reader.py:239`).

#### (h) `_reach_pattern` — copy from `backends/neo4j.py:451-484`, adjusted

```python
def _reach_pattern(depth: int) -> str:
    """The variable-length reach pattern — the ONE string-formatting site.
    ...
    """
    if (
        not isinstance(depth, int)
        or isinstance(depth, bool)
        or depth < 1
        or depth > MAX_DEPTH_CEILING
    ):
        raise ValueError(
            f"traversal depth literal must be an int in [1, "
            f"{MAX_DEPTH_CEILING}]; got {depth!r} — callers gate depth 0 and "
            "the over-ceiling decline before rendering (15.2-RESEARCH.md "
            "Pitfall 7)"
```

#### The pushdown-telemetry template, in full

`tests/graph/test_neo4j_backend.py:206-294`. Its docstring is the argument the
Fluree version needs verbatim (only the backend names change), and the reason
it exists at all: byte-identity is a **conformance** bar, not a **pushdown**
bar.

```python
@pytest.mark.neo4j
def test_cypher_traversal_is_pushed_not_silently_degraded(
    fabric_boot: "Callable[..., FabricHandle]",
) -> None:
    """The Cypher walk ran in the engine — telemetry, not byte-identity alone.

    Added by plan 15.2-14 on a BLOCKING finding from the §3.1 phase-close
    self-review. **Byte-identity to the fallback is a conformance bar, not a
    pushdown bar.** D-04 makes the degraded posture byte-identical *by design*
    (`GQ-34` at docs/GRAPH_QUERY_SEMANTICS.md:609), so a `_translate_query`
    that always returned ``None`` would pass the entire differential corpus —
    which was, until this test, the whole of the neo4j leg's evidence.
    ...
    ``memory`` is the differential control — the always-on KV floor, which
    has no native translation at all — so the reached sets and the canonical
    bytes are held identical while only the neo4j leg is asserted pushed.
    """
    from ccf.graph.protocols import GraphQuery, TraversalSpec

    seed_uri, mid_uri, target_uri = chain_uris()
    entities, relationships = chain_claims(
        mid_classification=PERMITTED_CLASSIFICATION
    )

    def walk_at(depth: int) -> TraversalSpec:
        return TraversalSpec(
            seed_entity_classes=SEED_CLASSES,
            relationship_types=RELATIONSHIP_TYPES,
            depth_limit=depth,
        )

    queries = (
        GraphQuery(tenant_id=TENANT, as_of=ON_BOUNDARY, traverse=walk_at(0)),
        GraphQuery(tenant_id=TENANT, as_of=ON_BOUNDARY, traverse=walk_at(1)),
        GraphQuery(tenant_id=TENANT, as_of=ON_BOUNDARY, traverse=walk_at(2)),
        GraphQuery(
            tenant_id=TENANT,
            as_of=ON_BOUNDARY,
            traverse=walk_at(2),
            allowed_entities=frozenset({seed_uri, target_uri}),
        ),
    )

    answers: dict[str, list[bytes]] = {}
    reached: dict[str, list[set[str]]] = {}
    for backend in ("neo4j", "memory"):
        handle = fabric_boot(backend=backend)
        for claim in entities:
            handle.worker.admit_entity_claim(tenant_id=TENANT, claim=claim)
        for edge in relationships:
            handle.worker.admit_relationship_claim(tenant_id=TENANT, claim=edge)
        views = [handle.reader.query(q) for q in queries]
        answers[backend] = [canonical_bytes(view) for view in views]
        reached[backend] = [
            {record.claim.entity_uri for record in view.entities}
            for view in views
        ]
        if backend == "neo4j":
            # The whole point of this test: every one of the four answers came
            # out of Cypher, none out of the fallback.
```

### 3.1 The Protocol `_FlureeTxn` must satisfy exactly — `_GraphTxn` (`_writer.py:320-468`)

The two rules (`:330-342`) — note that they were written *for* a batched HTTP
substrate (D-IMPL-88), which is why one Protocol covers a held Postgres
transaction, a buffered pymongo bulk write, and a single JSON-LD POST:

```python
    Two contract rules hold for every operation, and both exist so the seam
    stays implementable by a remote substrate whose commit is a single batched
    transaction with no held session (D-IMPL-88, module docstring):

    * **Mutating operations return rows actually changed, resolvable before
      commit.** Zero means an ignored duplicate — that number is the whole of
      how the writer distinguishes a new claim from a re-arrival. A batched
      adapter resolves it from (committed state read before buffering + its
      own buffer); INV-CH7-10 single-writer guarantees the pre-commit read
      cannot be invalidated concurrently.
    * **Reads see this transaction's own buffered operations, never another
      transaction's uncommitted state.** ``select_*_chain`` must include
      claims appended earlier in the *same* transaction; it never requires
      observing intra-transaction committed state.
```

```python

    """The single ``GraphWriter`` over one MongoDB graph — extras-gated (plan 15.2-13).

    Same algorithm as every other writer, inherited rather than restated. What
    differs is the transaction: :class:`_MongoTxn` implements the nine typed

    statements are set here, exactly as the memory and Neo4j backends (the
    typed seam's third non-SQL implementation, and its first *batched* one).

    drops it, and nothing was applied.

        txn = _MongoTxn(store=self._store)
        try:
            yield txn
        except BaseException:
            txn.rollback()
            raise
        else:
            txn.commit()
```

## 5. DO-NOT-COPY register

Seven items. The first is the one that costs a silently-wrong adapter.

### #1 — the Neo4j hop predicate `_WALK_EDGES_ALL` (`backends/neo4j.py:440-446`) ⛔ CRITICAL

```python
#: Crossability as a path predicate: only the materialized crossable edges
#: — surviving, permitted-type, endpoint-closed, in-set — extend a path,
#: and the artifact-authored type list rides as ``$types`` (`GQ-10`;
#: threat T-15.2-01).
_WALK_EDGES_ALL = (
    ")\n"
    "  AND all(r IN relationships(p) WHERE r.partition = $partition\n"
    "          AND r.tenant_id = $tenant\n"
    "          AND r.relationship_key IN $crossable\n"
    "          AND r.relationship_type IN $types)\n"
)
```

**Copying this into the Fluree adapter yields a silently empty reached set.**
On Fluree, `r.<prop>` on a plain RDF edge is present *only for a
reified/annotated edge*; a property-reading relationship variable sees nothing.
Every `r.*` evaluates null, `all(...)` is false for every path, and the query
returns `200` with zero rows. It is **not** covered by Fluree's "clear error,
never a silently wrong result" promise, which is about parse-time rejection of
unsupported *forms*.

**Warning sign named in Pitfall 7:** a traversal that returns exactly the seeds
and nothing else, at every depth.

**Replacement:** one node predicate over one prefix-namespaced parameter list —
`all(n IN nodes(p) WHERE n.ccf_admit_key IN $admissible)`. The two Neo4j node
predicates `_WALK_NODES_ALL` (`:422-427`) and `_WALK_NODES_ALLOWED` (`:434`)
collapse into it. Probe **F-A3(e)** exists specifically to *confirm* this break
before the code depends on it.

## 6. Divergence register — where the analogs stop matching

### Divergence 1 — the write commit primitive

| Aspect | `_MongoTxn` (analog) | `_FlureeTxn` | Consequence |
|---|---|---|---|
| Constructor | `__init__(*, store)` (`:1932`) | same | **matches** |
| Buffer | `_ops: dict[collection, list[UpdateOne]]` (`:1937`) | two ground-triple lists (`_insert`, `_delete`) | different container, same discipline |
| `commit()` | N `bulk_write(ordered=True)`, one per collection (`:1995-2002`) | **one** `POST {base}/update/{ledger}` with `{"@context": {}, "delete": [...], "insert": [...]}` and **no `where` clause** | D-01's single-POST atomicity |
| Post-commit | none | `self._store._min_t = max(…, response["t"])` | read-after-write; no analog in the tree |
| `rollback()` | `self._ops.clear()` (`:2004-2006`) | same | **matches** |
| Ordering | `ordered=True` lets a restitch update a claim the same txn inserted (`:1922-1925`) | **no ordering primitive exists** — a JSON-LD body has one `delete` and one `insert`. Intra-batch ordering must be resolved in Python before the body is built | **the real structural difference** |

**Divergence 1c — `update_*_supersession` has no `$set` analog.** Mongo buffers
`{"$set": {"superseded_by": …, "superseded_at": …}}` (`:2111-2121`). JSON-LD
offers ground delete + ground insert only, so the txn must know the **old**
value to delete it. That widens `_held` (`:1974-1979`) from a boolean existence
check into a value read. The *rowcount* half (`:2103-2110`) carries verbatim;
the *mutation* half is new code. This is the one operation where `_MongoTxn` is
not a complete template.

Also: the batch is one HTTP body with a **10 MB documented limit** (`413` on
breach). No analog exists for a byte budget on the write side. Recommendation
in §R2: fail loudly with a typed error naming the limit — splitting silently
would break the write atomicity D-01 exists to preserve.

### Divergence 2 — the read path's physical model

| Aspect | Neo4j (analog) | Fluree |
|---|---|---|
| Edge storage | property-bearing relationship: `(a:CcfEntity)-[:CCF_EDGE {relationship_key, relationship_type, partition, tenant_id}]->(b:CcfEntity)` | **interposed node**: `(:CcfEntity)-[:CCF_LINK]->(:CcfEdge)-[:CCF_LINK]->(:CcfEntity)` |
| Walk pattern | `-[:CCF_EDGE*1..depth]-` (`_reach_pattern:484`) | `-[:CCF_LINK*1..{2*depth}]-` |
| Hop predicate | `all(n IN nodes(p) …)` **AND** `all(r IN relationships(p) …)` (`:422-446`) | `all(n IN nodes(p) WHERE n.ccf_admit_key IN $admissible)` only |
| Admissibility parameter | `$survivors`, `$allowed`, `$crossable`, `$types` (four lists) | **one** `$admissible`, computed in Python as `{"e:"+uri …} ∪ {"r:"+key …}` — prefix-namespaced so an `entity_uri` can never collide with a `relationship_key` |
| Depth arithmetic | 1:1 | **×2** — a CCF hop of depth *d* is 2*d* Cypher hops (bipartite; only even-length paths end at an entity) |
| Terminal | `(x:CcfEntity)` (`_WALK_MATCH_SUFFIX:414`) | same — and the label is what makes parity handle itself |
| Cap behaviour | none | path-enumeration visited/path caps **error** rather than truncate → catch and `return None`, letting the D-04 fallback answer. **Note:** this decline happens *after* a round trip, unlike every existing pure-value decline. `GQ-32` constrains what a non-`None` return must contain, not when `None` may be produced |

**Pitfall 13 is the named risk of this divergence:** the ×2 is Mongo's
`maxDepth` off-by-one wearing different clothes. Assert depths 0, 1, 2 and 3
directly against the fallback before promotion — do not reason about it.

Adjudication of Mongo's four `$graphLookup` corrections on Cypher (research
§R5): #1 directedness doubling — **structurally immune**; #2 seed exclusion —
**not immune, transfers from the Neo4j template verbatim** (`neo4j.py:714`);
#3 depth-0 stage skip — **not immune, transfers verbatim** (`neo4j.py:715-718`);
#4 `maxDepth` off-by-one — immune in kind, **replaced** by the ×2. Net: two
transfer, one absent, one replaced, **plus three Fluree-specific breaks with no
Mongo analogue**. The honest count is five corrections, not zero.

### Divergence 3 — packaging

Everything in the tree that exists *because* a driver is an optional extra is
absent for Fluree. Named exhaustively so the gate script's evidence block can
assert the absences: no `[project.optional-dependencies]` entry
(`pyproject.toml:61-77`); no `[[tool.mypy.overrides]]` block
(`pyproject.toml:167-208`); no lazy in-constructor import
(`neo4j.py:219`, `mongo.py:290`); no deferred module import in the boot branch
(`boot.py:172-175`, `:192-197`); no `# noqa: PLC0415` anywhere; no change to
`ci.yml:141`; no "requires the optional `X` extra" clause in the pytest marker.
**Seven absences. Each is SUBQ-14 evidence, and each is cheap to assert.**

The real insertion counts are 52 / 15 / 5 / 40.

recorded so a future reader does not re-derive it.)*

three of the four files, because total-changed ≥ added for every file. D-IMPL-92
layer 2 rule (3) says "per-file **added-line** budgets", so the gate should
count the first `--numstat` column. **No budget needs changing on correctness
grounds.** But three things follow:

1. **State the true baseline in the gate script.** The comment beside each
   budget should read "mongo precedent: 52 added" not "63", so a future

   stated derivation is wrong is a budget nobody will trust when it fires.

2. **`tests/conftest.py` at ≤ 45 is the one to watch.** It is the only file

3. **`boot.py` will carry deletions, and that is expected.** The mongo landing
