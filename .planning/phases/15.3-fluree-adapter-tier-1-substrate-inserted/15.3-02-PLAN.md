<objective>
Build the store envelope and the JSON-LD buffered-batch write path, then register
the backend through the minimum surface the existing boot and deployment
mechanism requires — and prove it against the suite that **owns** the write
semantics rather than inferring it from a neighbour.

Purpose: this is the half of the adapter that D-IMPL-88's one-sentence hedge was
written for. `_GraphTxn` states its contract in terms of *observable results*
("returns rows actually changed, resolvable before commit") rather than
*mechanism*, which is why one Protocol covers a held Postgres transaction, a
buffered pymongo bulk write, and a single JSON-LD POST. A Protocol that had
leaked `cursor.rowcount` upward would have foreclosed every HTTP substrate
permanently. Landing `_FlureeTxn` without touching the Protocol is that hedge
paying off, and it is SUBQ-13's whole content.

**Any impulse to introduce a new neutral abstraction for this phase is a signal
something was misunderstood, not a gap.** The nine typed operations are already
CCF's store-independent mutation IR.

Output: `FlureeGraphStore`, `_FlureeTxn`/`FlureeGraphWriter`/
`_fluree_claim_projection`, the four Tier-B registration edits with `make
schemas` regenerated, and `12 passed` under `-m fluree` on
`tests/conformance/test_graphstore.py`.

**Zero packages installed.** `httpx==0.28.1` is a core pin (`pyproject.toml:44`),
so `import httpx` goes at module top with the other imports — no
`# noqa: PLC0415`, no lazy in-constructor import, no deferred module import in
the `boot.py` branch, no optional-dependencies entry, no mypy override. Every
one of those absences is deliberate SUBQ-14 evidence.
</objective>
