## BF-1, as implemented: how interposition makes the cuts expressible

The break, restated in one line: **a Fluree Cypher relationship over plain RDF
triples has no properties**, and the only bounded variable-length pattern the
engine admits is a **single fixed relationship type**. So on plain edges neither
the crossability cut nor the type cut has anywhere to live.

The write path (wave 2, untouched here) already stores every CCF relationship as

```
(:CcfEntity {ccf_admit_key: "e:<uri>"}) -[:CCF_LINK]- (:CcfEdge {ccf_admit_key: "r:<key>"}) -[:CCF_LINK]- (:CcfEntity {ccf_admit_key: "e:<uri>"})
```

and the walk reads exactly that:

```cypher
MATCH p = (seed:CcfEntity {ccf_partition: $partition, ccf_tenant_id: $tenant})-[:CCF_LINK*1..2d]-(x:CcfEntity)
WHERE seed.ccf_admit_key IN $starts
  AND all(n IN nodes(p) WHERE n.ccf_partition = $partition
          AND n.ccf_tenant_id = $tenant
          AND n.ccf_admit_key IN $admissible)
RETURN DISTINCT x.ccf_entity_uri AS entity_uri
```

Where each cut went:

| Cut | Where it lives now |
|---|---|
| **Type** (`GQ-10` typed crossability) | The **edges statement**, as `rc.ccf_relationship_type IN $types` on the `CcfRelationshipClaim` **node**. This looks like a relationship read and is not — which is why it survived Break 1 untouched, and why the walk needs no type cut of its own and so never needs the deferred bounded type-alternation |
| **Crossability** (temporal, policy, validity, `allowed_entities` on both endpoints, endpoint closure) | Also the edges statement. `$admissible` carries `r:`-prefixed keys of exactly the rows that statement returned — **membership in an already-computed set, never a re-derivation.** A re-derivation would be a second place for the semantics to live, and the two would eventually disagree (`backends/mongo.py:862-873`). Secondary "shortcut" relationships are rejected outright and the fragment's comment says so, so a future reader need not re-derive it |
| **Hop admissibility** (`GQ-13`) | ONE node predicate over ONE prefix-namespaced parameter list. The `e:` / `r:` prefixes are what make an `entity_uri` incapable of colliding with a `relationship_key` |
| **The uniform rule** (`GQ-15`) | Python: `survivor_uris & q.allowed_entities` before building `$admissible` — the D-IMPL-87 resurrection defect held shut in the term that expands the walk |

**One predicate on both legs.** `CCF_LINK` and nothing else. A two-type shape
(`HAS_EDGE`/`TO`) would have required the deferred bounded type-alternation and
reintroduced the very constraint being escaped; that option was considered,
rejected, and the rejection is stated in the fragment's own comment block.

**No direction doubling.** Cypher's `-[:T]-` is first-class undirected, so the
interposed model is written **once** — strictly cheaper than the Mongo write
path, which must store every edge forward and reverse because `$graphLookup` is
directed.

### Mongo's four corrections, as they actually landed

| # | Correction | Outcome here |
|---|---|---|
| 1 | Directedness doubling | **Structurally immune** — measured: the layout test asserts exactly two `CCF_LINK` triples, and three would mean a doubled write |
| 2 | Seed exclusion | **Transfers verbatim** (`reached = set(starts)`) — really Neo4j's correction, not Mongo's |
| 3 | `depth_limit == 0` skips the stage | **Transfers verbatim** — `*1..0` is not a bound, so depth 0 answers with the starts and never issues the `MATCH` |
| 4 | `maxDepth: depth_limit - 1` | **Structurally absent** (Cypher's `*1..N` is 1-based) but **REPLACED** by `M = 2d` — the same class of error, which is why it was measured rather than reasoned about |

Plus the three Fluree-specific breaks, which have no Mongo analogue. **The honest
count remains five corrections, not zero.**

## The depth doubling, measured at four depths BEFORE promotion

`test_fluree_interposed_depth_matches_the_fallback_at_zero_one_two_and_three`
runs a **three-hop** chain — deliberately one hop longer than the corpus's — so a
doubled bound over-reaches by exactly one CCF hop and a halved one under-reaches
by one. Both are invisible until depth 3 is asked.

| CCF depth | Rendered pattern | Reached (fluree) | Reached (memory) |
|---|---|---|---|
| 0 | *(no `MATCH` issued)* | `{seed}` | `{seed}` |
| 1 | `-[:CCF_LINK*1..2]-` | `{seed, mid}` | `{seed, mid}` |
| 2 | `-[:CCF_LINK*1..4]-` | `{seed, mid, target}` | `{seed, mid, target}` |
| 3 | `-[:CCF_LINK*1..6]-` | `{seed, mid, target, far}` | `{seed, mid, target, far}` |

`canonical_bytes` equal at all four depths, and the reached sets are asserted
**both** against the control and literally — so a control that silently broke in
the same direction could not make the test pass.

`_reach_pattern` is unit-asserted at CCF depth 1 → `-[:CCF_LINK*1..2]-`, CCF
depth 3 → `-[:CCF_LINK*1..6]-`, and `MAX_DEPTH_CEILING` → `*1..200`; bools,
negatives, zero and over-ceiling all raise.

## Deviations from Plan

### 1. [Rule 2 — Missing critical functionality] The walk must carry partition/tenant scope

- **Found during:** Task 1, writing sub-assertion (f) — before the walk existed.
- **Issue:** The plan's normative walk text is
  `MATCH p = (seed:CcfEntity)-[:CCF_LINK*1..M]-(x:CcfEntity)` with
  `WHERE seed.ccf_admit_key IN $starts AND all(n IN nodes(p) WHERE n.ccf_admit_key IN $admissible)`
  — no scope terms. But D-03 puts every partition of every fabric in **one
  ledger**, and every `fabric_boot(backend="fluree")` reuses the same
  `ENTITY_POOL` URIs under a fresh partition. So an unscoped
  `seed.ccf_admit_key IN $starts` matches that URI in **every partition
  present**: measured at **175 matches against 1** on the probe container.
- **Fix:** the inline map on the seed *and* `n.ccf_partition = $partition AND
  n.ccf_tenant_id = $tenant` inside the path predicate — which is exactly what
  `backends/neo4j.py:411-427` does, so this is faithful porting rather than
  invention. Admissibility is still `n.ccf_admit_key IN $admissible`: one
  predicate over one prefix-namespaced list, as the plan's `key_links` require.
  The added terms are *scope*, not admissibility.
- **Honest note on severity.** With an `$admissible` set the adapter *currently*
  produces, no leak was demonstrable: the set is computed from the scoped
  survivors and edges statements, so it names only keys the querying graph
  holds, and a relationship key determines its endpoints. The demonstrated leak
  (F-A3(f.2)) needed a deliberately foreign `$admissible` set. **That is the
  reason to fix it, not a reason not to.** The confinement must be a property of
  the *statement*, not a side effect of how a parameter happens to be computed
  in another function — and "no leak today" is precisely the kind of accident
  that stops being true later (threats T-15.2-03 / T-15.2-26).
- **Files:** `src/ccf/graph/backends/fluree.py`, `tests/graph/test_fluree_backend.py`
- **Commits:** `cd0b898` (the measurement), `94b6566` (the fix)

### 2. [Rule 3 — Structural] The `e:` / `r:` prefixes live on both sides of the CINV-02 boundary

Identical in shape to wave 3's Deviation 2, with a worse failure mode. The write
half (`_ENTITY_ADMIT_PREFIX` / `_RELATIONSHIP_ADMIT_PREFIX` in
`ccf.graph._writer`) and the read half must agree exactly, but the import can only
run one way: `_writer.py` imports `backends/fluree.py`, and the reverse would both
cycle and violate CINV-02.

Moving the constants into `backends/fluree.py` and importing them from
`_writer.py` is structurally strongest — and it **deletes lines from
`_writer.py`**, disturbing wave 2's measured `864 added / 0 deleted` SUBQ-13
headline in a phase with an explicit change-surface gate. Wave 3 set the
precedent: **duplicate and bind with an executable assertion.**
`test_the_write_path_materializes_exactly_the_admit_keys_the_walk_pushes` reads
both keys back **off the server** and compares them against the read-side
constants.

Why the failure mode is worse than the policy key's: a drifted prefix makes
`all(...)` false for **every** path — an empty reached set, a `200`, and no
error, indistinguishable from a correct empty answer without telemetry. That is
do-not-copy #1's failure arriving through a different door.

`git diff --numstat 7d94117 HEAD -- src/ccf/graph/_writer.py` **prints nothing.**

### 3. [Criterion vs. file] `grep -c 'relationships(p)'` fired on the prohibition itself
