## Sampling Rate

- **After every task commit:** `make lint typecheck` + `pytest tests -q -m "not postgres and not chroma and not neo4j and not mongo and not fluree"` — the quick suite must stay green from Wave 1 (`ci-core`'s standing rule).
- **At the stage-1 → stage-2 boundary:** `make leg-fluree` **must be green before any promotion code is written**, and probes F-A2/F-A3 must have run. The promotion gate is byte-identity over the full corpus (D-04) — measured, never expected.
- **Before `/gsd:verify-work`:** full suite green.
- **Phase gate:** `make ci` + `make legs` (four legs) + `make gate-15.3`, all re-verified **on `main` after merge**, not inherited from a worktree run (`DI-15.2-04`, and the 15.2 gate's own precedent).
- **Max feedback latency:** ~90s for the quick suite.

## The six validation layers

Recorded here because the per-task map below is meaningless without knowing which
layer a given test belongs to — and because layer 2 is a documented trap.

| # | Layer | What it proves | Observable signal | What it does **not** prove |
|---|-------|----------------|-------------------|----------------------------|
| **1** | Probes F-A1 / F-A4 / F-A5 / F-A6 run **before** dependent code (D-06) | The three silent-failure assumptions hold on the pinned server | Explicit assertions in `tests/graph/test_fluree_backend.py`; raw responses recorded in the plan SUMMARY | Nothing about conformance — these are existence proofs about the substrate |
| **2** | Differential byte-identity — `fluree` param in `test_substrate_differential.py` over the full corpus | Answers are byte-identical to the audited fallback oracle | `pytest -m fluree` green; `canonical_bytes` equality per case | **Nothing about pushdown.** Under D-04/`GQ-34` a `_translate_query` that always returns `None` passes this entire layer. This is the trap the 15.2 §3.1 review caught on Neo4j. |
| **3** | Pushdown telemetry, falsification-tested — `test_fluree_traversal_is_pushed_not_silently_degraded` | The translation actually ran in the engine | `reader.translated_answers == N and reader.fallback_answers == 0` across four trap shapes (depth-0, depth-1, out-then-in depth-2, resurrection), with `memory` as differential control | Not correctness — layer 2 owns that. Both are required. Template: `tests/graph/test_neo4j_backend.py::test_cypher_traversal_is_pushed_not_silently_degraded`. Falsification method of record: monkeypatch `_translate_query` → `None`, confirm layer 3 fails while layer 2 stays green. |
| **4** | The six D-IMPL-34 write semantics — `fluree` param in `test_graphstore.py` (D-05) | Compound identity, append-only supersession, lineage set-union, tenant isolation, first-class edges, idempotent re-arrival — asserted by the suite that *owns* those semantics | 12 passed under `-m fluree` (neo4j/mongo/postgres legs each report 12) | Nothing about the transaction *mechanism* — layer 5 covers confinement |
| **5** | Single-writer + write confinement | No write code outside `ccf.graph._writer`; exactly one writer per graph | `make lint` exit 0 (`cinv02-graph-writer` AST-walk rule); `tests/invariants/test_single_writer_boot.py` | Nothing Fluree-specific — a standing invariant the new backend must not break |
| **6** | The no-refactor gate + the always-on leg on `main` | The diff surface is what the claim says; the leg is continuously proven | `make gate-15.3` exit 0 with base SHA recorded; `Fluree leg` step green on `main` after merge | It proves a fact about *this* diff, not a general architectural property. The gate package must say so. |
