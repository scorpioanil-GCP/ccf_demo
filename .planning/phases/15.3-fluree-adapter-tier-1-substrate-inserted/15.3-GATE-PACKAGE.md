> **Adding a real substrate touched one new module, one writer class, and a
> bounded one-line extension of four existing enumerations — no mechanism

This is D-IMPL-92's wording, and it is deliberately weaker than Phase 15.3

outcome D-10 exists to prevent. A claim that survives contact with the tree is
worth more than a stricter one that cannot.

## 9. What the gate found — three corrections, and a recursion

The gate exited 1 three times against real work. **Every one of them changed
`D-IMPL-92` rather than the diff**, because in every case the *normative rule*
already permitted or forced the change and the *mechanical proxy* had
enumerated one instance of a class the rule states in general terms. Each is a
dated correction appended to `docs/DECISIONS.md`; none is an edit to a prior
entry.

| # | The gate said | The rule already said | The proxy gained |
|---|---|---|---|
| Q1 | `tests/graph/test_mongo_backend.py (+3/−0)` not in the allowlist — three `fluree_url=None,` lines forced by a new required keyword on `_preflight_backend` | "backend-specific unit tests … were never inside D-11's `src/ccf`-scoped hard line and are **free**" | the **class** `tests/graph/test_*_backend.py`, not the offending file — a special case would repeat the under-enumeration being fixed |
| Q2 | `tests/conformance/test_graphstore.py (+2/−1)` — one line outside the permitted shapes: the fixture's backend set-membership guard, without which the added param raises `NotImplementedError` | the same reasoning that produced the `#:` comment-block permission for the *other* suite, which has no `#:` block to reach | **one forced one-line enumeration extension** per suite, bounded mechanically (identical once string literals are removed; literals differ by exactly one; that one derived from the `backend` `Literal`) |
| Q3 | `docs/DECISIONS.md (+2/−0)` not in the allowlist — **the record of the fix for Q1 and Q2** | "was never inside D-11's `src/ccf`-scoped hard line"; and CLAUDE.md §11 makes logging a `D-IMPL` ruling **mandatory** | `docs/DECISIONS.md`, bounded **append-only** |

**The recursion in Q3 is the durable lesson, more than any of the three paths.**
Recording the correction for an under-enumeration *itself created a new
under-enumeration*. Substrate #7 should expect the shape rather than memorise
the paths: **any enumeration written by hand against a rule stated as a
category will under-enumerate, and the enumeration inside a gate is no more
exempt from that than the enumeration inside `boot.py` that BF-1 found.** The
gate's own allowlist is a registration enumeration; it under-enumerated three
times, and each time the fix was to name the class.

**Why Q3 is bounded append-only rather than simply allowed.** The
D-IMPL-86/-87/-92 discipline is that a correction is *appended and dated, never
edited into the entry it corrects, so the reasoning at each point in time
survives*. A bound of zero deleted lines encodes that discipline
**mechanically**: the entry stays a check that would still fire if someone
rewrote decision history, rather than becoming a hole in the surface. A
documented discipline nothing enforces is the same class of object as an
unfalsifiable architectural claim — which is what this whole gate exists to
convert. Verified: see negative test 8 in `15.3-05-SUMMARY.md`, where a
deletion in `docs/DECISIONS.md` is a `gate153-append-only` finding.

**Broadening Tier C to `docs/**` was considered and rejected.** It is tidier
and it is wrong: it would free `docs/GRAPH_QUERY_SEMANTICS.md`, whose freeze
this same ruling makes a hard line and which the gate asserts byte-untouched
across the phase. Real coverage traded for a shorter allowlist. Recorded so a
future reader does not "simplify" the entry into the hole it was designed to
avoid.

**A second, independent defence, found by running the negative test rather than
reasoning about it.** Deleting a line from `docs/DECISIONS.md` also turned
`make lint` red: two `cite02-anchor` citations in `src/ccf/graph/protocols.py`
and `src/ccf/projection/engine.py` point at `docs/DECISIONS.md:290`, and the
deletion shifted the anchor out from under them. Rewriting decision history is
therefore caught twice, by two mechanisms that know nothing about each other —
this gate's append-only bound and the standing citation lint the gate cites.

## 13. The limits of this claim, stated rather than implied

**This package proves a fact about THIS diff. It is not a general property of
the architecture, and it must not be read as one.**

- **The interposed traversal's equivalence to CCF BFS *in general* is a
  graph-theoretic argument**, and it is proved here only empirically, at corpus
  scale, against one oracle. Byte-identity over the generated corpus is strong
  evidence and is not a proof of universal equivalence.
- **The path-enumeration caps' behaviour in production depends on deployment
  graph density.** The caps *error* rather than truncate (Pitfall 11), so a
  denser graph than the corpus can turn a passing query into a loud failure.
  This is a named residual, not a solved problem.
- **A future Fluree release may break the adapter.** The scheduled drift job
  catches **patch** drift only: `4.1` resolves to `4.1.4` today, so the job is
  a **no-op until 4.1.5 ships** — a first green run proves the job works, not
  that no drift exists — and a `4.2.0` would pass unnoticed. The `4` tag would
  have caught it; D-09 says `4.1`, so `4.1` is what runs, and the gap is made
  visible rather than assumed away.
- **The budgets are an admitted proxy** for "extension, not modification",
  to be tightened to a direct AST check if any future phase finds them
  gameable.
- **The gate is phase-local and expected to be superseded**, not extended into
  a standing rule. It lives in `tools/gates/`, not `tools/lints/`, for exactly
  that reason (D-10).

**The claim's value is that it is falsifiable, not that it is universal.** The
gate was watched to fail eight times, on eight distinct violations, before it
was believed once — and **three of those failures were real findings that
changed `D-IMPL-92` rather than the diff** (§9). A gate that had passed on its
first run would have proved considerably less.

## 14. Re-verification

**Every number in §3–§5 and §11's second table was measured in a git worktree
and is PROVISIONAL.** DI-15.2-04 is the recorded reason: a worktree's `.venv`
symlinks to the main checkout's venv and the editable finder's `MAPPING` is
hard-coded, so a bare invocation imports the *main checkout's* source and every
conclusion drawn is wrong in the same direction. The gate's own self-tree
assertion confirms this run imported the worktree's `ccf`
(`…/agent-a7c3bd7b4f092e22c/src/ccf/__init__.py`) — the strongest statement a
worktree run can make about itself, and still not the same statement as a run
on `main`.

**Re-running `make gate-15.3` on `main` after merge is the phase gate's
obligation, and the numbers here must never be inherited from a worktree run.**
The precedent is the 15.2 gate's own discipline: *"re-verified on `main` at
`597171b` after merge — not inherited from worktree runs."*
