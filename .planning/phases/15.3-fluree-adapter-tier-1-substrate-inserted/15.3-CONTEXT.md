# Phase 15.3: Fluree Adapter (Tier-1 Substrate) - Context

**Gathered:** 2026-08-08
**Status:** Ready for planning

<domain>
## Phase Boundary

CCF's Context Graph runs on **Fluree v4** as a tier-1 storage substrate,
through the Phase 15.2 seams and **only** through them: `GraphReader.query(
GraphQuery) → GraphView` on the read side, the nine typed `_GraphTxn`
operations on the write side. Zero change to the SDK core, the `GraphQuery`
vocabulary, the `SourceAttestation` contract, or the conformance suites'
semantics.

The phase delivers two things at once, and the second is not decoration:

1. **A working adapter** — `src/ccf/graph/backends/fluree.py` plus
   `_FlureeTxn` in `ccf.graph._writer`, going green against the unchanged
   15.2 differential and six-semantics suites.
2. **The 15.2 no-refactor claim, demonstrated on a real substrate.** An
   adapter added post-gate whose entire suite-side diff is one
   `pytest.param` line per suite is the proof that "adding a substrate needs
   no SDK refactor" is a fact about the architecture, not a claim about it.
   D-10/D-11 below make that mechanically checkable rather than narrated.

**Not in this phase** (locked by prior rulings, restated so planning does not
drift into them):

- **No v2 support** — ever, not deferred. No dual-line abstraction, no
  version-negotiation seam (D-IMPL-91).
- **Fluree is not a foundation.** CCF stays substrate-neutral; Fluree is an
  adapter (here) and a *source* (MCP ingress today, tier 3 later, still
  deferred) (D-IMPL-88).
- **Tier-3 external sources stay deferred** — reading the institution's
  pre-existing Fluree KG is *not* what a tier-1 adapter delivers.
- **No Fluree capability reaches the seam** — native time travel, branching,
  SHACL, vector/BM25 graph sources are all unreachable through `GraphQuery`
  and must stay that way.
- **No new Python dependency.** `httpx==0.28.1` is already a core pin; no
  extra, no lazy import, no mypy override.

</domain>

<decisions>
## Implementation Decisions

### Write path

- **D-01 — Buffered batch, one commit.** `_FlureeTxn` accumulates the nine
  typed operations and commits as a **single POST**; nothing reaches the
  server until commit. Per-operation rowcounts resolve by *read-before-buffer*
  — sound precisely because `INV-CH7-10` single-writer guarantees no
  concurrent writer can invalidate the pre-commit read. Bolt explicit
  transactions rejected (Fluree's docs: explicit transactions require a
  single-node server; Raft/peer deployments reject `BEGIN` — a landmine for
  exactly the enterprise clusters motivating this adapter, and it would
  couple Fluree to the `neo4j` extra). Per-op autocommit rejected (abandons
  write atomicity).
  **This ratifies D-IMPL-88 precondition (b) — the last precondition
  standing. With it, Phase 15.3 is unblocked for planning.**

- **D-02 — JSON-LD writes, Cypher reads.** Each side uses the native path
  that actually works on this engine:
  - **Writes:** Fluree's own primary write path — JSON-LD
    `insert`/`delete`/`where`, one POST, atomicity native. No mapping through
    a query language.
  - **Reads:** openCypher. Not a preference — SPARQL 1.1 **cannot express
    bounded-depth repetition at all**, so Cypher is the only viable traversal
    target (research Q4).

  **Hard condition, not a note.** The adapter owns a **fixed minimal
  `@context` with zero datatype coercion** and creates the ledger with **no
  default context**. A `@context` that types a timestamp as `xsd:dateTime`
  silently destroys lexicographic-equals-chronological comparison, and
  byte-identity against the fallback dies with it — the failure mode is
  scattered as-of divergences, not an error. Probe **F-A5** verifies strings
  land as `xsd:string` before any code depends on it.

  *Superseded during discussion:* an earlier Cypher-for-writes recommendation
  (symmetry with `_Neo4jTxn`) was **withdrawn**. It privileged the Neo4j shape
  over Fluree's native model and leaned on Cypher-writes-onto-RDF, the thinner
  surface on that engine. Recorded so planning does not re-derive it.

- **D-03 — One CCF-owned ledger; `partition` + `tenant_id` as predicates.**
  Exactly the Neo4j and Mongo posture: `(partition, tenant_id, entity_uri)`
  is the compound identity, carried as properties inside one physical
  container. `graph_identity` = host/port/ledger#partition, **credential-free**
  (threat T-15.2-05, the T-04-24 postgres precedent). Ledger-per-partition and
  ledger-per-tenant both rejected for v1: each makes `Fluree-Min-T` per-ledger
  state, forces dynamic ledger lifecycle in CI, and diverges from how the
  other four backends realize the same concept.

### Pushdown

- **D-04 — Both stages ship, staged within the phase.** Mirrors what Mongo
  actually did (`backends/mongo.py:835`).
  - **Stage 1:** non-traverse pushdown (property filters +
    `allowed_entities` as a Cypher `$param` list) with **fallback traversal**.
    Fully conformant under D-04 of 15.2 — this is a working floor from the
    first task, so a stage-2 failure degrades to a shipped stage 1, never to
    nothing.
  - **Stage 2:** bounded **undirected** Cypher variable-length traversal, hop
    admissibility via `all(n IN nodes(p) WHERE ... AND n.entity_uri IN
    $allowed)`. **Promoted only at byte-identity over the full corpus
    including resurrection shapes.**

  Research expects this to go better than Mongo's: Cypher has no directedness
  doubling, no `maxDepth` off-by-one and no seed exclusion, so the four
  `$graphLookup` semantic corrections Mongo needed may not arise. Do not
  assume it — the promotion gate is byte-identity, not expectation.

- **D-05 — `fluree` joins BOTH suites.** One `pytest.param` line in
  `tests/conformance/test_substrate_differential.py` (byte-identity against
  the fallback oracle) **and** one in `tests/conformance/test_graphstore.py`
  (the six D-IMPL-34 write semantics). DI-15.2-02 established the second when
  it widened that fixture to all five backends at the 15.2 close; leaving
  fluree out would recreate exactly the asymmetry that entry closed.

- **D-06 — Split probe timing.** The five research `[ASSUMED]` items divide
  by *consequence*, not by convenience:
  - **Up front, in the phase's first task** — `F-A1` (container round trip),
    `F-A4` (conditional insert + `flakes_added` actually satisfies the
    `_GraphTxn` rowcount contract), `F-A5` (no datatype coercion). These two
    latter probes gate everything and **fail silently** — a wrong F-A5 still
    "works," it just stops being lexicographic. Nothing may be built on them
    unverified.
  - **At the stage-2 promotion** — `F-A2` (whether Cypher var-length bounds
    accept `$param` or need a validated integer literal) and `F-A3` (whether
    `all(r IN relationships(p) WHERE type(r) IN $types)` substitutes for the
    deferred `[:A|B*1..3]` form). Both bind only at stage 2 and **fail
    loudly**, with workarounds already named in the 15.2-12 plan.

  Precedent for treating pre-committed probes as load-bearing: plan 15.2-08's
  mandatory A5 probe **falsified its assumption** and produced D-IMPL-89 — a
  genuine replay defect caught because the probe ran before the code.

- **D-07 — Pre-committed falsification ladder, with rung 3 named concretely.**
  1. Use the documented workaround (F-A3 → untyped bounded pattern +
     `all(r IN relationships(p) WHERE type(r) IN $types)`; F-A2 →
     validated-integer literal at one documented site, Pitfall 7).
  2. Workaround also fails → **ship stage 1** and record a `DI-15.3-NN`
     deferred item.
  3. **STOP and raise a `D-IMPL` only if the finding would change what
     `as_of` MEANS on this substrate — not merely how it is expressed.**

  Rung 3 is worded that precisely on purpose: it removes the executor's
  classification judgment. An engine limitation with a documented workaround
  is rung 1, always. A semantics question reaches Dave, always.

### CI and pinning

- **D-08 — Fourth always-on service in `ci.yml`.** A `fluree/server` service
  block gated on `GET /health`, a `CCF_TEST_FLUREE_URL` env var mirroring
  `CCF_TEST_NEO4J_URI`/`CCF_TEST_MONGO_URI`, its own `pytest -m fluree` step,
  and the existing rule applying unchanged: **a skipped leg in CI is a
  failure, not a minimal environment.** The install step does **not** change
  (`pip install -e ".[dev,neo4j,mongo]"` stays as-is) because httpx is core.
  Operationally the lightest of the four legs: ~63–70 MB, Rust binary, seconds
  to start, auth off by default, ephemeral mode is the default.

  Rejected: an opt-in `live-legs.yml` leg — it would make Fluree the one
  backend whose conformance is not continuously proven, which is precisely the
  claim this phase exists to make. Also rejected: always-on but non-blocking
  at first — D-07 of Phase 4 forbids making a step non-blocking to hide a gap,
  and this would be that move under a different name.

- **D-09 — Exact pin + scheduled drift detector.** `ci.yml` pins
  `fluree/server:4.1.4` exactly; bumps stay deliberate acts requiring a
  differential re-run (the A1-style discipline the neo4j image already gets).
  **Additionally**, a scheduled `live-legs.yml` job runs the same differential
  against the floating `4.1` tag, so an upstream break is discovered on its own
  schedule rather than in the middle of someone else's phase. Justification:
  five patch releases April–July 2026 and **4.1.3 shipped breaking SPARQL
  changes inside a minor**; the research's own freshness note expires around
  2026-09-06.

  **Planning obligation:** re-verify the current v4 version and Cypher feature
  list at plan time — the research says so explicitly, and 4.1.4 may not be
  current by then.

### No-refactor evidence

- **D-10 — Mechanically checked, not narrated.** A phase-gate script
  enumerates the permitted change surface and **fails on anything outside it**:
  - `src/ccf/graph/backends/fluree.py` (new)
  - `_FlureeTxn` + `FlureeGraphWriter` in `src/ccf/graph/_writer.py` — CINV-02
    requires every backend's write code to live in that module and nowhere else
  - one `Literal` member in `src/ccf/controlplane/artifacts.py:968`
  - one `pytest.param` line in each of the two conformance suites
  - CI / Makefile / pytest-marker config

  Committed **with the gate package**, so the claim is reproducible rather
  than remembered. It lives with the phase rather than in `tools/lints`,
  because it asserts a fact about one phase's diff, not a standing invariant.

- **D-11 — What counts as violating the claim.**
  - **Hard line:** nothing under `src/ccf` changes except the adapter module
    and the `_writer.py` additions. A change anywhere else *is* the refactor
    the claim denies.
  - **Softer line on tests:** the two `pytest.param` additions are expected. A
    corpus addition is **permitted but must be recorded in the gate package**
    with why it was needed and whether it exposes a gap in the 15.2 corpus
    rather than a Fluree quirk.

  The distinction being preserved: *"the SDK bent"* is a failure; *"the corpus
  grew"* may be a finding about 15.2's coverage. Collapsing them would pressure
  an executor toward not adding a fixture that ought to be added.

  **`docs/GRAPH_QUERY_SEMANTICS.md` (1.0.1) must not change.** Fluree
  implements existing clauses and cites the same `GQ-NN` anchors. This is not
  merely preferred: the citation gate carries **line numbers** into anchored
  cites across `/src` and `/tests`, and the 15.2 record notes a naive insert
  near the top produced **124 citation-guard findings in one edit**. If an
  amendment turns out to be genuinely necessary, it goes in the `GQ-35`
  amendment lane, line-number-neutral, per the discipline stated in that
  document's own preamble.

### Requirements

- **D-12 — Requirement IDs extend the SUBQ lane: `SUBQ-12`..`SUBQ-14`.**
  `SUBQ-08` already reads "five adapters answer `GraphQuery` under both
  suites"; a sixth is the same requirement family, and one coverage lane stays
  one lane. The framing argument decided it: this phase's entire claim is that
  adding a substrate is *routine*, and minting a new requirement lane for it
  would quietly contradict that. A vendor-named `FLUR-NN` lane was rejected
  additionally as a substrate-neutrality smell that outlives the phase.

  Proposed shape for the planner to finalize (text is planning's to write,
  the lane and the count are settled here):
  - **SUBQ-12** — the fluree backend answers `GraphQuery` under both
    conformance suites, stage 1 conformant on its own and stage 2 promoted
    only at byte-identity over the full corpus.
  - **SUBQ-13** — the JSON-LD buffered-batch write path satisfies `_GraphTxn`
    with rowcounts resolved pre-commit, preserving single-writer
    (`INV-CH7-10`/CINV-02) with no write code outside `ccf.graph._writer`.
  - **SUBQ-14** — the no-refactor claim is mechanically demonstrated: the
    permitted-change-surface check passes, and the always-on container leg is
    green on `main`.

### Claude's Discretion

Taken as implementation detail below the seam; planning need not re-open these:

- **Read-before-buffer mechanics.** Per-identity reads issued the way
  `_MongoTxn._held()` does. Round-trip count is a performance question, and
  performance is never a replay input.
- **Read-after-write.** The store threads the last commit `t` into subsequent
  reads via the `Fluree-Min-T` header (or `opts.min-t`), so the differential
  suite cannot flake against an eventually-indexed read path. Named research
  pitfall 2 — not optional, but the mechanism is unremarkable.
- **`leg-fluree` Makefile target** added alongside `leg-postgres`/`leg-neo4j`/
  `leg-mongo` and joined to the `legs` aggregate (DI-15.2-04 precedent).
- **`fluree` pytest marker** registered; no extra, no lazy import, no mypy
  override — httpx is core.
- **Production auth.** Bearer token env-templated in the manifest connection
  field; never in `graph_identity` (T-04-24 precedent). CI needs none — v4
  auth is off by default.

## Existing Code Insights

### Reusable Assets

- **`_MongoTxn` (`_writer.py:1904`)** — the buffered-batch shape whole:
  per-target ordered operation lists, `_insert_once` as
  `ON CONFLICT DO NOTHING`, `_held()` for the pre-buffer committed read,
  `_arrival_index()` for the chain tiebreak, and own-buffer merging in
  `select_*_chain`. `_FlureeTxn` is this structure with a different commit
  primitive.
- **`_Neo4jTxn` (`_writer.py:1566`)** — the nine operations expressed against
  a graph (not document) model.
- **`Neo4jGraphReader._translate_query` (`backends/neo4j.py:585`)** and
  `_reach_pattern` (`:451`) — the Cypher read translation, including the
  bounded-pattern expansion the Fluree read path mirrors.
- **`_graph_identity` (`backends/neo4j.py:168`, `backends/mongo.py:195`)** —
  credential-free identity derivation; copy the shape, not the string.
- **`ccf.graph.fallback`** — answers anything not pushed. Stage 1 depends on
  it for traversal and it needs no modification.

### Established Patterns

- **The neutral IR already exists.** `_GraphTxn`'s nine typed operations are
  CCF's store-independent mutation IR, and `GraphQuery` is the read-side
  equivalent (canonically serializable — 15.2-08 pins the query bytes into the
  ArtifactStore as `ccf.graph-query` for replay). **Any impulse to introduce a
  new neutral abstraction for this phase is a signal something was
  misunderstood, not a gap.** Note also what the IR deliberately is *not*: it
  has no `deleteEntity` / `deleteRelationship` / `setProperty`, because the
  graph is append-only with logical supersession —
  `update_*_supersession` is documented as *"the only mutation ever applied to
  an existing claim (INV-CH7-04)."* A generic property-graph IR would be more
  portable and would break the invariants the fabric exists to hold.
- **Two-level scoping.** `(partition, tenant_id, …)` as compound-key
  properties inside one physical container, uniformly across postgres, neo4j
  and mongo. D-03 keeps Fluree on it.
- **CINV-02 write confinement.** Every backend's `*GraphWriter` / `*GraphTxn`
  lives in `ccf.graph._writer` and nowhere else; an ast-walk test proves it.
  No write operation may exist in `backends/fluree.py`.
- **Temporal fields are canonical RFC3339 text properties**, filtered in
  query. Native substrate temporal types are refused across every adapter —
  the byte-drift trap. Fluree's `t` is transaction time and **must not**
  implement as-of (D-IMPL-88; research Q5 gives the two divergence classes:
  late-arriving observations and data-supplied supersession timestamps).
- **Staged adapters are normal.** Mongo established that a stage-1 degrade
  posture satisfies the requirement and stage-2 promotion is a budgeted
  enhancement (see `SUBQ-08`'s own wording).

### Integration Points

- `src/ccf/graph/backends/fluree.py` — **new.** Store envelope, httpx client,
  credential-free `graph_identity`, adapter-owned JSON-LD `@context`, Cypher
  read translation, dict rows into the 15.2-03 materialization core.
- `src/ccf/graph/_writer.py` — **`_FlureeTxn` + `FlureeGraphWriter` only.**
- `src/ccf/controlplane/artifacts.py:968` — `backend` Literal gains `fluree`;
  connection field env-templated; `make schemas` regenerated.
- Boot exclusivity wiring — single-writer enforcement at boot, same shape as

- `tests/conformance/test_substrate_differential.py` and

- `.github/workflows/ci.yml` (service block, env, pytest step),
  `.github/workflows/live-legs.yml` (drift detector), `Makefile`
  (`leg-fluree`), pytest marker registration.

<specifics>
## Specific Ideas

- **The claim is a statement about a diff.** "The SDK needs no refactor to
  accept a new substrate" is normally an unfalsifiable architectural
  assertion. Reduced to "adding a real substrate touches only a backend
  module, a writer class, one `Literal` member and two `pytest.param` lines,"
  it becomes falsifiable — and therefore enforceable (D-10). That reduction is
  the phase's intellectual product as much as the adapter is.
- **Why the write-seam risk evaporated.** `_GraphTxn` states its contract in
  terms of *observable results* ("returns rows actually changed, resolvable
  before commit") rather than *mechanism*. That phrasing is why one Protocol
  covers a held Postgres transaction, a buffered pymongo bulk write, and a
  single JSON-LD POST with no version-shaped conditional anywhere. A Protocol
  that had leaked `cursor.rowcount` upward would have foreclosed every HTTP
  substrate permanently. This is the D-IMPL-88 one-sentence hedge paying off.
- **Probe consequence, not probe convenience, drives D-06.** F-A4 and F-A5
  gate everything and fail *silently*; F-A2 and F-A3 gate only stage 2 and
  fail *loudly*. Timing follows that asymmetry.
- **Native time travel is an auditor bonus, never a replay input.** A Fluree
  substrate gives auditors an independently immutable, content-addressed
  commit history *underneath* CCF's replay record — a genuinely good
  financial-services story. It is telemetry-tier value and must never be
  queried by the adapter's `query()` path.

</specifics>

<deferred>
## Deferred Ideas

- **Tier-3 raw external sources** — reading the institution's *existing*
  Fluree KG (data CCF never wrote). Explicitly deferred by D-IMPL-88 and the
  15.2 scope ruling; designed-for via 15.2's D-08 (another admission gate,
  same admitted wrapper) and D-09 (tier 3 is already an expressible value of
  the attestation schema). **A tier-1 adapter does not deliver this** — if the
  bank engagement actually wants it, that is a different phase, not a widening
  of this one.
- **Fluree as an L1 MCP-ingress source** — available today, configuration
  only, no new SDK code (D-IMPL-88 §2). Proceeds independently of and ahead of
  this adapter; not this phase's deliverable.
- **Exposing Fluree's native capabilities** — time travel, branching, SHACL,
  vector/BM25 graph sources. Unreachable through the frozen vocabulary by
  design. Any future move here is a `GraphQuery` vocabulary conversation, not
  an adapter decision.
- **A `fluree` leg in the Phase 11 perf battery** — raised and not pursued;
  pushed-vs-scanned telemetry covers what this phase needs, and performance is
  never a replay input.
- **Docs surface for the adapter** — backend documentation and a worked
  deployment manifest. Phase 16 owns the documentation rewrite against the
  post-15 surface; adding a doc lane here would collide with it.
- **Bolt as an alternative wire** — viable (Fluree speaks Bolt, the `neo4j`
  driver is already vetted) but rejected for v0: single-node-only explicit
  transactions and an unwanted coupling to the `neo4j` extra. Recorded so a
  future reader knows it was considered, not overlooked.
