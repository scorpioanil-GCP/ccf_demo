## Implementation notes a reviewer should know

**The base ref is a pinned literal SHA, not `git merge-base main HEAD`.** The
plan's recipe assumes the phase's work sits on an unmerged branch. It does not:
this workflow merges each wave into `main` as it lands, so by wave 5
`git merge-base main HEAD` resolves to `8cf1f16` — the phase's own post-wave-4
tip — and a recomputed base would measure an **empty diff**, i.e. a gate that
passes everything. The same is true of the post-merge re-verification on
`main`, where HEAD *is* `main`. `PHASE_BASE` is therefore
`96f54c55bef5469323d7cfc5fad3594f5bdd35a9` with its derivation stated in the
constant's own comment, which is also what R6 asks for ("record `$BASE` as a
literal SHA … so the claim is reproducible after `main` moves" — it has moved).
The gate prints both SHAs, says plainly when they differ and why, asserts the
pinned SHA is an ancestor of HEAD, and carries a `gate153-base-resolution`
check that **fails if the measured surface does not contain the adapter
module** — the guard against a mis-resolved base producing a vacuous pass.

**The schema check does not run `make schemas`.** D-IMPL-92 words the method as
"re-run `make schemas` and require a clean tree", but a gate whose first check
is *the working tree must be clean* must not itself dirty the tree. The gate
asserts the same fact side-effect-free: the generated `backend` enum equals the
`backend` `Literal` in `artifacts.py`. Full byte-for-byte regeneration drift is
already covered by the always-on
`tests/cli/test_schema_export.py::test_each_committed_schema_is_its_class_byte_for_byte`,
which the gate cites for the same reason it cites `cinv02-graph-writer` rather
than re-implementing it.

**`tests/conformance/query_corpus.py` is in the allowlist as its own tier
(`R`, recorded).** It has to be: the plan's own acceptance criterion requires
that adding the justification makes the corpus finding go away, which is
impossible if the path fails the allowlist check unconditionally. Blocked and
recorded are different, and the tier makes the difference visible.

**Two bugs found by running the gate and fixed** (both were gate defects, not
rule relaxations): the backend-name check assumed quoted string literals, but
`boot.py` carries the names as argument identifiers and docstring prose, so it
fired five false positives — it now asks the *base blob* which names that file
actually had; and stdout was not flushed before the stderr summary, interleaving
the output.
