<objective>
Implement the ruled v0 default `WireProtocol` — LF A2A on `a2a-sdk` — against the
abstraction 06-09 proved, and close the last transport gap in skill dispatch by wiring the
`a2a` binding type (D-05).

Purpose: D-IMPL-14 rules LF A2A as the default; D-11 sequences it second so the
abstraction and admission are already proven. LF A2A is at 1.0 under the Linux Foundation
with 150+ organizations and five official language SDKs, so this leg is not speculative
and must not be sized as such — but it does bring a protobuf surface, and the discipline
that CCF's own contracts are the typed boundary is what keeps C4 intact. Reimplementing LF
A2A's JSON-RPC dispatch, Agent Card discovery, or task lifecycle would forfeit the interop
that is the whole point of choosing it.
Output: `ccf_runtime.a2a.lf_a2a`, the exchange test parametrized over both transports, and
`a2a` skill dispatch.
</objective>

that `a2a.types.Part` has the fields `text, raw, url, data, metadata, filename,

Expected outcome from research: use `Part.raw` (bytes) with
`media_type="application/ccf-product+json"`, carrying the detached-JWS members in
`Part.metadata` or `Artifact.metadata`. `Part.data` is a protobuf `Struct` and round-trips
through Struct's JSON model, which breaks canonical byte equality and therefore the
signature. If the prototype shows `raw` also mutates the bytes, do not proceed on hope:
surface the finding and choose the placement that demonstrably preserves byte equality,
recording the reasoning in the module docstring and the SUMMARY.

type lives in this `/runtime` module and is converted to and from CCF's own contracts at
its edge. State in the docstring why: protobuf messages have neither Pydantic validation
nor `extra=forbid` semantics and silently preserve unknown fields rather than refusing
them, so the A2A message is transport and the admission gate validates the Context Product

| Boundary | Description |
|----------|-------------|
| Remote A2A peer → LF A2A transport | An untrusted peer's JSON-RPC/protobuf surface enters the process |
| a2a-sdk protobuf types → CCF contracts | Where an untyped, `extra`-permissive representation must be converted into a validated one |
| Skill binding endpoint → outbound network call | A binding value determines which peer the process contacts |

| T-06-54 | Tampering | A2A serialization mutating canonical bytes and thereby invalidating (or worse, silently re-scoping) the signature | mitigate | Assumption A2 resolved by prototype before implementation; byte-equality plus signature-reverification asserted as a standing regression test (Task 2) |
| T-06-55 | Spoofing | Malicious or spoofed Agent Card during peer discovery | mitigate | Peer admission depends on the detached-JWS `kid` bound to the trust-policy artifact, not on Agent Card contents; the gate verifies every inbound product with no fast path (D-IMPL-16) |
