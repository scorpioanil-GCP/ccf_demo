  <action>
Create `runtime/ccf_runtime/mcp/artifact_server.py` as a **separate module and a separate
`FastMCP` server instance** from `egress.py`. Per §7.1 and D-03 the two roles differ in
trust posture and must not share a module, a server object, or a resource namespace.
Configure it `stateless_http=True`.

Map the four `ArtifactStoreProtocol` operations per research Pattern 3 — the split is not
cosmetic, because MCP Resources are read-only and `put` mutates:
- `get(content_address) -> bytes` → templated **Resource** `ccf-artifact-blob://{content_address}`
  with a handler whose return annotation is `bytes`, producing `BlobResourceContents`
  (base64). A `str`-returning handler yields `TextResourceContents` and silently mangles
  canonical bytes that are not valid round-trippable UTF-8 — this is Pitfall 4 and it is
  the single most important shape decision in this task.
- `resolve_uri(uri) -> str` → templated **Resource**
  `ccf-artifact://{tenant}/{artifact_class}/{name}@{version}` returning the content
  address. Naming and identity stay two calls, as the Protocol docstring insists.
- `exists(content_address) -> bool` → a metadata **Resource** (or a Tool returning a
  declared Pydantic model) giving the client a structured, discriminable answer.
- `put(...) -> ArtifactRef` → a **Tool** named `put_artifact`, payload carried as base64
  in a field named `canonical_b64`. Declare a Pydantic return model on the tool so
  `structuredContent` is populated — research verified that a plain `-> dict` handler
  returns `structuredContent = None` and forces the client to parse `content[0].text`.

Per Pitfall 2, the server must return a signal the client can discriminate for "not
found" versus "unreachable". Implement absence as a positive structured answer (the
`exists` resource, or a typed `{"found": false}` structured tool result) so the client
never has to string-match an `McpError` message.

Per D-26, create `runtime/ccf_runtime/mcp/auth.py` declaring a token-source Protocol and
a file-backed **development** token source behind it, and wire a real `TokenVerifier`
into the artifact server's `FastMCP` construction. §7.4 says the artifact server sits
inside the tenant trust boundary but is authenticated; D-26 rules that v0 backs that with
mechanism rather than leaving it an unbacked claim. Real custody backends (PKI/HSM)
remain out of scope per §13, exactly as D-13 scopes A2A key custody — say so in the
docstring, in D-21 language: name what the reference implementation verifies and name
what a deployment must supply.

Module docstring carries the four mandatory `/runtime` blocks. Its "what this cannot do"
paragraph states that the artifact server is a persistence substrate reached through
Control Plane and L2 mechanism, holds no graph handle, and never becomes a second writer
to L3 (§7.4). Token values, key material, server names, and bind addresses are deployment
values — none may be literals (CINV-01, No-Hardcoding); dev token material must never be
committed.
  </action>

  <action>
Create `src/ccf/artifacts/mcp_store.py` declaring `McpArtifactStore`: a plain class, no
base class, keyword-only constructor taking the server URL and the shared sync facade
from `ccf.mcp.client` (injected, not constructed internally where the caller cannot close
it), presenting the four synchronous `ArtifactStoreProtocol` methods.

It consumes the 06-04 facade — one background loop thread, one session per call — and
builds no bridge of its own. Building a second bridge would fork the deadlock risk across
two modules.

`get` decodes `contents[0].blob` with `base64.b64decode`. `resolve_uri` and the URI
grammar go through `ccf.artifacts.protocol`'s existing `artifact_uri` /
`parse_artifact_uri` — reuse, never re-derive; re-deriving is how two stores drift into
resolving the same string differently, and routing through the shared parser is also what
earns the store the existing `@latest`-refusal test for free.

Translate the server's structured signals into the existing typed hierarchy:
`ArtifactNotFound` for absence, the unreachable-substrate error for transport failure,
`ArtifactUriUnresolvable` for a name that resolves to nothing, `MovingTargetRefused`
where the shared parser already refuses. Never `except McpError` with substring matching
— the conformance suite depends on this discrimination and Pitfall 2 is exactly this bug.

The conformance suite already imposes constraints this class must satisfy, so do not plan
around them: the module source may not contain the string `ccf.graph` anywhere, not even
in a comment (`test_the_store_holds_no_graph_write_surface` does
`inspect.getsource(module)`); the class may expose no `update`/`delete`/`remove`/
`overwrite`/`put_at`/`set` attribute; and two stores constructed over the same substrate
must share one naming index, which means the **server** owns the index and the client
holds none.

Keyword-only, private underscore attributes, no wall clock and no key of its own.
  </action>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ArtifactStore client → artifact MCP server | Persistence transport inside the tenant trust boundary, but authenticated (§7.4) |
| Artifact MCP server → L3 Context Graph | Must not exist; the store is a substrate behind mechanism, never a second writer |
| Artifact resource namespace → egress resource namespace | Different trust postures; separation is structural per §7.1 / D-03 |
