<objective>
Declare the `WireProtocol` abstraction and build the Control Plane admission gate that
sits ahead of L2 — the structural core of XPRC-02 and of ROADMAP criterion 2. Pin the
lineage set-union law with a Hypothesis property rather than fixture round-trips.

Purpose: D-12 rules that admission is a gate above every transport, not a check inside
each `WireProtocol` implementation, because per-transport checks duplicate the rule and
let a future transport omit it — the same drift IN-01 found in the pinned-resolution
logic. Two transports ship this phase and more could follow, so the rule belongs above
all of them. Building the gate before either transport also means the transports arrive
with nowhere else to go.
Output: `ccf.a2a.wire`, `ccf.a2a.admission`, admission tests with two peers, and the
lineage union property.
</objective>

Create `src/ccf/a2a/admission.py`: the single Control Plane gate every inbound A2A product
passes before it can reach L2 (D-12, D-IMPL-16 — verify every inbound product, no fast
path).

Check order is load-bearing and must be documented as such:
1. **Size ceiling** on the raw inbound payload, applied *before* canonicalization, so an
   oversized or zip-bomb payload is refused cheaply. The ceiling is a Control Plane value
   with no SDK default (D-IMPL-38).
2. **Signature verification** via the injected `IdentityProvider`, resolving the protected
   header's `kid` against the peer's entry in the pinned trust-policy artifact.
3. **Contract validation**: parse and validate the raw canonical bytes as a
   `ContextProductContract` (`extra=forbid`) — CCF's own validation is the typed boundary
   here, never the transport's types. State that in the gate's docstring per Pitfall 5.
4. **Policy-binding verification** against the trust-policy artifact: the asserted
   producer agent-definition hash, product `schema_name`, and policy-regime identifiers
   must all be within what this peer, for this tenant, is permitted to assert.
5. **TTL / expiry**: run the existing contract TTL refusal (`expires_at`, INV-CH6-05)
   rather than reimplementing it — a validly-signed stale product must not be admitted.
6. **Lineage integrity**: the inbound lineage `L` extends the consumer's by set-union.
   Producer entries survive, consumer entries survive, and the producer's operator plan,
   graph snapshot, and policy version are preserved. Replacement is a defect; the
   Hypothesis property in Task 3 is what pins it.

Refusals follow the established discipline exactly: a `GateRefusal`-shaped base carrying
`gate` and `detail`, with typed subclasses carrying the machine-readable fields and
**both sides of every mismatch** so the caller never re-derives (the
`LineageMismatchRefusal` shape). Refusals are **returned values**, never raised, and each
one is written to the audit journal with `resolved=False` — the audit plane records what
it turned away (T-05-16, T-05-04).

**The admitted-product decision.** Model the gate's success output as a distinct
`AdmittedProduct` type that L2's inbound entry point requires. Then "a transport cannot
hand a product to L2" is a type fact rather than a convention. Whether to enforce
inconstructibility with a module-private token (the `_GATE_TOKEN` / `ServableProduct`
pattern) is a real choice with a live counter-precedent: Dave's I.2 D-12 ruling removed
exactly that token from `Agent` in favour of a lint. **If this plan's implementation uses
a token, the module docstring must argue in writing why the A2A case differs from the
`Agent` case** — the honest distinction available is that `Agent` is constructed by an
in-process factory the SDK controls, whereas an `AdmittedProduct` originates from an
untrusted remote peer and its constructibility is the trust boundary itself. If that
argument does not hold up on inspection, use the type without the token and rely on the
same lint approach, and say so. Either way, do not leave the choice unstated.

**D-20 constraint:** this gate must not become a second consumer of
`ControlPlaneStateStore`. Nothing here is mutable-until-terminal Control Plane state —
trust policy is a versioned artifact, keys are an `IdentityProvider` concern, and peers
are resolved per call. If the implementation finds itself reaching for `state_store`,
stop: D-20 makes closing the audit-bearing-write-path gap a prerequisite task in this
same wave, and that is an unbudgeted change that must be surfaced, not absorbed.

Algorithmic module, house header, citation per CLAUDE.md §7.2 and whitepaper §8.3
Pattern 4.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Peer CCF fabric (untrusted) → admission gate | The phase's most consequential boundary: everything a remote peer asserts is untrusted until this gate says otherwise |
| Admission gate → L2 Context Assembly | Only an admitted product may cross; transports have no route |
| Trust-policy artifact + IdentityProvider → gate decision | Control Plane inputs, resolved by pinned version |
