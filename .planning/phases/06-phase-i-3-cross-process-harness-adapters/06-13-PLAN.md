<objective>
Bring LangGraph up against the suite 06-12 established, and harden
`HarnessAdapterProtocol` against the one structural difference research identified as the
deepest of the three.

Purpose: Claude and ADK expose callbacks into a loop they own; **LangGraph has no loop to
hook — the adapter builds the graph.** Research flagged (assumption A4) that Claude, being
the most callback-shaped, is least likely to surface this requirement, and recommended
hardening the Protocol against both before locking the suite. LangGraph comes second for
exactly that reason: if the Protocol cannot express topology ownership, it is better to
learn that now than after ADK has also been fitted to callback semantics.
Output: the LangGraph adapter, a Protocol that accommodates both shapes, and a suite with
two passing params.
</objective>

Create `runtime/ccf_runtime/adapters/langgraph/__init__.py` and `adapter.py` implementing
`HarnessAdapterProtocol` against `langgraph==1.2.9` / `langchain-core==1.5.1`.

Bind the four seams to the concrete APIs research verified:
1. **Context injection** — the typed Context Product and the agent's pinned rendered
   instructions become a state-channel value on the compiled `StateGraph` under a typed
   `TypedDict` schema (or `create_react_agent(prompt=...)`).
2. **Skill exposure** — `StructuredTool.from_function(func=..., name=..., description=...)`
   per bound skill, closing over `Agent.invoke_skill`, assembled into a
   `langgraph.prebuilt.ToolNode`. Let `infer_schema` derive the JSON Schema. The exposed
   set is exactly the agent's currently-bound skill-set — no more, no less.
3. **Effect capture** — because the adapter owns the topology, the effect seam is an
   adapter-owned node that returns a typed value and routes emission through
   `Agent.emit_effect`. It never writes; wrap or replace `ToolNode` as needed.
4. **Replay hooks** — `RunnableConfig` `metadata` and `tags` carry the correlation
   identifiers; capture the run identity and any reported model/usage information into
   `HarnessTrace`.

**D-IMPL-17 boundary, and it is easy to get wrong here:** this adapter binds only the
CLAUDE.md §7.3 agent-loop seams. LangGraph *as an orchestrator* is a distinct optional
`OrchestrationProtocol` integration and is Phase 7 scope. One tool, two seams, never
conflated. State that explicitly in the module docstring so a reader does not mistake the
adapter-owned graph for an orchestration integration.

Module docstring: the four `/runtime` blocks, citation marking the SDK extension per
CLAUDE.md §7.3 and D-IMPL-24, a "what this adapter cannot do" paragraph restated for this
seam, and the D-IMPL-17 disambiguation. No `__ccf_mode__` tag. No prompt literals; graph
node names, channel names, and tool names come from the agent's artifacts and catalog
entries. Import from `langgraph.graph` / `langgraph.prebuilt` / `langchain_core.tools`
explicitly — the top-level `langgraph` namespace is empty.

Constructor takes `Agent` and its own configuration, keyword-only, and nothing else from
the fabric.
