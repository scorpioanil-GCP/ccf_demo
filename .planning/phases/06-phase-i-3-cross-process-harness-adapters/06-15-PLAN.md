<objective>
Deliver the harness-neutrality proof: one agent definition artifact, executed unmodified
under all three reference adapters, producing replay records that are exactly equal on
every field CCF governs while harness-attributable fields stay isolated in
`harness_trace`.

Purpose: CLAUDE.md §7.3 says portability is demonstrated, not asserted, and this is the
demonstration. D-18 defines what equivalence means here — exact equality on the governed
fields, with model version, trace shape, and token counts confined to a named
sub-structure excluded from comparison, because full byte equality across three different
SDKs would either fail always or force those fields out of the record entirely. This test
is the I.3 precursor to `examples/03-harness-portability`, which lands in Phase 8 per D-06.
Output: the portability conformance test and its shared harness-free agent fixture.
</objective>

  <action>
Implement the D-18 split comparison over the three replay records the Task 1 runs produced.

**Governed fields — assert exact equality across all three.** At minimum, per research and
PATTERNS.md: the context-fabric snapshot, the policy bindings, the perspective conditioning
including `agent_definition_hash` and `grant_set_hash`, the lineage, and
`content_generation_path.product_content_address`. Compare via canonical serialization or
canonical hash, not `model_dump()` — the repo's canonical serializer normalizes
field-by-field precisely because dumping breaks set-valued fields.

**Harness-attributable fields — assert isolation, not equality.** Exclude
`model_version.harness_trace` from the governed comparison, then assert positively that
each record's `harness_trace.harness_id` names its own harness and that the three differ.
An implementation that wrote a harness's model version into a governed field would pass a
weak "records are equal" test and fail here.

Write the assertion so both failure directions are loud: if a governed field diverges
across harnesses, the report names which field; if `harness_trace` were empty or identical
across the three, the isolation assertion fails rather than silently passing on absence.

**The D-23 multi-principal case.** Run a **second** agent definition, with a different
grant set, through the same three adapters. Assert that its three records are equal to each
other on the governed fields, and that its governed field set is **distinct** from the
first agent's — specifically that `agent_definition_hash` and `grant_set_hash` differ.
Without this, the equivalence test could be satisfied by a comparison that collapses
everything to a constant, which is exactly the CR-01 class of planning defect D-23 exists
to prevent.

Add a regression guard for the D-25 extension: assert `DecisionReplayRecord` still has
exactly five top-level dimensions in these live records, so a future change that promotes
`harness_trace` to a sixth block fails here as well as in `tests/replay/`.
