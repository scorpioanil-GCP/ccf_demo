# Phase 13.1 Plan 03: Three External Client Legs Summary

**One-liner:** Bare-MCP, Anthropic-SDK, and Google-ADK client legs consume the authenticated CCF front door with zero CCF imports, deterministic offline via env-var base-URL redirect onto versioned two-turn fixtures.

## What was built

- **client_bare.py (leg 1, D-15 carrier).** ~70 lines, stdlib + `mcp` only.
  Short-lived `streamablehttp_client` session per call with a bearer
  Authorization header. Lists tools, calls every satisfiable one —
  `get_context`, `get_lineage`, `get_replay_record` among them — and reads
  the concrete product resource (discovered via resources/list when
  `CCF_EXAMPLE_RESOURCE_URI` is unset). Prints served context, lineage,
  and the five-dimension replay record; exits non-zero on any refusal.
- **client_anthropic.py (leg 2).** Textbook non-streaming
  `client.messages.create` tool-use loop; tools bridged from the MCP
  server's tools/list; `tool_use` blocks executed over MCP and returned as
  `tool_result`. Determinism is `ANTHROPIC_BASE_URL` +
  `ANTHROPIC_API_KEY=ci-replay` only (A1: env-var honored, no `base_url=`
  kwarg needed). Prints the model's final credit decision.
- **client_adk.py (leg 3).** `LlmAgent(model=env, tools=[McpToolset(
  StreamableHTTPConnectionParams(url, headers=Bearer))])` driven by
  `Runner` + `InMemorySessionService`; ADK discovers `get_context` from the
  server itself. Determinism is `GOOGLE_GEMINI_BASE_URL` +
  `GOOGLE_API_KEY=ci-replay` on the non-Vertex path.
- **fixtures/.** Two-turn recorded conversations per LLM leg
  (`tool_use`/`functionCall` -> final text decision) in exact vendor
  response schemas, with sibling `-request.json` review files.
  `fixtures/README.md` documents the layout, the ordinal-per-path matching
  rule, the live-recording regeneration procedure, and the D-10
  reviewed-event rule.

## Deviations from Plan

**1. [Rule 3 - Blocking] Bare leg cannot call every advertised tool blindly** —
the experience server also advertises built-in agent tools
(`invoke_agent` with a `definition_key` schema); calling all tools
naively crashed. Fix: the bare leg calls only tools whose declared
arguments are satisfiable from its env-provided values and skips the
rest. Commit d18181e.

**2. [Rule 3 - Blocking] Verify harness supplies tenant/entity env vars** —
entity URIs in the served payload are content-hashed, so the borrower
reference is not discoverable client-side, and the plan's inline verify
env set only URL/token. The verification harness reads
`artifacts/ontology.yaml` (tenant_id) and `artifacts/product.yaml`
(focus.entity_ref) and exports `CCF_EXAMPLE_TENANT` /
`CCF_EXAMPLE_ENTITY`, matching the plan's "values from env vars" rule.
Plan 04's Makefile target should do the same.

**3. [Rule 3 - Blocking] Worktree has no `.venv`** — symlinked the main
repo's venv (untracked, gitignored), same as plan 02.

Otherwise executed as written.
