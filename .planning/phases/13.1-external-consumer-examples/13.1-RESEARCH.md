### Locked Decisions

#### Directory structure and family partitioning
- **D-01:** New `examples/external/` family, unified by consumption model (external harness → MCP → black-box CCF), NOT by domain. Existing examples 00–08 unchanged.
- **D-02:** Domain number-bands inside the family: `00-hello-context` = hello world; `10–19` reserved for financial-services depth progression; `50+` reserved for the SituationalIntelligence family. New domains slot in without renumbering.
- **D-03:** `external/README.md` is the family charter: defines the zero-CCF-imports-client-side rule, client-leg conventions, auth posture, and the band map.
- **D-04:** Each example is self-contained (own `artifacts/`, own `serve.py` booting fabric + MCP egress server) — no cross-example fabric coupling.

#### Client harness lineup (00-hello-context)
- **D-05:** Four client legs, one directory, one shared fabric, one README (mirrors example 03's multi-leg pattern): 1. `client_bare.py` (~40-line generic `mcp` client, no LLM); 2. `client_anthropic.py` (pure `anthropic`-SDK agent, own tool-use loop); 3. `client_adk.py` (Google ADK agent with the CCF MCP server as an ADK toolset); 4. Claude Cowork / Claude Code / Claude Desktop — docs-only leg: `.mcp.json` registration snippet in the README.
- **D-06:** Client code must read as a textbook example of its harness — no CCF imports, no CCF-shaped helpers. The only CCF knowledge a client has is an MCP server URL and a bearer token.
- **D-07:** Hello-world domain is financial services, kept deliberately small — one product, one clear decision the served context visibly changes.

#### CI vs live LLM split
- **D-08:** ALL legs are CI-mandatory and deterministic — including the Anthropic and ADK legs.
- **D-09:** Determinism via transport-level replay: CI redirects the model API base URL (env var only, zero code branches in client legs) to a small local replay server serving recorded API responses. Live mode = unset the env var and provide real keys; same client code unmodified.
- **D-10:** Recorded responses are versioned fixtures; regeneration is a reviewed event with a documented command.

#### MCP surface the client sees
- **D-11:** Both surfaces demonstrated: Context Products listed/readable as MCP Resources AND a `get_context`-style MCP Tool callable mid-loop with an entity/scope argument.
- **D-12:** Bearer-token auth ON from day one, shown in the README; clients pass the token via env var. Uses the Phase-10 auth machinery. No anonymous mode.

#### Fabric-side replay and lineage (black-box audit story)
- **D-13:** The fabric records the inbound request itself — tool-call arguments / resource URI, requesting identity (from the auth token), timestamp — as part of the serve-side record. Zero client-side obligation.
- **D-14:** A replay-ready serve record (snapshot, policy bindings, lineage) lands fabric-side for every product served to an external client, by construction.
- **D-15:** Lineage and replay are READABLE BY CLIENTS over the same MCP surface (read-only resources/tools). The example asserts a client leg retrieves lineage + the replay record over MCP.
- **D-16:** Byte-equal reproduction is asserted fabric-side (re-derive the served product from the recorded snapshot/policy versions and compare canonical bytes).

#### Carried forward from Phase 13
- **D-17:** README follows the Phase-13 D-02 seven-heading template, D-04 gloss discipline, D-11/D-12 [ADAPT]/[MECHANISM] artifact markers, and per-example atomic commits with reviewed expected-output changes.

## Summary

The fabric side of this phase is almost entirely composition of existing, shipped mechanism. `runtime/ccf_runtime/mcp/experience.py` already provides an **authenticated** FastMCP server exposing Context Products as templated MCP Resources plus MCP Tools, wired to deployment-supplied resolver Protocols; `runtime/ccf_runtime/mcp/auth.py` ships the Phase-10 bearer-token verifier; `examples/04-cross-process/producer_child.py` shows the working pattern for booting a fabric and serving MCP over uvicorn from a process; `ccf.replay.serve.ReplayWriter`/`DeliveryCapability` gives the serve-side replay record by construction; `ccf.replay.engine.replay` plus `canonical_bytes` gives the D-16 byte-equal reproduction (example 06 pattern). [VERIFIED: repo source]

Two genuine gaps exist. First, **neither MCP module exposes a `get_context` tool or client-readable lineage/replay** (D-11's tool and D-15's read surface). The `build_experience_server()` tool set is fixed (`list_agents`, `invoke_agent`). Resolution: the example's `serve.py` registers additional deployment-side tools/resources on the returned `FastMCP` object (FastMCP decorators work post-construction, pre-run) — this is deployment composition, not SDK modification, and it keeps the role-separation source-grep tests intact. Second, the **`anthropic` package is not installed or declared** — it must be added as an example extra (verified on PyPI, 0.120.2, slopcheck [OK]).

Determinism (D-09) is achievable exactly as decided: the Anthropic Python SDK honors `ANTHROPIC_BASE_URL`; the installed `google-genai` (which ADK 2.5.0 calls through) honors `GOOGLE_GEMINI_BASE_URL` — verified in the installed source at `google/genai/_base_url.py:50`. A small local fixture-replay HTTP server (stdlib or starlette on uvicorn, both already available) serves recorded Messages-API / `generateContent` JSON; CI sets the two env vars plus dummy API keys; client legs contain zero branches.

**Primary recommendation:** Serve `00-hello-context` from the **Experience Layer server** (`experience.py`) — it is the only surface with the D-12-required auth machinery and CLAUDE.md §8.3 names it "the primary surface for external agent runtimes"; extend it deployment-side in `serve.py` with a `get_context` tool and read-only lineage/replay tools whose prose comes from artifacts.

### Pattern 1: Serving surface — Experience server, extended deployment-side
**What:** `build_experience_server()` returns a `FastMCP`; `serve.py` then registers additional `@server.tool()` / `@server.resource()` entries (a `get_context` tool, `get_lineage`, `get_replay_record`) before hosting it with uvicorn. FastMCP decorator registration works any time before the app is served. Tool descriptions/prose are loaded from artifacts, not authored inline (No-Hardcoding — examples are covered by §6.4).
**When to use:** Whenever an example needs surface the SDK module deliberately doesn't own. This keeps `tests/invariants/test_mcp_role_separation.py` and the source-grep assertions in `tests/crossproc/test_experience_edge.py` untouched — they grep the *module* files, not deployments. [VERIFIED: repo source of both modules]
**Why not egress.py:** `build_egress_server(server_name, resolver)` has no `token_verifier`/`auth_settings` parameters — D-12 is unsatisfiable there without an SDK change. `build_experience_server` requires both, and FastMCP installs auth middleware only when both are present (D-26 precedent). [VERIFIED: function signatures in repo]
**Caveat:** the experience server *requires* `agent_directory` and `agent_invoker` seams. This example exposes no agents; supply resolvers returning an empty tuple / raising, from artifacts-declared config, and say so in the README (or the planner may prefer to note this as mild friction and document it).

**Example (serving, from producer_child.py precedent):**
```python
# Source: examples/04-cross-process/producer_child.py (verified pattern)
server = build_experience_server(..., token_verifier=SourceBackedTokenVerifier(...),
                                 auth_settings=AuthSettings(...))
@server.tool(name=values["get_context_tool"]["name"])  # prose from artifacts
def get_context(tenant: str, entity: str) -> str: ...
uvicorn.Server(uvicorn.Config(server.streamable_http_app(), log_level="error"))
```

### Pattern 2: Request capture with requester identity (D-13)
**What:** Inside the tool/resolver closure, call `mcp.server.auth.middleware.auth_context.get_access_token()` — returns the verified `AccessToken` (client_id, scopes) for the in-flight request via a contextvar. Record `{client_id, tool args or resource URI, timestamp}` into the serve-side record before delivery. [VERIFIED: `mcp/server/auth/middleware/auth_context.py:13` in installed mcp 1.28.1]
**When to use:** Every externally-served product.

### Pattern 3: Transport-level replay (D-09)
**What:** A tiny local HTTP server that pattern-matches inbound POSTs (`/v1/messages` for Anthropic; `/v1beta/models/...:generateContent` for Gemini) against versioned JSON fixtures and returns them verbatim. CI env:
```bash
ANTHROPIC_BASE_URL=http://127.0.0.1:<port>  ANTHROPIC_API_KEY=ci-replay
GOOGLE_GEMINI_BASE_URL=http://127.0.0.1:<port>  GOOGLE_API_KEY=ci-replay
```
Live mode: unset base URLs, provide real keys. Zero branches in client legs.
[VERIFIED: `GOOGLE_GEMINI_BASE_URL` in installed `google/genai/_base_url.py:50`. `ANTHROPIC_BASE_URL` — CITED: anthropic-sdk-python README/client (`base_url` falls back to the env var); confirm during Wave 0 once the package is installed.]
**Warning:** Anthropic SDK appends `/v1/messages` to base_url; Gemini appends its full path — the replay server routes on path suffix, not exact match. Streaming: keep client legs non-streaming (`client.messages.create(...)`, `stream=False` default) so fixtures are single JSON bodies, not SSE.

### Pattern 4: Bare MCP client leg
```python
# Source: mcp 1.28.1 (project pin); pattern mirrors src/ccf/mcp/client.py session-per-call
from mcp import ClientSession
from mcp.client.streamable_http import streamablehttp_client
headers = {"Authorization": f"Bearer {os.environ['CCF_TOKEN']}"}
async with streamablehttp_client(url, headers=headers) as (read, write, _):
    async with ClientSession(read, write) as session:
        await session.initialize()
        result = await session.call_tool("get_context", {...})
        res = await session.read_resource("ccf-experience-product://...")
```
Note the session-per-call discipline from `ccf.mcp.client` (held sessions deadlock with anyio task groups — the server is `stateless_http=True` precisely to make this cheap). The client leg must not import ccf, but should follow the same short-lived-session shape. [VERIFIED: repo source]

### Anti-Patterns to Avoid
- **CCF imports or CCF-shaped helpers in `client_*.py`** — D-06. Even importing `ccf.contracts.canonical` to hash the product client-side is a violation; if a client wants to verify bytes, it hashes plain JSON bytes itself.
- **`if os.environ.get("CI")` branches in client legs** — D-09 forbids; determinism is env-var redirect only.
- **Adding auth to `egress.py` or lineage tools to `experience.py` in `/runtime`** — SDK mechanism change inside an examples phase; the role-separation and source-grep invariant tests will fight you. Deployment-side composition instead.
- **Serving `model_dump_json()`** — always `canonical_bytes` so client-side hash equals content address (existing modules already do this).
- **A shared fabric across examples** — D-04.
- **New `##` heading in the README** — the template asserts exactly seven.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Bearer verification | custom middleware | `SourceBackedTokenVerifier` + `FileTokenSource` + `AuthSettings` (Phase 10) | constant-time compare, fail-closed, already tested |
| Serve-record-then-deliver ordering | two statements | `ccf.replay.serve.ReplayWriter` → `DeliveryCapability.deliver` | capability pattern makes unrecorded delivery unreachable (D-14 by construction) |
| Byte-equal reproduction | ad-hoc re-run | `ccf.replay.engine.replay` + `canonical_bytes` comparison | example 06 already proves the pattern |
| Product URIs | string formatting per file | `experience_product_uri()` | drift prevention (module's own rationale) |
| MCP HTTP hosting | raw ASGI wiring | `server.streamable_http_app()` + uvicorn (producer_child.py) | working pattern incl. READY-line handshake for run.py orchestration |
| LLM mocking | monkeypatching SDK internals | base-URL env redirect to fixture server | D-09 locked; SDK internals churn |

**Key insight:** the fabric side is a composition exercise over five already-shipped modules; hand-rolling any of them re-litigates gated invariants.

## Common Pitfalls

### Pitfall 1: `anthropic` not installed
**What goes wrong:** `client_anthropic.py` ImportError in CI.
**Why:** package absent from pyproject; only `claude-agent-sdk` (a different package) is pinned.
**Avoid:** add `anthropic==0.120.2` to the dev/examples extra as a Wave-0-ish task; `make install` refreshes.
**Warning sign:** `pip list | grep -i anthropic` empty (it is, today).

### Pitfall 2: Experience server's mandatory agent seams
**What goes wrong:** `build_experience_server` requires `agent_directory` and `agent_invoker`; a naive `None` fails.
**Avoid:** artifacts-declared empty exposure (directory returns `()`); README notes agents are out of hello-world scope.

### Pitfall 3: FastMCP auth needs verifier AND settings together
**What goes wrong:** verifier without `AuthSettings` = server that "looks authenticated and refuses nothing" (D-26 note in module docstring).
**Avoid:** always pass both; `AuthSettings` issuer/resource values from artifacts.

### Pitfall 4: Templated resources vs. resource listing (Claude Desktop browsability)
**What goes wrong:** `@server.resource("scheme://{tenant}/{class}/{version}")` registers a resource *template*; `resources/list` may return nothing concrete, so "browsable from Claude Desktop" (D-11 intent) can look empty depending on the client's template support. [ASSUMED — verify against mcp 1.28.1 behavior during planning/Wave 0]
**Avoid:** additionally register 1–2 concrete (non-templated) resource URIs for the hello product in serve.py, or verify the client renders templates.

### Pitfall 5: Replay server path/shape mismatches
**What goes wrong:** Anthropic and Gemini hit different paths and expect exact response schemas (Messages API `content` blocks incl. `tool_use`; Gemini `candidates[].content.parts[].functionCall`). A fixture missing tool-call turns breaks the agent loop mid-conversation.
**Avoid:** record fixtures from one real live run (documented regeneration command, D-10); replay server matches on (path suffix, request ordinal or a request fingerprint). Keep the scenario to a fixed, short tool-use conversation (1 tool call + 1 final answer).

### Pitfall 6: ADK session/deprecation churn
**What goes wrong:** ADK 2.x moved MCP classes; older import paths (`google.adk.tools.mcp_tool.mcp_toolset`) are deprecated.
**Avoid:** import from `google.adk.tools.mcp_tool` package root as installed (verified exports include `McpToolset` via `__init__`); mirror example 03's ADK leg (Runner + InMemorySessionService) for the drive loop.

### Pitfall 7: Port collisions and startup races in run.py
**What goes wrong:** two servers (fabric MCP + replay server) plus clients race in CI.
**Avoid:** producer_child.py precedent — bind port 0, print `READY <port>` lines, parent parses before launching legs.

### Pitfall 8: No-Hardcoding lint on example code
**What goes wrong:** tool descriptions, scenario values, model names, or token values inline in serve.py/client legs trip `tools.lints` / review.
**Avoid:** everything domain- or deployment-shaped in `artifacts/` (incl. model name for live mode, tool prose, tenant/product-class names). Client legs read URL/token/model from env/args only.
