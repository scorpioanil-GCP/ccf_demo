# Phase 24.6 Plan 05: computed-empty served with its search, and Debt derived from evidence Summary

Two mirrored corrections in one row, and the second is the one Dave said was
*"the biggest issue I see"*. **"Zero results is not zero knowledge"** — an
operator that ran and returned nothing COMPUTED, so it is served with its search
attached rather than refused on cardinality. And its mirror, **"zero source
entities is not automatically high Debt"** — the reference debt scorer stops
turning an empty view into `D_c = 1` and asks the deployment's own scorers what
the evidence supports.

The invariant, verbatim (`D-IMPL-255` (2)): **"Cardinality never determines
Context Debt. Evidence determines Context Debt."**

## What was built

**Task 1 — the whole `src/` change and every existing-test re-derivation**
(commit `ac4e4573`).

`ComputedEmptyFinding` names what RAN and what it ran over: the operators that
returned empty, **every** operator invoked (so the emptiness is legible as a
fraction of the search — one empty out of four is a different fact from four out
of four), the plan, and the store head. `ContextProductContract.computed_empty`
carries it, hash-transparent at `None`, which is the claim every product
assembled before this field existed was already making.

The returned half of the empty-operator gate is gone: `_refuse_empty_results`,
`EmptyResultRefusal`, `GATE_EMPTY_OPERATOR_RESULT`, the `empty_results` keyword
on both runners, and the `empty-result-refusal` kind. The **declared** half is
untouched and is the control — a product computed by nothing is still not
servable, and a finding does not rescue it. The gate rosters went 6/5 → 5/4, six
distinct, judged by set equality with the departure reported by name rather than
by exempting it.

`AssemblyDebtScorer.__call__`'s zero-observation branch is deleted. What
replaces it is not a different constant but a different question:

| | before `24.6-05` | after |
|---|---|---|
| F over an empty view | `0` — a coverage claim wearing freshness's name | the multiplicative identity `1`, **unpinned** |
| C, S over an empty view | `0`, `0` — from the row count | the deployment's scorers' own answers, pinned |
| `D_c` for a class declaring C = S = 1 | `1`, `FAIL_CLOSED` | `0`, `OK` |
| what says the search was thin | nothing — the number said it | `computed_empty.emptiness`, a finding |

`ExecutionEvidence` carries **no row count**, deliberately: a field for it would
be an invitation to put the shortcut back. `EvidenceAwareFactorScorer` is an
optional companion Protocol rather than a widened one, so a `C`/`S` scorer
written before this row keeps working unchanged. `emptiness_of` ships **no
number** — no minimum query count, no coverage fraction — and its answer is read
by no scorer the SDK ships, which is Dave's refinement made structural rather
than promised.

**Task 2 — the evidence-derived Debt proven, and the sabotages watched**
(commit `f77145e3`). `tests/products/test_evidence_derived_debt.py`: 17 tests,
829 lines. **No assertion compares against a literal Debt.** Each computes its
expectation from the fixture's own declared factors, so a scorer that replaced
the deleted branch with a *different* constant fails even where the constant
coincides with today's figure.

Three of these are worth calling out.

- **The debt-scorer key link's first instrument could not fire.** Written as the
  plan's `key_links` suggest — an AST assertion that the resolver spells
  `evidence=ExecutionEvidence.of(execution)` — it would have been an assertion
  about source text. I measured the alternative first: dropping the keyword from
  the resolver left **all 722 tests green**. Nothing observed the search reaching
  the scorer. It was replaced by a behavioral test — a deployment scorer that
  *can* read the evidence is wired into the booted resolver, and what it received
  is compared against what the execution recorded on the product — which is RED
  under the same sabotage. Recorded because a control that passes is worse than
  no control.
- **The two constant sabotages are two on purpose.** The criterion says *"1 or
  any number"*. A control that only tried `1` would license `0.9`, which is
  precisely how a cardinality shortcut comes back wearing a different figure. The
  first attempt at the `0.9` leg was arithmetically wrong (`F=0.1, C=S=0` is
  `D_c = 1`, not `0.9`) and the test said so — the sabotage-did-not-take
  assertion fired before the predicate did, which is the assertion earning its
  place.
- **The `emptiness_of` sabotage failed three tests, not one.** The classification
  is load-bearing in the tier tests *and* end to end through the booted resolver,
  which is evidence the finding is genuinely woven in rather than asserted once.

## Deviations from Plan

**1. Task 1 carries the whole `src/` change and every existing-test
re-derivation; the plan splits them across two tasks.**
The tree must be green at every commit (plan 03 deviation 8, plan 04
deviation 3, same reason). The plan says *"write the import now and finish Task
2 before running"* — which is a RED Task 1 commit by construction, and the
resolver additionally needed `AssemblyDebtScorer.__call__` to accept `evidence`
before it could pass it. Task 2 is what remains and is self-contained: the new
module, the `halflife/debt.py` paragraph, and the sabotage runs.

**2. [Rule 1 — bug] Six test modules outside `files_modified` were RED by
construction and re-derived.** `tests/projection/test_empty_results.py` imported
the deleted helper; `tests/products/test_request_contract.py` enumerates
`ContextProductContract`'s field set by name; `tests/products/test_resolver_seam.py`,
`test_resolver_defaults.py` and `test_tolerance_exceeded.py` each hold a
deployment scorer that had to accept the new keyword;
`tests/products/test_reference_debt_scorer.py`'s empty-assembly assertion *was*
the deleted branch's specification. No assertion was weakened to admit the
change: the reference-scorer module's empty case gained a **third** control that
reproduces the deleted branch exactly and watches it fail.

**3. `tests/test_surface_completeness.py` gained a reconciliation, and this is
the deviation worth reading.** Removing `empty_results` from
`run_federated_gates` returned that signature to the **frozen Phase-15
baseline's, character for character** — plan `24.5-13` added `debt_tolerance`,
`24.5-15` added `empty_results`, `24.6-04` retired the first and this plan the
second. A round trip appears in **no** partition of `diff(baseline, live)`, so
four fragments (three of them historical) claiming `reshaped` for a name the
diff cannot see failed the completeness gate. There was no honest alternative:
calling it `behavior` is false, and the three historical fragments are records I
am fenced from editing. So the gate gained `restored_surfaces`, the mirror of
its existing `short_lived_surfaces` allowance, admitting a name only on **two**
`reshaped` claims *plus* shape equality in both documents — one claim is refused,
because a signature cannot return to the baseline's without having left it.
Four controls, two of them fed to the shipped assertion, and both conditions
watched RED under sabotage. The residual is stated in F-3.

**4. [Rule 2] `ComputedEmptyFinding` refuses an empty `operators_returned_empty`.**
Not in the plan's interfaces block. Without it there would be two spellings of
*no operator returned empty* — `None` and a finding naming nothing — and two
spellings of one claim put two content addresses on one product. The validator
makes the second unrepresentable; a test asserts the `ValueError`.

**5. F over an empty observation set carries NO scorer pin.** The plan says F is
the identity and says nothing about pinning. Pinning `FreshnessScorer` as the
producer of a value it never computed would be exactly the false record the old
branch's own docstring refused (*"naming a scorer as the producer of those zeroes
would be a false record"*). C and S keep their pins, because those scorers
answered. `DebtAssessment` already admits at most one pin per factor, so a
partial pin set needed no new mechanism.

**6. `AssemblyDebtScorerProtocol`'s widening is breaking for deployment scorers,
and the resolver passes the keyword unconditionally.** The plan directs both. I
considered making the resolver inspect the scorer and pass evidence only to those
that could take it; that is the silent repair this codebase refuses everywhere,
and it would make one seam behave as two. `runtime_checkable` does not check
signatures, so the failure is a `TypeError` at the first governed serve rather
than at boot — stated under Migration in the surface fragment because it is worth
knowing before upgrading.

**7. `src/ccf/projection/engine.py` and two comments in
`tests/products/test_resolver_seam.py` carried stale prose naming the deleted
symbols.** The engine's `empty_results` docstring held a live `:data:` reference
to a class that no longer exists — a dangling cross-reference in `src/`, and the
"diff-scoped review misses prose drift" defect class exactly. Both rewritten;
the engine's field and its computation are unchanged, and the docstring now says
so.

**8. The plan's `files_modified` names `src/ccf/products/__init__.py`; it was NOT
edited.** It re-exports nothing by its own stated invariant (plans 02 and 04
recorded the same measurement) and contains no occurrence of any retired name.

**9. Two `# type: ignore` / structural-typing accommodations in the new tests.**
`_assert_served` in the re-derived halves module compares `type(...).__name__`
rather than using `isinstance`: a sabotaged scratch copy of `gates.py` defines
its own `ServableProduct`, and an identity check would fail against the copy for
the wrong reason — reporting a class-identity mismatch where the subject is
whether the product was served.
