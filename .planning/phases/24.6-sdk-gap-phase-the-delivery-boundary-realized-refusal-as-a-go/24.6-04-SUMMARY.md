# Phase 24.6 Plan 04: the class's default tolerance, the retired debt half, and the `tolerance-exceeded` shell Summary

A product class lost the power to withhold context over its own preference, and
what withholds it now says who set the number. `ServeObligations.debt_ceiling`
is `default_debt_tolerance`; the declared-obligations gate's debt half and the
`debt_tolerance` keyword on both runners are deleted; and
`refuse_over_tolerance` holds an **already-admitted** product to the one
applicable tolerance — default, caller or policy — returning a shell that says
fulfillment was withheld and never that the Debt was wrong.

## What was built

**Task 1 — the rename, the retirement, the kind, and the path** (commit
`e75b069a`).

`ServeObligations`' two members stopped being the same kind of thing, which is
the whole ruling. `lineage_inputs_at` is an **obligation** the one shipped gate
enforces; `default_debt_tolerance` is a **default** no gate reads. The
docstring carries `D-IMPL-240` amendment 2's three debt concepts explicitly —
the product's figure informs, the consumer's is enforced as requested, a policy
constraint is governance — and says in one sentence that all three arrive at
one place as one `EffectiveParameter` with its authority attached.

The debt half of `_refuse_declared_obligations` is gone: the
`obligations.debt_ceiling` read, both `DeclaredObligationRefusal(obligation=
"debt-ceiling", …)` returns, the `min` fold plan 03 inlined as an INTERIM, and
the `debt_tolerance` keyword on `run_gates` and `run_federated_gates`.
`DeclaredObligationRefusal.obligation` is `Literal["lineage-inputs"]`, so the
retired token is not merely unused — it is unconstructible, and a control
asserts the `ValidationError`.

`ToleranceExceededRefusal` is deliberately **not** a `GateRefusal` and carries
no `gate` token. Because it declares neither `gate` nor `reason`,
`envelope_for` falls through to *"a refusal declaring neither is still a
refusal; its kind is the most specific true thing that can be said about why"*
— a branch nothing else in the vocabulary reaches today, now covered.
`observed: Decimal | None` types the retired half's `observed="no-assessment"`
string: `None` is the positive *no assessment was produced*, and reporting it
as `0` would claim a measurement nobody made. `breakdown` carries the whole
`DebtAssessment`, which is `D-IMPL-251` C2's *"debt information that can safely
be disclosed"*.

Two things had to arrive with it to make the class default reachable as a
default. `resolve_effective_request` — and the Protocol's `resolve`, and the
reference's — gained an optional `class_defaults` / `class_source` pair
defaulting to `None`, so **no plan-02/03 call site or test moved**, and the
class's characteristic is applied first with the **request contract's own
defaults winning for the same name**. The resolver folds the class default in
under the SDK's own parameter name with the declaration's content address as
its pin, and calls `refuse_over_tolerance` after `run_gates` on the admitted
product.

**Task 2 — the three authorities through the booted resolver** (commit
`68325500`). `tests/products/test_tolerance_exceeded.py`: 12 tests, 639 lines,
end to end through a real `load_and_boot` deployment and the shipped
`GovernedResolver`. `test_structural_gates.py` proves the comparison against
hand-built parameters; this module proves the **resolution** — that a
resolution which folded the three authorities wrongly, dropped a provenance, or
reached the gate instead of the delivery step is red even when every unit test
stays green.

## Deviations from Plan

**1. [Rule 2 — governance] A class default naming a parameter the request
contract does not declare is REFUSED, which the plan does not mention.**
Found while writing the fixture. `resolve_effective_request`'s step 5 holds
every **effective** value to the declared surface, so folding a class default
for an undeclared name in would refuse every request as
`undeclared-parameter` — reporting a deployment's mistake as a caller's, on a
path the caller cannot fix. Silently dropping it instead would be the silent
repair this codebase refuses everywhere. And the substantive argument settles
it: a class characteristic the caller has **no way to state** is not a default
at all, because there is no counterfactual — it is a ceiling wearing a
default's name, which is exactly the power `D-IMPL-251` C1=A took from a
product class. So it raises `ValueError` naming both remedies, on the
`capability_bindings` precedent (`D-IMPL-253` amendment 2 (3): the fabric
cannot reach a valid governed determination). See F-1 — the disposition is
arguably Dave's.

**2. [Rule 1 — bug] `refuse_over_tolerance` reads `int` as well as `Decimal`.**
The plan's interfaces block types `tolerance: Decimal`. Written that way, an
integer-authored tolerance raised: `ccf.products.request::_refuse_tolerance`
accepts `int` and `Decimal` at the request boundary (excluding `bool`), so an
`int` legitimately reaches a resolution — and a YAML-authored contract default
**must** be an int or a quoted decimal, because a float is not canonically
encodable and `EffectiveParameter` refuses one at construction. The tolerance
step now applies the same reading the boundary does, so there is one answer to
*"is this a number"* rather than two at two layers. The `TypeError` for
anything else stays.

**3. Task 1 carries the resolver, the `constraints.py` pair, and every
existing-test re-derivation — the plan puts them in Task 2.**
The tree must be green at every commit (plan 03's deviation 8, same reason). At
the Task 1 boundary the resolver still passed `debt_tolerance=` to a `run_gates`
that no longer accepted it, and five test modules asserted the retired
behavior; a Task 1 commit as scoped would have been RED on all of them. Task 2
is what remains and is self-contained: the new module, cp-04's prose, and the
sabotage runs.

**4. `test_envelope_for_tolerance_exceeded` was written at Task 1, not Task 2.**
`test_every_kind_has_its_own_test_function` walks the test file's AST and
requires a `test_envelope_for_<token>` for every kind, so the kind and its test
have to arrive together or the commit is red.

**5. `tests/products/test_policy_constraint_resolver.py` was edited and is
outside `files_modified`.** RED by construction: its `booted_with_tolerance`
fixture authors `serve_obligations` with the old key, which `extra=forbid`
refuses at parse. One key renamed; no assertion changed.

**6. The Debt is set by a supplied scorer, not by forcing a `DeclaredFactor`.**
The plan suggests forcing the observation *"via the deployment's `DeclaredFactor`
completeness"*. The resolver takes its debt scorer as a **constructor
argument** — a value the deployment owns, exactly as its projection and plan
factory are — so the module supplies its own and keeps the subject the
resolution rather than the scoring. A control asserts the fixture really does
measure `0.20`, so "above" and "below" are measured rather than assumed; a
scorer silently returning zero would fail it.

**7. Six surface-change fragment entries were reshaped to satisfy the
assembler.** Three mechanical corrections the gates found and I would not have
found by eye: the `Change type` vocabulary is closed to
`added|reshaped|removed|behavior` (so "renamed", "narrowed" and "extended" were
recast); a `Public surface: true` entry's `Surface` must be **one** dotted
token, so the two-runner and three-constraint-surface entries were split into
five; and `removed` on a *function* is refused by the completeness gate,
because dropping a parameter reshapes a name rather than removing it. The
content is unchanged.

**8. `THE_SEVEN` was renamed in place rather than losing a member.**
Plan 01's deviation 4 established that `THE_SEVEN` is a closed historical record
of `D-IMPL-243` amendment 2's sweep and is never *extended*. A rename is a
different operation: the field is the same field the sweep named, so moving it
to `NAMED_SINCE_THE_SWEEP` would make both rosters lie about when it arrived,
and `test_the_two_tree_rosters_are_disjoint` would still pass while doing so.

**9. Dave's Q9 quotation is elided at one word.** The docstring recording the
rename would naturally quote *"Keeping `debt_ceiling` after changing its
authority…"*, and that single word would put the retired identifier back in
`src/` and make the plan's own `grep → 0` criterion unsatisfiable. Both quoted
fragments are verbatim; only the identifier is replaced with "the previous
name", and the docstring says so.

**10. `src/ccf/products/__init__.py` was NOT edited**, against its appearance in
`files_modified`. It re-exports nothing by its own stated invariant (*"a second
import path for the same symbol is a second surface the drift manifest has to
track"*) and contains no occurrence of the renamed field. Plan 02's deviation 2,
same measurement.

## Findings for Dave

**F-1. I ruled on a case nobody ruled on: what happens when a product class
declares a default tolerance its request contract does not expose.** Three
readings were available — apply it anyway (breaks every request), ignore it
silently (a class believes it defaults to 0.5 and it defaults to nothing), or
refuse. I refused, because the second is a governance hole dressed as
leniency and the first misattributes the fault. The argument that decided it is
yours: a default the caller cannot override is a ceiling, and C1=A says a class
may not have one. Stating it because it is a reading, not a quotation, and
because it makes a previously-valid (if useless) artifact combination invalid.

**F-2. The retired 409 DEBT route leaves a gap nothing fills yet.** A caller
whose tolerance is exceeded now gets a `tolerance-exceeded` envelope, and the
HTTP door has no mapping for that kind — so under today's door it reaches
`served_answer` and raises. Plan 09 owns the door class table
(`D-IMPL-253` Q18), and this plan is fenced away from it, so the gap is
deliberate and one wave long. It is the same shape as plan 03's F-2 and worth
knowing before someone finds it without this note.

**F-3. Plan 03's six citation findings are unchanged and still open.** Deleting
`effective_debt_ceiling` stranded six `::` cites in the four `CP-SPEC-00N`
pages. This plan created no seventh and fixed none: the pages are dated,
digest-bearing artifacts it is fenced away from, and the three options plan 03
measured (re-cite in place / exempt the spec pages / a `SUPERSEDED` marker) are
still the three. `make lint` will stay rc 1 until one is chosen.

**F-4. An adopter's authored product-class document breaks loudly, and that is
the intended failure.** `extra=forbid` means a document still carrying the old

deployment that meant a *ceiling* has to decide which of the three debt concepts
it actually meant — but it is a genuine breaking change to an authored artifact
format, not just to a Python surface, and the surface-change fragment says so
under Migration. No shipped example declares one, so nothing in this repo moved.

35 *"still reads `c3224bb4…`"*. `CRITERIA-LOCK.md` Amendment 2 (`D-IMPL-256`)
added criterion 36 and re-pinned to `014dcd64…`. **The digest on this tree
reproduces `014dcd64…` exactly**, with 36 criteria, 38 lines, and the wrap
