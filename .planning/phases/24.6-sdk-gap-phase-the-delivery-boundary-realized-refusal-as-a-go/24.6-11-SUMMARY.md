# Phase 24.6 Plan 11: delivery is deterministic, and no transport takes replay back Summary

Dave, `D-IMPL-253` amendment 3, verbatim — the sentence this plan turns
into a measurement:

**"Same request + same governed state + same asked_at → same
determination, authority resolution, disclosure decision, and replayable
response. That is the end-to-end consequence of the architecture we've now
settled."**

And `D-IMPL-256`'s sequence principle, which is the other half:

**"Replay belongs to the governed determination, not to HTTP or MCP. That
matters because otherwise the standing-resource/tool asymmetry simply
reappears somewhere else."**

Three test modules, no `src/` or `runtime/` change. The architectural
property is now a test for both outcomes of the protocol; the `D-IMPL-254`
invariant is a thing the tree checks rather than a sentence in a planning
file; and the no-transport-mint rule is measured over the WHOLE delivery
surface for the first time — 24 modules, three doors, one permitted catch
site.

## What was built

**Task 1 — delivery is deterministic** (commit `c35f4e9d`,
`tests/products/test_delivery_determinism.py`, 983 lines, 11 test
functions).

Five same-answer cases through the booted governed resolver — one
fulfilled product and one refusal of each of `constraint-refusal`,
`policy-resolution-conflict`, `tolerance-exceeded` and
`subject-unavailable` — each asserting **four separate things**, because
they are the four layers `D-IMPL-254` separates and none implies another:

| # | The claim | How it is compared |
|---|---|---|
| 1 | the determination | the outcome's kind and value |
| 2 | the authority resolution | `policy_bindings.request_resolution`, canonical bytes |
| 3 | the disclosure decision | `content_generation_path.disclosure_decision`, and the parsed `DisclosureDecision` |
| 4 | the replayable response | the five dimensions by name, plus the content address or the shell bytes modulo the reference |

**The two references are asserted EQUAL, not merely resolvable**, and that
is the strongest form the claim has. A record is content-addressed
(`D-IMPL-26`) and the governed path reads no clock — `_record_refusal`
records at `request.asked_at`, and the served path does the same — so two
identical determinations produce byte-identical records that the store
files under one address. A reference that differed would mean a record
that differed.

`recorded_at` is asserted **equal** rather than compared "modulo", which
the plan's own interfaces block anticipated: there is no clock on this
path to be modulo of.

Two controls that must change the answer, and do: `asked_at` moved across
an effectivity boundary (a different policy is in force, a different pin
lands in `applied`, the tolerance resolves to a different number by a
different authority), and a constraint registered at a different value
under the same key (a different content address, so a new version, and the
refusal names the new bound). Both comparison helpers are watched
reporting planted differences, and the dimension roster is checked against
`DecisionReplayRecord.model_fields` so a sixth dimension cannot be
compared by nobody.

**Task 2 — the invariant recorded and its sabotages rostered** (commit
`b39eb434`, `tests/invariants/test_determination_authority_disclosure_delivery.py`,
553 lines, 27 collected).

Plan `24.6-08` wrote the invariant into three docstrings; this holds it
there, by AST rather than by `grep` (a module's own prose can trip a
source-text claim — plan `24.6-09` already had to move one claim for
exactly that reason), and it requires the arrow string **and both
citations**: a docstring naming the four layers without saying they are
SDK-defined under CLAUDE.md §11 would leave a reader to infer the
whitepaper committed to them.

The roster is five rows over criteria 6, 10, 21 and 22 — 22 is a pair,
because the ruling is about two subjects being indistinguishable *at a
door* and there are two doors — plus the eleven divergence controls behind
criterion 22's two equivalence tests. Held from **both** sides: defined at
module scope by AST (a nested function pytest would not collect does not
satisfy a row), and collected by pytest in a subprocess. Criterion 22's
own `minimal` leg is pinned by node id, because both equivalence tests are
parametrized over three levels and the criterion is about one of them.

`git diff --quiet 1022ad59 --` over CLAUDE.md and the whitepaper, with the
diff predicate itself watched answering non-zero on a scratch repository —
the criterion's last clause and `D-IMPL-253` Q28 as a gate rather than a
promise. §M7's measurement is recorded in the module docstring, in prose
rather than as line-anchored citations.

## Deviations from Plan

**1. [Rule 1 — the roster is built from the tree] Criterion 22's sabotage
does not carry the name the plan gives it.**

- **Found during:** Task 2, enumerating the roster.
- **The plan says:** *"criterion 22 → the HTTP and MCP
  `test_unauthorized_and_nonexistent_are_observationally_equivalent_at_minimal`
  plus their divergence controls"*.
- **The tree holds:** `test_unauthorized_and_nonexistent_are_observationally_equivalent`
  in both door modules, each `@pytest.mark.parametrize`d over the three
  disclosure levels. There is no `_at_minimal` function and there never
  was; plans 09 and 10 shipped one function per door with `minimal` as one
  of its legs.
- **What shipped:** the actual names, plus a separate assertion that
  `…[minimal]` is among the collected node ids. That is **stronger** than
  the plan's spelling, because it holds the level the criterion is about
  as its own claim rather than trusting a function name to carry it.
- **Files:** `tests/invariants/test_determination_authority_disclosure_delivery.py`.
- **Commit:** `b39eb434`.

**2. [Rule 2 — a control the plan's roster left open] "their divergence
controls" is enumerated by name rather than left as prose.**

- **Found during:** Task 2.
- **Issue:** the plan names the divergence controls collectively. A roster
  entry that says "and its controls" is a roster with an unbounded member,
  and nothing would notice one being deleted.
- **Fix:** `EQUIVALENCE_CONTROLS` lists all eleven by `(module, name)` —
  six at the HTTP door, five at the egress door — each asserted defined at
  module scope and collected. The two doors' control sets are not
  symmetric (the HTTP module has a `test_a_reference_that_does_not_resolve_is_reported`
  the MCP module folds elsewhere), which is why they are enumerated from
  each module rather than mirrored.
- **Commit:** `b39eb434`.

**3. [Rule 2 — the plan's interfaces block, applied] The version
perturbation control uses two deployments, not two registrations.**

- **Found during:** Task 1, case (7).
- **Issue:** the plan asks for *"a new version of the constraint registered
  (a changed `value`) with the same `asked_at`"*. Registering a second
  version under one key whose window also contains `asked_at` raises
  `ConstraintEffectivityConflict` by construction (`24.6-02`/`03`), so the
  literal instruction is unbuildable in one registry — and rightly so:
  that conflict is a different property with its own test.
- **Fix:** the Control Plane is put in two states by booting two
  deployments, each registering the same key at a different value. The
  registry mints a version as the content address of what was registered
  (`D-IMPL-26`), so a changed value **is** a new version, and the pins are
  asserted different and each asserted present in the shell it came from.
  The question, the perspective and `asked_at` are held word for word.
- **Files:** `tests/products/test_delivery_determinism.py`.
- **Commit:** `c35f4e9d`.

**4. [Rule 2 — a hole in the plan's own predicate] The whole-surface walk
checks forbidden IMPORTS, and both spellings of the disclosure plant.**

- **Found during:** Task 3, writing the `disclose` sabotage.
- **Issue:** the interfaces block specifies a call check on
  `ast.Attribute.attr`. A bare `disclose(envelope, level=…, policy=…)` —
  the way a transport would most naturally call it, and the way `src/`
  itself calls it — is an `ast.Name` call and would have crossed
  unreported. The block also specifies an import check, which the three
  per-door copies do not have.
- **Fix:** `ImportFrom` and `Import` are both walked against
  `FORBIDDEN_IMPORTS`, and the disclosure sabotage plants **both** forms:
  an attribute call (caught by the call check) and
  `from ccf.products.disclosure import disclose` (caught by the import
  check). Each is asserted reported separately.
- **Commit:** `c941c1d0`.

**5. [Rule 2 — vacuity, at the helper rather than at each caller] The
walker raises on an empty tree.**

- **Found during:** Task 3.
- **Issue:** the plan says an empty roster raises; the three per-door
  copies assert non-emptiness at the *call site*, which leaves every
  future caller to remember.
- **Fix:** `transport_mint_violations` and `catch_sites` both assert
  `modules` before reading anything, so a caller cannot obtain a clean
  answer over an empty tree at all. Sabotage 10 disables the guard and the
  vacuity test goes red.
- **Commit:** `c941c1d0`.
