# Phase 24.6 Plan 01: the Authority layer's value, the policy-constraint artifact class, and product defaults Summary

Three contracts and no resolution logic: the provenance record derived from Dave's four worked cases before any model is named, `ccf.policy-constraint` registered through the whole six-step chain, and `defaults` as the fifth key on the request contract — the shapes plans 02 and 03 are written against.

## What was built

**Task 1 — `src/ccf/products/provenance.py`** (commit `9740e6d5`). The module docstring is the design record and precedes every class, in the order Dave required (*"don't begin with Pydantic classes"*): the four worked cases as a table, then what each one forces, then D-04's comparability rule and the named `min(` defect the shape rules out. Below it: `Authority`, `AUTHORITIES`, `ProvenanceSource`, `ParameterBound`, `EffectiveParameter`, `OverrideRecord`, `EffectiveRequest` (with `values()` and `parameter()`).

Two properties are structural rather than documented. `ProvenanceSource` refuses an `artifact` source that carries no version and refuses a version on a `request` or `capability` source — `D-IMPL-253` amendment 2 (1)'s *"do not create fake artifacts"* made unrepresentable. And a float is refused at construction, recursively through containers, so a record that could never reach `canonical_bytes` cannot be built in the first place.

The module holds no number. The four cases' values appear in the docstring as quotations of Dave's cases and as executable fixtures in the test; `grep -cE 'Decimal\("(0?\.[0-9]+)"\)' src/ccf/products/provenance.py` is 0.

**Task 2 — `ccf.policy-constraint`** (commit `880cebc2`). `PolicyConstraint(VersionedArtifact)` with `policy_id`, `applies_to`, `parameter`, `operator`, `value`, `overridable`, `source_authority`, `effective_from`, `effective_until`, `reason`, `priority`; `ConstraintApplicability` with four axes where `None` means *any*; `CONSTRAINT_OPERATORS` derived from the `Literal`, five members, closed by equality in the test.

The chain, all six steps: the class and constant in `artifacts.py` with both names in `__all__`; `SDK_ARTIFACT_CLASSES`; `DeploymentConfig.policy_constraints` as the ninth reserved section — a **mapping** of label to body, deriving one manifest entry per key exactly as `operators` does, so no constraint disappears inside a bundle; `_RESERVED_SECTIONS`; the per-label derivation in `derive_deployment`; and the two regenerated schemas. `test_exactly_two_reserved_sections_are_adopter_owned` is unchanged and green — the new section is SDK-owned.

Validators refuse a value that does not match its operator **by name**, and a window that closes before it opens. A quoted number under `maximum`/`minimum` is read as a `Decimal` in a `mode="before"` validator, because a Control Plane document must quote its numbers (a YAML float is refused outright) and the operator is what makes the decimal reading unambiguous — `preferred` is deliberately left alone, since guessing between a number and a name would be the silent repair this module refuses everywhere else. The docstring states that `preferred` never refuses and that **the resolver, not a validator, enforces that**, because a validator sees one artifact and refusal is a property of a resolution.

**Task 3 — `ProductRequestContract.defaults`** (commit `0776953f`). The fifth declaration key, hash-transparent at the empty mapping, read by `from_declared` under `defaults`. One `model_validator` refuses three ways a default is not one — an undeclared name, a name the class declares and always refuses, and a value the declared argument's own type rejects — **naming every offender in one message**. The type check delegates to `refuse_payload` over `arguments` narrowed to the one name, so a default and a caller's value are judged by one rule rather than two.

## Deviations from Plan

**2. `src/ccf/controlplane/__init__.py` was NOT edited, against the plan's "Export both names from `src/ccf/controlplane/__init__.py` and `__all__`".**
Measured before deciding: that file's `__all__` is `["artifacts", "audit", "registry", "resolution", "state"]` — five **module** names and not one `ArtifactClass`. `DEBT_PROFILE`, `PRODUCT_CLASS`, `HALF_LIFE_TABLE` and every other shipped class constant are absent from it. Both names are in `artifacts.py`'s `__all__`, which is where every sibling lives.

**3. `SourceKind` was introduced and then withdrawn.**

Inlined. The fragment's prose says "seven public names" and the diff has seven.

**4. The lint-side hash-transparent roster is a new tuple, not an extension of `THE_SEVEN`.**
