# Phase 24.6 Plan 12: the housekeeping wave — a sweep with a derived universe, a roster read from its artifact, captions computed, and a loop that could never run Summary

Ruled wave 5. Four small carries, and the thread through all four is the same:
**an instrument whose subject is narrower than the surface it claims to
measure.** A grep with a hand-listed file set. A gate roster typed beside the
artifact that declares it. A caption typed beside the file it describes. A
branch guarding against something the step above it had already refused.

`D-26`: *"We learned in 24.5.1 what happens when the denominator is narrower
than the surface."*

## What was built

### Task 1 — the codified sweep and the derived roster (commit `cda5dd19`)

**`tests/invariants/test_present_tense_sweep.py`** (703 lines, 828 parametrized
rows + 15 property/control tests) replaces the criterion-15 grep that lived in
`.planning/phases/24.5.1-the-return-trip/24.5.1-BASELINES.md` §3.

|---|---|

| line-at-a-time | paragraph-at-a-time, decoration stripped, `module::Symbol` reduced to `Symbol` |
| a count | (file, line, phrase) triples |

**The wrapping finding, which is the one that mattered.** Five of the six sites
`24.6-L-09` names are wrapped across lines. A per-line scan over the same
universe finds **3 of 6**; the normalized scan finds **6 of 6** — and two more
nobody had listed (`run.py:28` and `README.md:139`, both wrapped). The
normalization is not decoration; it is the difference between the sweep working
and the sweep reporting clean.


The spec/ number is the exclusion's own control. Excluding by directory is only
defensible if the excluded pages actually carry the tokens — they carry 13,
including the `debt_ceiling` cites `D-IMPL-257` recast in place as dated prose —
so `test_the_spec_exclusion_is_load_bearing` fails if the exclusion ever becomes
a no-op nobody re-reads.

**The two carve-outs, both tested in both directions.** A dated `SUPERSEDED`
line is a quotation, not a claim. A `.py` line under `tests/` ending with
`# sweep-exempt: sabotage input` is a sabotage's INPUT — a control that plants
the retired output and watches a comparison reject it has to spell the retired
output. Both make the exempt line a paragraph BOUNDARY rather than a skipped
line, so its words cannot join their neighbors' and carry a phrase past the
scan. A marked line under `examples/` is still caught; an unmarked copy of the
marked line is still caught; the marker count over the universe is asserted to
be exactly one, at plan 06's needle.

**`CP04_IDS`** is now `yaml.safe_load(gates.yaml)["declaration"]["gates"]`. The
real-tree control compares what cp-04's modules claim by function name against
this set; while both sides were hand-maintained, the control could agree with
itself while disagreeing with the declaration. `CFT-G17` is excluded **by name**
(it is the id Dave withdrew) rather than by the arithmetic of a range, and the
derivation is proven live: an id removed from a scratch copy changes the set.

## Deviations from Plan

**1. [Rule 1 — instrument correctness] The xfail is per declared (path, phrase) pair, not per cp-04 path.**
The plan's interface block says *"rows whose path is under `examples/cp-04-*/`
or `tests/examples/test_cp_04_*.py` carry `pytest.mark.xfail(strict=True)`"*.
Applied literally that marks **21 cp-04 paths × 12 phrases = 252 rows**
(enumerated from `universe()`, not estimated), of which only 16 carry a
violation; the other **236 PASS**, and a strict xfail on a passing row is a
FAILURE. The plan also says the cp-04 rows *"currently XFAIL"*, which the
literal reading cannot deliver. Resolved by declaring `CP04_KNOWN_DEBT` —
the 16 measured pairs with their occurrence counts — and marking exactly those.
The set-and-count equality test carries the rest of the plan's intent.

**2. [Rule 2 — a lie this plan would have created] `produce.py`'s module docstring corrected.**
See Task 2 above. Deleting the branch would have left the docstring naming a
return value that no longer exists. Two sentences, one dated note, no code.

**3. The `24.5.1-BASELINES.md` docstring citation names the file, not a line.**
The plan asks the docstring to name the instrument it replaces. A `path:NN`
citation of that grep would land in the `no_anchor` bucket
`tests/invariants/test_citation_coverage.py` ceilings at zero, so the module
cites the file and the section (§3) instead. `make lint` rc 0 confirms.

**4. `tests/examples/test_cp_04_anchor.py` has no `CP04_IDS`.**
The execution brief said it *"gets `CP04_IDS` read from the artifact"*; measured,
that module has no roster at all (`grep -n 'CP04_IDS' tests/examples/test_cp_04_anchor.py`
→ nothing). The plan's own C-29 places the derivation in
`tools/product_gates_tests/test_check_product_gates.py`, which is where it went.
The anchor module got only its docstring clause, as the plan says.
