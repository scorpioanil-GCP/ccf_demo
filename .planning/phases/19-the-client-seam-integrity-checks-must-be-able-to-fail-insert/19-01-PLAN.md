## Rulings settled at planning, so they are not re-litigated in execution

1. **The one shape is `DoorOutcome`, defined in `src/ccf/products/door.py`.**
   `ccf.client.wire` re-exports it under the alias `WireOutcome`. This is
   `19-RESEARCH.md` §2.2 option **B**: no new import edge in either direction
   (`ccf.client → ccf.products` and `runtime → ccf.products` both already exist), and
   both published names keep importing from where they import from today, so
   `wire.__all__` is unchanged. Option A (`door.py` importing `ccf.client.wire`) was
   experimentally proven cycle-free and is still **rejected**: a producer-side shape
   module importing the client package reverses the established layering.
2. **`WireRequest` moves to `door.py` too.** The door has to name the type it echoes, and
   the door cannot import the client. `ccf.client.wire` re-exports it under the same
   name.
3. **The merged member set is exactly the five `WireOutcome` has today** —
   `request`, `product_json`, `content_address`, `replay_ref`, `refusal` — which is why
   `InProcessAdapter._encode` compiles unchanged and is **not** in this plan's
   `files_modified`. Do not add a sixth member. **No signature member is reserved**
   (`C-10`): a member nothing sets and nothing reads is the pattern this phase exists to
   close.
4. **The tool's `product_class` and `parameters` arguments stay, and the door
   cross-checks them against the encoded request.** `C-16` explicitly rejected reshaping
   the four §6.3 axis arguments wholesale. But two independent sources for the same fact
   is the bypass one level up: a caller could encode question A and supply arguments for
   question B, have A echoed and B answered, and the client's check would pass. So the
   handler refuses the disagreement by name, and resolves against the **decoded**
   request's parameters — one source for what is answered, and the echo is that same
   source.
5. **The clock does not move** (`C-15`, and `C-13` governing). `asked_at` stays a
   separate required tool argument computed client-side at `mcp_stdio.py:218-220`. The
   encoded `WireRequest` carries `temporal_boundary=None` when the caller sent `None`,
   and the door echoes that `None`. `door_answer` takes the resolved instant only inside
   the already-typed `ProductRequest`, never as something to echo. `door.py` is
   `__ccf_mode__ = "algorithmic"` and must stay clock-free.
