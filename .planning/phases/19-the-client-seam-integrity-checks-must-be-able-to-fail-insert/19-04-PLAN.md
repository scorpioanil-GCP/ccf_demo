wrapping each registered subject in a byte-corrupting decorator the adapter author never

argument, and it belongs in the docstring.

each with a control that shows it fails when the tamper is not caught.

## Rulings settled at planning, so they are not re-litigated in execution

1. **The decorator lives in `suite.py`, not in each binding module.** `C-12` says *"the
   suite wraps each registered adapter"*, which is explicit: an adapter author writes
   nothing and cannot opt out. A decorator per binding module would be a decorator an
   author can forget.
2. **The decorator WRAPS; it does not subclass.** `assert_wire_failure_parity` enforces
   `type(broken) is type(healthy)` for the break hook, and a wrapper cannot satisfy that.
   So the new legs state the **weaker** check explicitly — that the wrapper's inner
   adapter is the subject's own `connect(root)` — rather than silently dropping the
   same-type assertion. Say so in the docstring; a dropped check that nobody notices is
   this repo's recurring failure.
3. **The tamper keeps the bytes well-formed.** Appending a space inside the vessel's JSON
   text is a byte change that is not a contract violation, so the failure lands on the
   address check rather than on the parser (`codec.py:296`) or the contract check
   (`codec.py:254`). A tamper that broke JSON validity would make the leg prove the parser
   fires — `19-RESEARCH.md` Pitfall 3.
4. **The crossed echo is DERIVED, never spelled.** Read the question the leg was handed and
   produce a different one from it — flip an admitted parameter value, or suffix
   `product_id`. A spelled second question is a red no-hardcoding lint and would also put
   deployment vocabulary in a module whose whole claim is that it holds none.
5. **`D-GATE-18`'s zero-diff claim is not violated.** It was about binding a new *adapter*
   without touching the suite. Both new legs take the same `SUBJECTS` tuples and the same
   `provision` fixture; no existing leg changes; `test_inprocess_conformance.py` and
   `test_mcp_conformance.py` each gain exactly **two call lines**. Record that arithmetic
   (8 → 10 each) in the SUMMARY.

`_Tampering` is a small class holding `_inner: TransportAdapter` and
`_edit: Callable[[bytes], bytes]`, with `ask(self, request: WireRequest) -> bytes` returning
`self._edit(self._inner.ask(request))`. Its docstring states the argument that makes this
plan possible: the decorator is **generic and transport-blind because the seam is bytes**
(`C-05`), so an adapter author writes nothing and cannot opt out — and under the previous
object seam no such decorator could exist, which is how the defect survived.

Two module-private edit functions:

- the crossed-echo edit takes the bytes, parses them with
  `WireOutcome.model_validate_json` (raw parse, **not** `decode_outcome` — comment the
  reason), `model_copy`s the `request` to a **derived** different question, and re-encodes
  with the shipped `encode_outcome`. Derive the different question from the echo already on
  the wire: suffix its `product_id`, which needs no deployment vocabulary and changes the
  total-equality comparison on an axis `C-03` includes.
- the altered-vessel edit does the same parse, `model_copy`s `product_json` to the same
  text with **one space appended immediately after its opening brace**, leaves
  `content_address` at the producer's value, and re-encodes. Its docstring states the
  discrimination argument: the edited text is still valid JSON and still a valid contract,
  so the failure is attributable to the address check.

`assert_a_crossed_echo_is_caught(subjects, *, provision, question)` and
`assert_an_altered_vessel_is_caught(subjects, *, provision, question)` each:

1. call `_require_subjects(subjects, leg=...)` with a name for the leg;
2. per subject: provision a root, build `inner = subject.connect(root)`, wrap it in
   `_Tampering` with the leg's edit, drive a `ProductClient` on `question`, and require a
   `TransportError` whose message contains the leg's discriminating phrase. If no exception
   is raised, the `AssertionError` names the subject and says whether a served product or a
   refusal came back instead — the same wording shape `assert_wire_failure_parity` uses;
3. per subject: assert the wrapper's inner adapter **is** the object `subject.connect(root)`
   returned, stated explicitly as the weaker stand-in for the same-type check the break
   hook gets, with a docstring sentence saying why the stronger check cannot apply to a
   wrapper;
4. per subject: drive an **untampered** `ProductClient` on the same question against its
   own provisioned root and require a served, unrefused `Result`. The `AssertionError`
   here says that without this limb *"everything raises"* would pass the leg.

Both legs assert on the discriminating phrase so neither can pass on the other's failure.
Take the two phrases from `codec.py` — the echo message and the address message — and
hold them in two module-level `Final[str]` constants with a comment naming the codec lines
they mirror, so a message reword is one edit here rather than four.

Add both names to `__all__` in alphabetical position. Add nothing else to this module.
