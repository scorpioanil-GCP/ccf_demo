## Summary

Phase 13.3 closes four consensus residuals from the 13.2 cross-AI review (13.2-REVIEWS.md "Priority Fix List" items 2–5; item 1 and item 6 were resolved by 13.2 execution and deferred-to-14 respectively). All four are surgical changes to code that exists and was read in full this session: `runtime/ccf_runtime/mcp/experience.py` (builder validation + optional providers + agent-tool/resource description parameterization), `examples/external/00-hello-context/serve.py` (artifact-name assert), `examples/external/00-hello-context/replay_server.py` (startup orphan scan + URL-path fingerprint), and `examples/external/00-hello-context/fixtures/capture_proxy.py` (200+JSON-only recording, query-string forwarding). No new packages, no live capture, no new examples.

The dominant design constraint is the interlock between D-03 (allowlisted ⇒ provider+description required) and D-04 (backward compatibility). The current `build_experience_server` signature makes six provider/description parameters *required positional-by-keyword*; D-03/D-04 flips them to `Optional` with `None` defaults and moves the requiredness check to registration time, conditional on the allowlist. Existing callers (`serve.py`, `tests/crossproc/servers/mcp_experience_child.py`) pass everything and are untouched. The second-most-important constraint is the CINV-01/no-hardcoding lint: D-13's SDK-level default description constants for `list_agents`/`invoke_agent` (and D-14's resource default) are prose-in-code by ruling — they must stay under the lint's prose heuristics (`PROSE_CHARS = 200`, prompt-score) or land in `tools/lints/allowlist.yaml` with an explicit fingerprint entry.

**Primary recommendation:** Structure as two waves — (1) SDK builder changes in `experience.py` + unit tests + caller audit, (2) example-side changes (serve.py assert, replay_server orphan scan + path fingerprint, capture_proxy tightening) + `tests/examples/` guard tests — then close on `make test` and `make example-ext-00`.

### Locked Decisions

**Allowlist fail-fast seam**
- **D-01:** `build_experience_server` raises `ValueError` when `tool_allowlist` contains a name not in `EXPERIENCE_TOOLS`. Enforcement lives in the SDK builder — mechanism, not example glue.
- **D-02:** `serve.py` raises `ValueError` at composition time (before server start) when an artifact `tools.*.name` in `experience.yaml` does not equal the corresponding SDK tool constant, naming the offending artifact key and expected constant. No warn-and-continue.
- **D-03:** Fold in the provider-optionality residual: provider and description parameters of `build_experience_server` become optional (`None` defaults). New rule: a tool that IS allowlisted but lacks its provider or description raises `ValueError` at registration time (allowlisted ⇒ provider+description present).
- **D-04:** Backward compatible — parameters keep their names, become Optional keyword params with `None` defaults; existing callers passing everything are untouched.
- **D-05:** Test pinning: builder `ValueError` behaviors (unknown allowlist entry; allowlisted-without-provider) get unit tests next to existing experience.py tests; the artifact-name-mismatch raise gets a case in `tests/examples/`.

**Fingerprint guard strictness**
- **D-06:** `replay_server.py` scans fixture pairs at startup and refuses to start (clear error listing unpaired fixtures) when any response fixture lacks its `*-request.json` sibling. Symmetric: a request fixture with no response sibling also fails startup.
- **D-07:** The mandatory fingerprint-mismatch test (mutated request body → loud 500 with expected/actual) lives in `tests/examples/` alongside `test_ext00_fixture_schemas.py`, so `make test` collects it permanently.
- **D-08:** Include the URL path in the Gemini request fingerprint so model-in-URL drift is caught. The coarse fingerprint field set (same model/tools/count with different content passing) is documented as an intentional residual — not fixed.

**Capture-proxy semantics**
- **D-09:** Non-200 or non-JSON upstream responses: pass through to the client unchanged, record nothing. Error bodies never consume fixture ordinals.
- **D-10:** Forward `path + query` verbatim upstream (faithful `?alt=` capture). When persisting request fixtures, redact key-bearing query params (`key`, `api_key`); headers are never persisted (existing rule, restated as spec).
- **D-11:** No fresh live capture this phase. The tightened proxy is proven by unit tests with a fake upstream (404 / non-JSON / query-string cases). Existing 13.2 fixtures remain valid; no API keys or human D-10(13.1) checkpoint needed.

### Current state of each change site (verified this session)

**`build_experience_server` (experience.py:381–543).** Signature today: all six providers and three descriptions **required** keyword-only; `tool_allowlist: frozenset[str] | None = None`; line 454 does `allowed = EXPERIENCE_TOOLS if tool_allowlist is None else frozenset(tool_allowlist)` with **no validation** — unknown names silently register nothing. Registration blocks are `if <TOOL> in allowed:` guarded `@server.tool` decorators. `list_agents`/`invoke_agent` are registered **without** a `description=` kwarg — FastMCP falls back to the inner function's docstring (the CINV-01 inconsistency Cursor flagged). The templated resource at line 464 (`@server.resource(EXPERIENCE_PRODUCT_URI_TEMPLATE, ...)`) also carries no description (D-14 target — `FastMCP.resource` accepts a `description=` kwarg).

**`serve.py` (examples/external/00-hello-context, main() lines 486–652).** Loads `experience.yaml`; `tools = experience["tools"]`; passes `tools["get_context"]["description"]` etc. and `tool_allowlist=frozenset(experience["tool_allowlist"])`. The artifact's `tools.*.name` fields (`get_context`, `get_lineage`, `get_replay_record`) are currently **read but never compared** to `GET_CONTEXT_TOOL`/`GET_LINEAGE_TOOL`/`GET_REPLAY_RECORD_TOOL` — D-02 inserts that comparison before `build_experience_server` is called. serve.py already imports from `ccf_runtime.mcp.experience`; add the three `GET_*_TOOL` constants to that import.

**`replay_server.py`.** `_load_fixtures()` (lines 57–91) pairs `<prefix>-NN.json` with `<prefix>-NN-request.json`, storing `request: None` when the sibling is absent, and the handler **skips** the fingerprint check when `recorded_request is None` (line 160) — the soft-skip D-06 removes. A request fixture with no response sibling is currently silently ignored (the glob loop `continue`s on `-request.json` names). `fingerprint(prefix, body)` (lines 94–120) is a pure module-level function taking only prefix+body; D-08 requires threading the URL path in for the Gemini branch (change signature or add a path argument — the existing `tests/examples/test_ext00_fixture_schemas.py` already imports and unit-tests this helper via `importlib.util`, so the new signature must be reflected there).

**`capture_proxy.py`.** Handler (lines 76–116) forwards `f"{base}{path}"` — **query string dropped** (D-10 fixes: use `request.url.path` + `request.url.query`). It records unconditionally: `upstream.json()` on any status, ordinal consumed regardless (D-09 fixes: gate on `upstream.status_code == 200` and a JSON content-type/parse success; on failure pass the upstream response through and record nothing, ordinal untouched). Headers already never persisted (restate as spec comment). Query redaction on persisted request fixtures: strip/replace `key`, `api_key` params (redaction placeholder format is Claude's discretion). Note: persisted request fixtures today are body-only; if D-10's "faithful `?alt=` capture" means recording the query in the request fixture, redact there; if it only means forwarding, the redaction rule applies whenever query strings are written.

**Test homes.** `tests/examples/test_ext00_fixture_schemas.py` loads `replay_server` via `importlib.util` (example dir is not a package) — reuse that loading pattern for the new mismatch/orphan/proxy tests. "Next to existing experience.py tests" (D-05): the existing experience-builder tests live in `tests/crossproc/test_experience_edge.py` (which already has `test_an_allowlist_excluded_tool_is_never_registered` using `EXPERIENCE_TOOLS - {INVOKE_AGENT_TOOL}`); the new builder `ValueError` tests are plain construction-time unit tests and can live there (or an adjacent module) — they need no child process, just `pytest.raises(ValueError)` around `build_experience_server(...)`.

### Pattern 2: D-02 composition-time assert in serve.py

```python
# serve.py, before build_experience_server (D-02)
for artifact_key, constant in (
    ("get_context", GET_CONTEXT_TOOL),
    ("get_lineage", GET_LINEAGE_TOOL),
    ("get_replay_record", GET_REPLAY_RECORD_TOOL),
):
    declared = tools[artifact_key]["name"]
    if declared != constant:
        raise ValueError(
            f"experience.yaml tools.{artifact_key}.name is {declared!r}; the SDK tool constant is {constant!r}"
```

This is artifact *interpretation*, not authored domain values — consistent with No-Hardcoding (§6.4: code is interpreter).

### Pattern 3: Startup orphan scan (D-06)

Extend `_load_fixtures` (or a preceding scan) to collect two sets per prefix — response ordinals and request ordinals — and raise (or print-and-exit-nonzero, before `READY`) listing every unpaired filename, both directions. The existing "fail loudly" JSONResponse style is for request-time; startup failure should be process-exit with a clear message so `run.py`'s `readline()` handshake fails visibly rather than hanging (check how `run.py` handles a child that dies before READY — the parent's blocking readline gets EOF; an explicit stderr message plus nonzero exit is the right shape).

### Anti-Patterns to Avoid
- **Warn-and-continue anywhere** — every locked decision specifies raise/refuse.
- **Validating the allowlist in serve.py instead of the builder** (D-01 puts it in mechanism); serve.py's D-02 check is a *different* check (artifact names vs constants).
- **Making agent-tool descriptions required** — D-13 mandates the asymmetry (agent tools default, consumption tools required-when-allowlisted).
- **Long prose default constants** — keep D-13/D-14 defaults short and mechanism-describing, or the CINV-01 lint (`PROSE_CHARS = 200`, prompt-score) may flag them; if a default must be longer, add an allowlist.yaml fingerprint entry with justification.
- **Breaking the `fingerprint` helper import in `test_ext00_fixture_schemas.py`** when changing its signature for D-08 — update both together.
- **Adding CCF imports to replay_server.py / capture_proxy.py** — they are vendor stand-ins, deliberately fabric-free.

## Common Pitfalls

### Pitfall 1: Optional-params + mypy --strict
**What goes wrong:** Flipping nine parameters to `X | None = None` and then calling them inside registration closures makes mypy complain about possibly-None calls even after the runtime check.
**How to avoid:** Do the None-check immediately before the `@server.tool` block and bind to a narrowed local (`provider = context_provider; if provider is None: raise ...`), so the closure captures the non-Optional name. Repo bar is mypy --strict clean.

### Pitfall 2: CINV-01 lint vs D-13/D-14 default constants
**What goes wrong:** The no-hardcoding lint flags prose-shaped module-level string literals in `/runtime`; the new default description constants are exactly that shape.
**How to avoid:** Keep defaults terse and mechanism-voiced (< 200 chars, low prompt-score); run `python -m tools.lints` early; if flagged, an `allowlist.yaml` entry citing D-13 (Dave, 2026-08-02) is the sanctioned escape hatch. Warning sign: lint findings naming `experience.py`.

### Pitfall 3: Backward-compat blast radius of the signature change
**What goes wrong:** Only two non-example callers exist (`serve.py`, `tests/crossproc/servers/mcp_experience_child.py`) and both pass everything — but `tests/invariants/test_mcp_role_separation.py` and the source-grep assertions in `tests/crossproc/test_experience_edge.py` inspect `experience.py`'s source/identity and can break on structural edits (e.g., new imports, sibling-scheme strings in error messages).
**How to avoid:** Grep-audit both test files after editing; never mention `ccf-egress`/artifact URI schemes in new error strings; run `pytest tests/invariants/test_mcp_role_separation.py tests/crossproc/test_experience_edge.py` per change.

### Pitfall 4: D-08 fingerprint change invalidates committed fixtures' pairing
**What goes wrong:** Including the URL path in the Gemini fingerprint means comparing the *recorded* request's path against the *incoming* path — but committed `gemini-NN-request.json` fixtures are body-only; there is no recorded path to compare.
**How to avoid:** Two viable resolutions within the decisions: (a) derive the expected path from a stored field if present, else record the path going forward and treat absent-path in old fixtures as "compare model segment extracted from the incoming path against the fixture's implied model" — but that invents data; or (b) since D-11 forbids re-capture, compare the incoming request path across ordinals for consistency and/or fingerprint the path's `:generateContent` model segment against a single expected value derivable from `experience.yaml` `live_mode.gemini_model`... **This is the one genuinely underdetermined point in the phase** — see Open Questions. The safe planner move: store the incoming path at ordinal 0 and require subsequent ordinals to match (drift-within-run detection), OR extend the request-fixture format additively (a `"__path__"` key or sidecar) written by the tightened capture proxy for *future* captures while old fixtures fail-soft only on the path component — except D-06 forbids fail-soft on missing siblings, not on missing fields. Plan must pick one and state it; none of these contradict a locked decision.

### Pitfall 5: Orphan scan vs "empty fixtures dir is valid"
**What goes wrong:** replay_server's docstring commits to starting successfully with an empty/absent `fixtures/` dir (plan-03-era bootstrapping). A naive "any missing pair fails" scan could break the zero-fixture case — and `capture_proxy.py`/`diff_fixtures.py`/`README.md` live *inside* `fixtures/` and match `*.json` globs? (They don't — globs are `{prefix}-*.json` — but a scan rewritten with a broader glob could trip on them.)
**How to avoid:** Keep the `{prefix}-*.json` glob discipline; zero fixtures for a prefix remains valid (no pairs, no orphans); only *unpaired* files fail.

### Pitfall 6: Capture-proxy tests importing a module in a non-package dir
**What goes wrong:** `fixtures/` has no `__init__.py`; plain `import capture_proxy` fails under pytest.
**How to avoid:** Reuse the `importlib.util.spec_from_file_location` pattern already established in `test_ext00_fixture_schemas.py`.
