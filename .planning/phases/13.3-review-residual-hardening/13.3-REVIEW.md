## Summary

I verified each of the 16 prior findings against the current tree before
starting; every one describes code that no longer exists, and none is re-raised
here. The iteration-1 and iteration-2 fixes are individually sound: the CR-01
pre-forward 400 genuinely conserves ordinals (the parse precedes both the
forward and the `counters[prefix]` read); WR-02/NEW-01's `resolved or None`
collapse is correct through the argument seam and the env seam alike; WR-04's
conditional agent seams are consistent with the docstring, with `EXPERIENCE_TOOLS`
and with `serve.py`'s composition; WR-06's per-`client_id` `latest` map is
correct; IN-04's label-based record selection is genuinely order-independent
because both the writer and the reader go through the one shared
`get_context_request_label`.

**On the IN-01 path-prefix substitution (the primary question):** the mechanism
holds as a security boundary. `build_app` has no defaulted `secret`, so there is
no construction path that yields an open proxy. The check runs before the route
match, before the env key read, before the forward, and before the ordinal
claim. `strip_secret` uses `compare_digest`. The secret is stripped before the
upstream URL is built, so it never reaches the vendor; it is absent from the
recorded request and response bodies, from the recorded query (`QUERY_KEY`
records the query only, and the secret rides in the path), and from the
400/403/500 error bodies, which echo the *stripped* path. Path manipulation
cannot bypass it: the check is on segment 1 and Starlette performs no
dot-segment normalisation, so `/x/../<secret>/v1/messages` presents `x` and is
refused. I found one defect in it (WR-01) and one docstring overclaim (IN-01);
neither is a bypass.

The four warnings are all in the two categories the re-review was asked to
prioritise. Three of them (WR-01, WR-02, WR-03) sit in code and prose that IN-01
and IN-02 jointly rewrote in commit `f1bfa03` — exactly the interleaved region
flagged as the risk — and WR-04 is a cross-iteration interaction between WR-06
and a pre-existing `run.py` fallback. None is reachable from CI, because
`capture_proxy.py` is not on the `make example-ext-00` path and the `run.py`
fallback branch is not taken in the default leg set. That is why green gates do
not see them.

No finding contradicts a locked D-01..D-16 decision. No fix requires touching
`fixtures/*.json`, so D-11 immutability is unaffected. Nothing under `/src` is
implicated, so harness neutrality is untouched. On the IN-05 exemption: the
`SUFFIXES` / `ROUTES` notes do carry the argument they claim to — both modules
import nothing from CCF, both tables transcribe published vendor wire facts, and
both notes scope the exemption by naming what the rule still binds (no prompt,
no agent or task definition, no threshold, no policy value). I judge the
documentation sufficient and do not re-raise IN-05.

## Warnings

### WR-01: A non-ASCII first path segment crashes the capture proxy instead of refusing it

**File:** `examples/external/00-hello-context/fixtures/capture_proxy.py:169-181`, `204-218`
**Issue:** `strip_secret` passes the URL path segment straight into
`secrets.compare_digest`. Uvicorn (and the Starlette `TestClient`)
percent-decode `scope["path"]`, so a request to
`/%C3%A9/v1beta/models/m:generateContent` yields `presented == "é"` and
`compare_digest` raises
`TypeError: comparing strings with non-ASCII characters is not supported`.
Confirmed empirically against the current module:

```
POST /%C3%A9/v1beta/models/m:generateContent  ->  500 (unhandled exception)
```

That is an unhandled server error on an *unauthenticated* request, in the one
function whose whole job is to refuse unauthenticated requests cleanly. It is
not a bypass — nothing is forwarded, no key is read, no ordinal is claimed — but
an anonymous local caller can trigger a traceback at will, and the 403 contract
does not hold for that shape.

It is also a documentation-vs-code drift of exactly the class this phase already
shipped once (iteration-1 WR-01): the docstring asserts "Returns ``None`` on any
mismatch, which the handler turns into a ``403``". It does not — for a non-ASCII
segment it raises.

**Fix:** compare bytes.

```python
def strip_secret(path: str, secret: str) -> str | None:
    segments = path.split("/", 2)
    presented = segments[1] if len(segments) > 1 else ""
    if not secrets.compare_digest(
        presented.encode("utf-8"), secret.encode("utf-8")
    ):
        return None
    return "/" + (segments[2] if len(segments) > 2 else "")
```

Add the percent-encoded non-ASCII shape to the loop in
`test_a_request_without_the_capture_secret_is_refused`, driving it through
`TestClient(app, raise_server_exceptions=False)` so a 500 is observable rather
than re-raised into the test.

### WR-02: IN-02's new default output directory is a predictable, pre-creatable path in a shared temp dir

**File:** `examples/external/00-hello-context/fixtures/capture_proxy.py:313-324`, `201`
**Issue:** `default_out_dir()` returns
`Path(tempfile.gettempdir()) / f"ccf-ext00-capture-{stamp}"` with
second-granularity timestamp, and `build_app` opens it with
`out_dir.mkdir(parents=True, exist_ok=True)`. Two problems, both introduced by
the IN-02 fix — the previous default (`fixtures/`) had neither:

1. **Predictable path in a world-writable directory.** The name is fully
   derivable by any other local process. A hostile process can pre-create
   `/tmp/ccf-ext00-capture-<stamp>` — as a directory it owns, or as a symlink to
   a location of its choosing — and `mkdir(..., exist_ok=True)` accepts it
   silently. The captured vendor request and response bodies, which the operator
   subsequently promotes into the git tree, then land somewhere the attacker
   controls or can read. This is the same hostile-same-host threat model IN-01
   was fixed to defend against, so leaving this half open is inconsistent with
   the phase's own stated posture.
2. **"Fresh" is not actually guaranteed.** Two capture runs started within the
   same second resolve to the same directory, and `exist_ok=True` reuses it, so
   the second run's `anthropic-00.json` overwrites the first's — a quieter
   version of the very hazard IN-02 existed to remove. The docstring ("A fresh
   timestamped scratch directory") and `fixtures/README.md` step 3 ("a fresh
   timestamped scratch directory") both claim otherwise.
   `test_the_default_capture_output_dir_is_never_the_committed_fixtures` only
   compares against a year-2000 timestamp, so it cannot see this.

**Fix:** use `tempfile.mkdtemp`, which creates the directory atomically with
mode `0o700` and a random suffix:

```python
def default_out_dir(now: datetime | None = None) -> Path:
    stamp = (now or datetime.now()).strftime("%Y%m%dT%H%M%S")
    return Path(tempfile.mkdtemp(prefix=f"ccf-ext00-capture-{stamp}-"))
```

Keep `mkdir(parents=True, exist_ok=True)` for the explicit-`argv[1]` case only,
or have that case refuse a path that is a symlink. Update the docstring and
README step 3 to match, and extend the test to assert two back-to-back calls
differ (and, on POSIX, that the mode is `0o700`).

### WR-03: `fixtures/README.md` steps 7-8 still describe the pre-IN-02 output path

**File:** `examples/external/00-hello-context/fixtures/README.md:81-90` (vs `52-56`, `67-68`)
**Issue:** The IN-01/IN-02 README rewrite updated steps 3 and 4 of the capture
recipe but not the diff-review steps that consume their output. Step 7 tells the
operator to run:

```
python fixtures/diff_fixtures.py fixtures /tmp/capture-out
```

`/tmp/capture-out` is not a path this tool has produced since IN-02 landed — the
default is now `/tmp/ccf-ext00-capture-<stamp>`, printed by `main()` on its first
line. An operator following the recipe literally diffs against a nonexistent
directory, and `diff_fixtures.py` "exits nonzero when anything differs", so the
failure will read as fixture drift rather than as a wrong path. This is precisely
the interleaved-region interaction the re-review was asked to look for: steps 3/4
and steps 7/8 are two halves of one recipe and only one half was migrated.

Step 8 carries a smaller version of the same drift: it says "Copy the reviewed
recordings into `fixtures/`", while `default_out_dir`'s docstring and the fix
report both state that promotion is "an explicit reviewed `mv`". A copy leaves
the scratch capture — vendor responses recorded against a live key — sitting in
`/tmp` indefinitely.

**Fix:** parameterise steps 7-8 on the directory the proxy printed rather than a
literal, e.g. "`python fixtures/diff_fixtures.py fixtures <the directory the
proxy printed on its first line>`", and make step 8 a `mv` so it matches the
code's own claim. Add a closing sentence telling the operator to remove the
scratch directory after promotion.

### WR-04: WR-06's per-client refusal makes `run.py`'s D-15 fallback fail with an unnamed diagnostic

**File:** `examples/external/00-hello-context/run.py:642-664`; `examples/external/00-hello-context/serve.py:680-695`
**Issue:** WR-06 (iteration 1, `236d932`) made `get_replay_record` refuse for a
client that has served nothing. `run.py`'s D-15 fallback — taken when `bare` is
deselected — calls `get_lineage` and `get_replay_record` directly, *before*
`_mcp_probe` issues the `get_context` call that populates `latest[client_id]`.
It works today only because every other leg happens to call `get_context` first.
With `--legs ""` (which is accepted: `unknown` is empty, and PASS 1 prints an
empty leg list) or with any future leg that does not consume a product,
`_mcp_call_text` raises `AssertionError: get_replay_record refused: [...]`,
which reads as an Experience-surface regression rather than as "you deselected
the leg that produces the record". A reviewer chasing that message would look in
`experience.py`.

This is a genuine cross-iteration interaction: WR-06 changed the observable
behaviour of a path a pre-existing `run.py` branch depends on, and neither change
site mentions the other. The fix report flagged WR-06 as a behaviour change and
noted PASS 5 is green "with a single client" — this is the case it does not
cover.

**Fix:** make the dependency explicit rather than incidental. Hoist
`get_context_arguments` above the D-15 block and serve once in the fallback
branch:

```python
else:
    # WR-06: get_replay_record is per-client and refuses a client that has
    # served nothing. The bare leg normally satisfies that; when it is
    # deselected this stand-in must serve itself first.
    asyncio.run(
        _mcp_call_text(
            url,
            active["token"],
            experience["tools"]["get_context"]["name"],
            get_context_arguments,
        )
    )
    evidence = ...
```

Alternatively, reject an empty `--legs` selection outright with a named
`AssertionError` and document that the fallback presumes a prior serve.

### IN-01: The capture-proxy docstring overstates what the path secret defends against

**File:** `examples/external/00-hello-context/fixtures/capture_proxy.py:44-51`
**Issue:** "any local process — including a web page issuing a CORS-simple POST
— could otherwise spend vendor credit". The browser case is real and genuinely
mitigated. "Any local process" is not: the secret is exported into
`ANTHROPIC_BASE_URL` / `GOOGLE_GEMINI_BASE_URL` in the client legs' environment,
so a same-user process can recover it from `/proc/<pid>/environ`. Nothing is lost
relative to the baseline (such a process could read `ANTHROPIC_API_KEY` just as
easily), but given this phase's history of docstrings overclaiming guarantees,
the scope is worth stating exactly.

**Fix:** narrow the claim to "an unprivileged caller on loopback, including a
browser page issuing a CORS-simple POST", and add one sentence noting that a
same-user process able to read the client legs' environment is outside this
defence — as it is outside the API key's.

### IN-02: The WR-09 SDK-validation fallback degrades silently

**File:** `tests/examples/test_ext00_fixture_schemas.py:74`, `82-89`
**Issue:** When a future `google-genai` bump removes
`GenerateContentResponse._from_response`, `_FROM_RESPONSE` becomes `None` and the
Gemini response tests quietly drop from SDK-type validation to two `isinstance`
checks. That is the intended design, and it correctly avoids a failure that
"looks like fixture corruption" — but the run emits no signal, so a green suite
looks identical whether the strong or the weak assertion ran and the coverage
loss can persist unnoticed across many releases.

**Fix:** emit a warning on the degraded path so it appears in the run summary:

```python
if _FROM_RESPONSE is None:
    warnings.warn(
        "google-genai no longer exposes GenerateContentResponse._from_response;"
        " gemini fixture validation degraded to structural assertions",
        stacklevel=2,
    )
```

### IN-03: `_load_fixtures` derives the sibling filename with a replace-all

**File:** `examples/external/00-hello-context/replay_server.py:152-154`
**Issue:** `path.name.replace(".json", "-request.json")` substitutes every
occurrence, not the trailing one. Harmless for the committed `{prefix}-NN.json`
names, but it is a latent disagreement with `find_orphans`, which correctly
anchors on the suffix (`name[: -len(".json")]`). A fixture whose name contained
`.json` earlier in the string would pass the D-06 pairing check and then raise
`FileNotFoundError` at load — after `require_paired_fixtures` has already
declared the set sound.

**Fix:** anchor it, matching `find_orphans`:

```python
request_path = path.with_name(f"{path.name[: -len('.json')]}-request.json")
```
