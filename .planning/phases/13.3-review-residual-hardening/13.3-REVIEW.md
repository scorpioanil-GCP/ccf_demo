# Phase 13.3: Code Review Report

**Reviewed:** 2026-08-03
**Depth:** standard
**Files Reviewed:** 8
**Status:** issues_found

## Summary

The phase implements D-01 through D-14 substantially as decided: the allowlist fails
closed and "allowlisted implies provider + description" is enforced at build time
(`experience.py:519-526, 609-646`); `replay_server.py` refuses startup on unpaired
fixtures symmetrically (`find_orphans` / `require_paired_fixtures`); the capture proxy
gates recording on 200+JSON and redacts key-bearing query params; the agent tools and
the product resource now carry parameterized descriptions with SDK default constants.
Tests pin each of those behaviours.

What the review found is that several of the new guards are weaker than their own
docstrings claim, and one of them reintroduces the exact failure mode it was written to
prevent:

- The capture proxy consumes a fixture ordinal *before* it can fail on a malformed
  request body — the ordinal-renumbering hazard D-09 exists to eliminate (CR-01).
- The D-08 Gemini fingerprint compares the harness against itself: `run.py` feeds the
  same `GEMINI_FIXTURE_LABEL` constant to both the client leg and the replay server's
  expected side, so no *fixture* drift can be detected by it, and the expected side is
  read from ambient process environment inside an otherwise pure function (WR-01, WR-02).
- `build_experience_server`'s requiredness rule is applied conditionally to three seams
  and unconditionally to three others, so a deployment that allowlists no agent tools
  must still hand in dead `agent_directory` / `agent_invoker` callables — which
  `serve.py` duly does (WR-04, IN-03).
- `serve.py` crosses two untyped boundaries: raw artifact dicts into a Protocol declared
  to return `tuple[ExposedAgent, ...]`, and process-global `latest["replay_ref"]` shared
  across all callers of `get_replay_record` (WR-05, WR-06).

Assessment of the two flagged deviations. **D-10 redacted-query location** (redaction at
persist time in `capture_proxy.py` rather than at forward time) is sound: forwarding
verbatim is required for capture fidelity, and the disk boundary is the only place
redaction can happen without corrupting the upstream call. The one gap is case-
sensitivity of the parameter set (WR-03). **D-08 expected-model source** (env seam
instead of re-captured fixtures) is defensible given the no-re-capture constraint, but
the resulting guard is materially weaker than the docstrings assert, and nothing pins
`GEMINI_FIXTURE_LABEL` to the value `fixtures/README.md` documents (WR-01, WR-02).

## Critical Issues

### CR-01: Capture proxy consumes a fixture ordinal before it can fail, reintroducing the D-09 renumbering hazard

**File:** `examples/external/00-hello-context/fixtures/capture_proxy.py:169-187`
**Issue:** The ordinal is claimed at line 169-170, but the first operation that can throw
on caller-controlled input — `json.loads(body)` at line 177 — happens afterwards. Two
concrete paths:

1. A request body that is not valid JSON: `json.loads` raises `ValueError`, Starlette
   returns an unhandled 500 with a traceback, **and the ordinal is already spent**. The
   next successful capture writes `gemini-01.*` with no `gemini-00.*` — exactly the
   "a transient failure cannot shift the real turns' numbering" property the module
   docstring (lines 22-26) and D-09 commit to.
2. A body that is valid JSON but not an object (a list, a string): line 179
   `request_doc[QUERY_KEY] = ...` raises `TypeError`, same outcome.

The whole point of D-09 was that a non-recordable request must consume no ordinal; this
path consumes one and writes nothing. It is also the only unhandled-exception path in a
module whose sibling (`replay_server.py:231-243`, T-13.2-09) explicitly handles the same
malformed-body case with a loud JSON 500.

**Fix:** Parse and shape-check the request body *before* claiming the ordinal, and refuse
non-recordable requests the same way a non-200 is refused:

```python
            try:
                request_doc = json.loads(body)
            except ValueError:
                request_doc = None
            if not isinstance(request_doc, dict):
                return JSONResponse(
                    {"error": "request body is not a JSON object",
                     "path": path},
                    status_code=400,
                )
            # ... forward upstream, gate on 200+JSON as today ...
            if query:
                request_doc[QUERY_KEY] = redact_query(query)
            ordinal = counters[prefix]
            counters[prefix] = ordinal + 1
```

Add a unit test alongside `test_a_non_200_upstream_is_passed_through_and_never_recorded`
that posts `content=b"not json"` and asserts no ordinal was consumed by the subsequent
good capture.

## Warnings

### WR-01: The D-08 Gemini model guard compares the harness against itself and cannot detect fixture drift

**File:** `examples/external/00-hello-context/replay_server.py:162-205`; `run.py:107, 346, 527`
**Issue:** `fingerprint()`'s expected side reads `CCF_EXT00_GEMINI_MODEL`; `run.py` sets
that variable and `CCF_EXAMPLE_GEMINI_MODEL` from the *same* module constant
`GEMINI_FIXTURE_LABEL` (lines 346 and 527). Both sides of the comparison therefore
originate in one literal. The docstring claims "a request for a different model would be
served another model's fixture (D-08)" is prevented — but the recorded fixture is not on
either side of that comparison, so a fixture recorded against a different model is
undetectable. What the check *does* catch is a client leg that ignores
`CCF_EXAMPLE_GEMINI_MODEL`; that is a real but much narrower guarantee than stated.
Additionally nothing mechanically ties `GEMINI_FIXTURE_LABEL` to the `gemini-fixture`
value documented in `fixtures/README.md:66` — a rename in one place silently diverges.

**Fix:** Either (a) record the model into the request fixture under a reserved key at the
next capture (the `QUERY_KEY` precedent already exists in `capture_proxy.py`) and read
the expected side from the fixture, or (b) narrow the docstrings in both files to state
the actual guarantee ("catches a client leg that does not honour the pinned model label";
fixture-vs-model correspondence is unverified) and add a test asserting
`GEMINI_FIXTURE_LABEL` equals the label `fixtures/README.md` documents.

### WR-02: `fingerprint()` reads process environment, making a pure reduction ambient-state dependent

**File:** `examples/external/00-hello-context/replay_server.py:200-204`
**Issue:** `os.environ.get("CCF_EXT00_GEMINI_MODEL", "")` inside `fingerprint()` means the
function's output depends on invisible global state. The module docstring advertises
standalone startup (`python replay_server.py`, lines 36-38); run that way, the variable
is unset, every Gemini request fingerprints `url_model: ""` against a real path model,
and every call 500s with a diagnostic that names a mismatch the operator has no way to
interpret. The default is also silent: an unset variable is indistinguishable from an
intentionally empty model.

**Fix:** Read the value once in `build_app()` and close over it, and fail loudly when it
is absent rather than defaulting to `""`:

```python
def build_app(fixtures_dir: Path = FIXTURES, *, expected_gemini_model: str | None = None):
    expected_model = expected_gemini_model or os.environ.get("CCF_EXT00_GEMINI_MODEL")
    if expected_model is None:
        raise SystemExit("CCF_EXT00_GEMINI_MODEL must be set; run.py supplies it")
```

and pass it into `fingerprint(...)` explicitly.

### WR-03: Query-parameter redaction is case-sensitive and exact-match only

**File:** `examples/external/00-hello-context/fixtures/capture_proxy.py:87, 98-111`
**Issue:** `REDACTED_QUERY_PARAMS = {"key", "api_key"}` is compared with `name in ...`
against the raw parsed name. `?Key=SECRET`, `?API_KEY=SECRET`, or `?access_token=SECRET`
are persisted verbatim into a git-tracked fixture directory. The redaction is the only
thing standing between a live key and a committed file, so it should be the conservative
side of the trade.

**Fix:** Normalize case and match on substring for key-shaped names:

```python
_SECRET_MARKERS = ("key", "token", "secret", "password")

def _is_secret(name: str) -> bool:
    lowered = name.lower()
    return any(marker in lowered for marker in _SECRET_MARKERS)
```

Add a test case with `?Key=` and `?access_token=`.

### WR-04: `build_experience_server` applies "required only when exposed" to three seams and not to the other three

**File:** `runtime/ccf_runtime/mcp/experience.py:412-430, 557-607`
**Issue:** D-03's stated principle is that "requiredness is conditional on exposure"
(docstring lines 462-471). It is implemented for `context_provider` / `lineage_provider` /
`replay_record_reader`, but `product_resolver`, `agent_directory`, and `agent_invoker`
remain unconditionally required even when `LIST_AGENTS_TOOL` and `INVOKE_AGENT_TOOL` are
absent from the allowlist. The consequence is visible in `serve.py:587-595`: the example
allowlists only the three consumption tools, yet must still supply an
`agent_directory` closure and an `agent_invoker` that only raises — dead seams that exist
to satisfy a signature. That is precisely the shape D-03 was written to remove.

**Fix:** Give the three agent/product seams `None` defaults and apply `_missing()` to them
on the same conditional terms; `product_resource_description` already defaults, so the
product resource can register with `product_resolver` required only when it is registered.
Extend `test_an_allowlisted_tool_without_its_provider_is_refused` to cover
`INVOKE_AGENT_TOOL` with `agent_invoker=None`.

### WR-05: `agent_directory` returns raw YAML values where a typed `tuple[ExposedAgent, ...]` is contracted

**File:** `examples/external/00-hello-context/serve.py:587-592`
**Issue:** The closure is annotated `-> tuple[()]` and returns
`tuple(experience["agent_exposure"]["agents"])`, i.e. whatever the artifact holds. It is
empty today, so nothing fails. The moment a user follows the README's "what to change
first" instinct and adds an entry, raw dicts flow into
`agent_tool_listing(agent)` (`experience.py:369-401`) and blow up on `agent.skills` with
an `AttributeError` — validation deferred past the boundary, which CLAUDE.md §11 forbids
("Validation is at the boundary, never deferred"). The `-> tuple[()]` annotation also
does not conform to `AgentDirectoryProtocol.__call__`'s declared return type.

**Fix:** Validate at the artifact boundary and return the typed contract:

```python
        def agent_directory(*, tenant: str) -> tuple[ExposedAgent, ...]:
            del tenant
            return tuple(
                ExposedAgent.model_validate(entry)
                for entry in experience["agent_exposure"]["agents"]
            )
```

### WR-06: `get_replay_record` serves whichever record was written last, for any authenticated caller

**File:** `examples/external/00-hello-context/serve.py:543, 558, 614-622`
**Issue:** `latest["replay_ref"]` is a single process-global slot mutated by every serve
(`_serve_recorded`). `replay_record_reader()` returns whatever is in it, with no check
that the requesting client is the one whose delivery produced that record — and the
`ServeRequestRecord` written at line 562-569 is deliberately per-`client_id`, so the
deployment clearly does distinguish callers elsewhere. Client A's decision record is
readable by client B, and under concurrent requests a caller can read a record that is
not its own even with one client. As a demonstration of "audit by construction" this
teaches a cross-tenant/cross-client read as the default shape.

**Fix:** Key the slot by the verified identity and read it back through
`get_access_token()`:

```python
        latest: dict[str, ArtifactRef] = {}
        ...
            latest[token.client_id] = served.replay_ref
        ...
        def replay_record_reader() -> str:
            token = get_access_token()
            assert token is not None
            ref = latest.get(token.client_id)
            if ref is None:
                raise ExperienceProductNotServable("no product served for this client")
```

### WR-07: `_spawn` blocks on `readline()` with no timeout and leaks the stderr file handle

**File:** `examples/external/00-hello-context/run.py:212-237`
**Issue:** Two problems in one function. (a) `proc.stdout.readline()` has no timeout: the
docstring reasons only about a child that *dies* (stdout closes, readline returns empty).
A child that starts but never reaches `READY` — a uvicorn bind that stalls, a fixture load
that blocks — hangs `run.py` forever, and since this runs in CI it hangs the build with no
diagnostic. (b) `stderr=stderr_path.open("wb")` creates a file object that is never
closed; on the exception path in this same function the handle is leaked outright.

**Fix:** Open the stderr file in a `with` (or store and close it in `_terminate`), and
bound the wait — e.g. a watchdog thread that kills the child after N seconds, or
`select.select([proc.stdout], [], [], READY_TIMEOUT_SECONDS)` before the readline, raising
an `AssertionError` naming the script and stderr path on timeout.

### WR-08: Load-bearing invariant checks are `assert` statements in runnable example code

**File:** `examples/external/00-hello-context/serve.py:485, 491-497, 546`; `run.py:230, 257, 282, 331, 363-366, 427, 472-475, 496`
**Issue:** `python -O` removes every one of these. The affected checks are not
belt-and-braces: `serve.py:485` is the gate-admission check, `491-497` is the fabric-side
self-check the docstring calls "before anything external sees it", `serve.py:546-547`
`assert token is not None` guards a subsequent `token.client_id` dereference, and
`run.py`'s eight PASS assertions *are* the example's assertion suite — under `-O` the
example prints "OK (8 assertions)" having checked none of them. `run.py:363-366` (the 401
refusal, D-12/T-13.1-11) is the security-relevant one.

**Fix:** Convert the checks that carry a guarantee into explicit raises, at minimum
`serve.py:485`, `serve.py:491-497`, `serve.py:546`, and every `assert` in `run.py` that
backs a printed `PASS` line:

```python
    if response.status_code != 401:
        raise AssertionError(
            f"revoked token was not refused with 401 (got {response.status_code})"
        )
```

### WR-09: Fixture schema test depends on a private google-genai API

**File:** `tests/examples/test_ext00_fixture_schemas.py:71-73`
**Issue:** `GenerateContentResponse._from_response(response=..., kwargs={})` is a private
underscore method. The comment justifies *why* the public `model_validate` is inadequate
(forward-compat fields), which is fair, but a private call in a permanently-collected CI
test is a silent breakage waiting on the next `google-genai` bump — and it will fail in a
way that looks like fixture corruption rather than an SDK upgrade.

**Fix:** Either pin `google-genai` with a comment naming this call site as the reason, or
drop to structural assertions on the response fixture (`candidates[0].content.parts`)
matching the treatment the request fixtures already get, and note the trade-off.

## Info

### IN-01: Capture proxy is an unauthenticated confused deputy for the operator's API key

**File:** `examples/external/00-hello-context/fixtures/capture_proxy.py:126-141, 201-208`
**Issue:** Any local process — including a web page POSTing to `http://127.0.0.1:<port>/`
as a CORS-simple request — can cause the proxy to inject the operator's real
`ANTHROPIC_API_KEY` / `GOOGLE_API_KEY` and forward an arbitrary body upstream, spending
credit and writing attacker-controlled content into the fixture tree. The response body
is not readable cross-origin, so this is credit-spend and fixture-poisoning rather than key
exfiltration, and the tool is documented as ephemeral and never CI-wired.
**Fix:** Require a shared secret header (generated and printed alongside `READY <port>`)
before forwarding, or note the exposure explicitly in the module docstring's security
posture paragraph.

### IN-02: Capture proxy defaults its output directory to the committed fixtures directory

**File:** `examples/external/00-hello-context/fixtures/capture_proxy.py:59, 203`
**Issue:** Running with no `argv[1]` overwrites `anthropic-00.json` etc. in place. The
docstring says "review the diff before committing", and the files are git-tracked, so this
is recoverable — but a destructive default in a tool whose stated job is one-time capture
is an easy foot-gun.
**Fix:** Default to a timestamped subdirectory and print the path, leaving the promotion
into `fixtures/` an explicit `mv`.

### IN-03: `agent_invoker` in `serve.py` is an unreachable closure

**File:** `examples/external/00-hello-context/serve.py:594-595`
**Issue:** `invoke_agent` is not in the artifact allowlist, so the tool is never
registered and this closure cannot be reached from the wire — the comment at 588-591 says
as much. It exists only to satisfy the unconditional signature (WR-04). Dead code that
the example nonetheless teaches by example.
**Fix:** Remove once WR-04 makes the seam conditional.

### IN-04: `run.py`'s D-16 reproduction silently depends on ordering inside `_mcp_probe`

**File:** `examples/external/00-hello-context/run.py:603-614, 420-433`
**Issue:** `_assert_byte_equal_reproduction` resolves `versions[-1]` — the newest
`ServeRequestRecord` — and compares against `served_text`, which came from the
`get_context` call. That only lines up because `_mcp_probe` happens to call
`read_resource` before `call_tool`. Reordering those two lines inside `_mcp_probe` makes
the assertion compare a record from a different serve. It would still pass today (one
product, identical bytes), which is worse: the coupling is invisible and only breaks when
the example grows a second product.
**Fix:** Have `get_context` return, or the probe capture, the specific `replay_uri` for
that serve rather than reaching for "newest in the store".

### IN-05: Routing tables and vendor base URLs as code constants in `/examples`

**File:** `examples/external/00-hello-context/replay_server.py:60-63`; `fixtures/capture_proxy.py:63-78`
**Issue:** `SUFFIXES` and `ROUTES` are literal routing tables in example code, which
CLAUDE.md §6.4 names explicitly ("No task graph, routing table, ... expressed as code
constants"). The mitigating reading — these are vendor wire-protocol facts, not deployment
values, and both files are stand-ins for a vendor API rather than fabric code — is
reasonable and the modules say so. Recorded so the judgment is deliberate rather than
overlooked.
**Fix:** No change required; consider one sentence in each docstring stating why the table
is protocol rather than configuration.
