# Phase 13.3 Plan 02: External-Example Hardening Summary

Every warn-or-skip path the 13.2 review found in `examples/external/00-hello-context`
now fails fast — artifact-name drift at composition time, unpaired fixtures before
READY, model-in-URL drift at fingerprint time, and error responses at the capture
proxy — each pinned by a permanent test in `tests/examples/`.

## What Was Built

**`serve.py` (D-02)** — imports `GET_CONTEXT_TOOL` / `GET_LINEAGE_TOOL` /
`GET_REPLAY_RECORD_TOOL` and declares `TOOL_NAME_BINDINGS`, the artifact-key →
SDK-constant table this deployment actually composes against. `validate_tool_names()`
raises `ValueError` naming the artifact key, the declared value, and the expected
constant; it is called immediately before `build_experience_server`. Previously a
renamed `tools.*.name` was silent until a caller invoked a tool that had never been
registered. Factored as a module-level function so the guard is testable without
running `main()`.

**`replay_server.py` (D-06/D-08)**

- `find_orphans(fixtures_dir)` collects response-without-request AND
  request-without-response filenames per prefix, keeping the `{prefix}-*.json` glob
  discipline that excludes `capture_proxy.py` / `README.md` / `diff_fixtures.py`.
  `require_paired_fixtures()` prints them to stderr and `SystemExit(1)`s — called at
  the top of `main()`, before READY, so `run.py`'s blocking readline sees the child
  die. A missing or empty directory still yields zero orphans and starts.
- The handler's `if recorded_request is not None:` soft-skip is gone. `_load_fixtures`
  now reads the sibling unconditionally, so no ordinal can serve unfingerprinted —
  deleting a `-request.json` used to buy exactly that.
- `fingerprint(prefix, body, path="")` gained a `url_model` field on the Gemini branch,
  extracted from the `/models/{model}:generateContent` segment. The Gemini body carries
  no model, so without this a request for a different model was served another model's
  fixture. The expected side (computed from the body-only recorded fixture, no path)
  reads `CCF_EXT00_GEMINI_MODEL`. The coarse content-level residual is documented in
  the docstring as intentional (D-08).
- `_build_app()` → `build_app(fixtures_dir=FIXTURES)`, and `_load_fixtures` takes the
  directory, so the guards are exercised against `tmp_path` without spawning a process.

**`run.py`** — spawns the replay-server child with `CCF_EXT00_GEMINI_MODEL` set, via a
new optional `env` parameter on `_spawn`. Its docstring now records why a pre-READY
child death is visible rather than a hang (the readline returns empty and the assertion
names the script and its stderr file — RESEARCH assumption A2 verified, no code change
needed).

**`fixtures/capture_proxy.py` (D-09/D-10)**

- Forwards `base + path + "?" + query` — the query was being dropped, making captures
  unfaithful to the call the SDK made (`?alt=sse` selects a different response shape).
- Records only a 200 carrying JSON. Every other upstream answer (429, 500, SSE stream,
  HTML error page) returns to the caller byte-for-byte via
  `Response(content=..., status_code=..., media_type=...)` and consumes **no** ordinal,
  so a transient vendor failure can no longer renumber the real turns.
- A non-empty request query is persisted under the reserved `__request_query__` key with
  `key` / `api_key` values replaced by `REDACTED`, parsed and re-encoded through
  `parse_qsl`/`urlencode` rather than string-spliced. Headers remain off disk in both
  directions. The existing `json.dumps(..., indent=2, sort_keys=True) + "\n"` persist
  format is unchanged.
- `build_app(out_dir, transport=None)` takes an injectable httpx transport so the tests
  run against a fake upstream with no sockets and no API keys.

**`tests/examples/test_ext00_hardening.py`** (new, ~370 lines, 14 tests) — the permanent
guards: 2 for D-02/D-05, 2 for D-07 (drifted body → 500 with differing
`expected`/`actual`; undrifted body still served), 4 for D-06 (both orphan directions,
the committed set fully paired, an empty dir still starting), 2 for D-08, and 4 for
D-09/D-10. `tests/examples/test_ext00_fixture_schemas.py` was updated in the same commit
as the signature change and now also asserts `url_model`.

## Deviations from Plan

**1. [Rule 1 - Bug] The D-08 expected model comes from `GEMINI_FIXTURE_LABEL`, not `live_mode.gemini_model`**

- **Found during:** Task 2
- **Issue:** The plan (and RESEARCH Open Question 1) specified exporting
  `CCF_EXT00_GEMINI_MODEL` from `experience.yaml` `live_mode.gemini_model`
  (`gemini-3.5-flash`). But the replay server runs **only** in offline mode, and in
  offline mode `run.py` hands the adk leg `CCF_EXAMPLE_GEMINI_MODEL=GEMINI_FIXTURE_LABEL`
  (`gemini-fixture`) — so the incoming URL path carries `gemini-fixture`. Pinning the
  expected side to the live model name would have made every adk-leg request mismatch
  and broken `make example-ext-00`, which D-11 requires green.
- **Fix:** `run.py` exports `CCF_EXT00_GEMINI_MODEL=GEMINI_FIXTURE_LABEL` — the same
  label it gives the leg, from the same existing module constant. This is also the
  semantically correct source: the replay server serves fixtures, and
  `GEMINI_FIXTURE_LABEL` is already documented as naming a fixture rather than a
  deployment model. The live model name stays in `experience.yaml` for live mode, where
  no replay server exists.
- **Files modified:** `examples/external/00-hello-context/run.py`
- **Commit:** `8841f7c`

**2. [Rule 2 - Missing spec] Where the redacted query is persisted**

- **Found during:** Task 3
- **Issue:** D-10 requires redacting key-bearing params "when persisting request
  fixtures", but request fixtures are bodies-only and the plan did not say where a query
  lands. A sibling `*-query.json` file was rejected outright: it would match the
  `{prefix}-*.json` glob and register as an orphan in the D-06 scan.
- **Fix:** the redacted query is written into the request fixture under the reserved
  `__request_query__` key, and **only when the request carried a query**. The committed
  13.2 fixtures are query-less, so their shape is untouched and the schema tests are
  unaffected; the replay server's fingerprint reads only known fields, so a future
  query-carrying capture is inert to it.
- **Files modified:** `examples/external/00-hello-context/fixtures/capture_proxy.py`
- **Commit:** `463b966`

**3. [Plan-sanctioned] `_build_app` → `build_app` in both example modules**

Both modules hardcoded their directory. The plan directed parameterizing "if hardcoded";
both were, so `build_app` is now public and directory-taking (and transport-taking in the
proxy). No behavior change for the spawned-process path.

No Rule 4 deviations — nothing architectural. No CCF imports entered `replay_server.py`
or `capture_proxy.py`.
