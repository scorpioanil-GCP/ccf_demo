## Gemini Review

This review evaluates Phase 13.3 "Review-Residual Hardening," which addressed the four consensus residuals from the Phase 13.2 cross-AI review. The phase was executed in two waves (SDK builder and example-side) and followed by a rigorous internal code review that resulted in 10 additional fixes.

### Summary
The plan was exceptionally sound, characterized by high-fidelity mapping of review residuals to specific code sites and a strong TDD discipline. The outcome successfully achieves the phase goal of transforming "warn-or-skip" paths into "fail-fast" semantics. By moving validation to the earliest possible boundary—whether at composition time in `serve.py`, builder time in `experience.py`, or startup in `replay_server.py`—the system now prevents silent divergence between intended and served tool surfaces. The post-execution internal review significantly strengthened the implementation, particularly regarding concurrency safety (WR-06) and ordinal conservation (CR-01).

### Strengths
*   **Composition-Root Validation (D-02):** Validating artifact keys against SDK constants in `serve.py` before construction is a textbook example of "failing fast" at the deployment boundary.
*   **Symmetric Orphan Detection (D-06):** The startup scan in `replay_server.py` prevents a significant repudiation hazard (deleting a request sibling to bypass fingerprinting) and ensures fixture integrity before the server reports `READY`.
*   **Ordinal-Safe Capture (CR-01 Fix):** The refined capture proxy correctly parses and gates the request body before claiming an ordinal, ensuring that malformed local traffic does not "shift" the numbering of recorded vendor turns.
*   **Client Isolation (WR-06 Fix):** The transition from a process-global `latest["replay_ref"]` to a client-keyed mapping in `serve.py` corrects a cross-client data leak and ensures the example teaches "audit by construction" correctly.
*   **Robust Signal Propagation (WR-07 Fix):** Using `select.select` with a timeout for the `READY` handshake prevents silent CI hangs, a common failure mode in complex harness-adapter environments.

### Concerns
*   **Gemini Fixture Drift (WR-01 residual) [MEDIUM]:** While client-leg drift is now caught, the Gemini fingerprint still cannot detect drift in the fixture bytes themselves (since the expected model is env-pinned rather than recorded). This remains a gap compared to the Anthropic path.
*   **Routing Tables as Constants (IN-05) [LOW]:** `replay_server.py` and `capture_proxy.py` contain literal routing tables. While defensible as "protocol facts" for vendor stand-ins, they technically violate the §6.4 No-Hardcoding rule. This sets a potentially confusing precedent for users looking to follow the SDK's own conventions.
*   **Confused Deputy Risk (IN-01) [LOW]:** The capture proxy remains an unauthenticated local deputy for the operator's API keys. While ephemeral and not CI-wired, it represents an information disclosure path for any local browser/process.
*   **Private API Dependency (WR-09) [LOW]:** The fixture schema test still relies on `google-genai`'s private `_from_response`. Although guarded by a `getattr` fallback, it remains a point of fragility for future SDK upgrades.

### Suggestions
1.  **Refine Gemini Fingerprint:** For the next re-capture wave, record the model name into the `*-request.json` fixture under a reserved `__model__` key (mirroring the `__request_query__` precedent) to enable true fixture-drift detection.
2.  **Add Shared-Secret to Proxy:** To close the IN-01 exposure, have the proxy generate and print a one-time Bearer token at startup that `client_adk.py` must present, ensuring only the intended leg can consume the operator's credit.
3.  **Formalize Protocol Exemption:** Explicitly document in `CLAUDE.md` that routing tables *are* permitted in harness/vendor stand-ins when they represent immutable wire-protocol facts rather than deployment logic, to reconcile IN-05 with §6.4.

### Risk Assessment: LOW
The phase has successfully closed the primary "soft failure" modes identified in Wave 3. The risk of regression is minimal due to the exhaustive pinning of `ValueError` behaviors and the verification that all existing 13.2 fixtures remain valid (D-11). The behavior changes (returning 400s and refusing unserved records) align strictly with the "fidelity first" mandate. The system is now significantly more robust for external adopters.

## Codex Review

**Summary**  
The Phase 13.3 plans were sound and appropriately scoped: they mapped each 13.2 residual to the right ownership boundary, pinned behavior with permanent tests, and avoided new capabilities or fixture recapture. Based on the supplied execution, review, fix, and verification records, the final outcome achieves the phase goal. The 10 applied fixes mostly strengthen the implementation rather than widen scope; the three fixer deviations are defensible. Residual risk is mainly in operator-local capture tooling and example pedagogy, not in the core SDK hardening goal. I could not independently re-run workspace inspection because the shell sandbox failed before command execution.

**Strengths**
- SDK vs example responsibility was cleanly separated: allowlist validation lives in `build_experience_server`, while artifact-name validation lives in `serve.py`.
- The fail-fast semantics are now broad and tested: unknown allowlist entries, missing allowlisted seams, artifact-name drift, unpaired fixtures, and fingerprint mismatches all fail loudly.
- The fix pass addressed the most important behavioral defect: malformed capture requests no longer consume fixture ordinals.
- WR-06’s per-client replay-record lookup is a clear correctness and security improvement over “last global record wins.”
- The D-08 compromise is honestly documented after fixes: it catches client URL-model drift, not fixture-vs-model provenance drift.
- Verification breadth is strong: lint, strict mypy, full tests, example e2e, optimized `python -O`, and fixture immutability were all checked.

**Concerns**
- **MEDIUM:** IN-01 remains the largest residual security issue. The capture proxy is operator-local, but an unauthenticated localhost proxy that injects real API keys is still a confused-deputy risk. A browser-origin POST or local process could spend API credit or poison fixtures.
- **MEDIUM:** IN-02 remains a usability/data-loss foot-gun. Defaulting capture output to the committed fixture directory makes accidental fixture overwrite too easy, even if git makes recovery possible.
- **LOW:** IN-05 is acceptable but should be explicitly documented. The routing tables and vendor base URLs in example code are best interpreted as vendor wire-protocol constants, not CCF/domain configuration. Without that explanation, they look like a No-Hardcoding Rule exception by accident.
- **LOW:** WR-02’s “loud 500 on Gemini request” deviation is sound, but it leaves missing `CCF_EXT00_GEMINI_MODEL` as a runtime discovery. That is acceptable for preserving standalone/Anthropic behavior, but less crisp than startup validation.
- **LOW:** WR-04’s product resolver remaining required is sound because the product resource is always registered. The risk is only conceptual: if tool allowlisting later expands into resource exposure control, this seam will need revisiting.
- **LOW:** WR-05’s closure removal is sound for the shipped example. If the example later grows agent exposure, it will need a real typed `agent_directory` path rather than just validation telling the user what to add.
- **LOW:** The `google-genai` private API fallback reduces fragility, but still depends on a private method when present. This is acceptable for fixture validation, not ideal as a long-term dependency posture.

**Suggestions**
- Add a shared-secret header or nonce path to `capture_proxy.py`, printed with `READY`, and require it before forwarding.
- Change the capture proxy default output to a timestamped scratch directory; require an explicit path to write into committed fixtures.
- Add short comments/docstrings for IN-05 explaining that `SUFFIXES`, `ROUTES`, and vendor base URLs are vendor protocol facts, not SDK routing/configuration.
- Consider a startup warning or Gemini-only preflight when Gemini fixtures exist but the expected model label is absent, while preserving standalone non-Gemini startup.
- For future agent exposure, add an example-owned typed adapter that validates YAML into `ExposedAgent` and pass it only when `list_agents` is allowlisted.
- Replace the private `google-genai` validation path eventually with either a public API or a repo-owned structural schema sufficient for fixture guarantees.

**Risk Assessment**  
**Overall risk: LOW.** The phase goal is met, the important review blocker was fixed, and the behavior changes are directionally safer: malformed unrecordable capture requests now fail before forwarding, and replay records are no longer cross-client global state. The remaining risks are mostly confined to example capture tooling and documentation clarity. They are worth cleaning up, but they do not undermine Phase 13.3’s core deliverables.

### 4. Suggestions  

1. **Fix CR‑01** – move the JSON‑parsing validation **before** any ordinal is claimed. If parsing fails, immediately return a 400 (or 500 with a clear error) **without** touching `counters[prefix]`. This restores the true D‑09 guarantee that malformed or non‑JSON bodies never renumber the fixture sequence.  
2. **Align documentation with reality for D‑08** – update the `fingerprint()` docstring (and the design document referenced by D‑08) to state explicitly that the guard catches **client‑leg model drift**, not fixture‑drift, and that the expected model is supplied via an environment seam. 3. **Consider a stricter redaction policy** – either expand the secret‑keyword list to include common patterns (`secret`, `passwd`, `credential`) or switch to a *regex* that redacts any query‑parameter whose name contains “key”, “token”, “secret”, “pwd”, “auth”, etc., case‑insensitively.  
4. **Document the routing‑table rationale** – add a top‑level comment in `replay_server.py` and `capture_proxy.py` stating why the literal tables are protocol‑level constants, citing CLAUDE.md §6.4 as the authority. This will silence any future lint‑rule tightening.

7. **Add a regression test for the ordinal‑consumption bug** – after fixing CR‑01, add a test that performs a malformed request followed by a valid one and asserts the ordinals of the resulting fixtures are `00`, `01` (i.e., the malformed request did *not* consume an ordinal).
