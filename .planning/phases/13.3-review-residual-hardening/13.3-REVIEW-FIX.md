## Fixed Issues

### CR-01: Capture proxy consumed a fixture ordinal before it could fail

**Files modified:** `examples/external/00-hello-context/fixtures/capture_proxy.py`, `tests/examples/test_ext00_hardening.py`
**Commit:** `e4b1912`
**Applied fix:** The request body is now parsed and shape-checked immediately
after `await request.body()` — before anything is forwarded upstream and before
`counters[prefix]` is read. A body that is not a JSON object gets a `400` naming
the reason; nothing is forwarded and no ordinal is claimed.

I deliberately placed the refusal *before* the upstream forward rather than
after it (the review's sample was ambiguous between "refuse with 400" and "pass
through like a non-200"). Rationale: a body the proxy cannot record is not a
capturable turn under any upstream outcome, so forwarding it would spend vendor
credit on a call whose capture is impossible, and the refusal becomes
deterministic rather than dependent on what the vendor answers. Module docstring
restated to spec the new refusal alongside the 200+JSON gate.

New test `test_a_malformed_request_body_consumes_no_ordinal` drives both hazard
paths the review enumerated (`b"not json"` and a valid-JSON non-object
`b'["a", "list"]'`), asserts a 400 for each, asserts nothing was forwarded
upstream, and asserts the next good capture still lands at `gemini-00`.

### WR-01: The D-08 Gemini model guard overclaimed its guarantee

**Files modified:** `examples/external/00-hello-context/replay_server.py`, `tests/examples/test_ext00_hardening.py`
**Commit:** `3f6fd77`
**Applied fix:** Took the review's option (b), per the verifier's authoritative
correction. I did **not** redesign the fingerprint mechanism: the verifier
established that the comparison is not vacuous (the actual side is the URL
`client_adk.py` genuinely emits, so a client leg ignoring the pinned label *is*
caught), so the defect is the `replay_server.py:170-174` docstring overclaim,
not the mechanism.

Both the module docstring and `fingerprint()`'s docstring now state the exact
guarantee and its exact limit: it catches a client leg that does not honour the
pinned model, and it cannot detect fixture-vs-model drift because neither side of
that field comes from the fixture. The limit is tied to D-11 (no re-capture this
phase) so a future re-capture has an obvious hook.

New test `test_the_gemini_fixture_label_matches_what_the_readme_documents` pins
`run.py`'s `GEMINI_FIXTURE_LABEL` against the literal `fixtures/README.md`
documents in its Normalize step — the mechanical tie the review found missing.

### WR-02: `fingerprint()` read process environment inside a pure reduction

**Files modified:** `examples/external/00-hello-context/replay_server.py`, `tests/examples/test_ext00_hardening.py`
**Commit:** `3f6fd77`
**Applied fix:** `fingerprint()` takes `expected_gemini_model` as an explicit
keyword argument and reads no environment; `build_app()` resolves the label once
(argument, else the `GEMINI_MODEL_ENV` seam, now a named module constant) and
closes over it.

I diverged from the review's `raise SystemExit` suggestion on one point. Failing
at `build_app` time would break the standalone startup the module docstring
advertises *and* the Anthropic replay leg, which does not use the label at all.
Instead the handler answers a loud `500` naming `CCF_EXT00_GEMINI_MODEL` when a
**Gemini** request arrives with the label unresolved. That achieves the finding's
actual goal — an unset variable is loud and named rather than silently
fingerprinting `""` against a real model — without collateral damage.

Three tests: the pinned model now arrives explicitly; `fingerprint` provably
ignores an ambient `CCF_EXT00_GEMINI_MODEL`; and an unset variable produces the
named 500 through the real handler. The pre-existing
`test_gemini_expected_fingerprint_reads_the_pinned_model_from_env` was rewritten
(it tested the env read this finding removes) — not deleted; its assertion
content survives with the seam changed.

### WR-05: `agent_directory` returned raw YAML where `tuple[ExposedAgent, ...]` is contracted

**Files modified:** `examples/external/00-hello-context/serve.py`, `examples/external/00-hello-context/artifacts/experience.yaml`, `tests/examples/test_ext00_hardening.py`

### WR-07: `_spawn` blocked on `readline()` with no timeout and leaked the stderr handle

**Files modified:** `examples/external/00-hello-context/run.py`
**Commit:** `7a7886f`
**Applied fix:** Both halves. (a) A `select.select([proc.stdout], [], [],
READY_TIMEOUT_SECONDS)` bounds the wait at a new 60s module constant; on timeout
the child is terminated and an `AssertionError` names the script and its stderr
path — a child that starts but never binds now fails the build with a diagnostic
instead of hanging it. (b) The stderr file is opened in a `with` (the child keeps
its own dup of the descriptor, so closing the parent's handle after `Popen` is
correct), and any failure between spawn and READY terminates the child via the
existing `_terminate` before re-raising. The `assert proc.stdout is not None`
became an explicit raise in the same pass.

I chose `select` over a watchdog thread: it needs no extra thread, no join, and
no shutdown coordination in a function that already owns the child's lifecycle.

## Notes for the human reviewer

Two fixes changed **semantics** rather than only structure, and both pass lint,
typecheck, the full suite and the example — but syntax-level verification cannot
confirm the intent is right, so they warrant a read:

- **CR-01** now returns `400` for a non-object request body *before* forwarding.
  If you would rather the proxy stay a faithful forwarder and only decline to
  record (pass the upstream answer through, consume no ordinal), that is a
  two-line change in the same block. The ordinal-conservation property D-09
  commits to holds either way.
- **WR-06** changes an observable behaviour of the example's front door:
  `get_replay_record` called by a client that has served nothing now refuses
  where it previously returned another client's record. `make example-ext-00`
  exercises this path (PASS 5) with a single client and is green.

Three fixes deviate slightly from the review's suggested code, each documented in
its section above with the reasoning: WR-02 (loud 500 at Gemini-request time
rather than `SystemExit` at build time, to preserve standalone startup and the
Anthropic leg), WR-04 (`product_resolver` stays required, with the reason stated
in the docstring), and WR-05 (seam removed and the hazard closed at the artifact
boundary rather than typing a closure the wire cannot reach).
