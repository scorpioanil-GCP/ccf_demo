## Decisions Made

- **`KycDeployment` deleted, not kept.** The plan named the Protocol; the class
  existed for no other reason than to satisfy it structurally, and leaving it
  would have left the same defect one level down (a shape with no consumer).
  `connection` and `read` were already stateless — neither read `self`.
- **The spine keeps the `load_and_boot` call; `run.py` reaches it by passing
  the manifest.** The plan's `key_links` names `run.py → ccf.deployment.load_and_boot`.
  That link is satisfied transitively. Moving the call literally into `run.py`
  would put a fabric call outside `spine.py`, contradicting the module's own
  first line and the D-11 separation `tests/examples/test_spine_separation.py`
  gates. Flagged here so the phase-close audit reads the link as transitive
  rather than as unmet.
- **No proper noun in the new purpose paragraph.** See *Deviations*.

## Deviations from Plan

### 1. [Rule 2 — Missing Critical] The purpose paragraph names the question's shape, not `Acme Corporation`

- **Found during:** Task 2.
- **Issue:** The plan's `<action>` quotes the question to state as *"Who
  ultimately owns Acme Corporation, and does any natural person's stake cross
  the KYC reporting threshold?"* — but the same task's acceptance criterion
  requires that "no threshold, percentage or **entity name** entered the
  docstring", and `spine.py`'s own second paragraph asserts the file contains
  "no entity class, no source system, **no identifier**, no threshold, no
  policy version, no query and no boundary". `Acme Corporation` is the value of
  `subject_entity_ref` in `artifacts/ubo-question.yaml`
  (`http://example.org/fibo/AcmeCorp`) — it is exactly a domain value the
  program consumes. Writing it into `spine.py` would have made the file's next
  paragraph false and put a subject identifier into the module that claims to
  hold none (CLAUDE.md §6.4).
- **Fix:** The paragraph states the question in the same words minus the proper
  noun — *"Who ultimately owns this company, and whose stake crosses the
  reporting threshold?"* — and says explicitly that which company, at which
  instant, under which threshold, and which class counts as a natural person
  are none of the module's business. `run.py`'s docstring, which is the
  deployment-facing driver, keeps the concrete scenario it already had.
- **Files modified:** `examples/s1-01-hello-context-product/spine.py`
- **Verification:** `make lint` (the No-Hardcoding lint, `RULE_TREE_SCOPE`
  covers `examples`) exits 0; `tests/examples/test_spine_separation.py` passes.
- **Committed in:** `61b473b`

### 2. [Rule 1 — Bug] Stale `:meth:`KycDeployment.read`` cross-reference

- **Found during:** Task 1.
- **Issue:** `deployment.py`'s module docstring pointed at
  `:meth:`KycDeployment.read``, which the same commit deleted.
- **Fix:** Re-pointed to `:func:`read``. The module docstring's Protocol
