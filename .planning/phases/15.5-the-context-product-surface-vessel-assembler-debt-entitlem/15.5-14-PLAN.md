Three things about how the panel is briefed, each learned the hard way in this
project:

- **Hand it the findings already known and tell it not to re-derive them.** Its
  budget is better spent on what is *adjacent* to each known defect and on what
  each suggests about where the same defect class lives. Phase 15.4's close-time
  panel found a harness-neutrality lint hole that predated the phase entirely,
  purely because it was pointed at the neighbourhood of a fixed blocker rather
  than at the blocker.
- **Tell it what is ruled.** `D-IMPL-30`, `D-IMPL-31`, `D-IMPL-96`, `D-IMPL-97`
  and this phase's `D-IMPL-98`+ are Dave's decisions. A reviewer re-litigating
  a ruling is not a finding.
- **Point it at the phase's own risk shape.** The debt placement against replay
  determinism, the entitlement door's departure from the inert-when-unbound
  pattern, the N-way anchor choice, and the payload gate's effect on the micro
  band are the four places this phase is most likely to be wrong.

Then run the single-agent code review. It is **additive, never a substitute** —
the panel because independent models catch different blind spots, the
single-agent pass because it reads at a depth a panel prompt cannot carry.

Then **verify every finding against the tree before recording or acting on it,
and record the ones you reject as rejected.** Reviewers in this project have
produced confident, well-formatted, false findings: one was rejected outright in
Phase 15.1 for fabricated citations, and Phase 15.4 received a finding asserting
that two lint checkers had no tests when 41 test functions existed. An unverified
finding acted on is worse than no review.

Triage each verified finding as **blocking** — a violated invariant, a
whitepaper-fidelity defect, a missing deliverable element, an unsurfaced
decision — or **advisory**. Fix every blocking finding **inside this phase**. If
a blocking finding cannot be fixed without a decision Dave has not made, that is
a `D-IMPL` entry and a stop; the phase does not complete around it.
