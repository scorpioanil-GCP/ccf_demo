<objective>
Make a Context Product **callable** rather than configurable.

Purpose: `examples/s1-01` pins its subject, its temporal boundary and its `now`
as literals in artifacts — one company, one frozen instant, one answer. Chapter
1 names that as the thing CCF replaces: *"the difference between the verb
aggregate and the verb assemble."* The root cause is that
`ContextProductContract` has no surface for the question that provoked it, so
the subject and the instant have nowhere to live but a YAML file. The whitepaper
already commits the fix at §6.3 *Addressability*
(`docs/CCF_Whitepaper_1-2.md:1465`): *"every product a well-defined interface the
agent queries with intent, role, and freshness parameters."*

Output: the request surface, at the shape and scope Dave ruled on Q1, with the
whitepaper's own address pattern as its reference realization.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller → door | The request body is untrusted input crossing into the fabric; today the subject is a trusted YAML literal and there is no validation path at all |
| request → plan selection | Parameters reach `selection_params`, which conditions which projection plan runs |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15.5-31 | Tampering | the request body | mitigate | `refuse_request` validates against the class's declaration at the door, with `extra="forbid"` and a closed declared parameter set — validation at the boundary, never deferred (CLAUDE.md §11) |
| T-15.5-32 | Elevation of Privilege | a role asserted in the request | mitigate | Role is structurally absent from the request type, asserted by field enumeration; the door resolves it from the verified grant (plan `15.5-06`) |
| T-15.5-33 | Repudiation | which question a decision answered | mitigate | The request is content-hashable and two requests differing only in subject hash differently; plan `15.5-13` pins the issued queries through `QueryPinWriter` |
| T-15.5-34 | Tampering | a clock inside the engine | mitigate | The instant stays a caller-supplied request field; an AST assertion in plan `15.5-13`'s verification confirms `src/ccf/projection/` reads no clock |
| T-15.5-35 | Information Disclosure | an entity anchor naming a subject the caller may not see | mitigate | The anchor is validated for shape only; whether the caller may receive a product about that subject is the door's entitlement check plus Π conditioning, both upstream and already bound by plan `15.5-06` |
| T-15.5-SC | Tampering | npm/pip/cargo installs | accept | No package is installed — `15.5-RESEARCH.md` § Package Legitimacy Audit records that this phase adds no dependency |
</threat_model>
