## How to read this map

Every row names the *closest shipped thing in this tree* that the new work
should copy. This project has an unusually strong precedent culture: nearly
every mechanism this phase needs already exists somewhere and simply is not
wired here. **A plan that invents a second shape for something below is the
failure mode this document exists to prevent.**

Three conventions:

- `file:line` citations were read directly. Anything I could not verify is
  marked **[UNVERIFIED]** rather than stated.
- "Conditional" files depend on an open question (Q1/Q3/Q5/Q8 in RESEARCH.md
  § Open Questions). They are classified anyway so the planner can see the
  shape of each branch, but a plan must not choose the branch.
- Docstring excerpts are quoted because in this tree the docstring carries the
  *reasoning* the new module must restate for its own case. Copying the code
  without the reasoning produces a module that passes review and loses the
  argument the next time someone asks why.

## THE HARD CONSTRAINT — carry this into every plan that touches the vessel

`ReplayEnvironment.rehydrate_product` is a Protocol method
(`src/ccf/replay/engine.py:160-169`) that rebuilds the delivered product from
`(record, re-executed projection)`:

```python
# src/ccf/replay/engine.py:160-169 — VERIFIED
    def rehydrate_product(
        self, *, record: DecisionReplayRecord, projection: ProjectionOutput
    ) -> ContextProductContract:
        """Rebuild the delivered product from the record and the re-execution.

        The payload comes from the re-executed projection; the envelope
        (schema, TTL anchor, expiry) comes from the deployment's product class.
        The engine checks the result's content address against the record, so
        an envelope reconstructed wrongly is caught rather than accepted.
        """
```

and the engine hash-checks the result:

```python
# src/ccf/replay/engine.py:449-455 — VERIFIED
    reproduced_address = content_hash(product)
    if reproduced_address != path.product_content_address:
        raise ReplayDivergence(
            f"the rehydrated product hashes to {reproduced_address!r}; the "
            f"record names {path.product_content_address!r}"
        )
```

`ReplayDivergence` is **raised, not returned** (`engine.py:118`).

> **Therefore: any field added to `ContextProductContract`
> (`src/ccf/products/contract.py:160-181`) must be reconstructible at replay
> time from (a) the recorded replay record, (b) the deployment's
> `RegisteredProductClass`, or (c) the re-executed `ProjectionOutput`.**

`ProjectionOutput` carries exactly two fields — `plan_id` and `payload`
(`src/ccf/projection/plan.py:75-86`, VERIFIED). Debt is computed from
observations and a `now` the projection never sees, and is not class
governance. **Debt is none of (a), (b) or (c) today.**

Consequence the planner must not lose: **a plan proposing debt on the product
only is proposing a phase in which every replay of every product diverges.** If
debt lands on the product it must *also* land in the record and be readable
back by `rehydrate_product` — which changes a public Protocol and therefore
requires a `docs/surface-changes/` fragment. This is RESEARCH.md Q3, and it is
Dave's ruling, not a plan's.

`freshness_sla` (Q8) does **not** have this problem: it is reconstructible from
the product class, which is what makes option (a) of Q8 viable at all. Say so
where the two are discussed together, so they are not conflated.

### 1. Per-principal entitlement at the local egress door

**New file:** the product-entitlement artifact + resolver (placement is
Claude's discretion; `src/ccf/products/` and `runtime/ccf_runtime/authz/` are
both defensible — note that `PeeringTrustPolicy` lives in `src/`, and the door

**Analog:** `src/ccf/peering/trust_policy.py` — **the whole file, 231 lines.**
Read it end to end. It is 100% of criterion 5's shape on an easier boundary.

**The claim the module docstring makes structurally** (`:37-46`, VERIFIED):

```
**Verification is not configurable.** D-IMPL-16 rules that every inbound
Peering Context Product is verified, with no fast path for a high-trust peer.
That ruling is structural here rather than merely followed: **this contract
has no field that could turn signature verification off, and none that could
route a peer around it.** ``extra="forbid"`` closes the other direction — a
deployment cannot add one. What a trust tier can express is narrower or wider
*entitlement* ... and entitlement is checked after verification, never instead
of it. That claim is enforced by a field-enumeration test, not by this
paragraph; and it is the only claim of that strength this module makes.
```

Note the last clause. The module makes *one* claim at that strength and says
so. Copy that discipline: the new artifact should state exactly which of its
claims the enumeration test enforces and not overclaim the rest.

**The grant shape** (`src/ccf/peering/trust_policy.py:97-121`, VERIFIED):

```python

def test_no_field_on_the_contract_could_express_a_verification_skip() -> None:

    Enforced here rather than in a docstring, because a docstring cannot fail
    when a later contributor adds ``trusted_peer_fast_path``.

    names = set(PeeringTrustPolicy.model_fields) | set(PeerTrustGrant.model_fields)

        name
```

And the module docstring that explains *why the suite has this test at all*
(`tests/peering/test_trust_policy.py:1-15`, VERIFIED):

```

pass against a broken implementation:

* the **field-enumeration** test makes "this contract cannot express a
  verification skip" a claim the suite enforces rather than one the docstring
```

**Direction of the assertion differs, and that matters.** The trust-policy test
asserts an **absence** (no field may express a bypass). Criterion 2 needs a
**presence** assertion: each of the §6.3 elements is represented by a named
field on a named shipped type, and a missing one fails. Copy the *mechanism*
(`model_fields` enumeration against an explicit expected set, red when reality
drifts) and invert the predicate.

Two things the planner must carry into this test:

- **The element count is nine, not eight.** `D-IMPL-30` (RESOLVED,
  `docs/DECISIONS.md:49` per RESEARCH.md, [UNVERIFIED — I did not re-read
  DECISIONS.md]) rules nine including Assembly Mode. ROADMAP criterion 2 says
  eight. RESEARCH.md flags this as a one-line ruling for Dave. The test file is
  where the count becomes executable, so the count must be ruled before it is
  written.
- **It must enumerate across two types, not one** — the elements are split
  between `ContextProductContract` (`contract.py:173-181`) and
  `RegisteredProductClass` (`contract.py:126-137`), plus whatever Q8 rules for
  `freshness_sla`. The trust-policy test's `set(A.model_fields) |
  set(B.model_fields)` union is exactly that shape.

```python
class SkillArgumentSchema(CCFContract):

    JSON-Schema-shaped and MCP-``inputSchema``-compatible, pre-specified:
    ``properties`` maps argument names to typed specs, ``required`` is a

    required: tuple[str, ...]

    @model_validator(mode="after")
    def _required_names_exist(self) -> "SkillArgumentSchema":
        missing = [name for name in self.required if name not in self.properties]
        if missing:
            raise ValueError(...)
        return self
```

```python
# src/ccf/skills/catalog.py:242-257 — VERIFIED
    def to_input_schema(self) -> dict[str, Any]:
        """Render as an MCP-tool ``inputSchema``-shaped dict, losslessly.

        Pure and total: every declared value appears, nothing is authored,
        and ``additionalProperties`` is always emitted ``false`` — the closed
        world is part of the contract, not a renderer option.
        """
        return {
            "type": "object",
```

**Two caveats the map must carry, both re-verified at `dcb7c57`:**

1. **It declares; it does not validate.** I re-ran the grep. `argument_schema`
   appears in `src/`, `runtime/`, `tests/` and `docs/schemas/` only as
   declaration, rendering and construction — **no call site anywhere in the
   tree validates an actual argument mapping against a declared
   `SkillArgumentSchema`.** [VERIFIED by grep at `dcb7c57`.] Reusing the shape
   gives the declaration for free; **the validator is new code and must be
   budgeted.** Factor it once (see the `refuse_attestation` pattern below) so
   the product-payload check and any future skill-argument check cannot drift
   into two readings.
2. **It is one level deep, by ruling** (`catalog.py:194-203`, VERIFIED — *"Nested
   property specs beyond one level are out of v0 scope by ruling"*, and
   `:90-96`, *"nesting beyond one level is out of v0 scope by ruling"*). A
   payload with a list of owner objects is **not expressible**. Three branches,
   each with real cost: extend the shipped class (public-surface change +
   `make schemas` + a surface-changes fragment), add a nesting-capable sibling
   (two shapes in the tree), or flatten v0 payloads. **No existing ruling
   covers this.** It belongs in Q5.

Also relevant to the `[ASSUMED]` in RESEARCH.md A1: `SkillArgumentSchema`
declares a schema **as data**, which is the only machinery that can express a
per-class payload the SDK does not know at compile time. The `docs/schemas/`
export machinery generates schemas **from models**, which would require a
Pydantic model per product class — the subclassing `D-IMPL-97` rules out. Worth
one sentence of confirmation from Dave, per A1.

### 4. The gate pattern — how to add a fourth check without touching the canonical three

**Analog:** `src/ccf/products/gates.py` (VERIFIED throughout).

The shipped precedent is `GATE_SOURCE_ATTESTATION`, added in Phase 15.2 as an
*additive* gate. Its four properties are the template:

**(a) One shared comparison function, factored so two layers cannot drift**
(`gates.py:211-240`, VERIFIED):

```python
def refuse_attestation(
    *,
    attestation: SourceAttestation | None,
    product_class: RegisteredProductClass,
) -> AttestationRefusal | None:
    """The one D-09 accepted-modes comparison — shared by both layers.

    Called by :meth:`ccf.projection.engine.ProjectionEngine.check_source_attestation`
    (the caller-visible pre-execute check) and by :func:`run_gates` (the
    structural gate-path enforcement), so the two layers cannot drift into
    two readings of "accepted". Pure over its arguments: no I/O, no clock,
    no query.
    ...
    """
    if attestation is None:
        return None
```

**(b) Keyword-only, `None`-defaulted, so every existing call site is
byte-for-byte unchanged** (`gates.py:299-307`, VERIFIED):

```python
def run_gates(
    candidate: ContextProductContract,
    *,
    engine_resolved: frozenset[str],
    now: datetime,
    registry: ControlPlaneProtocol,
    product_class: RegisteredProductClass,
    source_attestation: SourceAttestation | None = None,   # <- the additive seam
) -> ServableProduct | GateRefusal:
```

**(c) Appended after the canonical three, leaving their order and refusal
precedence byte-untouched** (`gates.py:371-377`, VERIFIED):

```python
    attestation = refuse_attestation(
        attestation=source_attestation, product_class=product_class
    )
    if attestation is not None:
        return attestation

    return ServableProduct(candidate, _GATE_TOKEN)
```

`tests/products/test_gate_independence.py` exists to hold exactly that
property. A payload gate must not disturb it.

**(d) Refusal is a value, not an exception** — `GateRefusal` subclasses carry
**both sides of the comparison** so the caller never re-derives either
(`gates.py:180-208`, VERIFIED: `AttestationRefusal` carries
`failing_dimension`, `source_mode`, `accepted_modes`). A payload refusal should
carry the declared schema's expectation and what the payload actually
presented, in the same voice.

**The unforgeable-result shape** (`gates.py:271-296`, VERIFIED):

```python
_GATE_TOKEN = object()


class ServableProduct:
    """A product that passed all three gates — the only servable form.

    Not constructible outside this module: :meth:`__init__` requires the
    module-private gate token. Holding one of these *is* the evidence that the
    gates ran, which is why the delivery path takes this type and not a bare
    :class:`~ccf.products.contract.ContextProductContract`.
    """

    def __init__(self, product: ContextProductContract, token: object) -> None:
        if token is not _GATE_TOKEN:
            raise GateBypassError(
                "ServableProduct is constructed only by "
                "ccf.products.gates.run_gates; the three validation gates are "
                "the only construction path of a servable product "
                "(whitepaper §7.6, INV-CH7-52)"
            )
        self._product = product
```

Its twin is `DeliveryCapability` (`src/ccf/replay/serve.py:85-108`, VERIFIED),
with `_DELIVERY_TOKEN` and `CapabilityForgeryError`. **If criterion 1's "no
delivery path exists that drops debt" is to be structural rather than reviewed,
this is the mechanism**: make the thing that carries debt the only thing the
delivery seam accepts. The honest claim both docstrings make, and which any new
one must copy rather than exceed: *"no unforced path exists, and every forced
path fails at construction — never absolute prevention"* (DESIGN.md §9, quoted
at `gates.py:55-58`).

**Anti-pattern, stated explicitly:** the gates are pure over `(candidate,
engine_resolved, now, registry, product_class)` and **hold no principal**.
`run_gates` and `run_federated_gates` share `_refuse_empty_operators`
(`:498-514`) and `_refuse_ttl` (`:517-552`) *precisely so the two sequences
cannot drift*. Adding a principal to one and not the other reintroduces exactly
that drift. Entitlement belongs at the door. A `principal_id` parameter
appearing anywhere in `src/ccf/products/` or `src/ccf/projection/` is the
warning sign.

For criterion 8's "class registration refuses an SLA its components cannot

```python
def refuse_operator_set_divergence(
    *, declared: ProductClassDeclaration, plan: ProjectionPlan
) -> None:
    """Raise if the product class's claim and the plan's requirements disagree.

    ... Call it **between constructing the plan and calling**
    :meth:`~ccf.projection.engine.ProjectionEngine.execute` — after that, a
    product has already been assembled from a set the deployment's own claim
    contradicts.

    Order is not significant on either side: both are compared as sets ...

    Raises:
        ValueError: the two sets differ. **Refused, never repaired**: the binder
            does not choose which document is right, because only the
            deployment's author knows which of the two they meant. Silently
            preferring one would leave a deployment whose declared operator set
            depends on which document the SDK happened to trust ...
    """
    claimed = frozenset(declared.required_operator_keys)
    required = frozenset(plan.required_operators())
    if claimed == required:
        return
    raise ValueError(
        f"operator set divergence for plan {plan.plan_id!r}: the product class"
        f" claims {sorted(claimed)} and the plan requires {sorted(required)},"
        f" differing on {sorted(claimed ^ required)}; one of the two authored"
        " documents is wrong and only its author knows which (D-IMPL-86)"
    )
```

Copy the posture exactly: **refuse, name both sides and their symmetric
difference, do not pick a winner.**

### 7. Aggregate composition by set-union, property-tested

**Analog:** `src/ccf/peering/admission.py:354-387` (VERIFIED) — reusable
verbatim for criterion 8's lineage limb.

```python
def union_lineage(
    *, producer: ProductLineage, consumer: ProductLineage
) -> ProductLineage:
    """Extend ``consumer``'s lineage with ``producer``'s by set-union (D-14).

    * ``operators_invoked`` and ``policy_bundle_versions`` are unions ...
    * ``graph_snapshot_at`` is the **producer's**. It is not a set and cannot
      be unioned ...

    Because ``graph_snapshot_at`` is single-valued, the order-independence law
    is a law about the two *set* axes; the property suite states it that way
    rather than pretending an instant commutes.
    """
    return ProductLineage(
        operators_invoked=(
            producer.operators_invoked | consumer.operators_invoked
        ),
        policy_bundle_versions=(
            producer.policy_bundle_versions | consumer.policy_bundle_versions
        ),
        graph_snapshot_at=producer.graph_snapshot_at,
    )
```

**The asymmetry is load-bearing and it is where the analog stops.** This
function is a *producer/consumer pair* function. For an N-way composite of
sibling components, "whose `graph_snapshot_at`" is **undefined by the current
function**. `min(graph_snapshot_at)` — the most conservative anchor, by analogy
with the TTL floor `min(expires_at)` — is a **design choice, not a
derivation**. A plan that reaches for `union_lineage` on an N-way aggregate
must say which it is doing and why, not assume.

**The property-test analog:** `tests/properties/test_lineage_union.py` (VERIFIED
— hypothesis-based, four laws plus a strict-growth guard). Its docstring states
the design rule for the new suite:

```
Plus a strict-growth regression guard ... An implementation that *replaced*
one lineage with the other would satisfy neither survivor law, would fail
order-independence, and would fail strict growth — three of the four laws plus
the guard, which is what makes the failure unmistakable in the report rather
than a single ambiguous red line.

**Why the guard is here at all.** Laws 1 and 2 alone are satisfiable by an
implementation that unions and then *adds* something, and law 4 is satisfiable
by an implementation that returns a constant. Read together with strict growth
they are not. Properties are chosen to be jointly falsifying, not individually
reassuring.
```

*"Jointly falsifying, not individually reassuring"* is the bar for
`tests/products/test_aggregate_composition.py`. It also generates strategies
rather than drawing from the banking fixtures, *"because fixture values would
only narrow the space it is checked over."*

**The `LineageContinuityRefusal` companion** (`admission.py:340-352`, VERIFIED)
is worth copying as a concept: a refusal that is *unreachable while the
implementation is correct*, kept *"precisely for the day it does not."*
