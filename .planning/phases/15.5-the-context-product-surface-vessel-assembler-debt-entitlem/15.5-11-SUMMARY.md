## The split decision, with its stated trigger

**Not split into 11a/11b.** The objective's trigger was *"if 15.5-05 ruled Q3 as 'both placements', split this plan"* — and Q3 **was** ruled as both. The trigger fired and the decision was still not to split, for a reason the plan could not have known when it wrote the trigger: the record-side landing turned out to be **derived from the product** rather than threaded beside it. `build_replay_record` already receives the gated product, so dimension 5's `debt` is `product.debt` and nothing new crosses the builder's signature. The two landings are therefore one coherent edit with one blast radius, not two — and splitting would have produced an 11a whose record field had no producer and an 11b that had to revisit 11a's file anyway. The split condition was written to protect against two landing sites; there is one.

`DebtSignal`, `DebtFactors`, `ScorerPin` and `DebtAssessment` now live in a new leaf module `ccf.halflife.assessment`, re-exported in full from `ccf.halflife.debt` so no existing import or construction site moved.

## Deviations from Plan

### Auto-fixed issues

**1. [Rule 3 — Blocking] The vessel could not import the debt module**
- **Found during:** Task 1
- **Issue:** `ccf.products.contract` → `ccf.halflife.debt` → `ccf.controlplane.artifacts` → `ccf.products.contract` is a load-time cycle. The plan assumed `DebtAssessment` could simply be referenced from the vessel.
- **Fix:** New leaf module `src/ccf/halflife/assessment.py` holding the four shape types, with full re-export from `ccf.halflife.debt`. Nine names join the public surface; all nine are claimed in the fragment.
- **Commit:** `355fd27`

**2. [Rule 1 — Bug] A `float` factor was silently coerced**
- **Found during:** Task 1
- **Issue:** `CCFContract` is not strict-mode, so `DebtFactors(freshness=0.8)` coerced. Harmless while debt was discarded; once debt is inside a content address, a coerced float gives the address a platform-dependent provenance.
- **Fix:** `mode="before"` validators refusing `float` on every debt value, named as T-15.5-48 in the tests.
- **Commit:** `355fd27`

**3. [Rule 1 — Bug] `EscalationActionRecord` / `EscalationHandOff` reshaped without anyone asking**
- **Found during:** Task 3 (surface diff)
- **Issue:** `EscalationTrigger = ExplicitEscalation | DebtAssessment`, so the scorer pin changed the canonical bytes of both HITL types.
- **Fix:** Not a code change — four fragment sections recording it as consequential, with the migration ("re-record any content address taken over a debt-triggered escalation"). Left silent it would have been an unclaimed surface move.
- **Commit:** `0464b63`

It did not: no supersession link was built, and `test_no_salience_factor_or_scorer_exists` walks identifiers (not text) across `ccf/halflife/` so the *documented deferral* is allowed to name what was not built.
