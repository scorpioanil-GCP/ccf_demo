## Decisions Made

**1. Artifact-class placement: neither mapping.** The plan said to register the class in `src/ccf/controlplane/artifacts.py`, "choosing between `SDK_ARTIFACT_CLASSES` and `SDK_VERSIONED_ARTIFACT_CLASSES` on the same basis the existing classes are placed — and **do not widen the set the HTTP `/schema` route serves**." Those two instructions cannot both be satisfied, because `SDK_ARTIFACT_CLASSES` *is* the set that route serves and `SDK_VERSIONED_ARTIFACT_CLASSES` is closed to a contract that declares no `artifact_version` (`tests/deployment/test_class_lookup.py` asserts the mapping matches the contracts that actually declare one). The basis the existing classes are placed on resolves it: this artifact's nearest analog, `ccf.peering-trust-policy`, is in **neither** mapping because it is registered by adopter code against its real contract at the door, not named by a deployment manifest — and `ccf.scope-mapping` and `ccf.hitl-policy` sit there for the same reason. So does this one.

  **Consequence for `ccf schema export`:** none, and that is the point. The verb and the HTTP `GET /schema` route both enumerate `SDK_ARTIFACT_CLASSES`, which is unchanged at 12 entries; `git diff` against the phase base over `src/ccf/deployment/classes.py` and `runtime/ccf_runtime/http_api/routes/schema.py` is empty. The class still gets a committed schema, because `tools/dump_schemas.py::unaddressable_classes` **discovers** `ArtifactClass` instances in neither mapping rather than reading a list — the mechanism plan 15-17 put in exactly so a new class could not go un-emitted. The documented `SDK_VERSIONED_ARTIFACT_CLASSES` 404 gap is untouched. Registering this artifact travels `register_typed`; the D-05 bump check has nothing to verify on it.

**2. The version lane is spelled `policy_version`.** The plan specifies it by name and its acceptance criteria construct the contract with it. Mechanically it is safe — nothing in `/src` or `/runtime` reads a lane by attribute (`grep -rn "\.semver\b"` over both trees returns nothing), `register_typed` versions by content hash, and `register_versioned` reads `artifact_version`, which this class does not declare. It is nonetheless the **only** artifact contract in the tree that does not spell its lane `semver`, and this tree's own argument against second vocabularies ("there is no second vocabulary here to drift") applies. Flagged for the close-time panel rather than silently renamed, because the plan named the field.

**3. Roles on the grant, not on the perspective.** Perspective resolution at a door asks "which roles may this verified caller assert?" — the same lookup, the same subject, the same moment as the class check. `ccf.projection.plan.Perspective` and the projection engine are untouched: a door checks the grant and *then* constructs the perspective, and replay keeps feeding the recorded perspective rather than re-authenticating a principal who may no longer exist.
