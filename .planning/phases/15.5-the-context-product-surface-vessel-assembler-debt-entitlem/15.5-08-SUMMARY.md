# Phase 15.5 Plan 08: A Context Product Becomes Callable

A Context Product now has an interface a caller **queries** rather than a
configuration a deployment **fixes**. The subject a product is about and the
instant it is asked as of are typed arguments on a content-addressable
`ProductRequest`, validated against a per-class Control Plane artifact — and
**no recorded content address moved**, because D-IMPL-98 placed the surface
off the vessel.

## Task 1 — the ruling, read and recorded before anything was built

The plan's task 1 asked which of three branches was ruled, and required the
answer be recorded rather than inferred. **Branch (a) was ruled** —
`docs/DECISIONS.md` **D-IMPL-98**, RESOLVED, Dave, 2026-08-11:

> Every product class declares a **typed request contract as a Control Plane
> artifact**, in the `SkillArgumentSchema` shape. Subject and instant become
> arguments of that request rather than literals in an artifact.

So tasks 2 and 3 ran at full scope: a new artifact class, a new committed
schema, and the declaration authored on `ProductClassDeclaration`. Branch (b)
would have narrowed `request.py` to a parameter contract with no artifact and
no schema; branch (c) would have added a Phase 17 roadmap entry for a deferred
contract. **Neither applied, so neither was done** — in particular no ROADMAP
edit was made, and none was needed.

The fixed point every branch shared is stated in the module docstring and
asserted by test: **the caller supplying the instant is correct design; the
instant being a literal in a YAML file is the defect.** `ProjectionEngine.execute`
reads no clock deliberately, so replay feeds the *recorded* boundary through
the same code path and gets the same answer. Nothing in this plan put a clock
anywhere — `tests/products/test_request_contract.py` walks `request.py`'s AST
for `.now` / `.utcnow` / `.today` / `.time` / `.monotonic` attribute reads and
asserts the list is empty, and `grep -rn "datetime.now\|utcnow\|time.time"
src/ccf/projection/` still returns nothing.

## What Was Built

### The request, modelled on the whitepaper's address rather than on convenience

`ProductRequest` carries the four axes §6.3 **Addressability**
(`docs/CCF_Whitepaper_1-2.md:1465`) names — its worked pattern
`/context-products/credit-risk/counterparty/{counterparty-id}?intent=…&freshness=…`
"encodes exactly what the agent needs: which entity, for what decision, under
what temporal requirement":

| Axis | Field | Whitepaper phrase |
| --- | --- | --- |
| entity anchor | `subject` | *which entity* |
| intent | `intent` | *for what decision* |
| freshness expectation | `freshness` | *under what temporal requirement* |
| instant | `asked_at` | the *as of* the other three are read at |

Plus `schema_name` / `schema_version` (what is being asked, at which lane) and
`parameters` (the class-declared remainder, reaching plan selection through
D-IMPL-49's `selection_params` slot). **None of the seven has a default** —
asserted field by field, because a defaulted axis is a question nobody asked,
answered anyway.

**Two absences are structural, not documented.** There is no role field and no
tenant field: both are things the door *establishes* from a verified
entitlement grant (plan 15.5-06), never things a request *claims*. The absence
is enforced by field enumeration in the `tests/peering/test_trust_policy.py:213`
shape against eight forbidden markers (`role`, `principal`, `actor`, `tenant`,
`grant`, `entitle`, `permission`, `scope`), because a docstring cannot fail
when a later contributor adds `requested_role`. That is T-15.5-32 discharged.

### The contract, reusing the machinery the ruling said to reuse

`ProductRequestContract` is a `VersionedArtifact` carrying `schema_name`,
`schema_version` and `arguments: SkillArgumentSchema`.

**`arguments` is `SkillArgumentSchema` itself** — asserted by annotation
identity (`ProductRequestContract.model_fields["arguments"].annotation is
SkillArgumentSchema`), not claimed in a comment. No new alias was minted
either: `ProductPayloadSchema` already exists as one name for that type and a
second would be a third import path for one symbol. D-IMPL-103 was honoured on
both bounds — nothing was widened further, nothing was made self-referential,
and the `-Input`/`-Output` split 15.5-07 found is not reachable from anything
here (`openapi.json` regenerates byte-identically).

**The contract names the class and lane it serves**, which the payload schema
cannot: a `SkillArgumentSchema` is a shape and knows nothing about what
declared it, so a payload schema pinned onto the wrong product class is
undetectable. A request contract so pinned is refused at wiring time.

### One reading of "conforms", two verdicts that cannot be confused

`refuse_request(*, request, declared) -> ProductRequestViolation | None`
does **not** restate `refuse_payload`'s traversal. It calls it and translates
the verdict through a three-row table. This is a deliberate strengthening of
the plan's instruction ("factored exactly like `refuse_payload` ... so the
door's check and any registration-time capability check must not drift into two
readings of 'well-formed'"): delegation makes drift structurally impossible
rather than merely unlikely, and it means D-IMPL-103's one-level widening
reaches the request surface with no new traversal code at all — asserted by
tests that refuse at `nested.member` and at `listed[].element_member`.

The **verdict type** stays distinct for the reason `PayloadSchemaViolation` is
not a `GateRefusal`: a shared comparison must not become a shared verdict, or a
request refusal could travel out of the payload path by a later caller who
assumed the type meant it belonged there.

One reason has no payload analogue. `class-mismatch` is checked **first**,
before any parameter, because comparing a request's arguments against another
class's declaration produces a confident verdict about the wrong question —
the most misleading answer the function could give.

### Refused at wiring time, in the MAX_TTL voice

`refuse_request_contract_pin` raises `ProductClassRegistrationError` — the
shipped type, reused rather than a new one added — on four conditions: a
half-declared pin, a pin naming nothing registered, a pin naming an artifact
that is not a request contract, and **a pin naming a contract declared for
another class or another lane**. The fourth is the cross-check the payload pin
cannot make.

## The Two Rulings That Bounded The Work, And Where Each Bit

**D-IMPL-108 — the door-validation truth is DELIVERED BY 15.5-15.**

The plan declares the must-have truth *"The request surface is validated where
it crosses the door, not downstream"*. Dave ruled that unmeetable as scoped —
this plan's `files_modified` names no door file — and assigned it to a new
wave-5 plan `15.5-15`, which widens `ProductResolverProtocol` and
`ExperienceProductResolverProtocol` **exactly once**, carrying both the typed
request and the authorized `Perspective`, rather than reshaping the same 24
files twice.

**Recorded here as delivered by 15.5-15 — not met by this plan, and not
failed by it.** Verified rather than asserted: `git diff <base> -- runtime/`
is **empty**. Nothing under `runtime/` was opened.

What this plan did instead is design so that 15.5-15 can pass the contract
through a widened seam **without reshaping it**:

- `ProductRequest` is **self-describing** — it carries `schema_name` and
  `schema_version`, so the three-string seam `(tenant, product_class, version)`
  collapses into one typed value plus the tenant the door establishes, and the
  door can *cross-check* what it resolved rather than re-derive it.
- Tenant is deliberately **not** on the request, so the seam's tenant argument
  keeps its meaning as an established fact rather than acquiring a shadow claim.
- `refuse_request` is pure and takes `(request, declared)` only, so it can be
  called at the door with no plumbing beyond resolving the class's contract.
- `ProductRequestViolation` is a returned value, so the door decides the
  status code; nothing here presumes a transport.

**D-IMPL-98's measured cost, checked against what landed.** The ruling was
made against *"one new artifact class plus one new `docs/schemas/*.json` under
the bytes-equality drift gate"* and *"0 `ContextProductContract` call-site
repairs, because the request surface stays off the vessel"*. Both hold exactly:
`git status` after `make schemas` showed precisely one new schema
(`ccf.product-request-contract.json`) and one regenerated one
(`ccf.product-class.json`, for the added authored key), and
`ContextProductContract` is byte-untouched.

## Artifact Placement, Decided Deliberately And Recorded

`PRODUCT_REQUEST_CONTRACT` lives in `src/ccf/products/request.py` and joins
**neither** `SDK_ARTIFACT_CLASSES` nor `SDK_VERSIONED_ARTIFACT_CLASSES`. That
is the third bucket plan 15.5-03 discovered and occupied for
`ccf.product-entitlement-policy`, and the reasoning transfers exactly:

- `SDK_ARTIFACT_CLASSES` **is** the set the HTTP `GET /schema` route and the
  `ccf schema export` verb enumerate. Widening it here would be an unruled
  runtime surface change made incidentally — which the plan forbids.
- `SDK_VERSIONED_ARTIFACT_CLASSES` is closed to a contract declaring no
  `artifact_version`; `ProductRequestContract` declares `semver`, like every
  other third-bucket class.
- The schema still lands, because `tools/dump_schemas.py::unaddressable_classes`
  **discovers** `ArtifactClass` instances in neither mapping rather than
  reading a list — the mechanism plan 15-17 built so a new class could not go
  un-emitted.

**Consequence for `ccf schema export` and the HTTP route: none, and that is
the point.** The served set is byte-unchanged at 12 entries;
`git diff <base> -- src/ccf/deployment/ runtime/ openapi.json` is empty. A test
asserts the non-membership directly rather than leaving it to review. The
documented `SDK_VERSIONED_ARTIFACT_CLASSES` 404 gap is untouched. Registration
is adopter code: no manifest can name `ccf.product-request-contract`, and a
deployment's composition root registers it with `register_typed` against the
constant, exactly as it registers its entitlement policy.

## Deviations from Plan

Three. One is ruling-driven, one is hazard-driven, one is a strengthening.

**1. [Ruling — D-IMPL-108] The door is not touched, and the must-have truth is recorded as delivered elsewhere**
- **Found during:** Task 1 (reading the rulings before building)
- **Issue:** The plan's must-have *"The request surface is validated where it
  crosses the door, not downstream"* cannot be met by a plan whose
  `files_modified` names no door file.
- **Fix:** Built the contract, its committed schema and its refusal semantics;
  opened nothing under `runtime/`. Designed the request to be self-describing
  so 15.5-15 can widen the seam once without reshaping it. Recorded above as
  DELIVERED BY 15.5-15.
- **Files:** none under `runtime/` — verified by an empty `git diff`.
- **Commit:** n/a (an absence)

**2. [Hazard — parallel wave] The registration call site could not be taken**
- **Found during:** Task 3
- **Issue:** The plan says the declaration is *"resolved at
  `register_product_class`"*, which lives in `src/ccf/products/contract.py` —
  a file explicitly off-limits this wave, because concurrent plan 15.5-11 is
  putting `DebtAssessment` on `ContextProductContract` there under D-IMPL-100.
  Two agents editing it would collide.
- **Fix:** The refusal itself landed, complete and tested, as
  `refuse_request_contract_pin` in `request.py`, written with exactly the
  signature and voice `_refuse_payload_schema_pin` has so the one-line call
  site is a mechanical addition. The authored key landed on
  `ProductClassDeclaration` in `artifacts.py`, which is this plan's alone. What
  is deferred is the *call site* and the two mirror fields on
  `RegisteredProductClass` — see Deferred Issues.
- **Files:** `src/ccf/products/request.py`, `src/ccf/controlplane/artifacts.py`
- **Commit:** `ed7dc81`, `c3d3c94`

**3. [Strengthening] `refuse_request` delegates to `refuse_payload` rather than mirroring it**
- **Found during:** Task 2
- **Issue:** The plan says to write the comparison *"factored exactly like
  `refuse_payload`"*. Written literally that is a second traversal with the
  same rules — two readings of "conforms" that agree today.
- **Fix:** `refuse_request` calls `refuse_payload` and translates the verdict.
  There is now literally one traversal in the tree, so the two surfaces cannot
  diverge, and D-IMPL-103's widening reaches the request surface for free. The
  verdict types stay distinct so the sharing cannot be mistaken for
  interchangeability.
- **Files:** `src/ccf/products/request.py`
- **Commit:** `ed7dc81`

No authentication gate arose. No package was installed (T-15.5-SC did not
arise).
