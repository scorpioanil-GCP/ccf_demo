## 2. Codex — findings, verified

### P1 — the entitlement key's tenant is never compared to the policy's own
**Severity: BLOCKING. VERIFIED. FIXED IN-PHASE (`7453e87`).**

*Claim:* `ControlPlaneProductEntitlementSource.authorize` resolves a policy
under `ccf.product-entitlement-policy/<tenant>` and never checks
`resolved.tenant_id == tenant`.

*Verification against the tree:* accurate.
`runtime/ccf_runtime/authz/product_entitlement.py:272` builds the key from
`tenant`; `:291` checks only `isinstance(resolved, ProductEntitlementPolicy)`;
`:301-318` proceed straight to `grant_for` / `require_schema` / `require_role`.
The field exists and the comparison was possible —
`src/ccf/products/entitlement.py:186` declares `tenant_id: str`. Every call
site registers with the key and the field supplied **independently**
(`registry.register_typed(product_entitlement_key(tenant_id=X), policy, …)`,
7 sites), and nothing upstream binds them.

*Why it is blocking rather than advisory:* `ProductEntitlementPolicy`'s own
docstring (`entitlement.py:167-172`) claims tenant-scoping holds *"not by
convention, but because there is no shared object for it to leak through."*
That argument is about content addressing and is true of the **artifact**; it
was not true of the **lookup**. A docstring stating that something is enforced
where it is not is the exact defect class this phase exists to correct — the
`contract.py` claim that all four class-level §6.3 elements *"live"* on
`RegisteredProductClass`, where only `assembly_mode` did.

*Fix:* the comparison, in the wrong-artifact-type near-miss posture — audited
as a deny first (WR-04), then `TypeError`, because a misregistered policy is a
deployment fact and not a statement about this caller.
`test_a_policy_declaring_another_tenant_is_refused_under_this_tenants_key`
asserts the refusal, the audit trace, and the control (the identical policy
under its *own* tenant's key still serves).

### P2 — the AGNT-01 capability check is blind to attribute access
**Severity: ADVISORY as reported. VERIFIED. FIXED IN-PHASE (`c6693f4`).**
Reached independently by Cursor as C2, which raised it to BLOCKING.

*Verification:* accurate. `tests/agents/test_consumption_discipline.py:215-224`
built `named` from `ast.Name` nodes and import aliases only.
`MODULE_CCF_PREFIXES` admits *module* prefixes for `assembler.py`, so
`import ccf.projection.acquisition as acquisition` is permitted and
`acquisition.ContentAcquirer` after it is an `ast.Attribute` no `ast.Name`
scan sees.

*Triaged as blocking* on Cursor's reading rather than Codex's: plan `15.5-10`'s
own executor flagged this widening as *"the one change here that deserves a
reviewer's eye"*, and a widening is only as safe as the claim bounding it.

*Fix:* `ast.Attribute.attr` and the literal second argument of a `getattr`
call join the scan. The `getattr` leg is narrow on purpose — a module-wide
string-constant scan would fire on `FABRIC_CAPABILITY_NAMES`' own doc comment.
**No module in the tree trips the widened check**, verified before the change,
so this is a gate hardening and not a fix disguised as one.

## 7. Republication sweep — a surface the D-20 scanner does not cover

`tools/publish_scan.py` reads `site/` (and `public/` pre-build) only. The
committed JSON schemas under `docs/schemas/` embed Pydantic docstrings as
`description` fields, and `openapi.json` does the same, so whitepaper prose can
be republished into a committed artifact with no gate firing. This happened
during this phase and was found only as a side effect of fixing a docs page.

Scanned for this close using `publish_scan`'s own `pub01-whitepaper-shingle`
rule (`normalize` + `shingles_of` + `whitepaper_shingles`, N=10) against every
`description`, `title` and `$comment` string in all 26 `docs/schemas/*.json`
plus `openapi.json`:

```
scanned 27 files, 638 description strings
findings: 0
```

**Clean. The coverage gap is real and is residual R2.** A manual sweep is not a
gate; the next docstring that quotes the whitepaper into a schema will not be
caught by anything.

`docs/surface/v0.2-surface.json` was also checked and carries no docstrings —
names and shapes only — so it is not a republication surface.
