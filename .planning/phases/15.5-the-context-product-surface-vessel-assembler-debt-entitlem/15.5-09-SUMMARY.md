# Phase 15.5 Plan 09: Payload Conformity at Bind — and the Gate That Is Not There

A payload is now held to the schema its product class declared, at bind. The
canonical validation gates are exactly what they were: `src/ccf/products/gates.py`
does not appear in a single commit diff of this plan.

## The re-scope, recorded first because it replaced this plan's premise

`15.5-09-PLAN.md` was written on the premise of a **fourth payload gate**
appended to `run_gates` on the `GATE_SOURCE_ATTESTATION` template. **D-IMPL-102
removed that gate and kept the check.** Dave's ruling, verbatim:

> *"Q5 payload validation → Schema validity at registration + payload
> conformity at Bind (request time). Gate scripts remain structural only."*

| Limb | Where it landed |
| --- | --- |
| 1 — schema validity at **registration** | Plan `15.5-07`, already at this plan's base (`register_product_class` resolves and type-checks the pin) |
| 2 — payload conformity at **bind**, request time | **This plan** — `src/ccf/products/bind.py` |
| 3 — **no fourth gate** | Enforced by absence, and asserted structurally (below) |

What changed against the written plan, concretely:

- `src/ccf/products/gates.py` was in the plan's `files_modified`. **It is not
  modified.** `git show --stat` on all four commits names it zero times.
- The plan's serve-time performance argument went with the gate. There is no
  new work on the canonical sequence to benchmark, so the §A8 headroom (80 /
  230 / 507 ns) is again margin this phase **does not spend**. `make perf-micro`
  was still run, and the numbers are below, as evidence that the sequence did
  not move rather than as a budget drawn against.
- `tests/products/test_gate_independence.py` was in the plan's `files_modified`
  to hold a *gate-ordering precedence* case. With no gate there is no ordering
  to defend, and touching that file would also have raced plan `15.5-12`. The
  property that replaced it — *the gates module does not name the payload
  comparison at all* — lives in this plan's own test file instead.
- The `&&` ordering defect at `15.5-09-PLAN.md:197` was **not** edited here:
  the orchestrator had already fixed it on the main tree and directed that the
  plan file stay orchestrator-owned. Verification was nonetheless run in the
  **corrected order** — the three pytest suites first, `make perf-micro` last —
  which is the whole point of the fix.

## Where 15.5-08's request contract joins

`refuse_bound_payload` takes `(payload, product_class, registry)`. It takes
**no request and no door**, and that is the design decision, not an omission:

- **D-IMPL-98** (plan `15.5-08`, running in parallel at the time of writing)
  makes every product class declare a **typed request contract** as a Control
  Plane artifact. That contract is what a request binds *through*; it resolves
  a caller's arguments to a `RegisteredProductClass`.
- **D-IMPL-108** gave the widening of the three-string resolver seam
  (`runtime/ccf_runtime/mcp/egress.py:136`,
  `runtime/ccf_runtime/mcp/experience.py:215`) to the new plan `15.5-15`, which
  is what carries a typed request and an authorized `Perspective` to the doors.
- **The join is one call.** Once `15.5-08`'s bind has resolved a request to a
  class, and the payload for that bind exists, the bound path calls
  `refuse_bound_payload(payload=…, product_class=…, registry=…)` before the
  payload leaves it. Nothing in `15.5-08`'s or `15.5-15`'s surface has to be
  anticipated in this signature, and neither has to reopen it.

This plan therefore ships the **mechanism** of limb 2 with its call site
deliberately unwired, exactly as the re-scope directed. The unwired state is
recorded as a known seam below rather than presented as complete wiring.

## What Was Built

### `ccf.products.bind` (task 1, TDD)

| Callable | Contract |
| --- | --- |
| `resolve_declared_payload_schema(*, product_class, registry)` | Resolves the class's `(payload_schema_key, payload_schema_version)` pin by **exact** version. Returns `None` when the class declared none. Raises `ControlPlaneMissing` if the pin vanished, `TypeError` if it now holds a non-schema |
| `refuse_bound_payload(*, payload, product_class, registry)` | Delegates to `ccf.products.payload.refuse_payload`. Returns `None` for a conforming payload **and** for a class with no declared schema; otherwise the `PayloadSchemaViolation` carrying both sides |

Four properties, each carried over from the shipped mechanism it copies:

1. **One shared comparison.** `refuse_bound_payload` does not re-implement
   conformance — it calls `refuse_payload`, the same function
   `register_product_class`'s neighbourhood binds against, for the reason
   `refuse_attestation` is one function: *two layers that each implement a
   check drift, and a drifted admission check is an admission bypass on
   whichever layer is laxer.* Asserted by a parametrized test over six payloads
   that the bind returns **exactly** what the shared comparison returns.
2. **`None` means something positive.** A class that declared no schema is not
   a class whose payload was skipped — it is the honest
   `Mapping[str, Any]` gap D-IMPL-97 named, visible in the registration.
3. **A bad product is returned; a broken deployment is raised.** `gates.py`'s
   own asymmetry, applied to the second piece of pinned governance.
4. **No principal.** Entitlement is the door's (`15.5-06`). Asserted over AST
   identifiers rather than over prose, because `entitlement.py` legitimately
   uses the word in its docstrings and a naive grep would have been a test that
   passes for the wrong reason.

### The no-fourth-gate property, asserted rather than assumed

`tests/products/test_payload_bind.py::TestNoFourthGate` holds four assertions
that fail the moment limb 3 is eroded:

| Assertion | What it catches |
| --- | --- |
| `run_gates` has no parameter whose name contains `payload` or `schema` | The additive-seam shape a payload gate would need |
| `gates.py` source contains no `refuse_payload`, `PayloadSchemaViolation` or `ccf.products.payload` | The comparison reaching the canonical sequence by any route |
| `not issubclass(PayloadSchemaViolation, GateRefusal)` | A payload verdict acquiring the ability to travel as a gate verdict |
| `gates.py` source contains no `products.bind` | This module being imported into the sequence later |

The reasoning is recorded in the module docstring: the shipped gates are
**structural** — every verdict depends only on the product's own shape — while
a payload verdict depends on a schema a *deployment* declared. A payload gate
would have been the first configurable member of a set whose whole value is
that none of them is.

### The surface fragment (task 2)

**3. [Re-scope] The serve-path perf argument narrowed**
- No new gate means no serve-path cost to measure. `make perf-micro` was run
  anyway and the gate medians recorded, as evidence of *absence* of movement.

### Rule 1 — auto-fixed

**4. [Rule 1 - Bug] The no-principal assertion was passing on prose**
- **Found during:** task 1, first green run
- **Issue:** the test grepped the whole source file for `principal`, which the
  module's own docstring uses when saying entitlement belongs at the door — so
  the test failed for a reason that was not a defect, and a naive fix (deleting
  the sentence) would have made it pass for a reason that was not a property.
- **Fix:** the assertion now walks the AST and checks `ast.arg`, `ast.Name` and
  `ast.Attribute` identifiers. Prose may discuss a principal; no argument,
  name or attribute may be one.
- **Commit:** `5d4fd6f`
