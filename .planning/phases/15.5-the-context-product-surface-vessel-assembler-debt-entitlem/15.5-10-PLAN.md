Give the producer side the behavioural surface it does not have, as a Protocol
whose implementation is a declared agent.

Purpose: `D-IMPL-97` rules *"the assembler, which I agree should be a Protocol,
is what makes the ContextProduct a KYC_ContextProduct"* and *"agent becomes the
implementation protocol."* All six archetypes ship, but `ArchetypeComponent` is
**declarative** — `archetype_id`, `fabric_interaction_pattern`,
`replay_obligations`, `configuration_defaults` — so `_ContextAssemblyComponent`
declares the emission *pattern* and carries no assembly behaviour. The assembler
is a new behavioural surface, and the archetype is the seam it attaches to.

The fit is confirmation rather than convenience: axis 5, the half-life and debt
profile, is **already a required field on every agent definition**
(`halflife_debt_profile`, a pinned `ccf-artifact://` reference), so a product's
debt configuration already has a version-pinned home on the agent.

Output: the Protocol, its mechanism-only reference implementation, and axis 2's
emission side.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| assembler → the Context Graph | The assembler must never acquire a write handle; single-writer holds across this seam |
| enlisted agent output → the payload | Model-produced content must re-enter algorithmically, never as payload (§7.6.6) |
| policy regime → what may be consulted | Axis 4 is the constraint; an assembler that consults outside it is an entitlement bypass |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15.5-41 | Elevation of Privilege | assembler acquiring a graph write handle | mitigate | The outcome is a returned typed value carried into the graph by L2, following `Agent.emit_effect`'s shape; asserted by a source grep for writer names and by the single-writer test |
| T-15.5-42 | Tampering | enlisted-agent output entering the payload directly | mitigate | `AssemblyOutcome` has no payload route for enlisted output; content re-enters as `AcquiredContent` through `execute(recorded_acquisitions=…)`. Asserted by field enumeration, and by the `@algorithmic` lint |
| T-15.5-43 | Elevation of Privilege | consulting outside the policy regime | mitigate | `ConsultationRecord` records permitted and refused sets, and the axis-4 test asserts a narrower regime yields a non-empty refused set |
