# Phase 15.5 Plan 10: The Assembler Protocol Summary

The producer side of a Context Product is now a `@runtime_checkable` Protocol
whose implementation is a **declared agent**, with axis 2 grown the emission
side its own docstring reserved for it — and single-writer plus Algorithmic ⇄
Semantic Alternation both hold across the new surface by construction.

## What Was Built

**Task 1 — the Protocol and its reference implementation** (`64644d5`, RED at
`acdceac`). `ContextAssemblerProtocol` carries `assembler_id`,
`assembler_version` and a keyword-only `assemble(*, request, perspective,
tenant_id) -> AssemblyOutcome`. `ConsultationRecord` records what an assembly
was permitted and refused, as opaque identifiers the SDK never interprets, held
sorted/unique/disjoint so the record participates in content identity
deterministically. `AssemblyOutcome` carries the payload, the consultations,
the acquisitions, the assembler pin, the skill-set in force and the pinned
axis-5 ref. `DeterministicAssembler` is the mechanism-only reference: consults
nothing, returns Π's payload unchanged, reads the governed part off the
declared agent at assembly time.

**Task 2 — axis 2's emission side** (`812cdf7`, RED at `7383574`).
`ContextContract` gained `emits`, defaulting to the named `EMITS_NOTHING`
claim, on the seam its own earlier docstring reserved — not a parallel
artifact. `AgentFactory` gained two refusals (emitter without the
`context_assembly` archetype; emission to an unregistered class or lane) and an
injected `product_classes` mapping whose `None` is fail-closed rather than a
silent skip. `_ContextAssemblyComponent` is unchanged apart from a docstring
correction; its two replay obligations are asserted against an explicit
expected tuple.

**Task 3 — the axes proven to bind** (`44a450a`). 22 tests covering the six
claims, every agent built through the Agent Factory from fixture artifacts.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] The AGNT-01 import invariant refused the new L5 value imports**
- **Found during:** Task 1
- **Issue:** `tests/agents/test_consumption_discipline.py` enforces "no path
  from `Agent` to L1–L5" by an import allowlist over the whole `ccf.agents`
  package. `assembler.py` must name `Perspective`, `ProjectionOutput` and
  `AcquiredContent` — the plan requires all three — so the invariant fired.
- **Fix:** Argued the widening in, as that file's own rule demands ("must be
  argued into the allowlist, in review — never slipped in"), and **bounded it
  two ways** rather than merely widening: (a) a new `MODULE_CCF_PREFIXES`
  admits the three prefixes for `assembler.py` *alone*, so they do not become
  admissible for `agent.py`; (b) a new fourth claim asserts that no module in
  the package names any of `FABRIC_CAPABILITY_NAMES` (`ContentAcquirer`,
  `ContentAcquiringPlan`, `ProjectionPlan`, `ProjectionEngine`, `GraphView`,
  `OperatorOutput`). Admitting the module that *holds* a capability does not
  admit reaching for it, and a capability arriving through one of these doors
  is now a red build.
- **Files modified:** `tests/agents/test_consumption_discipline.py`
- **Commit:** `64644d5`

**2. [Rule 1 - Bug] A real import cycle: products.request → skills.catalog → agents.definitions**
- **Found during:** Task 2 (`tools/dump_schemas.py`, which enters the graph
  from a different module than pytest does)
- **Issue:** `assembler.py`'s module-level `from ccf.products.request import
  ProductRequest` closed a cycle — `ccf.products.request` imports
  `ccf.skills.catalog`, which imports `ccf.agents.definitions`, which
  initializes `ccf.agents`, which imports `assembler.py`. The test suite passed
  because it happened to reach the modules in a working order; the schema
  dumper did not. Exactly the "import graph whose success depends on which
  module a caller reached first" non-determinism D-IMPL-37 rejects.
- **Fix:** Deferred the import under `TYPE_CHECKING`, the pattern
  `ccf.agents.agent` already uses for `ccf.skills.dispatch` and for the same
  stated reason. `ProductRequest` appears only in annotations, which
  `from __future__ import annotations` leaves unevaluated. Verified
  order-independent by importing the graph from both ends.
- **Files modified:** `src/ccf/agents/assembler.py`
- **Commit:** `812cdf7`

**3. [Rule 3 - Blocking] Three committed artifacts drifted and were regenerated**
- **Found during:** Task 2 and Task 3
- **Issue:** `canonical_bytes` walks **every** declared field of a contract, so
  a defaulted `emits` on `ContextContract` moves the content hash of every
  agent definition — which moved two content addresses in the
  `examples/08-e2e-demo` transcript. Separately, the axis-2 widening reaches

- **Fix:** Regenerated all three. The transcript's own test warns that a

  the run was reproduced and diffed: **exactly two lines change**, both content
  addresses deriving from `content_hash(AgentDefinition)`, and every count,
  entity total, detection outcome and label is byte-identical.
- **Files modified:** `examples/08-e2e-demo/artifacts/expected_output.txt`,
  `docs/schemas/ccf.agent-definition.json`, `openapi.json`
- **Commits:** `812cdf7`, `44a450a`

### Deliberate Departures

**`AssemblyRefused` lives in `src/ccf/agents/errors.py`, not in `assembler.py`.**
The plan's `files_modified` did not list `errors.py`. That file holds the whole
agent-failure taxonomy with a stated rationale, and a stray error class beside
the Protocol would be the drift. It is documented in the surface-change
fragment as the sibling of `ConsumptionRefused` on the other face of the fabric.

**The axis-5 test asserts the pin *resolves*, not that it yields a `DebtProfile`
instance.** The plan's task-3 wording asked for the latter. The shipped banking
fixture registers its profile under the deployment's own declared class
(`debt-profile`) rather than the SDK's `ccf.debt-profile`, and its declaration
carries a `review_cycle` field that `DebtProfile` (`extra=forbid`) would refuse.
Asserting the instance claim would have required editing the fixture to make
the test true, which is the wrong direction. The test asserts what is actually
guaranteed — the ref is pinned (never `@latest`), the factory resolves it at
construction and refuses a definition whose pin resolves to nothing, and the
assembler reports the exact ref — and says so in its own docstring.

## The Consequence Worth Reading Twice

**Every agent definition's content hash moves with this change**, including
definitions nobody edits, because `canonical_bytes` serializes the defaulted
`emits`. What moves with it: `AgentIdentity.definition_hash`, the
`agent_definition_hash` on grants and on replay dimension 4, and every recorded
artifact that pinned one. This is D-IMPL-28's two-lane versioning doing exactly
what it is for — a `schema_version` lane widening — and it is unavoidable given
that D-IMPL-97 puts the emission binding on the agent definition. It is
documented in full under the `ContextContract` `Migration` field, with the
shipped worked case named.
