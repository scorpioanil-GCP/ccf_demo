<objective>
Close the live authorization gap: bind per-product-class entitlement and derive
Perspective from the verified grant at every exposed door.

Purpose: `Perspective(principal_id, role)` is passed *into* `execute()` by the
caller with nothing deriving it from a verified grant, and `build_egress_server`
binds no authorizer at all. Π conditioning and the policy operators both key off
perspective, so on an exposed surface the entire content-shaping layer sits
downstream of an unverified claim (`CONTEXT_PRODUCT_REVISION.md` §11.2). The
HTTP product route has the same shape. This is the phase's sharpest security
item and it is ungated by every open question — the artifact it reads is plan
`15.5-03`'s and the mechanism is the one `peering/trust_policy.py` already
proves.

Output: entitlement and perspective resolution bound at the MCP egress door and
the HTTP product route, with `ProjectionEngine.execute` byte-unchanged.
</objective>

  <action>
Add two seams to `build_egress_server`, keyword-only, and make them
**required**, not optional-and-inert.

This is the one place this plan deliberately departs from the shipped HITL
pattern, and the module docstring must say why: `hitl.py:115` is *"inert when
no authorizer is bound"* because it retrofits authorization onto a door that
already shipped. This door is being given its first authorization, so an
optional seam would ship the exact gap `CONTEXT_PRODUCT_REVISION.md` §11.2
measured — a door that answers everyone — and would make the deny-by-default
posture a deployment's choice rather than the SDK's. `build_egress_server`
raises on an absent entitlement source, in the voice
`ProductClassRegistrationError` uses at `src/ccf/products/contract.py:74-79`: a
door whose governance configuration is absent must not become servable.

Seam one: a `PerspectiveResolverProtocol` — `@runtime_checkable`, keyword-only
`__call__(*, grant: TokenGrant, tenant: str, requested_role: str | None) ->
Perspective`, copying `ProductResolverProtocol`'s own reasoning at `:95-115`
(*"the SDK has no business owning its shape — only its signature"*) and its
keyword-only discipline (*"so a three-string signature cannot be called with
the tenant and the class transposed"*).

Seam two: the entitlement source — a callable resolving the tenant's
`ProductEntitlementPolicy` from the Control Plane by
`product_entitlement_key(tenant_id=…)`, **re-resolved per call with no cache
and no TTL**, so the exact version in force lands on the audit record (D-07,
the shipped `ControlPlaneTenantAuthorizer` posture).

Order inside the handler, and the order is the security property: authenticate
→ resolve the policy → `grant_for(principal_id=…)` → `require_schema(…)` →
`require_role(…)` → construct `Perspective` → call the resolver. Entitlement is
checked **after** verification, never instead of it
(`trust_policy.py:37-46`). Audit both outcomes before returning either.

Three things the module must not lose, all asserted by the existing source-grep
test in `tests/crossproc/test_mcp_egress.py`: it still imports nothing from the
L3 graph package, holds no graph handle, and holds no principal name, role
name, tenant or product-class literal (CINV-01, `egress.py:40-42`). Read that
test before editing and extend it rather than working around it.

Extend `tests/crossproc/test_mcp_egress.py` with the behaviour cases above,
each watched to fail.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| untrusted caller → MCP egress door | Bearer-token-authenticated but previously unauthorized for product class or role |
| untrusted caller → HTTP product route | Same shape, same absence |
| door → projection engine | A resolved `Perspective` crosses; a principal must not |
| replay engine → recorded perspective | Replay must not re-authenticate a principal who may no longer exist |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15.5-19 | Spoofing | caller-asserted `Perspective.role` | mitigate | `PerspectiveResolverProtocol` derives the role from the verified `TokenGrant` via `ProductEntitlementGrant.require_role`; the caller may request, the resolver decides |
| T-15.5-20 | Information Disclosure | `context_product` resource, `GET /product/...` | mitigate | `require_schema` on the per-principal grant, checked after authentication; server-wide scopes are no longer the only gate |
| T-15.5-21 | Elevation of Privilege | an inert-when-unbound authorizer | mitigate | `build_egress_server` **raises** on an absent entitlement source rather than building an inert door; the departure from `hitl.py`'s optional posture is stated in the module docstring with its reason |
| T-15.5-22 | Elevation of Privilege | entitlement sinking below the door | mitigate | AST assertion that no `principal_id` parameter exists in `src/ccf/products/` or `src/ccf/projection/`, plus a signature assertion on `ProjectionEngine.execute` |
| T-15.5-23 | Repudiation | unaudited allow/deny | mitigate | Both outcomes append one `authz_decision` event to the one Control Plane audit log, following the shipped `ControlPlaneTenantAuthorizer` (D-09/D-10), including the near-miss-as-deny posture |
| T-15.5-24 | Tampering | stale entitlement policy | mitigate | Per-call re-resolution with no cache and no TTL (D-07), so the exact version in force lands on the audit record |
| T-15.5-25 | Denial of Service | replay of a deleted principal | mitigate | Replay feeds the recorded perspective and reaches no resolver; asserted by the invariant test |
| T-15.5-SC | Tampering | npm/pip/cargo installs | accept | No package is installed — `15.5-RESEARCH.md` § Package Legitimacy Audit records that this phase adds no dependency |
