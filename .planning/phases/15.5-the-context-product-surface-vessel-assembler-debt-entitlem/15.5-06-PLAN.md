<objective>
Close the live authorization gap: bind authentication, per-product-class
entitlement, and grant-derived Perspective at **every** exposed door.

Purpose: `Perspective(principal_id, role)` is passed *into* `execute()` by the
caller with nothing deriving it from a verified grant, and `build_egress_server`
binds no authorizer at all — and, as verified at `egress.py:127-129` and `:150`,
**no authentication either**: its `FastMCP` constructor receives neither
`token_verifier` nor `auth`. Π conditioning and the policy operators both key off
perspective, so on an exposed surface the entire content-shaping layer sits
downstream of an unverified claim (`CONTEXT_PRODUCT_REVISION.md` §11.2).

**Three doors, not one.** The tree exposes the same principal-free three-string
product signature in three places, and criterion 4 says *every* exposed door:

1. `runtime/ccf_runtime/mcp/egress.py:152-163` — the fabric-internal MCP egress
   resource. Unauthenticated today.
2. `runtime/ccf_runtime/http_api/routes/product.py:31-42` — the HTTP `retrieve`
   route.
3. `runtime/ccf_runtime/mcp/experience.py:551-570` — the **external front door**
   for third-party agent runtimes. It is already authenticated
   (`token_verifier` and `auth_settings` are required and reach the `FastMCP`
   constructor at `:543-549`) but its `context_product` resource is entitlement-
   free and perspective-free exactly like the other two.

This phase's founding complaint is *"an MCP server in front of a database."*
Shipping the SDK's own external front door ungated would be that complaint,
self-inflicted. The front door is therefore in scope, and it is the cheapest of
the three because its authentication seam already exists.

This is the phase's sharpest security item and it is ungated by every open
question — the artifact it reads is plan `15.5-03`'s and the mechanism is the one
`peering/trust_policy.py` already proves.

Output: authentication (where absent), entitlement and perspective resolution
bound at all three doors, with `ProjectionEngine.execute` byte-unchanged.

**Note on shape:** this plan carries four tasks rather than the usual two or
three. That is a deliberate consequence of covering the third door rather than
narrowing the criterion; the alternative was a fifteenth plan, which would move
the wave structure for one small task. Task 3 is genuinely small — it imports
task 1's seams and wires them into one resource handler.
</objective>

  <action>
Add **three** seams to `build_egress_server`, all keyword-only and all
**required**, not optional-and-inert.

**Seam zero, and it comes first because without it the other two are
decoration: authentication.** `build_egress_server` today constructs
`FastMCP(server_name, stateless_http=True, json_response=True)` at `:150` with
neither `token_verifier` nor `auth`. There is no bearer-token verification on
this door at all, and because `FastMCP` installs its authentication middleware
only at construction, it cannot be retrofitted onto the returned object by a
deployment. An entitlement check downstream of no authentication asks "may this
principal receive this class?" about a principal nobody verified.

Add `token_verifier: TokenVerifier` and `auth_settings: AuthSettings` as
required keyword-only parameters with no defaults, and pass both into the
`FastMCP` constructor, copying `experience.py:543-549` exactly. Copy its
docstring reasoning too, in this module's own words: both are required, and
required *together*, because `FastMCP` installs its authentication middleware
only when both are present (D-26, the artifact-server precedent). The reference
verifier is `ccf_runtime.mcp.auth.SourceBackedTokenVerifier`; the module names
it as the reference and holds no default instance, because a library that chose
a token source would be choosing an identity provider.

Seam one: a `PerspectiveResolverProtocol` — `@runtime_checkable`, keyword-only
`__call__(*, grant: TokenGrant, tenant: str, requested_role: str | None) ->
Perspective`, copying `ProductResolverProtocol`'s own reasoning at `:95-115`
(*"the SDK has no business owning its shape — only its signature"*) and its
keyword-only discipline (*"so a three-string signature cannot be called with
the tenant and the class transposed"*). This Protocol is exported and is the
one definition the other two doors import in tasks 2 and 3.

Seam two: the entitlement source — a callable resolving the tenant's
`ProductEntitlementPolicy` from the Control Plane by
`product_entitlement_key(tenant_id=…)`, **re-resolved per call with no cache
and no TTL**, so the exact version in force lands on the audit record (D-07,
the shipped `ControlPlaneTenantAuthorizer` posture).

This is the one place this plan deliberately departs from the shipped HITL
pattern, and the module docstring must say why: `hitl.py:115` is *"inert when
no authorizer is bound"* because it retrofits authorization onto a door that
already shipped. This door is being given its first authentication *and* its
first authorization, so an optional seam would ship the exact gap
`CONTEXT_PRODUCT_REVISION.md` §11.2 measured — a door that answers everyone —
and would make the deny-by-default posture a deployment's choice rather than
the SDK's. `build_egress_server` raises on an absent entitlement source, in the
voice `ProductClassRegistrationError` uses at
`src/ccf/products/contract.py:74-79`: a door whose governance configuration is
absent must not become servable.

Order inside the handler, and the order is the security property: authenticate
→ resolve the policy → `grant_for(principal_id=…)` → `require_schema(…)` →
`require_role(…)` → construct `Perspective` → call the resolver. Entitlement is
checked **after** verification, never instead of it
(`trust_policy.py:37-46`). Audit both outcomes before returning either.

Three things the module must not lose, all asserted by the existing source-grep
test in `tests/crossproc/test_mcp_egress.py`: it still imports nothing from the
L3 graph package, holds no graph handle, and holds no principal name, role
name, tenant or product-class literal (CINV-01, `egress.py:40-42`). Read that
test before editing and extend it rather than working around it.

Extend `tests/crossproc/test_mcp_egress.py` with the behaviour cases above,
each watched to fail. One of them is not like the others and must be written
as a real request rather than as a source inspection: **an unauthenticated call
must be shown never to reach the entitlement check** — bind an entitlement
source that records every invocation, issue a call with no bearer token, and
assert the recorder saw nothing. A test that only asserts the call order in
source would pass against a server whose middleware was never installed, which
is precisely the defect this task fixes.
