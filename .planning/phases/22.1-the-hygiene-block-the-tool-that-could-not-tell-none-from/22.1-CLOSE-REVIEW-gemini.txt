### 2. Vacuous Pass Potential in New Tests
*   **`test_the_examination_record_is_not_vacuous`:** This test (Line 924 of the test file) asserts `unexaminable() != ()`. It can pass vacuously if any unrelated part of the setup or a previous test leaked a record into the global `_UNEXAMINABLE` list. ### 3. K3 Exemption Polarity Trace
The argument in `_comment_lines` (Line 534) is **correct**.
1.  **The Fallback:** If `tokenize` fails, the fallback only catches lines starting with `#`. It misses trailing comments (e.g., `x = 1 # {WAVE_8}/run.py`).
2.  **The Polarity:** In `classify` (Line 565 full text), a line is `DOCUMENTARY` if it is in the `comments` set. 
3.  **The Result:** If a line with a trailing comment is missed by the fallback, `classify` falls through to the final return: `return default_shape, LIVE`.
4.  **The Safety:** Marking a line as `LIVE` creates a coupling. A coupling prevents deletion. For a retirement tool, over-reporting "live" status is the safe failure mode, as it prevents the accidental deletion of code that might still be in use.

### 4. Safety of Module-Level Mutable Collector
The `_UNEXAMINABLE` collector is **brittle for unit testing** but safe for `main()`.
*   **The Risk:** `sweep()` (Line 1433) correctly calls `reset_unexaminable()`, ensuring `main()` starts clean. However, `count_coupling_rows()` (Line 1022) **does not** reset the collector. 
*   **The Consequence:** If a developer writes a new test that calls `count_coupling_rows` directly without manually calling `reset_unexaminable()`, the test will be polluted by any recordings from previous tests in the same process. 
*   **Deduplication:** The deduplication in `unexaminable()` (Line 484) hides the *count* of leaks but doesn't prevent unrelated subjects from persisting across test boundaries.

### 5. Brittle and Incomplete Assertions
*   **Literal Formatting in `test_control_28c`:** This test (Line 5243) relies on the literal string `"- [ ] **"`. If the project changes the ledger format (e.g., removing the space or the bolding), the `.replace()` will fail silently, but the `assert "- [ ] **" not in all_ticked` might still pass, leading to a vacuous test of the refusal limb.
*   **Weak Control in `test_control_a_clean_sweep_still_exits_zero_and_writes`:** This test (Line 1102) mocks `sweep` to return an object with an empty `unexaminable` tuple. It proves `main` reacts to the `Sweep` object, but it **does not verify** that `sweep()` actually populates that tuple from the global `unexaminable()` collector. If the link between the global list and the `Sweep` return value were broken, this test would remain green while the tool failed to report errors in production.
*   **Index Error Risk in `_an_unticked_id`:** The logic `return unticked[0] if unticked else ""` (Line 2244) returns an empty string if the refusal is neutered.
