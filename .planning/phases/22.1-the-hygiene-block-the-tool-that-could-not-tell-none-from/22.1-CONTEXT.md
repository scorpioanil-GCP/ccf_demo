## The subject: what is actually wrong with the sweep tool

`tools/retirement_sweep.py` decides which files are safe to delete. It swallows
failure at three sites — `:789` (a module that will not import yields no rows),
`:982` (a floor scan that will not run yields no row), `:1124` (a sabotage run
that cannot be measured is not a witness) — each returning `None` or
`continue`. A module that fails to import therefore contributes zero rows and
the tool prints a confident total **at exit 0**. It cannot distinguish *"there
is no coupling"* from *"I could not look."*

This is not hypothetical. It was reproduced during the Phase 22 discuss sitting:
under the system `python3` rather than `.venv/bin/python`, three modules fail to
import, **six coupling rows vanish silently**, the tool reports `238` and exits
0, and the staleness gate then reports the CORRECT committed report as stale.
It was recorded there and ruled out of scope for Phase 22.

Two narrower sites — `:447` (unreadable bytes) and `:484` (untokenizable
source) — are to be **examined and either fixed or exempted with the reason
stated**, rather than left unmentioned.
