## Both questions RULED — `D-IMPL-288`

### `F-12` — the shape stands; only the timing moves.

> *"`F-12` is an SDK validation-timing defect, not an SDK schema defect. The Control Plane must
> reject an invalid `request_contract` at boot with a governed, field-specific refusal rather than
> allowing it to fail later with a bare `ValueError`. The canonical
> `unsupported_arguments: mapping[name, reason]` shape remains unchanged."*

Dave's reason: the mapping *"has architectural value: the refusal can explain **why** each argument
is unsupported. Accepting a bare list just to preserve cp-05 unchanged would be exactly the
example-driven SDK distortion we have been trying to eliminate."*

**cp-05's list is an objectively invalid declaration and may be corrected — after the SDK proves it
so.** *"We are not 'repairing the example around the SDK'; we are correcting an invalid declaration
after the SDK proves it invalid."* This sits inside `D-IMPL-261`'s existing carve-out for examples
that are objectively wrong.

**Measured scope of the correction — two edits, and the second deletes a workaround.**
`ccf_config.yaml:175` declares `unsupported_arguments:` as a one-element list (`- as_of`).
`deployment.py:272-274` then builds the mapping in code as
`{name: "not supported at this tier" for name in ...}` — so **cp-05's refusal reasons are constant
filler**, which is exactly the information the mapping shape exists to carry. Correcting the YAML
without also making that comprehension a pass-through would silently discard the reason just
authored. No test pins cp-05 digests or transcripts (measured); republication, if any, is
post-phase (`D-IMPL-261`).

### `F-11` — selection within a declared envelope, never override.

> *"Control Plane declares the envelope → request selects within the envelope → resolver records
> the effective value and authority → operator receives that value."*

**Not** *"declaration says X → deployment substitutes Y."* **And definitely not** *"empty
declaration → caller may supply anything."* The explicit rule:

> *"A request-derived operator parameter is legal only when the product declaration explicitly
> permits request-time conditioning for that parameter and the effective request value satisfies
> the declared domain/policy constraints. Undeclared or out-of-domain substitution is refused."*

Consistent with the established authority model: **policy boundary > caller value > product
default.**

**Empty means empty.** *"`permitted_classifications: []` cannot silently mean 'dynamically
unrestricted.'"* And: *"**Do not preserve the empty-list idiom by making it magical.**"*

**Where the gap actually is:** *"If the SDK currently has no declarative way to express that
binding, then that is the actual `F-11` SDK gap and 24.11 should add the minimum governed binding
mechanism."*

**THE QUESTION TO ASK AT STEP 4 — Dave's sequencing instruction.** Do not ask *"how do we make
cp-05's empty list work?"* Ask:

> ***"How does the canonical SDK declare and enforce a request-conditioned operator parameter?"***

**Consequence to carry, not resolve here:** whether cp-05's `permitted_classifications: []` is
*itself* an objectively invalid declaration under this ruling, or merely an idiom the SDK will not
honor, is a separate question (`D-IMPL-288`, "what this does not decide"). It decides whether cp-05
needs a second ruled correction, and it may decide whether cp-05 can reach the exit criterion at
all. Raise it when step 4's design is concrete — do not pre-empt it.

## Sequence (`D-IMPL-287` (6)) — small, and in this order

1. **`F-07` — correctness, P0.** Seed Π from the request on the canonical path, so execution and
   replay agree about the subject. **SDK-level regression test, not cp-05:** two different subjects
   must produce subject-conditioned execution and must not alias merely because the resolver
   dropped the seed. One direct test.
2. **`F-06` — composition.** Propagate `similarity_index_version` to `build_operator_registry`
   (`D-IMPL-38`). One direct test: a class whose operator set includes Similarity is servable.
   **Then delete the `build_operator_registry` monkeypatch** at
   `tests/examples/test_s1_01_governed_resolver_adoption.py:255`.
3. **`F-08`.** A seam in candidate construction for the three declared contract members. One direct
   test that a declared member reaches the served product and its content address.
4. **`F-11`** — add the **minimum governed binding mechanism**: a declaration that explicitly permits
   request-time conditioning for a parameter, a domain the effective value must satisfy, and a refusal
   for undeclared or out-of-domain substitution. The resolver records the effective value **and its
   authority**. **Then delete the `_operator_parameters` monkeypatch** at
   `tests/products/test_cp05_canonical_path.py:599`.
5. **`F-12`** — a governed, field-specific Control Plane refusal at **boot**, shaped like
   `_refuse_operator_set_divergence`. The `mapping[name, reason]` shape is untouched. **Then, and only
   then,** cp-05's two-edit canonical correction (`D-IMPL-288` (2)).
6. **Rerun `s1-01` and cp-05 unchanged, once.** Any new deficiency is **classified, not repaired**
   (`D-IMPL-287` (6), Dave: *"Do not repair the example during 24.11."*).

**The success signal, needing nothing built:** both `monkeypatch.setattr` calls are **gone**,
because the SDK supplies those capabilities itself. Not six XFAILs turning green.
