# 15.6-07 — when the source last published, as a fact of its own

`D-IMPL-112` recorded three things a KYC analyst shown `D_c=0.221 / forced_llm
/ F=0.803` still could not act on. Plan 15.6-06 shipped the first — a way for
debt to point at what it summarises. This plan ships the second: **when the
underlying source filings were last refreshed**, as a fact distinct from the
freshness the fabric computed.

The distinction is the whole content of this change, so it is worth stating
before anything else. `F` is a **derived** number: how much of a decay budget
`λ_c × Risk Sensitivity` the fabric's own curve has eaten since the fabric
learned each observation. A refresh instant is an **observed** fact about the
world upstream of the fabric: when the registry last filed. Neither is
recoverable from the other. A registry that publishes annually and filed last
week is current; one that publishes nightly and filed last week is a year of
silence wearing the same `F`.

`15.6-RESEARCH.md` § B3 verified that nothing in the tree modelled it, and the
places a reader would look first are each ruled out by their own docstrings:
`ccf.halflife.decay.Observation.observed_at` is *when the fabric learned the
observation*, `ccf.contracts.claims.LineageEntry.observed_at` is the same
clock, `ccf.halflife.debt.FreshnessScorer` computes the derived number rather
than the underlying fact, `ccf.controlplane.artifacts.HalfLifeEntry` carries a
rate rather than an instant, `ccf.graph.protocols.SourceAttestation`'s own
scoping note puts temporal correctness outside what a source attests, and
`ccf.products.contract.FreshnessSLA` is an expectation rather than an
observation. **Nothing above was extended.** `ccf.contracts.claims` in
particular is byte-identical, and its whole-file `sha256` pin
(`tests/peering/test_admission_record.py`) is green.

## What the SDK owes here, and what it does not

`D-IMPL-117`, verbatim: *"a slot for source-refresh recency, owing no
definition of a source or a cadence."* Concretely, and this is a list of things
that are **absent on purpose**: no source type, no source vocabulary, no
`Literal` of source names, no refresh-interval or cadence field, no staleness
threshold, no default of any kind, and **no comparison** of a refresh instant
against `now`, against a threshold or against an observation's own clock.

The SDK stores an instant and an opaque reference and draws nothing from
either. The moment it drew something it would have decided which sources matter
more than others — which is salience, which `D-IMPL-101` deferred to a later
phase with *"no mechanism for it"* landing here. Whether a July filing is
recent enough for an August decision is the context product creator's
judgement, expressed through the product's evolutionary capability rather than
through SDK code.

That the SDK never reads the value is asserted rather than promised:
`tests/halflife/test_debt.py::test_the_recency_is_carried_and_never_consumed`
scans every module under `src/ccf/` and requires `refreshed_at` to appear in
exactly one of them — the module that declares it.

## The content address moves, and that is the ruled change — the second of two

`ContextProductContract` gained a second hashed field this phase, so **every
content address recorded before this plan differs from the one the same product
produces now.** `D-IMPL-117` authorized that in advance — *"surface impact is
accepted"* — so it is a ruled cost, not a defect.

**This is the second address move inside Phase 15.6, and it chains to the
first.** Plan 15.6-06's fragment records the first. The before value below is
that plan's recorded after value, and they match exactly — read the two
fragments in order and the chain is continuous:

| Artifact | Value pinned | Before | After |
| --- | --- | --- | --- |
| `examples/08-e2e-demo/artifacts/expected_output.txt` | replay-record address (elided to a 16-hex prefix) | `06e454f49cc89712…` | `36ebd7593fd84d6c…` |

**Regenerated by running the demo, never by editing a hash.** The example's own
narration buffer was written to the artifact, and the resulting diff is exactly
one line. The census was re-run at this plan's base rather than recalled: 18
tracked files hold address literals across the swept roots, **1** moves, and
every site the census classifies as *does not move* was confirmed by running
the full suite rather than assumed.

`D-IMPL-118` places the slot **top-level on the vessel**, which is the branch
that is *not* free at replay. `ProjectionOutput` carries exactly
`(plan_id, payload)`, so a `(record, projection)` rehydrator can produce a
top-level vessel field only if the record carries it. The ruling therefore
obliges **both** halves, and both landed in one commit: a matching
`source_refresh_recency` member on `ContentGenerationPath`, and the read-back
in every shipped `rehydrate_product` — the Protocol contract in
`src/ccf/replay/engine.py` plus all seven concrete implementations across
`tests/replay/test_engine_rehydration.py`,
`tests/replay/test_query_sequence_pin.py`, `perf/suites/replay/conftest.py`,
`examples/06-decision-replay/run.py` and
`examples/external/00-hello-context/run.py`.

**That the read-back is load-bearing is a run result, and it has a precondition
worth recording.** Deleted while the tripwire's fixture product carried *no*
refresh instants, the line costs nothing — all 30 cases still passed, because
sentinel agrees with sentinel. With the fixture populated, deleting the same
line turns **10 of that module's 36 cases** red with `ReplayDivergence`,
including the `debt`, `debt_evidence` and `request` landings that predate this
plan. A read-back seam is only ever proven by a populated value, and the
measurement is recorded in a comment at the line so a later reader does not
have to re-run it.

The claim is proven on the real serve path rather than asserted:
`tests/replay/test_engine_rehydration.py::test_when_the_sources_last_published_replays_byte_exactly`
serves a recency-bearing product, ingests a later envelope so the graph has
moved on four months, replays, and recomputes **both** addresses. Its two
adversarial twins show the failure modes are detected rather than tolerated:
`test_a_rehydration_that_drops_the_recency_is_divergence`, and — not implied by
it — `test_a_rehydration_that_moves_one_refresh_instant_is_divergence`, which
rules out an implementation treating the slot as *which* sources were read
rather than *when* each last published.

**What an adopter with recorded addresses must do.** Records written before
this plan replay unchanged: their products recorded no refresh instants, their
dimension 5 carries the `NO_SOURCE_REFRESH_RECENCY` sentinel, and the two agree
— asserted by `test_a_record_written_before_the_recency_seam_still_replays`.
Addresses recorded *outside* the replay record — in a fixture, a transcript, an
external system's index — must be re-recorded for products assembled after this
plan.

## Two census findings, both recorded so a reader does not infer the wrong mechanism

1. **The `skill-set in force` hash on the line below the one that moved
   (`aafa91413bcd8b21…`) did not move**, exactly as plan 15.6-06 found for its
   own move and for the same reason: under `qa-toplevel` `DebtAssessment` is
   byte-identical, so nothing carrying one moves. Only the record address —
   which carries `ContentGenerationPath`, which gained the member — moves. This
   confirms 15.6-06's finding a second time rather than restating it.
2. **`examples/s1-01-hello-context-product`'s committed output did not move**,
   even though that example is where the slot is *populated*. Its transcript
   prints the answer and its provenance rather than a product content address,
   so a hashed-field addition is invisible to it. Recorded because the opposite
   would be the natural assumption.

## The value is populated by a deployment, and declared rather than derived

`examples/s1-01-hello-context-product` populates the slot, and **where the
instants come from is the teaching point.** They are authored in
`artifacts/product-governance.yaml`, one entry per source system id that
`artifacts/events.yaml` already stamps on its envelopes, each naming its zone.
They are not derived from anything the fabric observed, and the reason is
recorded at the artifact: deriving a refresh instant from an envelope's
`observed_time` would collapse it back into the fact it exists to be distinct
from, and computing it from the decision instant would make it a restatement of
`now`.

It is read as a scenario **field** rather than as a view-taking method, unlike
the `debt` and `debt_evidence` beside it. Those two are measured against what
the operators left standing; this one is declared, because a refresh instant is
not a property of the assembled view at all. Giving it a `GraphView` parameter
it would not read would suggest otherwise.

## ccf.halflife.assessment.SourceRefreshRecency

- Surface: ccf.halflife.assessment.SourceRefreshRecency
- Public surface: true
- Before: absent
- After: the annotated carrier type — a `tuple[SourceRefresh, ...]` validated to
  be **source-unique** and **canonically ordered**. A repeated `source_ref` is
  refused at construction with a message saying that two refresh instants for
  one source describe two facts claiming to be one
- Change type: added
- Why: an alias rather than a field-by-field re-declaration for
  `ccf.halflife.assessment.DebtEvidence`'s reason — the carrier lands in **two**
  places, the product vessel and replay dimension 5, and one validated shape is
  what keeps those from drifting apart. A sorted tuple rather than a
  `frozenset`: the value is inside a content address, so it must be
  order-insensitive in its bytes, and a set keyed on the whole entry would keep
  both halves of a contradiction while one keyed on the reference would drop a
  half silently. **This description is of what plan 15.6-07 shipped and is
  superseded by `D-IMPL-124`** — plan 15.6-13 replaced the per-source tuple
  with a two-instant `ccf.halflife.assessment.SourceRefreshWindow`, so the
  order-insensitivity assertion this entry originally cited was retired with
  the collection it guarded. See
  `docs/surface-changes/15.6-13-source-refresh-window.md`
- Migration: none — new name

## ccf.halflife.assessment.NO_SOURCE_REFRESH_RECENCY

- Surface: ccf.halflife.assessment.NO_SOURCE_REFRESH_RECENCY
- Public surface: true
- Before: absent
- After: the empty tuple, as a named module-level constant whose docstring
  states the positive claim *this product records nothing about when its
  sources last refreshed*
- Change type: added
- Why: `D-IMPL-38`, and the reason `NO_SCORER_PINS` and `NO_DEBT_EVIDENCE` each

  repudiation failure mode every sentinel here closes. Never `None` meaning
  "unknown"
- Migration: none — it is the default on both fields that carry the carrier, so
  every construction site written before this plan asserts exactly what it
  always asserted

## ccf.replay.record.ContentGenerationPath

- Surface: ccf.replay.record.ContentGenerationPath
- Public surface: true
- Before: nine fields, ending at 15.6-06's `debt_evidence`
- After: one further field, `source_refresh_recency: SourceRefreshRecency`,
  defaulted to `NO_SOURCE_REFRESH_RECENCY`, placed beside the `debt` whose
  freshness factor it is deliberately not
- Change type: reshaped
- Why: this member is **the price of the ruled placement**, not a symmetry.
  Because the carrier is top-level on the vessel rather than nested inside the
  assessment, it does not ride `debt` back through replay; `ProjectionOutput`
  carries exactly `(plan_id, payload)`, so without this field no implementation
  of the `(record, projection)` signature can produce the value and every
  replay of every product raises `ReplayDivergence`. Dimension 5 and not a

  `test_the_recency_lands_on_dimension_five_and_mints_no_sixth`
- Migration: none for construction. `NO_SOURCE_REFRESH_RECENCY` is the positive
  assertion *this decision recorded no refresh instants*, so a record written
  before this seam parses and verifies unchanged

## ccf.replay.record.build_replay_record

- Surface: ccf.replay.record.build_replay_record
- Public surface: true
- Change type: behavior
- Before: the record's dimension 5 said nothing about when the assembled
  sources had last published
- After: **the same signature.** Dimension 5's `source_refresh_recency` is
  *derived from the `product` argument the builder was already handed* — no new
  parameter
- Why: derivation rather than threading is what keeps every
  `build_replay_record` consumer byte-for-byte unchanged, and it makes a record
  pinning refresh instants its product does not carry **unrepresentable** rather
  than merely discouraged. It is the rule 15.5-11 applied to `debt` and 15.6-06
  applied to `debt_evidence`: a fact already present is read, never re-passed
- Migration: **none.** No call site changes. A caller that wants recency on the
  record puts it on the product

## ccf.replay.engine.ReplayEnvironment

- Surface: ccf.replay.engine.ReplayEnvironment
- Public surface: true
- Change type: behavior
- Before: a conforming `rehydrate_product(*, record, projection)` had to carry
  `record.content_generation_path.debt` (15.5-11) and
  `record.content_generation_path.debt_evidence` (15.6-06) onto the product it
  returned
- After: **the same signature** — which is why this is `behavior` rather than
  `reshaped`. What changed is the **contract**: it must now *also* carry
  `record.content_generation_path.source_refresh_recency`
- Why: `ContextProductContract.source_refresh_recency` is inside the hashed
  body and is **not** reachable through `debt` — the ruled placement made it a
  sibling of the assessment, not a member. `canonical_bytes` walks a model
  field-by-field over `type(value).model_fields`, so an implementation that
  omits it returns a product `ccf.replay.engine::replay`'s address check
  rejects with `ReplayDivergence`
- Migration: **required for any adopter with a custom `ReplayEnvironment`, even
  if you never populate the field, and it is one line.** Add
  `source_refresh_recency=record.content_generation_path.source_refresh_recency`
  to the `ContextProductContract(...)` your `rehydrate_product` returns. All
  seven implementations across six files in this repository were updated in the
  same commit (`src/ccf/replay/engine.py`,
  `tests/replay/test_engine_rehydration.py`,
  `tests/replay/test_query_sequence_pin.py`, `perf/suites/replay/conftest.py`,
  `examples/06-decision-replay/run.py`,
  `examples/external/00-hello-context/run.py`). **Do not re-acquire the refresh
  instants at replay** — a refresh instant is what the deployment declared about
  a source at assembly time, so a rehydrator that asked the source again would
  be recording today's answer against yesterday's decision. An adopter who omits
  the line does not get a silent wrong answer; they get `ReplayDivergence`,
  which is the failure mode this fabric prefers
