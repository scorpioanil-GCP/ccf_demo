# 24.10-03 — the acquisition boundary already existed; a reference implementation ships beside it

Applied 2026-09-08 under `D-IMPL-282` (`R-09`, option 3a — Dave), verbatim:

> *"Acquisition emits `SignalEnvelope`s only. Reuse the existing L1→L2 resolution/admission
> path to produce entities and relationship claims. Do not create a second relationship-claim
> output unless real evidence shows the existing envelope/resolution mechanism cannot express
> cp-05's edges. Ship the small file/fixture-backed reference implementation required by the
> SDK convention; use cp-05's real SPARQL only from the test harness to preserve the 77/100
> evidence without putting domain logic in `src/`."*

and under the bound `D-IMPL-283` (2) placed on this row:

> *"given the measured existence of `SignalSourceProtocol`, Plan 03 must not presume a new
> acquisition Protocol is required. … Only if it cannot should a new surface be proposed, and
> that proposal should stop for a ruling rather than ship automatically."*

## What did NOT change, stated first

- **No new Protocol was declared, and none was needed.** The measurement (below) came out
  REUSE. `ccf.signal.source.SignalSourceProtocol` is the acquisition boundary and already
  was; `D-IMPL-277` is resolved **by discoverability**, not by new surface.
- **No second relationship-claim output type.** Acquisition's only output type is
  `SignalEnvelope`, which carries no entity field and no relationship field — the property is
  structural, not a coding convention.
- **No change to `AssemblyWorker`, to the resolution spec, or to any L1→L2 code path.** The
  77/100 evidence is driven through the path exactly as it stood at the phase base.
- **No domain vocabulary entered `src/`.** No query, no predicate IRI, no anchor, no source
  system name. The roster of files under `src/` matching `SELECT|sparql` is byte-identical to
  its value before the first edit — 14 files, unchanged, and none of them under
  `src/ccf/signal/`.
- **Not one byte of `examples/` changed.** cp-05 is read for its declarations and its measured
  numbers and nothing else (`D-IMPL-261`).

## The measurement, because it is the deliverable

A deployment-side adapter was constructed over `SignalSourceProtocol` carrying cp-05's
acquisition parameters as **constructor state** and exposing them to the fabric through the
one parameter the Protocol declares, `tenant_id`. It was then run against the live estate.

| Question | Answer |
| --- | --- |
| `isinstance(adapter, SignalSourceProtocol)` | `True` |
| Did it produce envelopes for a parameterized acquisition? | Yes — 77 node envelopes, 100 edge envelopes |
| What could the constructor-state bridge not carry? | Nothing |

The bridge holds. `MCPSourceAdapter` already uses the same pattern for its resource selection,
which is why it was the existence proof to test against.

## ccf.signal.acquisition.FileRecordAcquisitionSource

- Surface: ccf.signal.acquisition.FileRecordAcquisitionSource
- Public surface: true
- Change type: added
- Before: absent — the ingress seam shipped with an MCP adapter but no file-backed reference implementation, so a reader looking for "how do external records enter CCF" found a Protocol with one network-shaped implementer and concluded no acquisition boundary existed
- After: a `SignalSourceProtocol` implementation reading a JSON array of source records and emitting one envelope per record, with the record verbatim in `raw_payload`, `observed_time` unset, a deterministic content-addressed `envelope_id`, and the acquisition parameters carried as constructor-side `selectors`
- Why: CLAUDE.md §11 requires a reference implementation beside every Protocol, and `D-17` makes it this row's deliverable; it is also the offline half of the `R-09` evidence, replaying a captured live acquisition to the same 77/100 with no estate reachable
- Migration: none — a new name, nothing removed or reshaped

## ccf.signal.acquisition.AcquisitionRecordError

- Surface: ccf.signal.acquisition.AcquisitionRecordError
- Public surface: true
- Change type: added
- Before: absent
- After: raised when a source document is unreadable, is not valid JSON, is not a JSON array, or carries a non-object member — naming the offending record's position
- Why: a silently dropped record is a graph that is quietly incomplete, which is worse than a stream that stops; this is the same posture `McpMappingError` takes at the same seam (T-06-25). An empty *selection* is deliberately not an error — "no records matched" is an answer
- Migration: none — a new name

## ccf.signal (package docstring)

- Surface: ccf.signal
- Public surface: true
- Change type: behavior
- Before: the package docstring said concrete adapters "live in the runtime package", which was already inaccurate (`ccf.signal.mcp_source` is one), and named no acquisition boundary

## Findings recorded, not repaired

### `24.10-F-04` — a Protocol nobody could find

`R-09` was raised on cp-05's own note that *"the SDK has no acquisition boundary for an
external graph store — every adapter in `ccf.graph.backends` is an L3 substrate the fabric
OWNS"*. That reading is correct about the **graph backends** and imprecise about **L1**: the
seam existed the whole time, one import away, with a conforming adapter beside it. The
defect is discoverability. `R-03` is the row that measures it, and this row does not
pre-empt that measurement.

### `24.10-F-05` — the resolution half cannot express an edge between entities that already exist

**Measured against a real fabric, not inherited from a prior phase's note.** An entity URI is
`f"{entity_class}://{content_hash(identity)}"` where `identity` is `{key: value}` over the
rule's `identity_keys`, so the identity hash covers the identity **key name**. Two
consequences, both asserted in
`tests/signal_layer/test_cp05_acquisition_boundary.py::test_the_resolution_half_cannot_express_an_edge_between_existing_entities`:

1. Two endpoint rules reading the *same* identity key resolve one edge envelope's two
   endpoints to the *same* URI; the pair is dropped as a self-loop. Entities 2 → 3, **0
   relationships**.
2. Two endpoint rules reading *distinct* key names mint two **new** entities and join those.
   Entities 2 → 4, **1 relationship**, between neither of the two entities that existed.

So an edge envelope can only join entities the *same envelope* resolved, and cp-05's edges
join entities minted by earlier envelopes.

**This is preserved and classified, not worked around** (`D-16`). The existing **admission**
half — `AssemblyWorker.admit_relationship_claim` — expresses them exactly, is still L2, is
still the single writer, and is where all 100 claims land. `D-15` names *"the existing L1→L2
resolution/admission path"*, both halves, so no second output type was created and no new
surface is proposed on the strength of this finding.

## Regression evidence

`tests/signal_layer/test_acquisition_reference.py` — 12 tests over the reference
implementation, written RED-first (committed failing at `065e4d72`, before the module
existed). The load-bearing ones are the negative controls: an excluded record emits nothing,
an empty selection is an empty stream and not an error, the payload compares byte-equal to
the record, ids are stable across two constructions, and no exported name is a Protocol.

`tests/signal_layer/test_cp05_acquisition_boundary.py` — 12 tests. The live half (3,
`pytest.mark.fluree`, env-gated on `CCF_CP_05_FLUREE_URL` / `CCF_CP_05_FLUREE_LEDGER`) drove
cp-05's real SPARQL against the read-only estate and observed **77 entities and 100
relationship claims off L3**. The offline half (9) replays the committed 177-record capture
through `FileRecordAcquisitionSource` to the same numbers, so CI asserts rather than skips.

**Sabotage-verified, three ways**, because a guard nobody broke is a guard nobody measured:
dropping one edge from the fixture turns the offline 77/100 and the non-vacuity check red;
planting a `SELECT` in `src/ccf/signal/` turns the domain-vocabulary guard red; and inverting
the `24.10-F-05` assertion to the *fixed-SDK* world turns that test red — which is what proves
it discriminates rather than merely passing.
