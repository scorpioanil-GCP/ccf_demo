# 20.1-01 — a public name needs a legal spelling

**No decision id is spent by this fragment.** `D-IMPL-346` remains unspent;
the `20.1` prefix names rung 20 and its first follow-up, not a `D-IMPL`.

`D-GATE-cp-20` follow-up, ruled by Dave 2026-09-22 during the release
qualification of `172f1612`. Raised by `tools/docs_tests/test_advisory_discharge.py::test_a1_no_submodule_import_is_taught_or_demonstrated`,
which found three submodule-spelled imports in `examples/cp-20-syndicated-lending-co-lender/deployment.py`.

## What did NOT change, stated first

- **No behavior moved.** `register_manifest_entries` is the same function, at
  the same definition site, with the same signature and the same semantics.
  Nothing calls it differently and nothing it returns is different.
- **It was already public.** `ccf.deployment.manifest.__all__` has named it
  since it was written, and the committed surface manifest already recorded it
  there. This is not a promotion from private to public.
- **Nothing was removed or reshaped.** The generated diff against
  `docs/surface/v0.2-surface.json` is **five insertions and zero deletions**.
- **`ccf.deployment.manifest` is unchanged** — the submodule keeps the name;
  the package now also offers it.

## The defect this closes

A-1 — the day-1 import convention — tells adopters to write
`from ccf.deployment import …` and treats `from ccf.deployment.<sub> import …`
as reaching into implementation detail. `register_manifest_entries` was
reachable **only** by the spelling that convention forbids. A public symbol
with no legal spelling is a surface an adopter cannot consume without
violating the documented convention, and cp-20 is the measured proof: it wrote
the illegal spelling because there was no legal one.

The omission was accidental rather than deliberate, and its own siblings are
the evidence. `ccf.deployment.manifest.__all__` names three symbols:

| symbol | re-exported at `ccf.deployment` before this change |
| --- | --- |
| `BootedFabric` | yes |
| `load_and_boot` | yes |
| `register_manifest_entries` | **no** |

Two of three were re-exported from the start. Nothing in the tree, the docs or
the decision log states a reason the third should differ.

## ccf.deployment.register_manifest_entries

- Surface: ccf.deployment.register_manifest_entries
- Public surface: true
- Change type: added
- Before: reachable only as `from ccf.deployment.manifest import register_manifest_entries` — public in the submodule's `__all__`, absent from the package's, and therefore writable only in the spelling A-1 forbids
- After: re-exported at the package, so `from ccf.deployment import register_manifest_entries` is the day-1 spelling and matches how `BootedFabric` and `load_and_boot` already resolve
- Why: a public name with no convention-legal spelling is a surface defect, not a style preference; cp-20 wrote the forbidden spelling because it was the only one that worked
- Migration: none. The submodule path still resolves and no existing call site has to move; new code should prefer the package spelling.
