# 24.5-13 — one structural gate for declared obligations: a class-declared debt ceiling a request may only tighten, and a class-declared lineage obligation, in both runners

Plan `24.5-13`, ledger rows `24.5-L-14` and `24.5-L-26` (`D-IMPL-236`). The
Wave-2 edit `D-IMPL-237` licenses and nothing beyond it:

- `L-14` — `DebtSignal.FAIL_CLOSED` was set by `assess_debt` and read by no
  product serve path; `debt_tolerance` was compared against nothing (0
  occurrences in `src/`); the Standard's *"Debt gate exceeded → 409 with the
  debt block"* (§9) was a documented lie through two closes.
- `L-26` — no per-attribute lineage obligation existed in the SDK; cp-03
  carried it as a product gate (`OFS-G12`) and `CP-SPEC-003` §F.4 #2 recorded
  the gap.

## What did NOT change, stated first

- **ONE gate mechanism, and only one** (`D-IMPL-237`). One token
  (`declared-obligations`), one function (`_refuse_declared_obligations`), one
  refusal type (`DeclaredObligationRefusal`), carrying both obligations under
  one `obligation` discriminator. No second gate type, no gate registry, no
  helper gate.
- **No payload gate** (`D-IMPL-238` reading `D-IMPL-102` limb 3). The lineage
  half reads the presence and non-emptiness of a NAMED top-level payload
  member and nothing else; `tests/products/test_structural_gates.py::test_no_payload_shape_is_read`
  serves a member holding garbage. `tests/products/test_payload_bind.py::TestNoFourthGate`
  is unchanged and green: `run_gates` takes no `payload`/`schema` parameter and
  `gates.py` names no payload comparison.
- **The five tokens D-IMPL-238 records are unchanged**, and the census
  re-enumerates both runners by set equality (below).
- **`_GATE_TOKEN`, `_ServableProductMeta`, `GateBypassError` untouched**
  (`D-IMPL-224` (5)). The new step returns a refusal before the token is
  minted, as the four before it do.
- **Every pre-phase call site is byte-identical under the defaults** (`D-10`):
  `debt_tolerance: Decimal | None = None` on both runners;
  `serve_obligations` defaults to `NO_SERVE_OBLIGATIONS` on the declaration,
  the registered class and `register_product_class`. A class that declares
  nothing never reaches a comparison — proven on a control at any `D_c`.
- **No number in `src/`** (CINV-01). The class declares the ceiling's
  presence and the deployment authors its number in the product-class
  artifact; the request supplies its own. `ServeObligations` validates the
  ceiling to `[0, 1]`, the interval `DebtAssessment.debt` already holds
  (a proportion's bounds, not a threshold).
- **No principal or perspective reaches any debt path** (`D-IMPL-105`); the
  resolver reads `request.parameters.get(DEBT_TOLERANCE_PARAMETER)` and the
  class's declaration, nothing else.
- **No example was edited.** `examples/` is closed; the HTTP `409` mapping is
  plan `24.5-14`; the empty-operator split is plan `24.5-15`.

## ccf.products.contract.ServeObligations

- Surface: ccf.products.contract.ServeObligations
- Public surface: true
- Change type: added
- Before: absent — a product class could declare no serve-time obligation; the ceiling and the lineage obligation had no seat
- After: `ServeObligations(debt_ceiling: Decimal | None = None, lineage_inputs_at: frozenset[str] = frozenset())` — `debt_ceiling` validated to `[0, 1]`, `None` the positive sentinel *no ceiling declared*; `lineage_inputs_at` the TOP-LEVEL payload members that must be present and non-empty at serve, the empty set the positive sentinel *no obligation declared*
- Why: `24.5-L-14`, `24.5-L-26`, `D-IMPL-237`, `D-IMPL-240` (3): the class declares the ceiling, a request may tighten it, serve refuses over-ceiling by name. Obligations, never gate types: a class declares what the one shipped gate holds it to
- Migration: none — additive. An adopter that wants the gate to bite authors `serve_obligations` on its product-class artifact

## ccf.products.gates.effective_debt_ceiling

- Surface: ccf.products.gates.effective_debt_ceiling
- Public surface: true
- Change type: added
- Before: absent
- After: `effective_debt_ceiling(*, declared: Decimal | None, requested: object) -> Decimal | None` — pure: `declared is None → None` (a request cannot CREATE a ceiling); `requested` absent or not a finite number → `declared`; else `min(declared, requested)`. A looser request is ignored, not refused: the class's ceiling is the floor of strictness. Both runners apply it themselves against the class's declaration, so no caller can pass a loosening value; the resolver's own call is idempotent
- Why: `24.5-L-14`, `D-IMPL-240` (3) (*"Class declares, request may tighten"*); threat `T-24.5-33`
- Migration: none
