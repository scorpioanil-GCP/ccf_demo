# 15.6-08 — what a debt signal obliges, bound by the deployment and named by nobody in the SDK

`D-IMPL-112` recorded three things a KYC analyst shown `D_c=0.221 / forced_llm
/ F=0.803` still could not act on. Plan 15.6-06 shipped the first, plan 15.6-07
the second. This plan ships the third and last: **what the routing state
actually obliges you to do.**

`15.6-RESEARCH.md` § B4 measured the asymmetry that makes it a gap rather than
a nicety. `ccf.halflife.assessment.DebtSignal.FAIL_CLOSED` has exactly one
consumer (`ccf_runtime.workflow.engine`, routing the exception path under
`INV-CH7-68`/`D-IMPL-65`) and `DebtSignal.OK` has exactly one
(`ccf.hitl.escalation`, refusing escalation for a nominal assessment). `DebtSignal
.FORCED_LLM` is produced at exactly one site — `ccf.halflife.debt::assess_debt` —
and **consumed nowhere**. The fabric already acts on two thirds of its own enum
and says nothing about the third.

## What the SDK owes here, and what it emphatically does not

`D-IMPL-117`, verbatim: *"a signal-to-obligation binding that survives replay,
and owes no obligation vocabulary (that is user configuration — CLAUDE.md §11,
and the same posture `D-IMPL-101` took on salience)."*

So the SDK ships a **binding**, and this is the list of what is absent on
purpose: no obligation type, no `StrEnum` or `Literal` of obligation names, no
default mapping, no reference constant, no permitted set, no docstring example
that reads as a recommended vocabulary — and **no branch anywhere in `src/` or
`runtime/` that reads an obligation and does something with it**. Taking an
action on the value would be choosing the vocabulary by the back door.

The SDK validates **keys** and never **values**. Keys are `DebtSignal` members,
a whitepaper §7.7 CAR type the SDK owns, ships and already branches on, so a
binding naming a state the fabric never produces is refused at construction with
the offending key in the message. The value beside it gets no such treatment:
`tests/halflife/test_debt.py::test_the_sdk_accepts_an_obligation_string_it_has_never_seen`
asserts that an arbitrary token no shipped module has ever seen round-trips
verbatim.

**This was the highest-risk item in Track B for CLAUDE.md §11, and it ran
against an armed gate rather than a post-mortem.** `D-IMPL-112` *quotes* three
words an analyst used, and they read like a specification. `15.6-RESEARCH.md`
§ B4 measured that no shipped lint would have caught them in code:
`cinv01b-numeric-table` catches a numeric table, and `cinv01a-prompt-shape`
scores prose against `MIN_PROMPT_CHARS = 40`. A three-member `StrEnum` of
obligation names is neither. Plan 15.6-03 therefore shipped
`tests/invariants/test_no_obligation_vocabulary.py` in wave 1, an AST walk over
`src/ccf/halflife/` and `src/ccf/controlplane/artifacts.py` — both of which this
plan edits. It was run and recorded green **before the first edit** and is green
after, with **no new exemption** and **no edit to the invariant**.

## FORCED_LLM has a binding now, and still has no consumer — that distinction is the point

This is the sentence a reviewer is most likely to misread, so it is stated
rather than left inferable. Before this plan, `FORCED_LLM` had zero consumers in
the SDK. After this plan it still has zero. What changed is that the *delivered
product* now carries what the deployment's own Control Plane says that state
requires, and the deployment's code is what acts on it.

That is not a half-measure; it is the boundary. A fabric that re-pulled a source
or escalated to a named officer on `forced_llm` would have decided what
`forced_llm` means for everybody. `tests/halflife/test_debt.py::test_the_sdk_names_no_obligation_and_takes_no_action_on_one`
enumerates every `DebtSignal.` reference in `src/` and `runtime/` and pins the
set at exactly the five that predate this plan — three in the producer, two in
the two consumers — so a future branch on `FORCED_LLM` is a failing test rather
than a code review someone might miss.

content address recorded before this plan differs from the one the same product
produces now.** `D-IMPL-117` authorized that in advance — *"surface impact is
accepted … the third product-content-address move [is an] authorized cost, not
[a] risk to be designed around"* — so it is a ruled cost, not a defect.

`D-IMPL-118` places the member **top-level on the vessel**, the branch that is

**That the read-back is load-bearing is a run result, with the precondition plan

still passed, because sentinel agrees with sentinel. With the fixture carrying a
real bound obligation, deleting the same line turns **13 of that module's 43
cases** red with `ReplayDivergence`, including the `debt`, `debt_evidence`,
`source_refresh_recency` and `request` landings that predate this plan. Both
figures are recorded in a comment at the line. A read-back seam is only ever
proven by a populated value.

## Why this member's replay seam is stronger than its two siblings'

For `debt_evidence` and `source_refresh_recency`, an implementation that omits
the read-back has **nowhere else to get the value**: `ProjectionOutput` carries
exactly `(plan_id, payload)`. For this member the alternative is not omission
but **re-resolution**. A rehydrator holds the deployment's `DebtProfile` and can
look the obligation up again for the very same signal, producing a value that
looks entirely plausible — and answering *"what was this decision obliged to
do?"* with **today's** binding for a decision made under yesterday's. That is a
tampering-and-repudiation failure, and `D-IMPL-26`'s exact-version rule forbids
it: replay resolves exact artifact versions, never `@latest`.

Pinning the resolved value into dimension 5 is what makes the substitution
*unavailable* rather than merely discouraged, and the content address is what
catches an attempt. Both halves are proven on the real serve path rather than
asserted:

- `test_a_replay_reproduces_the_obligation_in_force_at_decision_time` serves a
  decision under one calibration, **rebinds the profile in the Control Plane**,
  replays, and asserts both directions — the recorded obligation reproduces
  **and** the current one does not.
- `test_a_rehydration_that_resolves_todays_binding_is_divergence` attempts the
  substitution and is refused. It is strictly stronger than the drop case beside
  it: the returned product carries a *plausible* obligation rather than an empty
  one, so only the address distinguishes it.
- `test_what_the_signal_obliged_replays_byte_exactly` runs after the graph has
  moved on four months and recomputes **both** addresses rather than trusting
  either.

**What an adopter with recorded addresses must do.** Records written before this
plan replay unchanged: their products carried no bound obligation, their
dimension 5 carries the `NO_OBLIGATION_IN_FORCE` sentinel, and the two agree —
asserted by `test_a_record_written_before_the_obligation_seam_still_replays`.
Addresses recorded *outside* the replay record — in a fixture, a transcript, an
external system's index — must be re-recorded for products assembled after this
plan.

## Where the vocabulary lives, and why that is the whole demonstration

`examples/s1-01-hello-context-product/artifacts/debt-profile.yaml` declares two
bindings, in a KYC bank's own words, beside the CAR bands it already declared.
`ok` is deliberately left **unbound**, because a partly-bound calibration is the
common real case and the delivered product then carries the named sentinel — a
positive claim that nothing was bound, never a null standing for "we forgot".

The demonstration turns on a contrast the example already had. Question 1 is
fresh, routes to `ok`, and carries the sentinel. Question 3 asks the same thing
six weeks later against the same graph, measures more decay, crosses the
Forced-LLM band, and carries
`kyc/re-pull-registry-then-restate-with-debt-disclosed` — a string that exists
in exactly one place in this repository, and that place is an artifact.
`tests/examples/test_s1_01_output.py::test_the_routing_state_carries_what_this_deployment_says_it_obliges`
reads the artifact and asserts the delivered obligation is byte-identical to it,
so "no part of this came from CCF" is checkable rather than claimed.

## Two census findings, recorded so a reader does not infer the wrong mechanism

1. **The `skill-set in force` hash on the line below the one that moved
   (`aafa91413bcd8b21…`) did not move**, for the third time and for the same
   reason plans 15.6-06 and 15.6-07 each recorded: under `qa-toplevel`

2. **`examples/s1-01-hello-context-product`'s committed expectation document did

   because it breaks the pattern the two sibling plans established.

## ccf.halflife.assessment.SignalObligation

- Surface: ccf.halflife.assessment.SignalObligation
- Public surface: true
- Before: absent — a consumer could read a routing state and had no way to learn
  what that state required of them
- After: a `CCFContract` with exactly two fields — `signal: DebtSignal`, the key
  the SDK owns and therefore validates, and `obligation_ref: str`, opaque in the
  `ccf.skills.catalog.SkillRequirements` voice. A key that is not a `DebtSignal`
  member is refused at construction **with the offending key named**; a blank
  reference is refused, because a binding that obliges nothing must not be
  confusable with no binding; the sentinel's own spelling is refused, so nothing
  can impersonate it; a `float` is refused by the module's shared `_refuse_float`
- Change type: added
- Why: `D-IMPL-112` gap 3 named *what operational obligation `forced_llm`
  actually imposes* as the third thing a reader of a debt figure cannot get at,
  and `D-IMPL-117` scoped the SDK's obligation to the binding alone. Two fields
  are the whole structure that obligation supports
- Migration: none — new name, nothing referenced it. Note that the SDK never
  parses, checks or acts on `obligation_ref`, so whatever should *happen* when a
  decision carries one is yours to write

## ccf.halflife.assessment.SignalObligations

- Surface: ccf.halflife.assessment.SignalObligations
- Public surface: true
- Before: absent
- After: the annotated carrier type — a `tuple[SignalObligation, ...]` validated
  to be **signal-unique** and **canonically ordered**. A signal bound twice is
  refused with a message saying that two obligations for one state describe two
  duties claiming to be the single thing that state requires
- Change type: added
- Why: an alias rather than a field-by-field re-declaration, for
  `ccf.halflife.assessment.DebtEvidence`'s reason. A sorted tuple rather than a
  **mapping**, and the reason is this field's own: a YAML mapping keeps the last
  of two duplicate keys **silently**, and a signal bound twice is exactly the
  contradiction a profile author needs told about. Sorting also keeps the
  profile order-insensitive in its bytes, asserted by
  `tests/halflife/test_debt.py::test_binding_declaration_order_does_not_move_the_profile_bytes`
- Migration: none — new name

## ccf.halflife.assessment.NO_SIGNAL_OBLIGATIONS

- Surface: ccf.halflife.assessment.NO_SIGNAL_OBLIGATIONS
- Public surface: true
- Before: absent
- After: the empty tuple, as a named module-level constant whose docstring
  states the positive claim *this profile binds no obligation to any routing
  state*
- Change type: added
- Why: `D-IMPL-38`, and the reason `NO_SCORER_PINS`, `NO_DEBT_EVIDENCE` and
  `NO_SOURCE_REFRESH_RECENCY` each give: without a named sentinel, a deployment
  that deliberately declared no obligations and one whose bindings somebody
  dropped would be **the same artifact**. Never `None` meaning "unknown"

## ccf.halflife.assessment.NO_OBLIGATION_IN_FORCE

- Surface: ccf.halflife.assessment.NO_OBLIGATION_IN_FORCE
- Public surface: true
- Before: absent
- After: the marker string `ccf.no-obligation-in-force`, whose docstring states
  the positive claim *no obligation was bound to the state this decision landed
  in*
- Change type: added
- Why: a marker rather than an empty tuple because the field it defaults holds
  **one** reference and must stay one shape — the `ccf.products.contract

## ccf.controlplane.artifacts.DebtProfile

- Surface: ccf.controlplane.artifacts.DebtProfile
- Public surface: true
- Before: three declared values, none with a default — `risk_sensitivity`,
  `forced_llm_threshold`, `fail_closed_threshold`
- After: one further field, `signal_obligations: SignalObligations`, defaulted
  to `NO_SIGNAL_OBLIGATIONS`; plus one method,
  `obligation_for(signal) -> str`, returning the reference bound to that state
  or the sentinel
- Change type: reshaped
- Why: the calibration half belongs here because the calibration already is
  here. This artifact owns the two bands that decide *which* state a decision
  lands in; it is a `VersionedArtifact` with a published schema; and it is
  already pinned per-agent as `halflife_debt_profile: VersionedRef`, which
  `D-IMPL-97` named as *"axis 5 … the home for a product's debt configuration
  already exists, on the agent, declared and version-pinned."* Binding elsewhere
  would split one calibration across two documents and two version lanes.
  `D-IMPL-118`'s Q-A fork does not reach this half: a Control Plane artifact is
  not the product vessel. `obligation_for` resolves off the **resolved,
  version-pinned instance** the caller already holds and never reaches the
  Control Plane for a `@latest` (`D-IMPL-26`)
- Migration: **none to keep an existing profile working** — the sentinel default
  means every `debt-profile.yaml` in existence parses and means what it always
  meant. To bind obligations, add a `signal_obligations` list of
  `{signal, obligation_ref}` entries; bind only the states you have an answer
  for. `docs/schemas/ccf.debt-profile.json` was regenerated in the same commit

## ccf.products.contract.ContextProductContract

- Surface: ccf.products.contract.ContextProductContract
- Public surface: true
- Before: twelve fields, ending at 15.6-07's `source_refresh_recency`
- After: one further field, `obligation_in_force: str`, defaulted to
  `NO_OBLIGATION_IN_FORCE`. A **third sibling of** `debt`, not a member of it
- Change type: reshaped
- Why: `D-IMPL-118`, which is explicit that its four measured placements

## ccf.replay.record.ContentGenerationPath

- Surface: ccf.replay.record.ContentGenerationPath
- Public surface: true
- Before: ten fields, ending at 15.6-07's `source_refresh_recency`
- After: one further field, `obligation_in_force: str`, defaulted to
  `NO_OBLIGATION_IN_FORCE`, placed beside the `debt` whose routing state it
  answers to
- Change type: reshaped
- Why: this member is **the price of the ruled placement**, and it buys more
  here than for either sibling. Because the value is top-level on the vessel it
  does not ride `debt` back through replay; and unlike the other two, a
  rehydrator *can* obtain a plausible substitute by re-resolving the
  deployment's current `DebtProfile`. Pinning it here is what makes the
  decision's own answer the only answer. Dimension 5 and not a sixth dimension:
  `INV-CH7-80` holds, asserted by field enumeration in
  `test_the_obligation_lands_on_dimension_five_and_mints_no_sixth`
- Migration: none for construction. `NO_OBLIGATION_IN_FORCE` is the positive
  assertion *this decision was under no bound obligation*, so a record written
  before this seam parses and verifies unchanged

## ccf.replay.record.build_replay_record

- Surface: ccf.replay.record.build_replay_record
- Public surface: true
- Change type: behavior
- Before: the record's dimension 5 said nothing about what the routing state
  obliged
- After: **the same signature.** Dimension 5's `obligation_in_force` is *derived
  from the `product` argument the builder was already handed* — no new parameter
- Why: derivation rather than threading is what keeps every
  `build_replay_record` consumer byte-for-byte unchanged, and it makes a record
  pinning an obligation its product does not carry **unrepresentable** rather
  than merely discouraged. It is the rule 15.5-11 applied to `debt`, 15.6-06 to
  `debt_evidence` and 15.6-07 to `source_refresh_recency`: a fact already present
  is read, never re-passed
- Migration: **none.** No call site changes. A caller that wants the obligation
  on the record puts it on the product

## ccf.replay.engine.ReplayEnvironment

- Surface: ccf.replay.engine.ReplayEnvironment
- Public surface: true
- Change type: behavior
- Before: a conforming `rehydrate_product(*, record, projection)` had to carry
  `record.content_generation_path.debt` (15.5-11), `.debt_evidence` (15.6-06)
  and `.source_refresh_recency` (15.6-07) onto the product it returned
- After: **the same signature** — which is why this is `behavior` rather than
  `reshaped`. What changed is the **contract**: it must now *also* carry
  `record.content_generation_path.obligation_in_force`
- Why: `ContextProductContract.obligation_in_force` is inside the hashed body and
  is **not** reachable through `debt`. `canonical_bytes` walks a model
  field-by-field over `type(value).model_fields`, so an implementation that omits
  it returns a product `ccf.replay.engine::replay`'s address check rejects with
  `ReplayDivergence`
- Migration: **required for any adopter with a custom `ReplayEnvironment`, even
  if you never populate the field, and it is one line.** Add
  `obligation_in_force=record.content_generation_path.obligation_in_force` to the
  `ContextProductContract(...)` your `rehydrate_product` returns. All seven
  implementations across six files in this repository were updated in the same
  commit (`src/ccf/replay/engine.py`,
  `tests/replay/test_engine_rehydration.py`,
  `tests/replay/test_query_sequence_pin.py`, `perf/suites/replay/conftest.py`,
  `examples/06-decision-replay/run.py`,
  `examples/external/00-hello-context/run.py`). **Do not resolve the obligation
  from your current `DebtProfile`** — that is the one substitution this field
  exists to make impossible, and it is the failure a plausible-looking
  implementation will produce. An adopter who omits the line does not get a
  silent wrong answer; they get `ReplayDivergence`, which is the failure mode
  this fabric prefers
