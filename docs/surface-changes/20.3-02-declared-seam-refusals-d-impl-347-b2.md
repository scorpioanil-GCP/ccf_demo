# 20.3-02 — the declared seam-refusal map (`D-IMPL-347` B2)

Ruled by Dave 2026-09-23: *"Product class first; deployment may narrow, not
widen. The map is a governed value: exception type → cause / error code."*

A2 widened the **scope** at which a typed `GovernedRefusalRaised` is honored.
B2 is the other axis: which of a deployment's **own** exception types count as
governed refusals at all — and that is a product statement, not SDK mechanism,
because the SDK cannot know whether a `ControlRoomUnreachable` means *the
subject is unavailable* or *this deployment is broken*.

## What did NOT change, stated first

- **Nothing converts by default.** A class declaring no bindings converts
  nothing, which is exactly A2's behavior. Empty is the honest default.
- **Undeclared exceptions re-raise unchanged.** The `except Exception` at each
  seam consults the class's map and re-raises when there is no binding, which
  is what keeps a defect a defect.
- **Exact type, never a subclass walk.** A subclass is a different failure the
  product has not spoken about; inheriting a parent's cause is how a narrow
  declaration silently becomes a wide one.
- **Nothing is imported.** The declared string is compared against the raised
  value's own `module.QualName`, so a declaration cannot cause an import and a
  misspelled one never matches rather than executing something.
- **No new artifact kind**, per the ruling — `seam_refusals` joins
  `requires` and `serve_obligations` on the existing product-class declaration.

## ccf.controlplane.artifacts.SeamRefusalBinding

- Surface: ccf.controlplane.artifacts.SeamRefusalBinding
- Public surface: true
- Change type: added
- Before: absent — a deployment's own domain exception could only escape as a traceback (`CP17-F-11`, `CP13C-F-03`, `CP14-F-21`)
- After: one declared binding of `exception` → `cause` / `error_code`, carried on the product class as `seam_refusals`
- Why: the meaning of a product's own failure is a governed value the product states, in an artifact, like every other governed value (CLAUDE.md §11)
- Migration: none — `seam_refusals` defaults to empty and is hash-transparent, so no existing class declaration changes shape or address

## ccf.deployment.refuse_seam_refusal_widening

- Surface: ccf.deployment.refuse_seam_refusal_widening
- Public surface: true
- Change type: added
- Before: absent
- After: holds a deployment's selection to a subset of the class's bindings
- Why: *"Deployment may subset or bind codes already named by the class."* Refused by NAME rather than silently intersected — an ignored widening and an honored narrowing are the same green build, and the operator who wrote the extra name would never learn it did nothing
- Migration: none — an empty selection means "no narrowing" and is accepted

## ccf.deployment.SeamRefusalWidening

- Surface: ccf.deployment.SeamRefusalWidening
- Public surface: true
- Change type: added
- Before: absent
- After: the typed refusal raised when a deployment names a seam-refusal type its class does not declare
- Why: widening would let a deployment convert a defect the product never classified into an answer
- Migration: none
