# 20.4-01 — the Mode 2 packaging footprint reaches replay dimension 3 (`PKG-F-08`)

Ruled by Dave 2026-09-23 as required for `v1.0.0` if Mode 2 ships. `D-IMPL-347`
added `PackagingTrace` and `ModelVersionRecord.packaging_trace` **with no
producer**: `build_replay_record` took no such argument, so no caller could
ever supply one and `NO_PACKAGING_TRACE` was not a default but the only value
the field could hold. `dr-02` served a memo a model wrote, with real §7.10.4
pins on the payload, and filed a record whose dimension 3 read `no-packaging`
on every field.

No new decision id. `D-IMPL-348` stays unspent.

## What did NOT change, stated first

- **No existing record's address moved.** Every field here is
  `ccf_hash_transparent: True` at a sentinel, so a Mode 1 record carries the
  no-packaging block and hashes exactly as it did before dimension 3 could
  hold one. `THE_FIFTEEN` is untouched.
- **The SDK computes none of these values.** Which model ran, at what
  temperature, against which prompt artifact, producing which bytes are facts
  of the deployment's packaging stage (CLAUDE.md §11). The SDK ships the seam
  and the wiring; the values arrive through `PackagingTraceProtocol`.
- **Nothing is re-derived from the payload by the SDK.** A record rebuilt from
  the served product would make `output_hash` and `product_content_address`
  agree by construction and destroy the one question §7.10.4 asks them
  together — whether the packaging moved the conclusion.
- **Mode 1 deployments are unaffected.** They supply no trace, and the
  no-packaging sentinel is then the true claim rather than a gap.

## ccf.products.resolver.PackagingTraceProtocol

- Surface: ccf.products.resolver.PackagingTraceProtocol
- Public surface: true
- Change type: added
- Before: no way for a deployment to report what its packaging stage did
- After: a `__call__(*, product)` seam returning the five pinned values, exported beside the other deployment-supplied seam Protocols
- Why: §7.10.4 requires the Mode 2 footprint on the record, and only the deployment knows it
- Migration: none — `None` for every Mode 1 deployment, which is every one shipped before `dr-02`

## ccf.replay.record.ModelVersionRecord

- Surface: ccf.replay.record.ModelVersionRecord
- Public surface: true
- Change type: reshaped
- Before: `packaging_trace` existed on the model with no path to populate it
- After: `build_replay_record` accepts `packaging_trace=` and threads it into dimension 3
- Why: a typed slot nothing can fill is documentation wearing a type annotation
- Migration: none — the argument defaults to `None` and the field keeps `NO_PACKAGING_TRACE`, so every existing caller and every record already written is unchanged

## ccf.products.contract.RefusalCause

- Surface: ccf.products.contract.RefusalCause
- Public surface: true
- Change type: added
- Before: the three refusal causes were spelled as a literal in two modules
- After: one exported alias beside `TTLAnchor` and `AssemblyMode`, referenced by both
- Why: the restatement in `controlplane/artifacts.py` read as the SDK enumerating a vocabulary it does not own and took `test_no_obligation_vocabulary.py` from 54 passed to 43 failed (`D-IMPL-117`)
- Migration: none — same three values, same validation; the emitted JSON Schema enum is byte-identical

## The shapes this moved, and why each is not a break

Each of these gained a `packaging_trace` parameter:

- `ccf.products.product.OpenedProduct`
- `ccf.products.product.open_product`
- `ccf.products.resolver.GovernedResolver`
- `ccf.products.resolver.build_governed_resolver`
- `ccf.replay.record.build_replay_record`

**Optional on every helper and REQUIRED on `GovernedResolver`**, which is the
`composite_children` precedent exactly. The dataclass forbids defaults so a
deployment states its posture; a default there made *"this deployment does no
packaging"* and *"nobody wired the seam"* the same construction, and
`PKG-F-08` is what that costs.
