# 24.5-04 — node-class admission on the traversal walk

Plan `24.5-04` works ledger row `24.5-L-05`. Before it, `TraversalNeighborhood`
typed the walk on EDGES (`relationship_types`) and `seed_entity_classes` seeded
only; a walk that must stop at a class boundary — cp-04's `24.4-D-33` — had no
SDK expression. The fix is one additive parameter under the existing
`traversal` category (`D-10`: a new name is additive, a new category is not;
`OperatorCategory` stays four, `D-IMPL-223`), honored or declined by every
backend and amended into `docs/GRAPH_QUERY_SEMANTICS.md` `GQ-10` at semantics
version **1.1.0** (`GQ-35`).

## What did NOT change

- **`OperatorCategory` is four.** `typing.get_args(OperatorCategory)` is
  `("policy", "similarity", "temporal", "traversal")` before and after.
- **Every existing call, corpus entry and composition pair passes unchanged.**
  The field defaults to `None`, the positive assertion "every class is
  admissible on a hop" — the 1.0.x question, byte-for-byte on the answer.
  `TraversalSpec(seed_entity_classes=…, relationship_types=…, depth_limit=…)`
  still constructs; `tests/properties/test_composition.py`'s n² suite is
  untouched (n = 4).
- **The adjacency stays undirected.** Direction is ledger row `24.5-L-06`
  (plans `24.5-05` / `24.5-18`), not this plan.
- **`content_hash(GraphQuery)` moves for every traverse query** (`GQ-20`),
  because `canonical_bytes` walks every field. Research measured that no
  committed query pin exists in the tree and
  `tests/replay/test_query_sequence_pin.py` re-derives pins from live
  executions; the Fluree leg's cp-04 sealed-address tests (`CFT-G16`) stayed
  green, so the parameter's `content_hash` reaches no committed seal either.
- **`src/ccf/controlplane/artifacts.py` is untouched.**
  `TraversalNeighborhoodParametersArtifact` inherits the parameter class
  verbatim, so the committed schema
  `docs/schemas/ccf.operator-parameters.traversal.json` regenerated from the
  parameter edit alone (`tools/dump_schemas.py`); its docstring sentence
  "No field gains a default here" still describes what the ARTIFACT adds
  (nothing) and is left for the return trip to reword if wanted.

## ccf.graph.protocols.TraversalSpec

- Surface: ccf.graph.protocols.TraversalSpec
- Public surface: true
- Change type: reshaped
- Before: three required fields — `seed_entity_classes`, `relationship_types`,
  `depth_limit` — "all three required with no defaults"
- After: a fourth, additive, sentinel-defaulted field
  `admitted_entity_classes: frozenset[str] | None = None` — the spec's first
  sentinel field, on the `GraphQuery.allowed_entities` precedent. `None` admits
  every class (today's behavior); a set admits a hop only onto an entity whose
  `entity_class` is a member. Admission filters REACHED nodes and never walk
  STARTS (`GQ-11` selects starts; `GQ-10`'s "seeds are included" stands), and
  an entity absent from in-scope state is not a hop. The empty set admits no
  hop and answers the starts.
- Why: `24.5-L-05`; `GQ-10` at semantics version 1.1.0; `D-10` additive over
  breaking
- Migration: none — additive. A pushed answerer that cannot express the field
  declines to the fallback (`GQ-32`, D-04)

## ccf.operators.categories.TraversalNeighborhood

- Surface: ccf.operators.categories.TraversalNeighborhood
- Public surface: true
- Change type: behavior
- Before: `read_intent()` projected three fields onto `TraversalSpec`;
  `apply()` BFS-expanded from seed-class entities over the undirected typed
  adjacency and nothing filtered the reached node by class
- After: `read_intent()` mirrors `admitted_entity_classes`; `apply()` builds
  the view's class map once and admits a hop onto `n` only when
  `admitted_entity_classes is None or class_of.get(n) in admitted_entity_classes`.
  Constructor and key unchanged (the manifest records constructors only — the
  `24.1.1-03` dumper blind spot — so the behavior change is claimed here).
  `src/ccf/graph/fallback.py::_walk` — private, the differential oracle —
  applies the identical predicate, built from its `entities` argument's class
  map, which is what holds every pushed answer to this operator.
- Why: `24.5-L-05`, criterion 8 — an excluded neighbor shown against an
  all-admitted control (`tests/operators/test_traversal_admission.py`), the
  oracle agreeing, composition preserved under the parameter
  (`tests/properties/test_composition.py::test_composition_is_preserved_under_admission`)
- Migration: none — additive
