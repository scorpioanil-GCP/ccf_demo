# 24.11-03 — the resolver carries the obligation the profile declared

Row 3 of Phase 24.11, closing the obligation limb of finding `24.10-F-08`.
The ruling of record is `D-IMPL-117` (Dave, 2026-08-11): the SDK owes *"the
structure and the api to populate and extract this content"* for a
signal-to-obligation binding, and owes **no obligation vocabulary**.

`DebtProfile.obligation_for` — whose own docstring calls itself *"the extract
half of what D-IMPL-117 says the SDK owes, and the whole of it"* — has shipped
since Phase 15.6. Nothing on the governed path called it. So a product served
through `GovernedResolver` carried the SDK's `ccf.no-obligation-in-force`
sentinel wherever the deployment's own profile bound an obligation to the
routing state the assessment landed in: a **wrong governance answer** rather
than an absent nicety, and one that cannot be repaired afterwards because
`D-IMPL-118` put the member **inside the product's content address**.

The measured harm was on `s1-01`, not on cp-05 —
`tests/examples/test_s1_01_governed_resolver_adoption.py::test_the_served_product_carries_the_obligation_the_deployment_declared`
carried the finding as a strict xfail from `24.10`, XPASSed the moment the seam
landed, and is un-quarantined here **with no assertion weakened and no expected
value moved**.

## What the probe found that the finding did not say

`build_governed_resolver` refused an explicit `debt_scorer` alongside
`debt_profile_key`, on the stated ground that *"the material for building the
reference would be read by nothing"*. That was true while the profile was
scorer material only. It is not true now: the same profile binds the
obligation, which `D-IMPL-118` deliberately gave **its own identity on the
vessel** rather than making it a rider on debt.

The consequence was larger than the missing join. **Every deployment that
scores for itself was structurally unable to declare its bands**, and therefore
could never carry an obligation on the governed path at all. `s1-01` is one
such deployment, which is why naming its already-declared `debt-profile` key
was refused with a `TypeError` before this row narrowed the rule.

## ccf.products.resolver.GovernedResolver

- Surface: ccf.products.resolver.GovernedResolver
- Public surface: true
- Change type: reshaped
- Before: seventeen constructor arguments, none with a default. Four arrived as manifest keys; the deployment's debt profile was not among them, so the class held the routing state and never the binding
- After: eighteen, still none with a default. The new `debt_profile_key: str | None` is the **fifth** manifest key, read off `BootedFabric.artifacts` like the other four rather than passed as an object — the class docstring's own rule, and the one that makes the profile served provably the one the manifest put in force. `None` is admissible and is the positive claim that this deployment declares no bands
- Why: `D-IMPL-117` — the populate half of the binding the SDK owes. Read by key rather than object because the resolved value travels inside the content address, and `obligation_for` forbids a Control Plane *"latest"* for the same reason (`D-IMPL-26`)
- Migration: every construction site must pass `debt_profile_key` (`None` where the deployment declares no profile), because this class is the auditable, defaultless composition. Callers reaching the fabric through `build_governed_resolver` are unaffected. Two sites in the tree moved: `tests/products/test_resolver_seam.py::_arguments` and `tests/products/test_evidence_derived_debt.py::_ask_the_empty_fabric`.

## ccf.products.resolver.build_governed_resolver

- Surface: ccf.products.resolver.build_governed_resolver
- Public surface: true
- Change type: behavior
- Before: twenty-one keyword arguments, twelve optional — unchanged, and unchanged by this row. Supplying `debt_scorer` together with **any** of the four `DEBT_SCORER_INPUTS`, `debt_profile_key` included, raised `TypeError` as mutually exclusive
- After: the same signature. The exclusion now reads `_SCORER_ONLY_INPUTS` — `half_life_key`, `declared_completeness`, `declared_semantic_consistency` — so a deployment may supply its own scorer **and** name its bands. `DEBT_SCORER_INPUTS` is unchanged in membership and meaning: the reference scorer still needs all four, and the no-scorer path still refuses a call omitting any of them
- Why: the exclusion's own stated ground is *"the material for building the reference would be read by nothing"*, which stopped being true of the profile the moment the obligation seam read it. The two are alternatives about **scoring** and never about the **declaration**
- Migration: none, and none is possible in the refusing direction — the change only admits calls that previously raised. A deployment that supplies a scorer and wants its declared obligation carried adds `debt_profile_key`; one that does not is unaffected.

## What did NOT change

- **`DEBT_SCORER_INPUTS`.** Same four names, same order, same meaning, still
  exported. The narrower `_SCORER_ONLY_INPUTS` is module-private and is used at
  exactly one site.
- **`DebtAssessment`.** The obligation is not a rider on debt — `D-IMPL-118`
  declined `qa-nested` deliberately, and this row does not reopen it. The
  assessment is hoisted to a local so the product's debt and its obligation are
  derived from **one** scoring call and cannot land on different sides of a band.
- **The other two limbs of `24.10-F-08`.** `source_refresh_recency` and
  `debt_evidence` are still unset on the governed path, and neither is a
  dropped join: measured at this row, nothing in `src/` or `runtime/`
  constructs a `SourceRefreshWindow` or a `DebtEvidencePointer`, and no SDK
  artifact declares either. For the refresh window that absence is ruled
  (`D-IMPL-124`); for evidence pointers it is a standing prohibition
  (`D-IMPL-119` limb 4) whose named precondition this path still does not meet.
