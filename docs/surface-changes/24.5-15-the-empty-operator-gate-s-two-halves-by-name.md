# 24.5-15 — the empty-operator gate's two halves, by name: `empty-operator-result` beside `empty-operator-guard`, read from the engine's own emptiness record, in both runners

Plan `24.5-15`, ledger row `24.5-L-24` (`D-IMPL-236`). The Wave-2 edit
`D-IMPL-238`'s second sentence unlocks and nothing beyond it:

- `L-24` — two assertions shared the name `empty-operator-guard`. The SDK's
  half (`_refuse_empty_operators`, INV-CH7-46) refuses a product that
  DECLARED no operators; nothing in `src/` said anything when an operator
  RETURNED an empty set, while cp-00's `IH-G07` (*"an empty ASSEMBLED set
  fails closed; an empty SERVED set returns 200"*) and cp-01's `CPR-G08`
  carried the Standard's half as product gates. A refusal now names which
  half fired.

## What did NOT change, stated first

- **`empty-operator-guard` and `_refuse_empty_operators` are byte-identical**
  to their plan-13 state. The token stays; the halves are named BENEATH it
  (`D-10`), so no consumer branching on `empty-operator-guard` moves.
- **No second gate mechanism** (`D-IMPL-237`): the returned half is a NAME
  for an assertion that had none — one token, one refusal type, one helper
  function shared by both runners, in the exact shape of the five before it.
- **No payload gate** (`D-IMPL-238` limb 3): the returned half reads
  operator KEYS off the engine's execution record and nothing off the
  payload. `tests/products/test_payload_bind.py::TestNoFourthGate` is
  unchanged and green.
- **The order of gates in both runners is unchanged except as this row
  names**: the returned half sits immediately after the declared half —
  the two adjacent, declared first — and every later gate keeps its place.
- **Every pre-phase call site is byte-identical in behavior** (`D-10`):
  `empty_results: frozenset[str] | None = None` on both runners; `None` is
  *not observed* and passes, the `source_attestation` compatibility posture.
  Only the governed resolver threads the observation; the engine-level
  `run_gates` example in `ProjectionEngine.check_source_attestation`'s
  docstring keeps the default.
- **`_GATE_TOKEN`, `_ServableProductMeta`, `GateBypassError` untouched**
  (`D-IMPL-224` (5)): the new step returns a refusal before the token is
  minted, as every step before it does.
- **No example was edited.** `examples/` is closed. The one ladder test the
  half flips — `tests/examples/test_hw1_two_transports.py::test_both_documented_transports_return_the_same_answer`,
  because a clean checkout's hw1 boots an EMPTY fabric (`D-32`) and its one
  operator returns nothing — is recorded for plan `24.5-16`'s re-measure,
  untouched.

## ccf.projection.engine.ExecutionResult

- Surface: ccf.projection.engine.ExecutionResult
- Public surface: true
- Change type: reshaped
- Before: eleven fields ending `source_attestation`, `store_snapshot_pin`; the engine recorded WHAT ran and in what order, not whether any operator returned nothing
- After: one added last field, `empty_results: frozenset[str] = frozenset()` — the operator keys whose output view carried zero entities AND zero relationships, computed ALWAYS by `ProjectionEngine.execute` from one inspection of each `OperatorOutput` view as it is produced; the empty set is the engine's positive assertion, not a sentinel for absence. Inside one pushed segment the answer is composed, so an empty answer is recorded against every operator of that segment (the engine re-applies each over the answer, `GQ-19`); the record names what each operator returned. A result built by hand without the field carries the empty set
- Why: `24.5-L-24`; the returned half needs an input `run_gates` did not receive, and the only honest source is the thing that ran the plan — never the payload (`D-IMPL-238` limb 3)
- Migration: none — the default. A defaulted field is inside the canonical rendering, so the content address of an `ExecutionResult` value moves; no committed seal pins one (the execution record is not a served vessel; `D-IMPL-240` (1) measured the only sealed addresses in the tree as cp-04's two product addresses)
