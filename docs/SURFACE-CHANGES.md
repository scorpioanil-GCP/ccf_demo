## What this document is

This is the **migration note D-15B promises**. D-15B took free rein on the public API pre-1.0 on the explicit understanding that anyone building against v0.1 or v0.2 gets a migration; this is it. Every surface Phase 15 added, reshaped, removed, or changed the behavior of is recorded below with the reason it moved and what an adopter has to do about it.

It is assembled from the per-plan fragments under `docs/surface-changes/`, which each plan wrote **as it landed**. A migration note written retroactively at phase close is a note written from the diff, which is the one thing it is supposed to add information to.

**The `Behavior changes` section is why this document exists at all.** `docs/surface/v0.2-surface.json` is generated from every module's `__all__` and records signatures; it is structurally incapable of seeing a change like D-02's, where `load_artifact` kept its signature and changed what it returns for a timestamp-shaped scalar. A generated diff and a curated log are two halves of one guarantee, and `tests/test_surface_completeness.py` asserts they agree.

**Phase 16 consumes this document directly.** The documentation rewrite describes the surface that exists; this is the record of how it got there from the surface Phase 14 documented.

## How to read an entry

Every entry carries seven fields: `Surface`, `Public surface`, `Change type`, `Before`, `After`, `Why`, and `Migration`. The assembler refuses to build this document from an entry missing any of them.

`Public surface: true` means the entry names an exported Python name and appears in the generated manifest diff. `Public surface: false` entries are real changes an adopter must act on that are **not** Python API — lint scope, tooling, committed schemas, and artifact *document formats*. They are grouped separately under each change type so a Python API change is never mistaken for a YAML reshape. The classification is checked in both directions by `tests/test_surface_completeness.py`: a public change mislabelled non-public fails, and a non-public entry whose name turns up in the manifest diff fails too.

### Public Python surface

#### ccf.deployment.classes.resolve_artifact_class

- Surface: ccf.deployment.classes.resolve_artifact_class
- Public surface: true
- Change type: added
- Before: absent — `ccf.controlplane.artifacts` has no registry of artifact
  classes. Its `ArtifactClass` values are module-level constants that callers
  import by name, which is the right shape for a caller who knows statically
  which class it wants and the wrong shape for a manifest, whose whole point is
  that it does not
- After: `resolve_artifact_class(class_id: str) -> ArtifactClass`, returning the
  SDK's own constant for an id the SDK owns and
  `declared_artifact_class(class_id)` for every other id
- Why: the manifest declares each artifact by `path, key, class`, where `class`
  is a string. Nothing in the tree turned that string into a contract. The
  fallthrough is the D-01 line made operational: the SDK owns the schema of what
  it ships and never invents one for what it does not, so an unrecognized id is a
  deployment-authored schema and gets the open `DeclaredArtifact` envelope — by
  design, not by failure. SDK ids resolve from the reviewed mapping *first*, so a
  manifest cannot shadow an SDK class into the permissive envelope
- Migration: none — new function. Callers who import an `ArtifactClass` constant
  by name may keep doing so; this is the additional string-keyed direction, not a
  replacement

*Recorded by `15-06-class-lookup.md`.*

#### ccf.controlplane.artifact_base.VersionedArtifact

- Surface: ccf.controlplane.artifact_base.VersionedArtifact
- Public surface: true
- Change type: added
- Before: absent — the base existed as `ccf.controlplane.artifacts._VersionedArtifact`,
  module-private, with no module of its own
- After: a public `CCFContract` subclass declaring the single `semver` lane,
  validated through `validate_semver`, with no default
- Why: two reasons, and both are structural. **It had to move**, because
  D-IMPL-77 requires `EntityResolutionSpec` gain `semver` *in place*, so
  `ccf.controlplane.artifacts` must name a class from `ccf.assembly.worker` to
  declare `RESOLUTION_SPEC` — and `worker` reaches `ccf.controlplane.registry`,
  which needs `ArtifactClass`. Leaving these primitives in `artifacts` closed
  `artifacts -> worker -> registry -> artifacts` at **import** time, taking the
  package down rather than tripping a lint. The real closure proved wider than
  the registry edge alone: `worker -> peering.admission -> peering.trust_policy
  -> artifacts` closes it too, so every module importing only the relocated
  primitives now takes them from `artifact_base`. **It had to become public**,
  because L2's `EntityResolutionSpec` now inherits it, and an L2 contract
  inheriting a module-private Control Plane type is a relocation hazard the next
  refactor trips over
- Migration: none — `ccf.controlplane.artifacts` re-exports it, and
  `_VersionedArtifact` survives there as a module-level alias

*Recorded by `15-07-resolution-spec.md`.*

#### ccf.controlplane.artifacts.PolicyFilterParametersArtifact

- Surface: ccf.controlplane.artifacts.PolicyFilterParametersArtifact
- Public surface: true
- Change type: added
- Before: absent — `PolicyFilterParameters(...)` built by hand, with
  `permitted_policy_bundle_versions=frozenset({policy_version})` where
  `policy_version` is the return value of `registry.register(...)`

  pass the parsed artifact straight to `PolicyFilter` needs
  `build_operator_registry` instead: it is what constructs the real

#### ccf.controlplane.artifacts.ProductClassDeclaration

- Surface: ccf.controlplane.artifacts.ProductClassDeclaration
- Public surface: true
- Change type: added
- Before: absent — `register_product_class(...)` was called with six keyword
  arguments assembled by hand from a control-plane document at ten sites
- After: a `VersionedArtifact` declaring `schema_name`, `schema_version`,
  `ttl_anchor`, `assembly_mode`, `max_ttl_key`, and
  `required_operator_keys: tuple[str, ...]` with `min_length=1`. It declares
  **no** `max_ttl_version`
- Why: two deliberate omissions and one deliberate addition.
  **`max_ttl_version` is absent** because that pin is minted by *registering* the
  `MaxTTL` value and is a content hash of what was registered — the same shape
  D-IMPL-76 ruled on for the policy bundle's admitted-version set. An artifact
  declaring it would be authoring a hash of something it does not contain, and it
  would collapse Gate 3: the TTL ceiling stays an authored artifact value, the pin
  is derived from registering it, and a product's `expires_at` remains a
  separately authored number — Gate 3 checks one against the other, which is only
  a check while the two come from independent places (T-15-09-02).
  **`required_operator_keys` is present** because it is what a projection's
  `required_operators()` returns, and giving it an authored source is what keeps
  the projection's declaration and the engine's resolution two independent
  mechanisms. Gate 2 compares them for strict equality (INV-CH7-47); a projection
  returning the operator registry's own keys makes that comparison a value against
  itself and the gate silently stops being a gate (T-15-09-06). Every example in
  the tree today passes `operators.keys()` or `self._registry().keys()`, which is
  exactly that shortcut; plan 15-21 adds a standing AST guard against it. It lives
  on the product class rather than on a projection artifact because the product
  class is already the artifact that declares what the product *is*, and the
  operator set an interpretation requires is a property of the product, not of the
  code computing it

#### ccf.deployment.manifest.load_and_boot

### Public Python surface

#### ccf.controlplane.artifacts.load_artifact

- Surface: ccf.controlplane.artifacts.load_artifact
- Public surface: true
- Change type: behavior
- Before: parsed with `yaml.safe_load`, so PyYAML's timestamp resolver ran and a
  timestamp-shaped scalar arrived as a **naive** `datetime` — which
  `ControlPlaneRegistry.register` then refused as non-canonicalizable, forcing
  every caller to hand-normalize (six distinct helper implementations had
  drifted across eleven sites)
- After: parses through a private `_ArtifactLoader` with the
  `tag:yaml.org,2002:timestamp` resolver removed, so the scalar arrives as
  `str`; a contract field annotated `datetime` parses it into an **aware**
  value, and a date-time naming neither `Z` nor a `±HH:MM` offset is refused at
  parse by `_reject_naive_timestamps` with a message naming D-IMPL-38
- Why: D-02. `Z` is the ISO-8601 UTC designator, not an implicit timezone — the
  author stated UTC explicitly and PyYAML's resolver is what drops it. Refusing
  the author's document punished them for a rule they did not break, because the
  naive value was a *parser* defect rather than an authoring one. The SDK now
  reads timestamps as text and lets the contract parse them, exactly as it
  already refuses floats rather than repairing them. The resolver table is
  copied rather than mutated in place, so YAML parsing elsewhere in the process
  is unaffected.
- Migration: a caller relying on `load_artifact` handing back a `datetime` for a
  field its contract does not annotate as one now receives a `str` — annotate
  the field `datetime` on the contract and Pydantic parses it, aware. A document
  carrying a zone-less date-time is now refused rather than silently read as
  naive; state the zone as `Z` or as an explicit offset. No public
  timestamp-parsing helper is offered, deliberately: one would invite adopters
  to keep hand-normalizing the thing the loader now gets right.

*Recorded by `15-05-timestamps.md`.*

#### ccf.controlplane.registry.ControlPlaneProtocol

- Surface: ccf.controlplane.registry.ControlPlaneProtocol
- Public surface: true
- Change type: behavior
- Before: the Protocol declared `register`, `register_typed`, `resolve`,
  `resolve_latest` and `audit_events`. `register_versioned` — the D-05 hash-verified
  bump check — existed only on the reference `ControlPlaneRegistry`, so a conforming
  implementation could omit it entirely
- After: the Protocol also declares
  `register_versioned(key, artifact, artifact_class, *, actor=None, reissuable=False) -> str | RegistrationRefusal`,
  with a signature identical to the reference implementation's
- Why: D-IMPL-82 (Dave, 2026-08-05). The bump check is a governance obligation, and
  the Protocol's own docstring already argues that the obligations sit on the surface
  "precisely so a remote plane cannot conform while quietly dropping them" — a remote
  Control Plane that cannot run the bump check is exactly such a plane, and
  `load_and_boot` must be able to dispatch author-versioned classes to it to close
  CR-1 at all (T-15.1-01-01). Rejected: a narrow second
  `VersionedRegistrationProtocol`, which preserves the posture at the cost of a
  two-Protocol mental model in the phase whose subject is one mental model; and
  narrowing `load_and_boot` to the concrete `ControlPlaneRegistry`, which breaks the
  Protocol-over-inheritance posture CLAUDE.md §11 mandates. Recorded as
  `Change type: behavior` rather than `reshaped` because
  `docs/surface/v0.2-surface.json` records a Protocol's shape as `(*args, **kwargs)`:
  a member addition changes what conforms without moving any signature the generated
  manifest can see, which is the case the `behavior` class exists for
  (`docs/surface-changes/README.md`)
- Migration: a non-reference Control Plane implementation must now provide
  `register_versioned` — this is a FABR-07 remote-plane implementation obligation.
  The in-process `ControlPlaneRegistry` already satisfies it and needs no change; no
  caller's code changes. An implementation that omits the member no longer type-checks
  as conforming, and `isinstance(x, ControlPlaneProtocol)` returns `False` for it

*Recorded by `15.1-01-projection-requirements-and-protocol.md`.*
